## 0. 给用户与 Opus的先行裁定

**C-50 中的 `−1`，截至本轮不算 [KC-000047](../核心认知.md#L427) 意义上已经成立的“非现实推演结果”。**它是一个正确、很有启发性的形式结果：在 Opus 专门构造的 `ℤ`-纤维 `Ped` 中，若 `go` 与独立的 `back` 都被规定为 `+1`，那么 HoTT 自动给出的 `sym go` 的 transport 必为 `−1`。但从这条等式到“现实中出现了一次负一步行走”至少还缺三条未证桥：

1. 每一条 identity path，包含自动生成的 `sym go`，都必须对应现实的一次已执行行走；
2. `Ped : Places → Type` 的 `ℤ` 值必须是现实的、非负的计步器读数，而不只是有符号位移／形式逆元的账；
3. 现实任务必须要求把该 formal inverse 也当作一次动作，而不能把它当作未选中的代数逆／undo。

C-50 没有证明任何一条；它的源码反而选择了可为负的 `ℤ`。所以 `antiWalk` 是

```text
FORMAL_SIGNED_INVERSE_ACTION_WITH_SCOPE
/ REALITY_BRIDGE_OPEN
/ NOT_YET_KC-000047_NONREAL_RESULT
```

这并不把 A6′／A6″ 整体打回空白。010 的真正贡献是比 008 更清楚地暴露了攻击需要锁定的解释前提：`P-proc`、`P-carry`，尤其是此前没有写出的 `P-rev`。它使候选从模糊的“路径不能数步”变成可以严格审问的模型相对张力；但它也给出了 C-50 这个同一 HoTT 内的反模型，故不能再把困难归为 HoTT 身份类型必然强加给所有现实过程的结果。

## 3. C-47：它证明的是“无 stopping witness”，不是已实现的程序不停机

C-47 的形式定义是：

```text
roundTrips p n = (p · sym p)^n
after n = subst B (roundTrips p n) start
run fuel = 在 0…fuel 中搜索 after n 的读数是否增加 2
```

由于每个 `roundTrips p n = refl`，得到：对每个**有限** `fuel`，`run fuel = nothing`。这个结论很清楚，也完全可用；但它的准确名字是：

```text
NO_HALTING_WITNESS_IN_P_REV_TRANSPORT_SPECIFICATION
```

而不是已经形式化的“一个程序永不停机”。理由有二：

1. C-47 实际运行的 `run fuel` 是总的、有限的搜索；每次都会返回。它没有定义一个无界递归 evaluator、coinductive trace 或运行语义中的无限执行。
2. 即使我们在它之外定义“不断重复 round trip，直到 predicate 成立”的循环，其不停止仍条件于 `P-rev`：把现实回程规定为同一 `p` 的 formal inverse，并把物理计步器规定为纯 transport 的 readout。

因此，对 Opus 的 **T-015**，Terra 的回答是：它可以称为“在明示 P-rev 停止规格下不存在停机时刻”的数学候选；尚不能称为 [KC-000010](../核心认知.md#L87) 所要求的、已经由 HoTT 强迫出现的程序不可停机。把“无见证”写成无界循环的描述是一条额外操作语义桥；更重要的是，现实计步任务并不要求 P-rev。

这不是用“对象里有时间变量”草率结束候选。相反，KC-000011 要求我们检查理论思考是否错误地消除了过程；而一份真正的过程 contract 不能把现实所需要的 event/update 先从输入与操作中删去，再把删去后的 stopping predicate 不可满足归罪于理论。扩展认知也明确警告：A 方向不能把简单现实任务偷偷换成更强的理论任务，或预先剥去必要信息。[扩展认知 003](../扩展认知/003%20-%20芝诺、圆环、ASK%20与两种方向.md:114)

## 4. C-48：形式边界正确，摘要“历史只保留次数”错误

C-48 证明一个有价值但狭窄的 quotient 事实：若将相邻交换声明为 path，任何 `MS → Maybe Bool` 的函数必须尊重这条 path，故不能同时把所有代表列表送到其“第一项”。这应标为：

```text
FORMAL_ORDER_OBSERVER_NOT_QUOTIENT_INVARIANT_WITH_SCOPE
```

它**不**证明“补丁理论历史只保留次数、不保留次序”。JFP 2016 §7.1–7.2 的直接一手文本恰好作出更细的区分：为了表示可交换 patch，Boolean lists 被按 permutation quotient 为 `MS`；但作者明确说 **`MS` 的元素仍保存应用顺序的显式 log，而它们之间的 paths 识别仅差置换的 logs**。[JFP 2016 PDF §7.1–7.2](https://www.cs.cmu.edu/~rwh/papers/htpt/jfp.pdf)

这与 C-48 并不矛盾：

| 层 | 能保留什么 | C-48 是否否定 |
|---|---|---|
| point constructor / 具体 presentation | `true :: false :: []` 与 `false :: true :: []` 的显式顺序日志 | 否。JFP 正说元素保留。 |
| quotient-invariant set-valued observer | 不应把被声明可交换的两种日志分成不同 `Maybe Bool` 值 | 是。 |
| 现实 chronological/audit log | 需固定是否把独立可交换操作的先后当作语义上重要的观察，并选择保存的 representation | C-48 未决定。 |

因此对 **T-016** 的裁定是：接受 C-48 的形式与来源事实，拒绝它被概括为“历史层不能保存次序”或“凡进入路径结构的东西都失去时间”。HPT 的基本架构还明确区分 patch theory、其 model 和 concrete changelog；其 introduction 直接把 patch histories 写作“maintaining a list of patches themselves”。[JFP 2016 PDF](https://www.cs.cmu.edu/~rwh/papers/htpt/jfp.pdf)

## 5. C-49 与 C-50：真正发现的是 reversible transport 的边界

### 5.1 C-49 的数学含义

C-49 的核心正确：identity-path transport 是 equivalence，因此 `p` 后接 `sym p` 恢复纤维元素。若一个 `ℕ`-valued readout 对**所有** identity paths 均不降低，则在反对称性下它也不能严格增长；`suc : ℕ → ℕ` 不可能是 universe 中一条 identity path 的 transport。

这是关于**纯 path transport**的结构性边界，而不是“任何 HoTT 模型都无法保存非负 event count”。列表、台账、C-50 的独立 `back` 及任何明确的 operational/event layer 都不在 C-49 的量词内。故 current wording 中的“任何 HoTT 建模都躲不开”须改成“任何把携带完全因子化为 identity-path transport，且要求对全部这类 path 单调的模型”。

对 **T-017**：transport 确是 HoTT 中 identity path 对 dependent fiber 的 canonical action；但“现实中随身携带的计步器只能是这种纯 transport”并不是 HoTT 规则。一个形式化的执行状态可包括 event、counter、trace 或更新关系；它仍在 HoTT 内，且是否只是“对象里的变量”还是指定理论 process 的一部分，要由任务 contract 决定，不能由术语位置一刀切。

### 5.2 C-50 是 A6″ 的最强反解释，不是第二支已闭合悖论

C-50 构造的 `Places` 有两条**独立生成**路径：

```text
go   : west = east
back : east = west
```

并令两者都在 `ℤ` fiber 上作用为 successor。它由此成功建立：`go · back` 加 2、停止搜索在 fuel 1 成功；同时 formal inverse `sym go` 作用为 predecessor。数学正确，且恰好证明 C-47 的普遍化不成立。

但 `antiWalk` 的类型只是：

```text
subst Ped (sym go) 0 = -1
```

它不含“`sym go` 是一次实际步行”“−1 是计步器的真实读数”或“所有 identity paths 都必须入现实 event log”。在最自然的代数读法中，`sym go` 是 `go` 的 formal inverse，而 `ℤ` 是有符号变化；负一完全正常。把它命名为“−1 步行走”是 Opus 加入的现实解释，不是 kernel 结论。

所以对 **T-020** 与用户的新裁定问题，Terra 的明确回答是：**C-50 是 A6″ 任务形式的最强形式反解释；C-49(e) 说明 inverse transport 具有相反的有符号效果，但尚不构成现实侧没有、不可接受的成本。**要让它成为 KC-000047 现象，至少需要一个固定 consumer，证明 formal inverse 也必须当作实际 event，并证明实际 counter 不允许这类 signed inverse interpretation；当前没有。

Opus 的“两难”也不是穷尽的：

```text
选项 A：实际回程 = sym go              → P-rev counter specification 不会达到 +2
选项 B：实际回程 = 独立 back            → 所选 go/back 都可 +1；sym go 可留作 formal inverse
选项 C：实际 event 只取生成的 go/back；→ sym go 不是一次实际行走，而是群胚 completion 的 inverse
        另以 event/log contract 说明计数
```

选项 C 不是在理论外偷偷加一个补丁；它正是“primitive event / formal inverse / semantic equivalence”必须分层的建模纪律。HPT 自己将 generating patches、自动获得的 inverse/composition，以及 concrete histories 区分开。论文确认 path 表示会自动给出两侧 inverse，也说明为什么这可能带来应用层取舍；这支持继续研究，但不支持把每个 inverse path强制等同于一次现实动作。[JFP 2016 §3.1–§3.2](https://www.cs.cmu.edu/~rwh/papers/htpt/jfp.pdf)

## 6. 有向消融：有意义的比较，尚非严格的核心因果证明

010 的有向线是本轮最有希望的技术增量，但其证据等级必须分层：

| 项目 | Terra 判词 |

## 7. “Think in HoTT”不应被压成 008 的二选一

对 008 §9 第 1 问，Terra 建议采用三层、可审计的含义，而不是在 `(a) 原生路径建模` 与 `(b) 任意编码` 之间二选一：

| 层 | 含义 | 这轮证据能说什么 |
|---|---|---|
| T0 | HoTT 核心演算可写什么：identity、transport、HIT、List、Nat 等 | 它既支持 C-49 的 path boundary，也支持事件数据；不能单独判现实失败。 |
| T1 | 指定的 HPT-style semantic contract：哪些 generator 是实际 patch/event，哪些 identity path 是 formal completion，history/log 要满足何种 law | 这是可以被针对性攻击的层；必须固定 consumer、输入、观察和 Done。 |
| T2 | 强现实桥：每条 identity path 都是一次实际行走、回程就是 `sym p`、物理 counter 只能由 pure transport 得到 | C-47/C-50 的张力在此出现；它是额外解释前提，不是 HoTT 的一般规则。 |

这既修正 Terra 007 过于绝对的“所有替代编码都必须失败”措辞，也拒绝 Opus 的反向绝对化“只要 HoTT 能编码数据，一切 A 候选必然失败”。正确问题是：**有没有保留指定 T1 的理论收益、又保持同一现实任务的替代表示？它带来的成本是否真是现实侧没有、且由理论强加？**

对 HPT 而言，论文自己的 theory/model/history 架构正是一个强反解释：它不是简单地把问题赶到“理论外”，而是在 HoTT 编程应用中显式维护 histories/concrete changelogs，并区分 formal laws 与实现。它不自动结束所有模型相对候选，却要求 A6′/A6″ 不能再用“HoTT 必然不让时间参与”表述。
