## 1. 决定性发现的形成（reasoning `:317` → `:347` → `:355`）

这是本回合最重要的思维链。

### `:317` —— 发现证据链未入 Git

> "Critical finding confirmed: ALL interaction/audit directories … are git UNTRACKED (0 tracked
> files each). Even goal.md is untracked! That's a critical finding — the root goal contract itself
> is not in Git. So the FR-001 'actual vs pinned' conflict cannot be resolved by Git archaeology
> at all, because goal.md has never been committed."

### `:327` —— 把发现升级为决定性

> "MAJOR FINDING: goal.md has NEVER been committed to Git in any branch … And the S151 checkpoint's
> before/after copies only include STATE.json, HEAD.json, and the session RUNS.json — NOT goal.md or
> R4 TaskSpec. So: 1. goal.md has no committed history → FR-001 Path A (recover old bytes from Git)
> is IMPOSSIBLE for goal.md."

### `:347` —— 主动检验反解释

> "Actually, hold on. Let me reconsider: could the pinned hash have been recorded from a DIFFERENT
> moment? …"

**为什么这个动作关键**：我没有停在"路径 A 不可能"上，而是**主动检查时间线**：goal.md 的
mtime（07:10:11Z）晚于 S151 checkpoint（06:38Z），且与 GLM 独立审计 README 诞生（07:06:35Z）
同窗。于是我得出一个**不对称**的判别性推断（而非对称的"两版本各自自称 current"）：

> "证据不对称地支持 actual 内容为 intended current，STATE pin 只是过期。我不能证明编辑者身份，
> 但可以给出这个判别性推断和它的证据等级。"

这是我在审计报告 01 里把它写成 A1（独有的决定性发现）并**显式标注证据等级**的原因。

### `:355` —— 汇总独有发现

## 4. 分片合规的失败与修复（reasoning `:584` → `:713`）

这是本回合最能体现"我如何对待规则"的一段。我写完 5 片后**主动跑项目的分片校验器**，
然后连续失败多轮：

| reasoning | 失败原因 | 我的修复 |
|---|---|---|
| `:584` | 校验器要求 shard table 标记 | 加 `governance-shard-table:start/end` |
| `:640` | v2 合同要求 shard_root == 索引词干；我的索引是 `README.md`（词干 README ≠ 修订片） | 把 v2 索引改为 `修订片.md`，README 降级为普通导航文档 |
| `:668` | 文件名正则要求 3 位编号，我用的是 2 位（`01 -`） | 改为 `001 -`，表内 shard_id 同步改 3 位 |
| `:692` | 文件名主题必须 == 链接标题 == 分片 H1 | 三者统一 |
| `:713` | **PASS**：`governance shard indexes=456（was 455；我的新索引 +1），notices=0` |

**为什么这么想/这么做**：我没有把校验失败当成"工具不适用"，而是把项目的分片合同当作
**对我的硬约束**——因为 U1 的产物是"修订后的方案分片"，它必须满足项目自己的分片规范，
否则交付物本身就是 fail-closed 的。修复完成后我才让报告引用新路径（`:722` 的批量引用修正）。
