# 用户提示词回收：方法论全集（2026-10-16）

> **定位**：本文档完整记录"找回研究发起人发给 AI 的全部提示词"这项工作的方法、方案、思路与脚本——比 `WORKLOG.md`（进度与接手契约）更进一步：**为什么这么设计、怎么实证、踩了什么坑、如何复用**。任何 AI 或人，拿着本文档可以对任何项目、任何平台重做一遍同样的事。
> **执行人**：GLM 会话（Codex/ZCode）。**产物**：442 会话、3691 条用户消息（见 `_总索引.md`）。

## 一、问题与总方案

**问题**：三平台（Codex / ZCode / Claude）的对话录分散在各自的私有存储里，格式互不相同，且都混有大量非用户内容（系统注入、工具结果、AI 回复）。要找回的只有一样东西：**研究发起人亲手打出（或粘贴）的内容**。

**总方案**（研究发起人亲自给的两条定位策略＋一条前置）：

1. **前置——先找全工作树**：所有与 GitHub 分支对应的本地 AI 工作树目录是"研究发生地"的清单。`git worktree list`（41 条）＋`~/.claude/projects/` 目录名化石（28 个，含已删 worktree 的痕迹）。
2. **策略一（路径规律，优先）**：对话录内部记录了会话发生时的工作目录（cwd）。只读每个文件的头一行即可判定归属——**快且准，不解压全文**。
3. **策略二（关键词兜底）**：`HoTT`、`悖论`、`芝诺`、`ZFC`、`形式化与机器证明` 全文流式扫描，接住 cwd 不在研究仓库、但内容相关的会话（临时目录、其他项目里的研究讨论）。

**通用纪律**：全程工作记录（WORKLOG）先于执行建立——长任务可能中断，接手契约让任何 AI 零起点续做；产物只含用户内容，隐私边界在提取器里硬编码。

## 二、三平台的存储结构与判据（全部实证）

### Codex（`~/.codex/`）

- **存储**：`sessions/YYYY/MM/DD/rollout-<时间戳>-<会话id>.jsonl.zst`（344 个，按日期）＋`archived_sessions/*.jsonl.zst`（172 个平铺）——共 516 个 zstd 压缩的 JSONL 流。
- **定位**：首行 `{"type":"session_meta","payload":{"cwd":...}}`——**每个文件只读一行**。516 个全扫秒级完成。
- **用户消息**：`type=="response_item"` ＋ `payload.type=="message"` ＋ `payload.role=="user"`。
- **注入剔除（九种前缀，逐个实证发现）**：`# AGENTS.md instructions`（环境注入 AGENTS 正文）、`<app-context>`、`<environment_context>`/`<ENVIRONMENT_CONTEXT>`、`<user_instructions>`、`<turn_aborted>`（中断标记）、`# Codex desktop context`、`<permissions`、`<app-signal`、`<external_codex_apps`（**这个是试跑时漏网后补的**——GUI 事件标签也走 user 通道）。
- **保留的特例**：`# Files pasted by the user:` 包装——是用户粘贴的内容，保留并在产物中标注"（用户粘贴的文件）"。
- **压缩**：zstd 流式处理（`zstdcat` 管道逐行），绝不落盘解压整文件（最大单文件数百 MB）。

### ZCode（`~/.zcode/cli/`）

- **存储决策**：有 rollout JSONL（model-io-sess-*.jsonl）和 sqlite（`db/db.sqlite`）两个源——**选 sqlite**，因为它比 rollout 全（fork 会话只在 db 里有完整消息、GUI 的源头也是 db；rollout 只有跑过 turn 的会话）。
- **结构**：`session(id, parent_id, project_id)`——fork 链与项目过滤入口；`message(id, session_id, time_created, data)`；`part(message_id, data)`——正文在 `part.type=="text"`。
- **判据**：`message.role=="user"` 且 `data.metadata` 无 `source`、无 `synthetic`（todo 提醒、agent 列表增量、fork 标记全带这些标记）。只读连接（`file:...?mode=ro`）。

### Claude（`~/.claude/projects/`）

- **存储**：每个工作目录一个编码目录（路径 `/`→`-`、`_`→`-`），内含 `<session-id>.jsonl`。**目录名本身就是工作树化石清单**——含已删除 worktree 的历史痕迹。
- **判据**：`type=="user"` 且非 `isMeta`；剔除固定前缀注入：`This session is being continued`（压缩摘要——注意它含历史消息摘要但**不是用户打的字**，剔除）、`[Usage limit reached`、`Your response above was cut off`（断流续传指令）、`<command-name>`/`<local-command-caveat>`（命令回显）、`<system-reminder>`；`<pasted_content>` 保留并标注。
- **大文件**：62MB 级 jsonl 用 python 逐行流式，不整读。

## 三、关键词兜底的分层设计

332 个关键词命中直接全收会把"别的项目顺带提到 ZFC"的噪音混进来。**按命中关键词数分层**：

- **≥3 个关键词（232 个）**：大概率真是研究讨论——自动提取，但**放进独立的 `codex-related/`**，索引标明"cwd 非研究仓库但内容强相关，供人工筛"（其中大量是菲尔兹靶项目 `Collected-Papers-of-Fields-Medalists` 的会话——它本来就是本研究的分支 CG-004）。
- **1–2 个关键词（100 个）**：留清单（`source/codex-keyword-hits.txt`）不自动提取，按需人工复核。

## 四、安全红线（本次踩的坑，未来必做）

**用户提示词里可能藏着真实密钥。**本次推送 dev 时被 GitHub Push Protection 拦截：两个文件里有你当时粘贴的 OpenAI API Key（9-21 与 10-05 的会话）。处置：

1. 正则 `sk-[A-Za-z0-9_-]{20,}` **全产物目录扫描**（不是只改报错的那几处——同模式可能多处）；
2. 替换为 `[REDACTED: …应视为泄露并作废]` 并保留位置可读性；
3. `git commit --amend`（提交尚未推送时 amend 是安全的）后重推；
4. **提醒密钥主人作废该密钥**——清除入库物不能撤销"它曾经被贴进过对话"这一事实。

**流程化结论**：任何"用户原话入库"的操作，推送前必须跑一遍密钥模式扫描（本目录的教训已固化为此步骤）。

## 五、脚本使用手册（`tools/`，三个皆可独立重跑）

```sh
# Codex 侧
python3 tools/codex_user_prompts_extract.py scan          # 全量：重扫 516 个首行 cwd → 提取 HoTT 会话
python3 tools/codex_user_prompts_extract.py extract --list <清单文件>   # 按清单提取（清单为 "ts\tcwd\tpath" 三列或单列路径）
python3 tools/codex_user_prompts_extract.py keyword       # 关键词兜底扫描（非 HoTT 会话）

# ZCode 侧（sqlite 只读；--project-filter 可换项目子串）
python3 tools/zcode_user_prompts_extract.py --project-filter hott

# Claude 侧（--match 为项目目录名子串）
python3 tools/claude_user_prompts_extract.py --match HoTT
```

每个脚本的产物：每会话一个 Markdown（`<日期>-<会话id8>-<N>p.md`，`N`=消息数）＋`_INDEX.md` 索引。会话文件头部记录会话 id、时间、cwd/项目、条数、身份声明。

## 六、复用清单（对任何项目做同样的回收）

1. 建工作目录＋WORKLOG（接手契约先行）。
2. 枚举工作树：`git worktree list` ＋ Claude projects 目录名化石 ＋ 已知磁盘位置。
3. 定位：首行 cwd 匹配（快）→ 关键词全文扫描（兜底）→ 强弱分层。
4. 每平台先**小样本实证判据**（列出几条 role=user 的消息，人眼分出真实输入 vs 注入，归纳前缀集），再全量提取——判据是实证出来的，不是猜的。
5. 三处质量抽查（每平台至少一份产物人工核对）。
6. **密钥扫描**（第四节）→ 提交 → 推送 → 远端回读。
7. 总索引＋待办清单（fork 去重、弱命中复核、非研究目录兜底、更早平台范围声明）。

## 七、本方法论的边界

- 覆盖 Codex/ZCode/Claude 三平台的本机存储；更早的 LocalGPT/WebGPT/Gemini 原话由 `核心认知.md`/`sources/prompts/` 体系管理，不在本方法范围。
- "用户消息"的判定基于注入前缀黑名单——**新平台的注入类型可能在样本里没出现过**（本次 `external_codex_apps` 就是漏网后补的）。复用时保留"试跑→人工看样本→补判据→重跑"的循环，不要盲信黑名单完备。
- ZCode 的 fork 会话复制母会话消息，条数有重复；按 `forkOrigin` 去重是待办。
