我的核心建议是：**建设一个“任务与理论表示相互约束、候选生成与反例反馈相互推进”的研究系统。机器搜索的对象，应当是一条完整的理论化过程：原来要完成什么，HoTT 怎样表示它，规则组合改变了什么，合法推演产生什么现象，以及这个现象怎样对应回原活动。**

这份方案没有预设 HoTT 必然存在目标悖论，也没有把“未找到”当作理论获得豁免。它把搜索范围和未解决义务都做成能够检查、扩展和复跑的对象。

**一、系统采用两层研究循环。**

内层固定理论配置、任务、候选语法和预算，机器自动执行：

**生成构造 → 检查类型与规则 → 寻找差异或反例 → 缩减候选 → 原生 HoTT 核验 → 审查现实对应 → 保存结果。**

外层检查：当前任务语言是否遗漏了你的问题，哪些规则家族尚未进入搜索，哪些失败只是旧机制重现，是否需要提出新的任务或改变搜索语法。

这个区分很关键。只有内层，系统容易把已有偏见自动化；只有外层，又容易不断写新方法而没有实际构造。两层之间的每次修改都保留版本和依据，不能通过悄悄换题把失败变成成功。

具体算法见 [候选生成、搜索与反馈算法](</Volumes/D/HoTT独立答复/HoTT非现实性悖论机器统观完整方案/004 - 候选生成、搜索与反馈算法.md>)。

**二、学术界已有工作提供了可借用的技术，但 HoTT 适配必须单独完成。**

方案纳入了 20 项论文或官方资料，并标注了阅读范围、采用方式和不能外推的地方。其中最重要的几组是：

| 学术基础 | 在系统中承担什么 |
|---|---|
| QuickSpec、Hipster、TheSy | 让机器从定义出发主动提出关系和辅助引理 |
| SyGuS、CEGIS | 用类型与语法约束候选，用反例改善下一轮生成 |
| CEGAR、有限模型检查 | 寻找抽象过程与具体过程的对应失败位置 |
| egg／等式饱和 | 在适用范围内减少重复表达式和改写顺序造成的搜索浪费 |
| Cubical Agda | 核验涉及单价性、路径、HIT 等内容的精确命题 |
| FunSearch、LeanDojo | 借鉴程序生成与独立评价、前提检索和可复现评测 |
| Guarded Cubical、CATT、2LTT | 为时序、成本、自描述和层级问题提供独立的比较配置 |

**三、对 HoTT，必须同时保留有限搜索和原生高阶搜索。**

有限模型求解器适合快速寻找小型结构、操作顺序和具体反例；但它不能自动承担一般依赖类型、高阶路径与相干性的全部语义。

因此，方案要求两条路径并存：

- **有限模型路径**：产生候选和范围明确的结果，再重建相称的原生证明。
- **原生符号路径**：直接生成有类型的 HoTT 项、路径与证明义务，处理不能由有限模型替代的问题。

第一版建议复用现有 Cubical Agda 工具链，采用一个协调程序、小型有类型枚举器和必要的 cvc5 适配。不会一开始就同时安装全部学术工具，也不把大型多 AI 平台设为前置。

还有一条容易忽略的要求：**搜索器自身不能为了去重，提前抹掉我们正在研究的区别。** 程序语法、运行成本、证明来源和路径见证需要独立保留；只在已经证明适用于当前观察时，才能用某个等式合并候选。

**四、研究范围明确覆盖六条线，时间结构不会被时序问题吞并。**

| 研究线 | 主要寻找什么 |
|---|---|
| L1 抽象与操作组合 | 单独可用的抽象进入复合过程后，出现什么行为差异 |
| L2 局部存在与整体完成 | 逐例、有限阶段、相容整体和最终完成之间的连接义务 |
| L3 时间与运动结构 | 连续性、稠密性、细分、尺度和完成模型怎样改变原活动 |
| L4 同一性与操作身份 | 现实动作在类型同一性下是否承担了额外的统一性或相干要求 |
| L5 自描述与内部担保 | 编码、替换、验证域和自应用怎样形成真正的担保依赖 |
| L6 补偿与新增义务的组合 | 局部可用的补偿能否在同一输入、阶段和资源条件下共同使用 |

每条线都写了输入、机器动作、正反控制、退化条件和下一项可检查实验。六条线用于保持广度，不是对所有可能悖论的排他分类。

尤其是 L3，它独立保留了你对时间与运动结构的关注；不会因为系统能够记录事件先后，就声称时间问题已经被覆盖。详见 [六条研究线与首轮实验](</Volumes/D/HoTT独立答复/HoTT非现实性悖论机器统观完整方案/005 - 六条研究线与首轮实验.md>)。

**五、现实对应审查必须独立于候选生成器。**

这是整份方案最重要的正确性要求之一。

机器必须分别回答：

- 原任务是否已经被改变？
- 困难来自 HoTT 的哪条规则、哪种表示选择或哪一步解释？
- 所谓补偿是从原输入恢复信息，还是预先保留信息，或新增了输入与规则？
- 现实侧完成的是一次操作，理论侧却是否被要求完成一个更强的全称任务？
- 原生证明所验证的命题，是否正是自然语言报告所声称的命题？

**形式命题成立与现实相对目标成立，是两项验收。** 内核负责前者的精确核验；后者还需要任务关系与证据。真实软件消费者是重要入口，自主提出合理任务同样是入口，不把两者互相设成普遍前置。

同时，候选程序不能修改目标模块、评价程序或可信规则；超时、类型拒绝、范围内无结果和已证不可能分别记录。运行隔离、哈希失效、取消、恢复、缓存、数据版本和现有 proof/run/index 的接入，都已写进 [证明证据与运行合同](</Volumes/D/HoTT独立答复/HoTT非现实性悖论机器统观完整方案/006 - 证明证据与运行合同.md>)。

**六、第一步是贯通真实搜索链，随后立即扩大覆盖。**

建议先用现有 delay／商／观察模型做校准：把定义和操作交给生成器，让它自动寻找候选，经缩减和原生核验后交出完整报告。已知答案只能用于校准，不能被硬编码成“自动发现”。

之后推进原生高阶搜索，再覆盖其它研究线，并用冻结搜索器之后确定的留出任务检验探索能力。验收既看新关系与关键未知，也看错误升级、换题、遗漏和复跑表现；不以候选数量或证明数量判成功。

实施分为 M0–M5，已经写明每阶段的真实交付、退出判据、暂不做的事项和初始可调整预算。详见 [实施路线、资源与验收](</Volumes/D/HoTT独立答复/HoTT非现实性悖论机器统观完整方案/007 - 实施路线、资源与验收.md>)。

**“完整”的含义也已经固定：规则来源、核心问题、指定搜索空间、证据链和研究流程分别有覆盖责任；不把有限搜索包装成对无限 HoTT 的穷尽。** 全部 36 条核心认知都有具体设计落点，另列了现实形式化、高阶适配、自描述与原创性等仍待解决的研究义务。

本轮已完成方案文档、来源整理和结构检查；九个分片、索引与本地链接通过核对，标准分片校验通过。**尚未安装或运行这套搜索系统，也没有新增 HoTT 数学证明。** 方案保存在 repo 外，未改动共享研究源码或状态，项目内仅追加本会话的对话归档。
