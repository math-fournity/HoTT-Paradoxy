我们可以放弃SOCKS5端口，你参考一下这个：我先核对目前仍在维护、适合把 VLESS 套在 Cloudflare Worker 上的仓库和文档，再整理成可直接交给另一个 AI 落地的方案。



下面是一份可直接转发给另一个 AI 的落地说明。只保留 VLESS。分两条链路：一条用 Worker 当入口、流量透传到你自己的后端（真正隐藏源站 IP）；一条是 Worker 自己当 VLESS 服务端（不暴露你的 VPS IP）。优先用第一条。



\## 目标



客户端只连 Cloudflare 边缘 IP / 你的自定义域名，不连已被 GFW 封禁的源站 IP。Cloudflare 终止 TLS，再用 WebSocket（或 HTTP Upgrade / XHTTP）把 VLESS 转到后端。源站防火墙只放行 Cloudflare 回源 IP。



\## 推荐架构（隐藏已有 VPS）


```
客户端 (VLESS + WS + TLS)
    → 自定义域名:443（Cloudflare 橙云 / Worker）
    → Worker 或 CDN 反代
    → 源站 Xray/sing-box（VLESS + WS，可只听内网或非标准端口）
    → 出网
```



不要用 Reality、裸 TCP、gRPC（除非确认该域名已开 gRPC）。Cloudflare 免费反代稳定支持的是 WebSocket。flow 必须留空，不要填 \`xtls-rprx-vision\`。



\### 源站（Xray）要点



- 协议：\`vless\`
- \`decryption\`: \`none\`
- \`network\`: \`ws\`
- \`security\`: 若前面是 CDN 橙云且 SSL 模式为 Full，源站可继续用 TLS；若 Worker 自己回源到 HTTP，源站可关 TLS，只监听本机或仅 Cloudflare IP 可达的端口
- \`wsSettings.path\`: 随机长路径，例如 \`/a1b2c3d4-vw\`，客户端必须完全一致
- UUID 与客户端一致
- 防火墙：只允许 [Cloudflare IP 段]\([https://www.cloudflare.com/ips/](https://www.cloudflare.com/ips/)) 访问该端口



\### Cloudflare 侧



1. 域名接入 Cloudflare，A/AAAA 记录指源站，代理状态为橙色云。
2. SSL/TLS 设为 Full (strict)；源站证书可用 Cloudflare Origin CA。
3. 不需要单独打开 WebSocket 开关，免费套餐默认支持。
4. 客户端 address / SNI / Host 都填这个域名，端口 443，不要填源站 IP。



若橙云直反代仍被干扰，再在同一域名上挂 Worker 做二次转发，参考下面的透传仓库。

  Worker 反代 Xray/sing-box 的 VLESS/VMess/Trojan，支持 \`ws\` / \`xhttp\` / \`httpupgrade\`。后端仍负责鉴权。TLS 在边缘终结，源站可走明文 HTTP。

  用 Worker 接收 WebSocket，再转到已有的 VLESS/VMess/Trojan 配置。

\## 客户端参数（两条链路通用）



\| 项 | 值 |

\| --- | --- |

\| 协议 | VLESS |

\| 地址 | 自定义域名，或 \`\*.workers.dev\` |

\| 端口 | 443 |

\| UUID | 与服务端一致 |

\| encryption | none |

\| flow | 空 |

\| 传输 | ws |

\| TLS | tls |

\| SNI / Host | 与地址域名相同 |

\| path | 与服务端完全一致，区分大小写 |

\| early data | 可选 \`ed=2048\`，path 常写成 \`/?ed=2048\` |



\## 交给另一个 AI 时的执行顺序



1. 生成 UUID 和随机 path。
2. 在源站用 Xray 或 sing-box 建 VLESS + WS，先本机自测。
3. 域名接入 Cloudflare，橙云，SSL Full (strict)，源站只放行 Cloudflare IP。
4. 客户端用域名直连验证。失败再部署 \`cf-xray-proxy\` 或 \`V-Bridge-Worker\`，把回源地址写成源站域名或仅 Worker 可达的地址。
5. 若没有可用源站，改部署 \`cmliu/edgetunnel\` 或 \`eooce/CF-Workers-VLESS\`，只改 UUID，自定义域名绑定 Worker，客户端按上表填写。
6. Worker 名称和路径不要带 \`vless\`、\`proxy\` 这类词。免费套餐有请求数和 CPU 时间限制，大流量会失败。



注意：用 Workers 做代理出口可能违反 Cloudflare 服务条款，账号有被限制的风险。\`workers.dev\` 在部分网络不稳定，优先绑自己的域名。这只能藏 IP 和套一层 Cloudflare TLS，不能保证长期不被干扰。
