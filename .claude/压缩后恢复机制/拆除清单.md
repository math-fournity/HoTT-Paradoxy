# 拆除清单：压缩后恢复机制

> **配套方案**：`方案.md`（同目录）。本清单只在任务结束或中止时使用。
> **原则**：先让它**自动失效**（段一，由执行会话完成，不需要人），再**清理文件**（段二，需要确认）。
> **状态**：本清单随方案一起落盘；机制尚未安装，因此清单目前不需要执行。

## 0. 触发与分支

| 任务终态（闭包 §4） | 是否拆除 | 做什么 |
|---|---|---|
| TOTAL_CLOSED | 是 | 段一 → 段二（段二需要确认）。 |
| PARTIAL | 否 | 保留 `ACTIVE` 与全部文件（还要恢复）。 |
| BLOCKED | 否 | 保留，直到研究发起人决定。 |
| 用户明确放弃任务 | 是 | 你删除 `ACTIVE`（段一的第 T1-2 步）；段二由设计会话按本清单完成，需要确认。 |

## 4. 回滚（拆错了时）

- 从提交恢复文件（只恢复文件，不切换分支）：`git checkout <提交号> -- <路径>`。
- 或从 `.claude/压缩后恢复机制/模板/` 复制回安装位置（方案第 8 节 I-5）。
- 恢复标记：`touch audit/GUI-ASSET-REAUDIT/ACTIVE`。

## 5. 不要做的事

- 不要在执行会话里删除或修改 `.claude/` 下的任何文件。执行规则禁止这样做，`.claude/` 的清理只由设计会话或用户完成。
- 不要用 `git stash`、`git checkout <分支>`、`git reset` 来"清理"。仓库里还有其他未提交内容（例如执行会话的产物）。
- 不要用 `rm -rf`。单个文件用 `unlink`，空目录用 `rmdir`。
- 不要把 `@` 导入当作替代拆除的手段（见方案第 3 节）。
- 不要使用 `git add -A` 不带路径的形式；只按路径暂存。
