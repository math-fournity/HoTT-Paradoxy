# 压缩后自动恢复机制：方案

> **状态**：方案已落盘，**未安装，未提交**（2026-10-07，会话 43345aa3）。
> **对应任务**：GUI 导出全量复算（规范 `dev-docs/GUI导出全量复算重读审计SOP.md`，闭包 `认知闭包/GUI-ASSET-REAUDIT-001.md`）。
> **配套文件**：`拆除清单.md`（同目录）；`模板/`（三个待安装文件，放在这里不会生效）。
> **判断的简版**：`.claude/思考与发现/CN-059 - 压缩后自动恢复：为什么不用 @ 开关.md`。

## 1. 问题与事实

- 2026-10-07，GUI 导出复算的执行会话（Claude Code，Haiku 5.5）在压缩后，凭压缩摘要里的记忆写分片路径。它写的 `001.md`、`001 - 冻结与身份.md`、`002 - 分块与行的定义.md` 等都不存在，读取失败；随后它改用规范索引里的全名，读取成功。
- 排查结果：分支没有切换（reflog 中唯一的 checkout 发生在执行会话开始之前）；失败只是找不到文件，没有改动任何东西。
- 原因：压缩后记忆中的文件名失真；恢复提示只写了"001 至 005 分片"，没有精确文件名；闭包的恢复算法也没有列出文件名；语料文件名很长（例如 `dev-08 - 20261005T140115Z-…-gui.md`），同样容易失真。

## 2. 要求

- 用户原话（2026-10-07）："不能总是靠着人去盯着。" 压缩之后，AI 应当自动拿回精确路径和恢复步骤，不需要人提醒。
- 不能长期污染其他会话：本仓库的其他研究会话不应受到这套机制的影响。
- 任务结束后要能干净地失效，并且可以拆除（见 `拆除清单.md`）。
- 不增加规范本体的维护负担：规范只有一份，不复制。

## 3. 方案比较

| 编号 | 方案 | 结论 | 理由（依据：Claude Code 官方文档，见第 11 节） |
|---|---|---|---|
| A | 把整份规范用 `@` 导入 CLAUDE.md，用完去掉 `@` | 不采用 | 导入在启动时整份展开，文档明确"导入不减少上下文成本"；规范索引加五个分片约 5.4 万字节（粗估 1–2 万 token）；仓库目前没有根目录 CLAUDE.md，要新建；放进 `~/.claude/CLAUDE.md` 则所有项目都背上；"去掉 `@`"要人工操作，忘了就影响所有会话；文档建议每个 CLAUDE.md 少于约 200 行。 |
| B | 只用 `.claude/rules/` 常驻规则 | 不采用 | 无 `paths` 的规则在每个会话启动时加载，污染所有会话；也解决不了"压缩后第一步就写错路径"。 |
| C | 用钩子注入整份规范 | 不可行 | 钩子的纯文本与 `additionalContext` 上限 10,000 字符；超过时输出被存成文件，只留 2,000 字符预览；文档原文是 Claude 能读那个文件，但 Claude Code 不会要求它去读（见第 11 节）。 |
| D | 路径作用域规则（`paths`）+ 压缩钩子（`SessionStart`，matcher 为 `compact`）+ 精确路径 + 标记文件开关 | **采用** | 规则只在 Read、Write、Edit 匹配文件时加载，压缩后再次接触匹配文件时重新加载；压缩后钩子触发，纯文本输出进入上下文；路径由文件系统生成，不会写错；标记文件让任务结束后自动失效。 |

## 4. 采用的方案 D

### 4.2 `ACTIVE` 标记的生命周期

| 时点 | 动作 | 由谁做 |
|---|---|---|
| CL-A2 第 7 步（写 `STAGE_START` 时） | 创建 `ACTIVE`（空文件） | 执行会话（需要闭包修订才会写进流程） |

| 状态为 PARTIAL 或 BLOCKED | **保留** `ACTIVE`（还要恢复，或等待决定） | — |
| 放弃任务 | 删除 `ACTIVE`（一个命令），钩子随之失效 | 你 |

### 4.3 压缩后的预期流程

1. 上下文被压缩（自动或 `/compact`）。
2. `SessionStart`（source 为 `compact`）触发钩子。若 `ACTIVE` 存在，钩子输出恢复提示：闭包路径、规范索引路径、五个分片全名、SESSION/seal-log/STATUS 三个文件、CL-BR2 步骤，以及"语料路径只从 `manifest2.json` 取"。
3. AI 按提示读闭包。读闭包属于 Read，于是路径规则加载（内容：精确路径来源、CL-BR2 要点、禁止事项）。
4. AI 读规范索引与五个分片，使用提示中的全名，不靠记忆。
5. AI 执行 SOP 005 §4 的 CL-BR2（protocol-echo、游标、RS 收据）；全部通过前不写入。

## 7. 已知限制与风险

1. **规则和钩子是上下文提示，不是强制约束。** 文档原话："Claude treats them as context, not enforced configuration." 硬拦截（禁止 `git log`、禁止写 `.claude/`）需要 PreToolUse 钩子，目前未设计，需单独立项。
2. **钩子输出上限 10,000 字符。** 当前输出约 1.1 KB，留有余量；以后加入更多内容时要检查长度。
3. **噪音范围。** `ACTIVE` 存在期间，本仓库任何会话压缩后都会收到这段提示（其他研究会话也会，约 1 KB）。缓解办法：只在任务期间保留 `ACTIVE`，任务结束即删除（第 4.2 节）。
4. **脚本成本。** 每次压缩都会执行一次 shell 脚本；`ACTIVE` 不存在时立即退出，开销可忽略。
5. **提示与规范的一致性。** 分片全名由脚本从文件系统生成，改名后自动跟随；但提示中的步骤文字（CL-BR2 要点）是手写的，规范改动时需要同步。
6. **不替代 CL-BR2。** 钩子只负责"拿回地图"；恢复的正确性仍然靠 SOP 005 §4 的 CL-BR2（protocol-echo、游标、RS 收据）。
7. **已在上下文中的内容不会因删除而消失。** 拆除只影响以后的注入。

## 11. 依据（Claude Code 官方文档，2026-10-07 查阅）

来源：`code.claude.com/docs/en/memory`（记忆）与 `code.claude.com/docs/en/hooks`（钩子）。以下为要点，关键句原文如下：

- 项目根 CLAUDE.md：「Project-root CLAUDE.md survives compaction: after `/compact`, Claude re-reads it from disk and re-injects it into the session.」
- 导入：「Imported files are expanded and loaded into context at launch alongside the CLAUDE.md that references them.」「…don't reduce its context cost, because imported files also load at launch.」
- 长度：「target under 200 lines per CLAUDE.md file.」
- 路径规则：「Path-scoped rules trigger when Claude uses the Read, Write, or Edit tool on a file matching the pattern, not on every tool use.」「Nested CLAUDE.md files in subdirectories and rules with `paths:` frontmatter load again on demand.」（指压缩之后）
- 性质：「Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.」
- 钩子的 source：`compact` 为压缩之后的启动来源；matcher 表中 `compact` 的说明为「Auto or manual compaction」。
- 纯文本：SessionStart 中「Claude Code adds plain-text stdout as context that Claude can see and act on.」
- 上限：「A hook's `additionalContext`, `systemMessage`, and `initialUserMessage` strings, and its plain stdout, are capped at 10,000 characters.」超出时：「Claude Code saves the output to a file in the session directory and replaces it with the file path and a preview of up to the first 2,000 characters.」「Claude Code doesn't ask Claude to read the file, so keep anything Claude must always see within the cap.」
- 路径变量：`${CLAUDE_PROJECT_DIR}` 为「the project root where the session started」。
