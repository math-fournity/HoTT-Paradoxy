## 0. 测什么，不测什么

- **测**：设计的每一项机制在真实 Claude Code 中是否按设计工作，尤其是压缩边界（手动 `/compact` 触发）之后，模型的行为是否遵从卡片与规范。
- **不测**：规范的学术内容（由人工审计负责）；第一次运行的笔记质量（由审计脚本与抽样负责）。

## 1. 环境与隔离

- **正式工作树** `.claude/worktrees/git-worktree-path-4c282f`（分支 `claude/gui-reaudit-continuation`，提交 `c598d05b`）：只做静态核对，不运行模型，不写入。理由：它是执行者的正式环境，任何测试产物（ACTIVE、账本记录）都会污染正式运行。
- **测试副本** `R = /Volumes/D/HoTT-reaudit-testrun`：`git clone --shared --no-checkout` 产生，与正式工作树同一提交、同一稀疏模式（语料、规范、闭包、存档）、同样的三件钩子（逐文件核对哈希）。删除 `origin`，使副本无法推送。所有模型驱动的测试都在 R 中进行。
- **会话形式**（修订 R2、R3）：主路径为桌面应用的 Code 会话，目录为 R，模型为 Haiku 5.5。CLI 的 `--setting-sources project,local` 会排除用户级 CLAUDE.md（`/context` 实测），与正式环境不一致，故不作主路径；CLI 仅用于不需要模型身份的机械检查，结果标注为 Haiku 4.5。
- **认证**：沙箱内 CLI 未登录（`loggedIn: false`，已核实）。桌面会话使用应用自身的登录，无需 CLI 的 `/login`；若改用 CLI，需研究发起人自行 `/login`。
- **模型**：CLI 2.1.291 不接受 `claude-haiku-5-5`（`unrecognized_model`，已核实），其 `haiku` 别名为 Haiku 4.5，且 Haiku 不支持 effort。桌面会话的 transcript 中 model 字段为 claude-haiku-5-5 即为核实（设计会话本身：499 条）。每个测试会话都须通过同样的核实，否则该会话作废。

## 2. 测试矩阵

每个 ID 给出：步骤、预期、证据来源。证据优先取自 transcript（JSONL）与文件系统，而非模型的自述。

- **A2** ACTIVE 存在，手动 `/compact`：卡片出现，列出 6 个分片全名（含 006），探针能逐字引用卡片全部行。证据：JSONL 标记串；卡片 669 字符、1201 字节（实测，见 CN-063 §3；原“约 1200 字符”的单位有误，R1）。

- **A4** ACTIVE 存在，`--continue`（resume）：无卡片。
- **A5** 删除 ACTIVE 后 `/compact`：无卡片（开关生效）。
- **A6** SOP 目录不存在时直接运行脚本：无输出（离线，不需要模型）。

## 5. 已知风险

- 副本使用 `--dangerously-skip-permissions`：可以执行任意命令。副本无远程、与正式工作树分离，但 R 与正式工作树同在一块磁盘上。测试中模型若使用绝对路径写入正式工作树，会被审计发现（测试前后对正式工作树做哈希快照）。
- `/compact` 为手动触发。自动压缩的时机无法精确控制；本计划不测自动压缩。
- 模型的行为有随机性。每个关键 ID 至少运行两次；两次结果不一致时记为 PARTIAL，并给出差异。
