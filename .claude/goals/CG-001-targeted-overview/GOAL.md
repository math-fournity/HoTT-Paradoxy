## 1. 目标与完成门

**父目标（用户原意，KC-000010、KC-000022、KC-000047、KC-000048）**：用 Think in HoTT 构造一个过程，推出现实中并不存在的困难（A：现实能完成，理论里完成不了），或者把现实完成不了的事当作已完成（B：绕过 ASK）。要像芝诺、罗素、圆环那样，有清楚的靶前提和针对性过程，理论侧要机器证明。重点是理论的非现实性，不是 HoTT 内部矛盾。

**本目标的路线**：不做全书式覆盖。
1. 先画一张 HoTT“便利地图”：整体层和机制层先行，添入的理想条件与省去、合并的条件两面都看。
2. 再以现实中的各种完成方式为主通道，生成种子句：理论为了 E，把 T 改成 T′；若做 P，预计 O 会变。
3. 最后挑排名靠前、机制不同的种子，逐个追到判词。

**成功标准**：交出诚实的结果。要么至少一个合格命中（QUALIFIED_HIT），要么在写明的范围内没有合格命中；无论哪种，都要说清这条路线看见了什么、没看见什么、下一步去哪。

**完成门**（六门全满足才可 `close --status COMPLETE`）：
1. **G-ALIGN**：开工对齐说明写在对话和工作台里，包括：实际读了什么及其指纹、一句原意复述、“已走过的路”清单（前几轮已关闭的机制，附出处）。
2. **G-MAP**：便利地图。每一项写明：精确位置（Book 节、规则或 Cubical 构造，附版本）；收益 E；被改条件 T→T′，注明是添入还是省去、合并；给外行的人话解释，以及从哪一句开始贴不上。地图要既有单条规则，也有共同取舍和整体层。每一项都要有处置：已出种子 / 暂无种子（写原因）/ 与已关闭机制重复（写出处）。
3. **G-SEEDS**：种子池。每个种子写一句 E／T→T′／P／O，并注明：现实过程类型、邻近对照（一个很像但不依赖 T 的任务）、查重判词（新 / 有差量 / 重复）。写明排名理由。
4. **G-PURSUE**：排名靠前、机制互不相同的种子，逐个追到判词：QUALIFIED_HIT、STRONG_CANDIDATE、BOUNDARY、REFUTED 或 OPEN_WITH_NEXT_STEP。至少追三个；合格种子不足三个时，写明其余便利为什么没有产生合格种子。每个种子都要有候选卡、前提敏感性检查、正控制和最强反解释。数学结论过 F-011，否则降格。
5. **G-OMISSION**：换一种组织方式（按 Book 章节或规则家族）再过一遍，找出便利地图漏掉的项，逐项处理或写明理由。
6. **G-REPORT**：最终报告，包含：命中状态；每个种子的判词和证据位置；结论账本（身份标注，加《最高指示-Claude版》§7 的两项自检）；方法对照（本路线与 MO3 覆盖路线各自看见了什么）；relay 清单；下一步。

**合格命中（QUALIFIED_HIT）的判据**，五条全满足：
- (a) 靶前提能在 HoTT 的精确规则或配置里定位。
- (b) 候选任务 X_i 的输入、允许操作、观察、完成标准，在现实侧和理论侧逐项对照；现实侧注明身份（实际过程、理想实验或比喻）。
- (c) 理论侧结果由原生证明器检查通过（F-011）。
- (d) 改变 T 的对照能让困难消失，即前提敏感。
- (e) 最强反解释已经处理：它不是“同成本、同任务下加个字段就能解决”的表示差异，不是一般可计算性界限的普通实例，也没有偷换任务。

“库里确实有人这样用”（自然使用者）是加强证据，不是门槛。只满足部分判据的记为 STRONG_CANDIDATE，写明缺哪一条。

**非目标**：不证明 HoTT 内部矛盾；不做父范围覆盖（那是 Codex Session C 的任务）；不把“没找到”说成“不存在”；不追求种子数量或 proof 数量。

## 6. 方法细则

### 6.1 便利地图怎么画

从原典出发：Book 原文 `HoTT/theory-schema/upstream/book-578b85cc/*.tex`（commit 578b85cc），项目 Schema `HoTT/theory-schema/CORE_RULES.md`、`DERIVED_STRUCTURES.md`、`EXTENSIONS_AND_METATHEORY.md`，以及 Cubical Agda 与 cubical 0.9 的实际定义。先写整体层（HoTT 作为一个整体为使用者省了什么），再写机制层，最后才是单条规则。

**起点清单**。每项都要回原典核实，可增可删；它不是结论，也不是配额：
- 单价性：等价即相同（结构同一原则）。
- 同伦不变性：一切构造自动尊重路径和等价，transport 保持一切。
- 证明相关的相等与高阶相等。
- HIT：用生成元和路径直接定义空间，例如圆 S¹ 不经点集和实数。
- 截断与命题：遗忘见证，只保留“有”。
- 函数外延性。
- 判断相等与计算：定义性化简、β/η。
- 宇宙与大小：累积层级、可选的 resizing。
- 可选公理（LEM、选择、Markov）的按需添加。
- 合成同伦论：不经拓扑和实数直接谈空间与连续。
- Cubical：区间 I、面格、Kan 组合、Glue。
- 证明即程序：完成、时间与资源不计。
- 实数与极限的构造（Cauchy、Dedekind、HIIT）。

每项都要写“添入了什么理想条件”和“省去、合并、提前交付了什么条件”两面；来源只支持一面时，写明另一面检索过、缺什么。

### 6.2 现实过程清单（主通道）

对每种过程，写清谁取得对象、谁操作、谁观察、谁宣布完成：
- 到达与运动：逐步逼近、分段完成。
- 形成与构造：一步步做出一个对象。
- 复原与逆操作：拆开后装回，走过去再走回。
- 挑选并交付：从一堆里拿出一个交给别人。
- 等待与可用：结果什么时候能读取。
- 计数与有限：数完、清点、有限次。
- 先后承诺：先答应甲，再处理乙。
- 比较与同一：两样东西是否“一样”，一样到什么程度。
- 观察与测量：精度、有限次观察。
- 命名与指称：用名字拿到东西。
- 验证与担保：谁来担保担保者。

只在过程与便利之间有语义联系时生成种子，并写明这个联系是什么。

### 6.3 排名

按五条排：
1. P 让 T 决定结果的直接程度。
2. 现实侧完成方式是否清楚到外行能懂。
3. 与已关闭机制的差异。
4. 理论侧能不能形式化。
5. A、B 两个方向是否都照顾到。

不要让“最容易证明”决定下一题。

### 6.4 深追与核证

- **候选卡**写明：理论位置 T、收益 E、X_i（输入、操作、观察 O、完成 Done）、解释桥、敏感过程 P、正控制、最强反解释、证据等级。
- **送证明器之前**先问：模型里真的有 T 吗？没有，就记 `MODEL_TARGET_LINK_OPEN`，先补桥或换模型，不扩大枚举。
- **原生证明**：
  - 工具链沿用 `HoTT/formal/dedekind-omega-missile/TOOLCHAIN.json`（Agda 2.8.0-3d04bac，cubical 0.9）。
  - 捕获用 `scripts/audit/capture_agda_proof_run.py`，校验用 `scripts/audit/verify_formal_proof_run.py --run-dir … --rerun`；用之前先看 `--help`。
  - 规范见 `docs/quality/数学结论机器证明与证据留存规范.md`。
  - 编号用本目标自己的前缀：proof 为 `MP-CG001-<名称>-001`，claim 为 `CG001-C-NN`，run 为 `YYYYMMDD-CG001-<名称>-NN`。
  - 本目标的索引写在 `证据索引.md`；进入 `HoTT/CLAIM_EVIDENCE_MATRIX.md` 的行只写成 relay 草稿。
  - 未进入共享矩阵、也未提交时，标 `LOCAL_UNCOMMITTED_NOT_VERSION_CLOSED` 或 `GOAL_LOCAL_INDEX_ONLY`。
- **允许的结局**：撤回、降为表示边界、换更敏感的过程、保留为条件命题、进入证明义务。正确拒绝不是 BUG。
