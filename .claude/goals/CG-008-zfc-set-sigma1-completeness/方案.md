## 3. P1 的关键判断（2026-10-11，闭包读完后的分析）

交接单 §4 给的路线是「在 `ZFCSetSigma1.lean` 内自建集合论 Σ₁ 完全性 + D3 内部化」。
读源码后，我得到的关键事实如下（每条都标出证据层级）：

### 3.1 `Provable` 的见证在 V 里，所以缺口两端是「V 内部可证性」

- `Provable T φ := ∃ d, Proof T d φ`，其中 `d : V`（`Syntax/Proof/Basic.lean:541`）。
- 因此 `Provable 𝗭𝗙𝗖 (⌜ψ⌝ : V)` 说的是「V 内部有一条 ZFC 推导 d，其结论是 ψ」。
  对非标准 V，这**严格弱于**真实的 `𝗭𝗙𝗖 ⊢ ψ`（后者是元层存在）。
- 缺口两端都是这种 V 内部可证性，且由 `models_zfcTr_iff`（`Z0Full.lean:67`，是 **↔**）与
  `V↓[ℒₒᵣ] ⊧ zfcTr τ` 逐字对应。**这是缺口坍缩的正确读法。**

### 3.2 `SetTheory.complete` 只产生外部推导，不能填这个桥

- `SetTheory.complete (T) (φ) (H : ∀ M ⊨ T, M ⊨ φ) : T ⊢ φ`（`Misc.lean:269`）。
- 它给的是**元层** `T ⊢ φ`。要变成 V 内部的 `Provable T (⌜φ⌝ : V)` 需要
  `internalize_provability`（`D1.lean:27`），后者要求**元层**前提 `T ⊢ φ`。
- 但缺口的前提是 V 内部的 `Provable 𝗭𝗙𝗖 (⌜translate τ⌝ : V)`，**不能**反向降成元层
  `𝗭𝗙𝗖 ⊢ translate τ`（那正是 `Z0Probe7` 证伪的载体墙）。
- **结论**：`complete` + `internalize_provability` 这条组合对缺口无用。

### 3.3 缺口的两端在 V 内部差一个「翻译保真」步

把缺口写成 V 内部语言（用 `models_zfcTr_iff` 双向翻译）：

```
前提：V↓[ℒₒᵣ] ⊧ zfcTr τ          （即 V 内部：ZFC 证明了 translate τ）
目标：V↓[ℒₒᵣ] ⊧ zfcTr (zfcTr τ)  （即 V 内部：ZFC 证明了 translate (zfcTr τ)）
```

由 `zfcTr_def`：`zfcTr σ = trProv.val/[⌜σ⌝]`，而
`trProv = .mkSigma “x. ∃ y, !iTDef y 0 x ∧ !(provable 𝗭𝗙𝗖) y”`（`Z0Full.lean:40`）。

所以在 V 内部，前提给出一个 `y` 使 `iTDef y 0 ⌜τ⌝ ∧ provable 𝗭𝗙𝗖 y`；
目标要求一个 `y'` 使 `iTDef y' 0 ⌜zfcTr τ⌝ ∧ provable 𝗭𝗙𝗖 y'`。

**这就是缺口的精确形状**：V 内部要把「τ 的翻译」的证明码 `y`，
转成「(zfcTr τ) 的翻译」的证明码 `y'`。这一步正是 ZFC 的**内部化 Σ₁ 完全性 / 反射**。

### 3.4 与 `iT_quote` 的关系（可用的正面工具）

- `iT_quote`（`InternalTranslate.lean:611`）：对每个算术公式 φ，
  `iT n ⌜φ⌝ = ⌜arithTrln.translate φ⌝`（在任意 𝗜𝚺₁ 模型 V 内）。
- 这把「翻译的编码」与「编码的翻译」在 V 内等同起来，是 §4 第 4 步的关键工具。
- 但要产生**证明码** `y'`，还需要 ZFC 在 V 内部对自身可证性的 Σ₁ 完全性——
  这正是 Foundation 未形式化的部分（`Z0D3Attempt.lean` 的结论）。
