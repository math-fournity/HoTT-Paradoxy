## 2. 测试环境：为什么改为桌面应用

CLI 路线有三处阻碍，均已核实：

1. **认证**：沙箱内 `claude auth status` 报 `loggedIn: false`；tmux 中的会话显示 `Not logged in · Run /login`。登录只能由研究发起人本人完成。
2. **模型**：CLI 2.1.291 对 `claude-haiku-5-5` 报 `unrecognized_model`；`/model` 菜单对 Haiku 只给出 Haiku 4.5，并标注 `Effort not supported for Haiku`。
3. **用户级设置**：`--setting-sources project,local` 排除了用户级 CLAUDE.md。`/context` 实测：rt（用了该参数）无 memory 文件；rt2（默认设置）列出 `~/.claude/CLAUDE.md`，156 tokens。计划 §1 的假设与此相反，已更正（R2）。

桌面应用的 Code 会话没有这三处阻碍：

- 本设计会话即为桌面会话。其 transcript（`~/.claude/projects/-Volumes-D-HoTT-AI-HANDOFF-20260911/43345aa3-34f4-420f-9b5e-37f4840ffa91.jsonl`）中，`model` 字段为 `claude-haiku-5-5` 的记录有 499 条【证明】。
- 桌面会话加载用户级 CLAUDE.md 与用户设置，与正式环境一致。
- 钩子只来自 R 的项目设置 `.claude/settings.json`。
- effort：Haiku 不支持 effort。桌面端若显示 effort 选项，保持默认并如实记录所见。因此 "max thinking" 无法满足，这是环境限制，不是遗漏。

R 的 transcript 目录（`~/.claude/projects/-Volumes-D-HoTT-reaudit-testrun/`）里已有 rt、rt2 的 CLI 记录，内容是未登录的界面，无实质内容。分析时按文件时间区分。
