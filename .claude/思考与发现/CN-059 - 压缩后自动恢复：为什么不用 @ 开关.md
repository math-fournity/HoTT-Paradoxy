# CN-059 · 压缩后自动恢复：为什么不用 @ 开关，改用标记、路径规则与压缩钩子

> **身份**：【来源】（Claude Code 官方文档条目，2026-10-07 重新核对）、【证明】（本地钩子输出测试，有范围）、【判断】与【建议】。
> **会话**：43345aa3，2026-10-07。
> **完整方案**：`.claude/压缩后恢复机制/方案.md`；拆除清单：`.claude/压缩后恢复机制/拆除清单.md`。

## 1. 事实

- 2026-10-07，GUI 导出复算的执行会话在压缩后，凭压缩摘要写分片路径，5 个路径不存在，读取失败；随后改用索引全名读取成功。分支没有切换（reflog 为证）。
- 原因：压缩后记忆中的文件名失真；恢复提示只写了"001 至 005"，闭包也没有列出精确路径。

## 2. 用户的提议

把规范用 `@` 导入 CLAUDE.md，压缩后自动加载，用完去掉 `@`。

## 3. 判断：不采用

- 有效的部分：文档说项目根 CLAUDE.md 在 `/compact` 后会从磁盘重读并重新注入，导入的文件随之展开，所以压缩后确实能回来。
- 不划算的部分：导入在启动时整份展开，文档明确"不减少上下文成本"；规范约 5.4 万字节；仓库没有根 CLAUDE.md，放进全局则所有项目都背上；"用完去掉 `@`"需要人工，忘了就影响所有会话；文档建议每个 CLAUDE.md 少于约 200 行。
- 所以问题不在"能不能回来"，而在"代价和人工开关"。

## 4. 发现：钩子只能放地图，不能放整份规范

- 钩子的纯文本、`additionalContext`、`systemMessage`、`initialUserMessage` 各自上限 10,000 字符（文档：每个字符串单独计量，纯 stdout 整体计量），文档说这个上限没有可以提高它的设置或环境变量。超过时输出存成会话目录里的文件，只留最多 2,000 字符预览。文档原文：「Claude can read the file, but Claude Code doesn't ask it to.」即 Claude 能读那个文件，但 Claude Code 不会要求它去读。
- 因此钩子适合放"地图"（精确路径、步骤、禁止事项）。整份规范仍然要靠 Read。

## 5. 采用：标记 + 路径规则 + 压缩钩子

- 标记文件 `audit/GUI-ASSET-REAUDIT/ACTIVE` 作为总开关：CL-A2 时创建，TOTAL_CLOSED 时删除；钩子只在它存在时输出。测试：不存在时 0 字符，存在时 1,081 字符，删除后 0 字符。
- 路径规则（`.claude/rules/gui-reaudit.md`）只在读写匹配文件时加载，压缩后再次接触时重新加载（文档）。
- 压缩钩子（`SessionStart`，matcher 为 `compact`）在压缩后输出恢复提示，文件名由文件系统生成。

## 6. 为什么用标记，而不用"工作区存在"

工作区（`ledger2.jsonl`）在任务结束后仍然存在。若用它做开关，任务结束后钩子会一直输出。标记可以在任务结束时删除，钩子随之自动失效。

## 7. 未验证

- 压缩后钩子输出是否进入上下文；规则在读闭包时是否加载；中文路径的 glob 是否匹配；运行中的会话是否需要重启才生效。以上都要在新会话里实测（方案第 9 节）。
