# 使用与维护规则

> 2026-09-24 由 Claude（Opus 5.5，会话 6fd0312a）按用户要求建立。用户原话：“要有一份总的索引入口索引所有工作、思考和发现，并且被不断地追加、更新，这份总索引的目标，以后接手工作的AI也要知道对它的使用、维护。”

## 1. 目的

本索引把 Claude 在本仓库的全部工作、思考和发现串成一个入口，回答五个问题：

1. 做过什么：会话、目标包、交接、中继、工作台。
2. 证明了什么：证明包、运行、命题编号。
3. 想到了什么：思考、发现、判断、旁证，统一用 CN 编号。
4. 现在停在哪里：待用户裁定、待 integrator、下一步、Git 状态。
5. 按什么顺序发生：工作日志。

它是路由，不是证据。每一行都指向底层文件，结论的身份以底层文件为准：
- 用户原意：`核心认知.md`（唯一权威）。
- 数学结论：证明包 `CLAIM.md`，加上运行目录 `RUN.json` 与精确重放。
- Claude 的操作指令：`最高指示-Claude版.md`。

索引与底层文件冲突时，以底层文件为准，并在 005 追加一条更正。

## 2. 谁读、何时读、怎么读

- **谁读**：每个 Claude 会话，以及任何接手 Claude 这条工作线的 AI（包括 Codex 会话和独立审计者）。
- **何时读**：
  - 开工、恢复或压缩之后，在依赖旧上下文作判断之前；
  - 用户问“做到哪了”“有哪些发现”“下一步做什么”时。
- **怎么读**：按分片表顺序读全文；本索引体量不大，全文读取是默认做法。按 `docs/quality/长治理文档分片与索引合同.md`，不得把索引首页、第一片或最后一片当作全文。
- **读完以后**：要做研究，仍须按 `AGENTS.md` 与 `.claude/rules/hott-claude.md` 的档位读四件套与《最高指示-Claude版》。本索引不豁免任何开工闭包，也不能代替回到原文。

## 3. 何时维护、怎么维护

**时机**（任一发生即维护）：
- 一个工作单元结束，例如一个证明包过核、一份笔记写完、一个判断形成；
- 会话结束前，或上下文接近压缩之前；
- 用户作出纠正、裁定或给出新原话之后；
- 发现索引与底层文件不一致时。

**方法**：

| 分片 | 写法 |
|---|---|
| 002 当前状态 | 原位更新。改前读全片；改后在片首写明更新日期与会话。旧状态由 Git 与 005 保留，不追加“最新版”覆盖块。 |
| 003 工作与证据登记 | 只追加行。已有行状态变化（提交、作废、被取代）时改该行的“状态”列，并在 005 记一笔。不删行。 |
| 004 思考与发现登记 | 只追加行。被推翻或修正的条目不删，把“状态”改为 `REVISED → CN-xxx` 或 `WITHDRAWN（原因）`。 |
| 005 工作日志 | 只追加（本逻辑文档的 `append_target`）。更正也写成新条目，不改旧条目。 |

**先落盘，再登记**：思考和发现先写成文件，再在 004 登记。文件可以是 `.claude/思考与发现/CN-NNN - 标题.md`，也可以是工作台、证明包 `CLAIM.md` 中的一节（写明节号）。只在对话里说过的想法，不算已登记。

**新建分片**：某片过长、妨碍定位时可以新建分片，但必须在同一次提交里同步更新分片表、`last_shard` 与 `append_target`。日志片满了，就新建下一片“工作日志（续）”，把 `append_target` 与 `last_shard` 都改到它。改完运行 `python3 -B scripts/audit/verify_governance_shards.py`，结果须为 PASS。

## 4. 编号

| 证明包命题 | `CG001-C-NN`（沿用 CG-001 前缀，连续） | 003 片首 |

| 运行 | `YYYYMMDD-CG001-<名称>-NN`；负控制加 `-NEG` | —— |
| Claude 目标包 | `CG-NNN-<slug>`，放在 `.claude/goals/` | 该目录 |

编号一经发布不复用。

## 5. 身份标注

每个判断都要带身份，量词与强度照实写：
- 【原话】用户原文；
- 【来源】已核对的书、库、论文；
- 【证明】有范围的机器证明，写明工具链与运行；
- 【解释】AI 解释；
- 【猜想】未证；
- 【建议】设计建议。

## 6. 写入边界

- **可以写**：本索引与它登记的 Claude 自有文件，即 `.claude/` 下各目录、`HoTT/formal/claude-cg001/`、名字含 `-CG001-` 的运行目录。
- **不写**：研究 STATE、MEMORY、方向追踪、全景视野、核心认知、`HoTT/CLAIM_EVIDENCE_MATRIX.md`、各 Session 目录，以及他人未提交的文件。需要登记到这些共享 owner 的内容，写进 002 的“待 integrator”，作为 relay 交出。
- **Git**：只在用户授权时按精确路径提交；不 push、不 tag、不发布。工作分支是 `dev`；`main` 只放结论与证据，只由 `scripts/release/build_main_release.py` 从 `dev` 生成，推送要用户授权（`rulings.md` 2026-09-30 末节）。
- **其他**：不调用 Agent 工具（项目裁定）。数学结论交付前过 F-011。

## 7. 与其他机制的关系

| 机制 | 位置 | 与本索引的关系 |
|---|---|---|

| 探索工作台 | `.claude/explore/` | 单次会话的过程记录；稳定的发现要抽成 CN 笔记 |
| 思考与发现笔记 | `.claude/思考与发现/` | CN 笔记的正文 |
| 证明包与运行 | `HoTT/formal/claude-cg001/`、`HoTT/verification/runs/*-CG001-*` | 003 登记；目标内索引在 `.claude/goals/CG-001-targeted-overview/证据索引.md` |
| 自动记忆 | `~/.claude/projects/…/memory/`（仓库外） | 只作 Claude 跨会话的提示；仓库内的状态以本索引为准 |
