# 设计总纲：分级治理与两族原理的完成

## 一、v5 要解决的三件事（与 v4 的差距）

1. **强度只有一档**（用户 2026-09-18 警觉的根源）：v4 对一切非平凡任务收同一笔
   全额闭包税（governance ≈41.3 万 / research ≈49.7 万 est tokens），而五种失败
   模式在任务间分布并不均匀——轻任务付了它用不上的保险费，重事务又被自己的
   重量压到被绕过（S170–176）。**v5 答：T0–T3 分级**。
2. **宿主单绑**：整套资产放在 `.codex/`，文档叙事写"Codex 数学研究治理框架"，
   ZCode 侧没有正式入口——同一 repo 两套宿主只能各玩各的。**v5 答：宿主中立的
   单一真值树**（分片 002/003）。
3. **三处保真义务无容量配套**（机制报告 009 的诊断）：STATE 全文常驻、压缩全额
   重付、不变量平级复述。**v5 答：热/冷拆分、收据制复认、复述改指针**——
   不是放弃保真，而是把"重付字节"升级为"可验证的持有证明"。

## 二、T0–T3 分级设计（核心新机制）

定级变量：**主张风险 ×（自治程度 × 视界长度）× 状态改写**。四档：

| 档 | 判据 | 启动加载（v5 后 est tokens） | 结束义务 | 硬门禁 |
|---|---|---|---|---|
| **T0 lite** | 只读/单会话/无主张/可重来 | AGENTS + MEMORY/001 队列片 + 任务文件 ≈**1.5 万** | 无（对话内交代） | 来源边界；禁 Sub Agent；不 push |
| **T1 standard** | 写代码/文档；无数学主张 | 瘦身启动核 + latest/active ≈**4 万** | 轻量 SESSION.md + 触及集复认 | + 写回归属表；validator |
| **T2 research** | 数学研究/系统化探索 | research 集（切档后）≈**12 万** | 分片审计集（触及集计量） | + 四件套全文；完备性回评 |
| **T3 mutation** | checkpoint/数学结论/core 更新 | 全量 | 全量 KC 审计 + 原子事务 | + F-011 机器门禁；result.json 收据 |

升降级规则：任务中途升级（如 T1 里冒出数学结论）→ 立即升 T3 门禁，不允许
"先交付后补证"；降级需用户裁定。档位由 AGENTS 路由表判 + 会话首条声明 +
SESSION.md 记录（可审计是否越档）。

**为什么更好**：(a) 你的"其他 AI 不走框架也能工作"观察被制度化——那些任务
本来就该走 T0/T1，v4 却按 T2 收税；(b) S170–176 消融实验证明执行纪律可低成本
替代、状态机不可绕过——T0/T1 恰好只卸执行仪式、保留状态门禁；(c) 低档位
不再是"违反合同"，消除绕过的道德成本，收据链反而更完整。

## 三、压缩与跨会话：收据制复认（替代全额重付）

v4：`FULL_SET_EVERY_SESSION_AND_COMPACTION` → 每次压缩重付 49.7 万。
v5：压缩后重付 = 启动核（按档）+ **持有收据复认**——逐文档核对 sha256 未变 +
逐 KC 一行复认（46 行 ≈2–3K）+ 抽查 N 段原文。全文重付只在三触发器下发生：
core_sha256 变化 / 档位升级 / 用户指令。复认记录入 SESSION.md（可审计）。
**为什么更好**：v4 的重付买的"防摘要失真"由 hash+复认以常数成本达成；
runtime 本来就声明 `NOT_CERTIFIED_BY_TOOL`——重付从未买到过它想要的认证，
复认买到的证据强度相同（_bytes-match 收据 + 模型公开复认文本）。

## 五、非目标（明确不做）

不做常驻审计 AI、不做数据库/平台、不引入每函数 trace（PROTOCOL §7 原则延续）；
不削弱证据纪律（归档≠删除，一切冷档 query-first 可达）；不动核心认知的
curation/generation 机制（机制报告 005：它是全框架纪律最好的部件，作为 C7 的模板）。
