# 宪法层重设计：指针化与分档路由

（对应《机制报告》002：根 AGENTS 与 .codex/AGENTS 的调查结论）

## 1. 根 AGENTS.md

**原来存在什么问题**（机制报告 002 实测）：宪法里嵌入了会过时的事实——正文
写死"generation-4/36 KC"，而权威 STATE 已是 generation-7/46；这是"指针宪法"
设计的自我违反。此外宪法只有一档强度：所有非平凡任务被引向同一个重闭包
（用户的警觉即由此而来）；任务路由表没有"轻任务"出口。

**打算如何调整**：重写为三层结构（目标 ≤5,500 est tokens，现 ≈6,000）：

1. **身份与硬边界**（≈1,500）：工作根、来源边界、禁 Sub Agent、不 push、
   数学门禁与分片合同的一句话指针（不再内嵌全文级长节——两大合同正文
   已有 owner 文档，宪法只留触发条件+指针）。
2. **分档路由表**（≈1,200）：任务类型 → T0–T3 档位 → 各档读什么/写什么/
   过什么门禁（替代现"任务路由"节的单档重路由）。T0 行是新增的合法出口：
   "只读/单会话/无主张 → AGENTS+MEMORY/001+任务文件，即可开工"。
3. **指针区**（≈800）：核心身份（generation/KC 数）**只写**"从
   `STATE.current_core` 动态取得"，全文禁止出现具体代数/KC 数（机械检查：
   validator grep `generation-\d` 在 AGENTS 内必须零命中）。

**为什么调整后更好**：宪法回归"稳定层"本位（机制报告 001 的分层判定逻辑：
宪法要稳、状态放权威源）——代数漂移这一类缺陷被结构性消灭而不是靠人同步；
分档路由表把你的消融观察制度化为合法低档，轻任务不再"违反宪法或付重税"
二选一；体积不增反减，注入成本（两宿主每会话）同步下降。

## 2. `.codex/AGENTS.md`（原位降格为导航页）

**原来存在什么问题**：它是"复述式不变量清单"——90% 内容与
PROTOCOL/LOAD_SET/Skill 重复；实测已与根 AGENTS 在核心事实上互相矛盾
（gen-4 vs gen-7）。复述防漏的收益 < 平级同步的成本（机制报告 002 的平方定律）。

**打算如何调整**：降格为**入口导航页**（≤60 行）：目录树一览 + 各文件的
唯一职责一句话 + "一切规则以 owner 文档为准，本页不复述任何规则/数字"。
不变量的唯一权威收敛到 PROTOCOL v3 的"invariant 章"（一处定义，处处引用）。

**为什么调整后更好**：不变量从 N 处复述变 1 处定义——同步成本从 O(N) 降为
O(1)，gen-4/7 类冲突失去存在条件；导航页内容天然稳定（目录结构变更频率远低于
规则/事实），符合其所在层。代价是读入口时少一次"重点预告"，但这正是
PROTOCOL 全文必读所覆盖的——复述本来就没有提供增量信息。

## 3. 配套：validator 新增两条机械检查

(a) AGENTS 类文件（根 + `.codex/AGENTS.md`）不得内嵌动态事实（generation-N/KC 数/
revision 数）；(b) 治理正文不得出现宿主排他措辞（分片 003 的 R3）。
**为什么**：本方案的两个"结构性消灭"都需要机械守门，否则随时间回归
（本 repo 的既有教训：纪律没有 validator 支撑时，S170–176 式漂移必然复现）。
