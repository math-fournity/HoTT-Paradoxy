# 研究层重设计：三文档切档与触及集审计

（对应《机制报告》008：业务 Skill / 三问 / FRONTIER / LESSONS / RESUME 的调查结论）

## 1. 业务 SOP（hott-paradox-research，≈10,400 tokens）

**原来存在什么问题**：机制报告 008 判定其设计良好（方法论合同化、决策点
结构化），主要问题是历史沿革章节（v1.3→v1.9 六节）占正文约 1/4——
它们是方法论进化史，消费方式是"追溯时查"而非"每轮研究重读"。

**打算如何调整**：沿革六节移入 `references/version-history.md`（按需），
正文保留现行有效的方法论（≈7,500 tokens）；**原位**于 `.codex/skills/`（2026-09-18
修订：树不迁移，Codex 项目级发现零损失），
frontmatter 保留（Codex 发现兼容），措辞宿主中立化。

**为什么调整后更好**：研究档再省 ≈3K；现行方法与历史考据分层——与
本方案"按消费方式定层"的总原则一致；方法论内容零删减。

## 2. 三问（≈12,378 tokens）

**原来存在什么问题**：无——机制报告 008 定位它是"历史定本"（问题意识锚，
自我声明有阅读边界），定本类文档本就该整体常驻。

**打算如何调整**：**不动**。**为什么**：定本无增长性、无漂移面；
它的作用（每轮研究从"为什么"出发）依赖全文在场——这正是"保真与容量
不冲突"的另一例（体积恒定、价值恒定）。

## 3. FRONTIER（≈13,000）/ LESSONS（≈20,000）/ RESUME（≈33,000）

**原来存在什么问题**（机制报告 008）：三件停留在"前治理"的滚动形态——
FRONTIER 滚动膨胀；LESSONS 全量常驻（教训的价值在"遇到情境时想起"，
支付却在每轮）；RESUME 停止点层层叠叠且与 MEMORY/001、FRONTIER、
STATE.latest 职责四方重叠（同一"现在在哪"有四个半权威版本）。

**打算如何调整**：三件统一切档为"hot 节 + 冷归档"：

- **FRONTIER** → `FRONTIER.md`（当前前沿 ≈5K，原位改写）+ `FRONTIER/log/`
  （历史里程碑按 S 号分文件，query_first）。
- **LESSONS** → 索引 + 情境路由表（每条教训一行：情境关键词 + 所在分片）
  + `LESSONS/` 分片（≈2 万 tokens 全保留，query_first 按情境水合）；
  研究档只载索引+路由表 ≈2K。
- **RESUME** → 只保留"固定恢复流程"节 + **当前**停止点（每轮覆写 ≈3K）；
  历史停止点全部移 `RESUME/log/`（query_first）。职责合同重写：
  队列=MEMORY/001、前沿=FRONTIER hot、停止点=RESUME hot、指针=STATE.hot
  ——四方各写各的，禁止互载（消灭五重复制的一端）。

**为什么调整后更好**：research 附加从 ≈84,127 降到 ≈**2.5 万**（业务 SOP
7.5K + 三问 12.4K + FRONTIER hot 5K + LESSONS 索引 2K + RESUME hot 3K ≈
30K，含三问定本后 ≈3 万）；全部历史零删除（log/ 只增不改）；教训的
"情境水合"正是 STATE 已验证的 query-first 模式——研究层从"前治理形态"
升级到框架其余部分早已达到的形态。

## 4. 审计触及集计量（020 合同的深化）

**原来存在什么问题**（姊妹报告 007）：分母=全部 46 KC 而非触及集——
一轮碰 2 条也要为 44 条写带论证的 NOT_TOUCHED；S-175 已自发采用"重写 11 条
+指针沿用"但未成合同。

**打算如何调整**：合同化为三段式——(a) 触及集/张力延续集/裁决延续集逐条
五元组（现格式不变，含反证条件）；(b) 其余 KC 一行一条 `NOT_TOUCHED`
+ 下次触及条件（免五元组展开）；(c) 扩展认知逐段回评同样按片触及计量。
S-174/S175 的实践 retro-fit 为标准格式。

**为什么调整后更好**：审计集稳定在 ≈8K 以内（S-175 的 12,643 → 预计 ≈8K，
历史 13 万格式永不回退）；PROTOCOL §4 的立法本意（"每条 KC 每轮都有一个
可审计立场"）完整保留——NOT_TOUCHED 清单仍是逐条立场，只是表达密度
与信息量成正比；这是把"大量 NOT_TOUCHED 是诚实结果"的合同原文翻译成
与其诚实价值相称的成本。
