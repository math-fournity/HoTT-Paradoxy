1. 每项状态 ∈ `DONE / PARTIAL / BLOCKED / SKIPPED`；勾选 `- [x]` 时必须在行尾
   追加 `→ 证据：<路径或命令摘要>`。
2. `SKIPPED` 必须附用户 ruling（日期+原话出处）；`BLOCKED` 登记缺口与解锁条件，
   **不得绕过或代之以等价小动作**。
3. 阶段验收门（G-P0…G-S）是该阶段全部项非 BLOCKED 的必要条件；过门后立即做
   阶段自审计：逐项核对状态+证据，审计记录落当轮 dev-note，并在 commit message
   引用本文件与阶段号。
4. 涉及 `~/.zcode`/`~/.codex` 全局层的项走 maintainer 流程（基线+备份+验证），
   不 push。
5. 命令均在本 repo 根执行；est tokens 一律用 `Codex治理框架报告/measure_context.py` 复算。
