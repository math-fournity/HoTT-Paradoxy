## 四、核心证据问题：`M` 条目数恒定不能证明 tracked owner 未改变

### 4.1 GLM 的推论

GLM 记录四个时点：

```text
161 untracked + 38 M
166 untracked + 38 M
168 untracked + 38 M
169 untracked + 38 M
```

然后从 `M` 数量始终为 38 推出：

```text
NO_NEW_TRACKED_FILE_MODIFICATION_OBSERVED_ACROSS_FOUR_ROUNDS
/ UNDECLARED_OWNER_CHANGE_RESTRICTED_TO_PREEXISTING_38_MODIFIED_SET
```

这个推论不能由所列证据支持。

### 4.2 计数恒定没有排除的变化

即使 `M` 的数量始终为 38，仍可能发生：

1. 这 38 个既有 dirty 文件中的一个或多个继续被修改；
2. 一个原 dirty 文件恢复到 index/HEAD，另一个新 tracked 文件变 dirty，数量仍为 38；
3. 同一路径的内容、行数或 hash 发生变化，状态仍只显示一个 `M`；
4. staged/unstaged 组合改变但被粗计数合并；
5. rename、typechange 或其它状态在 `awk` 归类中没有保留路径与两列状态语义。

当前关键 owners 中，STATE、方向、全景、MEMORY、Feature、rulings 等已经属于这 38 个既有 modified 路径；根 `goal.md` 则是未跟踪文件，`核心认知.md` 与思想展开正文不在当前 modified 清单。前一组既有 dirty owners 若在文本轮次中再次变化，`M` 数量不会增加；未跟踪 owner 的内容变化也不会从默认折叠计数中被可靠识别。因此，“数量恒定”不能回答 N5 最关心的 owner 字节是否变化。

### 4.3 untracked 增量也不能与创建文件数量粗对账

默认 `git status --porcelain` 对未跟踪目录通常会把整棵目录折叠为一个条目。`GPT的回应/`、`GLM的回应/` 已经是未跟踪目录；在其中新增第二、第三份文件不一定增加 untracked 条目。`.codex/research/hott/sessions/` 下新增一个独立子目录则通常增加一个条目。

所以 `+1～+5` 与“实际创建的文件／Session 数量级吻合”不是可靠的逐文件归因证据。

### 4.4 这条证据实际支持什么

现有历史观测最多支持：

```text
TRACKED_MODIFIED_ENTRY_COUNT_REPORTED_STABLE_AT_38
/ UNTRACKED_ENTRY_COUNT_INCREASED
/ PATH_SET_AND_CONTENT_HASH_NOT_CAPTURED
```

它不能把 N5 从 self-report 升为 `PARTIAL_INDEPENDENT_CORROBORATION`。GLM 可以说“没有观察到 tracked modified 条目数增加”，不能说“没有观察到 tracked 文件新增修改”。

### 4.5 怎样取得真正的部分独立佐证

未来轮次应在动作前后保存：

1. `git status --porcelain=v1 -uall` 的完整路径与两列状态；
2. 所有 current-owner 文件的 SHA-256 manifest；
3. index 与 working-tree diff name-status；
4. 当前任务允许写入路径的白名单；
5. 实际 patch／tool receipt；
6. 前后 manifest 差异。

只有这样才能支持：

```text
NO_CURRENT_OWNER_BYTES_CHANGED_DURING_THIS_UNIT
```

即使有这些证据，也只能证明该工作单元的文件变化，不能证明不存在未记录的外部写者，除非另有 writer／进程边界。
