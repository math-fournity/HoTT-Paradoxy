## 三、潜势层／兑现层：接受，但要进一步分为三层

GLM 从 Z owner §2.6.1 与 §2.6.2 提取“潜势层／兑现层”，这一贡献成立。它解决了两个相反误读：不能用尚未兑现来否定已经机器证明的非因子化，也不能用非因子化来冒充具体 HoTT 悖论。

为了不让“潜势层强律实例”再次变成过强标签，需要分成三层：

### P0：一般非因子化骨架

形式：给定 `α(w₀)=α(w₁)` 且 `J(w₀)≠J(w₁)`，`J` 不通过 `α` 因子化。

证据：C-59–C-66 及其具体模型。

意义：证明“所选抽象没有保存所选观察量”。

限制：它不自动说明 `α` 是 HoTT 特有、不说明 `J` 是现实同任务必要量，也不说明任何人实施了完成／现实提升。

建议判词：

```text
Z_TECHNICAL_NONFACTORIZATION_INSTANCE_WITH_SCOPE
```

### P1：HoTT 相关的潜势实例

除 P0 外，还要求：

1. `α` 来自精确 HoTT／Cubical 构造或规则；
2. 合并／不可恢复性质由相称机器证据支持；
3. HoTT 相关性与 HoTT 必要性分开声明。

C-124–C-148 的 SIP、univalence、truncation／无统一选点比一般 cost 或在线模型更接近这一层；C-71–C-99 中的部分机制仍可能主要是一般商、过程或外延表示现象。

建议判词：

```text
HOTT_RELATED_POTENTIAL_INSTANCE
/ PROMOTION_SOURCE_OPEN
/ REALITY_BRIDGE_OPEN
```

“HoTT 相关”仍不是“HoTT 特有”。只有消融表明关键结论依赖 HoTT 构造，才能增加 `HOTT_ESSENTIAL_WITH_SCOPE`。

### A1：已兑现的现实相对候选／实例

要求完整通过 Z owner §2.6.2 五项，并另行通过 Goal 的 HoTT 必要性、同任务、自然／来源 consumer 与反解释门。

建议状态顺序：

```text
POTENTIAL_INSTANCE
→ PROMOTION_SOURCE_FOUND
→ SAME_TASK_BRIDGE_ESTABLISHED
→ HOTT_ESSENTIALITY_ESTABLISHED
→ REALITY_RELATIVE_WITNESS_WITH_SCOPE
```

因此，GLM 可以把阶段 A 改成“潜势层机器证据综合”。但不能写“Z 强律已经被机器证明”。现有结果证明的是若干具名 `α,J` 的技术实例；`Z_STRONG_PHILOSOPHICAL_LAW` 对所有 proper abstraction 的上位断言仍是用户哲学原则和开放的外部形式化边界。

## 七、`stuck-transport` 的剩余分歧：HoTT 相关性不等于机制特有性

GLM 接受 family 写错和六层证据区分，同时保留“公理式 univalence 使 Book HoTT 出现 canonicity 问题”的研究方向。这条线可以保留，但必须用对照区分两个命题：

1. **HoTT 相关性**：当前不透明常量恰好是 univalence 公理，因此该例与公理式 HoTT 的计算呈现相关；
2. **机制特有性**：项停止在不透明常量处是否是 univalence 独有，还是任何无判断计算规则的公理都会产生。

修正后的校准至少需要：

- 使用真正依赖类型的 family，例如先审查 `X ↦ X`；
- 固定 exact calculus、universe、equality、K/UIP 条件；
- 记录公理式版本的 reducer 结果；
- 构造一个与 univalence 无关的不透明公理控制；
- 构造纯 MLTT 与 Cubical 版本的正向对照；
- 区分“不是 constructor normal form”“不能判断归约”“可命题证明行为”“canonicity 元定理失败”；
- 不用一次求值记录证明一般 normalization／non-normalization。

若 arbitrary-axiom control 产生同型 stuck 行为，则机制判词应为：

```text
GENERIC_OPAQUE_AXIOM_COMPUTATION_BOUNDARY
/ UNIVALENCE_INSTANCE
```

只有进一步证明 univalence 的特定原则造成控制中没有的现象，才能提升 HoTT-essentiality。S052/N10 的编译结果仍只属于固定实现和后端，不与理论 canonicity 合并。
