### 4.1 十条当前哈希均能重放

当前执行标准校验：


### 4.2 声称 11 个 owner，实际为 10 个

实际哈希路径：

1. `goal.md`
2. `核心认知.md`
3. `.codex/research/hott/STATE.json`

### 4.3 逻辑文档只固定 index，未固定正文

项目治理明确规定：

```text
逻辑文档全文 = index + table 顺序中的全部 shards
```

baseline 只含：

- `方向追踪.md` index；
- `全景视野.md` index；
- `MEMORY.md` index。

它没有包含：

- `方向追踪/001`–`005`；
- `全景视野/001`–`008`；
- `MEMORY/001`–`003`。

当前多个实际内容 shard 已是 dirty 状态。未来若只改 `方向追踪/005`、`全景视野/004` 或 `MEMORY/001` 而不改 index，baseline 会全部显示 OK，却遗漏真实 current 内容变化。

因此，不能称为这些 logical owners 的内容基线。最多称为：

```text
SELECTED_INDEX_AND_FILE_HASH_BASELINE
```

### 4.4 第四件思想展开没有进入 baseline

项目四件套中的第四件是 index + 5 shards。GLM 正文在讨论 tracked-clean 保护时提到“阐释层正文”，但 baseline 没有记录其 index 或任何 shard。它不能为第四件提供未来变化检测。

### 4.5 “dirty owner baseline”描述不准确

baseline 的 note 写：

```text
baseline pins CURRENT bytes of dirty owners
```

但实际集合混合：

- `goal.md`：untracked；
- `核心认知.md`：tracked-clean；
- STATE／方向／全景／MEMORY／Feature／rulings／AGENTS／matrix：tracked-dirty 或依当前状态而定。

它没有逐路径记录 Git status、index status 或 logical-document role。准确名称应是 selected critical paths baseline，而不是 dirty owners baseline。

### 4.6 它没有执行 GPT §4.5 的完整协议

GPT 第四轮 §4.5 要求未来轮次保存：

1. `git status --porcelain=v1 -uall` 完整路径与两列状态；
2. current-owner SHA-256 manifest；
3. index 与 working-tree diff name-status；
4. 当前任务允许写入路径白名单；
5. 实际 patch／tool receipt；
6. 前后 manifest 差异。

GLM 当前只完成了第 2 项的一部分，并附时间与 HEAD。它没有资格写成“按 GPT-4 §4.5 协议建立”；应写成：

```text
PARTIAL_IMPLEMENTATION_OF_GPT4_SECTION_4_5
/ SELECTED_PATH_HASH_COMPONENT_ONLY
```

### 4.7 baseline 本身没有不可变锚

文件是 untracked，GLM 第五轮正文没有记录它的 SHA-256。它可以与 owner 一起被改写，从而失去比较点。当前本审计首次记录其 SHA：

```text
bc432c497c7ad9a1463cd4c491cbfe4706e617862f0232f6c6e4806d1ab45705
```

但本审计也尚未进入 Git commit，所以整个链仍是 `LOCAL_UNCOMMITTED_NOT_VERSION_CLOSED`。真正持久的 baseline 至少需要：

- baseline 自身 hash 被独立 receipt 引用；
- receipt 与 baseline 进入可恢复 commit；
- 或由另一个不可变对象／签名保存其身份。

### 4.8 单时点顺序哈希不是原子快照

文件列出一个 `observed_at`，没有记录：

- 生成命令；
- 开始／结束时间；
- 生成前后 Git status；
- 同一路径的二次重哈希一致性；
- writer／lock 状态。

如果生成过程中有其它写者，十条哈希可能来自不同瞬间。当前没有证据表明这种变化实际发生，但 baseline 不能自证原子时点。

### 4.9 检测变化不等于归因作者

未来重哈希可以发现某个列入路径的字节与 baseline 不同，却不能单独说明：

- 哪个 Agent／进程写入；
- 哪个 patch 引起；
- 变化是否获授权；
- 是否为 generator 合法重建；
- 多次变化的中间历史。

所以“谁改了什么不再需要争论”应拆成：

```text
what selected bytes changed = 可由前后 hash 检测
who changed them = 仍需 patch/tool/session/role evidence
```
