# 发布清单与证据单位合同

## 1. Manifest-first 原则

Phase 1 的唯一发布范围 owner 是计划中的 `release-manifest-v1.json`。在 manifest 通过验证前，任何“复制 `formal/`”“复制 10 个收据”都只是候选操作，不能称为公开结果包。

manifest 必须固定：

```text
release_id, schema_version, source_repo, source_commit, source_tree_sha256,
public_unit_id, public_claim, proof_id, claim_ids,
source_paths, dependency_paths, source_sha256,
run_ids, expected_outcome, expected_exit, expected_stdout_sha256,
expected_stderr_sha256, result_class, scope, nonclaims,
license_sources, public_doc_anchor, inclusion_reason, exclusion_reason
```

`expected_outcome` 只能是 `KERNEL_ACCEPTED`、`EXPECTED_NEGATIVE_CONTROL` 或 `SOURCE_REPORTED_NOT_REPLAYED`；后者不得进入“已完成机器证明”表。每一个原项目范围内的完成模块、run 或 claim 都必须在 inventory 中有 `INCLUDE`、`AUXILIARY_DEPENDENCY`、`SUPERSEDED`、`OUT_OF_PUBLIC_SCOPE` 或 `PROCESS_ONLY` 的明确处置。任何未分类项目使 manifest 校验失败。

## 2. 十个候选公开证据单位

下表是对旧“10 核心收据”的精确化。它不是已经发布的 manifest，也不是对每项数学结论的重新认证；Phase 1 必须对每行重算源 hash、索引一致性、依赖闭包和许可证来源后，才可将其冻结。

| Public unit | 现有 proof / 主要 run | 公共结果角色 | 公开时必须同时披露 |
|---|---|---|---|
| `R01-PROCESS-GAP` | `MP-DEDEKIND-OMEGA-M1` / `20260917-MP-DEDEKIND-OMEGA-M1-04` | Pell 夹钳的精确过程层不闭合命题 | 这是有理数/整数层构造；不证明 HoTT 不一致、普遍程序不终止或实数层结论。 |
| `R02-RATIONAL-IRRATIONALITY` | `MP-DEDEKIND-OMEGA-M2` / `…M2-01` | `√2` 的有理交付规格无居住者 | 交付类型无居住者不等于任何实际过程都不终止。 |
| `R03-SPECIFICATION-SEPARATION` | `MP-DEDEKIND-OMEGA-M3` / `…M3-01` | 显式 `LEMᵒ` 前提下两规格不等价 | `LEMᵒ` 是显式假设；不是 HoTT 内部矛盾。 |
| `R04-UNCONDITIONAL-SEPARATION` | `MP-DEDEKIND-OMEGA-M3-UNC` / `…M3-UNC-01` | 去条件化的规格分离 | 不证明完整 Dedekind 实数对象无条件构造。 |
| `R05-DECISION-VS-SEARCH` | `MP-DEDEKIND-OMEGA-BP` / `…BP-01` | 固定序列的可判定否证与搜索终止的区别 | 不将固定构造外推为通用停机结论。 |
| `R06-CUT-CONDITIONS` | `MP-DEDEKIND-OMEGA-GOLD` / `…GOLD-02` | 单个 `√2` cut 的四条件构造 | 只覆盖 ℚ 层单个 cut；不等于实数完备性或 ℝ 层结论。 |
| `R07-CANONICITY-CONTROLS` | `MP-DEDEKIND-OMEGA-TA` 及必要的 TA/AC/LEM 最终控制 runs | 明确公理注入后的规范化边界控制 | 预期被拒绝的 `refl` probe 是元层控制，不是对象层不一致性证明；所有被公开的非零 exit 必须被 manifest 明示。 |
| `R08-REAL-LAYER-SUFFICIENCY` | `MP-DEDEKIND-OMEGA-REAL-LAYER` / `…REAL-LAYER-02` | `SingleOmega ℓ → ℝLayerAt ℓ` 的充裕性 | 无条件 Necessity 仍是 `CONJECTURE`；不能写成“某一固定币种必付”。 |
| `R09-REBOUND-DISARM` | `MP-DEDEKIND-OMEGA-REBOUND-DISARM` / `20260919-…REBOUND-DISARM-01` | 指定 HIT 紧化重建的可构造性和闭计算 | 不否定极限理论本身；它把攻击面收窄到完成声明的免费化。 |
| `R10-LEM-Necessity` | `MP-DEDEKIND-OMEGA-NECESSITY-LEM` / `20260919-…NECESSITY-LEM-01` | `LEMProp ℓ → Necessity ℓ` | 这是条件蕴含；无条件 Necessity、LEM 真值与 HoTT 不一致性均不由它推出。 |

`R07` 是一个证据单位而不是单个 run：若公开说明声称覆盖 UA、AC、LEM 三类显式公理注入的控制，则相应正向/负向 run 都必须进入该单位；若只公开其中一类，其他类必须在 manifest 中列为范围外且不得在 README 暗示“三类都已覆盖”。

## 3. 来源、许可证与匿名/身份边界

每一个 manifest unit 必须列出：自写源码、Cubical 库依赖、HoTT Book 短引文、第三方论文/源码的各自来源与许可证状态。完整 HoTT Book 快照不得被搬入 MIT public repo。短引文只能在出处、版本、许可说明和用途齐备时保留。

发布前必须使 `README`、`CITATION.cff`、LICENSE 版权行和仓库级提交身份一致。当前预期公开显示身份是 `Math Fournity <math-fournity@proton.me>`；这是一项 Phase 1 的一致性检查，不代表本规划已经改写了目标仓库的既有 LICENSE 或历史提交。
