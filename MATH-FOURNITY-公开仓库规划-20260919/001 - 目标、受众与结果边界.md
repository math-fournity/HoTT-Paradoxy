# 目标、受众与结果边界

## 1. 公开包要交付什么

`MATH-FOURNITY` 是一个面向数学同行与形式化验证读者的**结果包**：它只展示在精确范围内完成的形式化命题、必要源码、可重放收据、清晰的禁止外推和仍未闭合的问题。

它不是研究工作区镜像，不是四弹对话整理，不是思想史、dev-notes、四件套、治理框架或失败实验全集。读者不需要先理解“导弹”“反弹”“交接”这些内部工作语汇，才能知道一个命题是什么、如何重放，以及它不证明什么。

### 1.1 读者最短路径

公开入口必须按以下顺序组织：

1. **结果表**：每个公开证据单位的一句精确自然语言结论、形式命题链接、证据等级与禁止外推；
2. **重放**：一条可移植命令重放全部已公开单位，或按单位重放；
3. **边界**：哪些命题仅在显式假设下成立，哪些只是预期拒绝的负向控制，哪些仍为 `CONJECTURE`、`QUESTION` 或 `SOURCE_REPORTED_NOT_REPLAYED`；
4. **开放问题**：只列会改变公开结论或同行可直接接手的具体义务；
5. **最短背景**：用中性、非过程化语言解释为何这些命题被并置。

### 1.2 公开结果的准入不变量

一项内容只有同时满足下列条件才可进入公开结果包：

- 它属于被冻结的 release scope；
- 它有精确的公开主张，而不是“我们研究过它”或“AI 认为它重要”；
- 其源码、必要依赖、运行收据、期望结果与禁止外推都被 release manifest 逐项指向；
- 正向命题有相称 proof assistant/kernel 证据；负向控制明确写成“预期的工具拒绝/边界证据”，不冒充对象层否定定理；
- 公共副本不含私有上下文、凭据、用户原始未精化表达、对话或无关历史工件；
- 任一被公开结论都能从 README 直接回到一个可重放证据单位。

“全部完成的机器证明”在本计划中的含义是：**对冻结范围内每个最终证明或最终必要控制，都给出收录或排除的明示理由；不允许只挑有利结果，也不允许把调试过程伪装为最终证据。** 它不等于把整个 `HoTT/formal/`（当前 88 个 `.agda` 文件）或所有 90 个 run 目录无选择地复制进公开仓库。

## 2. 明确不公开的材料

以下材料仍在当前综合项目中保留为溯源和内部认知资产，但不进入 MATH-FOURNITY：

- `AI对话录/`、raw trajectory、`private-audit/`；
- 四件套及其用户原始表述；
- dev-notes、Session 审计、checkpoint、STATE、治理配置和历史工作计划；
- 已被后续精化的早期表述；
- 纯调试失败 run；
- HoTT Book 完整源码快照及任何无法清楚声明许可证来源的第三方内容。

当某项负向运行是最终公开主张所必需的控制时，允许以**收据的一部分**公开；但它必须在 manifest 中标为 `EXPECTED_NEGATIVE_CONTROL`，并说明它检验的只是精确边界，不是失败历史。

## 3. 当前现场与不授权边界

截至本规划修订时，`/Users/aurolafly/MATH-FOURNITY` 只有占位 README 与 MIT LICENSE。它尚未有 `formal/`、`receipts/`、`evidence/`、三语 README、CITATION 或 CI；因此状态是 `PUBLIC_PACKAGE_NOT_IMPLEMENTED`。

本规划不授权：复制任何源码或收据到目标仓库、修改其 README/LICENSE/CITATION、生成 SSH 密钥、commit、创建 release、push、开启 Issues/Discussions 或公开发布。它只把这些未来动作的输入、边界和验收写清。
