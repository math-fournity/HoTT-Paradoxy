# 公开文档、语言与读者路径

## 1. 公开树的最小形态

公开仓库构建时采用以下读者优先布局；这里是计划，不表示任何路径已创建：

```text
MATH-FOURNITY/
├── README.md              # 中文主入口：结果表、重放、边界、开放问题
├── README.en.md           # 英文镜像：同一 release manifest 生成的结论
├── README.fr.md           # 法文镜像：同一结论与符号，不扩展新主张
├── CITATION.cff
├── LICENSE
├── release/
│   ├── release-manifest-v1.json
│   ├── portable-replay-receipt.json
│   └── provenance-and-license.json
├── formal/                 # manifest allowlist 的源码及必要依赖
├── receipts/               # manifest allowlist 的最终原始收据
├── evidence/
│   ├── CLAIM-MATRIX.md     # 仅公开单位的清洗版 claim matrix
│   └── claim-packages/     # 只保留公开单位所需的短引文/精确规格
├── tools/replay_release.py
├── docs/
│   ├── results.md
│   ├── boundaries.md
│   └── open-problems.md
└── .github/workflows/replay.yml
```

如果该公开 Git repo 跨 Session 长期维护，先按 bootstrap 合同建立诚实的最小认知入口；这些维护入口不在 README 的读者首路径中，也不得成为公开研究内容或过程叙事。

## 2. README 的固定阅读顺序

README 不写项目全过程。它只包含：

1. 一句话定位：Cubical Agda 中关于指定理想元素/完成主张的 machine-checked、范围受限研究包；
2. 十个证据单位的紧凑表：结论、形式主张、证据等级、重放按钮、`does not show`；
3. 一条全量 replay 命令和一条单元 replay 命令；
4. 四类边界：条件前提、预期负向控制、未证问题、第三方来源；
5. 具体开放问题与投稿/同行审阅入口。

内部代号可以留在源码和 receipt ID 中以保证可追溯，但公开标题、摘要和 README 不应要求读者理解“导弹”“战役”“击落”或任何用户—AI 讨论史。优先写“过程层不变量”“规格分离”“cut 条件”“条件性充裕性”“规范化边界”等精确对象名称。

## 3. 三语一致性

中文为 canonical public prose；英文与法文是语义镜像，不得在翻译时增强或弱化数学主张。每个公开 claim 有稳定 ID，三语文档只引用 ID 与同一 manifest 单元。符号、假设、证据等级、禁止外推和开放状态必须相同；没有经人工数学审校的翻译不能标为正式 release。

## 4. 结果而非过程的内容检查

Phase 1/2 的内容 validator 至少检查：

- 不包含 `AI对话录/`、`private-audit/`、`.codex/`、`dev-notes/`、四件套或 trajectory 路径；
- 不出现未被 manifest 支持的定理、量词或“已完成”措辞；
- 每个 `CONJECTURE`、`QUESTION`、`SOURCE_REPORTED_NOT_REPLAYED` 都有邻近边界说明；
- 每个公开 Book 引文都有出处与许可信息；
- 公开叙述不使用未精化的“自我否定”“HoTT 以传统拓扑学为公理”等历史措辞；
- 任何必需的负向控制被标为控制，而不是隐藏的调试残留或对象层定理。
