## 2.5 `hAll` 的**精确**剩余（2026-10-12，分析，尚未机器验证）

上一轮把 `hAll` 归到「一条算术蕴含式 `⊢ A → B`」。本轮把它**算开**了：

```
A := iT 0 (free ℒₒᵣ p)                        （层数 0）
B := free ℒₛₑₜ (imp ℒₛₑₜ domZero (iT 1 p))    （层数 0）
```

用已证的 `free_imp_domZero`（`TranslateShiftCompat.lean:792`）：

```
B = imp ℒₛₑₜ (subst ?[^&0] domZero) (free ℒₛₑₜ (iT 1 p))
  =: D 🡒 free (iT 1 p)          （D := domZero[&0]，即「&0 ∈ ω」）
```

**关键观察（新）**：`A → B` **不是**等式问题，而是

```
A → B   ⟺   A → (D → free (iT 1 p))
```

若再有一条 **`iT_free`**：

```
iT_free :  iT 0 (free ℒₒᵣ p)  =  free ℒₛₑₜ (iT 1 p)        (p 层数 1)
```

则 `B = D → A`，于是 `A → B` 就是 **`A → (D → A)`——命题逻辑恒真式**，
`Derivable` 层由 `axL` + `Derivable.or` 直接构造（**不需要任何算术内容**）。

### 为什么 `iT_free` 可信（手算两例）

* **原子**：`p = ^rel 2 eq ?[^#0,^#0]`。
  左边 `iTR 0 2 0 ?[^&0,^&0]`；右边 `subst ?[^&0] (iTR 1 2 0 ?[^#0,^#0])`。
  `iTR` 的 `conjunct` 把「p 的变量」编码成 `#(n+1)`，经 `qqAlls 2` 后正好是自由 `#0`，
  于是右边那次 `subst` 落在同一个位置上。两边逐项对上。
* **全称**：`p = ^∀ p'`。左边 `iT 0 (∀¹ (p'[#1↦&0])) = ∀¹ (domZero → iT 1 (p'[#1↦&0]))`；
  右边 `free (∀¹ (domZero → iT 2 p')) = ∀¹ (domZero → (iT 2 p')[#1↦&0])`。
  两者相等**当且仅当** `iT 1 (p'[#1↦&0]) = (iT 2 p')[#1↦&0]`——
  **同一条律的上一层**。故 `iT_free` 是**自相似**的，可由
  `UformulaRec1.Construction.semiformula_result_induction`（`iT_shift` 用的同一台机器）一次拿下。

### 等价的一般形式

`free L p = substs1 L ^&0 (shift L p)`，配合已证的 `iT_shift`，`iT_free` **等价于**

```
iT_subst_fvar :  iT 0 (subst ℒₒᵣ ?[^&0] σ) = subst ℒₛₑₜ ?[^&0] (iT 1 σ)      (σ 层数 1)
```

即「**把最外层绑定变量换成自由变量**」这一代入与 `iT` 交换。
上一层需要 `?[^#0,^&0]` 版（即 `qVec ?[^&0]`），故实际要证的是
「`w` 为**变量向量**（各分量是 `^#j` 或 `^&j`）时 `iT 0 (subst w p) = subst w (iT n p)`」。

**这与已证伪的「`iVE` 与任意 `subst` 交换」不同**：反例（第十二、十八轮）用的是
**含函数符号的项向量**与**穿透 `iVE` 自带绑定变量 `#0` 的代入**；
而 `?[^&0]`/`?[^#0,^&0]` 是纯变量向量，`iVE` 的 `#0` 由 `qqAlls 2` 绑定，代入不穿透。
**这是本轮最需要机器验证的一条判断。**

## 10. 2026-10-12 本轮进展（第十二次接手）

### 10.1 已进入**生产包**的新工具（`GodelQ/ZFC/TranslateShiftCompat.lean`，均 exit 0）

**`subst_congr_prefix`** —— 本轮最重要的基建，形状经三次收紧：

```lean
lemma subst_congr_prefix : ∀ {n : V} (p : V), IsSemiformula ℒₛₑₜ n p →
    ∀ {k₁ k₂ m w w' : V}, n ≤ k₁ → n ≤ k₂ →
    IsSemitermVec ℒₛₑₜ k₁ m w → IsSemitermVec ℒₛₑₜ k₂ m w' →
    (∀ i < n, w.[i] = w'.[i]) → subst ℒₛₑₜ w p = subst ℒₛₑₜ w' p
```

配套 `termSubst_congr` / `termSubstVec_congr`（项层，`IsSemiterm.sigma1_induction`
+ `nth_ext'`）。

**为什么必须要有它**：Foundation 的 `substs_substs` 硬性要求
`IsSemitermVec L n m w`（向量长度 = 公式层数）。而 `conjunct` 的向量长度是
`b+n`（`b=2,n=1` 时是 3）、`cDomN` 的代入像层数是 2——**永远对不上**。
先经 `subst_congr_prefix` 把向量缩到层数，`substs_substs` 才能用。

**三次收紧的教训**（写进代码注释了）：
1. v1 把长度钉在层数上（`k = n`）：覆盖面太窄；
2. v2 要求两向量同长（共享 `kl`）：仍太窄——真正要比较的
   `?[^#0,^#1,^&0]`（长 3）与 `?[^#0,^#1]`（长 2）**长度不同**；
3. v3（最终）只要求 `n ≤ k₁`、`n ≤ k₂`：这正是 `subst` 的语义（只看前 `n` 个分量）。

### 11.4 本轮踩到的 Lean 陷阱

1. **`rw` 每次只重写第一处匹配**。目标里有三个 `subst _ (^rel …)` 站点时，
   `rw [substs_rel …]` 只动第一个，第二次 `rw` 会报「找不到模式」——
   看起来像「引理不适用」，实际是**还有未重写的站点**。
   解法：`conv_lhs => rw […]` / `conv_rhs => rw […]` 逐侧定位。
2. **`nth_ext'` 的签名是 `(l) (hl₁) (hl₂) (H)`**——`l` 在最前，
   长度证明在 `H` 之前。漏掉会得到「`introN` failed: no additional binders」。
3. **`IsFormula L p` 是 `IsSemiformula L 0 p` 的 abbrev，不是投影**。
   `h.isFormula` 不存在；要写 `h.isFormula` 需先有 `IsSemiformula … 0 …`，
   而 `IsSemiformula.subst` 保留**目标层数 `m`**，故传 `m := 0` 才拿到 `IsFormula`。
4. **`Arithmetic.isFunc_iff_LOR` 的第一个显式参数是 `V` 不是 `L`**。
5. **`?[a,b]` 上的 `rw [show (?[^&0] : V) = …]` 不可靠**：
   直接对 `((^&0 : V) ∷ (0:V) : V).[0]` 做 `rfl` 重写更稳，
   或整条走 `simp only [termSubst_bvar, nth_adjoin_zero]`。
