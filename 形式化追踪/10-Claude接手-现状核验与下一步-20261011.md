### 1.1 关键发现：`neg_neg_code` 的缺口原为 Foundation 已有引理

前几轮文档（`ShCraigElimNegFilled.lean`、`ShCraigElimNegGen.lean` 的注释）都写着
「Foundation 只有元层的 `Semiformula.neg_neg`，码层面没有现成引理」。**该记载不成立**：

```lean
-- Foundation/FirstOrder/Arithmetic/Bootstrapping/Syntax/Formula/Functions.lean:127
@[simp] lemma IsUFormula.neg_neg {p : V} :
    IsUFormula L p → Bootstrapping.neg L (Bootstrapping.neg L p) = p
```

而 `Bootstrapping.neg L p := Negation.construction.result L 0 p` **正是码层面的 `neg`**。
故整条对合律一行可得，前几轮那份 146 行的归纳重做是在重证 Foundation 已有的东西
（改写后 64 行）。

**教训**：文档说「Foundation 没有 X」时，要回源码核。本轮同类问题撞到两次
（另一处是 `dev` 的 `AGENTS.md` 说构建缓存「未被 `.gitignore` 覆盖」，实际
`.gitignore:33` 明确排除，且两者是同一个提交引进的）。

### 1.2 `iT_neg` 一证，`hAxL`/`hCut` 立刻通

`ShCraigElimBranches.lean` 的文档把 `hAxL`/`hCut` 列为「需要的相容律**不存在**」。
`iT_neg` 一证，这两支一次编译通过——之前那份缺口清单低估了 `iT_neg` 的杠杆作用。

### 1.3 剩余三支的障碍已精确定位（不是笼统的"还差"）

`hAll`/`hExs`/`hShift` 要 `iT` 与 `shift`/`setShift`/`substs1` 的相容律。
本机核实**不是平凡交换**：

| 运算 | 对 `^#z`（bvar） | 对 `^&x`（fvar） |
|---|---|---|
| `iVE` | `eqAtom (^#(z + 1))` —— 码加一 | `eqAtom (^&x)` —— 不动 |
| `termShift` | `^#z` —— 不动 | `^&(x + 1)` —— 码加一 |

两者作用于**不同的变量类**，而且要证的不是 `iVE n (termShift t) = termShift (iVE n t)`
（两边甚至不在同一语言里——`termShift` 是 `ℒₒᵣ` 的项层运算，`iVE n t` 已是 `ℒₛₑₜ` 公式），
而是 `iT 0 (shift ℒₒᵣ p)` 与 `shift ℒₛₑₜ (iT 0 p)` 的关系，即一条**跨语言相容律**。

### 下一个单点：`iVE_shift` 的 `func` 支（已推进到精确卡点）

- **用什么**：`IsSemiterm.sigma1_induction`（`isSemiformula_iVE` 是先例，
  见 `SeqTranslateFormula.lean:268`）。
- **可借的先例**：`isSemiformula_iVE` 的 func 支用
  `iVE.construction.nth_resultVec` 把 `resultVec` 的每个分量化成 `iVE n v.[i]`，
  再交给归纳假设。

**已实测推进（2026-10-11 第二轮）**：func 支的 **k = 0 情形**可归约到

```
ve0 0 f = shift ℒₛₑₜ (ve0 0 f)
```

路径：`termShift_func` + `termShiftVec_nil` + `iVE_func` + `split_ifs`（已实测可走到，exit 0）。
该式展开为

```
neg ⊤ ⋎ subst (^#0 ∷ 0) (cFunc 0 f) = shift ℒₛₑₜ (neg ⊤ ⋎ subst (^#0 ∷ 0) (cFunc 0 f))
```

所以还需要两件东西：

1. **`cFunc 0 f` 在 `shift` 下不变**——它是 `ℒₛₑₜ` 的引号化公式码。
2. **`subst` 与 `shift` 的交换**——Foundation 有 `shift_substs`
   （`Syntax/Formula/Functions.lean:628`）：
   `shift (subst w p) = subst (termShiftVec w) (shift p)`；
   再配 `termShiftVec (^#0 ∷ 0) = ^#0 ∷ 0`（bvar 不动）。

**卡点与可行路（第二轮实测）**：

- `Semiformula.quote_shift` 的形状是 `⌜Rewriting.shift φ⌝ = shift ⌜φ⌝`，
  而 `cFunc` 的码在 `Sentence` 层（`⌜σ⌝ : V` 直接是 V 元），`rw` 匹配不上。
- `Sentence.shift_quote`（`Syntax/Formula/Coding.lean:466`）**只对 `ℒₒᵣ` 陈述**，
  Foundation 未给 `ℒₛₑₜ` 版。
- **可行路**：照 `quote_shift_fixitr`（同文件 567 行）的写法自建 `ℒₛₑₜ` 版：
  先用 `Semiformula.rew_eq_self_of`（`Syntax/Classical/Rew.lean:412`，
  陈述为 `(∀ x, ω #x = #x) → (∀ x, φ.FVar? x → ω &x = &x) → ω ▹ φ = φ`）
  证「自由变量为空的公式在 `Rewriting.shift` 下不变」，
  再 `rw [← Semiformula.quote_shift, hshift]`。
  注意 `Semiformula.quote_shift` 要 `Semiproposition`（不是 `Sentence`），
  `cFunc` 的码要先经 `Sentence.quote_def` 化到那一层。

**另**：func 支的 k ≠ 0 情形（`ve2` 支）还没碰，它要 `iVE.construction.resultVec`
与 `termShiftVec` 的相容（向量层，可能沿 length 归纳）。

**已归档的 API 探针**：`probes/W8-ShiftCompat-API-probe-20261011.lean`，

### 本轮踩到的坑（都已在代码注释里记下）

1. **`∷` 的层数参数必须写成 `(2 : V)`**——写 `2` 会让 `Adjoin` 类解析到 `ℕ` 上，
   报 `failed to synthesize Adjoin V ℕ`。`Adjoin V V` 实例在 Foundation 的
   `HFS/Vec.lean`，`∷` 是它的 `scoped infixr`。
2. **`shift_rel` 的 `IsRel` 义务用 `codeIn_rel_quote`**——`(by simp)` 过不去。
3. **`iVE_bvar` / `neg_or` / `neg_and` 等都是 `@[simp]`**——`rw` 一次就化简掉，
   写两次会报「找不到模式」；有时 `rw` 前需先 `show` 展开。
4. **带 `V` 的辅助引理要写 `IsUFormula (V := V) ℒₛₑₜ x`**——只写 `IsUFormula ℒₛₑₜ x`
   时 `V` 会被解成 `Type 0`，报 universe mismatch。
5. **`isSemiformula_iTR` 要 `IsSemitermVec`，而归纳给的是 `IsUTermVec`**；
   走 `IsUTermVec.isSemitermVec` 会引入 `listMax` 项触发 `whnf` 心跳超时。
   本轮的解法是把 `IsUFormula` 作为**显式假设**传入（与 `neg_and_branch` 的
   `hsp`/`hsq` 同法）。
6. **含 `sorry` 或注释里出现未证标记英文词的文件会被 `zfc_lean_check.py` 纯文本扫描拒收**，
   进不了收据源。中文注释用 Python 写 `.lean`（zsh heredoc 会坏 unicode）。
