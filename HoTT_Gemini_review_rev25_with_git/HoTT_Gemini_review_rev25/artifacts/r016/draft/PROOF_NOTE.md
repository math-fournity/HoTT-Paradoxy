## 2. 一个没有业务难度的任务

令B是布尔类型，0=false，1=true。定义可直接计算的等价

    e:B≃B,
    e(0)=1,
    e(1)=0.

逆也是e，双侧逆关系逐个构造子证明。直接表达式e(0)经有限的函数和Bool计算得到1。

单价性产生

    p=ua(e):B=_U B,
    b=transport_(X↦X)(p,0):B.

原书给出的计算定理是路径：

    β_UA(e,0): b =_B e(0).

结合e(0)≡1，可得b=_B1。这个数学结果没有疑义，但必须区分内部路径与judgemental conversion。

## 3. 仅凭命题计算规则，不自动增加基本归约步骤

基础transport/J的计算在refl上发生。书式公理常量不自动增加

    transport(ua(e),x) ↦ e(x)

作为基本规则。因此从“有β_UA路径”本身，不能断言一个只使用既定β/δ/iota/J归约的求值器会采用它。

严格实验边界：原书的primitive为univalence:isequiv(idtoequiv)，ua由其逆导出；本轮没有实现这个完整依赖语法、isEquiv定义和投影展开。代码采用一个明确的primitive-ua Bool片段，将相应路径表示为不透明常量。它模型化了所审查的计算缺口，但尚未证明它与原书全部elaboration逐步对应。不能把toy checker结果说成在Agda/Coq/Lean/HIT内核中复现了原书程序。

在该声明片段中，若p=ua(e)不透明且参数已是0，b没有任何基本归约步骤，也不是布尔构造子。故b是一个闭的、Bool类型的非规范正常形。

    没有下一条规则 ≠ 有无限多条归约步骤。

所以本例的基本归约会停止，交付协议“只有拿到0或1才算返回”却没有满足。不能称其发散，更不能从它推导整个业务任务不可计算。

## 4. 实际操作模型

源码：scripts/research/r016_axiomatic_transport.py。
测试：scripts/tests/test_r016_axiomatic_transport.py。

语法只含Bool、函数类型、de Bruijn变量、λ/application、Bool if、refl_Bool、两种Bool自等价对应的opaque ua路径、以及该端点上的coe。它不是完整的依赖类型/宇宙/单价模型。

类型检查：闭项、函数应用、分支同型、transport端点；ua的输入只接受实际二元素排列数据。它不接受虚构的常值“等价”。

BASIC规则：

    (λx.t)u → t[u/x]
    if true then a else b → a
    if false then a else b → b
    coe(refl_Bool,x) → x

按左最外强归约访问子项，每步检查在此片段中类型保持。没有对ua添加refl化或计算规则。

PROOF_GUIDED_REWRITE模式另行提供：

    coe(ua(e),x) ↝ e(x)

轨迹明确标记为PROPOSITIONAL_UA_BETA_REWRITE_NOT_KERNEL_REDUCTION。这是使用原始数学定理进行显式改写的模拟，不是悄悄把公理变成内核规则，也不是cubical实现。

结果标签：VALUE、NORMAL_NONCANONICAL、ILL_TYPED、FUEL_EXHAUSTED。任何FUEL_EXHAUSTED都不被解释成发散。代码没有设置一般fix/while语法来人为制造一个循环。

## 5. 有哪些真实对照？

| 表达式与方式 | 实际结果 | 正确解释 |
|---|---|---|
| e(0)，BASIC | 1，有限步 | 原始业务有可执行实现 |
| coe(refl,0)，BASIC | 0 | transport并非一律阻塞 |
| coe(ua(e),0)，BASIC | 无基本redex的非规范形 | 不是无限计算 |
| coe(ua(id),0)，BASIC | 仍为非规范形 | 数学上恒等等价也不自动令ua≡refl |
| if coe(ua(e),0) then 0 else 1 | 非规范形 | 需要这个值的观察者也可能等待不到构造子 |
| (λx:Bool.0)(coe(ua(e),0)) | 0 | β允许丢弃不需要的项；不能声称有opaque ua的项全部卡住 |
| coe(ua(e),0)，显式定理改写 | 1 | 保留可用等价数据与计算定理，可以完成 |

“观测者等待不到”只指在该规则/协议下没有可交付值。人为加一个反复调用无进展归约的轮询器可以造成无限循环，但那是wrapper的新行为，不能记为HoTT内在不可停机。

## 6. 不仅单次：有限运输链总能给出答案和证明

取任意有限个已给定的可执行Bool等价e_1,…,e_n和b_0∈B。定义

    t_0=b_0,
    t_(k+1)=coe(ua(e_(k+1)),t_k),
    b_(k+1)=e_(k+1)(b_k).

在声明的BASIC片段里，当n>0，t_n的每层path都是opaque ua，底层是字面Bool，没有任何redex；所以是非规范正常形。这是对语法构造的有限归纳事实，不是从穷举深度6推到任意n。

但可同时通过结构归纳构造

    c_k:t_k=_B b_k。

基步c_0=refl。递推先用

    ap_(z↦coe(ua(e_(k+1)),z))(c_k)

把t_k替换成b_k，再连接β_UA(e_(k+1),b_k)，最后计算e_(k+1)(b_k)为b_(k+1)。整个证书由有限多个congruence、路径连接和已给定计算定理组成。

因此，给定有限等价列表，可以有效生成一份“布尔值b_n＋其等于原表达式t_n的证明”。这不要求先解决无界搜索，也不要求一般任意公理闭项具有计算行为。它仅使用该片段中实际可取得的e_i及β_UA证据。

这对用户目标的反向意义很明确：本例不能证明原任务没有可行完成路径。原任务还可以直接调用e，或携带这份结果证书完成。只有特定的“仅基本归约到构造子”交付协议缺少一个实现环节。

## 8. ASK定位与准确裁决

本轮可以明确区分：

    FORMATION：b有合法Bool类型。
    PROPOSITIONAL_SPECIFICATION：可以证明b=1。
    BASIC_EXECUTION：opaque-ua片段没有把b化成构造子的步骤。
    VALUE_DELIVERY：仅基本归约的交付协议未满足。
    ALTERNATIVE_EXECUTION：原等价映射/显式定理改写/证书保留可完成。

存在一个潜在的不当提升：“结果有命题证明”→“只用基本归约就可以交付”。这在选定片段中被反例明确区分，但标准Book已经区分这两层，不是发现了被原书隐瞒的矛盾。

判决：KNOWN_PRESENTATION_BOUNDARY，局部纸笔＋自建操作模型检查；目标“理论诱发现实本无的完成困难”的全桥梁仍OPEN。没有确认真实系统承诺了这个不成立的执行规格。

不能把无redex改名为不停机，不以缺乏某实现规则推导任务不可计算，不把公理化呈现的问题升级成所有HoTT/计算性呈现的问题。
