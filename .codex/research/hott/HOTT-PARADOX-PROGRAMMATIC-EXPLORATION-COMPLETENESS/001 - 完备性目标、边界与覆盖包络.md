# 完备性目标、边界与覆盖包络

## 一、目标现象不是单一“矛盾”

本研究寻找的对象至少分为：

1. 精确 HoTT/立方类型论规则中的形式矛盾；
2. 附加公理、计算规则或解释组合造成的不相容；
3. 表示/抽象使一个现实任务新增完成义务的方向 A 候选；
4. 理论对象被提升为尚未获得的计算/交付能力的方向 B 候选；
5. 时间、时序、运动、连续性、稠密性与完成条件之间的现实相对张力；
6. 一般计算、证明搜索、元程序或实现边界的 HoTT 实例；
7. Gödel/Kleene/Lawvere/Löb 型自指、不完备与自担保界限；
8. 能反驳上述过强指控的模型、正实例与表示防线。

程序化统观要同时生成正候选与反解释。一个 timeout、类型拒绝、循环、独立句或模型差异只进入对应类别，不自动称为 HoTT 悖论。

## 二、八轴搜索张量

完整规划的基本分母为：

```text
TheoryConstruct
  × AbstractionChange
  × RealityOrTask
  × ConsumerOrContext
  × ObservationLayer
  × CompletionProperty
  × Oracle
  × FrameworkOrModel
```

| 轴 | 内容 |
|---|---|
| `TC` TheoryConstruct | Path/identity、univalence、HIT/truncation/quotient、universes、modalities、guarded/clocked、partiality、reflection、2LTT 等 |
| `AC` AbstractionChange | 忘却、商化、统一化、量词加强、层级提升、资格擦除、时序坍缩、自编码与跨模型移植 |
| `RT` RealityOrTask | 现实过程、运动/时间、在线交付、证明/分类、计算合法性 ASK、应用合同和合成校准任务 |
| `CC` ConsumerOrContext | transport/J、eliminator、deadline/race、bind、normalizer、typeclass/proof search、reflection、compiler、业务 continuation |
| `OL` ObservationLayer | 值、trace、当前可用性、判断相等、Path、mere existence、chosen witness、资源、事件时序、物理量 |
| `CP` CompletionProperty | 终止、生产性、规范化、canonicity、proof-check completion、search completion、decidability、finite-to-exact、现实完成 |
| `OR` Oracle | kernel、模型/反模型、运行、发散/不可判定证明、差分/metamorphic、自然消费者、现实对应审查 |
| `FM` FrameworkOrModel | Cubical Agda、Coq-HoTT/Rocq、UniMath、agda-unimath、Arend、cubicaltt/redtt/cooltt、2LTT 与语义模型 |

全笛卡尔积通常无意义且不可承受。每项 TaskSpec 选择有类型、有语义关联的 cell；覆盖计划先保证每个主轴和关键 pairwise interaction 至少有真实薄路径，再对出现信号的组合深化。未组合的 cells 明确为 `UNTOUCHED`、`NOT_APPLICABLE(reason)` 或 `DEFERRED_WITH_TRIGGER`。

## 三、HoTT CompletenessEnvelope

每个候选族或有界研究 pass 至少固定：

1. `calculus`：理论版本、公理、universe、相等概念、计算/消去规则；
2. `candidate_class`：typed syntax/semantic class、参数和大小/深度界；
3. `direction`：A、B、Gödel、时间/运动或反解释；
4. `task_identity`：现实/理论任务、输入、输出、consumer、观察量、完成标准；
5. `construct_axes` 与 `excitation_operators`；
6. `generator`：枚举/合成/变异/搜索算法、fairness、random seed 或模型/prompt；
7. `reducer`：等价类、规范形、task-preserving guard；
8. `oracles`：类型/证明、运行、模型、发散、自然使用、现实对应；
9. `controls`：正例、负例、单因素与关键组合消融；
10. `denominator`：源码/论文/版本/grammar/bound、哈希、排除项；
11. `coverage_level`：本轮声称 EC-0～EC-6 中何种完备性；
12. `unknown_ingress` 与 `invalidation`；
13. `stop/success`、未决和下一 bounded successor。

这些字段可进入现有 TaskSpec、SCOPE/FREEZE、plan 和 report；不要求立即新增统一 schema。若以后重复机械维护成为真实瓶颈，再设计 manager 与迁移，而不是手工再建第二数据库。

## 四、相对完备性与全局边界

当前可争取的强结论有三类：

- 对有限 typed grammar：证明 enumerator 覆盖全部 inhabitant，remainder=0；
- 对无限可枚举 code：证明 dovetailing/fairness，使每个有限 code 最终获得配额；
- 对较大 candidate class：证明到已搜索 canonical grammar 的 total、typed、property/task-preserving reduction。

一旦候选域能表达一般部分计算，不能预设存在总会停机的全局语义决定器。研究系统应让 positive witness、divergence proof、countermodel、reduction certificate 可验证，并让无证书项保持 `UNRESOLVED`。该元理论边界不能成为缩小规划的借口：每个声明分母仍须证明自己的覆盖。

## 五、机制链完成门

候选只有贯通下列链条，才接近目标：

```text
精确规则/公理/表示
  → 激发算子改变的前提或层级
  → 合法候选与自然/声明consumer
  → 可观察完成性断裂或不相容
  → 机器证明/反模型/运行证据
  → HoTT必要性消融
  → 同一现实任务对应
  → 结论与禁止外推
```

前五项可以形成一般计算或形式候选；缺 HoTT 必要性时标 `GENERIC_MECHANISM_WITH_HOTT_INSTANCE`；缺现实对应时标 `REALITY_BRIDGE_UNRESOLVED`。两者都不能由“构造很精彩”补齐。

## 六、当前基线

当前实现/证据 worktree 已有：strict-v2 证据流程、L1–L6 walking skeleton、M2 小型 symbolic slice、M4-lite、社区 consumer audits、CCTT tick/forcing 边界、固定对象机数学发散、自然数 proof code、proof/refutation PartBool、条件性 synthetic incompleteness、作者 Coq 算术实例重放，以及 `PF-CUBICAL-CANDIDATE-COVERAGE-001` 对 bounded delay grammar 的首个机器覆盖定理。它们仍是 contributor-side candidate evidence，尚未进入 main canonical checkpoint。

当前没有：全搜索张量 coverage、一般 dependent/higher synthesis、R2 universal evaluator/undecidability、exact HoTT calculus Gödel instance、class-wide reduction theorem、自然现实 consumer、物理 bridge 与独立大样本 holdout。
