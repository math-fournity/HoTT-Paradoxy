# 生成器、执行器与判据组合

## 一、目标程序架构

```text
source/framework qualifier
  → exact calculus + typed candidate IR
  → rule/operator/consumer generator
  → type/constraint pruning
  → fair scheduler and bounded executor
  → kernel/model/runtime/differential oracles
  → task-preserving reducer
  → correspondence + HoTT-essentiality review
  → immutable evidence + query index
  → omission/holdout feedback into taxonomy
```

当前 `/Volumes/D/HoTT-machine-overview/machine-overview/` 已有 strict-v2 的 qualifier/spec/generator/executor/reducer/review/evidence 骨架；后续优先扩展 IR、operator 和 oracle，不重写已验证的收据链。

## 二、生成器族

### GNR-1 Typed term/proof synthesis

- 从 exact calculus 导出 constructors、typing rules、universe constraints 和 eliminator side conditions；
- size/depth/fuel 分层枚举，canonical alpha-renaming 与等价类去重；
- bidirectional/type-directed synthesis 从目标 observation 反推 holes；
- 对 dependent paths/HIT motives 生成正合法和最小边界错误两类候选；
- 每个 grammar 给出覆盖分母、未支持构造与 completeness proof obligation。

### GNR-2 Rule mutation and ablation

- 原规则只读冻结；mutant 以 stable ID 表示加入/删除/方向翻转/量词加强/资格擦除；
- 单因素 controls 后采用受约束 pairwise/three-way 组合；
- mutation result 只定位依赖/防线，不冒充原理论结论；
- surviving/missed mutants 用于评价 oracle 和 generator blind spot。

### GNR-3 Consumer/context synthesis

- 从 operation signatures 生成 well-typed evaluation contexts；
- 固定 consumer families：transport/J、HIT eliminator、quotient recursor、deadline/race/bind、normalizer、proof search、reflection、compiler 与 application continuation；
- 先声明 observation，再生成 context，禁止见到差异后发明判据；
- 同一候选在多个 consumer 下做 contextual equivalence/characterization。

### GNR-4 Self-reference and universal computation

- finite ProgramCode、decoder、step-indexed universal evaluator、dovetailing；
- quote/decode/substitute/evaluate 与 proof code/predicate；
- Kleene self-application、Lawvere diagonal、Gödel fixed point 与 Löb/self-guarantee 分开模块；
- 每层明确 inner/outer theory 和 universality/representability 前提。

### GNR-5 Metamorphic/differential/property generation

- invariants：renaming、substitution、transport、equivalence、normalization、composition、clock weakening、truncation elimination；
- 同题跨 Cubical Agda/Coq-HoTT/其它框架与版本；
- 优化/表示/求值策略变化只改变声明维度；
- 差异先分类为 theory、axiom、elaboration、automation、resource 或 evidence mismatch。

### GNR-6 Source-guided and AI-guided proposals

- 论文 theorem/limitation、community source consumer、issue/regression、历史 diff 进入 versioned seeds；
- LLM prompt 只见 source/spec，不见 holdout witness/golden；模型/effort/context/tools/预算固定；
- AI 输出 typed candidate proposal/unknown，不直接写 formal claim；
- 与规则驱动和随机 generator 同 denominator 比较 unique hits、invalid rate、cost 和 omissions。

## 三、执行器与调度

执行类型分开：parse/elaborate、type check、kernel proof、normalize/reduce、proof search、macro/reflection、compile、object execution、model finding、source scan。一个过程卡住不得阻塞全域：

- finite grammar 用 work queue 完整执行；
- infinite code 用 dovetailing 或 iterative deepening；
- proof search 同时运行正/反方向，成功有有限 witness，双无结果保持 partial；
- 每候选固定 CPU/wall/memory/output limits，但 timeout 只登记 observation；
- 同类候选用 progressive budget/complexity curve，避免固定延迟误判；
- scheduler 保存 starvation/fairness receipt 与 interrupted attempt。

## 四、Oracle 组合

每个 candidate 至少选择一个合法性 oracle 和一个目标现象 oracle；强结论通常需要更多：

| 义务 | 主要 oracle | 反约束 |
|---|---|---|
| well-typed/legal | native elaborator/type checker | 手工 AST 结构检查不够 |
| theorem/contradiction | trusted kernel + exact assumptions | 编译成功不证 spec fidelity |
| normalization/canonicity | native reducer + theorem/source | timeout 不证不规范化 |
| concrete divergence | invariant/coinduction/induction | 重复运行不证永不停止 |
| undecidability | certified many-one reduction/universal evaluator | 单个 divergent program 不够 |
| model-relative tension | qualified model/countermodel | finite model 不外推全域 |
| implementation difference | aligned differential run | 不自动裁定哪方正确 |
| natural HoTT use | pinned community consumer/source | 关键词命中不证语义消费 |
| HoTT essentiality | ablate/translate away HoTT constructs | 通用机制的 HoTT 实例仍非专属 |
| reality-relative paradox | same task/input/observation/completion mapping | correspondence checklist 不自证哲学结论 |
| originality | literature/source comparison | AI 训练记忆或无命中不够 |

## 五、缩减和规范形

Reducer 的优先顺序是删除无关参数、简化类型/项、缩短 trace、减少 axioms，再尝试语义规范形。每一步机械检查：

1. source calculus/axioms 不变；
2. direction 与 theory construct 不变；
3. input、consumer、observation、completion 不变；
4. witness/oracle classification 保持；
5. reality map 的 preserved/changed fields 不丢；
6. 若 HoTT essentiality 是 claim，关键构造未被缩掉。

无法保持时，保留原 witness，缩减结果另立 family。未来要声称类级覆盖，必须证明 normalization/reduction total、typed、termination 和 preservation，而不是只看若干缩减成功。

## 六、证据对象

每个正式 run 最少保存：Scope/TaskSpec/grammar/profile freeze、source manifest、toolchain/framework identity、generator/scheduler/reducer identity、candidate AST/hash、commands、stdout/stderr/exit/resources、controls/ablations、replay、oracle verdict、correspondence、coverage level、non-goals 与 Git status。外部框架构建还保存 commit、依赖、稳定产物和跨干净工作树重放。

数学结论继续服从 `MATH_PROOF_BEFORE_DELIVERY_V1`；机器统观 run 不自动进入 formal claim matrix。AI 报告、文件存在和 test count 只证明其精确层级。

## 七、最小实现顺序

1. 为现有每条 L1–L6 TaskSpec 补张量坐标与 completeness fields；
2. 建通用 operator/consumer registry 的 Markdown owner，先不建数据库；
3. 将 typed grammar 扩到 dependent term、Path/HIT/universe constraints 的最小真实 slice；
4. 给每个 finite generator 一个 coverage theorem 或独立 enumeration receipt；
5. 加 fair scheduler、progressive budget 与 starvation tests；
6. 把 object-machine、proof-code、reflection、consumer scans 接入统一 coverage query；
7. 只有重复机械维护出现后，才评估 schema/manager。
