# 下一选择、停止与反证条件

## 已走过的路

G0 没有把“ZFC 能表示过程”当作答案。它先以 C-366 排除表示性误读，再把实际 source 分为 formal proof acceptance、standard-resolution completion contract 与 model representability 三类。Metamath source 证明第一类真实存在；IEP/Norton 证明第二类的完成合同会显式改写；它们没有形成同一 consumer。

## 即将作出的选择

| 选择 | 当前裁决 | 支持它的证据 | 反证／重开条件 |
|---|---|---|---|
| 释放 G1 | 不释放 | parent `OriginDone`、`ρ`、bridge 未由同一 source 固定。 | 一个 source 同时给出 ZFC-facing acceptance 与 process contract。 |
| 以 host code 续造 diagonal | 拒绝 | G2/G3 明确要求 T 内表示和实际 Code/Check。 | 先获得可审计 T internalization。 |
| 用 Foundation 同源共存实例化 generic theorem | 拒绝 | exact control 已表明 `SetTheory` 不能直接作为 `ArithmeticTheory`。 | 给出 source-level interpretation／arithmetization，并逐项支付 theorem 假设。 |
| 将 G0 写为 ZFC 缺陷 | 拒绝 | 当前是 source roles 的 split，非 object-language derivation。 | 需要同一任务的实际 completion-reflection source 或相称 theorem。 |
| 启动上位 T0 | 不启动 | T-PRECISION-DIAGONAL-SOP仍为 PREPARE_ONLY。 | 用户明确调用 T-PRECISION-DIAGONAL-SOP。 |

## 停止条件

本单元到此完成 G0 的当前来源分母、角色分离和有界 unified-source screening。下一自然单元只能由一个能改变 source split 的版本固定来源、受验证的 target mapping，或研究发起人重定的原过程合同触发；重复更多同型 proof checker、模型编码或 project fixture 不构成进展。当前 audit 不是最终方案完成，也不是 `/goal` 的 total completion receipt。
