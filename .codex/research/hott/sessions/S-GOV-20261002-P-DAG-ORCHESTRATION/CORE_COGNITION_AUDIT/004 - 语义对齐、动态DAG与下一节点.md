# 语义对齐、动态DAG与下一节点

## 用户主张与禁止收窄

用户要求的是：Master 可以动态安排不同刀具和不同信息访问条件，让真实不一致产生有界 Battle；Master 自己也可进入质询。它不是“让多个模型投票”，不是“所有节点永远离线”，也不是“App Server 一出现就可安全执行”。本轮将其落实为 TaskCard、NodeCard、access profile、Battle trigger、Master evidence verdict 和 run receipt。

## 已走过的路

1. 旧静态 card 中，relation 是否是 consumer 发生可定位冲突；Battle以同一source与L2b裁决为 `SOURCE_CONSUMER_GAP`；
2. 网络 source节点找到 Mathlib ZFSet model 的真实 consumer；这填充 L2b，却未提供 P2 reentry 或 P3 lifecycle；
3. Isabelle/ZF Formula source 在同一冻结卡上给 P2 一条 formula→satisfaction→environment/de Bruijn reentry 的 guarded mapping；P1 没有 native positive Q，P3 没有 lifecycle transition；
4. Metamath `pwex` 的 proof-system C/I/O/Done 触发 Battle-002。裁决要求新增 L2c：proof-level contract 不能跨层升级为对象、语义实际使用或 runtime consumer；
5. 三张未预封存 source allowlist 的网络节点在四分钟内没有 terminal output；Master 停止它们，并把无终态改成 NodeCard 的显式 fail-closed 情形，而不把中间搜索当 evidence；
6. 因此图不是“越多节点越接近结论”，而是“缺哪个字段才开哪个节点”。所有结果仍回到 `P2_MATCHED_WITH_SCOPE / PROOF_LAYER_ONLY / TIMEOUT_NO_TERMINAL_OUTPUT / NO_COMMON_Q / NOT_ZFC_Q_LOCATED`。

## 即将作出的选择

| 候选下一节点 | 为什么进入 | 反证条件／停止 |
|---|---|---|
| target-layer ZFC-side source tracer | 先声明 proof-system／对象／语义实际使用／runtime 层，再找该层可冻结 C/I/O/Done 与 native positive Q | proof-level contract 不跨层；若仅复得静态 contract，记录控制并停该卡。 |
| P2 same-card extension | Isabelle 已给 guarded formula-semantics reentry；只有 source 还将它接到同一 consumer Q 时才扩展 | 不能由公式编码、sats 或 `DPow` 自造 fixed point/悖论。 |
| P3 operational tracer | 只有明确 runtime/state/transition source才有资格启动 | 只有声明／证明对象、静态 syntax/semantics 时 `CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`。 |
| single-URL timeout-controlled tracer | SOURCE-003 只留下“搜索太宽而无终态”的流程证据；下一节点必须预封存一条具体 primary URL、版本、层与 deadline | 无 final output 时记录 `TIMEOUT_NO_TERMINAL_OUTPUT`，不重跑泛搜索、不生成 source card。 |
| App Server smoke | 先资格化 sandbox forwarding、approval/model effort回显和 lifecycle收据 | 未满足权限证据时不启动研究worker。 |

本 Session 的结论均是调度与来源边界结论。未来 source、模型、权限、TaskCard 或用户范围改变时，本审计失效并重建相应节点。
