## 3. 两个 GPT 的结果关系

### 3.1 LocalGPT 结果的完整性边界

LocalGPT 的当前工作树不是一个只有最终 `HoTT/` 文件的干净发布包。它同时包含：

- `/Volumes/D/ALL-Markdown` 的 8-commit `codex/prime` 历史；
- 当前 dirty 的 `aistudio-docs`→`HoTT/sources/aistudio-docs` staged renames 和未跟踪的研究文件；
- `HoTT/` 当前 owner、认知闭包、形式化代码、测试、来源 registry 和 memory/feature/rulings；
- private Codex trajectory 原件及其 canonical reader 的 hash；
- 顶层综合 repo 已保存的 `sources/local-gpt` snapshot、response/tool/product/claim ledger。

因此 LocalGPT 结果的当前投影只在明确列出这些层次时才有效：`DOCUMENTED`、`FORMAL_CHECKED_WITH_SCOPE`、`FINITE_CHECKED`、`NOT_RUN`、`DIRTY_UNVERSIONED` 不能互相替代。

### 3.2 WebGPT 结果的完整性边界

WebGPT 的 `STATE` 和研究目录比当前顶层早形成了每轮结果链，但它的结果仍是单一 WebGPT workspace 的历史状态。它没有天然知道 LocalGPT 的另一条 Git/trajectory 谱系，也没有天然产生本用户要求的跨 AI `方向追踪.md` 和 `全景视野.md`。本文件因此保留 `source_ai=WebGPT`、`source_record_id`、`source_commit` 和 `source_status`，不把 WebGPT 的 summary 直接改名成综合事实。

## 4. 全景与方向的交叉审视

每次工作结束至少回答：

| 问题 | 本次要看什么 | 若不满足 |
|---|---|---|
| 方向是否仍服务核心认知 | 当前方向的 user/core 关联、目标范围和排除条件 | 标 `MISALIGNED`/`REVIEW_REQUIRED`；不能修改 core 求一致 |
| 方向是否产生新结果 | 新 paper/code/run/failure/unknown 是否有结果 ID | 没有就 `NO_RESULT_YET`，不能填“已完成” |
| 结果是否有方向归属 | result 的 direction ID 和 unmapped reason | 孤儿结果 fail closed |
| 状态是否有直接证据 | 文件、代码、测试、运行、Git、source hash 和适用范围 | 降级 `REVIEW_REQUIRED`/`UNKNOWN` |
| 是否需要更新 core | 只有用户新原文/明确工作意识变更才是“是” | AI 结果不得反向改 core |
| 是否需要更新方向 | 候选、优先级、下一动作、依赖或状态改变 | 原位更新本文件和 STATE 对应 owner |
| 是否需要更新全景 | 新结果、正反例、失败、未知、验证范围改变 | 原位更新本文件和 result owner |
