## 1. 三方职责和使用规则

```text
核心认知.md  → 用户原始研究意识、方向约束、方法顺序和不可漂移航向
方向追踪.md  → 当前所有方向/候选/支线的组合、优先级、依赖和下一判别动作
全景视野.md  → 每个方向已经产生的结果、正反例、失败、未知和证据边界
STATE.json    → 机器状态、开放记录自动发现、依赖闭包和 source hash
audit/        → 用户提问、AI 可见回复、工具事件、产物、主张—证据的原始定位
sources/Git   → 历史来源身份、代码、文件、提交和 dirty 边界
```

使用本表前必须：

1. 先全文读取 `核心认知.md`；
2. 再全文读取本文件和 `全景视野.md`；
3. 将当前方向与 `STATE.json` 的记录身份、`MEMORY.md` current queue 和直接证据对照；
4. 若方向不服务任何用户核心主题，标 `CORE_UNRELATED`，不得因为它在 WebGPT 历史中出现过就进入当前执行队列；
5. 若方向状态来自历史 AI 自述而没有对应文件/运行/Git，降为 `REVIEW_REQUIRED` 或 `UNKNOWN`；
6. 结束时反向检查：本轮结果是否改变方向状态、下一动作、依赖或优先级，以及是否需要更新核心（仅用户新原文才更新核心）。

## 2. 状态和证据语义

| 状态 | 含义 |
|---|---|
| `ACTIVE_USER_DIRECTION` | 用户当前明确要求或当前研究航向 |
| `NEXT_CANDIDATE` | 有直接判别价值的下一候选，尚未执行 |
| `CANDIDATE` | 有研究价值但尚未成为当前下一步 |
| `SUPPORTING_DIRECTION` | 支撑主线的理论、来源、治理或证据方向，不自动成为数学主线 |
| `REVIEW_REQUIRED` | 有历史记录或结果，但 source/hash/上下文/适用域仍需复核 |
| `PARKED` | 暂不执行，保留明确重开条件 |
| `CLOSED_WITH_SCOPE` | 在明确范围内完成，不能外推到更宽命题 |
| `REJECTED_WITH_REASON` | 该方向/表达被直接证据排除，保留原因和可重开条件 |
| `UNKNOWN` | 来源、目标、状态或关系不足以做更强判断 |

`优先级`不是数学真值；它由用户当前目标、能否消除关键未知、HoTT 规则是否真实参与、证据成本、与既有方向是否重复和安全/恢复边界共同决定。

## 5. 与 `核心认知.md` 的交叉审视合同

### 5.1 核心 → 方向

每个 `ACTIVE_USER_DIRECTION` 必须列出至少一个 core 主题和后续精确 KC 关联；若只是 AI 自己的方向，标 `AI_DERIVED`，不得冒充用户原始要求。当前初始投影先使用主题级关联，等句子级映射完成后再补 stable KC IDs。

### 5.2 方向 → 成果

每个方向必须有 `已有结果`，或者显式写 `NO_RESULT_YET`。候选方向没有结果不是错误，但不能让未来 AI误以为已经验证；已有结果若仅是设计/纸笔/有限模型，必须在全景中保留相同证据等级。

### 5.3 成果 → 方向

全景中的每个结果必须反向引用一个或多个 direction ID；纯治理、source gap、附件缺失和历史交接可标 `UNMAPPED_WITH_REASON`，不得出现无主结果。

### 5.4 结果/状态 → 证据

任何 `VERIFIED`、`PAPER_PROVED`、`RUNTIME_OBSERVED` 或“已完成”都必须回到对应文件、代码、测试、运行收据和 Git。`STATE` 的字段、AI 自述或 summary 只能作为导航，不能独立提高证据等级。

## 6. 当前优先级和停止边界

当前优先顺序：

1. `DIR-G-UNDERSTANDING-RECONCILIATION` 与 `DIR-E-LOCAL-HISTORY-COVERAGE`：先让历史交接链可审计；
2. `DIR-W-RACE-TIMEOUT`：在新的数学研究被明确恢复后，作为 WebGPT R039 指向的最小新判别动作；
3. `DIR-L-GUARD-ERASURE` 与 `DIR-L-SAME-FUNCTION-DIFFERENT-TIME`：围绕用户时间维度主线寻找 HoTT 特定实例；
4. `DIR-L-RUSSELL-FORMATION`、`DIR-L-SELF-REFLECTION`、`DIR-L-MATRIX-CONTINUITY`：作为支撑或独立候选，按直接证据推进；
5. WebGPT 其余 `REVIEW_REQUIRED` 分支：只在新证据、用户明确重开或当前候选依赖它们时进入。

不因方向数量增加而自动开始所有方向；不因 WebGPT `active` 列表存在而恢复旧数学研究；不因某方向在 `核心认知` 中被提及就把它提升为当前任务。用户当前目标、`MEMORY` current queue、直接证据和本表的下一判别动作共同决定资格。

## 7. 更新规则

- 用户提出新原文、修正或采纳/撤回：先保存原文输入，再更新 `核心认知` generation 和 `rulings`；
- 新候选、候选状态、优先级、依赖、下一动作：更新本文件和 STATE 对应记录；
- 新证明/推导/代码/测试/失败/未知：更新 `全景视野.md`、result owner、artifact/ledger/Git；
- 结果不自动改写 core；只有用户之后明确形成新的工作意识时，才新增 core 原文；
