# 01 - 总结论与决定性发现

## 0. 总裁决

**机器统观项目在证据纪律、机器证明资产、防误报和治理连续性上已达到罕见的高质量；GPT 方案
v2.1 是九轮真实证伪程序的可靠收敛，其执行架构方向正确、证据身份诚实。但从"确保最终成功"
的角度，存在一个尚未被 GLM 与 GPT 双方真正解决的决定性问题：根 goal.md 的完成门把两种
不同证据类型的环节（可机器证明的非因子化 / 可能无法在文献中源化的经验性"提升来源＋现实同任务"）
捆绑成一条不可分割的链，而该问题的处置方式直接决定 PSJ/TGSQ 是"对一个可能不存在的来源的无界
搜索"还是"把已经机器钉死的最强论证组装交付"。这个问题必须在进入执行前由用户作出明确裁定，
否则项目最可能的下场是：继续产出大量高质量有界负结论与文献/CE-MAP 账本，却始终无法交付
用户真正想要的非现实性论证。**

三个决定性发现（详见 §1–§3）：

1. **FR-001 的哈希漂移属实，且是更深治理脆弱性的症状**（§1）。
2. **GPT 方案在方法上成立，但存在五个具体缺口，其中 EXP-001 的排序错误是方案内部自相矛盾
   的硬缺口**（§2）。
3. **"自然消费者/现实同任务"是经验命题，不是数学命题；这是 goal.md §11 完成门能否闭合的
   分水岭，而九轮互审把它修成了"正向门可达"，却始终没有回答"若源化搜索无命中怎么办"这一
   决定成败的问题**（§3）。

## 1. 决定性发现一：FR-001 哈希漂移属实，且暴露系统性脆弱

### 1.1 漂移本身（confirmed，本审计独立复核）

| 文件 | 实际 SHA-256 | STATE 钉住值 | 结论 |
|---|---|---|---|
| `goal.md` | `5c21d3ff…e5c5` | `f302d37a…311` | 漂移 |
| `R4-HOTT-NAT-EFFECTIVITY-001.md` | `38f0e65d…0e91` | `6cb41c9b…63b3` | 漂移 |
| `核心认知.md` | `7548bd17…877b` | `7548bd17…877b` | **未漂移** |

mtime：goal `07:10:11Z`、R4 `07:10:41Z`（本机 `03:10` EDT），晚于 S151 checkpoint
`06:38:03Z`。GPT 方案对"漂移发生在该窗口内"的前提已诚实标注为"该前提本身未被 checkpoint
证明"，本审计同意该审慎。

### 1.2 为什么这是"系统性脆弱"而不只是"两个文件漂了"（candidate，需进一步确认）

关键观察：`核心认知.md`（四件套之一，受 `STATE.current_core` + manifest + curation 三重 hash
管理）未漂移；而 `goal.md` 与 R4 TaskSpec（active records，其 source hash 钉在 STATE.records
的 `source_hashes` 里）漂移了。这提示（candidate，未确认）：**四件套有启动加载时的 hash 闭包
检查（cognition_runtime 的 plan/read/check），而 active goal/R4 TaskSpec 的 source hash 可能
没有同等的启动检查强度，导致漂移在 S151 之后才被"research hydration 返回 review_required"
被动发现。**

这一机制若成立，则 FR-001 只治标：它重建这两个文件的 intended content，但没有堵住"任何
非四件套 current-truth 文件的 hash 漂移都不会被主动探测"的洞。本审计已在修改方案中建议
FR-001 增加一个系统性修复条款（见 `DeepSeek的方案/` FR 增补片）。

### 1.3 对"确保成功"的含义

目标契约文件本身处于"actual 与 pinned 冲突"状态，任何后续数学研究在冲突裁决前都可能建立在
错误的 intended goal 上。GPT 方案把 FR-001 列为第一前置，**这一排序是对的，且是本审计确认
其方案正确性的最重要一点**。风险在于：FR-001 的"路径 B（旧 bytes 未恢复）"要求做
`SEMANTIC_RECONSTRUCTION_WITH_MISSING_BYTE_BASELINE`，这是一项重治理工作，若执行者把
"把 pin 改成 actual hash"误当成修复（方案已禁止），会制造虚假闭合。方案已明确禁止，风险可控。

## 2. 决定性发现二：GPT 方案方法成立，但有五个具体缺口

逐片审计详见 03。这里只列五个**决定成败**的缺口：

### 缺口 1（硬缺口，方案内部自相矛盾）：EXP-001 被排到"exact target 之后"，但它不能由
PSJ/TGSQ/R4 替代，且直接服务用户核心认知。

方案 007 片 §8 自己承认："这两项（最小表达保真 + HoTT 表达用户悖论理论）不能被 PSJ、TGSQ
或 R4 自动替代"，却又在 002 片工作包表把 `EXP-001` 标为 `PLANNED_AFTER_EXACT_TARGET`，且
里程碑 M0–M6 中 EXP 没有任何早于 R4X 的位置。这是自相矛盾：一个"不可替代、且是用户核心认知
（KC-000031 最小理论覆盖、KC-000035 表达 Z 理论本身）显式要求"的单元，被无限期顺延到
"选定 exact target 之后"，而 exact target 的选择（R4X）本身就是一条可能长期不收敛的线。

**修正**：EXP-001 的最小表达保真单元应在 PSJ 第一批之后、R4X 之前作为一个独立低成本单元
执行（它只需一个最小 source theory + interpretation + preservation 判词，不需要等 R4 target）。
详见修改方案 EXP 增补片。

### 缺口 2：文献截止日（2026-09-14）逾期，方案没有逾期处置，反而做了语义再解释。

goal.md §5 具名截止日 2026-09-14 已过，`LIT-DENOMINATOR-001` 判词
`COMPREHENSIVE_COVERAGE_NOT_ACHIEVED`，GLM 已列为盲区 B6（"没有任何一份逾期处置记录"）。
GPT 方案 008 片 §10 的回应是："当前 as-of date 是文献纳入边界，不是项目交付期限"——这是一次
**对具名截止日的语义再解释，而非逾期处置**。它没有回答：具名截止日为何不再约束覆盖义务？
是顺延、撤销、还是改为 as-of 语义？这需要用户裁定或明确登记，否则 goal.md §5 的具名义务
被静默软化。

**修正**：方案应增加一条"文献截止日逾期处置"条款（顺延/撤销/改语义，三者选一并登记），
详见修改方案 LIT 增补片。

### 缺口 3：VC-001 的单一副本风险被"需要 Git 授权"这一前置降级为可延后事项，但风险在增长。

本审计复核：`git status --porcelain` 显示 216 个 changed 路径（约 38 modified + 178 untracked），
含 807 文件 Coq 归档等不可再生重建证据，全部 `LOCAL_UNCOMMITTED`。GLM 审计快照时为
"161 untracked + 38 modified"，现在增长到 216，说明**风险在累积**。方案 003 片把 VC-001 列为
"PLANNED / REQUIRES_MATCHING_GIT_AUTHORIZATION"，未把它标为紧急。

**修正**：方案应把 VC-001 的紧急度上调，并给所有者一条明确的、带精确路径清单的 commit 授权
请求（GLM 建议方案 05 §2 已有路径清单雏形，GPT 方案未吸收其紧急度）。详见修改方案 VC 增补片。

### 缺口 4：PromotionSource 的分母与"natural consumer"的验收阈值仍未钉死。

方案 004 片 §6 给了 7 层 PromotionSource 分母顺序，§3 给了九字段，这是对的；但它没有钉死
**"多强的来源才算 source-grounded（可进入 A1），多弱才算 SYNTHETIC_CALIBRATION_CONSUMER"**
的阈值。第 4 层（proof assistant/编译器/运行接口的真实承诺）与第 7 层（synthetic translation）
之间的第 5–6 层（外部应用合同、用户解释）边界模糊。若不钉死，PSJ 的判词可能重演 GLM 审计
自己批评的"审查者口味分派"。

**修正**：方案应增加一条最小验收阈值（例如：来源必须"先于本项目候选存在"＋"可引用 input/
observation/completion"＋"非本项目或本项目 AI 生成"三者同时满足才算 source-grounded）。
详见修改方案 PSJ 增补片。

### 缺口 5：TGSQ 的"多解释冲突 → 请求用户选择"这一终局，没有给出"用户选不了/不想选"时的
后备路线，且用户核心认知里"现实是离散/量子化"本身是一个物理立场。

方案 005 片 §5 三终局之三 `MULTIPLE_INCOMPATIBLE_INTERPRETATIONS` 的处置是"既有用户裁定
无法消解时才请求新选择"。但用户核心认知（KC-000003/004）把"现实时空是离散/量子化"作为一个
**前提**，而方案 005 片 §6 又正确地说"用户关于现实非连续性的哲学/物理立场被保留，但不因
进入 TaskSpec 自动成为已证物理定理"。这两者之间有张力：TGSQ 若找不到"HoTT 文献明确把
Path/interval 用于物理运动"的来源，TGF 无法启动，Q2（圆环/运动）这条用户点名的主线就会
停在"无来源"——而这条线恰恰是用户最关心的（KC-000003 芝诺、KC-000004 圆环、KC-000024）。

**修正**：方案应明确 TGSQ 无命中时 Q2 的降级路线（把"稠密性假设 vs 离散现实"的对比降为
用户哲学框架内的论证交付，而非要求物理定理），避免 Q2 因"无源化解释"被无限搁置。
详见修改方案 TGSQ 增补片。

## 3. 决定性发现三："自然消费者/现实同任务"是经验命题，不是数学命题——这是成败分水岭

### 3.1 证据类型分析（本审计的核心判断）

goal.md §11 完成门要求的链条是：

```text
exact HoTT 规则/表示 → 抽象/资格变化 → natural consumer → 机器证明的不完成/不相容
→ HoTT 必要性 → 现实同任务对应 → 方向 A 或 B
```

其中三段可以（且已经）被机器证明：

- "exact HoTT 规则/表示 → 抽象/资格变化"：C-71–C-148 的表示/资格边界族已机器证明；
- "机器证明的不完成/不相容"：非因子化（α(w₀)=α(w₁) 而 J(w₀)≠J(w₁) ⇒ J 不因子化）已机器证明
  （C-96–C-99、C-71–C-76、C-92–C-95、C-106–C-109 等）；
- "HoTT 必要性"：可通过 arithmetic-only / comparison-calculus 消融机器检验。

两段**不是数学命题**，而是经验/解释命题：

- "natural consumer"：存在一个先在的真实任务/消费者，它确实把较弱理论对象当完整身份使用；
- "现实同任务对应"：理论侧 input/observation/completion 与现实侧相同。

这两段不能被任何 proof assistant 证明——它们需要**先在的、可引用的外部来源**（论文/库 API/
应用合同/物理任务），或者被承认为"本项目研究者构造的解释桥"。

### 3.2 九轮互审把它修到了哪里

GLM 最初断言"目标结构性不可达"（把数学可形式化部分与哲学不可形式化部分捆绑），GPT 反驳为
"正向门可达，缺的是开放世界无命中时的负向终止门"，GLM 让步。这个修正是**对的**——正向门
确实可达（只要找到真实 PromotionSource + same-task）。

但九轮互审**始终没有回答**这个更尖锐的问题：

> **若 PSJ/TGSQ 的源化搜索在冻结分母内无命中（这是方案自己列的三终局之一，且概率不低，
> 因为"natural consumer"的定义本身就要求它先在、可引用、非合成），那么 goal.md §11 的
> 完成门就永远无法闭合——不是因为它"结构上不可达"，而是因为闭合它所需的经验事实在可及
> 的文献/来源中不存在。此时项目该做什么？**

方案的答案（010 片 §10）："停止工作包只产生 scoped negative 和 successor，不证明 HoTT 全局
无候选，不自动完成 root Goal"。这个答案在**治理上诚实**，但在**项目成功上不完整**：它意味着
项目可以无限期地"继续下一项有判别力的 bounded successor"（goal.md §11 原文），而用户真正的
交付（N1 哲学论证）始终不被交付。

### 3.3 这正是"护航"必须解决的：把 L1 与 L2 的验收关系交给用户裁定

本审计的判断（与 GLM 的 B1 部分一致，但更精确）：

- goal.md §11 的完成门本身**没有错**，错在它**没有区分 L1（定理见证）与 L2（哲学交付）的
  证据类型**，导致"已经机器证明的 Z 技术核"因缺一个"可能不存在的经验性 consumer"而被判为
  "不够"，同时"离用户目标最远的 generic Gödel 线"反而被优先。
- GPT 的 P0/P1/A1 三层**正确**地把"非因子化实例（P0）"与"现实相对见证（A1）"分开，但它
  **仍然把 A1 作为唯一可交付的"成功"**，没有为 L2（把 P0 结果 + 明确写下的提升语义桥组装
  成最强论证）设立独立的交付完成态。

因此，本审计不主张单方面改写 goal.md（它是用户契约，010 片 §11 也已把"改根 Goal 门"列为
仅用户可裁定），但**主张用户必须在进入执行前作出如下裁定之一**（这是"护航"的核心动作）：

- **裁定甲**：维持 goal.md §11 原门——即 source-grounded natural consumer 是硬性完成条件。
  后果：接受"若源化搜索无命中则项目可能长期不闭合"这一事实，PSJ/TGSQ 按方案执行，R4 按
  继承框架交付，最终交付物是"最强候选 + 未闭合桥梁"报告（方案 008 §11 中间报告）。
- **裁定乙**：把 L2 设为独立交付完成态（如 GLM 建议的 `DELIVERED_ASSEMBLED`）——即"机器证明
  的 Z 技术核 + 明确写下的提升语义桥 + 所有者评审通过"构成哲学论证交付；定理线（A1 见证）
  继续作为开放研究但不阻塞交付。后果：项目可停机交付，N1/N5 满足，N4 不降级（提升桥
  显式标 SYNTHETIC/解释桥，不冒充自然 consumer）。
- **裁定丙**（折中）：先执行 PSJ 第一批（C-71–C-76、C-96–C-99 的 PromotionSource 判定），
  以第一批的**实际结果**（是否找到真实来源）为裁定甲/乙的输入，再决定验收门。这与方案
  M1-A 里程碑一致，且不空转。

本审计**推荐裁定丙**：它不预判结果、不空转、把"验收门"的最终形态建立在 PSJ 第一批的真实
证据上，同时避免"先改门再发现改错了"或"先不改门再无限搜索"两个对称风险。

## 4. 对"机器统观能否成功"的直接回答

| 问题 | 回答 |
|---|---|
| 数学机器资产可靠吗？ | 可靠（收据结构诚实、non_goals 显式、分片校验 PASS；本审计复核见 02） |
| GPT 方案方向对吗？ | 对（FR 第一、PSJ/TGSQ 先于 R4、P0/P1/A1 分层、source-first、arithmetic-only 消融） |
| 方案能闭合 goal.md §11 吗？ | **不确定，且关键变量不在方案内**——在"源化搜索是否命中 natural consumer"这一经验事实，以及用户对 L1/L2 验收关系的裁定 |
| 最大的失败模式是什么？ | 不是"证错"，而是"永远在正确的高质量有界负结论中打转，从不交付用户真正想要的东西"（GLM 已预警，本审计确认其机制仍存在） |
| 现在最该做什么？ | ① 用户就 FR-001 冲突作出 content 裁定或授权 canonical integrator 裁决；② 用户做"裁定丙"（先跑 PSJ 第一批再定验收门）；③ 尽快授权 VC-001 commit（单一副本风险在累积） |

## 5. 与 GLM/GPT 结论的差异定位（避免重复劳动）

- 本审计**确认** GLM 的"零见证诚实、B2 空间错位、B3 自指分母、B6 截止日逾期"四条，并独立复核了其中可机械复核的部分；
- 本审计**确认** GPT 对 GLM 的四要害击破（合成消费者循环论证、提升来源、债务统一叙事、stuck family `λ _ → Bool`）是成立的；
- 本审计**新增**的、双方都未充分覆盖的点是 §2 缺口 1（EXP 排序自相矛盾）、§2 缺口 5（TGSQ 无命中时 Q2 降级路线）、§3（L1/L2 验收关系必须由用户裁定，且应在执行前做）。
