#### **第2章：类型系统 - DTT的化身**

Chronos的类型系统是其革命性的核心。它不是一个被附加到语言之上的约束系统，而是**语言本身**。类型系统直接将动态类型理论（DTT）的四个核心公理，编码为可被编译器静态检查的规则。在Chronos中，一个类型正确的程序，就是一个在DTT宇宙中逻辑自洽的构造。

**2.1 时间类型 (`Time`) - 时间化公理的实现**

*   **规范 `[LS-2.1.1]`:** 系统内置一个唯一的、离散的、全序的基础类型 `Time`。其实现等价于自然数`Nat`。
*   **规范 `[LS-2.1.2]`:** 所有类型检查都发生在一个**隐式的全局时间上下文 `τ: Time`** 之中。
*   **规范 `[LS-2.1.3]`:** 禁止任何导致时间`τ`减少或停滞的计算。任何计算，其类型签名若不将时间`τ`至少推进`+1`，都无法通过编译，除非它是一个纯粹的、无副作用的“视图”计算（view computation）。

**2.2 时间依赖类型 (`Type Families`)**

*   **规范 `[LS-2.2.1]`:** 语言提供`type ... (t: Time) is ...`的语法，用于定义一个**类型族 (Type Family)**。一个类型族是一个从`Time`到`Type`的函数。
    ```chronos
    // 定义一个随时间演化的宇宙状态
    // 在时间0，它是一个数字。在时间1之后，它是一个字符串。
    type UniverseState (t: Time) is
      if t == 0 then
        Nat
      else
        String
    ```
*   **规范 `[LS-2.2.2]`:** 使用一个类型族中的具体类型时，必须使用 `at` 关键字显式地绑定时间变量。
    ```chronos
    let state_at_zero : UniverseState at 0 = 10
    let state_at_one  : UniverseState at 1 = "hello"
    ```
    `let invalid_state : UniverseState at 1 = 10` 将产生一个编译时类型错误。

**2.3 过程类型 (`Process Type`) - 过程公理的实现**

*   **规范 `[LS-2.3.1]`:** 语言的核心函数类型是**过程类型**，使用`proc`关键字定义。其类型签名**必须**将时间`τ`向前推进。
    ```chronos
    // 这是一个从 A 在时间 τ 的状态，演化到 B 在时间 τ+1 的状态的过程
    proc process_name (t: Time) -> (input: A at t) -> B at (t+1) is ...
    ```
*   **规范 `[LS-2.3.2]`:** 任何对一个`proc`的应用（函数调用），都会在类型检查器的上下文中，将当前的全局时间`τ`加一。这强制要求程序的执行流与时间的流逝在类型层面保持同步。

**2.4 历史类型 (`History Type`) - 可观测历史公理的实现**

*   **规范 `[LS-2.4.1]`:** 语言提供`history T of A`的语法，用于定义一个**历史类型**。
    ```chronos
    // 定义一个记录了UniverseState完整历史的类型
    type UniverseHistory is history of UniverseState
    ```
*   **规范 `[LS-2.4.2]`:** 一个`history`类型的值，是在编译时静态已知的、截至当前时间`τ`的所有状态的序列。它允许安全的、只读的“历史回溯”。
    ```chronos
    proc check_history (t: Time) -> (h: UniverseHistory at t) -> Bool at (t+1) is
      // 我们可以安全地读取时间0的状态，因为它 ≤ 当前时间 t
      let initial_state = h.at(0)
      // ...
    ```
    `let future_state = h.at(t+1)` 将产生一个编译时错误，因为无法观测“未来”。

**2.5 等价与相等 (`Equiv` & `Id`) - 动态单价公理的实现**

*   **规范 `[LS-2.5.1]`:** 语言内置两种不同的相等性判断：
    *   **身份相等 (`Id`):** 使用 `==` 操作符。它判断两个对象是否是同一个，其类型为 `Id A a b`。
    *   **结构等价 (`Equiv`):** 使用 `≃` 操作符（或 `~~` 作为ASCII替代）。它判断两个对象是否在结构上同构。
*   **规范 `[LS-2.5.2]`:** 类型系统将**动态单价公理**作为其核心的类型转换规则。这意味着，一个关于“动态等价”（即一个贯穿历史的结构等价）的证明，可以被编译器**自动地、安全地**转换成一个关于“身份相等”的证明。这使得我们可以基于对象的“行为”来进行推理，并保证其与对象的“身份”相一致。

#### **第3章：表达式与控制流**

本章定义了Chronos语言中用于进行计算和控制程序执行流程的核心构件。所有这些构件的设计，都严格遵守并利用了第2章中定义的动态类型系统。

**3.1 变量绑定 (`let ... in ...`)**

*   **规范 `[LS-3.1.1]`:** `let` 绑定用于将一个值赋给一个不可变的（immutable）变量。
    ```chronos
    let x : Nat at t = 5 in
    let y : Nat at t = x + 1 in
    // ... 在 in 之后的作用域内，x 和 y 可用
    ```
*   **规范 `[LS-3.1.2]`:** 所有`let`绑定的值，其类型都必须在编译时被完全确定。类型检查器将严格执行时间`at t`的一致性。在一个确定的时间步`t`内，所有计算都被视为“瞬时”完成的纯粹计算，不消耗DTT时间。

**3.2 过程应用 (Process Application)**

*   **规范 `[LS-3.2.1]`:** 对一个“过程”(`proc`)的应用，是Chronos中**唯一**能将全局时间`τ`向前推进的基本操作。
    ```chronos
    // 假设 t_current = 5
    // proc_a 的类型为: proc (t: Time) -> A at t -> B at (t+1)
    let input_at_5 : A at 5 = ... in
    let result_at_6 : B at 6 = proc_a at 5 (input_at_5)
    // 在这行代码之后，编译器的全局时间上下文 τ 将变为 6
    ```
*   **规范 `[LS-3.2.2]`:** 编译器将静态地跟踪全局时间`τ`的演化。任何试图将一个`at t`类型的值，传递给一个期望`at t'` (`t' ≠ t`)类型的过程的尝试，都将导致编译时类型错误。这从根本上杜绝了“时序错乱”的逻辑错误。

**3.3 模式匹配 (`match ... with ...`)**

*   **规范 `[LS-3.3.1]`:** `match`表达式是Chronos中用于进行复杂数据解构和条件分支的核心工具。它必须是**穷尽的 (exhaustive)**，编译器将检查所有可能的情况是否都已被处理。
    ```chronos
    type Option (A: Type) is
      | Some (value: A)
      | None

    proc safe_div (t: Time) -> (n: Nat at t, d: Nat at t) -> Option Nat at (t+1) is
      if d == 0 then
        None at (t+1)
      else
        Some (n / d) at (t+1)

    // 在另一个过程中...
    let result_at_t1 : Option Nat at (t+1) = safe_div at t (10, 2) in
    match result_at_t1 with
      | Some val -> // 在这里 val 的类型是 Nat
          ...
      | None -> // 在这里处理除以零的情况
          ...
    ```
*   **规范 `[LS-3.3.2]`:** `match`表达式本身不消耗DTT时间。它是一个在**单个时间步**内完成的决策过程。

**3.4 历史溯源 (`trace`)**

*   **规范 `[LS-3.4.1]`:** `trace`是一个内置的语言构件，它允许一个过程安全地“回溯”并读取一个`History`类型对象的过去状态。
    ```chronos
    // h 是一个 UniverseHistory at t
    // 我们可以读取时间点 5 (假设 5 < t) 的状态
    let past_state : UniverseState at 5 = trace h at 5
    ```
*   **规范 `[LS-3.4.2]`:** `trace`操作受到类型系统的严格约束。尝试追踪一个未来的时间点 (`t' > t`) 或一个类型不一致的历史记录，将导致编译时错误。
*   **规范 `[LS-3.4.3]`:** `trace`是一个只读操作，它不消耗DTT时间。它被视为一次“记忆的查阅”。
