## 1. 攻击对象与构造草图

**对象**：MLTT + UA-作公理（`postulate ua : ∀ {A B : Set} → Iso A B → A ≡ B`，
无计算规则）中，构造闭 ℕ 项使其不归约到任何数字。

**构造草图（三步）**：
1. Bool 的换位自同构：`not : Bool → Bool`（`not (not b) ≡ b` 可证）；
2. `e : Bool ≡ Bool := ua (not , not , not∘not)`——公理无计算规则，
   `transport e` 不再可约简；
3. `n : ℕ := if transport e true then zero else suc zero`——**闭项**，
   但 `transport e true` 卡在公理上，n 既不是 `zero` 也不是 `suc _` 的
   范式（这就是 canonicity 破坏的最小形态）。

**对照组**：`MissileFourChargeDemo.agda`（已编译，exit 0）——LEM/AC 公理注入后
闭项 `n-lem`/`n-ac` 同样卡在公理应用上。该演示件是本靶的 LEM/AC 格预演；
靶 A 的特殊处是用 **UA**（而非 LEM/AC）：UA 是 HoTT 的本位公理，其破坏 canonicity
直接命中「理论-引擎对齐」的核心（cubical Agda 为恢复 canonicity 而引入计算规则
——靶 A 演示的正是「无计算规则的公理注入」的代价）。

## 2. 「卡住」的机械化路径（三选项；本文件的核心设计任务）

「n 不归约到数字」是元层性质，无法在 Agda 内部直接断言。三条路径：

- **路径 (i) 外部归约检查器（推荐，元层工具——正合 027 §4 拒证二元性）**：
  用 Agda 批处理规范化接口（`--interaction-json` / `C-c C-n` 的脚本等价物）
  对 n 求范式，机械检查其头部符号为公理应用（中性）而非构造子。
  产出形态 = 范式输出存档（stdout 为证）+ 检查脚本入库。
  风险：依赖交互接口的脚本稳定性；输出格式需固定存档。
  符合纪律：外部归约检查 = 元理论工具，证书由元层颁发（027 §4）。

- **路径 (ii) 条件性内部证明（备选，高难度）**：在 Agda 内证明条件命题——
  「若该 UA 公理携带 J-规则/计算规则，则 n ≡ zero 与 n ≡ suc zero 皆可证/皆不可证」
  之类的内部化切片。风险：UA 的严格公理形态带泛化和 J 规则，内部化设计复杂；
  登记为备选，不预设可行。

- **路径 (iii) 独立微型引擎（远期）**：写一个微型归约引擎（覆盖演示语言片：
  ℕ/Bool/transport/if），在其上证明 n 卡住。最重；仅在 (i) 失败时启用。

**推荐执行序**：(i) 为主，(iii) 为后备，(ii) 视外部审计要求启用。

## 3. 与主定理模式的接线

靶 A 的收据在主定理模式（027 §2.3）中的位置 = **UA-作公理实例**：
- 三选一取「显式化并丧失完成义务」支——公理注入即显式化，canonicity 破坏即
  完成义务的丧失；
- 与 LEM 格（M3：显式化 + 保持拒绝能力）合读：完成义务的收费随公理的种类而
  形态不同——LEM 收「判定不再可执行」，UA 收「等价不再可计算」；
- 与靶 B 对齐矩阵互证：矩阵的「显式假设」格逐格升级为本靶形态的收费实例。

## 4. 风险与不声称

- 不声称路径 (i) 的范式输出构成「不可归约」的**数学证明**——它是元层工具的
  检查记录（与 canonicity 元定理互证）；按 `ARGUMENT_ANCHORED_ON_MACHINE_
  CHECKED` 精神登记，不冒充 `MACHINE_PROVED` 的对象层定理。
- 不声称 UA-作公理的系统不一致（Huber 结果是非规范性，非矛盾）。
- 若路径 (i)(ii)(iii) 均不可行：该否定结果本身登记为本方向的合法产出
  （027 §10 预留）。
