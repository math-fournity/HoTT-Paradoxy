# HoTT 跨Session治理 v1.2.0：实施与验证报告

## 实际交付与职责

本次用户要求是把Skill从固定方法文本升级为能够保存新成果、跨Session恢复和核对一致性的行动入口。已在工作副本原位实现，不是仅提出方案。

- 根AGENTS：全文加载、当前认知、权限、每个实质里程碑和结束回写、冲突/依赖复核、自主方法边界。
- 根MEMORY：可更新的当前记忆；旧344行MEMORY在history完整保全，不能与当前态竞争。
- 第五闭包原文不变；三问从572行修订为595行，将合取、先发现/确认、九方向、自主构造与证据边界对齐。
- STATE是动态索引，FRONTIER保存调度，LESSONS保存失败/纠偏/重开条件，RESUME保存可执行下一问。
- Session记录保留原始请求、实际差量、依据和状态变化，不保存隐藏思维链；最近、活动、待复核、未解决及递归依赖的完整正文进入当次加载。
- Skill已原位升级1.2.0；不冻结曾经的文件长度、路径集合或旧加载收据。

## 加载机制

每次执行、新Session、用户要求继续而再次进入，以及上下文压缩后都重新plan，按当前文件内容阅读全文。固定必读包括第五闭包、修订三问、AGENTS、Skill、README、MEMORY、用户原文、研究owner/矩阵、Schema入口和认知协议。STATE递归加入最新会话、活动/复核/未决记录、它们的依赖与需全文读取的证据。

一次版本1的实际加载包含21份正文、333828字节、5210行；正文以17个分页输出，加启动阶段已经全文输出的入口文件，连续覆盖。该数字是当时快照，不是未来固定上限。详细字节检查见full-load-byte-coverage.json。工具无法观察模型语义状态，也无法证明后续压缩没有丢掉正文；哈希和EOF不能代替理解或压缩后重新加载。

## 动态回写与并发边界

checkpoint要求同批提交根MEMORY、FRONTIER、LESSONS、RESUME、STATE和一个新的不可覆盖Session记录。先校验输入快照/各文件基线，再独占锁，保全改前/改后字节，发布事务，逐项替换并最后发布HEAD。中间状态对守协议的读者不可用。

旧Session的快照不匹配就拒绝，不能静默覆盖新成果。依赖源哈希变化会列出直接和传递待复核对象；仅改哈希/时间戳不等于数学复核。中断恢复需明确确认原写者停止；只接受事务旧/新字节，第三方新内容或损坏备份会阻止恢复。支持finish或rollback，不自动抢锁或提权。

保证范围是同一文件系统中遵守本协议的读写者，不是分布式数据库；不能阻止外部程序不守协议写文件。权限不从历史MEMORY继承；本次治理实现不授予下一会话发布、Git提交、子AI或模型切换权限。

## 真实测试与证据

新治理工具的40项机械测试实际运行，40/40通过。包括全文连续覆盖、文件增长、错误/缺失、动态新增、递归依赖、来源变化传播、两次写回冲突、中断各写边界、finish/rollback、第三方写入拒绝、只读dry-run、Session不可覆盖、路径与UTF-8检查。精确命令、时间、stdout/stderr和退出码见test-execution.json与test-output.txt。

其中用新Python进程再次读取的是机械调用者，不是另一个AI或独立Fresh Session。未运行HoTT项目脚本、Agda/Lean或新数学实验。

真实工作目录的checkpoint另见real-checkpoint.json；新调用的plan及旧快照拒绝见fresh-invocation.json和stale-writer-rejection.json。它们记录本轮成果怎样进入下一次必读集合，不以模板存在代替交接。

## 认识连续性与智能性

共同起点、问题身份、证据范围、已知失败和权限要连续；具体证明方法、构造顺序、假设及候选结论可以被新证据改变。八种操作和三个调度位置不是封闭思想目录。新方法可直接尝试，之后才总结可复用经验，不先把Skill改成许可名单。

记忆不自动提高可信度。先前R001在对话中报告过不同检查数量和包名，但本次没有对应源报告/实验；已写Q-R001-EVIDENCE为待核，而非伪造PASS。缺件只阻塞其认证，不阻塞独立的研究。数学主张矩阵、理论来源和用户原文未因治理升级而改结论。
