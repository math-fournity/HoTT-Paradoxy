# 四个形式模块的重放与命题忠实性

## 1. 重放结果及解释边界

四入口使用原RUN.json的实际命令，经当前 `verify_formal_proof_run.py --rerun` 重放，全部exit0、`PASS_WITH_SCOPE`、`EXACT_EXIT_STDOUT_STDERR_MATCH`。工具链Agda2.8.0-3d04bac/Cubical0.9；源码含safe/cubical/guardedness/two-level。记录在[REPLAY.json](../../audit/zcode-7cb03240-review-20260920/replays/REPLAY.json)，原始输出按run分目录保存。

这是**四个精确模块的重放事实**。校验器返回的`scope`是旧RUN自由文本，不是它独立证明的自然语言定理；本轮特别发现其中有不受代码支持的解释。G4四proof目前未列入`PROOF_VERSION_CLOSURE.json.later_packages`，所以本轮不宣称通过全部包关系/版本闭合，也不把它们直接加入已验收15包分母。

## 2. RingOrigin：保留控制，限制“来源”含义

源：[RingOrigin.agda](../../HoTT/formal/flash-first-hunt/RingOrigin.agda:36)，run=`20260919-MP-G4-RING-ORIGIN-02`。

36–37行定义 `SourceCarrier C p = Σ[ x ∈ C ] (¬(x≡p))`；45–46行把已有x及已有不等式装成pair；52–57行`BreakoutFromM`的输出仍是相同Σ，body为`x.fst,x.snd`。77–78行给的是整数排除0的实例。

可吸收：指定参数下的排除型、配对/投影与非空实例控制。**未交付**：两个端部、共同缺口、环境嵌入、构造历史、时间过程，或从裸N恢复指定p。p在函数参数上下文中已经给出；源码没有实现“从对象取出被遗忘的p”。把这一pair称为完整“断点三件套”的最小证明仍缺语义对应。

与本方关系：已有`PathExclusion.agda`/`PointRestoration.agda`研究相同排除形态及恢复义务，不能重复计算为独立几何突破；原生HIT路径排除与点集删点的区别继续保留。

## 3. NoBreakout：精确反证与口头目标不一致

源：[NoBreakoutFromBare.agda](../../HoTT/formal/flash-first-hunt/NoBreakoutFromBare.agda:31)，run=`20260919-MP-G4-NO-BREAKOUT-02`。

31–33行的精确目标是给定C和p，否定`(x:C) → ¬(x≡p)`；证明体直接是`f p refl`。这里**p明确在场**，也没有任何“遗忘p”的输入接口。代码反证的是“所有x都不等于p”这种规格，包括x=p自身；Unit实例只是已有定理的一个应用。

因此，“不知道p所以无法排除p”“裸N无法恢复缺口”“信息遗忘不可逆”“参数性/free theorem元层结果”都不是这段代码实际检查的目标。第5节新增的是注释及范围说明，没有新增元层语法、语义或参数性证明。将其标记为**排除规格过强的反证控制**可复用；若要来源恢复不可行，需单独给出Forget、恢复输出与观察保持条件。

## 4. BreakpointBridge：目前只有自身恒等函数

源：[BreakpointBridge.agda](../../HoTT/formal/flash-first-hunt/BreakpointBridge.agda:22)，run=`20260919-MP-G4-BREAKPOINT-BRIDGE-03`。

22–23行又定义一个排除Σ；29–31行是`bridge : ExcludedCarrier C r → ExcludedCarrier C r`、`bridge x = x`。imports没有RingOrigin、CutGoldForm、CutRealLayer、ℚ、ℝ或实际圆环模型；具体实例仍是ℤ去0。

所以本轮认可源码重放，不认可“GOLD L/U与圆环已连通”。目前没有函数从实际cut成员、逼近轨迹或圆环状态出发，没有输入/操作/观察/完成的保持定理。两个任务都使用Σ形状，只是建模线索。`r:C`还需要真实类型选择：不能把一个预定不存在的有理根当作已经可传入的ℚ参数。

## 5. CutAsSourceCarrier：函数族不等于cut成员载体

源：[CutAsSourceCarrier.agda](../../HoTT/formal/flash-first-hunt/CutAsSourceCarrier.agda:24)，run=`20260919-MP-G4-CUT-AS-SOURCE-01`。

27–28行的`FamilyCarrier C r`实际是`(q:C) → ExclFamily C r q → ExclFamily C r q`，**是接收并返回已有排除证据的函数族**，不是`Σ q, L q`或`Σ q, U q`。35–36行`family-to-point`继续要求调用者提供`x≢r`；53–55行`family-ok q e = e`。

实际GOLD的L/U、顺序、roundedness、locatedness以及实数表示未导入。文件39–42行注释称“ℚ层/√2 cut”，但实现没有对应ℚ实例。故保留为谓词族函数/应用控制；“cut每个成员携带排除证据已机器化”的解释尚需真正接入cut。

## 6. 对未来实现的直接影响

以后复用这些模块时先使用精确类型名与实际作用，不沿用过强注释。完整桥必须从实际GOLD/实际圆环输入构造，明确所得排除证据是否丢失左右信息、是否仍满足原观察与Done。仅有`id`或重复定义别名不能通过该验收。

以上是对已重放源码与声明之间的忠实性审查，不是新的一般不可定义性定理，更不是HoTT内部矛盾。本轮未改作者源码或旧收据。
