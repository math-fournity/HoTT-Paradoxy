# 目标、成功判据与既有证据

## 1. 父目标与本轮权限

当前目标的第一阶段是数学真理性地判断原四弹是否已经建立一个 HoTT 现实相对问题：同一 X 的任务，经过明确的 HoTT 理论化后，发生可证明的完成障碍或交付能力越级。它不以“又有一段代码通过”为终点，也不预设一定要导出基础 HoTT 的空类型。若第一阶段的证据只能支持范围内未成立或局部成立，该判词本身是完成结果；新的失配候选另属第二阶段。

用户当前授权是持续Goal：先补入方案，完成断点与证明机制检查，据实际结果不断更新本策略，再继续执行完整策略，并维护跨压缩认知。当前AI负责本专题证明/运行/索引及相应状态集成；其他AI的审计原件保持其所有权。不调用Sub Agent，不把研究授权扩大为公开发布或push。

“击落”是用户对研究目标的称谓。最终学术输出必须落实到精确被否定的命题/解释/理论配置，不能把这个词本身作为已成立判词。

## 2. 成功不能只由四个局部结果相加

完整成功证据至少有六项，缺一项不得宣称原目标完成：

| ID | 必须具备的内容 | 验收对象 |
|---|---|---|
| AST-G01 | 一个固定的 X、操作、可用信息、观察与完成条件 | 同任务规格及来源；不靠名称相同 |
| AST-G02 | 一项确切的 HoTT 理论操作或声明能力 | 演算/规则/实例/引用；能定位为何这样建模 |
| AST-G03 | 目标困难的正确形式命题 | 全称不完成、无实现或明确行为失配之一，量词不能滑动 |
| AST-G04 | 共同任务到形式命题的保真连接 | 输入、观察、操作、完成保持；全部假设可见 |
| AST-G05 | 最强保任务恢复和单因素对照已经检查 | 不能只证明一个故意贫乏的表示失败 |
| AST-G06 | 源码、原生核、依赖、收据、解释与反例范围一致 | 数学检查与理论/现实解释分别验收 |

方向 A 还需在同一比较合同下提供现实/参考侧的完成证据。方向 B 还需定位理论所得被当成有效交付的那一步，并证明该交付未被取得。若现实侧来自假想现实或显式操作模型，结论要标为该模型相对；不能伪装成已经实测的物理定律。

## 3. 六种终局都必须可报告

| 结果 | 可交付内容 | 是否完成父目标 |
|---|---|---|
| `TARGET_MISMATCH_CONFIRMED_WITH_SCOPE` | 六义务齐备的现实相对失配，明确作用域 | 在所声明的目标范围内完成；原创性/学术影响另验 |
| `REPRESENTATION_BOUNDARY_ONLY` | 某个表示/接口不能承担指定观察 | 否，保留为辅助结果 |
| `DEFENSE_PRESERVES_TASK` | 合法恢复保留原任务与信息 | 当前候选被否定；不是“换一种方式击落成功” |
| `WRONG_SPECIFICATION_OR_ATTRIBUTION` | 规格换题、错误公理、归因无据 | 当前实例退回重构 |
| `OPEN_WITH_PRECISE_OBLIGATION` | 精确未决命题、已尝试路径和剩余义务 | 否；有界单元可结束 |
| `ORIGINAL_FOUR_STAGE_REDO_COMPLETED_WITH_SCOPE` | 原四层、层间桥、承诺、保任务恢复与证据范围均已对账，整体判词为未建立或局部成立 | 是，完成当前 redo 第一阶段；不等于第二阶段的新候选研究已开始 |

若真的出现 `⊥` 候选，立即单列精确演算、所有公设、工具版本与归约/可信基检查。它既不被预设为不可能，也不自动被认作基础 HoTT 不一致。必须排除额外不相容公设、实现现象和错误输入后，按相称流程独立复核。

下表引用现有资产及首次审计的范围，不重新注册数学结论。原 run、源码和索引保持历史身份。

## 6. 是否重新执行四弹：本次执行裁决

用户2026-09-20原问：

> 所以为什么我有种好像之前的四弹没有被AI成功执行的感觉？我们是否有必要把之前的四弹，重新让你去执行一遍？

当前AI的判断是：已有有效的局部形式化、运行和修复，但用户要求的同一X、同任务与HoTT归因的完整链没有完成；历史上若干答复过早把局部成功当成整体成功。需要由当前AI重新验收并执行关键论证链，而不是机械重复编译全部旧文件。第三十五轮已经完成这项对账，结论是原整体击落论证未建立；按 2026-09-21 的两阶段 goal，这一范围判词完成 redo 第一阶段，不预设或启动第二阶段。

原题从用户原文和后续明确修正恢复；最初圆环表述与后来四层规格分别保留，不默认Pell/Spec_A/Spec_B已经保真代表原圆环。任何替代实例先证明输入、动作、观察和完成的保持，失败则分开交付。

| 四层职责 | 可以复用的实际成果 | 必须重新验收或完成的连接 |
|---|---|---|
| 过程层 | 原Pell递推不变量；实际几何的环境否定与连续正构造 | 哪些过程正是原允许过程；“不能完成”量化的类别，不能从单一算法扩大到所有方法 |
| 对象与兑现层 | 有理精确根边界、GOLD算术及部分实数表示材料 | 原任务到底要交付什么；表示/查询/逼近/过程完成分别检查，不让有理根规格替代任意实数任务 |
| 识别层 | M3-UNC规格非等价及边界控制 | 哪个真实HoTT操作或使用承诺把两者相连；保结构表示、Forget、消费者和Done是否保持 |
| 元层 | 已核条件引理、明确公设控制和历史观察 | 充分/必要、对象/元层、特定实现/理论配置分开；只对主实例实际依赖的前提归因 |

本轮第6/7轮Lean构造与旧Agda成果同样接受题意审查。C-269至C-273闭合其声明的允许端部移动合同，不自动满足固定端部/环境/历史条件；不能因为是当前AI的新代码就免除保真义务。

重新执行的每个实际单元使用同一条链：原文要求→精确规格→源码/核结果→任务保持证据→理论归因。复用的旧定理不重新计作突破。遇到保任务正恢复或反例，应明确关闭对应候选；若原规格矛盾、错题或缺乏理论侧承诺，返回修订而不是把任何结果都改名成功。能否最终得到HoTT问题由证据决定，不由换一个AI保证。

按原意重新执行已有C281–296的直接原生实数点集/结构/限定任务，以及C297–303的标准GOLD和算术请求对照。它们不穷尽原广义操作/弱域条件及四层整体。具体下一动作由第010片与STATE拥有，本节不复制独立执行队列。继续以真实输入检验原意与理论联系；不另建并行重启方案、不清空已有证据、不改变已授权父范围。
