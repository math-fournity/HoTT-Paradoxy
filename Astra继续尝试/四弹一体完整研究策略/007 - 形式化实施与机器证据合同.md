基础证明入口使用实际 `OPTIONS --safe --cubical --guardedness`，只有确需时才加 `--two-level` 并说明用处。理论检查以真实 pragma、命令及传递导入为准，不再以注释中是否含 `--safe` 判定。普通公设演示单列目录/单位；不得在 safe 主证明中隐藏导入。

Lean/Coq 可以作为已固定辅助命题或模型研究工具，但若结果涉及原生 HoTT 规则，必须原生证明或另有已检查保真翻译；不能用同名 Eq/实数类型自动转移结论。

## 3. 当前脚本的实用与已知边界

实际核查了以下 CLI，不虚构参数：

```text
capture_agda_proof_run.py --run-id ID --proof-id ID --claim-id C-N
  --source REPO_RELATIVE_SOURCE --toolchain REPO_RELATIVE_TOOLCHAIN
  --manifest-file DEPENDENCY_PATH [可重复]
  --scope EXACT_SCOPE --non-goal NONCLAIM [可重复]

verify_formal_proof_run.py --run-dir HoTT/verification/runs/ID --rerun
mark_proof_run_indexed.py --run-dir HoTT/verification/runs/ID
freeze_proof_index_rows.py --help
```

这里的 `--manifest-file` 是额外源路径，不是读取另一个 JSON 清单的开关。capture 不自动发现本地 import 闭包；每个本地依赖必须显式纳入并对照实际 checker 输出。当前 capture 要求 project root 的 `.git` 为目录，不能假装已支持任意 linked worktree。当前 mark 的 claim 解析有 `C-数字` 约束：本策略 `AST-*` 是计划义务 ID，不冒充已注册 claim；实际 C-N 由 canonical integrator 在运行前分配，不擅自固定一个可能冲突的编号。

第三轮已修复matrix前缀、legacy CAND身份、真实外部依赖树消费及字符串伪pragma问题。每个当前交付包必须分别通过formal-run源码/选项资格与明确proof分母的关系检查；本地关系命令为`verify_proof_version_closure.py --evidence-only --proof-id MP-...`，不会给Git或全仓PASS。默认全registry版本检查仍执行并记录失败；源码漂移、错接行、未列本地依赖等不能因选择范围而忽略。精确合同见数学证据规范v1.2；不手翻index_status制造完成。

## 4. 每个新结果的证据包

正向包须有：精确命题及假设、native proof source、依赖 manifest、实际 command/cwd/非敏感环境、stdout/stderr/exit、版本、时间、scope/non-goals、claim/proof/run 连接、控制与当前 Git 状态。

每次源码/依赖/命题变化都生成新 run ID，不覆盖旧收据。重放已有 claim 使用明确的 replay 关系；“输出恰好一样”不替代源码身份。

预期负向控制至少记录：目标诊断类别、预期 exit、对应正控制、允许的路径规范化、原始输出 hash、公设和观察范围。缺文件/错误 include path/语法错误不得算“预期的类型拒绝”。负 run 保持控制身份，不走 positive theorem 的索引资格。

命题正文、代码、摘要中的条件逐项对账。`registers_new_claim:false` 不是允许交付无证明数学断言的豁免。

## 5. 运行、超时与恢复

执行前记录本次观察预算；当前 capture CLI 没有 timeout 参数，不传不存在的选项。需要受界运行时复用获准的进程控制/外部 watchdog 并保存真实命令与取消结果，不能把 wrapper 的 timeout 写成 Agda 的数学判词。长运行以状态和新输出沟通，不固定轮询空结果。

遇到异常先保留 run 原件。源码漂移→新 snapshot；工具链 hash 不符→停止使用该缓存；负控制错因→该控制失败；正文与类型不符→修 owner 后新 run；部分写入→保留并新建完整 run，不补造旧成功。不得自动删除历史 `.agdai` 或其它写者缓存以求 clean；`--ignore-interfaces` 负责需要的完整检查。
