# 第四弹：必要条件与元层归因

## 1. 第四弹不再承担“重新解释失败为成功”

第四弹的任务是证明第三弹所得现象究竟依赖什么，并确定它能否支撑用户目标。类型检查拒绝、对象层否定、元层不可证、程序发散、规范性失效分别立项；没有连接证明时不能互相代替。

充分性P→Task、必要性Task→P、以及P相对于明确基线是否必须新增，是三个不同义务。C307/C308已经为指定同点/求逆合同给出前两种关系，但没有给出第三种不可导出/独立性证明。任何“必付”表述都必须说明究竟是哪一层，而非把显式参数本身当严格新增前提的证明。

不预设所有理论、所有经典理想元素都满足同一“三选一”。对每个明确实例写具体定理，再判断是否存在可证明的一般化。分类语言不是元定理。

## 2. 理论配置基线

| 配置 | 内容 | 可比较的事项 |
|---|---|---|
| T-CUBICAL-BASE | 固定 Agda/cubical 的原生规则、明确使用的 primitives/HIT；safe 入口 | 已有构造能力与本任务的直接实现 |
| T-LEM-PROP | 加入精确 universe 的 mere-proposition LEM | 该原则怎样改变当前任务；不使用对所有类型的 LEM∞ |
| T-RESIZE | 命名的 pointwise resizing 或 Ω-smallness，分开层级 | 哪种结构足够、哪种必要、是否有其它路线 |
| T-CHOICE | 一个写明 domain、truncation、量词的选择原则 | 从什么存在性得到什么选择；不只 postulate 现成 ch |
| T-OPAQUE-DEMO | 指定无计算规则的常量扩展 | 仅诊断不透明性，不当作基础 cubical 的行为 |

同一名称若取不同配置，run 和公开陈述必须分别固定。“不额外收费”的数学化仅表示相对明确基线不增加某类假设/输入，不表示没有任何公理、时间或工程成本。

## 3. Ω 与实数小型化支线

标准dcut的命题性/层级、Book记法桥及原GOLD装配已有C297–299；后续`SmallRD ℓ`仍是独立小型化目标。原`SingleOmega ℓ`、`PropResizing ℓ`、`LEMProp ℓ`保持不同原理，重放成功不等于同义。当前圆子任务接口没有显式要求SmallRD，但不据此宣称已穷尽固定库全部公设的逻辑后果。

待检验的目标：

| ID | 目标义务 | 允许结局 |
|---|---|---|
| AST-OMEGA-SUFF | 给定明确 small Ω，构造标准 RD 的 small copy | 构造/反例/规格修订 |
| AST-OMEGA-NEC | 从精确 SmallRD 推出某个独立命名的原则 P | 证明/反模型/OPEN；P 不能定义成目标本身来制造必要性 |
| AST-OMEGA-ALT | 层级追踪、σ-frame、Cauchy/choice 路线与标准目标之间的关系 | 精确保真或指出变更；文字提及路线不是模型反例 |
| AST-OMEGA-TASK | 原始 X 的任务为什么需要这种 small copy | 对应证明或明确不需要；不需要则停止将其用于原目标 |

尝试必要性时预先声明欲推出的 P 及 universe，不在证明失败后把“某种原则”不断放宽到任何定义都算代价。0/1-cut 编码若在 locatedness 处调用了目标原则，登记循环依赖；既有失败分析不是所有反向证明均不可能的证明。

首次精确目标固定为 `AST-OMEGA-NEC-SO : SmallRD ℓ → SingleOmega ℓ`，不能在该 ID 下换后件。替代路线初选为有理数子集族的可数选择 `CCℚ`：对 `P : ℕ → ℚ → hProp ℓ`，从逐 n 的截断有理见证取得截断的统一有理选择序列。是否由它得到当前精确 SmallRD、是否与 ¬SingleOmega 共存，都另立目标并实际证明；本计划不预先接受旧 030 片的相关蕴含。若研究更弱的必要原则，分配独立目标 ID、说明与初目标关系，不把弱化后的结果报告为原目标已证。

`LEM→Necessity` 的实数前件未用，保留为条件校准，不充当 AST-OMEGA-NEC。CC 反模型只能在模型存在、原则解释及目标 SmallRD 的含义都被证明后，才否定必要性；旧 030 片的模型设想不是现成证据。

本支线没有 AST-OMEGA-TASK 时，只能交付宇宙/小型化结果，不得把它接成圆环主线的第四弹成功。

## 4. 规范性与公设控制支线

重建三类对象，分别审查前提：

1. 标准 native `ua` 的消费者；与明确不透明、带所需连接性质的公理化 UA 消费者对照。
2. `(P : Type ℓ) → isProp P → P ⊎ ¬P` 或精确等价形式的 LEM；不再从 `LEM ℕ` 取任意自然数。
3. 精确 choice 原则及由它取得函数的消费者；区分原理、已给数据和程序。

另加入一个普通不透明常量控制，排除“任何 postulate 都会产生同类现象”这一通用原因被错归 HoTT 独有。所有 `refl` 负向探针仅证明所测试转换被拒，不证明目标的命题否定。

若要交付“某项在此演算中是中性形式/不能归约到构造子”，需要明确归约关系和语法证明，或受限范围内可靠的规范化证书。若要交付全部闭项的规范性或一致性，先资格化相应文献/形式化演算，证明它与实际 flags、HIT、原语和公设配置的适用关系。无需为一个局部工具观察先重造完整 Huber 证明；反过来，局部观察不能认证全理论。

## 5. 不可证性、自指与元层证明

本轮主线不自动复活全部 Gödel 工程。只有当候选确实需要“某精确命题在 T 中不可证”时，才固定有效公理化、语法/证明编码、可表示性、证明谓词、导出条件和一致性前提，并消费已有 R3/R4 资产的适用部分。

不能从“HoTT 内证明了 ¬E”推出“HoTT 在自反时必然不完备”，也不能从缺少模型/翻译推出该翻译永远不可形式化。“现实判词选择不形式化”不是一个不可表达定理。

## 6. 归因的反向检查

至少检查三个问题：

- 去掉 HoTT 特有构造，是否得到同一机制？若是，标为通用机制的 HoTT 实例，不丢掉其实例价值，也不宣称 HoTT 独有。
- 保留共同任务的更充分表示能否恢复？若能，原贫乏表示失败不能升级成基础理论不适用。
- 失败是否由额外公设、外部语义/物理假设或当前软件实现产生？分别列依赖，不合并为“HoTT 自毁”。

## 7. 整体交付的实际形式

最终给出一个明确的条件定理/反例包，并逐项说明它否定的具体命题、证明的精确层级、现实对应及适用域；需要的解释性论证与机器定理分开，但不允许缺失。

第一弹的过程证据、第二弹的理想对象、第三弹的关系与第四弹的归因，必须由同一任务参数和已证明的接口连接。任一连接未完成，整体保持未完成；其中一个候选被正控制反驳时，不能借另一个不相关分支改名为四弹成功。
