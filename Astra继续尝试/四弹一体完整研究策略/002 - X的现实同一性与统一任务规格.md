# X的现实同一性与统一任务规格

## 1. 共同指称先于理论表示

用户原意来源为 ZCode `72#/request/messages/62`：M/N 的数学身份可能变化，但仍指向数学现实中的 X 与其变换过程。本设计把这条共同指称要求当作研究起点，不让 HoTT 的某种等价判据替研究者重新选定研究对象。

随后要验证的是两套表示是否忠实于该共同对象。标上相同 `origin_id` 只提供 provenance，不证明两个任意模型已经描述同一个过程；相同对象在不同阶段的延续也不等于所有阶段性质相同。形式化必须保留这些差别。

## 2. 选定两个实例，禁止无证明互替

| ID | 角色与对象 | 固定范围 |
|---|---|---|
| `AST-X-RING` | 主问题：带指定点和来源/操作历史的圆环、删点所得 M、展开表示 N、复原任务 | 以用户原始圆环论述和修订片 022/023 为来源；任何理想化假设逐项公开 |
| `AST-X-SQRT2` | 校准支线：同一代数数的查询、近似、精确表示与有理根规格 | 复用现有 M1–GOLD；验证旧替换是否保留任务，不默认代表圆环 |

两线要共用的是任务对应的检查方式，不是默认相同的数学对象。若提出它们同属一个候选类，另证明 source→target reduction 保留输入、操作、观察与完成；只说“同形”不够。未建立 reduction 时，两线结果独立计量。

## 3. 原圆环的建模选择已经具体化

几何主模型采用**点集/结构化拓扑对象**：一个带指定点的圆 `C_pt`、删点子对象 M、开区间呈现 N 及相应结构映射。默认 N 是历史 022 片明确使用的 `(0,1)`；如果要研究闭区间或其它端点结构，另立 `AST-X-RING-CLOSED` 变体，不能事后混用。

M/N 之间所需的同胚、嵌入、指定点恢复等都列为待证明义务；本计划没有把它们 postulate 成最终结果。保持它们的来源图及复合关系，才算保住 X。

**不将原生 HIT `S¹` 直接当点集圆。** 原生 `base/loop` 用于同伦/运输控制。若要把点集圆转为同伦对象，再证明该转换能保留当前需要的观察。旧“只有一个点构造子所以任意 x 的路径已给定”的说法不作加载前提；mere connectedness、选定路径和可删点对象分开检查。

首轮`PathExclusion.agda`与`RationalPointSet.agda`分别是内部路径排除和有理点集控制，其原范围不变。当前C-281至C-290已在固定no-erasure agda-unimath/without-K配置中构造实际Dedekind点集圆、metric、原(0,1)和强域/条件弱域的连续互逆及原生Path作用；这是直接原生证明路线。没有把HIT圆替换成点集圆，也没有声称这些实数结果已经全部移植到先前Cubical变体。

第二轮extend/PointDecidable、第四至七轮Lean实际几何/F/闭参数纤维及第八轮边界观察保留各自证据范围。C-291/C-292现对C290同一实际逆映射直接证明闭参数延拓、内点一致、连续及端部像，M两端同像与N直线异像由公式推出。这里未证明Cauchy泛性质或原物理Trace，旧Lean的完整F也不自动获得原生身份。下一步用实际StrongPuncture/原(0,1)为Bare、真实延拓为Rich接Task合同；不能退回环境Plane的恒等关系，不能只填端点答案标签，也不把较弱过程当固定端点任务。

## 4. 统一任务接口：设计草图，不是已检查 Agda

下列字段是 `TaskContract.agda` 的语义要求；精确 universe 参数在实施时按类型检查确定，未运行前统一 `CONTRACT_SKETCH_NOT_KERNEL_CHECKED`。

```text
Input                -- 初态、X 的来源和允许提供的数据
State i              -- 输入 i 下的过程状态
initial i : State i
Step i s t           -- 一次允许操作；不是任意可定义函数
Trace i s t          -- 由 Step 形成的有限执行，实际定义后证明连接律
Observation          -- 任务在开始前选定的可观测内容
observe i s
Done i s             -- 同一完成标准
Output i             -- 允许交付的结果类型
Satisfies i out       -- 输出正确性；不与 Output inhabited 混同
Denotes i repr       -- 该理论呈现怎样指向同一个 X
```

两表示 `R₁/R₂` 必须各有 `Denotes`、初始化、操作模拟、观察对应与完成保持。需要双向替换时证明双向；仅有正向模拟不得标成等价。

接口的初始 universe 选择采用显式多态：`Input : Type ℓi`、`State i : Type ℓs`、`Step i s t : Type ℓstep`、`Observation : Type ℓobs`、`Done i s : Type ℓdone`、`Output i : Type ℓout`；组合记录位于这些层级及所用类型量化的 join，不使用 `--type-in-type` 或隐式 resizing。`Step` 保留动作见证，有限 `Trace` 由 nil/cons 构造。最终 universe 推导由核检查，但实现者不得擅自以降层公设消除报错。

第一版同时定义 `FiniteSuccess i = Σ s, Trace i (initial i) s × Done i s` 与 `MereSuccess i = ∥ FiniteSuccess i ∥`。前者携带实际有限执行证据，后者只承载命题意义的可达性；程序交付还需独立的有效代码/执行正确性，不由任一个名字自动取得。保持定理明确它搬运的是 Trace、截断存在还是程序实现，禁止再次漏掉这一差别。

“现实完成”若由现实操作或假想现实模型给定，单独列来源及假设。量子化运动、普朗克尺度和最小瞬移不作为已证事实输入；可以建立显式离散模型，但其结果不能外推成现实物理。dense/continuous 与事件先后分别有字段。

## 5. 三类完成必须预先分开

| ID | 完成意义 | 不得互换 |
|---|---|---|
| `DONE-EXACT` | 有限合法 Trace 到达所指定的精确终态/交付值 | 不能由每个有限精度都可达替代 |
| `DONE-APPROX(n)` | 给定精度 n，有限返回满足该精度的结果 | 不要求运行一次便枚举所有 n |
| `DONE-REP` | 得到有限的定义/程序/证明项，满足明确对象规格 | 不声称对象所描述的一切过程都已经执行 |

原问题选定哪一种，另一表示就比较同一种。允许研究它们之间的转换，但转换的前提和结论必须另写。第一阶段必须确定每个任务的 Done 及来源，不能等出现差异后挑一个能得到否定结论的标准。

## 6. 共同 X 的保真验收

`AST-BRIDGE-001` 的目标是对一个固定实例提供以下材料：

1. 原始 X、M/N 的明确数学对象与来源；
2. 两表示共同指称 X 的关系与初态对应；
3. 每个被使用的动作如何模拟，是否增加数据/删掉历史/改变合法操作；
4. 观察是否在同一时点/尺度/精度比较；
5. Done 是否保持；不保持时给具体失败输入，而不是只比较类型名称；
6. 反解释是否满足同样合同。

这个包是主链最小连接，不是另建全现实的总模型。完成一个有界 X 即可进入下一层；没有必要先形式化所有数学哲学或证明时空本性。
