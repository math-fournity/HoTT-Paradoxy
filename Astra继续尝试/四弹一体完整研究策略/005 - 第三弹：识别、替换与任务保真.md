# 第三弹：识别、替换与任务保真

## 1. 本弹改变旧 M3 的关键位置

旧 M3 证明两个自定义规格不等价，新第三弹要审查**某次具体识别/替换是否保留共同 X 的任务**。它不能从“都用 HoTT 表达”推得理论承诺二者相同。

识别来源分成三类：

- 原生规则或定理许可的转换，例如实际使用的 `ua`、transport、商消去；
- 明确的一手数学构造/接口，把某种对象当作某种能力使用；
- 为研究自主构造、理由清楚的解释合同。

第三类无需先有真实软件事故，但结论必须带解释合同的范围。若要升级为基础 HoTT 的缺陷，必须进一步表明是哪条理论机制导致问题，不能靠自主加入不相容要求完成归因。

## 2. 替换关系与任务等价分别定义

实施 `RepresentationBridge.agda` 时，至少固定：

```text
encode₁ / encode₂                  -- 同一 Input 的两个表示
Denotes₁ / Denotes₂                -- 共同 X 的对应关系
TheoryRelated r₁ r₂                -- 实际理论许可的关系
Use₁ / Use₂                        -- 指定消费者，含输出正确性
ObsRelated (Use₁ r₁) (Use₂ r₂)      -- 预先选择的观察关系
CompletionPreserved                -- 同一 Done/交付要求
```

完整统一接口仍是设计义务。C-275–C-286完成各自边界观察、实际实数模型、输入条件、全参数等价及原生Path作用。C-287/C-288又用实际逆元局部模数，把同一两映射接到原度量，取得强域↔Real的双向连续互逆；原W域仍显式依赖Lift，LEM只充分。这个同胚合同没有声称metric数据相等、等距或构造来源/端部过程保持。后继接同一(0,1)开区间，完整弱域和原操作条件仍开放。

候选 `AST-PRESERVATION-001`：这次合法替换对所选任务保持观察和完成。候选 `AST-SEPARATION-001`：存在精确输入及相关表示，消费者结果不能在同一观察合同下对应。二者先同时尝试，不先选择有利的一边。

## 3. 防止“把不可能性写进规格”

禁止下列做法：

1. 让“HoTT 的工作方式”直接定义为 `Spec_A ≃ Spec_B`，再用旧 M3 否证，宣布发现；
2. 先令 consumer 依赖被自己删除的信息，再把必需信息的缺失当作理论新增问题；
3. 在 A 的输入预置答案、B 的输入不给答案，却声称比较同一任务；
4. 以原理名称代替真实使用位置，例如看到 resizing 就当它承诺算法交付；
5. 让参考模型中的 Done 按自己希望取值，而没有独立的任务依据。

为每条关系保留来源句子、形式定义和调用链。若来源只承诺结构等价而未承诺某种操作等价，必须记录这个限制。这个限制是否使原理论不适于原任务，可以继续研究，但不能伪称其已经违反自己的定理。

## 4. “不同规格”不是自动结束，也是不能省掉的检查

共同 X 允许研究者追问理论为何合并或分开某些结构。发现形式身份不同后，需要说明：不同发生在编码中，还是由某个理论操作导致；是否改变了原有观察与完成；是否是正确区分两个本来不同的任务。

本弹接受有根据的现实相对冲突，不要求先取得 `T ⊢ ⊥`。但冲突需要同一声明范围内的前提与后果，而非把不同的分类标签写成 P 与非 P。

## 5. 最强恢复必须进入同一个证明包

对每个失败消费者至少测试：

- 保留原输入中已经有的来源/轨迹/标记，以 Σ/record 增强表示；
- 使用实际合法的消去器与其侧条件；
- 给出显式模数或程序，前提是这些数据能由原输入构造，不是免费增加；
- 保持 universe 层级而不强迫同层小型化；
- 用原生计算性 UA，而非额外不透明的同名 postulate。

每个恢复必须说明哪项合同不变、哪项新增。保任务恢复成功应得到 `DEFENSE_PRESERVES_TASK`；新增数据或改完成标准的恢复只能标 `RESTORED_UNDER_CHANGED_CONTRACT`，不能拿来消除原任务问题。

## 6. 旧 M3 的复用限度

M3-UNC 仍是有用的分离校准。实施 `Sqrt2TaskComparison.agda` 时先导入旧类型保持原身份，再定义标准 `SQ-QUERY/SQ-REP/SQ-APPROX` 的类型与可取得方式；证明哪些确有连接，哪些没有。不得重命名旧 Spec_A 让其看起来已等于新下切割。

M3 条件版只作依赖消融/历史对照，不作为第二个独立发现。若新任务链出现缺失的前提，不自动补成公设后宣布无条件结果。

## 7. 第三弹到第四弹的交接

第三弹必须给出一个完整的 `instance`：X、合同、表示、实际关系、消费者、观察、成功/失败证据与最强恢复。第四弹只对这个 instance 作归因，不另找一个不相关的 Ω 结果来替代其缺口。

只有该实例的真实来源和所有连接都闭合时，才允许使用“某个理论操作在该同一任务下造成失配”。如只证明一个自选表示无法恢复信息，状态保持 `REPRESENTATION_BOUNDARY_ONLY`。
