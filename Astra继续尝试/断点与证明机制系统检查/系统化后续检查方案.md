# 断点与证明机制的系统化后续检查方案

> ⚠️ 逻辑文档索引：全文 = 本索引 + 下方 7 个分片；缺一片即未完成，按表顺序读取。

本方案判断HoTT中的表示、等价、证明连接或信息消去，是否使一项必要局部条件在后续结论中被错误忽略。以用户“一点断开”作为开放机制入口，采用原生规则核查、正反构造、下游使用者检查和有界程序化生成；新数学命题均为候选/证明义务，设计存在不等于发现已成立。

版本`astra-breakpoint-check-plan/v1.2`；Git基线`40b1ca78fe0e391201848923e09423808a2178ee`。用户已授权实际执行，且明确要求先修复项目加载与检查点；该恢复已由revision173真实事务闭合。输入为[连续对话原文](对话原文.md)及[evidence/外部AI反馈-001/用户转交原文.txt](evidence/外部AI反馈-001/用户转交原文.txt)。v1.1完整设计基线保存于[evidence/方案v1.1基线/](evidence/方案v1.1基线/)。本版增加精确的内部路径排除、集合层删点及固定参照表示控制，不预认候选成立；执行结果另据真实源码与收据更新。

**主线：必要局部条件 → 表示/等价/消去 → 实际下游是否仍需该条件 → 合法恢复与反例 → 区分理论规则问题、附加公理后果、表示失配或正常边界。**

不预设只有来源、物理操作或复原能力重要；不将“一点”等同为证明语法一步。六机制族先横向校准，再对新信号深化。未命中只覆盖冻结范围。
