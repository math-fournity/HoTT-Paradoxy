# 额外归约的配置诊断

检查对象是 Agda `2.8.0-3d04bac` 加固定 agda-unimath `7b81411d9f60afec359d29ed1e4edf43f4711c8a` 的实际配置。不是把 Agda、Cubical Agda、univalence 公理和额外原语合并为同一个理论。

## 1. 观察与最小复现

实际实数模型初次检查在导入 pushouts 时给出 `WithoutKFlagPrimEraseEquality` 警告。上游 `.agda-lib` 的 flags 含 `-WnoWithoutKFlagPrimEraseEquality`；本次入口的显式选项让警告可见。警告的出现只是调查入口，不能独自证明矛盾。

源码 `ErasureConfigurationDiagnostic.agda` 没有新增 `postulate empty` 或未完成洞。它导入上游的 `primEraseEquality` 和 univalence，构造：

1. `eraseRetract`：由路径归纳得到 `primEraseEquality p ＝ p`。
2. `loopRefl`：对任意 `p : x ＝ x`，原语的特殊归约使左侧变成 `refl`，从而得到 `p ＝ refl`。
3. `swapEquiv`：Bool 上交换 true/false 的等价；`eq-equiv` 给出宇宙中的对应路径。
4. `swapAction` 与 `collapsedAction`：前者从 univalence 的 section 定律得到交换的动作，后者用 `loopRefl` 把同一路径的动作化为恒等动作。
5. `configurationEmpty`：由这两项取得 true=false，再用 Bool 构造子的区分得到 empty。

正式配置诊断 run：`20260920-MP-ASTRA-ERASURE-CONFIG-001-01`，exit 0，原始 warning 保留。它证实的是**这一额外归约与库公理组合被检查器接受了 empty 项**，并非标准 HoTT 仅用自身规则推导 empty。

## 2. 单项消融与正控制

原始库树保持不变，另建 D 盘隔离副本。数学变化只有把公开 primitive 改为同类型普通函数 `primEraseEquality p = p`；另一文件变化是独立 library 名称和删除相应 warning 抑制选项。完整差分与两树 hash 留在 `no-erasure/identity-replacement.patch` 和 `DERIVATION.json`。

对同一 `ErasureConfigurationDiagnostic.agda`，草稿对照在第 22 行给出：

~~~text
p != refl of type Id x x
when checking that the expression inv (eraseRetract p) has type p ＝ refl
~~~

这是精确的目标类型失败；缺文件的 attempt002 另存，不能算作成功负控制。attempt003 是原配置接受；attempt004 是普通函数配置拒绝。正式忽略 interfaces 的对照另由 `20260920-MP-ASTRA-ERASURE-CONTROL-001-01` 保存，不用失败运行领取正定理资格。

同时检查实际实数模型和旧 C-05，避免仅以“错误源码不再通过”声称整个研究环境可用。通过它们也只能说明相应源码可重放，不能认证全部库、全部额外公理或 Agda 实现永远一致。

## 3. 已知性与准确归因

Agda 2.8.0 的官方 Safe Agda 文档明确列出此 primitive 与 without-K 的兼容性问题；built-ins 文档解释端点定义相同时的归约。这是本项目新发现的环境资格缺口，不能包装成首次发现的数学危机。[Safe Agda](https://agda.readthedocs.io/en/v2.8.0/language/safe-agda.html)、[Equality built-ins](https://agda.readthedocs.io/en/v2.8.0/language/built-ins.html#equality)。本轮已实际访问这些版本化一手页面。

上游 erasing-equality 文档也公开解释这种行为，并举 circle loop 的例子。当前源码全树精确搜索只找到 pushouts 中两次实际调用，用于两个点构造子的 beta 证明；不能因此推断每个导入它的已有定理都使用了危险的自环归约。库中特定受限调用是否能保守消去，必须以对应证明重放判断。

四弹项目里的普通 Cubical `--safe` 证明和这套公理式 without-K 库是不同输入；本轮结果没有撤销前者，更不能把所有 Agda 拒绝或接受都归因于这一项。需要调整的是原 agda-unimath 配置的证明资格说明及其实际消费者。
