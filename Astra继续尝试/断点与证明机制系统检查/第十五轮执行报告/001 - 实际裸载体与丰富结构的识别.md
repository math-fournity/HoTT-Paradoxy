# 实际裸载体与丰富结构的识别

C-293把前两轮的实际内在几何和闭图装配在同一原生类型中。这里的Bare分别为StrongPuncture和原OpenRealInterval，不是共同平面Plane。原弱删点W的无条件Lift仍未被省略。

## 1. Rich保存了什么

~~~text
CurveData A =
  parametrization : OpenRealInterval ≃ A
  realize         : A → RealPlane
  close           : ClosedParameter → RealPlane
  closeContinuous : 原度量下close连续
  agrees          : ∀u, close(openIntoClosed u)
                         = realize(parametrization(u))

RichCurve = Σ A:UU₁, CurveData A
Bare = 第一投影
~~~

mData导入C290真实逆映射、实际圆包含及C291同一延拓；agrees直接由mInterior推出。nData导入原区间恒等参数化、普通直线实现(u,0)及其真实延拓。二者端部值由C292导出，没有新答案标签。metric连续证明也进入数据，不只存几个坐标。

`barePath : Bare mRich = Bare nRich`就是C290原生univalence路径。它作用于内在类型，没有新增“所有结构都相同”的前提。

## 2. 指定丰富结构确实不同

EndCoincidence观察实际close在0/1的像是否相等。mRich满足，nRich不满足。对假设路径mRich=nRich沿该观察运输，会得到nRich的端部相等，继而矛盾；这给出`noRichPath`。

进一步的`noAnyBarePathLift`量化全部`p : StrongPuncture = OpenRealInterval`，证明`tr CurveData p mData`不等于预选nData。`noUniformBareRecovery`排除一个**仅以裸类型为输入**、同时精确返回这两份预选Rich的统一函数。它没有排除保留原数据、来源或额外参数的恢复。

裸载体路径与Rich无路径属于两个不同命题。这里没有把类型不同偷偷写成同一P和非P，也没有从丰富结构差异推出底层空间不等价。

## 3. 完整运输的正控制

令`transportedM = tr CurveData barePath mData`。它的载体已经是原开区间，但数据是由M整体运输所得。

`fullTransportPath`给出mRich到transportedRich的真实路径；`fullTransportKeepsEnds`证明端部相同保持；`transportKeepsClosedImage`还对全部参数证明固定平面里的闭图不变。运输由identity消去构造，不另假设结论。

这揭示了旧说法中的关键区别：

- 把M完整地用区间载体重新呈现，可以保留其端部结构。
- 运输所得的区间数据，不是另一份预先选定的普通直线nData。

不能把二者都叫“N”之后，声称理论先证明了同一完整对象相等、又拒绝相等。本轮代码保留其类型、数据与目标差异。

这项保留证明针对当前实际闭图及字段。原物体的所有历史/物理属性并未被这个record穷尽，故不能外推成任意现实语境都已正确表达。
