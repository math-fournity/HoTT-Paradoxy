# 有限环境任务的正反实例

C-294固定一个具体数学操作类：平面的双向点态连续同胚，并要求它与起点、终点的**同一闭参数标签**下的曲线呈现相容。本轮结论只覆盖此类步骤及其有限复合，不把它定义为全部物理或原用户许可操作。

## 1. Step的内容与独立不变量推导

~~~text
AmbientStep r s =
  motion   : PointwiseHomeomorphism RealPlane RealPlane
  commutes : ∀u, close(s,u) = forward(motion)(close(r,u))
~~~

字段里没有“端部相同必须保持”或“不能到达M”。`stepKeepsCoincidence`用函数对相等的作用推出保持；`stepReflectsCoincidence`再用真实逆映射及逆律推出反射，从而也得到端部不同保持。

但操作类本身仍是一个实质前提：它要求**全平面同胚**与闭图相容，强于只给每个时间切片的开曲线嵌入。本轮没有把重参数化、端部反向、增加/合并点、非全局环境变形或物理制造过程全部纳入该Step。旧Lean曲线族F不能仅凭名称被归入或排除此类，须检查实际合同。

## 2. Trace与Done实际落到代码

`Trace Step s t`是有限归纳数据：stop及一步证书加后继Trace。`appendTrace`提供有限拼接，`tracePreserves`把单步性质提升为任意有限长度。

~~~text
CurveTask = (initial : RichCurve, target : RichCurve)
Done task r = (r = target)
Success task = Σ r, Trace AmbientStep initial r × Done task r
MereSuccess task = ∥ Success task ∥
~~~

由实际M/N的端部事实得到`noTraceNtoM`与`noTraceMtoN`，再得到两方向`noSuccess`；N到M的mere success也被否定。这里没有“运行超时所以永不完成”的推断：否定由有限Trace的归纳定理给出。

这个Done是精确丰富对象终态的数学证书，不是物理时间消耗或数值算法。这里的Input为一对实际Rich、观察由closedImage给出；主策略要求的完整来源/Denotes和原现实操作对应仍需独立接入。

## 3. 两个不同用途的成功对照

**非平凡环境操作**：交换平面坐标是实际双向连续同胚。`swapSuccess`给出普通N到竖直呈现swappedN的一步Success；`swapActuallyChangesCurve`证明二者Rich不相等，故正例不只是“什么都不做”。其端部仍不同。

**同模型完整运输**：`richPathStep`从任意Rich路径构造合法AmbientStep，使用平面恒等同胚和实际identity运输。对第一片的fullTransportPath应用后，`fullTransportSuccess`在**相同AmbientStep与Done定义**下给出mRich到transportedRich的一步成功；mere版本也有项。它保留M闭图、换成区间载体，没有把target偷换成直线nRich。

因此当前模型既拒绝指定不相容目标，也接受保留原数据的重新呈现。不能只报道前一半，称为“HoTT无法处理来源”；也不能只报道后一半，称为“普通N已完成任意原复原任务”。

## 4. 裸表示过程不能任意升级

另定义`BareStep A B = (A=B)`，C290路径给出实际bareTrace和bareSuccess。`noUniversalTraceLift`用本例排除从任意裸Trace自动得到对应AmbientStep Trace的全域函数。

它比较两种明示操作合同，而不是证明HoTT自身曾许诺这个提升。理论是否在某个实际使用或原论证中把两合同混用，是下一来源/语义审查的任务。
