# 删点表示与圆的两种检查

## 内部路径排除

原生源码 [PathExclusion.agda](../../../HoTT/formal/astra-breakpoint-check/PathExclusion.agda) 的定义为：

```text
PathComplement A a = Σ x:A, ((x ≡ a) → ⊥)
```

这里排除的是“存在一条通到a的路径”。`connectedExclusion` 的输入还包含对每个x的 `∥a≡x∥₁` 见证。它只向命题空类型消去截断，没有从截断中免费抽取任意路径。库中给定的圆连通见证被用于 `circleExclusion`；内核接受相应映到空类型及等价的证明项（C-251）。

这不是“随便删除一个点就得到空集”的一般主张。文件内还包含Bool补集非空控制，明确排除这种外推。它也不是把S¹的唯一点构造子误认为唯一元素；第003片的绕数控制保留非平凡路径。

## 集合层圆形点集

[ RationalPointSet.agda](../../../HoTT/formal/astra-breakpoint-check/RationalPointSet.agda) 定义：

```text
QCircle = Σ x:ℚ, Σ y:ℚ, x*x+y*y ≡ 1
PuncturedQCircle = Σ x:QCircle, ((x ≡ east) → ⊥)
```

源码给出 `north=(0,1)`、`east=(1,0)`、两者不同、`north`属于删点后对象，以及QCircle为set的见证；C-255对应内核接受记录。这样补上了一个非平凡坐标对象的正控制，避免仅用Bool回答圆形问题。

**这仍不是实数拓扑圆。** 本文件没有定义QCircle上的拓扑、完成的实数、开区间同胚、环境嵌入或物理操作。因此不能把“有理坐标点集上的结果”写作“真实圆环模型已完成”。

## 两种结果如何并存

两份源码的输入和相等层级不同，且没有提供一个保持删点操作、观察和完成条件的比较映射。未经该比较，结果并列不构成同一P与非P。

从现实任务出发，这一差异值得调查：如果某使用链将点集圆换成其同伦表示，然后把路径排除当成删掉几何点，可能产生表示失配。**本轮没有定位到实施了这一步的真实理论推导或库调用**；这句话是待查机制，不是已经发现的社区错误。

## 外部AI反馈的价值与限度

用户转交原文保存在 [反馈原件](../evidence/外部AI反馈-001/用户转交原文.txt)。其价值在于把“删点”拆成可核验的表示问题，提出固定结构和实际消费者检查。相关候选已在本轮被具体执行。

需要限制之处：不能从PathComplement的行为推断所有删点操作；不能把集合型实数与“实线的同伦形状”混为一谈；不能把理论可以表达结构，自动当成原任务已经保真表达。第004片保持最后一项为OPEN。
