# 给定来源数据的原生重呈现合同

C-295/C-296在前轮真实模型上补齐输入、最终图对应与输出正确性的明确接口。这里的source是输入提供的完整Rich数据，不是从裸区间免费推测出来的历史。

## 1. 输入与任务各字段

~~~text
Input = (source : RichCurve,
         targetCarrier : UU₁,
         encoding : Bare(source) ≃ targetCarrier)

State i = Output i = RichCurve
initial i = source i
Step i = AmbientStep
Observation i = ClosedParameter → RealPlane
observe i r = closedImage r
Denotes i r = ∀u, observe i r u = observe i (source i) u
Satisfies i r = (Bare r = targetCarrier i) × Denotes i r
~~~

这是给定源图的精确重呈现合同。Denotes固定的是全参数函数，强于仅保端部同/异，也不等同于任意物理历史相同。未声称任意AmbientStep中间态均保持Denotes；本任务要求最终输出满足它。

`reexpressed i`把source的数据沿由encoding取得的类型路径整体运输。`Done i r`要求r等于这份明确目标；`Run i`携带有限Step Trace和Done。输出规格Satisfies还独立要求目标载体及全图对应，而非只靠Done命名。

本构造使用完整源数据及等价作为输入，**没有证明它们是所有可能构造的最小必要条件**。不能把一个充分输入合同写成普遍“收费必要性”。

## 2. 成功和输出正确性

`runReexpression`对每个Input构造真实有限Run；步骤由前轮richPathStep取得。`denotesReexpression`逐参数证明全闭图保持；`doneIsSound`从任意合法Done推出Satisfies；`checkedOutput`从Run提取真实终态及其正确性。

actualInput使用实际mRich、原OpenRealInterval和C290已核圆→区间等价，不是无实例的类型参数。`actualOutputIsTransported`核其输出就是前轮transportedRich；`actualRun/actualCheckedOutput`实际实例化整个链。

它支持“给定完整M数据，可以用区间载体保图重呈现M”。它没有证明“从未提供M来源的任意普通N，可恢复那段物理历史”，也没有执行所有实数参数所描述的物理运动。

## 3. 同一输入下的错误输出对照

普通nRich具有目标载体，`plainNBareAccepted`是refl。但`plainNDoesNotDenote`否定它的全图对应：若N的0/1像分别等于M的0/1像，就会由M同像推出N同像，与真实N端部不同矛盾。

于是`plainNNotSatisfied`、`bareCheckIsInsufficient`和`actualOutputNotPlainN`分别排除这个错误输出、排除“所有通过裸载体检查的输出都忠实”的提升、区分实际返回结果与普通直线N。

这证明一个具体的规格风险：只查类型载体会漏掉本任务实际要求的图对应。它没有证明HoTT的规则强制使用那个较弱检查；这里原生系统正接受了正确合同及反例。

`straightTargetStillFails`保留同一源mRich到预选直线nRich的旧AmbientStep精确目标失败。成功的重呈现目标与这份失败目标没有被混名。

## 4. 证据范围

该包使用前轮固定no-erasure原生配置、明确宇宙及库公设；没有额外LEM/Lift输入，因实际几何实例仍是已声明的强删点域。原弱删点定义无条件Lift保持OPEN。

本轮补齐的是source-supplied模型的Input/Denotes/输出与完成连接，不是所有用户物理操作的普遍合同。既不从正确核验推出完整现实忠实性，也不从当前反例推出HoTT内部矛盾。
