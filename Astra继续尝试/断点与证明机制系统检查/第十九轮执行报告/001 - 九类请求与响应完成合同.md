# 九类请求与响应完成合同

C-302把输入保留在Request中，把返回数据与正确性分为Output和Done，再定义`Response r = Σ o:Output r, Done r o`。层级统一使用显式向上Lift，小类型的内容可直接lower；这不是propositional resizing，也没有把高层实数载体压回低层。

## 1. 声明分母与实际结果

| Request族 | 输入/输出与Done | 实际结果 |
|---|---|---|
| representation | 返回标准载体元素，L/U必须等于原GOLD谓词 | 有响应；合格输出的值等于goldReal |
| queryL | 给q，返回Bool及与真实Lq双向对应证明 | 有响应，对全部q |
| queryU | 给q，返回Bool及与真实Uq双向对应证明 | 有响应，对全部q |
| approximation | 给n，返回实际Bracket及宽度=(1/2)^n；成员在Bracket内 | 有响应，对全部n；另接实际n次Trace |
| oldTable | 生成旧平方比较函数及全q正确性表 | 有响应，使用原无条件构造 |
| suppliedLower | 给正确旧Spec_A和q，返回正确Lq查询 | 有响应；与生成查询响应逐q相同 |
| rationalRoot | 返回q:ℚ及q²=2，保留旧Spec_B未额外加正号的类型 | 响应为空 |
| bisectionMeeting | 返回n及本二分lo(n)=hi(n) | 响应为空 |
| pellZero | 返回n及原Pell整数D(n)=0 | 响应为空 |

后两项是精确输出诊断合同，不能只因名称“相遇/归零”就说它们穷尽原物理任务。九族包含无界q/n参数，但不包含任意HoTT命题、程序或未来扩展。

## 2. 分派器的准确含义

`dispatch : (r : Request) → Dec (Response r)`逐构造子完成这九族。六族返回yes及实际认证响应，三族返回no及响应空性的证明。

它不是通用证明搜索器，也没有判定任意外来候选答案是否正确。表示响应直接构造goldReal；查询/近似调用现有算法；否定分支调用实际空性定理。缺少SingleOmega的同层小型化等未决任务不在这个总分派器里，没有被悄悄标为已解决。

`noUniversalSuccessfulResponder`证明不能给每个Request都产生成功Response。因此“每个本域请求都能获得一个有证据的判定”不等于“每个请求都完成了所要求的见证”。

## 3. 可完成与查询真值不同

实际归约控制同时给出：

~~~text
feasibleTag(dispatch(queryL 2)) = true
lower(fst(lowerReply 2)) = false
feasibleTag(dispatch rationalRoot) = false
~~~

在输入2处，返回正确的否定成员答案就是查询任务的成功；它不是L2为真的证明。相反，有理根请求要的是q及等式，负可行性证书不是该见证。

这把ASK/服务可行性、对象命题真值和输出正确性三个层次实际分开了，不能以一个Bool标签混计。
