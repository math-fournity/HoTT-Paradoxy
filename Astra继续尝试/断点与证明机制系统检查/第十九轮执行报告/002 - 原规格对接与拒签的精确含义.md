# 原规格对接与拒签的精确含义

C-303不只为旧任务另起名字，而是将新响应与旧类型实际对接，并保留错误解释和合法恢复的两侧。

## 1. 原类型没有被替换

`tableResponseEquivOriginal : Response oldTable ≃ Spec_A`与`rootResponseEquivOriginal : Response rationalRoot ≃ Spec_B`提供明确双向函数和逆律。包装只用向上Lift，转换可直接lower，没有新增选择、resizing或被隐去的输入。

原Spec_B只有q²=2，没有正号条件。本轮保留这个原类型，同时另定义PositiveRootResponse并证明其为空；没有偷偷把旧规格改成更强正根条件后报告原定理。

representation的Done明确固定原GOLD L/U，`representationCanonical`证明任何合格响应的值等于goldReal。不会只交付某个不相关的标准实数就把固定目标标为完成。

## 2. 来源数据与合法恢复

oldTableReply使用原`specA-inhabited-unc`生成平方表；suppliedLower则以正确旧表作为显式输入，消费它来完成目标下切割查询。`suppliedGeneratedAgreement`对任意合法给定表及q证明两种响应相同。

这不证明给定表的生产成本为零，也不把函数表示说成已执行所有q。给定数据与生成数据的请求仍分开。恢复对目标Lq查询正确，不声称保留旧平方表在所有q上的原真假值。

`oldAnswerFailsLowerDone`直接在−3处证明：把实际旧表的答案原样当成下切割查询答案，无法满足新Done。前一轮的符号补偿恢复仍成立，没有被错误控制遮蔽。

## 3. 当初“拒签”到底是什么

`originalM3Refusal`就是原无条件M3-L1；`noOldTableToRoot`进一步直接用旧Spec_A实际居住项与旧Spec_B空性，否定一个总函数Spec_A→Spec_B；`responseRefusal`把同样分离接到新响应类型。

这些都是**被内核接受的否定定理**。本轮不是把编译失败、缺库或归约卡住当作证明，也没有发现“Agda拒绝了HoTT规则本来保证的等价”。

机器链支持的是：旧平方表确有项、精确有理根类型为空，因此不能有那个类型等价。仍未提供的是：HoTT理论或实际消费者曾承诺把这两个完整任务当成同一个任务。少了后者，不能把正常规格分离说成理论自我否定。

## 4. 第四层条件仍然明确

`smallnessIfProvided : (ℓ : Level) → SingleOmega ℓ → ℝLayerAt ℓ`直接保留旧sufficiency及其实际输入。没有提供无条件SingleOmega，也没有证明Necessity，更没有从有条件充分性推“必付”。

当前GOLD标准Type1表示、查询与近似的正构造不消费这个输入；同层小型化是独立更强合同。它被单列，未放入无条件九族分派器以取得虚假完备性。
