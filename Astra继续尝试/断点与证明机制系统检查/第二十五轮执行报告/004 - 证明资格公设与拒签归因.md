# 证明资格公设与拒签归因

本轮8包各执行formal记录检查和选定HEAD版本检查，全部exit0。没有额外重跑内核；核的历史原始输出、源和选项均按当前hash对账。对话6条、两个导出manifest和022/023两篇共10行来源记录全部匹配。

## 三类证明配置

- Cubical算术包：safe/cubical及明确层级配置，检查原GOLD/M1–M4的任务合同。
- 原生实数几何：固定without-K/no-erasure派生agda-unimath，保留基础公设；不能写成safe Cubical或未经修改的上游。
- 经典Lean几何：明确Real/拓扑与经典基础、公理输出及所固定编译依赖。不能因同名圆/区间就作为原生HoTT类型路径证明。

NativeSourceContract与WeakLiftConsumer的实际导入图并集有1087模块。沿用现有code-fence reader的词法候选记录见IMPORT-UPPER-BOUND.json；公开postulate家族包括funext、replacement、truncations、univalence、circle、pushouts及Level内建声明。该数据是语法导入上界，不是最小证明项公理集，也不证明每条声明被每个结论使用。41项runtime/source pin并不意味着所有内建模块都被导入。

## “拒签”不能合并

| 现象 | 当前身份 |
|---|---|
| 原M3 Spec_A/Spec_B不等价 | 被内核接受的否定定理，不是编译器拒绝合法HoTT定理 |
| AmbientStep下N/M不可达 | 明确操作类中的数学否定；与其它Step的正结果不冲突 |
| 删除Glue/边界/消去条件后的项被拒 | 该指定项的类型边界；对应普遍否定须另证 |
| 原弱域Lift作为额外参数 | 具体能力合同的原则关系；尚无“基线绝不可能推出它”的元证明 |
| 旧primEraseEquality与without-K配置诊断 | 独立的工具/配置问题，旧证据保持；当前几何使用固定派生树，不把它归为基础HoTT矛盾 |

因此本轮整体未闭合的主要原因不再是“相关文件没有被任何机器检查”，而是所要组合的结论是否承担同一任务，以及指控的理论能力承诺是否真的存在。配置与公设边界仍须一并披露，不能用本句抹去。
