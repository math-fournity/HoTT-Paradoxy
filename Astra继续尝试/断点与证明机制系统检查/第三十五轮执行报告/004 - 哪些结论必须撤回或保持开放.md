# 哪些结论必须撤回或保持开放

本片是论证资格审计，区分原数学结果和解释层跃迁，不删除旧原文或原始run。

## 1. 不再作为当前已证结论的说法

| 旧说法 | 当前处置 |
|---|---|
| 两个判据都出自HoTT，所以“判据不同”的反解释已被吸收 | 撤回该推论资格。同源不等于同任务，仍需G01/G04 |
| M3证明两规格不等价，就是引擎拒绝HoTT实际使用的同一性 | 保留前半的精确定理；后半归因未定位，不能随前半升级 |
| 完整cut或实数对象的取得一般都必须Ω塌缩 | 不作为已证事实；标准GOLD与层级路线有正构造，原B1a只给条件充分性 |
| Markov或可数选择“显形”，因此四弹已击落 | 不成立为当前证据结论。它们在C321–324中的具体作用已核，必需性与实际错误承诺仍是另外的义务 |
| 类型良好却不归约，自动等于逻辑不一致；所有诚实引擎都必须同样拒绝 | 缺exact calculus、计算关系、元语义和全称证明，保持未证，不以局部观察认证 |
| 任一正恢复都是“换币”而仍自动命中 | 必须回到原合同；保任务恢复若成功，就要限制或撤回对应指控，不能使任何结果都确认原结论 |

## 2. “拒签”至少要拆成四类

1. **否定命题被接受**：如M3的非等价证明。这是一个通过的证明，否定的是声明中的具体命题。
2. **某份候选项被拒绝**：需核缺边界、类型不合、缺导入等具体诊断；一般不能推出不存在任何证明。
3. **不透明公设或指定配置的计算现象**：必须保留精确公设和原生/非原生差异；不是全HoTT的行为证明。
4. **关于整个演算或所有实现的元结论**：需要相称元理论，不能从以上三种局部收据直接得到。

本轮汇总脚本因旧审计JSON的容器名读取错误失败，也不属于数学拒绝；失败和修复另有原件。将其与Agda内核结果混用会重复原来同类错误。

## 3. 用户问题仍然保留

来源、断点、允许操作和现实同一性是可以继续研究的内容。现有HoTT原生点集/度量/Rich/Task实物已表达其中若干方面，不能再概括为“HoTT中完全无对应物”；同时不能把我们的Rich模型说成用户全部原意。

完整HoTT目标仍需某个实际被声明的能力、同任务保持与相称困难。当前未取得这样的整体证据，并不证明未来永远不能取得。

旧报告的过程历史保留；当前数学主张由唯一矩阵与精确源/run限定。源码声明、核接受、运行归约、现实判词和公开影响分别验收。
