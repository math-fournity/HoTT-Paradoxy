# 研究问题、原意与结论等级

## 1. 原始问答到研究要求

| 对话分片 | 用户问题/要求 | 本方案处理 |
|---|---|---|
| 001 | M关乎从圆删点而来的对象；尝试形成P与非P | 保留原文；不预认矛盾结论，审核同一命题与语义连接。 |
| 002 | 质疑“以无法完成的方式完成”、极限与紧化 | 保留过程完成轴，不要求所有检查先归结为距离或有限步。 |
| 003 | N无法真正变成M，应质疑等价判据本身 | 不以定义结束现实对应审查；检验抽象对独立任务是否充分。 |
| 004 | 拓扑思路会否把风险传入HoTT | 跟踪表示→等价→下游→解释回原任务。 |
| 005 | 不受M≠N具体表现限制；检查断点与证明本身 | 六机制族横向覆盖，来源/历史不是唯一观察。 |
| 006 | 先完整保存从提问开始的问答，再制定方案 | 已先导出21条可见消息并精确核验；不改写旧回答。 |
| 007 | 缺口及两侧关系属于完整M；固定两端仍可变形；某些形状仅可由特殊方法生成 | 增加指定缺口/环境/端部结构与构造可达性检查；后两项不可达/唯一生成主张保持候选。 |

横向覆盖由当前AI执行；项目禁止Sub Agent，不隐含新会话或外部协作者调用。

## 2. 核心问题

对固定命题或任务，局部条件δ是否不可缺少；表示/等价/消去是否让δ不再可用；后续规则或使用者是否仍交付需要δ的结果。

δ可以是指定点、端点对应、重叠一致性、路径见证、结构字段、代表元选择、宇宙条件或计算数据。这是首批入口而非完备枚举。“只少一项”描述最小变更，不说明它数学上无关，也不说明每次缺失都有矛盾。

不预设：HoTT必有矛盾；同胚就是现实操作可互换；所有证明是点集曲线；检查相等证明须逐点执行；类型拒绝就是缺陷；历史标签可替代真实来源；同名变量足以保证同任务。

## 3. 层次与证据

| 层 | 内容 | 证据 |
|---|---|---|
| 对象/解释 | 两表示是否同任务、保留观察 | 来源/模型、明确对应与保持/失配证明 |
| 理论规则 | 精确演算允许什么项/推论 | 原生推导/核检查，必要时模型与元证明 |
| 实现 | checker/elaborator/reducer行为 | 固定版本、输入、控制与原始诊断 |
| 使用者 | 弱证据是否被当成强交付 | 实际依赖/调用、类型与语义对账 |
| 现实/完成 | 原任务是否取得所需能力 | 同输入/动作/观察/完成下的证据 |

可先构造合成数学实例，不要求已有软件误用才准研究；声称某库/Book/共同体正在这样使用时，才须给实际来源。共同X不需HoTT先批准；形式化须接受共同X的保真核查。

## 4. 允许的结局

- `RULE_OR_IMPLEMENTATION_CANDIDATE`：出现不相称现象，先排配置、附加公理与错规格。
- `REPRESENTATION_MISMATCH_WITH_SCOPE`：抽象不保指定观察，未必反驳理论承诺。
- `CONSUMER_MISUSE_WITH_SCOPE`：实际下游把不充分证据当充分。
- `DEFENSE_PRESERVES_TASK`：合法恢复保同任务，当前指控被削弱或否定。
- `EXPECTED_BOUNDARY_REJECTION`：缺条件的指定项被正确拒绝。
- `OPEN_WITH_OBLIGATION`：精确未决，不自动变成功或全局不可能。

内部矛盾须同一命题、可共用假设与合法证明。语法接受、局部定理、现实失配和新颖性分别验收。

## 5. 既有工作

旧四阶段设计保留为背景，本轮从一般机制起步，不先要求AST-X-RING全部完成。原圆环是重要回归问题，不能由算术支线或抽象控制冒充完成。

三次Astra审计提供工具/证据纪律，不把旧缺陷当当前事实。M2/M3、标准dcut和条件引理只复用精确范围，不构成本轮断点机制已存在的证据。BP-*是设计定位，不是新STATE/claim ID。
