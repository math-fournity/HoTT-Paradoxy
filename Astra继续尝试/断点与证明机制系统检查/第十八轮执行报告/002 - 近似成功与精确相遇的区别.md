# 近似成功与精确相遇的区别

C-301给出了同一二分输出上的正负性质：它满足精度合同，同时仍有正的非零宽度。这两项没有用不同初态或两个无关输出拼接。

## 1. 成功与非零在依赖见证中共存

~~~text
successWithPositiveGap : (n : ℕ) →
  Σ a : ApproxTask n, width(fst a) ≠ 0
~~~

这里被证明非零的就是返回的ApproxTask输出。`widthPositive/widthNeverZero/boundsNeverMeet`对任何有效Bracket证明宽度正、宽度不为零及端点不同；`widthStrictlyDecreases`还证明每一步严格减小。

因此，当前模型同时满足“每个n都完成指定精度”与“每个有限n都没有精确相遇”。本二分的`ExactMeetingTask = Σ n, lo(approx n)=hi(approx n)`有否定证明。

这不是精确相遇任务的成功恢复。近似Done与精确相遇Done不同，不能拿前者替后者盖章，也不能拿后者失败否定前者。

## 2. 正负执行控制

`twoStepLower/twoStepUpper`通过refl检查实际二分两步后端点为5/4和3/2；全称宽度定理在该输入给宽度1/4。这个闭项检查会实际归约查询与refine，不只检查函数名字。

反控制`initialFailsPrecisionOne`证明：初始1、2虽然是有效L/U夹逼，却不满足精度1所要求的宽度1/2。由此区分“返回某个有效区间”与“返回当前精度要求的区间”。

## 3. 精度范围与未证明项

本轮量词是全部自然数n，对应二进制精度界(1/2)^n。没有在此另证对任意正实数ε选择n的共终性，也没有新增实数度量中的完整收敛/完备性定理；不能只凭“全精度”简称越过这项范围。

没有一次执行所有n，没有取得精确有理根，也没有证明任意Dedekind cut都有统一可执行近似器。当前结果专属于实际GOLD谓词及已核classifier。
