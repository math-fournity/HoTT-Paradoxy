# 同一有理模型中的二分与全参数证明

C-300沿用GOLD的Cubical.Data.Rationals.Base.ℚ及实际L/U，没有更换数的表示。库中现成ℚCommRing实例使用另一QuoQ载体；本轮在源码查明这一点后，用原类型的代数律直接证明所需恒等式，没有把另一种有理数当成原对象。

## 1. 对象与单步

Bracket包含lo、hi及G.L(lo)、G.U(hi)的实际证据，故原GOLD的disjoint给出lo<hi。初始端点为1与2，成员由原inhabL/inhabU提供。

~~~text
gap(a,b) = b−a
middle(a,b) = a + (b−a)/2
~~~

halfQ=1/2与初始端点1、2是不同参数。`halfPlusHalf`通过原ℚ商相等证明；`leftHalf/rightHalf`证明中点两侧宽度均为原宽度的一半，`middleAbove/middleBelow`证明它严格在原端点之间。

`refine`调用已核GOLD classifier：中点在L则替换lo，在U则替换hi。每个输出都仍携带L/U证据。`lowerNested/upperNested`证明一步内缩，`lowerFromInitial/upperToInitial`证明所有输出仍在初始界内。

## 2. 全自然数参数

~~~text
approx 0       = initialBracket
approx (n+1)   = refine (approx n)
dyadicWidth 0  = 1
dyadicWidth(n+1) = dyadicWidth n × (1/2)
~~~

dyadicWidth就是本合同采用的(1/2)^n递归定义。`approxWidth`对全部n证明width(approx n)=dyadicWidth n。不是从若干样例外推；证明由单步宽度恒等式和自然数归纳给出。

`ApproxTask n`要求一个实际Bracket及该宽度等式，`approximate`是对每个n返回该类型的构造。`packedBounds`把实际成员证据直接接到上一轮goldReal的L/U投影。

## 3. 有限执行证书

RefinementTrace的idle与next记录此算法的有限refine调用；`approxTrace`和`certifiedApprox`把恰n次细化、实际终态、成员及宽度关联在同一个依赖数据中。

这个计数不是CPU指令数、墙钟时间、内存上界或物理运动时间。当前有理数表示也未做大规模性能优化。本轮证明的是给定n的数学构造与证书，不承诺在固定资源内处理任意大n。

所有结论保留固定Cubical配置及当前GOLD前提；没有新增LEM、resizing或选择神谕。
