## 4. 系统总览

### 4.1 数据流

```text
profiles（工具链 + 源码 + 符号 + support 锁）
   └─ create-case ──► cases/<case-id>/case-revision-N.json（不可变；冻结 profile/task/grammar 哈希）
                          └─ search ──► runs/<search-run-id>/RUN.json（完整枚举、见证、控制、AST 哈希）

                                                                     └─ explain ──► reports/*.md
generated-index/index.json ◄── rebuild-index / 各写命令自动重建（派生数据，可丢弃重建）
```

### 4.2 两条证明入口

- `coordinator_template`（默认）：可信协调器用 pinned support 引理 + 可计算事实渲染
  `Proof.agda`；`Target.agda` 先生成、先哈希、再接受证明。
- `external_file`（`--proof-file`）：候选提供证明源码；先做禁用声明扫描（`postulate`、
  `primitive`、终止/宇宙绕过、未解 meta 等），再做同样的 Target 冻结与内核核验。

### 4.3 证据等级

- 探索/校准收据（`machine-overview/runs/**`）：`machine-overview-search-run/v1`、
  `machine-overview-verify-run/v1`；**不进入** `HoTT/CLAIM_EVIDENCE_MATRIX.md`。
- 正式数学 claim 的交付合同（本 worktree 未触碰）：源码 → `HoTT/formal/`，

## 7. 数据模型与收据 schema

### 7.1 Profile（`profiles/*.json`，`machine-overview-profile/v1`）

- `profile_id` / `theory_variant` / `toolchain_ref` / `library_registry`；
- `sources[]`：每项 `{path, role, sha256, symbols[{name, kind, lines[start,end]}]}`；
  **sha256 必填**（缺失即资格失败 `SHA256_PIN_REQUIRED`）；
- `support_sources[]`：如 `MVSupport.agda`（每次内核运行都会导入，必须锁）；
- `supported_operations[]` / `unsupported[]`：声明支持域与显式缺口；
- `coordinator_identity_note`：协调器自身不锁 hash，靠每个 run 记录 coordinator version +
  Git HEAD + 完整命令与 include 路径。

### 7.2 TaskSpec（`tasks/*.json`，`machine-overview-task/v1`）

`purpose` / `source_basis` / `input` / `environment` / `observation` / `completion` /
`quantifiers` / `allowed_resources` / `prohibited_extra_information` / `assumptions` /
`obligations` / `known_positive_controls` / `known_negative_controls` / `claim_refs` /
`correspondence{original_activity, theoryization_steps, observation_justification,
preservation_claims, open_obligations}`。

### 7.3 Grammar（`grammars/*.json`，`machine-overview-grammar/v1`）

`delay_index_max` / `race_partner_index_max` / `include_omega` / `context_depth_max` /
`deadline_horizons` / `bind_continuations[{id, map}]` / `reduction_guard
{never_drop_kinds, never_drop_continuation_ids, reason}` / `calibration_benchmark` /
`declared_bounds_note`。
**`reduction_guard` 是任务保持的关键**：它把「任务声明的消费者」钉住不被缩掉；没有它，
贪心缩减会把 completion-divergence 见证降成更小的 raw-race 见证（run `-001` 实测）。

### 7.4 CaseRevision（`cases/<id>/case-revision-N.json`，`machine-overview-case/v1`）

`case_id` / `revision` / `parent_revision` / `created_at_utc` /
`profile|task|grammar {path, sha256}` / `source_pins[]` / `candidate_ast{status,...}` /
`target_text_hash`（本实现中为 null —— 目标冻结改由 `target-freeze-N.json` 维护）/
`assumptions` / `obligations` / `claim_refs` / `state_axes` / `immutability`。
**不可变**：内容变化必须新建 revision（`create-case --revision N+1`）。

### 7.5 Search run（`runs/<id>/RUN.json`，`machine-overview-search-run/v1`）

- `inputs`：`case_sha256`、`task_sha256/path`、`grammar_sha256/path`，
  加 `verified_inputs{profile,task,grammar}`（实际读入的字节哈希）；
- `statistics`：

## 11. 已知缺口与陷阱（接手者务必先读）

1. **M2–M5 未实现**：当前只有有限文法内的确定性枚举 + 原生核验；没有符号搜索、没有
   高阶路径/HIT 语义适配、没有六线覆盖、没有留出集评测、没有主线集成。
2. **canonical capture 与 worktree 不兼容**：`scripts/audit/capture_agda_proof_run.py`
   要求 `(project_root/".git").is_dir()`；worktree 的 `.git` 是文件 → `PROJECT_GIT_ROOT_REQUIRED`。
   本目录因此使用自己的 `machine-overview-*` 收据；把它接入 F-011 正式链路属于 M5。
3. **两个 canonical verifier 需要被 gitignore 的嵌套资产**：
   `verify_understanding_merge.py` 需要 `AI对话录/理解章节`；
   `verify_fresh_three_way.py` 需要
   `sources/local-gpt/ALL-Markdown-root/HoTT_is_GONE_COMPLETE.md`。
   二者在 fresh worktree 都会 FAIL；另外四个（governance shards / three-way cognition /
   ledger retrodiction / proof version closure）在 worktree 中 PASS。不要把这两个 FAIL 归因于
   本实现。
4. **不要编辑已提交的收据**：`RUN.json`、`ATTEMPT.json`、`case-revision-*.json`、
   `target-freeze-*.json`、`reviews/*.json` 都是记录；要改就建新 run/revision/review。
   pre-fix 收据的补充信息只放 `LEGACY.json` / `.superseded/README.md`。
5. **`reduction_guard` 不要删**：没有它，缩减会换题（见 run `-001` 与 AUDIT-RESPONSE F5）。
6. **`target_text_hash` 在 case revision 里是 null**：目标冻结在
   `target-freeze-N.json`；不要因为看到 null 就认为冻结缺失。
7. **重放分级不是“失败”**：冷缓存多出的 `Checking …` 行会产生
   `EXIT_STDERR_MATCH_WITH_CACHE_LOG_DIFFERENCE`；只有真实 stdout/退出码差异才算失败。
8. **同一环境下并行 verify**：Agda 的 XDG 缓存是共享的；两个 verify 并行可能相互影响
   （缓存写入）。当前实现按单写者设计；要并行就先给每个 run 独立缓存目录（需要改
   `runtime_cache` 或 profile；这是未做的改进点）。
9. **索引是派生数据**：`list/get/query` 只读；要刷新用 `rebuild-index`。不要手工编辑
   `generated-index/index.json`。
10. **run 时间与磁盘**：每次 verify 会在 `runs/<id>/generated` 生成 5 个 Agda 文件与
    `.agdai` 缓存（后者被 gitignore）；不要在仓库里提交 `.agdai`。
11. **dev-notes 不提交**：`dev-notes/0003 …md` 是对话归档（按 Skill 规则不 stage/commit）。
12. **不要 push/tag/合并**：本分支的存在是为了隔离；是否并入 main 由用户决定。
13. **本目录的“校准通过”不是研究结论**：`NATIVE_CHECKED_CALIBRATION_INSTANCE` 只说明
