# 发现引擎：语义重定向作为八轴搜索策略

> 修订对象：GPT 方案 v2.1 第 007 片 §2（八轴搜索张量）与 §3（六类生成器）**增补一组供给策略**；
> 关联第 002 片工作包表（GEN-001 的上游）。
> 依据：Atria 审计报告集 08（对机器统观作为发现路径的独立判断）。
> 修订性质：**把"发现侧"从"六生成器的实现进度"问题，改为"新任务族从哪里来"的问题**。
> 与修订片 003 的分工：003 验收"引擎能跑通一条新的有界链"；本片规定"新任务族从哪里来、
> 由谁供给、如何标注"。两片不重叠。

## 1. 修订的动机（assessment，详见报告集 08）

GPT 007 片 §3 要求六类生成器各一条 input→candidate→oracle→receipt 真实链，但
按本审计核查（报告集 05 / A3）：当前只有声明文法枚举与三个研究扩展，**M2 自述
"no general dependent/higher-path search"**。引擎是**声明文法校准器**：
分母人工声明，引擎不越界。

因此"六生成器的实现进度"这个提法，把发现侧的问题错记成了**实现工作量**问题。
真正的问题是：**新任务族（新分母）从哪里来、由谁供给、如何标注**。本片把这个问题
在方案内显式化，并给出六条用户原文锚定的供给策略（S1–S5 来自审计识别，S6 由用户
2026-09-16 认识论修正直接指定，见 §2 末）。

## 2. 六条语义重定向作为供给策略（增补到 007 片 §2 之后）

每一条不是待验证的命题，而是**在八轴张量上移动的策略**：它指定去 Theory Schema 的
哪一组规则看，从而供给一个新的冻结任务族。

| 策略 | 用户原文锚点 | 它移动八轴的哪一维 | 供给的新任务族形状 |
|---|---|---|---|
| **S1 ASK 移位** | KC-000012 / KC-000013 | `ObservationLayer`：从"命题真假"移到"提问是否合法/可停机" | 一个任务，其完成依赖某项尚未取得的资格；观察层固定为资格检查而非结果 |
| **S2 方向 B（绕过 ASK 假装已完成）** | KC-000014 / KC-000022 / KC-000024 | `CompletionProperty`：理论侧宣称完成，现实侧不可停机 | 一个现实不可停机的过程，其理论对应物被当成已完成对象；归约须检验完成属性是否被替换 |
| **S3 理论经济（被省略者）** | KC-000029 / KC-000030 | `AbstractionChange`：抽象替思考者节省了什么 | 一个任务，其平凡情形可省某条件而结果不变；构造必须逼出该条件不可省的情形 |
| **S4 自反（验证者进入被验证域）** | KC-000025 / KC-000026 / KC-000028 / KC-000036 | `ConsumerOrContext` + `Oracle`：担保责任回到同一过程 | 一个验证任务，其所需依据只能由该验证过程本身提供；须显式检查分层/良基/有限证据结构 |
| **S5 表达保真（极简理论不被覆盖）** | KC-000031 / KC-000035 | `TheoryConstruct` × `FrameworkOrModel` | 一个极简目标理论，"理应被覆盖"但保真编码失败；归约检验 preservation 而非仅可编码 |
| **S6 现实对齐（前提解释回现实，在断裂处停下）** | KC-000044 / KC-000045 / KC-000046 | `RealityOrTask`：从"前提是真是假"移到"该前提是对什么现实过程的骨架式模仿、用现实解释它时在何处断裂" | 一条前提被解释回某个现实过程（或假想现实）；解释在某处卡住、绕过、或需要额外假设来圆；该断裂点登记为 `divergence_point`，冻结成任务族后检验"被省略的条件是否在该任务下确实不可省" |

**量词纪律（沿用 007 片 §9 的双向限定）**：单个编码失败不证明无法表达；能写一个类型也
不证明保留任务。每条策略供给的是**候选**，不是结论。

**S6 的地位与前五条不同（必须说明）**：S1–S5 是审计者在 generation-4 的 36 段用户原文中
识别出的重定向。**S6 不是识别出的，是用户在 2026-09-16 直接指定、并纠正了审计者一处
错误前提之后确立的**（核心认知 generation-7，KC-000044–046；详见修订片 008 §1 与
报告集 09 §5）。审计者原先主张"HoTT 的现实那一侧没有可把握标准"，被用户否证：理论永远
是对现实的骨架式模仿，假想中的现实也是现实，**现实标准是在用现实解释理论并不断对齐的
过程中被构造的，不预存**。

因此 S6 与 S1–S5 的关系不是并列多一条角度，而是**前置动作**：ASK 移位、方向 B、理论
经济等策略在被应用到 HoTT 前提上之前，必须先把该前提解释回某个现实过程
（`reality_skeleton`），否则这些策略无从知道该往哪儿移动。PREMISE-001（修订片 008）
是 S6 的首个具体执行，其 P2 的 `reality_skeleton` / `divergence_point` 必填字段即本
策略的产出格式。

## 3. 供给规程（新增 §3.1 到 007 片 §3）

每个新任务族的供给必须登记五项，缺一不可：

```text
SUPPLY_REGISTRATION
  / strategy: S1–S6 之一（必填，不得留空为"自由联想"）
  / kc_anchor: 驱动它的用户原文 KC 编号
  / human_supply: 人工（用户或受权 Agent）冻结的任务定义、构造子清单、分母大小
  / program_role: 引擎在冻结文法上的枚举/归约责任（不得声称超出分母）
  / kernel_role: 原生核的校验责任（不得由 Python 枚举或普通 Lean Eq 替代，F-011）
```

**核心纪律（响应 KC-000007 与 KC-000017 的张力）**：

- LLM 的模式匹配**只准在"供给新任务族"这一层使用**，且必须由 S1–S6 之一驱动并登记；
- LLM 的模式匹配**不准在"判断候选是否成立"这一层使用**——该层只走原生核；
- 每个供给必须显式标注人工/程序/核三角色分工，**不准把人工供给冒充为引擎的生成能力**。

这一条把 003 片 §5 的角色分工从"单元内纪律"提升为"供给规程"：没有 S1–S6 锚定的新族，
不进入 GEN-001 的输入。

## 4. 与六生成器表的关系（对 007 片 §3 的澄清，非替换）

007 片 §3 的六类生成器是**横向骨架**（M5 里程碑）。本片不替换它，只澄清：

- 第 1 类（typed term/proof synthesis）的真实链由 **GEN-001 + S5** 共同验收：
  GEN-001 验收链的贯通，S5 供给新族；
- 第 3 类（consumer/context synthesis）由 **S1 / S2** 驱动供给；
- 第 5/6 类（组合/自指）由 **S4** 驱动供给；
- S3 作用于所有类的**归约阶段**（它决定哪些情形不可省）。
- **S6（现实对齐）作用于所有生成器类的目标选择阶段**：它不替换任何一类，而是决定
  "去解释哪一条前提、该前提的断裂点冻结成什么族"。S6 供给的族是 PREMISE-001
  （修订片 008）的首个具体分母来源。

本片完成后，六生成器中至少第 1 类同时具备"链贯通"（GEN-001）与"族供给来源"（S5）。
其余类的状态不变，本片不声称覆盖六类。

## 6. 停止条件与失败判词

```text
SUPPLY_STRATEGY_EXHAUSTED_WITH_SCOPE
  / 已用 S1–S6 各供给至少一个冻结任务族
  / 每个族经 GEN-001 流程跑出 scoped negative 或候选
  / 不声称覆盖开放候选空间；不声称引擎已能自主发现
```

**scoped negative 不得冒充发现能力**（沿用 003 片 §6）：若某族全部候选得 scoped negative，
判词是 `GENERATOR_LINK_DEMONSTRATED_WITH_NEGATIVE_RESULT`——链已贯通、结果为负，
与"该族无候选"和"发现能力缺失"都是两回事。

## 7. 反解释与自我限定

- **声明文法路线必须保留**：本片不要求无约束生成；S1–S6 供给的是**新冻结分母**，
  安全性质（可枚举、remainder=0）不变。
- **"发现可能只能靠人"**：若 S1–S6 供给的族经引擎全部 scoped negative，本规程的上限
  被测出，这是一个合法结果（回答了"AI 供给是否有效"），不是失败。
- **S6 的自我限定**：某条前提的 `reality_skeleton` 写不出，**不等于该前提非现实**，
  只说明当前解释未找到落点；`divergence_point` 登记的是候选断裂，不是结论。S6 的产出
  仍须走 P3/P4 与 GEN-001 链。
- **S1–S6 不是穷尽的**：S1–S5 来自 generation-4 的 36 段用户原文，S6 来自 generation-7
