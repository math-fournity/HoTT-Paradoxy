# PREMISE-001 HoTT 前提集穷尽清单与 P1–P4 分工

> 修订对象：本方案自己的 006 片 §3（`SUPPLY_REGISTRATION` 供给规程）与
> 003 片（GEN-001 有界生成器验收单元）的分母选择。
> 依据：`Atria的审计报告集/09 - 反思路径的结构性边界与前提清单的可枚举性.md`；
> 用户 2026-09-16 的接受决定（"接受把'HoTT 前提集的穷尽 P1/P2 清单 + 你的 P3/P4 判定'
> 作为下一手"）。
> 修订性质：**把 SUPPLY-001 规程落成它的第一个具体分母 —— HoTT 自己的前提集。**
> 与 003/006/007 片的分工：003 验收链的贯通；006 规定新族从哪来；007 规定供给的自检；
> 本片规定**第一个被穷尽枚举的分母是什么、三角色在清单内部的步骤级分工**。
> 四片不重叠。本片是 006/007 的执行，不是替代。

## 1. 修订动机（assessment，详见报告集 09）

用户的核心观察是正确的：**理论的基础问题在基础之处，基础确实在训练数据中**。
但"反思知识谱"这条路没有分母（报告集 09 §4.2），因此不可证伪；而用户自己
发明圆环悖论的过程显示，发现的方向是**现实→理论**（报告集 09 §2），判据在
现实那一侧。

唯一同时满足"用户直觉"与"可证伪"的形态是：**把 HoTT 的前提集当作有穷分母做穷尽
枚举，AI 完成 P1/P2（结构检索与省略分析——这正是语料充分、AI 低惯性的层），
P3/P4（在什么任务下被省略的条件重新不可省 / 替代物换了什么）交用户判定**。

这也是项目从未做过的一件事：机器统观引擎枚举了 15 个任务文法（`l1-v2.json` 等），
**从未把 HoTT 自己的公理集当成被枚举的分母**（报告集 09 §3）。

用户的认识论前提（observed，2026-09-16 修正）：**理论永远是对现实的骨架式模仿**，
即便数学对象在现实中不存在，也是对假想中现实的骨架式模仿；数学可以映射到现实，
HoTT 必然可以映射到现实。因此被省略者**不是靠审视前提本身被看见的**，而是靠
"用现实解释该前提、在解释断裂处"被看见的——断裂点就是理论为了经济性舍弃了
不该舍弃的地方。这决定了本任务 P2 的必填产出（§4 的 `reality_skeleton` /
`divergence_point`），也决定了 AI 的角色边界：AI 可以产出对齐的**候选解释**，
但"哪里是真正的断裂、哪里是被不当省略者"必须由用户判定（P3/P4，§3）。

## 2. 任务定义

**PREMISE-001**：对 HoTT 的前提集做一次穷尽的 P1/P2 登记，产出一份每条挂三栏的
清单，交用户做 P3/P4 判定；对用户判定为"非现实"的前提，冻结成新任务族并进入
GEN-001 验收链。

分母（第一版范围，`PREMISE_DENOMINATOR_V1`）：

```text
HoTT 前提集（候选条目类别）
  A. 类型构造子的规则四元组（formation / introduction / elimination / computation）
     Π、Σ、Nat、identity/Path、universe U/El、HIT 构造子
  B. 判定与相等：definitional equality / conversion、β、η、J 的计算规则
  C. 恒等与等价：identity type 的命题性、function extensionality、univalence
     （公理形式与 cubical Glue/composition 定理形式分别登记）
  D. cubical 机器：interval I、连接（connections）、cofibration、
     composition/coe/transport、Kan 填充、cofibration 紧性
  E. 截断与层级：isProp/isSet 截断层级、命题截断、商（HIT 形式）、
     层级的稠密性（可任意截断）
  F. 宇宙与分层：U 的封闭性、Cumulativity / 2LTT 式内外层分工
  G. 设计决策类前提（用户意义上的"抽象"）：把恒等设为类型族、把相等设为命题、
     把高阶相等设为可无限迭代、把等价提升为同一、把"所有 cofibration 可填充"
     设为构造可用
```

**域外**（不在本任务分母内，需另立任务）：具体的证明助手实现现象（Agda/Coq/Lean
的 elaborator、universe checking 行为）、第三方库 API、性能与工程问题。
这些是 R0–R3 或 `IMPLEMENTATION_PHENOMENON`，不是理论前提。

## 3. 每条前提的三栏与角色分工（沿用 007 片 P1–P4）

| 栏 | 内容 | 归属 | 理由 |
|---|---|---|---|
| **P1** | 前提逐字是什么、出处（规则/公理/设计动机）在哪里 | **角色 A（AI）** | 结构检索；语料充分，AI 流利且此层低惯性 |
| **P2** | 它替思考者**节省**了什么（省略所在） | **角色 A（AI）** | 结构分析；省略在"收益"里，不在陈述里 |
| **P3** | 在什么**任务**下，被节省的条件重新变成不可省略 | **角色 B（用户）** | "超越"发生的层，不能经过 AI 的流利 |
| **P4** | 若该条件不可省，理论用什么替代物顶上；替代物是否把完成/时序/可用性换成了别的东西 | **角色 B（用户）** | 现实判断，须显式供给 |
| **C** | 冻结任务族 → 枚举 → 保归约 → 原生核收据 | **角色 C（引擎）** | 机械层：只核验，不塑造问题显著性 |

角色分工的硬约束（沿用 007 片，本片不放宽）：**P3/P4 不得由 AI 自证**；
`reality_anchor_holder` 必须是用户或用户明确授权的来源。

## 4. P2 的分析口径（本片新增）

每条前提的 P2 必须先产出**现实骨架映射**，再回答**它省略了现实中什么条件**，
并按用户的问题意识归类到一个或多个"省略形状"：

```text
REALITY_MAPPING（P2 必填，AI 产出，用户复核）
  / reality_skeleton: 该前提是对什么现实过程（或假想现实）的骨架式模仿？
                      用人话可解释的程度——就像给数学专业之外的人解释同伦型；
                      必须给出一个可指认的现实对应，不得以"无对应"留空
  / divergence_point: 用上述现实解释该前提时，解释在**何处断裂**？
                      （例：现实过程在此处需要某个条件，而理论把它省掉了；
                       或理论在此处把"部分/存在/有限近似"当作"已完成"）
  / evidence_level: 上述两项是结构分析（assessment）还是已观察的事实（observed）
```

**`reality_skeleton` 不准留空**（用户认识论前提：HoTT 必然可映射到现实）。若 AI
确实无法为某条前提找到现实骨架，登记 `REALITY_SKELETON_NOT_FOUND` 并说明尝试过的
现实域——这是一个待用户复核的缺口，**不是"该前提无现实对应"的结论**。

`divergence_point` 是 P3/P4 唯一可判定的对象：用户看着断裂点判定"这里被省略的条件
是否在该任务下确实不可省"。没有 `divergence_point` 的条目不进入 P3/P4。

省略形状（沿用）：

```text
OMISSION_SHAPE
  / continuity   —— 假设了无限可分/稠密（芝诺族：圆环悖论的形状）
  / completion   —— 把部分/存在/有限近似提升为已完成/已交付/已全知（方向 B 的形状）
  / observability —— 假设观察层可与结果层分离或可任意延后
  / sequencing   —— 假设时序可坍缩、依赖可重排、当前可用性不构成前提
  / self-evidence —— 把验证者放进被验证域而不另设分层（自反族）
```

每条前提的 P2 必须显式选至少一个 `OMISSION_SHAPE` 并说明依据；选不出时登记
`NO_OMISSION_IDENTIFIED`，不得留空，也不得默认归入 continuity。
**`OMISSION_SHAPE` 不是结论**，它只是把 P2 的产出结构化，使 P3/P4 有可判定的对象。

## 5. SUPPLY_REGISTRATION 的应用（三道闸，沿用 006/007）

清单中每条进入 GEN-001 输入的前提，必须完整登记：

```text
SUPPLY_REGISTRATION（PREMISE-001 适用版）
  / strategy: S1–S5 之一（必填）
  / kc_anchor: 驱动它的用户原文 KC 编号（必填）
  / premise_id: PREMISE-<类别字母>-<序号>，如 PREMISE-C-03
  / omission_shape: §4 的至少一项
  / human_supply: 用户冻结的任务定义、构造子清单、分母大小（P3/P4 之后填写）
  / program_role: 引擎在冻结文法上的枚举/归约责任
  / kernel_role: 原生核的校验责任（F-011；不得由 Python 枚举或普通 Lean Eq 替代）
  / reality_skeleton: §4 的现实骨架映射（AI 产出，用户复核）
  / divergence_point: §4 的现实解释断裂点（AI 产出，用户复核；P3/P4 的判定对象）
  / premise_step: P1–P4 中由本条实际完成的步骤
  / corpus_pressure: 二选一并说明依据（省略结构撑得起 / 语料频率为主）；
                     若主要是语料频率，该条只能由角色 B 供给
  / reality_anchor_holder: 本条的 P3/P4 由谁提供（必须是用户或用户明确授权来源）
```

**硬约束**：`corpus_pressure` 为"语料频率为主"且由角色 A 供给的条目，登记无效。
候选 KC 锚点：KC-000003（稠密 vs 量子化）、KC-000010（不可停机性为特征）、
KC-000013/029（抽象必然否定现实前提）、KC-000031/035（极简理论覆盖/表达保真）、
KC-000014/022/024（方向 B 与两类时序）、KC-000025/026/028/036（自反）。

## 6. 验收判词与停止条件

```text
PREMISE_INVENTORY_COMPLETE_WITH_SCOPE
  / 分母 PREMISE_DENOMINATOR_V1 全部条目完成 P1/P2 登记
  / 每条带 omission_shape（或显式 NO_OMISSION_IDENTIFIED）
  / remainder=0：分母内无未登记条目
  / P3/P4 已交用户，用户已对每条给出判定或显式"暂不判定"
  / 不声称覆盖 HoTT 全部可能的未命名前提；未命名前提走 004 片的 unknown ingress

PREMISE_AUDITED_NO_NONREAL_PREMISE_WITH_SCOPE
  / 用户对全部分母条目判定为无非现实前提
  / 这是一个有分母的负结论，不是"反思不够"
  / 不声称分母外无非现实前提；unknown ingress 保持开放
```

**scoped negative 不得冒充发现能力**（沿用 003/006 片纪律）：若某条前提经 GEN-001
链跑出 scoped negative，判词是 `GENERATOR_LINK_DEMONSTRATED_WITH_NEGATIVE_RESULT`
——链已贯通、结果为负，与"该前提无候选"和"发现能力缺失"都是两回事。

## 8. 执行顺序（M1 内，与 PSJ 只读部分并行）

```text
1. 冻结 PREMISE_DENOMINATOR_V1（类别 A–G，条目编号），登记 hash
2. 逐条 P1/P2（角色 A），输出结构化清单 + omission_shape
3. 交用户逐条 P3/P4（角色 B）；用户可"暂不判定"，但不得由 AI 代填

5. 任务族进 GEN-001 链：枚举 → 保归约 → 原生核 → run 收据 → CE-MAP 索引

```

## 9. 反解释与自我限定

- **声明文法路线必须保留**：本片不要求无约束生成；供给的仍是新冻结分母，
  可枚举、remainder=0 的安全性质不变（006 片 §7 纪律沿用）。
- **分母不是穷尽的 HoTT**：`PREMISE_DENOMINATOR_V1` 只覆盖到 2026-09-16 的
  公开 HoTT/cubical 规则集；新构造（新 HIT、模态、2LTT 变体）进入时分母须显式扩版
  （`PREMISE_DENOMINATOR_V2`），旧版保留，不做静默重写。
- **本片不产生数学结论**：F-011 不适用；P1/P2 产出的是结构与省略分析，
  不是命题证明，也不是"该前提非现实"的结论。任何"非现实"判定必须来自 P3/P4 的
  用户裁决，再由引擎与原生核验证。
- **本片不声称发现只能靠人**：它只声称 P3/P4 的判定不能由 AI 在最流利处自证
  （007 片 §7 纪律沿用）。
- **现实域不限于计算**：用户 2026-09-16 的修正确立"理论是对现实的骨架式模仿、
  HoTT 必然可映射到现实"。计算是对齐结果**可机械验证**的现实域（也是机器统观
  的原始出发点），但运动/连续/转动等母域同样是现实域。`reality_skeleton` 应优先
  给出最贴近该前提本性的现实域，不得默认只填计算域。
- **`reality_skeleton` 与 `divergence_point` 是 AI 的候选解释，不是结论**：
  真正的断裂点与被省略者由用户在 P3/P4 判定。AI 的现实解释可能错位——
  它把现实对齐到理论时，可能对齐到了语料中最熟悉的那个现实例子（KC-000043），
  而不是最贴近该前提本性的那个。这正是三道闸中 `corpus_pressure` 声明
  对 `reality_skeleton` 同样适用的原因。
