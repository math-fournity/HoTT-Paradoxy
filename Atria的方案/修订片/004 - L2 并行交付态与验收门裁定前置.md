# L2 并行交付态与验收门裁定前置

> 修订对象：GPT 方案 v2.1 第 010 片 §9（根 Goal 正向完成门）与 §11（只有用户能够改变的事项）；
> 关联第 008 片 §11（中间报告）。
> 依据：Atria 审计报告集 01 §6（A6）、06（目标契约、用户原文与验收门裁定）。
> 修订性质：**新增一个与 A1 正交的并行交付态，不降低 A1 标准，不替用户裁定**。

## 1. 争论的重新定性（A6 的结论）

- GLM B1：验收门把哲学命题塞进数学定理门（范畴错配）；
- GPT 反驳：正向门可达，缺的是负向终止门（GLM 让步）；
- DeepSeek：L1 定理见证 / L2 哲学交付需用户裁定（推荐"裁定丙"：先跑 PSJ 第一批再定门）。

**本审计补上的判别性证据**：争论双方都有用户原文支撑。

| 支持严格门（贯通导向） | 支持组装交付（构造导向） |
|---|---|
| `rulings.md` §23（2026-09-14，时序最晚、针对新 Goal 的显式裁定）："至少一个候选贯通…**自然 consumer**、**现实同任务对应**和方向 A/B" | **KC-000005**："找到悖论才是关键，至于悖论作为矛盾，它到底是否定了哪个前提，那是未来的下一个故事" |
| Z_LAW §0："提升为已完成对象时产生可证明的非法构造" | **KC-000010**："用 Think in HoTT 的方式，**构造**出来了一个悖论…以'不可计算性/不可停机性'为特征" |
| | **KC-000011**："看它什么时候，不想让时间、时序参与到 Think in HoTT 这件事中" |

**重新定性**：这不是"AI 自设门槛对不对"，而是**用户两处原文之间的真实张力**。两种读法都有
用户原文支撑，因此**只有用户能裁决**。GPT 方案维持 §23 门是**正确的默认**（时序更晚、更具体、
针对当前 Goal），但它把 A1 设为**唯一**可交付成功，使 KC 的构造语气在方案内**没有任何完成出口**
——008 片 §11 的"中间报告"不是完成态。

## 2. 新增交付态：DELIVERED_ASSEMBLED_WITH_SCOPE

对 010 片 §9 的修订：§9 的十门保持不变，作为 A1（`REALITY_RELATIVE_WITNESS_WITH_SCOPE`）
的**唯一**判定路径。新增一个**正交的并行交付态**，不与十门竞争、不替代十门、不豁免十门：

```text
DELIVERED_ASSEMBLED_WITH_SCOPE
  定义：把已机器证明的非因子化边界族，以显式"提升为完成对象"的语义桥组装成一份
       可交付论证，其数学部分已机器证明，解释桥显式标为合成。
```

### 2.1 七项必要条件（全部必须成立）

```text
1. 组装零件全部为已机器证明的边界族（证据等级 MACHINE_PROVED_LOCAL_UNCOMMITTED
   或更高；见 §3 清单），不含未证明的数学命题；
2. 显式语义桥：每条"提升为完成对象"的推断写为文本，并显式标注
   SYNTHETIC / INTERPRETATION_BRIDGE，不得冒充 natural consumer、不得冒充
   source-grounded task（响应 010 片 §11"是否降低 natural/source-grounded consumer
   资格：仅用户"——本态不降低该资格，只是另一类交付物）；
3. 反解释清单与正控制：每个零件附 strongest counter-explanation 与正控制
   （008 片的反解释八项；现有零件已具备）；
4. 所有者评审通过：唯一裁判是用户（所有者），不是 kernel、不是 Agent；
5. 范围限定：交付物明确标注"覆盖范围 = 已枚举的边界族 + 已写下的解释桥"，
   禁止外推到未覆盖的族或未写下的桥；
6. F-011 不豁免：其数学部分已经机器证明（身份是"已证边界 + 解释桥"，不是新定理）；
   若组装过程中出现任何新的数学命题，该命题必须独立走 F-011 全部门禁；
7. 与 A1 的关系显式登记：L2 完成 ≠ Goal complete；Goal complete 仍需 A1 十门全部闭合。
```

### 2.2 与 010 片 §9 十门的关系（不是第十一种门）

```text
A1（十门）        : 现实相对候选/见证，Goal 完成的唯一判定路径。
L2（本修订新增）  : 已证边界族的组装交付，一个并行可达的独立交付态。
                   它交付的是"论证"，不是"witness"。
```

判词上必须区分：`DELIVERED_ASSEMBLED_WITH_SCOPE` 不得写成
`REALITY_RELATIVE_WITNESS_WITH_SCOPE` 的前缀、子态或部分完成。两者是不同的交付物类型。

### 2.3 为什么需要这个出口（R1 风险的方案内消解）

DeepSeek 预判的 R1 模式：源化搜索无命中 + 用户未裁定 → 高质量有界负结论无限累积、
从不交付。在只有 A1 一个完成态的方案结构下，R1 无法在方案内消解——每轮正确的 scoped
negative 都"还不够"。

有了 L2 并行态：

- 已有机器结果族（§3）可以**立即**进入组装，不等待 A1；
- 定理线不受影响：A1 的十门标准一字不动，搜索继续；
- 用户获得一个**已可交付**的中间成果，同时保留"完整 Goal 仍需 A1"的诚实表述。

**注意方向性**：本修订不是"降低标准让项目能宣布完成"，而是"让已被机器钉死的最强论证
从被封存变为可交付，同时明确它不是 Goal 完成"。如果用户选择不要这个出口（裁定甲），
本修订要求方案**显式登记"接受 R1 风险"**，而不是留空（见 §6）。

## 3. 可用于组装的现有零件（事实，非评估）

| Z 铁律要素 | 已有机器结果 | 判词 | 证据等级 |
|---|---|---|---|
| 同一抽象等价、现实效应不同 | C-96–C-99（funext 使行为等价函数相等；细化表示可恢复，正控制） | `REPRESENTATION_BOUNDARY` | MACHINE_PROVED_LOCAL_UNCOMMITTED |
| 无时间完成态的压缩伤痕 | C-71–C-76（race/deadline 非同余、商上无选择子） | `REPRESENTATION_BOUNDARY` | 同上 |
| 阶段/时序擦除 | C-92–C-95（保律擦除 ⇔ 不动点） | 边界族 | 同上 |
| 在线资格边界 | C-106–C-109 | 边界族 | 同上 |
| 提升未落定 spec 为完成对象 | C-134–C-141、C-142–C-148（不可恢复族、无统一选点） | 边界族 | 同上 |

这些零件目前**全部**被 A1 门判为"不够"。L2 态不改变它们的数学身份，只改变它们的**交付身份**。
本修订不主张它们已经构成 Goal 完成。

**前置依赖**：这些零件的 run 收据正受 A2 的 14 项证据契约失配影响（修订片 002）。因此
L2 组装的**证据基座闭合**依赖 EC-001 完成——不能在 25/25 未达成前宣称组装交付的
证据等级为 MACHINE_PROVED。

## 4. 执行顺序与裁定输入的关系（对 DeepSeek"裁定丙"的修正）

DeepSeek 推荐"裁定丙"：先跑 PSJ 第一批，以实际命中再定门。本审计认为裁定丙**仍是稳健的**
（不预判结果），但应先做 EC-001 与 GEN-001：

```text
M0    EC-001（证据契约修复 + 目标契约/方案/审计入版本控制）
M0.5  协调器最小可用闭包接入 main（A3 的执行载体）
M1    GEN-001（有界生成器验收单元）        ┐
      PSJ-001A 只读部分（九字段、comparison pool、来源分母）┘ 并行
        └─ 两者的产出共同构成"验收门裁定"的输入
M1.5  用户裁定（A6：甲/乙/丙；A7：截止日三选一）
M2    按 GPT v2.1 原执行链推进
```

理由：若目标契约版本不可固定（A1/A4）且证据契约 14 项失配（A2），PSJ 第一批的判词将写在
**不可恢复的基座**上——判词无处可存，裁定输入本身不可信。EC-001/GEN-001 不改变任何数学判词，
只固定执行基座，因此它们是**任何裁定的前置**，不构成对裁定内容的预判。

## 5. 对 010 片 §11 的修订（用户专属条款的补充）

010 片 §11 已列七项"只有用户能够改变的事项"。本修订在其后补充：

> **新增第 8 项**：是否设立 L2 并行交付态（`DELIVERED_ASSEMBLED_WITH_SCOPE`）。
> 该事项与第 3 项（是否降低 natural/source-grounded consumer 资格）**互相独立**：
> 设立 L2 态不降低该资格（L2 显式标注 SYNTHETIC，不冒充 natural consumer）；
> 但 L2 态是否算"项目层面的可交付成果"，只有用户能裁定。

同时明确：Agent 可以**起草** L2 组装草案（零件清单、语义桥草稿、反解释清单），但
`DELIVERED_ASSEMBLED_WITH_SCOPE` 判词的最终给出权在所有者评审（§2.1 第 4 项）。
Agent 不得自行宣布 L2 交付完成。

## 6. 三种裁定的方案内后果（不替用户选）

```text
裁定甲（维持现状：A1 为唯一完成态；L2 组装只作中间报告）
  方案后果：本修订片 004 的 §2 条款不激活；008 片 §11 的中间报告路径沿用。
  必须新增：在方案中显式登记"接受 R1 风险（高质量有界负结论可能无限累积）"，
  不得留空。Agent 每轮报告需提示该风险处于活跃状态。
  代价：已有机器结果族继续保持"被封存"状态。

裁定乙（并行交付态：本审计建议）
  方案后果：本修订片 004 的 §2 条款激活；L2 组装可在 EC-001 完成后启动。
  定理线：A1 十门标准不变，搜索继续。
  必须新增：所有者评审作为 L2 的唯一裁判；L2 完成 ≠ Goal complete 的显式登记。
  代价：多一个需要用户评审的交付物类型（治理成本小幅上升）。

裁定丙（DeepSeek 推荐：先跑 PSJ 第一批再定门）
  方案后果：延后裁定；M1.5 推迟到 PSJ-001A 判决之后。
  必须新增：PSJ-001A 的只读部分须先经 EC-001 固定基座（§4）。
  代价：R1 风险在裁定前处于活跃状态，需按裁定甲同样登记。
```

三种裁定都**不**改变 EC-001/GEN-001 的必要性（它们与裁定无关，见 §4）。

## 7. 反解释与自我限定

- **本修订不主张零件已构成 Goal 完成**：§3 的清单是事实，"它们足以交付一个论证"是
  candidate 级判断，需要所有者评审确认（§2.1 第 4 项）。
- **不主张 KC 原文要求降低标准**：KC-000005/010/011 的构造语气**与** §23 的贯通要求
  都是用户原文；本修订不判定哪一方"才是用户真意"，只提供让两者都有出口的结构。
- **时序论证的局限**：§23（2026-09-14）时序晚于 KC（09-09/09-10），这支持"§23 是当前默认"，
  但**不**证明 KC 已被废止——后出的裁定可能只是针对新 Goal 的补充而非对验收语言的撤回。
  该不确定性保持 `UNKNOWN`，由用户在裁定时澄清。
- **L2 的数学风险**：解释桥（SYNTHETIC）若被下游误当作已证命题传播，会污染结论。
  对策是 §2.1 第 2 项的显式标注 + 第 5 项的范围限定，以及在 CE-MAP 中为 L2 交付物
  单列证据等级 `ASSEMBLED_WITH_SYNTHETIC_BRIDGE_NOT_A_THEOREM`。

## 8. 与 DeepSeek 增补 G 的关系

DeepSeek 增补 G《验收门裁定前置增补》把"裁定"的时点提前并给出裁定输入清单；本片把
**裁定乙的具体形态**（七项必要条件 + 正交交付态 + 所有者评审）写入方案，使裁定乙从
"一个建议"变为"一个有验收判据的可达状态"。执行顺序（§4）与 DeepSeek G 的前置清单
同向；本片额外要求 EC-001 先行。不冲突。
