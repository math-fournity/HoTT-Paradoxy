## 2. EXP-001 提前（A8）

### 2.1 用户原文锚点（observed）

```text
KC-000031（用户原文）："构造一个最小化的理想理论，这个理论由于其极其简单，理应被 HoTT
  所覆盖，但是因为 HoTT 对理论范型的严格性，导致它不能被覆盖。"

KC-000035（用户原文）："HoTT 是否可以完整地表达我刚刚论述的这套悖论研究理论呢？"

rulings.md §14：把"极简理论覆盖、项目悖论理论表达"列为新直接研究方向。
```

GPT 007 片 §8 自认"这两项不能被 PSJ、TGSQ 或 R4 自动替代"；但 002 片工作包表标为
`PLANNED_AFTER_EXACT_TARGET`，009 片 M0–M6 中 EXP 无任何早于 R4X 的位置。

**这是方案内部矛盾**：自认不可替代，却无限期顺延（风险 R5）。且它是**用户显式要求**，
不是方案自生的可选单元。

### 2.2 提早的合法性：EXP 最小单元不依赖 R4 target

GPT 007 片 §9 的 EXP 任务需要"在 R4X 选定 exact target 后构造 interpretation"。但该依赖只对
**完整版** EXP 成立。**最小版**只需要：

```text
最小 source theory（对象与操作）
formation and construction history
observation/completion relation
abstraction map
ASK qualification relation
required preservation
```

这些输入来自**用户理论本身**（KC-000031/000035），不需要 R4 的 exact target。因此
EXP-001 最小单元可与 PSJ 第一批并行，在 R4X 深化之前给出首轮判词。

### 2.3 EXP-001 最小单元规格

```text
id: EXP-001-MINIMAL
name: MINIMAL_EXPRESSIVITY_FIDELITY
line: COV/EXP 支撑线
priority: P1（用户显式要求；不阻塞 PSJ，与 M1-A 并行后串入 M2-C）
owner: canonical integrator（main）
input:
  KC-000031 / KC-000035 用户原文（极简理想理论 + 悖论研究理论的表达要求）
  rulings §14 的方向登记
  HoTT/cubical 的 formation/construct/observation/completion 形式化能力清单
action:
  1. 冻结最小 source theory（对象、操作、观察/完成关系）；
  2. 构造到 HoTT/cubical 的 interpretation（abstraction map + ASK 资格关系）；
  3. 逐项判断 preservation（007 片 §9 的六个判词）：
     SYNTAX_ENCODABLE / DERIVATION_PRESERVED /
     OBSERVATION_COMPLETION_PRESERVED /
     ONLY_EXTERNAL_PARAMETER_PRESERVES_TASK /
     NO_FAITHFUL_INTERPRETATION_CANDIDATE_WITH_SCOPE / INCONCLUSIVE；
  4. 单个编码失败不证明无法表达；能写一个类型也不证明保留任务（007 片 §9 的双向限定）。
deliverable:
  EXP-001-SOURCE-THEORY.json（冻结的最小理论）
  EXP-001-INTERPRETATION.md（abstraction map + 判词表）
  若涉及形式化：HoTT/formal/ 下 topic/claim 子目录 + HoTT/verification/runs/ 收据
verification:
  六个 preservation 判词中至少一个非 INCONCLUSIVE，且附机器证据（若涉及形式化）；
  判词范围限定为该最小理论，禁止外推到完整用户悖论理论。
stop:
  - 首轮判词完成 → 决定是否扩到完整理论（007 片 §10）；
  - 最小理论无法冻结（用户的"极简"描述本身含未定参数）→ 登记
    EXP_SOURCE_THEORY_UNDERDETERMINED，请用户澄清，不猜参数。
```

## 3. 截止日处置（A7）

### 3.1 事实

```text
rulings.md §23（用户裁定，2026-09-14）：明文要求"具名截止日学术覆盖"。
LIT-DENOMINATOR-001.md：截止日 = 2026-09-14。
当前判词：COMPREHENSIVE_COVERAGE_NOT_ACHIEVED。
全库检索"逾期 / overdue"：无任何处置记录——截止日只作为冻结参数出现一次。
GPT 008 片 §10 的处置："当前 as-of date 是文献纳入边界，不是项目交付期限"。
```

### 3.2 为什么必须登记（提级理由）

008 片 §10 的再解释把一条**用户裁定级义务**（§23 明文）软化为"纳入边界"。这属于
DeepSeek 所说的"语义再解释而非逾期处置"，但本审计把等级从 DeepSeek 的"缺口 2/中"提升为
**P1**：它软化的是用户明文裁定，不是方案内部约定。截止日已过（今天 2026-09-16），
继续无处置会让"覆盖义务"在方案内永久悬空（风险 R6）。

### 3.3 三选一登记表（必须选一并登记进 `rulings.md`）

| 选项 | 内容 | 登记要素 | 后果 |
|---|---|---|---|
| **(a) 顺延** | 设定新的具名截止日（建议与 M1.5 裁定同批确定） | 新日期、顺延理由、覆盖义务保持 | 义务保留；`COMPREHENSIVE_COVERAGE_NOT_ACHIEVED` 在新日期前为合法中间态 |
| **(b) 撤销** | 撤销"具名截止日学术覆盖"义务 | 撤销理由、撤销者（仅用户）、替代义务（若有） | 义务移除；`COMPREHENSIVE_COVERAGE_NOT_ACHIEVED` 判词降级为 `COVERAGE_AS_OF_SCOPED` |
| **(c) 改语义** | 确认 008 片 §10 的 as-of 解释，并**经用户明文确认** | 确认记录、as-of 日期、覆盖范围说明 | 义务转为纳入边界；必须用户确认，不能由方案单方面生效 |

**关键纪律**：(c) 只有在用户**明文确认**后才生效。008 片 §10 目前的写法是方案单方面的
再解释，在用户确认前，义务状态应登记为 `DEADLINE_OBLIGATION_IN_REINTERPRETATION_PENDING_USER_CONFIRM`，
不能默认已处置。

登记位置：`rulings.md`（用户裁定的唯一 owner）。方案不得自行写入裁定结果，只登记
"待裁定"状态与三个选项。这响应 010 片 §11"既有证据无法消解的现实/物理解释冲突：仅用户"。
