# 全面自动化推进纪律（009 片的执行链扩展）

> 修订对象：本方案 009 片 §4/§5 中仍隐含"等待用户"的执行流残留，
> 以及 SOP `.codex/skills/hott-paradox-search-sop/SKILL.md` 中所有
> "邀请用户介入/请求用户裁定"的触发点（P3/P4 之外：门槛判定 G-a/G-b/G-c、
> 越界作用域化判定、判词生成、同族坍缩判定、omission audit 结论、
> checkpoint 与交付物、以及方案修订本身）。
> 依据：用户 2026-09-16 最终裁定——"我认为 AI 可以做，我需要你全自动化地去做，
> 但是要明确地留下可审计性的信息，将来我会让其他 AI 来审计你的工作，包括你作出的
> 关键判定。人可以做的，说给你听你可以理解，那么事实上，就意味着你可以独立做。
> ……以后就是全面地自动化推进后续的工作，不要再邀请我的介入，
> 你全部做完之后，我会安排外部 AI 审计你的工作。"
> 修订性质：**把 009 片的"P3/P4 自动化"扩展为"整条执行链自动化"**，
> 并把可审计性从"P3/P4 逐条审计链"加严为"每个关键判定都必须可追溯"。
> source=user。

## 1. 为什么这是扩展而非替代（assessment）

009 片解决的是**判定层**的角色分工：P3/P4 由 AI 执行 + 强制审计层 + 外部追溯审计。
它留下一个缺口：执行链上还有大量**流程判定**（不是前提判定）仍然默认"问用户"——
门槛判定、作用域化边界、判词选择、停止与否。这些判定如果不自动化，
整条链仍会在每个门槛处停转，而用户的裁定已经表明：它们不需要停。

用户给出的认识论理由是自洽的，本审计独立复述并接受：**"人可以做的，说给你听
你可以理解，就意味着你可以独立做"**——能力不因授权形式而改变，改变的是
责任归属与可追溯性。因此自动化的正确形态不是"AI 代替用户猜"，
而是"AI 独立判定 + 每个判定都留下足以被外部审计推翻的证据"。

**同时必须明确的（本片不放宽的）**：自动化取消的是**等待**，不是**证据标准**。
下列门禁在全自动模式下一字不改：

- `MATH_PROOF_BEFORE_DELIVERY_V1`：数学结论仍需相称的机器证明 + run receipt。
- `F-011` 与修订片 015 §3.4 忠实性警戒：点集模型可靠但不完备，
  oracle verdict 只能由原生核在真实区间 I 上给出。
- `DENOMINATOR_SINGLE_SOURCE`（016 片）：验收的期望值与被验值同一 canonical 来源。
- 四件套全文加载、SOP 的反思循环与 `plan-revise` git 纪律、
  GEN-001 的 remainder=0 / 越界证明 / 正负控制 / 收据化（003 片）。
- 009 片 §3 的 `P3P4_AUDIT_TRAIL` 全部必填字段（含 steelman 与 falsifier）。

## 2. 自动化的边界：什么仍然停止

```text
仍然停止（AUTOMATION_BLOCKED_EVIDENCE_GAP）
  / 唯一条件：证据缺失到无法形成任何有界的下一步，
    且无法通过降级结论强度继续。
  / 动作：写 BLOCKED 报告（含已搜索范围、失败原因、可证伪条件），
    git 提交，然后继续执行该报告之外不受阻塞的其余单元。
  / 不做的事：不等待用户回复；不用摘要补证据洞；不把降级结论写成已成立。

仍然报告但不停止（REPORT_AND_CONTINUE）
  / 授权边界动作：git push / tag / 破坏性 Git 操作 / 超出本 repo 与引擎
    工作树的写 / 恢复已移走目录。这些动作被跳过并在最终交付中披露，
    其余工作继续。
  / 外部工具链不可用（如 Agda 核缺失）：报告具体阻塞，降级为
    ENUMERATOR_ONLY 并显式标注未核验，不冒充已核验。

不再产生（USER_ADJUDICATION 类阻塞全部删除）
  / 任何"等待用户裁定"的停止判词。用户权威改为纯非介入式：
    随时推翻、定义外部审计标准与审计者。这两项不需要 AI 停转。
```

## 3. 关键判定的强制可审计清单（加严）

全自动模式下，下列每个判定在产生时必须同时落盘以下五项，缺一则该判定
无效、不得进入下游产物：

```text
KEY_ADJUDICATION_AUDIT_TRAIL（本片新增，适用于执行链上的流程判定）
  / adjudication_id      : 判定唯一 ID（含所属 run / family / shard）
  / question             : 被判定的问题（精确到可被外部审计复述）
  / verdict              : 判定结论
  / verdict_reason       : 判定论证，必须引用机械证据（收据路径、数字、退出码）
  / falsifier            : 什么可观察事实会推翻本判定（可操作、可指认）
  / evidence_anchors     : RUN.json / witness-manifest / kernel receipt /
                           git commit / 修订片 / STATE revision
  / audit_status         : AI_ADJUDICATED_PENDING_EXTERNAL_AUDIT
  / depends_on           : 若被推翻，哪些下游产物必须回滚或降级
```

适用清单（非穷尽，以"该判定会改变下游产物"为准）：

1. 门槛判定 G-a / G-b / G-c（014/015 片）：是否从 delay 片段升到 V2 片段。
2. 越界作用域化判定（012 片 §2.3 + V2）：哪些见证是 V2 专属、哪些是
   L1 共享 ingress。
3. kernel 见证选择（KERNEL_POLICY）：为什么是这四个 cell。
4. 判词生成（`GENERATOR_LINK_DEMONSTRATED_WITH_SCOPE` 等）：四项判据逐条。
5. 同族坍缩判定（013 片 Q4）：同族多成员是否真的坍缩到同一机制。
6. omission audit 结论（O-1…O-5 类）：未耗尽/饱和的判定。
7. checkpoint 内容判定：KC audit 的 ALIGNED/DEEPENED/NOT_TOUCHED 分类。
8. 方案修订本身（plan-revise）：触发条件、修订条款、不变项。

`P3P4_AUDIT_TRAIL`（009 片）是本清单在第 9 类（前提判定）上的特化版本，
字段更严（强制 steelman），不与本片冲突。

## 4. 执行流变更（替换 SOP 中的介入触发点）

```text
旧（隐含）                    新（017 片）
门槛判定 → 问用户       →     AI 判定 + KEY_ADJUDICATION_AUDIT_TRAIL，
                              判定即执行，反思写入 git log（reflection=）
遇到未知 → 问用户       →     未知分类：非阻塞 → 披露后继续
                              （AUTOMATION_CONTINUE_WITH_DISCLOSED_UNKNOWN）；
                              阻塞性 → §2 的 BLOCKED 路径
阶段完成 → 等用户确认    →     checkpoint --apply（canonical 收据）+
                              修订片登记 + goal-1 指针同步，全部 git 提交
全部完成 → 交付          →     交付物自带 pending-audit 标记与
                              外部审计入口（审计清单 = §3 的 trail 集合）
```

外部审计（角色 D）的终局性不变：它复核的不仅是 P3/P4 条目，
而是 §3 清单上的全部关键判定。推翻任一条时，按 `depends_on` 回滚或降级
下游产物，并在 git log 留痕。

## 5. 新增/修订的失败判词

```text
AUTOMATION_CONTINUE_WITH_DISCLOSED_UNKNOWN（新增）
  / 存在影响局部的未知，但不阻塞当前有界 pass 的完成
  / 必须在交付物中显式列出该未知、其影响范围、以及为何不阻塞
  / 不允许把该未知写成"已处理"或"不存在"

AUTOMATION_BLOCKED_EVIDENCE_GAP（新增，替换一切 USER_*_REQUIRED 残留）
  / 见 §2；产生 BLOCKED 报告后继续执行不受阻塞的其余单元

GENERATOR_LINK_DEMONSTRATED_WITH_SCOPE（沿用，验收证据要求加严）
  / 四项判据（remainder=0 / 越界证明 / oracle 由原生核给出 / 完整链）
    每一项的引用必须是具体收据路径与数字，不得是概述
  / 若 oracle 未由原生核给出（仅枚举器），判词降级为
    ENUMERATOR_ONLY_NOT_KERNEL_CONFIRMED，不得作为该族结论证据
    （F-011 加严 + 015 §5 V2 专属强制披露）
```

## 6. 反解释与自我限定

- **本片不是"AI 判定即正确"**：恰恰相反，§3 全部字段存在的前提是
  "AI 的流程判定可能出错，因此必须可追溯、可推翻、可回滚"。
  自动化提高的是**推进速度**，不是**结论等级**。
- **本片不取消用户的任何权利**：用户随时可推翻、暂停、改回旧分工。
  取消的只是"必须等待"这一阻塞形式。
- **本片不声称穷尽关键判定类型**：§3 清单是非穷尽的，
  判定标准是"该判定会改变下游产物"——外部审计可追加新类型。
- **本片不产生数学结论**：全部为规程修订。F-011 不适用。
- **可证伪条件**：若外部审计发现某个关键判定缺少 §3 的任一字段，
  该判定及其下游产物必须回滚。这是本片的验收条件。

## 7. 与既有片的关系

- **009 片**：角色分工表（§2）与 P3P4_AUDIT_TRAIL（§3）完全保留；
  本片只把适用范围从 P3/P4 扩到整条执行链，并删除其 §5 残留的
  "USER_ADJUDICATION_REQUIRED" 语义（该判词在 009 片已删除，
  本片删除其在执行流上的等价物）。
- **003 片（GEN-001）**：验收标准不变；本片只要求四项判据的引用
  具体化（§5）。
- **014/015 片**：门槛判定 G-a/G-b/G-c 的判据不变，
  判定者由"用户 + AI"改为"AI + KEY_ADJUDICATION_AUDIT_TRAIL"。
- **016 片**：DENOMINATOR_SINGLE_SOURCE 不变，成为 §3 evidence_anchors
  的必检项之一。
- **SOP Skill**：其反思循环（穿越压缩边界后系统调查前一阶段工作是否
  应调整方案、方案优化必须 git 提交）在本片下从"建议"变为"强制"，
  因为它是全自动模式下方案演化的唯一可追踪载体。
