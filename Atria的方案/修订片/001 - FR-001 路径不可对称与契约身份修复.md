# FR-001 路径不可对称与契约身份修复

## 2. 对 003 片 §1 的修订：判词升级

003 片 §1 的判词是：

```text
PINNED_BYTE_SNAPSHOTS_NOT_RECOVERED_IN_CHECKED_REPO_EVIDENCE
```

该判词的搜索范围（Git、S151 before/after、checkpoint/session/audit 的 7,484 文件）在本审计中独立复核为**已正确执行**，判词本身不假。但它把"未找到"与"不存在"的边界留在搜索行为上，未区分两个 affected record 的**可恢复性结构差异**。修订为：

```text
PINNED_BYTE_SNAPSHOTS_NOT_RECOVERABLE_WITHIN_REACHABLE_EVIDENCE
  / APPLIES_TO: goal.md
  / REASON: git_history_empty + no_worktree_copy + pinned_hash_not_git_object
           + checkpoint_transaction_did_not_snapshot_file
  / SCOPE: reachable_evidence_only
```

对 R4 TaskSpec：两个 pinned 哈希均非 Git 对象（confirmed）；R4 TaskSpec 文件自身的 untracked 状态**未单独验证**（A4 的 `git ls-files` 只覆盖了八个互动目录与 goal.md）。因此 R4 保留 003 片原判词 `..._NOT_RECOVERED_IN_CHECKED_REPO_EVIDENCE`，并在 EC-001（修订片 002）中把"R4 TaskSpec 的跟踪状态"列为待补检查项。这是范围诚实的区分，不是对称框架的延续。

## 3. 对 003 片 §4 的修订：路径 A 对 goal.md 不可用

003 片 §4 把"路径 A：旧 bytes 可恢复"写成与路径 B 并列的可选分支，执行者需先尝试 A 再回退 B。修订为**前置判定**：

```text
IF affected_record == goal.md:
    路径 A 在可及证据范围内不可用 → 直接进入路径 B（§5 语义重建）
    禁止把"继续搜索旧 bytes"当作 FR-001 的进行中状态
ELSE（R4 TaskSpec 等其它 record）:
    维持 003 片原双路径流程
```

判定依据是 §1 表中的四项结构事实（Git 历史空 / 无工作树副本 / pinned 非 Git 对象 / checkpoint 未快照），它们共同穷尽了项目内可及的 byte 恢复位置。**这是"在已检查范围内不存在"的定范围负结论**，不是全局不可能（见 §7 反解释）。

执行含义：FR-001 对 goal.md 不再有"搜索旧 bytes"的工时消耗；工时转向 §4 的语义重建与 §5 的契约身份修复。

## 4. 对 003 片 §5（路径 B）的加强：语义重建的输入集与不对称性

003 片 §5 已规定语义重建只允许 `SUPPORTED_CURRENT_CONTENT` / `SUPPORTED_HISTORICAL_INTENT` / `NEW_UNPINNED_CONTENT` / `CONFLICT` / `UNKNOWN_DUE_TO_MISSING_SOURCE` 五态。本修订**不改变五态**，只加强输入集与一项推断。

### 4.1 语义输入集（actual goal.md 与既有权威的逐项对照）

| actual goal.md 条款 | 对照权威 | 一致性 |
|---|---|---|
| §11 完成门含"自然 consumer" | `rulings.md` §23（2026-09-14 用户裁定） | 逐项吻合 |
| §11 完成门含"现实同任务对应" | `rulings.md` §23 | 吻合 |
| §11 含"方向 A / 方向 B" | `rulings.md` §23、Z_LAW §0 | 吻合 |
| §1/§9 现实相对非现实性（非 `HoTT ⊢ ⊥`） | Z_LAW §0、KC-000010 | 吻合 |
| "具名截止日学术覆盖" | `rulings.md` §23、`LIT-DENOMINATOR-001.md` | 吻合（截止日本身的处置见修订片 005） |

对照收据：Atria 审计报告集 06 §1（三方契约一致性复核，confirmed）。

### 4.2 不对称性推断（candidate，需与 §4.1 合并阅读）

003 片把局面表述为"actual 与 pinned 各自自称 current、不预先判定哪版正确"。本审计认为该对称框架对 goal.md **过强**，理由有三：

1. **无竞争版本**：旧 bytes 不存在，actual 不是"两个版本之一"，而是唯一存在的版本。对称裁决需要一个对照端，该端在可及范围内不存在。
2. **语义吻合**：actual §11 与时序最晚、最具体的用户裁定（§23，2026-09-14）逐项一致（§4.1）。
3. **时序同窗**：两个文件的 mtime 落在 GLM 独立审计 README 诞生（07:06:35Z）之后的同一窗口，且在 S151 checkpoint 之后 32 分钟。

因此：

```text
FR-001 对 goal.md 的正确完成路径 =
    以 actual 为 intended current 候选
  + 用 rulings / Feature / 用户原文做语义佐证（§4.1 的逐项对照作为证据）
  + 登记 pin 过期（pin = S151 时刻快照，非当前真值）
  + 登记"目标契约从未进入版本控制"这一根因（§5）
  + 重钉（canonical checkpoint 原位，禁止手工改 STATE）
```

**编辑者身份不在本审计可证范围**（source-reported 级别事实）：本审计不能断言修改由用户完成。上述推断的证据是"内容与用户既定意图一致 + 时序同窗"，不是"作者身份证明"。修订方案因此把 intended-content 判定与作者判定分开登记。

## 5. 新增 §12（003 片之后）：目标契约入版本控制（A4 根因登记）

A4 的事实：九个互动/审计目录与 goal.md 的 `git ls-files` 全部为 0；`git status` = 218 changed（180 untracked + 38 modified）。含义：FR-001 试图用 Git 考古裁决冲突时，**冲突两端都不在版本控制里**——一端在文件系统（actual），另一端在 STATE 的一个过期哈希里（pinned）。

修订要求：FR-001 的完成判词必须包含根因登记，否则 FR 会被"改 pin 为 actual"假修复（风险 R3）：

```text
ROOT_CAUSE_REGISTERED: TARGET_CONTRACT_NEVER_VERSION_CONTROLLED
  / goal.md 从进入项目起未被任何 commit 跟踪
  / 影响：目标契约的"当前版本"不可从 Git 固定；任何基于当前 Goal 的执行前提不可跨 Session 恢复
  / 处置：进入 VC-001 第一批提交内容（见修订片 002 §6）
```

`ROOT_CAUSE_REGISTERED` 与 003 片 §8 的 `ACTIVE_RECORD_SOURCE_IDENTITY_RECONCILED` 是**两个必须同时成立**的判词。只达前者而未重钉，等于登记了问题未修复；只达后者而未登记根因，等于把"改 pin 为 actual"当作完成。

## 6. 对 003 片 §6 的修订：canonical integrator 的裁决路径

003 片 §6 原文："既有用户指令、rulings 与 Feature 足以唯一裁决时，由 canonical integrator 执行并引用旧来源；不重复询问。"

修订为（加粗为新增条件）：

> 既有用户指令、rulings 与 Feature 足以唯一裁决时，由 canonical integrator 执行。**当 byte 基线不可恢复时，"引用旧来源"应替换为"引用 actual 与既有权威的语义对照表（§4.1）"**，并显式登记该裁决的证据等级为
> `SEMANTIC_RECONSTRUCTION_WITH_MISSING_BYTE_BASELINE`（沿用 003 片 §5.3 的判词），**不得**声称 byte 级裁决。只有两个版本表达互斥目标、且语义对照也无法消解时，才请求新的用户选择。

这一步不扩大 canonical integrator 的权限：它仍然只在既有权威可裁决时行动；它把"缺 byte 基线"从"无法裁决"变成"以语义证据裁决并降级标注"。

## 7. 反解释与降级（本修订的自我限定）

- **未搜索位置**：主机级 Time Machine 快照、用户私存的编辑前副本、其它备份系统不在本审计搜索范围内。若存在，路径 A 对 goal.md 可能重新可用，判词回退为 003 片原判词。本修订的所有结论因此带 `SCOPE: reachable_evidence_only`。
- **校验器与哈希工具本身**：本修订依赖 `git log`/`ls-files`/`cat-file` 的输出为真。这些是机械 Git 命令，不构成数学判断。
- **语义对照的局限**：§4.1 的吻合证明"actual 与 §23 一致"，不证明"actual 是用户最终想说的全部内容"——可能存在未被任何 rulings 捕捉的新意图。该项保持 `UNKNOWN_DUE_TO_MISSING_BYTE_BASELINE`，不由文件存在填补。

## 9. 与 DeepSeek 增补 A 的关系

DeepSeek 增补 A《FR 来源身份重建增补》补的是 FR 的**语义重建流程细节**；本片补的是**路径适用范围与契约身份根因**。两者叠加：DeepSeek 的语义重建步骤在路径 B 内执行，本片规定何时进入路径 B、以及完成后必须附 `ROOT_CAUSE_REGISTERED`。不冲突。
