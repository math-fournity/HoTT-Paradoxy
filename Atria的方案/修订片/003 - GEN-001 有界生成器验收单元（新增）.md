# GEN-001 有界生成器验收单元（新增）

> 修订对象：GPT 方案 v2.1 第 002 片工作包表（新增一行）+ 第 007 片 §3（六生成器真实薄切片）。
> 依据：Atria 审计报告集 01 §3（A3）、05（引擎能力边界审计）、
> `evidence/commands/03-machine-overview-engine.txt`（selftest 94/94 独立复现）。
> 修订性质：**新增 M1 并行单元，验收"引擎能产生当前声明文法之外的新候选"这一能力**，
> 而不是要求引擎变为无界生成器。

## 1. 能力事实（observed，本审计独立复算）

| 检查 | 结果 |

| `registry.json` | `implemented_stages = [M0, M1, M3]`；`partial_stages` 中 **M2 = "one symbolic-horn proof-search slice …; no general dependent/higher-path search"**；M4/M5 集成与版本闭合 open |

**定性结论**：机器统观引擎目前是**声明文法校准器**——在人工声明的有限文法上做完整枚举、
grammar-preserving 归约、原生核校验与收据化。这是高价值的验证设施，但它**不生成**新的理论构造、
新的 consumer、新的抽象变换或新的现实任务。

## 2. 为什么这是 P0 级（A3 的论证）

GPT 007 片 §3 要求"六类生成器各至少一条 input→candidate→oracle→receipt 真实链"。当前状态：
声明文法枚举（第 1 类的部分）+ 三个研究扩展（tick-irrelevance / reflected-tick /
quotation-bridge，属第 5/6 类的个案）。**要求存在、实现不存在、且 M0–M6 里程碑里没有任何单元
验收该能力获得**。

GLM 的 B4（基础设施偏好：验证侧扩张而假设生成侧无对应投入）与 Astra 的 3.3（把新候选生成提前
到第一轮验收）都触及了这一点，但**没有任何一份审计把它标为 P0 级的"确保成功"能力缺口**。

对"机器统观能否成功"的直接含义：若不建设生成器，无论 PSJ/TGSQ/R4X 的判词多干净，候选空间
始终由人工预置的文法与任务决定——**"统观"退化为"对已知族的穷举校准"**（风险 R11，
与 GLM 的 B3"分类法即命运"是同一问题的两面：分母由人工声明，引擎不越界）。

Goal 的完成门（rulings §23）要求"至少一个候选贯通"，该候选必须是**新**的贯通候选；
校准器不能发现新候选，因此不能单独闭合 Goal。

## 3. GEN-001 的定位：有界，不是无界

本修订**不要求**引擎变为无约束生成器。声明文法路线本身是正确的安全设计：可枚举分母、
remainder=0、防止无界搜索、每轮可收据化。GEN-001 的目标是在**保持这些安全性质**的前提下，
验证一次"引擎能产出当前声明文法之外的新候选"的完整链。

具体地，"新候选"在此单元中的合法含义被限定为：

```text
有界新组合 = 冻结的新任务族（不在现有 15 个已声明文法内）
           × 冻结的构造子组合空间（有限、可枚举分母）
           × 引擎的 grammar-preserving 归约
           × 原生核校验 + 收据
```

即：分母仍然人工冻结（安全设计不变），但**冻结的权利从"只在既有文法内选"扩展到"可以冻结
新的任务族"**。这一步把生成器能力从"人工预置"推进到"人工供给新文法 + 程序枚举 + 核验分工"。

## 4. GEN-001 任务规格（九字段）

```text
id: GEN-001
name: BOUNDED_GENERATOR_ACCEPTANCE_UNIT
line: COV/EXP 支撑线（GPT 002 片 §1）
priority: P0（能力建设；与 PSJ-001A 只读部分并行，不阻塞判词）
owner: canonical integrator（main 工作面；引擎在 /Volumes/D/HoTT-machine-overview
       只读候选来源上运行，收据回写 main）
input:
  - 机器统观引擎（mo.py / search.py / registry.json / 已声明文法清单）
  - 一个由人工（用户或 Agent 在用户确认后）冻结的新任务族：
      不在现有 15 个已声明文法内；建议从用户 KC 点名方向选取
      （KC-000031 极简理论覆盖、KC-000035 悖论理论表达、KC-000003 稠密 vs 量子化、
       KC-000024 两类时序悖论）
  - 新任务族的有限构造子清单（形成可枚举分母）
action:
  1. 冻结新任务族：任务定义、构造子清单、分母大小、观察层、完成属性、oracle 类型；
  2. 声明对应文法（遵循 search.py 的 declared-grammar 契约），明确它与现有 15 个文法不相交；
  3. 引擎执行遍历（declared grammar only，界由新文法固定）；
  4. 对每个枚举出的候选执行 grammar-preserving 归约；
  5. 用原生核校验（非 Python 枚举、非普通 Lean Eq；HoTT/cubical 相关结论用相应原生系统，
     遵循 F-011 与 MATH_PROOF_BEFORE_DELIVERY_V1）；
  6. 产生 run 收据（RUN.json / stdout / stderr / environment / source-manifest，
     存入 HoTT/verification/runs/<run-id>/）；
  7. 在 CE-MAP 建立索引行（claim ID / proof ID / 源码 / run receipt / 证据等级 / 禁止外推）。
deliverable:
  GEN-001-GRAMMAR.json（冻结的新任务族与文法）
  GEN-001-ENUMERATION.json（分母、枚举结果、remainder）
  GEN-001-RECEIPTS/（原生核 run 收据）
  CE-MAP 新增索引行
verification:
  - 分母固定且 remainder=0（有限文法的完备性要求，007 片 §4）；
  - 至少一个候选是"现有 15 个文法无法产出的"（证明越界，而非重复既有族）；
  - 每个候选的 oracle verdict 由原生核而非启发式给出；
  - 完整链存在：input → candidate → oracle → receipt（007 片 §3 的最小真实链）。
stop:
  - 上述四项全部达成 → 判词 GENERATOR_LINK_DEMONSTRATED_WITH_SCOPE；
  - 新任务族无法在有限构造子内表达 → 判词
    GRAMMAR_REQUIRES_UNBOUNDED_SPACE_REGISTERED，登记该族的无限性证据，
    转为 dovetailing/iterative deepening 计划（007 片 §4 的 infinite codes 路径），
    不假装已枚举；
  - 原生核不可用或不可复现 → 判词 GENERATOR_LINK_BLOCKED_KERNEL_UNAVAILABLE，
    登记 kernel/环境缺口，不降级为 Python/启发式校验。
```

## 5. 角色分工（人 / 程序 / 核）

本单元的关键是三个角色的分工不得互相冒充：

| 角色 | 职责 | 不得冒充 |
|---|---|---|
| 人工（用户或受权 Agent） | 冻结新任务族、供给构造子、固定分母 | 不得冒充"引擎自动发现了新任务" |
| 程序（引擎/search.py） | 在冻结文法上完整枚举 + grammar-preserving 归约 | 不得冒充"生成了文法之外的对象" |
| 原生核 | 校验候选、给出 oracle verdict、产生收据 | 不得由 Python 枚举或普通 Lean Eq 替代（F-011） |

**关键纪律**：人工供给了新任务族，因此 GEN-001 验收的是**引擎的枚举/归约/核验能力在新族上的
贯通**，不是"引擎自主发现新研究方向"。这一区分必须在判词中显式写出，否则会把人工供给
冒充为生成能力（这正是 A3 反解释要防的）。

## 6. 完成判词与禁止外推

```text
GENERATOR_LINK_DEMONSTRATED_WITH_SCOPE
  / generator_family: 第 1 类（typed term/proof synthesis）的真实链
  / scope: 单一冻结任务族；remainder=0
  / 其余五类生成器状态不变（仍 PARTIAL）
  / 不声称：开放候选空间的完备覆盖
  / 不声称：引擎已具备自主发现新方向的能力
```

**scoped negative 不得冒充生成能力**：若新任务族上全部候选都得到 scoped negative
（无命中），GEN-001 的判词是 `GENERATOR_LINK_DEMONSTRATED_WITH_NEGATIVE_RESULT`——
链已贯通、结果为负。这与"生成器能力缺失"是两回事，也与"该族无候选"是两回事
（007 片 §10：`NO_HIT_WITHIN_SCOPE` 不构成全局无候选证明）。

## 7. 与 GPT 007 片 §3 六生成器表的关系

007 片 §3 的六类生成器是**横向骨架**（M5 里程碑）。GEN-001 只验收其中**第 1 类**（typed
term/proof synthesis）的一条真实链，且是在一个新冻结任务族上。其余五类的状态在 GEN-001 完成
后**保持不变**（PARTIAL），本修订不声称覆盖六类。

GEN-001 的作用是把 007 片 §3 的"要求存在"变成"至少一条已被验收"，从而使 M5 的横向骨架
有了第一个可累积的锚点。后续可按同一模式逐类补链，每类一个有界单元，不要求一次性完成。

## 9. 反解释与自我限定

- **声明文法路线是正确的**：可枚举分母、remainder=0、无界搜索风险，这些都是真实的安全收益。
  本修订不主张改为无约束生成；GEN-001 的"新"严格限定在"新冻结的任务族"内（§3）。
- **校准器足以验证候选**：A3 反解释成立的部分是"校准器能验证"；不成立的部分是"它不能发现，
  而 Goal 要求至少一个新的贯通候选"。本修订保留这一区分。
- **不新增平台**：GEN-001 复用 mo.py / search.py / TaskSpec / RUNS / CE-MAP /
  `HoTT/verification/runs/`，不建第二套 manager、daemon 或常驻审计 AI（遵循 GPT 010 片 §5
  与项目 AGENTS 的"不新增治理平台"约束）。
- **不产生数学结论**：GEN-001 产出的候选若要作为数学结论交付，仍须走 F-011 全部门禁。
  本单元验收的是**链的贯通**，不是数学命题的真值。

## 10. 与既有审计建议的关系

- **Astra 3.3**（把新候选生成提前到第一轮验收）：本修订采纳其方向，但用"有界新任务族"而非
  "开放生成"来实现，避免无界搜索风险。
- **GLM B3/B4**（分类法即命运 / 基础设施偏好）：本修订正面回应——把"分母由人工声明"从
  隐含约束变为显式契约（人工冻结新族的权利 + 引擎枚举的责任 + 核验的分工，§5）。
- **DeepSeek**：DeepSeek 的七片增补不含生成器能力项；本片是 Atria 独有。两者不冲突。
