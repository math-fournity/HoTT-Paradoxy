## 1. 核心判定：两类承载系统的结构（用户第三弹「两类拓扑学」的升级）

用户第三弹原指令的结构是「利用两类系统使同一对象获得相反判定」（原为：传统拓扑学
vs 圆环悖论拓扑学）。第四弹把该结构升级到元层：

- **系统一：HoTT Book 理论层**——可以宣布「已完成」而不必兑现（实数就是 cut、
  位置已经确定；单价公理作为公理 asserted 而无计算内容）。
- **系统二：计算引擎 cubical Agda 层**——必须真的算完才能盖章；理想元素不能
  悄悄发放，LEM 必须作为显式假设现身（第三枚已实证此现形机制，
  `MP-DEDEKIND-OMEGA-M3`，run `…-M3-01`）。
- **落差**：理论宣布了引擎无法兑现的东西；非现实性住在这条缝里。

**已有定理级支撑（`SOURCE_REPORTED_NOT_REPLAYED`，本轮未跑核）**：把单价公理
作为普通公理加入 MLTT 会破坏 canonicity——存在既非 `zero` 也非任何后继的闭项，
即**理论中存在不被任何真实计算承载的成员**（Huber 型反例，标准结果）；
cubical Agda 是恢复 canonicity 的工程回答（让 UA 真的可计算）。
**这条缝是学科自己承认的，不是本项目虚构的攻击面。**

**位置链（思想来源原文的忠实展开）**：物理现实 → 程序（必须停机才能交付）→
证明引擎（必须真的检查）→ Book 理论（可以宣布不兑现）。引擎不是「现实」本身，
它是**被迫兑现的理论**——把 ASK 强制执行掉的关卡。本方向不声称「Agda=现实」。

### 2.1 研究对象：承载三元组 (T, E, X)

理论 T、引擎 E、经典理想元素 X。首批实例：(cubical type theory, Agda, LEM)；
(MLTT + UA-作公理, 任何检查器, UA)。

### 2.2 定义草案（PENDING_KERNEL；「承载」的判定对应关系之严格形式登记为设计难点）

- **定义一（承载 carrying）**：E 的判定忠实对应 T 的推演——E 是 T 的
  「被迫兑现版」。
- **定义二（完成义务 completion obligation）**：E 所接受的内容都必须真的兑现——
  canonicity / 可实现性的精化。
- **定义三（显式化 surface）**：X 进入 E 的状态可被机械检查，恰为三者之一：
  拒绝 / 显式假设 / 表达力塌缩。

### 2.3 主定理模式草案（不可兼得定理）

**完成义务与经典理想元素不可兼得**：若 T 含 X，任何承载 T 且有完成义务的引擎 E
必然三选一——拒绝 X；显式化 X（并丧失/限制完成义务）；塌缩表达力。

- 已有实例：LEM → 显式化（`MP-DEDEKIND-OMEGA-M3` 收据 = 本模式第一张核收据）；
  UA-作公理 → canonicity 破坏（Huber 型反例，`SOURCE_REPORTED_NOT_REPLAYED`，
  = §3 靶 A）；resizing → 不可表达（= §3 靶 B 预测格）。
- 证明地位：**逐实例的元定理**，不存在单条覆盖所有三元组的 Agda 定理；
  机械化 = 每个三元组一次发射（继承「逐发留收据」纪律）。

### 2.4 本方向的自我定位：ASK 的数学化

ASK（「是否可停机/合法」）的数学基石 = 不可判定性 + canonicity + 可实现性这一族
定理。第四弹 = 把 ASK 从一个审查动作升级为形式理论，(HoTT, Agda) 为第一个被
正式审查的 (T, E) 对。

### 2.5 corpus 与诚实登记

- 组成部件（canonicity / 可实现性 / 不可判定性）为已知数学，**corpus 风险高**
  （第 1 通道，006/007 片纪律必须披露）；新的不是部件，是把它们作为攻击理论
  对准 (T, E) 对、并与 `PROCESS_DECLARATION_GAP` 接线（元层推广）。

## 3. 第四弹候选靶与打法原则

### 3.1 三个候选靶（供给，不判定；执行靶由下一执行单元按 023 四标注打造）

- **靶 A（canonicity 缝隙的机械化）**：在 Agda 中以 `postulate` 引入 UA 公理，
  构造 Huber 型反例闭项，机械化展示其不归约到任何数字。**设计难点（登记）**：
  「不可归约」是元层性质，其机械化路径（归约引擎判定 / 语义论证 / 范式检查器）
  须在执行单元中设计，不预设可行。
- **靶 B（对齐审计矩阵）**：对 F2 前提清单（7 条缺口层 + 分母 A–G）逐条登记
  「引擎可见性」：该前提进入引擎时现形为**显式假设 / 不可表达 / 静默消失**。
  已完成一格：LEM → 显式假设（M3 收据）。预测（未核）：resizing → 不可表达；
  AC → 显式假设。产出 = 对齐矩阵 + 逐格收据或「未核验」标注。
- **靶 C（反弹武器化）**：把「你们只是在引擎里证明的」这一防御反弹反转为攻击：
  构造一个 Book-HoTT 实践中合法、而任何 canonicity 引擎必须拒绝或显式化的
  具体推理模式——第三枚（LEM 显式化）是其首个实例，靶 C 找第二、第三个实例。

### 3.2 打法原则：哥德尔式打法（收官版新增）

哥德尔式打法 = 对每个对象，找到它那句具体的不可证句。翻译到本方向：**对每个经典
理想元素 X，找到它在诚实引擎中的「必收费命题」。** 三靶排序由此获得原则：

- 靶 B = 清点 F2 清单里每个 X 的 G 的目录（成本最低，每格出收据或「未核验」
  标注）；
- 靶 A = 把最重的那把 G 锻造成收据（价值最高，机械化路径需先设计）；
- 靶 C = 把目录武器化为攻击序列。

（原则来源：dev-notes/0014 收官综合——第四弹之于第三弹，恰如「不完备性的普遍
定理」之于「某个具体的不可证句」。）

## 4. 证明论落位：证伪格，而非独立性格（收官版新增）

- **三分法**：证明 / 证伪 / 证明为不可证（独立性）。第三弹的实际落位是**证伪格**：
  M3-L1 不是「没找到 A=B 的证明」，而是给出构造式拒绝——LEMᵒ 假设 + M2 之下，
  `Spec_A ≃ Spec_B` 被证明为空。证伪强于不可证：不可证只说「没有证书」，证伪说
  「谁出示证书谁被当场击落」。
- **拒证二元性**：引擎内证伪（M1/M2/M3-L1 三张拒绝程序收据）+ 元理论颁发不可证
  证书。「第三弹的原始形态（在系统内引爆炸弹）不可证」这一判定，需要「Agda 一致」
  作前提，而足够强的系统不能在内部自证一致性——**哥德尔第二定理的形状保证了：
  不可证性证书必须由元理论颁发，引擎自己开不出。** 第四弹 = 颁发证书的元理论
  （§2 的承载三元组理论）；它每证明一个三元组上的三选一，就是颁发一张
  「此处必然拒绝」的证书。
- 边界：此为**架构级同构**（实践—形式之差、必然性模式、元层证明的被迫性），不是
  字面的哥德尔句——核心收据是构造式证伪，不是独立性结果。禁止声称「HoTT Agda
  的哥德尔不完备性被实例化」。

## 6. 收官判定：四弹一体（哥德尔镜头；收官版新增）

### 6.1 三幕同构：一场小型的「纲领→拒绝→元数学」历史重演

哥德尔不完备性的实际历史表现是三幕结构：Hilbert 纲领预期（系统内完成一切证明
目标）→ 哥德尔交出拒绝（系统无法兑现其实践承诺）→ 元数学诞生（研究系统必然
做不到什么）。四发导弹逐幕重演：第三弹原预期 = 纲领式预期（A=B 引爆）；第三弹
实际战况 = 哥德尔式拒绝（引擎不肯为实践所用的话签字）；第四弹 = 元数学的诞生
（研究诚实引擎必然拒绝什么）。**四弹是一个整体 = 那次历史事件的可控复现实验。**

### 6.2 镜像结构：真而不可达 / 用而必拒

哥德尔侧落差：「真而不可达」——存在真的句子，形式系统够不着。我们侧落差：
「用而必拒」——实践日日用的话（实数就是 cut，位置已确定），引擎扛不住、必拒之。
同一条缝（实践承诺与形式兑现之差），两个方向。§2.3 的三选一定理把两个方向统一成
必然性模式：任何有完成义务的承载，要么够不着、要么必须收费。**每个诚实引擎、
对每个经典理想元素，都有自己的那句「不可证」。**——这是第三-第四弹关系的定理化：
第三弹拿到的是那把具体的 G，第四弹要证的是「每个诚实引擎都有自己的 G」。

### 6.3 第三-第四弹关系 = 对象层/元层的被迫关系

第三弹在对象层取得三张拒绝收据；但「这个拒绝 = 击毁」的判定书，对象层自己开不出
——需要一致性/canonicity 元事实，哥德尔第二定理保证这类自证证书系统内不存在。
**拒绝在引擎内发生，拒绝的意义由元理论颁发。** 由此，第三弹的原预期以唯一可能的
货币兑现：经典逻辑货币（P∧¬P → 爆炸）换成构造式拒绝货币——两币汇率由第四弹给出。

### 6.4 四条闭环

- **战术闭环**：每发吸收上一发激起的反弹（023 片机制），第四发把最后一发反弹
  （「炸弹没炸」）本身升格为理论——反弹序列终结于把它反转为学科。
- **层级闭环**：过程层（不可完成）→ 声明层（不可能完成）→ 识别层（拒绝同一性）
  → 元层（理论与引擎的关系本身成为靶）。
- **语义闭环**：「击毁」的最终定义：不是内部矛盾，而是理论的真实数层理想元素在
  任何诚实引擎中都是不可支付的债务；理论要么改口，要么承认自己在被拒之桥上行走。
- **历史闭环**：圆环悖论 → Z 铁律 → ASK → 三发锚定 → 第四发 = ASK 的数学化。
  这条弧从核心认知第一段原文走到今天。
