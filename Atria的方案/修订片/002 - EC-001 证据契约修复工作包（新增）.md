# EC-001 证据契约修复工作包（新增）

> 修订对象：GPT 方案 v2.1 第 003 片 §9（VC-001）**之前插入一个前置工作包**；不修改 §9 的六步流程本身。
> 依据：Atria 审计报告集 01 §2（A2）、01 §4（A4）、`evidence/commands/02-verifiers.txt`（独立复算收据）。
> 修订性质：**新增 TaskSpec 级工作包，修复与 Git 跟踪状态无关的 14 项证据契约失配**。
> 数学影响：**零**。本工作包不修改任何 proof source、不改写任何 run 收据的 KERNEL_ACCEPTED 状态；
> 只修包装脚本契约、依赖登记与 manifest 哈希同步。

## 1. 为什么必须在 VC-001 之前（A2 的核心）

GPT 003 片 §9 的 VC-001 流程是"冻结 status → 逐包枚举 → 跑 closure verifier → 精确 stage/commit →
翻转 version status"。本审计独立复算 `verify_proof_version_closure.py` 全量运行返回
`BLOCKED / GIT_FAILED`（C-188 资产 untracked），绕过 Git 前置后对 25 个 later packages 逐包调用
`check_later_package`：

```text
later_packages: 25  OK: 11  FAIL: 14
 7 × LATER_COMMAND_SOURCE_MISMATCH
 6 × LATER_DEPENDENCY_GAP_NOT_ALLOWLISTED
 1 × LATER_SOURCE_HASH_DRIFT
```

**这 14 项失败全部与 Git 跟踪状态无关**：即使把 `git status` 的 218 个 changed 路径全部提交，
这 14 包仍会失败。因此 VC-001 按当前写法执行，会在 commit 之后立刻暴露 14 项新失败，且
003 片没有处置路径——失败会被误读为"Git 未授权"（风险 R10）。

这不是"数学证明为假"的证据。F-011 要求的 source→run→index 三方绑定在 14 个包上不闭合，
是**证据契约层**失配。

## 2. 失配清单与逐项裁决路径（14 项）

收据原文：`../../Atria的审计报告集/evidence/commands/02-verifiers.txt`。

### 2.1 `LATER_COMMAND_SOURCE_MISMATCH`（7 项）

```text
MP-COQ-MM2-UNDECIDABILITY-REPLAY-001
MP-COQ-MM2-PROGRAMCODE-BRIDGE-001
MP-COQ-PARAMETRIC-CT-INTERNAL-UNDEC-001
MP-CUBICAL-GROUPOID-SYNTAX-REPLAY-001
MP-AGDA-FLAT-INTERNAL-UNIVERSES-REPLAY-001
MP-COQ-INTERVAL-REPLACEMENT-BOUNDARY-001
MP-COQ-SYNTHETIC-INCOMPLETENESS-R3-001
```

校验器语义：包装脚本的 argv 中，被校验的源码路径必须**恰好出现一次**。当前 7 包的命令源（wrapper
脚本）不满足该形状。

裁决路径（每包必须选一并登记，不得留空）：

```text
(a) 修包契约：改 wrapper 使源码路径在 argv 中恰好出现一次（如把路径从环境变量/配置文件
    提升为显式 argv，或消除脚本内的二次展开）。
(b) 修校验器假设：若该包的正当封装确实需要路径出现多次或以其它形式承载（例如 wrapper 固定
    调用固定路径、源码路径由 manifest 指定），则裁决校验器假设对该形状过严，改校验器并登记
    "假设放宽后的等价语义证明"（路径仍可被唯一解析为该包的源码）。
```

**(a) 与 (b) 的选择标准**：默认走 (a)；只有当 wrapper 的形状是**有意的设计**（如跨 kernel 的统一
入口必须固定参数顺序）且能给出等价唯一解析证明时，才走 (b)。走 (b) 时必须在
`CLAIM_EVIDENCE_MATRIX.md` 对应行登记校验器版本变化。

### 2.2 `LATER_DEPENDENCY_GAP_NOT_ALLOWLISTED`（6 项）

```text
MP-CUBICAL-MACHINE-HALTING-001
MP-CUBICAL-PROGRAM-CODE-001
MP-CUBICAL-NAT-PROGRAM-CODE-001
MP-CUBICAL-FAIR-ENUMERATION-001
MP-CUBICAL-SEMI-HALTING-001
MP-CUBICAL-MM2-BRIDGE-001
```

校验器语义：later package 依赖了**未登记在 allowlist 中的外部源树**（此处为外部 Cubical 源树）。

裁决路径：

```text
(a) 登记依赖：确认外部 Cubical 源树是真实构建依赖（非可选参考），把它加入该包的
    dependency allowlist，并登记其来源、版本/commit、路径与用途。
(b) 切断依赖：若该依赖实际未被构建使用（例如只是历史残留的 include path），从包的构建配置
    中移除，并登记移除不影响 kernel 结果的证据（重跑同包，收据一致）。
```

**注意**：(a) 必须附带"外部依赖的来源与版本固定"，否则 allowlist 会退化为无界白名单——
这与 003 片 §11 "无混入其它作者或未验收路径" 的要求冲突。

### 2.3 `LATER_SOURCE_HASH_DRIFT`（1 项）

```text
MP-CUBICAL-2LTT-FIBRANT-REPLACEMENT-UIP-001
  / 漂移对象：.codex/research/hott/LIT-HOTT-CO…（LIT 说明文件）
```

校验器语义：LIT（literature）说明文件更新后，未同步 manifest 中登记的哈希。

裁决路径：

```text
(a) 同步哈希：说明文件的更新是内容性更新（新文献、新判词），把 manifest 哈希更新为新值，
    并登记"旧哈希→新哈希"的变更理由与受影响判词范围。
(b) 回退文件：若更新是误编辑或格式漂移，回退说明文件到 manifest 记录的哈希对应内容。
```

选择标准：说明文件的内容更新是否已在 `LIT-DENOMINATOR-001.md` 中有对应记录。有则 (a)，无则
先补 LIT 记录再 (a)。

## 4. 完成判词

```text
EC_CONTRACT_CLOSED
  / later_packages 25/25
  / zero proof source modified
  / zero run receipt modified
  / verifier version changes registered（或 none）
```

允许的部分完成态（必须登记，不得静默）：

```text
EC_CONTRACT_PARTIAL_WITH_REGISTERED_GAP
  / closed: N / 25
  / open_gap: [package_id, error_code, blocking_reason]
```

## 5. 与 VC-001 的集成（对 003 片 §9 的最小修订）

003 片 §9 的六步流程顺序不变，只在**步骤 4 之前插入 EC-001**：

```text
0（新增）. EC-001：修复非 Git 类证据契约失配，达 25/25
1. git status --porcelain=v1 -uall 冻结完整路径与两列状态
2. 每个 proof package 枚举 source/run/index/dependency/source identity
3. 审计往返、baseline/meta、S-AUD 作为独立审计批次，不与数学包混交
4. 每批跑 closure verifier、link/hash、git diff --check
5. 精确 stage/commit，回读 tree 与路径
6. 只对实际进入 commit 的资产翻转 version status
```

**另外一项修订（A4）**：003 片 §9 步骤 5 的提交批次中，**第一批必须包含目标契约与全部审计文档**，
而非仅 proof package。第一批清单（精确路径 stage，非目录级）：

```text
goal.md
GPT的方案/HoTT机器统观后续工作方案.md
GPT的方案/HoTT机器统观后续工作方案/*.md          （10 片）

Atria的审计报告集/  Atria的方案/
```

理由：这是"让下一轮的执行前提可恢复"的第一步，而不是"保护 807 文件 Coq 归档"的附属动作。
A1 的 `ROOT_CAUSE_REGISTERED: TARGET_CONTRACT_NEVER_VERSION_CONTROLLED`（修订片 001 §5）
在此批次提交后才能翻转为 `RESOLVED_BY_VERSION_CONTROL`。

提交纪律沿用全局 Git 规范：`git diff --check`、精确 stage、回读 HEAD 与 tree、
不自动 push、不混入其它作者的 index。

## 6. 并行性与不阻塞项

- **EC-001 与 PSJ-001A 的只读部分不冲突**：PSJ 的九字段冻结、comparison pool 构造、来源分母
  建立都是只读/新建 TaskSpec 动作，不触碰 14 个包的 wrapper/manifest。可并行。
- **EC-001 与 GEN-001 不冲突**：GEN-001（修订片 003）在机器统观引擎上工作，与 proof package
  的证据契约是两条路径。
- **EC-001 阻塞 VC-001 的 commit 步骤，但不阻塞任何数学判词的产生**：PSJ/TGSQ 的判词可以先写，
  只是它们的版本闭合状态在 EC-001 + VC-001 完成前保持 `LOCAL_UNCOMMITTED_NOT_VERSION_CLOSED`。

## 7. 反解释与自我限定

- **校验器可能过严**：`LATER_COMMAND_SOURCE_MISMATCH` 的"恰好出现一次"假设对某些正当封装可能
  过严（§2.1(b)）。本工作包不预判责任归属，把它留给逐项裁决；但无论责任在包还是在校验器，
  14 项失配必须被显式裁决——留在原处只会让 VC-001 的失败被误读。
- **本工作包不声称修复了"证据已独立验证"**：003 片 §9 已写明"commit 只使 source-reported 记录
  可恢复；它不把原事件升级成已独立验证"。EC-001 同理：25/25 只证明 source→run→index 的
  三方绑定闭合，不提升任何数学结论的证据等级。
- **允许的失败**：若某外部 Cubical 源树的来源/版本不可固定，§3 stop 的 `EC_CONTRACT_PARTIAL`
  是合法终态，不是失败。把它写成"全部闭合"才是失败。
