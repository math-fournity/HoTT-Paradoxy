# 模块一设计RingOrigin与正控制

## 1. RingOrigin 的形式化选择（对照用户开火令）

| 用户概念 | 模块对应物 | 设计说明 |
|---|---|---|
| 「M 携带断点信息」 | `SourceCarrier C p = Σ (x:C), ¬(x≡p)` | 每点携带「不是断点」的排除证据；p 作为类型参数=来源记录 |
| 「来源携带是合法构造」 | `postulate-free-build` + `instance-witness`（ℤ 实例，pos1≢pos0 构造性） | 正控制：零 postulate、--safe——对照 TA 族（公设才卡住） |
| 「断点三件套可从 M 取出」 | `BreakoutFromM C p` + `breakout-witness` | 取出函数以 **p 为显式来源参数**——裸载体（无 p）上该类型无法陈述 |
| 「N 不携带」 | 参数化类型差异（`BreakoutFromM` 需要 p） | 不可定义性的 ∀ 证明**未做**（需元层/函发性论证，本模块无 ∀ 主张——下一单元义务） |

## 2. 设计裁量与理由

- **不建模 (0,1)/S¹ 的完整点集拓扑**（Astra 002 片纪律：HIT S¹ 不冒充点集圆；
  点集全建模是后续单元）。`SourceCarrier` 对任意 C/p 参数化——先立「来源
  携带 vs 裸载体」的类型学区分，几何实例化留后。
- **`¬(x≡p)` 而非更丰富的断点记录**：最小起步。断点三件套的完整形态
  （两端点+断点的相互关系）需拓扑结构（邻域/序），是下一层。
- **不证不可定义性**：「N 上不可取出」的证明需要论证「p 无法从 N 的数据中
  构造」——这本质上是**信息论陈述**（N 不携带 p），在类型论内的正确形态
  可能是函发性/参数性论证或更精细的 universe 层构造，需专门设计。

## 3. 下一单元（UNIT-2）候选（待用户/后续裁定）

1. **不可定义性证明**：参数化多态下的「p 不可构造」——尝试 free-theorem
   风格或 universe 级分离；
2. **真实消费者狩猎（G1 的圆环版）**：在 HoTT 语料中找「使用去点/补点对象
   而未携带来源」的位置——检验「植入」假说；
3. **GOLD/断点连接**：把 √2 cut 的 L/U 谓词重新表述为 SourceCarrier 形态
   （L q 蕴含「q 不是 √2 的有理位置」的排除证据——打通圆环线与既有 ℝ 层线）；
4. **Astra 策略 AST-X-RING 的点集模型资格化**（若用户要求全面性）。
