# 研究层：业务 Skill、三问、FRONTIER、LESSONS、RESUME

（research profile 的条件性必读——只在研究类会话全文加载，合计 ≈84,127 tokens）

## 1. `.codex/skills/hott-paradox-research/SKILL.md`（32.9KB / ≈10,400 tokens；v1.9）

**作用**：业务研究方法论合同。二十节：执行先恢复来源与记忆、执行合同、
范围与权限先判定但不做无限准备、三层认知闭包、**主动生成而非只审计旧候选**、
自主调度前沿、实际研究循环、已有线索的正确下一步、证据/实验/形式化、
候选多轴状态、接续与交付、验收边界、独立思考与动态记忆边界、
以及 v1.3→v1.9 的六次历史目标澄清（版本沿革即研究方法进化史）。

**目的**：防研究的两种退化：(a) 退化成**无限准备**——永远在审计历史、
建索引、不产出新数学（§1"不重做无限准备"、§3"主动生成"就是针对这个）；
(b) 退化成**无方法漫游**——没有候选状态、没有验收边界的碰运气。
它同时是"研究 Should 层"：什么算一个好候选（多轴状态）、什么算一次有效推进。

**原理**：方法论 Skill 化（把研究 SOP 变成宿主可路由的合同）+ 章节化的
**决策点结构**（每个环节都是"判定规则+停止条件"，不是原则陈述）。
版本沿革节把每次方法论修正的原因留在正文里（如 v1.7 加数学门禁、
v1.9 加程序化完备性）——方法论自身的可审计演化。

## 2. `HoTT/HoTT研究三问-找什么-怎么找-凭什么-20260909.md`（38.4KB / ≈12,378 tokens）

**作用**：研究纲领原始文档——四部分系统回答"在 HoTT 中找什么（悖论的形状）、
怎么找（方法）、凭什么找（依据）"，加综合判断与来源边界。它本身是 KC-000001
（用户要求"最深刻、最通透、最人话"的三问论述）的历史产物。

**目的**：**问题意识锚**。每次研究从"为什么做这件事"出发，而不是从"上次做到
哪"出发。它是 core（用户之问）与研究执行（AI 之作）之间的第一份桥梁文档。

**原理**：纲领全文常驻。值得注意其自我定位（末节"来源、阅读边界与文档职责"）：
它明确自己是 2026-09-09 时点的回答、有阅读边界——即它是**被治理的历史交付物**
而非永恒真理；research_full 层全文加载它，买的是"每轮研究都能回望最初的
问题意识"，与 core 的关系是"原文（问）→纲领（答）→后续研究（做）"的三级链条。

## 3. `.codex/research/hott/FRONTIER.md`（37.3KB / ≈13,000 tokens）

**作用**：研究前沿滚动快照——当前各线（R3/R4、T3、GEN-001 族、PREMISE-001
步进…）推进到哪、下一步是什么。标题直接带最新里程碑（S151…）。

**目的**：防"重复已做"与"不知道下一步"。方向追踪投影的是**方向全景**，
FRONTIER 聚焦**当前最前沿的细节状态**（粒度到步/族/判词）。

**原理**：单文件滚动更新（每次里程碑改写标题与正文）。代价机制：滚动文档
天然膨胀（历史里程碑不舍得删），105KB 级的 RESUME 同病。它没有采用分片+
归档的容量模式，是研究层里层内结构最"传统"的一件。

## 4. `.codex/research/hott/LESSONS.md`（60KB / ≈20,000 tokens）

**作用**：经验教训库——交接阶段起累积的"哪些做法错了、为什么、以后怎么办"
（证据卫生、口径先行、审计方法…）。

**目的**：防"错误重犯"。姊妹记忆里的"十轮淬炼可迁移纪律"（observed_at+command
计数、否定性主张同等 grep、锚点分母 remainder=0…）就沉淀在这里。

**原理**：教训累积+常驻。**机制张力最尖锐的一件**：教训的价值在"遇到对应情境
时想起来"，而全文常驻的支付在每轮。20,000 tokens 买"每轮重读全部历史教训"，
其中大部分与本轮任务无关。它是最典型的应该"索引+情境水合"化的文档——
而框架在 STATE 水合上已经证明会做这件事。

## 5. `.codex/research/hott/RESUME.md`（105KB / ≈33,000 tokens）

**作用**：接续手册——"每个新 Session/压缩后的固定恢复"节 + 多个"当前停止点"节
（历史上每次停机追加，未删旧节）。

**目的**：最小成本恢复——理论上这是"新会话第一件该读的东西"，比四件套更短平快
的续接入口。

**原理**：固定恢复流程+停止点快照。**实测诊断**（姊妹报告）：它的"停止点"节
从不清理，105KB 里大半是历史停止点的层层叠叠；且其职责与 MEMORY/001（队列）、
FRONTIER（前沿）、STATE.latest（指针）四方重叠——同一"现在在哪"信息有四个
半权威版本。它本应是 research 层最便宜的一件（设计目标就是省），现在是最贵的一件。

## 6. 研究层五件合并的机制定位

| | 业务Skill | 三问 | FRONTIER | LESSONS | RESUME |
|---|---|---|---|---|---|
| 回答 | 怎么研究 | 为什么研究 | 推进到哪 | 什么坑 | 怎么恢复 |
| 原理强度 | 方法合同化 | 纲领锚定 | 滚动快照 | 教训常驻 | 恢复手册 |
| 容量病灶 | 与治理Skill复述重叠 | 无（历史定本） | 滚动膨胀 | 全量常驻 | 停止点叠层+四方职责重叠 |

**三问总结**：作用=研究方法论/纲领/前沿/教训/恢复五位一体的"研究记忆"；
目的=防无限准备、无方法漫游、重复劳动、错误重犯、恢复失据；原理=Skill 化
合同+纲领常驻+滚动快照。研究层的机制水平参差：业务 Skill 与三问设计良好
（合同化/定本化），FRONTIER/LESSONS/RESUME 三件停留在"滚动文档"的前治理
形态，是 research profile 84K 开销中的主要可优化部分（姊妹报告 G4）。
