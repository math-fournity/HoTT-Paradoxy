# 合同层：PROTOCOL、LOAD_SET、SKILL_ROLES 与本地治理 Skill

## 1. `.codex/cognition/PROTOCOL.md`（16KB / ≈4,939 tokens；`handoff-cognition/v2.6`）

**作用**：当前执行合同——治理框架的"操作系统正文"。七节：真值源分层表（哪层
事实归哪个 owner）、每次开始的硬步骤（8 步）、核心认知账本使用规则、四件套交叉
审视与更新归属表（什么新事实改哪个文件、明确不许改哪个）、分片读写规则、
结束时的逐编号回评格式、写入与 checkpoint 事务规则、失败/未知/停止条件。

**目的**：把"怎么做一个合格的会话"从 AI 的临场判断变成**可审计的算法**。
它防的是治理里最隐蔽的失败：不是不读文档，而是读了以后**按自己的习惯重组流程**
（先干正事再补闭包、用摘要替代、冲突时写"最新版"覆盖）。PROTOCOL §2 的八步
顺序本身是防伪设计：先闭包→再交叉→再动作，使"没闭包就动作"在时序上可见。

**原理**：算法化会话生命周期（机制 2）+ 更新归属表。归属表是本框架最有特色的
机制：每类新事实（用户新意识/新候选/新结果/稳定知识/冲突）映射到唯一应改与
唯一不应改的文件——这是"事实类型分权"（机制 4）的操作化，防的是**真值源增殖**
（同一事实写进多个文件后互相打架）。代价是表本身要随 owner 演化维护（漂移清单
里的 gen-4/7 冲突就是归属表执行不彻底的产物）。

## 2. `.codex/cognition/LOAD_SET.json`（5.7KB / ≈1,498 tokens；`cognition-load-set/v4`）

**作用**：机读加载清单——把全部治理文档按消费方式分层（always_full_documents /
always_full_boot / research_full / query_first / task_expand / archive_verify_only），
声明 profile 策略、记录关系语义（depends_on 递归水合 vs research_parent 不水合）、
checkpoint 必备件、分片合同参数。

**目的**：让"读什么"成为**数据**而非散文，从而可被机器强制执行和校验。
散文宪法只能请求，机读清单能被 `cognition_runtime.py graph()` 逐项展开、
对每片 hash、缺片即 BLOCKED——这是把"全文义务"（防 F3 摘要失真）从道德要求
变成技术事实的唯一接口。

**原理**：声明式配置 + fail-closed 执行（机制 3/5）。注意它同时是**容量原理的
枢纽**：query_first/task_expand 两层就是"不常驻、按需水合"的制度化。
姊妹报告的核心发现（STATE 放错层）用本分片的语言说就是：**最大的账本被
声明在了最小的层**。LOAD_SET 本身没有缺陷，缺陷是数据填错了层。

## 3. `.codex/skills/SKILL_ROLES.json`（911B / ≈240 tokens；`hott-skill-roles/v2`）

**作用**：三角色名册——governance（hott-local-session-governance）、business
（hott-paradox-research）、execution（hott-paradox-search-sop），声明入口是 AGENTS.md、
宿主不假定自动发现、治理与业务同一次调用不递归重启。

**目的**：防路由歧义与无限递归。历史上 WebGPT 治理→业务→治理保存的设计曾在
跨 Skill 调用时产生"重新启动自己"的循环风险；名册把"谁在什么角色、从哪进、
何时算同一次调用"钉死。

**原理**：唯一名册 + 显式 entry（机制 4 的路由版）。它小到几乎无成本，
是框架里性价比最高的一件：用 240 tokens 买掉一整类循环/错路由故障。

## 4. `.codex/skills/hott-local-session-governance/SKILL.md`（19KB / ≈5,833 tokens；v3.7.0）

**作用**：治理角色的完整 SOP 正文——本框架的"操作手册"。八节：角色与唯一入口、
根与权限与来源边界、开始时四件套全文闭包 8 步（含 BLOCKED_FULL_SET_COGNITION
停止协议）、核心认知语义纪律、结束时的分片审计集格式（五元组/relation 词表/
反证条件强制）、系统化完备性回评、历史 AI 覆盖分母（LocalGPT 38 turns/220 条、
WebGPT 56P/55R、Gemini 各计数）、写入/checkpoint/恢复规则、停止与负结论。

**目的**：把治理做成**宿主可路由的 Skill**，获得两个普通文档没有的性质：
(a) Skill 机制的路由优先级（命中即全文加载）；(b) 与业务 Skill（hott-paradox-research）
形成明确的角色分工——治理先行、业务随后、同一次调用。它同时是停止协议的
承载者：容量不足时显式 `BLOCKED` 而非静默降级（ruling §11 用户原意的落实）。

**原理**：复用宿主 Skill 机制承载治理（机制 1 的扩展）+ **反证条件化的审计格式**
（机制 10 的强化：每条 KC 的 relation 判定必须带"什么证据会推翻这个判定"，
使审计本身可被证伪而非表演合规——SKILL §5.2 明言"把 46 条全写成 ALIGNED 的
审计，即使格式合规，仍是失败审计"）。这是整套框架里认识论上最锋利的一条设计：
它承认 AI 的自我评估不可信，于是要求自我评估自带推翻条件，供外部审计复查。

**实测的代价**：其 §4/末尾同样写死 generation-4/36（已过时两代），是复述原理
的又一处漂移样本；19KB 的体积使它自身成为启动核第 4 大件——一个"讲如何省
上下文的文档本身花 5,833 tokens"的自指现象（其内容约 60% 与 PROTOCOL/AGENTS
重叠，三份文档互相复述）。

## 5. 合同层四件的三问总结

作用=把会话生命周期、加载义务、路由角色、停止条件全部**合同化+机读化**；
目的=防"读了但没照做"与"做错了不知道错在哪"（治理从请求变成可执行、可审计
的算法）；原理=声明式数据 + fail-closed 执行 + 名册化路由 + 可证伪的审计格式。
这四件是框架中真正独创的部分——市面上常见 AGENTS 宪法，罕见"宪法→合同→
机读清单→runtime 强制"的完整链条。
