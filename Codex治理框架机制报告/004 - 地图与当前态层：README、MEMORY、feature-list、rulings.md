# 地图与当前态层：README、MEMORY、feature-list、rulings

## 1. `README.md` 逻辑文档（索引+4 片，≈8,235 tokens）

**作用**：资产地图与入口导览。四片分别覆盖：当前入口与关键文件（工作链路图：
用户原始提问→sources→核心认知→理解章节→HoTT/审计）、历史交接包说明、
加载方案与验证入口、增量交换/归档恢复/接手继续。

**目的**：防 F1 的空间维——新会话**知道仓库里有什么、每块是什么身份、从哪进**。
地图的价值在"不知道自己不知道什么"的时刻：AI 不需要找文件，需要知道存在哪些
类别的文件。README/001 的工作链路图是这个 repo 独有的需求（普通 repo 的链路
是代码→构建，这里的链路是**认知流**：原文→账本→理解→证据）。

**原理**：地图与真值分离（地图只路由不承载数据）+ v2 分片保持可维护。
实测漂移同前：001 片写死 generation-4/89 消息——地图嵌身份事实的过时样本。

## 2. `MEMORY.md` 逻辑文档（索引+3 片，≈39,716 tokens；sequential，append_target=003 片）

**作用**：当前工作记忆。001=当前执行队列（原位更新）、002=当前证据上限与恢复入口、
003=当前验证状态**顺序日志**（S023→S176 逐会话追加，现为 218 行/≈27,551 tokens）。

**目的**：防 F1 的时间维——跨会话回答"现在在哪、刚做完什么、下一步是什么"。
三片是有意分层：队列（要做的）原位改、上限（能确信的）原位改、日志（做过的）
只追加。append-only 日志的目的是**时序可审计**：谁在什么时候宣称了什么状态，
有顺序证据链，不可回改。

**原理**：队列/边界/日志三职分离 + append-only。**但它是容量原理缺位的重灾区**
（姊妹报告 P4）：顺序日志在 always_full_boot 层，追加越勤勉、启动越贵，
最终 003 片一家占启动核 9.2%。它的机制目的（时序证据）本不需要每轮全文重读——
历史日志的消费者是"需要回溯时的 AI"和外部审计，不是"每次启动的 AI"；
需要的只是尾部 N 条 + 索引。这是"层归属按写入习惯而非消费方式定"的典型错配。

## 3. `feature-list.md`（10.8KB / ≈3,190 tokens）

**作用**：当前需求状态 owner。16 条 F-001–F-016，每条四段：需求陈述、
当前状态（如 `MECHANICALLY_VERIFIED_VERSION_CLOSED_FRESH_MODEL_BEHAVIOR_NOT_RUN`）、
证据/下一步（SRC/DES/IMP/VER 四类证据定位）。

**目的**：防两种需求侧失败：(a) 历史 AI 的"已完成"冒充当前需求还在（ruling §16
的"修正过时入口"）；(b) 需求漂移无迹——需求怎么从"三件套"变成"四件套"、
从"审计历史"变成"程序化探索"，每步有据。

**原理**：需求 ID 化 + 四段证据状态。注意其状态词表本身就是 F5 防御：
`IMPLEMENTED ≠ VERIFIED ≠ MECHANICALLY_VERIFIED ≠ VERSION_CLOSED`，
且普遍后缀 `FRESH_MODEL_BEHAVIOR_NOT_RUN`——把"文件都对但模型没试过"这个
最容易被忽略的缺口钉在每条需求的状态里。这是"证据分级"落到需求管理的一例，
机制上非常成功（16 条需求的证据链全部可点验）。

## 4. `rulings.md`（16KB / ≈5,094 tokens）

**作用**：立法记录——24 条编号裁定 + 5 段用户原文引用块。内容覆盖：repo 定位
（§1）、核心原文边界（§2/§3/§12）、四件套语义（§8/§10/§19）、精简红线（§11：
"只能移除三件套之外的……不得压缩、摘要、选择性加载"）、数学门禁（§15）、
审计处置授权（§16）、分片两波（§17/§18）、单工作面（§22）、第三条发现路径（§24）。

**目的**：防"AI 推测用户意图"。用户原意在本框架里是一手数据——所有机制的
合法性都追溯到这里（LOAD_SET 的层定义来自 §8–§19，数学门禁来自 §15 原话，
四件套来自 §19 选 A）。没有 rulings，整套框架就是 AI 的自我加戏；
有了它，框架是用户的定购仪器。

**原理**：逐条编号 + 用户原文逐字引用（`~~~text` 块）+ 开头一句反冒充声明
（"历史 AI 的建议、推测和旧状态不写成用户裁定"）。**它是全 repo 唯一
"复述零漂移"的多处引用源**——因为人人引用它、它不引用别人，处于引用链
的根位置。这个观察有一般价值：**复述的安全方向是自底向上（引用权威），
危险方向是横向平级复述（宪法互抄）**。

## 5. 四件合并的机制定位

| | README | MEMORY | feature-list | rulings |
|---|---|---|---|---|
| 回答的问题 | 有什么 | 在哪/下一步 | 该做什么/做到哪 | 为什么是这样 |
| 失效模式 | 地图过时 | 日志无界 | 状态词膨胀风险 | （引用根，稳） |
| 层归属合理性 | 合理 | 003 片错配 | 合理 | 合理 |

三问总结：作用=空间地图/时间记忆/需求账本/立法记录；目的=分别防"不知道有什么"、
"不知道在哪"、"该做的漂移"、"意图被推测"；原理=职责分离+ID 化+原文引用+
append-only（其容量副作用见姊妹报告）。
