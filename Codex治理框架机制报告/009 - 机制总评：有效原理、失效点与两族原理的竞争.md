# 机制总评：有效原理、失效点与两族原理的竞争

## 一、被证据支持的原理（真正起作用的部分）

1. **证据分级 + 机器证明门禁（F5 防御）**：仓库现存 17 个冻结 + 25 个 later proof
   package（feature-list F-011），全部判词带作用域（`MACHINE_PROVED_LOCAL_COMMITTED_
   NOT_PUSHED`、`KERNEL_ACCEPTED_WITH_SCOPE`、`registers_new_claim:false`）。
   MEMORY/003 的逐轮记录显示判词纪律被严格执行到工程验收层（连"能力验收，
   不是数学结论"都逐轮复读）。**在本 repo 的全部机制里，这条的执行率最高、
   零已知冒充事件**——原因：它把"结论"的交付条件锚在 kernel 退出码这种
   模型无法伪造的外部事实上。
2. **fail-closed**：两次实战拦截——(a) 姊妹报告 P1（RESUME 直接提交后
   `UNCOMMITTED_STATE` 阻断 plan）；(b) MEMORY/001 第 15 条自记的 revision 160
   事件（out-of-band commits 导致 plan BLOCKED、HEAD.tracked 漏文件，161 修复）。
   机制在真实漂移面前**真的说不**，而不是装饰。
3. **依赖语义三分 + 显式水合（容量原理的胜利）**：F-012 记录 task plan 从
   3.68–29.42MB 降到 0.84–0.93MB（≈97% 减容）——拆掉叙事性 depends_on 递归、
   装上 query-first 水合的 direct 战果。**框架自己最成功的一次瘦身，用的正是
   它现在最缺的那把刀**。
4. **hash 锚定的代际机制**：核心认知七代演进全有 transition receipt，旧代
   PRESERVED_EXACT；投影的 `source_state_revision` 让投影-基线漂移可检测。
5. **审计分片化（020 合同）**：每轮审计从 ≈13 万 tokens 降到 1.4–3.4 万——
   框架对自身写作义务的一次成功减重，证明"义务可以瘦身而证据性不塌"。
6. **latest+active 增量续接**：全部历史不可见是失忆、全部可见是爆炸，
   这个中间解是框架里被正确实现的增量模式。

## 二、失效或负效的原理（本次两项调查的合并证据）

1. **全文重付遇上无界增长 = 物理不可满足**：governance 413K / research 497K
   超过多数窗口 → 会话被迫在"违反合同"与"做不了事"之间选择 → S170–S176 选择
   绕过（P2）→ 绕过制造收据缺口 → **防漂移机制的重量制造了它本来要防的漂移**。
   这不是执行不力，是机制只建了一半：有保真义务，没有退休通道。
2. **横向平级复述**：generation-4/7 冲突存在于根 AGENTS、本地治理 Skill §4/§8、
   README/001、扩展认知 baseline 至少四处——每处复述都要人同步，同步率实测
   低于 50%。复述防漏的收益 < 一致性成本（002 分片的平方增长规律）。
3. **叙述性五重复制**：同一判词在 STATE 记录、SESSION.md、MEMORY/003、投影行、
   审计集各写一遍，五处措辞各异需人工对账（S-174 索引 panorama_change=YES 与
   事实不符即其症状）。
4. **滚动文档无退休**：FRONTIER/LESSONS/RESUME/MEMORY-003 四件"越勤勉越贵"
   的滚动体，与 append-only 证据性目的部分错配（时序证据不需要每轮全文重读）。

## 三、两族原理的竞争史（本报告的核心论点）

把 001 的两族原理放到时间轴上：

- 框架每次存活，都是**容量原理**的一次胜利：三件套投影化（不直接读原始
  对话录）、F-012 水合改造（-97%）、020 审计分片（-90%）、manifest 降层
  （43K 移出启动核）。
- 当前危机，是**保真原理**在三个点无界应用的结果：STATE 全文常驻、
  压缩后全额重付、不变量平级复述。

而核心认知证明：**保真与容量可以不冲突**——它保真要求最严（逐字、hash、
禁手改），却是启动核里纪律最好、体积最稳的文件（12K/七代/零失控），
因为它同时具备三个姊妹件缺的东西：单文件收窄写路径、generation 退休机制、
元数据降层。**问题从来不是"要保真还是要容量"，而是保真义务是否配对了
容量配套**。

保真原理的正确完成形态不是字节重付，而是**可验证的持有证明**：hash 锚定
（已有）+ 带反证条件的复认（020 审计已发明）+ fail-closed（已有）。
框架手里已经握着全部零件——它需要做的，只是把 F-012 证明过的那把刀，
挥向自己剩下的三处全文义务。这就是姊妹报告 G1–G7 建议的机制学根据。

## 四、对用户原始三问的一句话总答

- **作用**：把一个跨年度、跨会话、跨三个 AI 平台的研究 program 变成可继续、
  可审计的状态机——每份必读文档是状态机的一个部件（宪法/合同/地图/记忆/
  立法/原文权威/投影/账本/研究记忆）。
- **目的**：防御 AI 会话的五种固有失败——无记忆、训练先验、摘要失真、
  历史冒充当前、结论膨胀（外加横切的容量约束）。
- **原理**：十项机制归两族——保真（注入、全文、hash、fail-closed、机器门禁）
  与容量（分层、水合、投影、双状态轴、退休）。当前成本危机不是设计错误，
  而是保真义务在三个点没有配容量配套导致的机制未完成；修复路径不是放弃
  保真，而是把保真从"重付字节"升级为"可验证的持有证明"——这条路径的
  每个零件，框架都已在自己历史上的成功战役里造出来过。
