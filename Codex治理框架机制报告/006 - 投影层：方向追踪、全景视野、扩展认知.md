# 投影层：方向追踪、全景视野、扩展认知

## 1. `方向追踪.md`（索引+5 片，≈13,786 tokens；`integrated-direction-portfolio/v1.12`）

**作用**：方向组合与统筹的**人类可读投影**——DIR-* 方向行（治理/用户/LocalGPT/
WebGPT/证据覆盖五族）、交叉审视合同、优先级与停止边界、更新规则。索引里的
身份 marker 块（`source_state_revision: 169`、`projection_generation:
20260917-direction-169`、`semantic_status`）把投影钉在 STATE 基线上。

**目的**：防"隧道视野"。ruling §10（用户原意）："使 AI 始终纵观全部历史分支和
未来候选，从而在每次新发现后回望全历史、重估全方向并智能统筹下一工作。"
——研究的敌人是局部优化：新会话很容易顺着最近一条线索走下去，而用户要的是
每轮都把全部方向拿出来重新统筹一遍。

**原理**：**投影（projection）**——从机器账本（STATE）派生出可读视图，但明确
"不是 STATE 的替代品"（索引首段自declares）。为什么需要投影而不直接读 STATE？
因为 STATE 是机器格式（记录身份/hash/依赖），人机都不适合通读；投影把同一数据
组织成"方向→候选→下一判别动作"的决策视图。身份字段保证投影与基线的一致
可校验（revision 漂移即 `REVIEW_REQUIRED`，PROTOCOL §2.6 的三方交叉检查）。
分片后行族分片（DIR-G/DIR-L/DIR-W…）+ 表头唯一重复 + 逐行对账。

## 2. `全景视野.md`（索引+8 片，≈41,857 tokens；`integrated-outcome-panorama/v1.12`）

**作用**：结果、正反例、失败、未知的**对称全景投影**——OUT-* 结果行
（MP 证明包/距离综合/证据抽样/T3 脉冲失败台账/历史来源结果/当前未完成）。

**目的**：与方向追踪对称的另一半：防"只记得成功"。索引规定每条结果必须同时
回答七个问题：做了什么/理论配置/证据属纸笔-代码-一次运行-全域-现实哪层/
正向控制与反解释/对应哪些方向/证据在哪/哪些仍未运行——**把证据分级强制到
每一条结果行**（F5 防御的投影版）。006 片整个是失败台账、008 片整个是
"当前未完成"——失败与未知的显式保留是本投影的招牌特征。

**原理**：同投影机制 + 七问结构化。姊妹报告指出其 41,857 tokens 为四件套
最大件——机制诊断：投影的**行空间随结果数单调增长**（每个新结果一行），
而"回望全部结果"的消费需求其实分层（当前活跃结果 vs 冻结/历史结果）。
这是投影层下一个该做 hot/cold 拆分的地方（方向追踪同理但规模小一半）。

## 3. `扩展认知.md`（索引+8 片，≈32,812 tokens；`essay-role:v1`，AI_EXPOSITION_LAYER）

**作用**：AI 阐释层——把 46 段用户原文按**思想关系**（而非时间编号）连贯成
一篇可进入的文章：问题意识→理论简化→前提与时间→芝诺/圆环/ASK→两种方向→
HoTT 与理论自反→表达界限→第三条发现路径→AI 数学的助力/阻力→现实对齐。
引文=用户完整原话逐字保留；引文之间=AI 撰写的解释性展开。

**目的**：解决账本的可进入性问题。ruling §19：用户审阅后说"甚至我们要从三件套
升级到四件套"并选方案 A。账本（核心认知）保真但按时间平铺——第 3 条与第 41 条
的思想关联要靠读者自己重建；阐释层把"原始思想能够被连续理解、重新思考和用于
发现"变成常驻输入。它服务的还是 F2：不仅注入原文，还注入**原文之间的结构**。

**原理**：**双层文本+角色声明隔离**。权威隔离靠三重机制：marker 块
（`role: AI_EXPOSITION_LAYER / authority: NOT_USER_ORIGINAL`）、索引自述
（"核心认知.md 仍是唯一用户原文权威"）、审计字段（`essay_change=YES` 永不提升
为原文/数学结论）。展开文字"不把原话中的强判断擅自升级为新定理，也不借证据
边界把其研究锋芒消解掉"（双向禁令：既防膨胀也防稀释）。原文变化时必须按新代
重新检查覆盖（baseline 字段钉住所依据的 generation——当前标 generation-4，
实际引 generation-7，又一处待同步的基准字段）。

## 4. 投影层三件合并的机制定位

| | 方向追踪 | 全景视野 | 扩展认知 |
|---|---|---|---|
| 投影对象 | STATE 的方向/候选记录 | STATE 的结果记录 | core 的 KC 原文 |
| 视角 | 前瞻（下一步做什么） | 回顾（已得到什么） | 内向（思想本身如何连贯） |
| 防 | 隧道视野 | 只记成功 | 账本不可进入 |
| 独有机制 | 交叉审视合同 | 七问+失败台账 | 角色声明权威隔离 |
| 容量病灶 | 行单调增长 | 行单调增长（最大件） | baseline 漂移 |

**三问总结**：作用=从机器账本派生出决策视图/证据视图/思想视图三种可读投影；
目的=防隧道视野、只记成功、思想不可进入（F2/F4 的投影层防御）；原理=投影与
真值分离+身份字段锚定+结构化行格式+权威角色隔离。投影是容量原理的好设计
（视图按需重组），但"投影本身进 always_full 层且行空间无界增长"使它成了
保真原理的载体——这就是它既是好设计又是第二大开销的原因。
