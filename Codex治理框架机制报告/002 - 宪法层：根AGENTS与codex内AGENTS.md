# 宪法层：根 AGENTS 与 .codex 内 AGENTS.md

## 1. 根 `AGENTS.md`（19,329B / ≈6,016 tokens，always_full_boot）

**作用**：项目的宪法与总路由。它定义：工作根与来源边界（哪些目录是什么身份）、
启动闭包的固定顺序（读什么、按什么序）、研究与证据纪律（六种状态不得互相冒充）、
四项大合同（程序化完备性探索、数学证明门禁 `MATH_PROOF_BEFORE_DELIVERY_V1`、
分片索引 `GOVERNANCE_SHARD_INDEX_V2_PROJECT_V1`、写入/Git/交接规则）、
Sub Agent 禁令（用户 2026-09-17 裁定）、任务路由表（什么任务加载什么 Skill）。

**目的**：防御 F1（无记忆）的入口版——保证任何新会话的**第一步**就落在治理路径上，
而不是 AI 自由发挥后再补救；同时防御越权（push、Sub Agent、改历史来源）。
宪法放在 AGENTS.md 而不是普通文档里，是因为宿主（Codex）**自动注入** AGENTS——
这是唯一不依赖 AI 自觉读取的加载通道。

**原理**：宿主注入（机制 1）+ 指针宪法。细读其结构会发现它几乎不承载"状态"，
只承载"规则 + 指向 owner 的指针"（如"当前核心身份必须从 STATE.current_core 动态取得"）。
这是刻意设计：宪法要稳定，状态放权威源，才能避免宪法过时。
**但实测它没有做到纯粹指针化**：正文写死了"generation-4/36 KC"，而权威 STATE 已是
generation-7/46——宪法嵌事实的那几行成了最先过时的部分（姊妹报告 P3）。
这是"复述不变量"原理（把关键事实在多处复述以防漏读）的固有代价：每复述一处，
就多一处要同步的位置。

## 2. `.codex/AGENTS.md`（4.4KB / ≈1,357 tokens，always_full_boot）

**作用**：`.codex` 目录的治理入口与硬不变量清单：四件套 invariant（固定顺序全文、
三者职责不得互相覆盖）、分片 invariant（索引+全部分片=全文）、核心 invariant
（generation/KC 分母动态取得）、record 关系 invariant（depends_on ≠ 谱系）、
checkpoint invariant（原子三件套 + result.json 唯一收据）、数学门禁指针。

**目的**：把散落在 PROTOCOL/LOAD_SET/Skill 里的**最硬的几条不变量**在离目录入口
最近的地方再复述一遍——防"AI 读合同读到一半漏掉关键禁令"。它是对根 AGENTS 的
局部放大镜，服务于同一目的（入口防走偏）。

**原理**：冗余复述（保真原理的典型应用）。判断依据是：它 90% 的内容在别处有权威版本，
自身定位是"摘要复述+指针"。**机制代价可实测**：它比根 AGENTS 新（已同步 generation-7/46），
于是两份宪法在核心事实上互相矛盾（4 vs 7 代）——复述没有防住漏，反而制造了
需要消解的冲突；PROTOCOL 里"冲突按事实类型/版本/时间消解"的规则正是为此类
情况准备的补救条款。这印证了一个一般规律：**复述式不变量的收益随文档数递减，
一致性成本随文档数平方增长**。

## 3. 两件合并的机制定位

| | 根 AGENTS | .codex/AGENTS |
|---|---|---|
| 加载方式 | 宿主自动注入 + 显式读 | 启动闭包显式读 |
| 内容 | 规则+路由+边界 | 不变量复述+指针 |
| 失效模式 | 嵌入事实过时 | 与根版本冲突 |
| 不可替代性 | 高（唯一注入通道） | 低（可被 PROTOCOL 索引替代） |

**三问总结**：作用=宪法+路由+不变量复述；目的=把会话第一步钉进治理路径、
防越权与防漏读关键禁令；原理=宿主注入的强制性 + 指针化保持稳定 + 复述化防漏
（后者已产生实测的反效果，是瘦身候选）。
