# 总论：框架防御的失败模式与两族原理

## 一、这套框架到底在治理什么

普通软件 repo 治理的对象是**代码与构建**；本 repo 治理的首要对象是**认知**——
一个跨三个 AI 平台（LocalGPT/WebGPT/Gemini）、跨 dozens 个会话、以"寻找 HoTT
非现实性悖论"为目标的长期研究 program。AI 会话有五种固有失败模式，全部在
rulings/PROTOCOL/AGENTS 里有对应的显式防御条款：

| # | 固有失败 | 表现 | 框架的防御条款（例） |
|---|---|---|---|
| F1 | **无记忆** | 新会话/压缩后不知道项目在哪、做过什么 | 四件套全文重付、STATE、RESUME、MEMORY |
| F2 | **训练先验** | 模型用训练数据里的 HoTT 常规认知覆盖用户的非常规思想 | 核心认知.md（ruling §9 用户原文：上下文工程） |
| F3 | **摘要失真** | "我记得/摘要说"替代原文；压缩后走样 | 全文到 EOF、hash 对账、`NOT_CERTIFIED_BY_TOOL` 诚实声明 |
| F4 | **历史冒充当前** | 旧会话的"已完成/已证明"复活成现在时 | lifecycle/evidence 双轴、`historical_session_auto_load=false`、投影身份字段 |
| F5 | **结论膨胀** | 把"代码存在/跑过一次/AI 自称"说成"已证明" | F-011 数学证明门禁、证据分级词表、判词纪律 |

另一个横切失败是**容量**（上下文有限 vs 认知资产无限增长）——它不是被防御的对象，
而是所有防御机制必须在其中运行的约束；这正是姊妹报告测出的成本危机。

## 二、十项机制原理总目（后文逐文档对号）

1. **宿主注入**：宪法放 AGENTS.md，由宿主每会话自动注入，不依赖 AI 自觉。
2. **算法化会话生命周期**：PROTOCOL 把"开始 8 步 / 结束审计 / checkpoint"变成合同步骤。
3. **声明式加载清单**：LOAD_SET 把"读什么"变成机读数据，runtime graph() 强制展开、fail-closed。
4. **事实类型分权**：每类事实唯一 owner（裁定→rulings、需求→feature-list、状态→MEMORY/STATE、
   方向/结果→投影、用户原文→core），冲突按类型消解，不许"最新版覆盖"。
5. **全文重付 + 字节级对账**：四件套每次会话/压缩后全文读；read_chunk/check_coverage
   证明"发射的每个字节与文件 hash 一致"。
6. **hash 锚定的派生关系**：manifest/curation/投影的 `source_state_revision`、
   `projection_generation`、`core_sha256` 把派生物钉在基线上。
7. **双状态轴**：STATE 把"任务资格"（lifecycle）与"证据可信度"（evidence）分开，
   防待复核历史自动复活。
8. **显式水合（query-first）**：大账本不常驻，按 stable record ID 显式展开证据。
9. **机器证明门禁**：数学结论交付前必须有 kernel 运行收据（F-011）。
10. **逐编号回评**：每轮结束对全部 KC 留下带反证条件的关系判定（审计集）。

这十项可归为两族：

- **保真原理**（1/5/6/9 及复述式不变量）：宁可多付上下文，不许失真。
- **容量原理**（3/4/7/8 及分片/投影）：宁可多一层间接，不许爆仓。

两族的张力是理解每份文档形态的钥匙（009 展开）：框架历史上每一次存活下来，
都是容量原理的一次胜利（水合、分片审计、投影化）；而当前的成本危机，
是保真原理在三个点上无界应用的结果（STATE 全文、压缩重付、复述不变量）。

## 三、必读文档的分层图（谁在哪一层，为什么）

```
宿主注入层    根 AGENTS.md（宪法+路由）
启动核        README(地图) MEMORY(当前态) feature-list(需求) rulings(立法)
              .codex/AGENTS.md PROTOCOL LOAD_SET SKILL_ROLES 本地治理Skill（合同五件）
四件套        核心认知(用户原文权威) 方向追踪(方向投影) 全景视野(结果投影) 扩展认知(AI阐释)
动态状态      STATE.json(机器账本+指针) + latest session SESSION.md + active 记录路径
研究层        业务Skill 三问 FRONTIER LESSONS RESUME（research profile 才全文）
按需层        manifest/SOURCE_MANIFEST/audit 汇总(query_first)、理解章节/HoTT(task_expand)
```

分层的判定逻辑不是"重要性"，而是**变更频率×消费方式**：
宪法要稳定（注入层），当前态要新鲜（启动核），用户原文要保真（四件套），
机器账本要可校验（STATE），研究记忆要可恢复（研究层），大证据要按需（水合层）。
姊妹报告发现的层归属错误（STATE 放启动核）就是违反这个判定逻辑的实例。

## 四、一个贯穿性事实：这套框架是"用户深度共同设计"的

rulings.md 显示：三件套→四件套（§19 用户选 A）、分片两波（§17/§18 用户启动）、
数学门禁（§15 用户原话）、核心认知重建（§12 用户授权）、精简边界（§11 用户划线
"只能移除三件套之外的……不得压缩、摘要、选择性加载"）。因此后文谈"目的"时，
多数能落到具体 ruling 的用户原意上，而不是 AI 的自我设计——这一点本身是
理解框架的关键：**它不是 AI 自发的官僚主义，而是用户为对抗 F1–F5 逐条定购的仪器**。
代价（姊妹报告的主题）也是这套定购在容量约束下的必然摩擦。
