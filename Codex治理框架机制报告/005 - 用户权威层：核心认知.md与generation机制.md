# 用户权威层：核心认知.md 与 generation 机制

## 1. `核心认知.md`（38.6KB / ≈12,191 tokens；core-cognition-generation-7，46 KC）

**作用**：用户原文账本——46 个按 UTC 时间编号的语义单元（KC-000001…KC-000046），
每条=紧凑来源锚点（sources/prompts/…#L 行号 + 消息 ID）+ 用户原话逐字块。
正文只有两节：§0 解释与证据边界（一段），§1 按时间顺序的原文。**它是四件套中
唯一单文件**（curation+manifest 管理，禁手改）。

**目的**：这是全套框架的**原点**，且目的由用户亲自定义（rulings §9 用户原话，
2026-09-12）：

> "我的思想，不是AI训练数据中的思想，我们这一次的工作是元数学理论研究和创新，
> 它需要AI超越它的训练数据给它的带来的认知惯性和路径依赖。它是我设计的AI上下文
> 工程。如果AI不携带我当初定义的核心认知.md去在未来思考悖论问题，那么我很多话
> 就要反复地重新说……所以必须每个压缩边界之后都必须重新完整加载。"

即：防御 F2（训练先验）。用户的悖论思想（合取前提分析法、方向 A/B、第三条发现
路径、现实对齐……）不在任何模型的训练分布里；如果靠"摘要+模型先验"重建，
得到的会是训练数据里的常规 HoTT 认知，而不是用户的思想。

**原理**：为什么是"全文逐字重付"而不是摘要/检索？其认识论根据是：
**对训练分布外的内容，摘要失真不可恢复**。普通项目文档摘要错了，模型的
领域知识能补洞；用户思想摘要错了，没有任何先验能补——所以保真要求必须
是字节级的（这就是 §0 与 rulings §11 反复强调"摘要、manifest、主题索引、
KC 子集和旧 receipt 均不得替代"的原因）。配套机制：

- **generation/curation/manifest 三件套**：谁进 core 由人工 curation（JSON，
  hash-pinned inherits 链）决定，`build_core_cognition.py --write` 生成，
  manifest（43,615 tokens，query_first 层）保存全部 hash/行范围/处置；
  core 正文只留"锚点+原文"，防元数据反向吞噬思想。
- **排除规则**：转发 AI、附件、一般治理、继续指令不进 core（ruling §2/§3）——
  防"AI 的展开冒充用户思想"，这是权威单向性。
- **§0 自我降权**："不因进入本文就自动成为数学定理"——防权威溢出到数学层。

**成本视角**：12,191 tokens 买 46 条用户思想的全保真常驻，是全框架**单位价值
最高的 spends**（姊妹报告的所有优化建议都不动它）。它也最守纪律：单文件、
生成器管理、七次 generation 演进全有 transition receipt——**它证明了"层归属
正确+有退休机制（旧代归档）"时，常驻保真可以不失控**。STATE 的失控正是不具备
这两个条件。

## 2. `核心认知.manifest.json`（159KB / ≈43,615 tokens；query_first 层）

**作用**：core 的元数据账本（每 KC 的来源 hash、行范围、消息处置、主题、关系）。

**目的**：让"哪句话从哪来、有没有被改"可机器审计，而不把这些审计数据放进
必读正文。

**原理**：**元数据与正文分离 + 层降级**——这是容量原理在用户权威层的正确应用
（与 STATE 形成对照）：正文保真常驻，账本按需查询。manifest 巨大没关系，
因为它不在启动核。

## 3. generation 机制（curation → builder → transition receipt）

**作用**：core 的唯一合法演化通道。新用户原文 → 更新 curation JSON → 生成新
generation（编号+KC 分母变化）→ 全量迁移收据（旧代 PRESERVED_EXACT）→
旧代由 Git/tag 保留。

**目的**：防两类事故：(a) 手工润色用户原文（保真破坏）；(b) 在旧代末尾直接
追加造成代际混杂（账本不可审计）。

**原理**：**写路径收窄到生成器**（机器管理）+ 人类只在 curation 数据层做语义
决定（HUMAN_EDITED curation / MACHINE_MANAGED 生成物分离）。
七代演进（913→g2→g3/27→g4/36→…→g7/46）每次都有 transition——这是全框架
运行最平稳的变更机制，可作为 STATE 瘦身改造的模板（姊妹报告 G2 建议的
可行性论据）。

## 三问总结

作用=以字节保真方式常驻注入用户的非训练分布思想；目的=对抗训练先验/认知惯性
（F2，用户亲自定义的上下文工程）；原理=逐字原文+hash 锚定+生成器通道+元数据
分离——保真原理与容量原理**协作而非竞争**的孤例，其纪律（单文件、退休机制、
写路径收窄）正是其余文档应当效仿的形态。
