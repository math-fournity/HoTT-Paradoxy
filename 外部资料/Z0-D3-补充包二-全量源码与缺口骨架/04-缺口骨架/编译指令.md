# 编译指令（三种环境）

> 目标：让接手 AI 能在**自己的机器上**把 24 个模块 + 骨架编译起来，
> 而不是像上一位复核 AI 那样"对着看不见的 API 写证明"。

## 你需要的东西

| 组件 | 版本 | 说明 |
|---|---|---|
| Lean | `4.34.0`（commit `293d5d0c`） | 精确版本，别用别的 |

## 方式一：你已有 Foundation + Mathlib 的 olean 构建树（最快）

项目包里的 `LEAN_TOOLCHAIN.json` 与 `MATHLIB_CLOSURE.json` 已经把路径钉死。
若你的路径与它们不同，改这两个 JSON 的 `prefix` / `lean_path` 字段。

```bash
PKG=<你的检出>/HoTT/formal/claude-cg001/godel-q-zfc-z0-full

# 迭代编译（约 60 秒冷启动，增量几乎瞬时）
python3 -B devbuild.py $PKG \
  GodelQ/ProcessObservation.lean GodelQ/EffectiveTheory.lean GodelQ/GodelZenoRunner.lean \
  GodelQ/FoundationArith.lean GodelQ/ZFC/SetLanguage.lean GodelQ/ZFC/SchemaDelta1.lean \
  GodelQ/ZFC/ReplacementDelta1.lean GodelQ/ZFC/ZFCDelta1.lean GodelQ/ZFC/NumeralCode.lean \
  GodelQ/ZFC/NeverRE.lean GodelQ/ZFC/OmegaArith.lean GodelQ/ZFC/NumeralSemantics.lean \
  GodelQ/ZFC/ArithInterp.lean GodelQ/ZFC/R0Model.lean GodelQ/ZFC/Effective.lean \
  GodelQ/ZFC/Soundness.lean GodelQ/ZFC/OmegaLaws.lean GodelQ/ZFC/PAModel.lean \
  GodelQ/ZFC/Z0Shadow.lean GodelQ/ZFC/Z0PA.lean GodelQ/ZFC/ShRE.lean \
  GodelQ/ZFC/InternalTranslate.lean GodelQ/ZFC/TranslateRE.lean GodelQ/ZFC/Z0Full.lean \
  GodelQ/ZFC/SeqTranslate.lean GodelQ/ZFC/SeqTranslateFormula.lean \
  GodelQ/ZFC/Z0Layer1.lean GodelQ/ZFC/缺口骨架.lean
```

`devbuild.py` 是本 repo 的开发用增量驱动（不是收据工具）。它做的事：

1. 用 `LEAN_TOOLCHAIN.json` 里的 `prefix` 绝对路径调 `lean`，不经过 `elan` 代理；
2. 在 `/usr/bin/sandbox-exec` 的 `(deny network*)` profile 里跑；
3. `LEAN_PATH` = 你的临时构建目录 + `MATHLIB_CLOSURE.json` 的 `lean_path`；
4. 按 `(相对路径, 源码 SHA-256, 前面所有源的链式哈希)` 跳过未变的模块。

## 方式二：从零构建 Foundation（你没有构建树时）

Foundation 有 308 个源文件。构建顺序由 `import` 关系决定，用 `lake` 最省事：

```bash
git clone https://github.com/FormalizedFormalLogic/Foundation.git
cd Foundation
git checkout 1fb01b72de546e1b50821fd05b1314a8d958583f
# 按它的 lakefile 拉 Mathlib（同样钉到 5ed29652）
lake exe cache get      # 若可用
lake build
```

**注意**：本 repo 的 Foundation 构建树是用一个顺序编译脚本（`ffl_build.py`）建的，
不是 `lake`。两者产出的 olean 应当等价，但如果出现 `olean` 版本不匹配，
优先按方式三做单文件探针。

## 方式三：单文件探针（只验证一条引理能否 elaborate）

当你只想确认某个 API 名字/签名对不对，不必编译整个链：

> 下面的 `/tmp` 是**你自己机器上的**临时目录，不是本 repo 的路径。在本 repo 里工作时，
> 用 `.claude/goals/CG-007-formalization-completion/tools/lean_probe.py`（见该目录 README）。

```bash
cat > /tmp/probe.lean <<'EOF'
import Foundation.FirstOrder.Arithmetic.Bootstrapping.DerivabilityCondition.D3

open FFL FFL.FirstOrder FFL.FirstOrder.Arithmetic Bootstrapping
open scoped FFL.FirstOrder.Arithmetic FFL.FirstOrder.Bounding

variable {V : Type*} [ORingStructure V] [V↓[ℒₒᵣ] ⊧* 𝗜𝚺₁]
example (σ : ArithmeticSentence) (hσ : ℬ[<, ℒₒᵣ].Hierarchy 𝚺 1 σ) :
    V↓[ℒₒᵣ] ⊧ σ → Provable 𝗜𝚺₁ (⌜σ⌝ : V) :=
  fun h ↦ Bootstrapping.Arithmetic.sigma_one_complete (T := 𝗜𝚺₁) hσ h
EOF

LEAN_PATH=<foundation-build>/lib/lean <lean-prefix>/bin/lean /tmp/probe.lean
```

## 关于 `sorry`

- 收据工具（`capture_run.py` / `verify_cg001_run.py`）**拒绝含 `sorry` 的源**。
- 所以 `缺口骨架.lean` 里的两个 `sorry` 是**给你看的形状**，证完必须删。
- 想先看骨架长什么样，可以直接 `lean 缺口骨架.lean`，它会以 `sorry` 警告通过（exit 0）。
- **不要**为了让它进收据而加 `axiom` / `native_decide` / `unsafe` / `opaque` / `skipKernelTC`。

## 卡住时

把卡点写成一条**精确的 Lean 命题**（类型逐字），放进一个带未证标记的文件，
并在 `CLAIM.md` 里说明：缺什么、为什么是实的、谁可以继续。**不要**留 `sorry` 冒充完成。
