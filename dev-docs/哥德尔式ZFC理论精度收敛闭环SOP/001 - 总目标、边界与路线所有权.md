# 总目标、边界与路线所有权

## 1. 父结果

父结果是把研究发起人关于“理论精度／观察力不完备”的想法，做成一个可以被证明、被反例限制、或被来源范围拒绝的 ZFC 实例研究程序。它必须同时保持四件事：

1. **Gödel 技术的真实性：** code、有限 proof checker、substitution、quotation、diagonal 与独立性不能由一句自然语言自指代替。
2. **HoTT 对应的真实性：** R3 的一般证明论结果必须经过 exact HoTT calculus 的规则、对象层编码和有效性审计，才能成为 R4 结果。
3. **原过程的真实性：** `OriginDone`、芝诺／圆环／H0 与 `FormalDone` 的关系不能被新定义的完成词偷换。
4. **ZFC 归因的真实性：** bare ZFC 的理论精度问题必须绑定版本固定的 ZFC-facing interface、实际 acceptance／adequacy claim 或明确的形式语义，不能由研究者自造 record 代替。

允许的总交付是：

- `ACTUAL_GODEL_ZFC_PRECISION_CONSEQUENCE_WITH_SCOPE`：各层的真实来源／形式前提已支付，最终精确 consequence 通过 kernel；
- `ALL_DECLARED_ROUTES_REJECTED_WITH_SCOPE`：声明的全部路线各有固定分母、反控制和后继结论，实际实例没有成立；
- `FORMAL_TARGET_UNDERDETERMINED_WITH_SCOPE`：在已声明的来源与用户指定范围内，bare-ZFC-facing completion interface 或唯一 `OriginDone` 无法冻结，故不能形成单一可形式化目标。

这三个结论都不等于 `ZFC ⊢ False`，也不等于“ZFC 没问题”。

## 2. 研究 profile 与授权边界

本任务是 `RESEARCH_PROFILE_GOVERNED`：它跨多个理论层、来源集合、proof assistant、Session 和 worktree；一条新来源、反例或精确模型映射会改变后续选择。它不因此获得后台运行、自动联网、worker、push、tag、外部写入或自动恢复旧 Goal 的权限。

每次实际研究仍须按当前用户授权决定是否调用网络、P-DAG worker、proof assistant 或 Git mutation。P-DAG 只在其单独授权范围内用于模式 P 的盲测／来源／Battle；本 SOP 不把它泛化为本路线的默认执行器。

## 3. 语义不变量

### I1 · 总路线不被局部结果截断

`SOURCE_GAP`、`MODEL_VARIANT_GAP`、`TOOLCHAIN_VARIANT_GAP`、一次 timeout、一个 checker 失败、一个负控制、一个 source denominator 的 scoped rejection，均只能关闭该精确 target。它们必须产生下一条有界 successor，或标记一个明确、外部可观察且不可由当前行动解除的阻塞条件。

### I2 · successor 必须改变判别面

不得把同一 source、同一理论变体、同一 `Done` 合同、同一 compiler 缺口，换个文件名后重复运行。下一条路线必须至少改变下列之一：固定 source、对象理论／模型变体、实际 consumer、任务桥、可表示性机制、proof kernel、或明确补上的前提。

### I3 · 总停止必须全图结算

任何人要写 `TOTAL_CLOSED`，必须逐项核对本 SOP 第 002 片的全部 declared route，确认每条都有：范围、证据、反控制、局部 verdict、`reopen_if`，以及它对总判词的贡献。没有这张总账，不得从“我暂时没有下一步”推到“研究结束”。

### I4 · 不用一般定理偷换实际接口

一般 Gödel 不完备性、Lean/Coq/Agda 宿主中的 proof search、不带来源的 `Accept` record、或一个现实过程 toy model，都只能推进其明确层级。它们不能自动支付 actual `Accept_ZFC`、`AdequacyLift`、`SameFullQ` 或 `OriginDone`。

### I5 · 不用来源不足否定问题本身

一个来源不含 completion consumer，只证明它不是这条路线的 payment；它不反证 bare ZFC 的理论精度问题。同样，一个来源或模型确实保留 process information，只证明该 target 有防御，不能外推为全部 ZFC 实践有防御。

### I6 · 每一自然单元都回到父结果

每个单元结束时回答：它减少了哪一个 R3/R4/T-DIAG/M1–M5 未知；它为何没有偷换同一任务；它关闭的只是哪一个范围；下一单位如何使总图更接近三种合法终局之一。不能让“完善刀具／写文档／重复重放”脱离这个问题成为独立交付。

## 4. 当前范围与非目标

**范围内：** 固定 H0 的过程观察、Gödel式编码与反射、exact HoTT calculus、ZFC-facing foundations/acceptance interfaces、芝诺／圆环与 H0 的 completion contract、机器证明和版本化来源审计。

**范围外：** 宣称 ZFC 的对象语言不一致；以一次性能或 timeout 证明不可停机；以形式化系统的存在本身证明现实任务同一；未经来源和同一任务支付地将数学共同体的说法写成 bare ZFC 的公理后果。

## 5. 理念与来源的消费方式

本 SOP 消费核心认知中关于时间／时序、计算合法性、HoTT 与程序自反界限、以及罗素计算—存在—自指模式 P 的研究方向，尤其是 `KC-000024`、`KC-000027`、`KC-000036`、`KC-000059`。这些是生成和审视候选的观察角度；数学结论仍须由版本固定的规则、来源、控制和 kernel 运行支持。

对每一个新靶，先问：理论为了可用性把哪一种形成、过程、观察或完成责任压缩了？再问：该压缩是否在同一任务中被一个可证明、可编码或可来源审计的过程逼迫显现？最后才判断这一现象是否能归因到具体理论接口。
