# 总目标、独立性与反锚定合同、完成门

## 1. 任务来源、性质与"最大的成本"

### 1.1 任务来源（逐字）

- 研究发起人 2026-10-07 本次指令（节选，逐字）：「我现在需要你让另外一个AI以最大的成本去重新全量审计，就像重新做一遍一样……并且交代清楚如果跨越压缩边界，应该如何确保自己的上下文内容该有的都有，不该被压缩的，要重新完整加载。」
- 研究发起人对第一战役的原始要求（第一战役 SOP 001 §1 所引，逐字节选）：「重复的不用重复读，但是如果过去读的不再上下文中了，你要重复加载。」

### 1.2 性质

本战役不是抽查，也不是重新核对收据哈希。它是一场**独立的重读战役**：另一位审计者从零开始，自建冻结、对齐与分块，亲自读完全部义务行，亲自写出笔记、分类、资产账本与收据，再做自检；之后才解封第一战役的产物，逐笔比对，给出终审判词。两套独立记录在内容层面一致，才构成"读过"的证据。

第一战役的设计者审计已经证明"收据哈希与文件一致、覆盖账目自洽"，这是机械事实。但它没有、也不可能证明"执行者真的读了那些字节，并如实记录"。本战役要补的正是这一层。

### 1.3 "最大的成本"的操作定义

"最大的成本"不是浪费 token，而是**遇到"省"与"严"的选择时，一律选严**。它落成下列可检查的要求：

| 编号 | 要求 | 检验位置 |
|---|---|---|
| M1 | 义务行全部亲读：自建的每个 UNIQUE 行都经由读取工具进入上下文 | 003 拍 1；004 B-03 |
| M2 | 全部记录自建：notes2、classes2、assets2、ledger2 由本次会话从原文写出，不复制第一战役的任何文字 | 003 §4 至 §7；004 B-06、B-07 |
| M3 | 每块读两遍：拍 1 整读；拍 4 在记录写完后再整读一遍做复读自检 | 003 拍 4；004 B-11 |
| M4 | 长行与截断不放过：凡返回不完整或超过窗口阈值的行，按窗口读完整并记录 | 003 §9 |
| M5 | 对齐双算法取交集：两种算法对共享判定不一致的部分，一律当作义务行读 | 002 §3.5 |
| M6 | 第一战役的每一笔收据逐一判词，不以抽样代替判词 | 004 §3 C-03；R2 |

| M8 | 压缩边界一律完全重载，不以摘要代替，按 005 的清单执行 | 005 §3、§4；RS 收据 |
| M9 | 重做一遍：自建叙事与资产总表（重做版的 D2、D3），再与第一战役的 D2、D3 比对 | R5；004 §3 C-04 |

### 1.4 非目标

- 不产生任何数学结论；不运行证明器；不重开研究判词。
- 不修改语料（八份导出）、`git-worktree对话录/README.md`、第一战役目录，以及研究 owner（`STATE`、`MEMORY`、`方向追踪.md`、`全景视野.md`、`核心认知.md`）。
- 不读取原始 JSONL trajectory、其他分支、其他 worktree 的文件。
- 不 commit、不 push、不发布。
- 不使用子代理。本仓库 AGENTS.md 对 Sub Agent 的禁令（2026-09-17）仍然有效；P-DAG 的任务限定授权不适用于本任务。
- 不因为"已通过"就宣称完成。完成与否只按 §7 判定。

## 2. 对象、语料与角色

- **语料**：`git-worktree对话录/` 中的八份 GUI 导出，即文件名以 `dev-` 开头、以 `-gui.md` 结尾的文件。用 `git -c core.quotepath=off ls-files` 确认。八份是唯一的阅读对象。
- **身份**：一手身份是 `HEAD` 中的 blob（002 §2）。工作树副本必须与之逐字节相同，否则 BLOCKED。
- **角色**：独立审计者。依据仓库治理文件中对"独立审计"角色的定义：先复述原问、取舍、过程与验收标准，再独立回源核对被审对象的证据；不借被审对象的摘要取得定义权；不替被审对象补成果后宣布通过。
- **出界**：见 §1.4 与 §4。

## 3. 独立性与封印合同（I0 至 I8）

- **I0 自建一切**：冻结、对齐、分块、收据、笔记、分类、资产账本、校验与抽样，全部由本次会话自建。第一战役的脚本、收据、笔记、账目、报告，都不得作为本次任何一步的输入（阶段 C 的外部对照用途见 004 C-08）。
- **I1 封印（反锚定）**：阶段 A 与阶段 B 期间，禁止打开第一战役的任何产物或规范（§4）。合法顺序只有一条：读原文，然后写本块的 notes2 节、classes2 行与 assets2 条目，然后复读自检，最后提交收据。第一战役的内容只能在阶段 C 解封之后读取。
- **I2 结构也封印**：第一战役的 manifest、区间表、账本的"结构信息"同样属于产物，阶段 C 之前不读取。不得以"只看区间表"为由提前对账。
- **I3 一手身份**：语料身份以 HEAD blob 为准。不得使用任何既有 manifest 或他人算出的哈希作为身份。
- **I4 冲突并陈**：自建结果与第一战役不一致时，两者并陈，给出可复核的位置。不默认自己对，也不迁就对方。
- **I5 禁抄**：notes2 与 assets2 中的句子，必须由本次会话根据语料原文组织。不得复制第一战役产物中的任何句子或定义。引文只来自语料本身。
- **I6 过程留痕**：每次打开第一战役产物，都记入 `seal-log.jsonl`（ACCESS）。每个修正都以追加条目登记（RC），不改写既有收据。
- **I7 反锚定数字**：本次会话的中间产物与交付物，不引用第一战役的任何计数、判词或结论。所有总数只能由自建脚本从语料算出。
- **I8 疑则读之**：对齐、分块、分类、判词出现不确定时，选择"读更多、记更细、判得保守"，并登记。

## 5. 继承裁定 R-1 至 R-4

- **R-1 分层登记**：用户轮逐字（超过 200 字符取前 200 字，附长度与整行 SHA-256 前 16 位）；Codex 的决定性陈述逐字；中间过程按要点；资产逐条带行号锚定；机械块分类。
- **R-2 哈希、锚定摘录、抽样复核**：逐块字节切片哈希；逐字引文；抽样种子由本次 manifest2 派生，不使用第一战役的种子。
- **R-3 机械行全部亲读、分类标记**：环境块、注入块、模板行都要进入上下文（即被读），标注分类即可，不必逐行摘录；胶囊类线索逐条登记。
- **R-4 新会话、异模型、结果交另一 AI 审计**：执行者的模型家族须与第一战役的设计会话和执行会话不同（§9）。可假设约 100 万 token 上下文，但**必须按 005 处理压缩边界**，不得因上下文大而放松证据要求。
