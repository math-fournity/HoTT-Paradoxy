# 全量重读五拍循环与双账本

## 1. 阅读单位与顺序

- 阅读单位是块（002 §4）。按 tag 字典序处理文件，文件内从上到下处理块。
- 块内每一行都必须进入上下文。义务行必读；上下文缝内的行随块读入。

## 2. 读取方法

- **只能整读**：使用宿主的文件读取工具（例如 Read 的 offset 与 limit 分段），或 `sed -n 'a,bp'` 之类的整段输出。禁止用 grep、awk 抽取、head 或 tail 片段，或摘要代替阅读。
- 每次读取的请求区间与返回的行号必须一致：返回的最后一行号等于请求的 end，或已到 EOF。若返回被截断或行号不连续，缩小区间重读，并在 `ledger2.jsonl` 的 `tool_reads` 中如实记录每次调用。
- 单次输出过大时可以拆分，但各段须首尾相接、无缝。

## 3. 每块五拍

**拍 1 整读**：读取块的 [start, end] 全部行（§2）。

**拍 2 写 notes2**：在 `notes2/<tag>.md` 追加一节（§4）。节标题为块 ID。

**拍 3 写 classes2 与 assets2**：
- 在 `classes2/<tag>.tsv` 追加本块的分类区间行（§5），覆盖本块全部义务行；
- 在 `assets2.md` 追加本块的资产条目（§6）。

**拍 4 复读自检（第二遍整读）**：再次整读本块全部行，逐段对照 notes2 节、classes2 行与 assets2 条目，用 §10 的检查表寻找遗漏。发现遗漏，在 notes2 节末尾追加 `[补记·拍4]` 条目，并补充 classes2 与 assets2（只追加，不改原文）。然后运行 `reread.py <块ID> --status PASS|FAIL --addenda N`。

**拍 5 预检与提交**：
- 运行 `commit_block.py <块ID> --precheck`。全部检查通过后，运行 `--commit`。它会追加 RA 收据到 `ledger2.jsonl`（含 notes2、classes2、assets2 当前内容的哈希），并刷新 `STATUS.md`。
- 预检失败：回到对应的拍修补。不得跳过。

**块提交判据**：拍 2、3、4、5 全部完成，`reread` 为 PASS，且 RA 收据已写入，块才算已提交。未提交的草稿节保留在文件中，但须追加一行 `[作废·块未提交]` 标注，不删除。重做时，`commit_block` 只采用块提交时最后一个未作废的节。

## 4. notes2 格式

每个块一节。格式如下（示例为示意，行号与内容由执行者自定）：

```markdown
## B-dev-01-0003 | 行 412–611
- [T] L412–L455: 「<用户轮首行，逐字，不超过200字符>」 | 轮长=44
- [C] L456: 「<Codex 决定性陈述，逐字，不超过200字符>」
- [P] L470–L489: <进展要点，不超过120字，执行者自拟>
- [A] L503: A2-0012 | 「<资产名称，逐字>」
- [F] L520: 「<胶囊的字面行，逐字>」 | 字面模式见 SESSION
- [G] L530: <commit 哈希，逐字> 「<主题，逐字，不超过200字符>」
- [M] L600–L611: <机械块类别，不超过40字>
- [X] L700–L702: <其他，须说明>
- 已读无资产（仅当本块没有 [A] 时写明）
```

规则：

- **[T]**：每个用户轮都要有一条。范围是该轮的全部行，引文取其首行。
- **[C]**：每个 Codex 轮至少有一条 [C] 或 [P]。[C] 指做出决定、下结论、宣布状态或边界的陈述。
- **[P]**：其余过程性内容的要点。
- **[A]**：每个资产一条，对应 assets2 中的一个 ID（§6）。
- **[F]、[G]、[M]、[X]**：分别对应胶囊、commit、机械块与其他。
- **引文**：逐字取自语料，并可由工具在指明的行中找到。超过 200 字符的，取前 200 字符，并附长度与整行 SHA-256 前 16 位。
- 笔记不得复制第一战役的任何文字（I5）。

## 5. classes2 格式

`classes2/<tag>.tsv`，制表符分隔，列为：`block_id`、`start`、`end`、`class`、`ref`。

- `class` 取值为 T、C、P、A、F、G、M、X 之一；
- `ref` 指向 notes2 中的条目，如 `L412` 或 `L503(A2-0012)`；M、P 类可用 `-`；
- 覆盖规则：本块所有行的 [start, end] 并集，必须恰好等于本块的义务行集合；各行之间不得重叠；每行只属于一个类别。混合的区间须拆分。

## 6. assets2.md 格式

表格，列为：ID、位置、名称（逐字）、类别、定义（自拟，不超过120字）、状态、引文（逐字，不超过200字符）、块。

- **ID**：`A2-NNNN`，顺序分配，永不复用；
- **类别**：概念、方法、形式化、来源、开放候选、判词或门规格、裁定或方法论、版本或身份、commit、其他；
- **状态**：`首现`，或 `又见→A2-NNNN`（指向首现条目）。同一名称在不同处出现时，逐次追加"又见"行，不合并；
- **1:1**：每个 [A] 条目对应恰好一个 ID，每个 ID 至少对应一个 [A]；
- **逐字**：名称与引文必须是语料原文的子串（工具校验）；
- **不合并**：不得为了表格"好看"把多个资产合成一行。

## 7. 账本 ledger2.jsonl

追加写入，每行一个 JSON 对象。每行都带字段 `prev`，其值为上一行原始字节（含换行）的 SHA-256。记录类型如下：

- `SESSION_START2`：身份声明（SESSION §1）的哈希，以及复述（SESSION §2）的哈希；
- `RA`：阶段 A 块的提交收据。字段：`rid`（RA-NNNN）、`block`、`tag`、`start`、`end`、`obligations`（义务行数）、`context_ranges`、`bytes`、`chunk_sha256`、`tool_reads`（每次读取的请求与返回末行）、`notes_sha256`、`classes_sha256`、`assets_ids`、`reread`（状态与补记数）、`ts`、`prev`；
- `RR`：重读收据（阶段 B、C 的重读）。字段：区间、`reload_reason`、`chunk_sha256`、`purpose`（如 B-12、C-03）、`ts`、`prev`；
- `RS`：压缩边界或文件边界的恢复收据（005 §4）；
- `RC`：更正收据。字段：`target`（被更正的 rid 或条目 ID）、`voids`、`reason`、`stage`。只追加，不改旧条目；
- `FILE_DONE2`：tag、块数、义务行数、资产条目数；
- `CHECKPOINT2`：`next_gap`（块 ID）与原因；
- `NOTE`：PROTOCOL_NOTE、FORMAT_ANOMALY、ENCODING_ANOMALY、REALIGN、ALIGN_ERROR、SOP_CONFLICT 等说明。

## 8. 文件边界与阶段 A 完成判据

- 文件边界（tag 切换）：完成上一文件的 `FILE_DONE2` 之前，执行 CL-F2（005 §6）。
- 阶段 A 完成判据：全部块已提交；全部文件有 FILE_DONE2；`cursor.py` 报告"无下一块"；`ledger2.jsonl` 的链完整；`STATUS.md` 显示 A_DONE；`seal-log.jsonl` 追加 `STAGE_DONE A`。

## 9. 长行、截断与失败

- **长行**（字节数超过 2000）：按字节窗口读取。每窗不超过 2000 字节，窗口边界对齐到 UTF-8 字符边界，窗口首尾相接直到行末。每个窗口的起止字节记入 `tool_reads`。
- **截断**：宿主显示截断时，缩小区间重读。
- **编码异常**：记为 NOTE（ENCODING_ANOMALY），不得静默替换字符。
- **失败**：任一拍失败，不提交。已写的内容保留，并标注 `[失败·拍N]`，然后重做对应的拍。同一块连续两次失败，则把该块拆成两个更小的块（按 002 §6 的重算规则，旧块收据作废并登记）。

## 10. 拍 4 复读自检检查表

- 每个 `## User` 轮的首行是否有 [T]；
- 每个 `## Codex` 轮是否有 [C] 或 [P]；
- 块内所有以 `## ` 开头的行，是否已按 002 §8 判定为角色标记或正文标题；
- 块内每个 commit 候选（7 至 40 位十六进制，词边界）是否有 [G]；
- 块内每个反引号包裹的标识，是否在 notes2 或 assets2 中出现，或在豁免表中有理由；
- 块内每个胶囊字面行是否有 [F]；
- 每个 [A] 是否在 assets2 中有对应行；
- classes2 是否覆盖本块全部义务行。
