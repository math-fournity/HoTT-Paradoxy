# 顺序执行、写回与完成判据

## 1. 四个顺序阶段

审计按证据依赖和时间顺序推进。不得先写最终综合，再把原子卡补成对综合的注脚。

| 阶段 | 允许动作 | 通过条件 |
|---|---|---|
| `A0_DENOMINATOR_FREEZE` | 枚举、去重、拆分和排除候选执行族。 | 原子账本的身份与排除分母 `remainder=0`，总数精确。 |
| `A1_ATOMIC_REPLAY` | 按实际发生顺序逐一写 AtomicAuditCard。 | 每个已冻结 `atomic_id` 有一张封存卡；前一张提交后再进后一张。 |
| `A2_PARENT_RECONCILIATION` | 将已完成子卡逐一回接对应的 R01--R13 粗自然单元。 | 每个父单元的子项清单、旧判词差异和范围修正明确。 |
| `A3_CROSS_CARD_SYNTHESIS` | 只在所有原子卡完成后，总结 P/Q 共同涌现、偏差、财富与下一可检验缺口。 | 分母、卡、父单元和所有重开项均有可核对状态。 |

`A0` 前可以调查候选来源，但不得写“全量审计已经开始”。`A1` 的顺序以发生时间为主；时间无法可靠排序时，先写
`ORDER_UNRESOLVED` 与证据，再按依赖图顺序推进，不能伪造精确先后。

## 2. 每个原子单位的标准工作循环

对一个 `atomic_id` 完成以下循环后，才可转到下一个：

1. 读取该单位的原始报告、NodeCard、source pack、Git commit 与可见 session/trajectory；复核它仍属于 A0 冻结分母。
2. 写 `AtomicAuditCard` 的 `AS_RUN` 部分，不读取后来结论来补当时事实。
3. 写当前合同的反事实，完成 P/Q 判词、偏差分类、同一任务控制、falsifier 和财富。
4. 更新原子账本该成员的审计状态，保留原始 identity 和去重理由；如发现分母漏项，立即标 `STALE` 并返回 A0。
5. 执行相称的 Markdown／链接／来源定位校验，复读当前 owner，并对这**一张卡及其账本 delta**做精确路径 Git commit。

一个原子卡是最小可审计工作单元。正常情况下，一卡一 commit；如果一个证据对象不可分地同时定义两个已有
`atomic_id`，仍要分别写两张卡，并在 commit 中列出两个 ID 和不可拆原因。不得用“节省提交”把一批未审节点
揉成一次提交，也不得把并行工作树的修改混入。

## 3. 写回、验证与审计谱系

| 事实 | owner |
|---|---|
| 原子分母、身份、去重和逐卡状态 | `audit/20261003-P-FORGE-ATOMIC-LEDGER.md` 及其分片 |
| 单卡和最终综合 | 新建的原子审计 campaign index／分片；不覆盖历史 R00--R15 |
| 原初理念与偏差规则 | `刀具系统理念.md`、P-DAG 005 与 full origin audit 的相应 owner |
| 当前需求／用户裁定 | `feature-list.md` 与 `rulings.md` |
| 当前恢复入口 | `MEMORY/001` |

每次写入前运行现有文件的 Git baseline 检查；每次提交前至少运行 `git diff --check`、受影响逻辑文档的
`python3 -B scripts/audit/verify_governance_shards.py`，以及适用时的
`python3 -B scripts/audit/verify_pattern_p_tool_history_sources.py --root .`。验证失败保留失败实物，卡标
`RUNNER_OR_EVIDENCE_FAILURE` 或相称状态，不能用下一张卡覆盖它。

每个 `A2_PARENT_RECONCILIATION` 还必须比较该父单元已有宏观结论与所有子卡：宏观结论只能保留为
`SUPPORTED_BY_COMPLETED_CHILDREN`、`PARTIALLY_SUPERSEDED` 或 `RETRACTED_WITH_SCOPE`。没有全体子卡时，
不得恢复“全部轮次已经审计”的表述。

## 4. 完成、暂停与阻塞的精确定义

只有同时满足以下条件，才允许标记 `ATOMIC_AUDIT_COMPLETE_WITH_SCOPE`：

```text
A0 exact D_atomic frozen; no unresolved identity or candidate family remainder
every D_atomic member has exactly one completed AtomicAuditCard
every card has AS_RUN evidence, Q verdict, counterfactual, deviation, falsifier and reopen trigger
all R01--R13 parent reconciliations are completed
A3 synthesis distinguishes Q progress from tool-only work and retains every Wealth item
links, ledger counts, Git commits and required validators pass
```

它仍不等于 `ZFC_Q_LOCATED`、`Q-4 CONVERGED`、ZFC 不一致、Power Set 已穷尽或模式 P 已被永久证明有效。
审计只说明：在声明的历史分母内，P/Q 共同锻造过程被逐单位审过。

如果原始来源缺失、identity 无法区分或 validator 无法解释，状态为 `BLOCKED_WITH_EXACT_GAP`，并列出需要的证据；
不得以估计数完成。用户明确要求暂停时才用 `PAUSED`。本 SOP 的建立本身不恢复当前已暂停的 Goal。

## 5. 后续 `/goal` 的稳定启动句

研究发起人可在未来直接使用：

```text
按照SOP=P-FORGE-ATOMIC-AUDIT-SOP，继续推进，直至无法推进。
```

该句要求先进入 `A0_DENOMINATOR_FREEZE`，随后按本 SOP 的逐原子循环推进；它不授权跳过分母冻结、启动新的
理论节点或把部分审计说成完整审计。若用户要限定范围，可写：

```text
按照SOP=P-FORGE-ATOMIC-AUDIT-SOP，从 A0 冻结原子分母后逐单位审计；不要启动新的理论 worker。
```
