# 形式化与机器证明交付合同

## 1. 机器证明必须证明什么

`C6` 不接受“一个形式化文件通过”作为核心结果。每个核心 theorem 必须有一个 source-to-spec fidelity table，将一手 source 的字段逐项映到形式对象：

| source 字段 | 形式字段 | 保真义务 |
|---|---|---|
| M 的基础关系 | `FoundationContext` | 不是 proof checker 或单一模型替代 |
| S 的数学对象／定理 | `Subtheory` / `FormalDone` | 版本、演算和 theorem 精确固定 |
| Q 的原任务 | `Process` / `OriginDone` | 输入、操作、观察与完成逐项保留 |
| P 的提升 | `Promotes : FormalDone → ClaimSolved Q` | 必须有来源 locator |
| bridge | `Bridge : FormalDone → OriginDone` 或被拒绝的对应命题 | 明确是已支付、失败还是 task switch |
| M 的审查责任 | `Adequacy` | 来源或明确的规范前提，不能偷设 |

核心 machine-proof target 只有三种合法形态：

```text
Failure theorem:
  ActualPromotion ∧ ¬ BridgePaid ∧ AdequacyRequiresBridge
  → CoreAdequacyFailure

Defense theorem:
  ActualPromotion → BridgePaid
  或 ActualPromotion → ExplicitTaskSwitch

Independence / underdetermination theorem:
  在明确 M/S/Q/P/Adequacy 的 formal contract 内，
  两个满足相同 M/S/P 观察的解释给出相反 Bridge verdict，
  因而该 contract 不能决定 core verdict。
```

第三种不是“bare ZFC 有问题”的自动替代；只有它的 `M/S/Q/P/Adequacy` 都是 actual contract 时，才是核心结果。

## 2. proof package 的强制资产

每个 C6 命题要通过项目 `MATH_PROOF_BEFORE_DELIVERY_V1`，并额外具备：

1. 唯一 `CORE-*` claim ID 与量词、假设、理论变体、禁止外推；
2. `HoTT/formal/zfc-meta-subtheory-adequacy/<claim>/` 中的唯一源码；
3. 保存于 `HoTT/verification/runs/<run-id>/` 的真实 kernel 运行；
4. `CLAIM.md` 中的 source-to-spec fidelity table、控制、source hashes 和 falsifier；
5. `HoTT/CLAIM_EVIDENCE_MATRIX.md` 的唯一索引行；
6. 一份 `DifferentTaskControl`：若把 OriginDone 改为 revised Done，结论如何改变；
7. 一份 `BridgePaidControl`：实际支付 bridge 时 core failure 不应继续成立；
8. 一份 `H0Control`：H0 未支付 SameQ 时不得作为 core theorem premise。

普通 Lean `Eq`、有限 Python 枚举、proof checker replay 或无 source mapping 的 conditional theorem，只可作为控制，不能登记为 `CORE-*` verdict。

## 3. 机器证明与来源缺口的分工

机器证明能验证固定 contract 的逻辑推论；它不能自行决定 source 的一句“解决”是否仍是同一任务。因此 C1–C5 的来源／任务审计和 C6 的 kernel proof 必须双向闭合：

```text
source ↔ CoreAdequacyCard ↔ formal specification ↔ kernel theorem ↔ controls
```

任一箭头缺失时，状态是 `NOT_CORE_MACHINE_PROVED`。不得用“源码难找”“无法安装依赖”“当前工具不支持”填充该箭头；它们只能生成一个有界 run block，并自动回到 `C0` 的替代候选或 `C1–C5` 的缺失字段。

## 4. H0 比较门

若要声称“ZFC 对芝诺的放过与 HoTT H0 的暴露是同一 Q 的异判”，必须另交付：

```text
SameQ_H0 : Q ↔ H0Q
UniformJudgment : 同一 Adequacy contract 对二者使用同一判准
```

没有这两个 asset，只能说二者可能存在结构类比，不能说 ZFC 出现同 Q 异判矛盾。
