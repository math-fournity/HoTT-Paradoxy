# 路线图、原子单元与反作弊

## 1. C0–C6 连续路线

| 单元 | 唯一问题 | 最小可交付 | 局部停止后必须发生什么 |
|---|---|---|---|
| `C0` | 锁定 candidate universe：哪些实际 ZFC-founded S/Q/P 组合有资格？ | `CoreAdequacyCandidateManifest`，每候选都有版本、source、字段缺口与排除理由 | 不得说“没找到”；选择尚未覆盖的最高判别候选 |
| `C1` | 该来源是否真实把 ZFC／foundation M 与子理论 S 连起来？ | `M→S` 基础关系卡 | 若只到应用来源，转 C1b 的 foundation source；不转 proof checker |
| `C2` | Q 与 FormalDone 的合同能否逐字段固定？ | source-backed `QContract` + `FormalDoneSpec` | 任务不固定时继续候选或形成 `QContract`，不能结束 Goal |
| `C3` | P 是否实际将 FormalDone 提升为“Q solved”？ | `PromotionCard`，含原文 locator 与反 promotion control | 没有 P 只能排除该候选，自动选择下一候选 |
| `C4` | Bridge 是否支付、还是 task switch？ | source-level `BridgePaymentCard` + 同一任务对照 | bridge 缺失不是总完成；转 C5 或另一候选 |
| `C5` | M 的基础责任能否被来源与形式规格明确？ | `AdequacyContract`，定义 M 应审查什么且有来源／反例 | 若 criterion 只是 AI 预设，继续追来源和替代准则，不得归罪于 ZFC |
| `C6` | 把固定 contract 写成保真 formal target 并完成 machine proof；仅此处作 core verdict | theorem / countermodel / defense proof、source-to-spec fidelity table、controls、run、claim matrix | 若 kernel target 不足或拒绝，只结束 proof route，回到 C0–C5 的下一个可支付候选 |

`C0–C6` 是一条连续链。某个叶子产生 `SOURCE_GAP`、`TASK_SWITCH`、`MODEL_MISMATCH`、`COMPILER_BLOCK` 或 `PROOF_REJECTED` 时，Master 必须先运行 `SUCCESSOR_SCAN`：检查其余 C0 manifest、M/S/Q/P/Bridge 字段、H0 same-Q 支线和替代 formalization。没有这一步，任何“本轮结束”都是无效状态。

## 2. 候选宇宙的穷尽纪律

本方案不允许无边界网搜，也不允许只盯一个容易形式化的 proof interface。`C0` 必须冻结至少下列候选族及其 remainder：

1. **标准连续统来源族**：明确将 ZFC-with-Choice／实分析作为芝诺 Standard Solution 基础的来源，及其所引用的数学 S；
2. **ZFC formalization 族**：版本固定、可执行或可核的 ZF/ZFC 内实数、序列、极限、连续性 formalization；
3. **foundation-adequacy 族**：明确说明集合论作为基础如何解释、保真或验证子理论的模型／语义来源；
4. **H0 comparison 族**：只有能支付 `SameQ_H0` 的来源／formalization；
5. **defense 族**：明确拒绝 P、支付 bridge 或说明 Q 已切换的来源。

每族的 `candidate_count / examined / rejected / live / remainder / reopen_if` 必须写进 manifest。`set.mm`、ACL2、generic Gödel 和现有 toy fixtures列入 control catalog，不可占用任一核心候选位。

## 3. 原子卡和反作弊字段

每个自然单元必须先写 `CoreAdequacyTaskCard`：

```text
unit_id / parent C-id / exact M,S,Q,P,FormalDone,OriginDone,Bridge,Adequacy
source identities + frozen hashes / proof target / controls
candidate claim / strongest falsifier / local stop / successor scan
allowed conclusion / prohibited conclusion / reopen_if
```

以下情形直接判 `SURROGATE_INTERFACE_DRIFT`：

- 把 proof checker acceptance 写成连续统／运动完成；
- 用可表示过程代替完成 bridge；
- 由“没有 time primitive”推出不可表示时间；
- 用项目自定义 policy 当数学共同体或 bare ZFC policy；
- 将 H0 的 never 定理当作 SameQ 已支付；
- 把一个 C-id 的 source gap 说成整个核心问题的负结论；
- 用机器证明一个较弱 fixture 后声称 C6 已完成。

## 4. 自动继续规则

在 active Goal 下，Master 不得因下列情形结束、暂停或要求用户重新授权：

```text
一个原子单元完成
一条 source route 无 payment
一个 proof assistant target 被拒绝
一个环境或 compiler 缺失
一个来源指出 task switch
一个 control 成功
```

这些只决定下一步：记录本叶的范围、触发 successor scan、选择能最大改变 `CORE_ADEQUACY_FAILURE / DEFENSE / CONTRACT_NOT_FIXED` 的下一最小单位。只有用户明确暂停／取消，或第 004 片的**总完成门**满足，才允许停止整个 Goal。
