# 核心合同与原始任务

## 1. 本方案真正要判断什么

本方案不问“ZFC 能否编码时间”。SEP 与既有 C-366 已经说明：集合论语言可以编码序列、状态、轨迹和证明。核心问题是一个**基础充分性**问题：

```text
M = bare ZFC，或来源明确的 ZFC-founded foundation context
S = M 所支撑的、版本固定的连续统／极限子理论
Q = 芝诺／圆环的原任务合同
P = 将 S 的形式结果提升为“Q 已经解决”的实际 promotion

M 是否要求：P 只能在一个已支付的 Bridge 下发生？
```

所求判词不是预设为“ZFC 有罪”。最终结果必须在固定合同下二选一，或者保持 active：

```text
CORE_ADEQUACY_FAILURE_WITH_SCOPE
    = 来源与形式化共同显示：实际 M/S/P 把 FormalDone 升格为 OriginDone，
      而 Bridge 未支付，且 M 的适当基础责任没有阻止这一升级。

CORE_ADEQUACY_DEFENSE_WITH_SCOPE
    = 来源与形式化共同显示：实际 M/S/P 明确要求或支付 Bridge，
      或 P 从未声称 OriginDone，因此核心指控在此合同下不成立。

CORE_CONTRACT_NOT_YET_FIXED
    = 还没有固定实际 M/S/Q/P；这不是完成、不是负结论，也不允许结束 Goal。
```

## 2. 核心对象与禁止偷换

每一候选必须填完以下 `CoreAdequacyCard`：

| 字段 | 必须支付的内容 | 禁止替代 |
|---|---|---|
| `M` | ZFC 或明确的 ZFC-founded foundation context、版本和基础关系 | `set.mm` proof checker、单一模型或一般集合编码 |
| `S` | 实数／极限／连续统子理论的精确版本、定义或 formalization | 泛称“实分析”或只给哲学叙述 |
| `Q` | 原任务的输入、允许操作、观察、`OriginDone` | 仅写“必须有最后一步”或由极限定义任务 |
| `FormalDone` | S 的 theorem、limit、endpoint、completion object 或正式结果 | 自造 Bool 结果或 toy world |
| `P` | 实际来源从 `FormalDone` 到“Q solved”的 promotion 句、规则或使用 | AI 的类比性总结 |
| `Bridge` | 保持输入／操作／观察／Done 的映射或明确 task switch | “极限存在”本身、proof checking 或模型存在 |
| `Adequacy` | 为什么 M 作为基础应要求／检查该 bridge 的来源或可形式化准则 | 把研究者偏好伪称 ZFC 公理 |
| `Control+` | 同一任务下 bridge 真正支付或 promotion 未发生的实例 | 换掉 Q 的普通成功例 |
| `Control−` | 同一 M/S 但 bridge 未付或 task switch 的实例 | 与 ZFC 无关的悖论故事 |

`P` 是整个合同的铰链。没有实际 promotion，不能把“一个理论不能表达所有现实语义”归为 ZFC 缺陷；没有 `M` 的基础关系，不能把一个极限论证归为 bare ZFC；没有 `Q`，不能让 `FormalDone` 自己决定 `OriginDone`。

## 3. 现实与形式层的精确关系

`OriginDone` 可以是严格过程完成、圆环复原、可执行到达或别的用户指定任务，但必须先固定；它不由 AI 自动等于 Norton strict reading，也不由标准极限的 endpoint 自动改写。

`FormalDone` 只能由 S 的实际 theorem 或定义给出。数学上可以同时存在多个合法 `FormalDone`；它们不因此支付同一个 `OriginDone`。

`Bridge` 至少须分别说明：

```text
输入保真      Q.input  ↔ S.input
操作保真      Q.operation ↔ S.operation / interpretation
观察保真      Q.observation ↔ S.observation
完成保真      Q.OriginDone ↔ S.FormalDone，或明确给出单向可用性
```

只有完成保真和前面三项在同一合同中到位，才能谈“解决”。这是一项待来源／哲学论证的 foundation adequacy criterion；不是从 ZFC 语法中自动析出的对象语言定理。

## 4. HoTT H0 的位置

H0 不再被当作自动的 B 输入。它只有在 `SameQ_H0` 支付后才可进入核心 consequence：

```text
SameQ_H0 : H0 的对象、输入、操作、观察、Done
           与固定 Q 的相应字段逐项对应。
```

若这个映射没有支付，H0 是一个重要的平行控制：它可以帮助提出“理论何时把追问／完成压平”，却不能证明 ZFC 对 Q 的裁决自相矛盾。

## 5. 首个必要反控制

下列已有材料必须作为控制被保留，而不能再承担核心结论：

- C-362／IEP／Norton：真实 application-level task switch 的来源线索；
- C-364：固定 coarse application view 不能决定 OriginDone 的形式控制；
- C-365／C-366：集合论可表示过程的正控制；
- C-367／C-368：观察精度与条件性对角化的通用逻辑核；
- `set.mm`、Foundation、ACL2：proof acceptance 或跨理论来源控制。

它们若被说成核心 verdict，立即触发 `SURROGATE_INTERFACE_DRIFT`，回到本片的 `M/S/Q/P/Bridge/Adequacy` 字段。
