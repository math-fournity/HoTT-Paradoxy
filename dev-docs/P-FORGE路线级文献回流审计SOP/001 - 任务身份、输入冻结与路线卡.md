# 任务身份、输入冻结与路线卡

## 1. TaskDescriptor 与最小闭包

执行本 SOP 前，Master 必须把下列 TaskDescriptor 写入当轮 session 或回流 audit owner：

| 字段 | 固定含义 |
|---|---|
| 父结果 | P1/P2/P3 的持续锻造与 ZFC Q 的发现是同一共同收敛过程；历史 A3 已在固定分母内完成 |
| 当前目标 | 用冻结的文献证据检验它是否改变已审 P/Q 路线的来源前提、控制或下一最小判别动作 |
| 成功标准 | 每个已纳入来源路线都有可复核 RouteBackflowCard、判词、falsifier、影响对象和停止/重开条件；所有可能 current-owner 改写均有明确资格 |
| 范围 | R_i → Z_i → Q_i 路线、Power Set-subset 与 quotient 路线、H0 → Z0 传输、formation/use/delivery/control 路线及它们对既有审计的影响 |
| 非范围 | 文献的全领域综述、候选分支集成、数学证明、worker 重放、重新审完全部原子卡 |
| 消费者 | 后续 P-FORGE Master、来源审计者、未来 canonical integrator；不是裸 ZFC 的数学读者 |
| 证据等级 | 来源受限的路线/方法结论；候选 worktree 在集成前只能支持候选性审计 |
| 快照 | 当前 dev HEAD、候选 ref/commit/base、worktree dirty 状态、所选 source manifests 与页/行 locator |
| 失效条件 | dev 或 candidate ref 前移；候选 worktree 变更；manifest/hash 不匹配；某路线缺同一任务字段；新的用户裁定改变 P/Q 成功定义 |

本任务默认选择 RESEARCH_PROFILE_PREPARE_ONLY：已有文献工作树是一个可能改变路线的候选证据包，但其交接单已过时且 worktree 有未提交文件。只有 B0 取得一个可复核、被接受的证据包后，执行者才重新判定是否需要 RESEARCH_PROFILE_GOVERNED；该判定本身不启动研究节点。

## 2. B0 的 LiteratureEvidenceEnvelope

回流开始前必须冻结一个 LiteratureEvidenceEnvelope。没有它，状态为 BACKFLOW_INPUT_NOT_FROZEN，禁止形成 current-source 回流结论。

~~~
envelope_id
authority_status:
  CANDIDATE_READ_ONLY | FROZEN_CANDIDATE_ONLY | CURRENT_EVIDENCE | STALE_OR_UNFROZEN
candidate_ref / exact_source_commit / source_worktree
source_worktree_status: clean | dirty-with-listed-paths | unavailable
candidate_base / observed_dev_target / current_dev_target
selected_commits / explicitly_excluded_commits
selected archive paths / manifest paths / source hashes / page-or-line locators
candidate claims that are being admitted for review
known conflicts / unreviewed material / integration disposition
freeze timestamp / Master / verification commands and outputs
reopen_if
~~~

|---|---|---|

## 3. 路线的两个方向和四个不可混用层

### 3.1 R_i → Z_i → Q_i

R_i 是 HoTT/UF 作者或权威来源提出的动机、批评、愿望或实际接口问题。Z_i 必须是一个精确的 ZFC-side 对象、规则、形成接口、consumer 或实践任务。Q_i 只有在 P 的字段与同一任务控制仍成立时才可以成为候选。

~~~
R_i source claim
  → candidate Z_i correspondence
  → source-defined formation/use/payment comparison
  → same-task test
  → P1 / P2 / P3 test
  → Q_i qualification verdict
~~~

R_i 不是 Z_i 的证据；一个术语相同、两者都被称为“集合”、或都使用“存在/构造/等价”，都不构成对应。Z_i 也不是 Q_i：只要来源明示了 payment、切换了 route、换了 theory layer、换了 Done，回流结论就是控制或失配。

### 3.2 H0 → Z0 → Q0

H0 指既有 HoTT 主线中被用户判定或研究者提出的过程位置；Z0 是试图在 ZFC 中寻找的对应。此路线必须经过 T0--T5：

| 门 | 必须保持的内容 | 任一失败的回流判词 |
|---|---|---|
| T0 | 理论/来源层：裸 ZFC、扩展、模型、proof assistant、元语言必须明确 | SOURCE_LAYER_CONTROL |
| T1 | subject：同一类对象及其身份条件 | TRANSPORT_ANTI_ANALOGY |
| T2 | formation/availability：对象何时被交付、何种支付仍在 | TRANSPORT_ANTI_ANALOGY |
| T3 | operation/reentry：算符或判断作用在谁、何处回入 | TRANSPORT_ANTI_ANALOGY |
| T4 | observation：任务真正观察什么 | TASK_SWITCH |
| T5 | Done：谁宣布完成、完成是否相同 | TASK_SWITCH |

通过 T0--T5 只表示可生成一个 H0-to-Z0 资格化卡；它仍须经 P1/P2/P3、正负控制和来源核验，才可能影响 Q0。

## 4. 16 个标准化审计维度

每张 RouteBackflowCard 都必须对 RB-D01--RB-D16 给出内容、N/A 理由或 EVIDENCE_INSUFFICIENT。它们是判断维度，不是自动评分模型。

| 组 | ID | 维度 | 要问的精确问题 |
|---|---|---|---|
| 证据身份 | RB-D01 | Envelope 身份 | 来源是否来自冻结的 ref/commit/manifest，当前属于 candidate 还是 current？ |
| 证据身份 | RB-D02 | R-source 原话 | 作者或一手来源究竟说了什么、没有说什么、版本/页码何在？ |
| 对应 | RB-D03 | Z-side 精确位置 | Z_i 是对象语言对象、规则、模型、proof layer、元语言还是数学实践？ |
| 对应 | RB-D04 | 路线保真 | formation route 是否相同；例如 P(A)-subset route 是否被 RepFun route 偷换？ |
| 对应 | RB-D05 | H0/Z0 传输 | 若涉及 H0，T0--T5 各门是否保留？ |
| 任务 | RB-D06 | 同一任务 | 冻结 T/u/F/C/I/O/Done，逐项说明谁保持、谁替换、谁缺失。 |
| P 字段 | RB-D07 | P1 形成与真实 consumer | 该对象是否为理论内一等对象，形成与 active consumer 是否由 source 给出？ |
| P 字段 | RB-D08 | P2 计算/逻辑再入 | 是否有同一对象、同一层的 formula/representation/operator/reentry，而非一般编码？ |
| P 字段 | RB-D09 | P3 生命周期/资格 | 是否有 NeedBuild → OperatorUse → BuildDone 或同等的 admission/完成顺序？ |
| 支付 | RB-D10 | payment/guard | 哪一条公理、规则、choice、mapping、domain guard、模型假设或证书已经支付？ |
| 层级 | RB-D11 | layer integrity | 证据是否跨越 bare ZFC、ZFC extension、模型、proof formalization、元语言或现实解释？ |
| Q 关联 | RB-D12 | 旧 P-FORGE 影响 | 它影响哪个 atomic/parent/A3 claim，还是只改变未来 source frontier？ |
| Q 关联 | RB-D13 | Q 状态 | Target-Q、Candidate-Q、Control-Q、QConvergenceLink 和 Q-0--Q-4/Q-R 各为何？ |
| 反证 | RB-D14 | controls/falsifier | 最强正控制、负控制、same-task control 和足以推翻本卡的来源事实分别是什么？ |
| 证据处置 | RB-D15 | 判词边界 | 该卡是 ingress、payment、route mismatch、transport anti-analogy、task switch，还是资格化候选？ |
| 行动 | RB-D16 | owner/action | 是否需要 B4、由谁写哪个 owner、何时停止、什么条件重开？ |

## 5. RouteBackflowCard 的不可省略字段

~~~text
route_id / route_family / card_kind
LiteratureEvidenceEnvelope identity and authority_status
R_i claim: source/version/locator/claim boundary
candidate Z_i: theory layer / exact object or interface / formation route
H0→Z0 fields when applicable: T0,T1,T2,T3,T4,T5
frozen same-task map: T / u / F / C / I / O / Done
P1 / P2 / P3 evidence and explicit absences
payment, guard, route mismatch, layer integrity
Target-Q / Candidate-Q / Control-Q / Q state before and after
affected AtomicAuditCard / parent Rxx / A3 statement, or NO_CURRENT_IMPACT
positive, negative, same-task controls; falsifier
verdict / evidence boundary / source status
writeback owner / action / stop condition / reopen_if
Master source review and exact commit after any current-owner mutation
~~~

若任何卡缺 RB-D01、RB-D06、RB-D10 或 RB-D14，它不得产生 CANDIDATE_Q_ELIGIBLE。若未通过 B0，它不得产生任何 current-owner 写回建议。
