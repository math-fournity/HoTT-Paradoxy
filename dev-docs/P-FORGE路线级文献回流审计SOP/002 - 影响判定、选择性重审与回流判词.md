# 影响判定、选择性重审与回流判词

## 1. B1：先建路线库存，不先宣布发现

B1 的输入是 B0 已冻结的 evidence envelope。执行者按 source claim 建立路线库存，每条路线至少有一个 R_i、一个被提议的 Z_i 以及一条明确的“不足以到 Q”的边界。

候选工作树当前可供重新资格化的路线名称可包括：R-STRUCT、R-CONSTRUCT、R-HIGHER、R-MACHINE、R-SET-CONTROL、Power Set-subset/quotient、formation/use/delivery、H0-to-Z0。这些名称只描述候选 archive 的组织方式；B0 前不能把它们当作 dev 当前路线，更不能假设每条都必然进入 B2。

B1 的产物是一张 RouteInventory：

~~~
route_id / R-source locator / proposed Z-side site
candidate envelope status / expected changed RB dimensions
known payment or mismatch control
possible existing P-FORGE impact
minimum missing fact / admission or stop reason
~~~

若来源只重复“ZFC 是一阶语言”“HoTT 更自然”“存在不等于程序”“需要 Choice”“模型有层级”等已知一般话语，而没有改变一张冻结卡的 RB-D03--RB-D14，它应停在 NO_NEW_SOURCE_INGRESS。

## 2. B2：回流判词字典

每张卡只能使用一个主判词；可另列支持性 control。判词描述的是证据对路线的作用，而不是理论真值。

| 主判词 | 必需条件 | 对 Q 与历史审计的效果 |
|---|---|---|
| NEW_SOURCE_INGRESS | 新来源明确改变了某一 RB-D03--RB-D14 字段，尚未决定同一任务是否成立 | 建立路线卡；不自动重开父级 |
| PAYMENT_CONTROL | 同一冻结任务的 source 明示支付了被怀疑的 formation/use/Done 条件 | 有界收紧 Candidate-Q；不推出 ZFC 无 Q |
| ROUTE_MISMATCH | R-side/Z-side 或两个 consumer 的 formation route 不同 | 阻断错误映射；保留真正同 route 入口 |
| TASK_SWITCH | subject、operation、observation 或 Done 被替换 | 阻断同一任务外推；不能把新任务的成功/失败算作旧 Q |
| TRANSPORT_ANTI_ANALOGY | H0-to-Z0 的 T0--T5 至少一门失败 | 阻断 H0 向 Z0 的传输；H0 和 Z0 分别保持开放 |
| SOURCE_LAYER_CONTROL | 证据只发生在模型、proof assistant、元语言或扩展理论层，而非声明的层 | 更正层级；不宣称 bare ZFC 被处理 |
| CANDIDATE_Q_ELIGIBLE | B0 已接受、RB-D01--D16 完整、same-task 与未付义务成立，且 controls 未直接支付 | 仅可创建一张 Q-qualification ForgeIntent；不是 Q-4 或 ZFC 结论 |
| EVIDENCE_INSUFFICIENT | 缺一手来源、locator、任务字段、payment 或 control | 不作实质路线判断，登记缺口 |
| NO_IMPACT_ON_CURRENT_AUDIT | 来源不能改变任一固定历史/当前方法 claim | 保留在 archive，不新增 current audit 负担 |

特别规则：CANDIDATE_Q_ELIGIBLE 不等于 Q_GENERATE。它只说明一个新来源已经有资格由 P-FORGE 的普通 ForgeIntent 合同作下一步检验；是否启动该 ForgeIntent 仍由用户和 P-FORGE-SOP 决定。

## 3. P 的来源回流检查

### 3.1 P1：形成与消费者

P1 不是“文献说某类对象存在”。卡必须指出：

1. ZFC-side 的 u 是否在声明层的一等对象；
2. F 是哪一个形成接口，是否为同一路线；
3. C 是否是真实 consumer，而非论文作者的背景说明、proof obligation 或模型解释；
4. consumer 是否有 source-defined I/O/Done；
5. source 是否显示 C 在 F 的支付未完成时仍使用 u。

若 consumer 已把 domain、single-valuedness、choice、mapping、type contract 或 formation rule 写成输入，结论一般是 PAYMENT_CONTROL，不是 P1 命中。

### 3.2 P2：表示、算符与再入

P2 必须固定同一个对象在表示、公式、环境、算符或判断中怎样回入。一般“ZFC 可编码公式”“有 Gödel 数”“proof search 会循环”不能代替。若对应发生在 proof layer 或外部程序，写 SOURCE_LAYER_CONTROL；若 reentry 指向的是另一个编码对象，写 ROUTE_MISMATCH 或 TASK_SWITCH。

### 3.3 P3：资格与完成次序

P3 需要来源支持的状态序列或等价语义，而不只是“定义有递归”：

~~~
NeedBuild / pending qualification
  → OperatorUse
  → BuildDone / declared completion
~~~

一条真正在同层中发生的 formation-use/admission 交错可以改变回流前沿；普通归纳、rank recursion、反射定理、axiom assumption、局部 proof witness 或模型构造都可能是有效控制，却不自动构成此序列。

## 4. 选择性影响分流：B3

历史审计不是可任意整体重跑的白板。B3 先判每一张路线卡的影响等级：

| 影响等级 | 判定 | 允许的写回 |
|---|---|---|
| I0 | 不改变任何冻结 P/Q、source layer、payment、same-task 或 stop 条件 | 仅在回流 audit 中登记 NO_IMPACT_ON_CURRENT_AUDIT |
| I1 | 改变未来 source admission 或一个已知控制的表述精度 | 更新未来入口/Memory 的受限备注；不改 A3 |
| I2 | 直接反驳、细化或补足一个父级/AtomicCard 的来源前提 | 为该卡和其父级写 source-facing addendum；AS_RUN 不改 |
| I3 | 改变 A3 的一项 Q/财富/恢复门的证据边界 | 只在 I2 已完成后，为 A3 写明确的 delta addendum |
| I4 | 通过 CANDIDATE_Q_ELIGIBLE 产生一张新的 Q-qualification ForgeIntent | 新卡进入 P-FORGE 准入，不写 ZFC_Q_LOCATED |

当前的初步影响索引可优先核查 R04、R07、R10、R11、R13 及其有关的 atomic cards，因为已有综合把 Power Set formation、source payment、finite bridge、reflection/source layer 和 QConvergenceLink 放在这些相邻路线。但这只是 B3 的检索起点；具体 parent 必须由原子账本和来源字段重新确认，不能靠本名单硬编码。

### B3 的硬规则

1. 候选 evidence envelope 只有 FROZEN_CANDIDATE_ONLY 时，最多形成 I0/I1/I2 的候选草案；任何 dev current-owner mutation 都等待 CURRENT_EVIDENCE。
2. 一张来源卡只因“看上去与 P 相似”不得提高 I 级；必须列出变化的 RB-D 维度、旧事实、来源新事实和同一任务差异。
3. 任何 I2/I3 的 addendum 分开写 AS_RUN 与 SOURCE_BACKFLOW_DELTA。后者不能篡改历史运行、输入、模型、权限或当时状态。
4. I4 的输出不是 worker 指令。它必须按 P-FORGE-SOP 冻结 Target-Q、Candidate-Q、Control-Q、C/F lane、source layer、controls 和 stop/reopen 条件。

## 5. B4：选择性父级/A3 重审

B4 只在 B3 产生 I2 或 I3 后开始。每个受影响 owner 按下列顺序处理：

1. 读取原子卡/父级/A3 当前全文和其直接来源；
2. 固定旧断言、旧 source scope、旧 Q 状态与旧 stop/reopen；
3. 写明文献回流的 exact envelope、路线卡、改变的 RB-D 维度；
4. 说明此改变是 payment、route mismatch、task switch、layer control、transport anti-analogy，还是来源不足；
5. 给同一任务正负控制和可推翻条件；
6. 在 SOURCE_BACKFLOW_DELTA 中写新的范围结论；
7. 原位更新受影响的 current statement，并保留历史由 Git/旧审计承担；
8. 运行链接、分片、来源与 diff 验证，精确路径 commit，然后重读 owner。

## 6. 结果的两类闭合

### 回流完成但无新 Q

这是有效结果。可写：

~~~
LITERATURE_BACKFLOW_COMPLETE_WITH_SCOPE
SOURCE_FRONTIER_REFINED
ZFC_SITE_SELECTED
Q-0 UNFORMED
ZFC_Q_NOT_LOCATED
~~~

它表示：已冻结的路线库存都获得来源/任务/支付处置；它绝不表示世界上已无文献或 ZFC 已无 Q。

### 回流产生候选资格

只有全卡经过 CANDIDATE_Q_ELIGIBLE，才可写：

~~~
LITERATURE_BACKFLOW_PRODUCED_Q_QUALIFICATION_CANDIDATE
Q-0 → Q-1 SEED
FORGEINTENT_REQUIRED_BEFORE_ANY_THEORY_CLAIM
~~~

这个结果仍必须等用户启动相应 P-FORGE 工作。没有三刀同卡会合，严禁写 Q-4、ZFC_Q_LOCATED 或“ZFC 悖论”。
