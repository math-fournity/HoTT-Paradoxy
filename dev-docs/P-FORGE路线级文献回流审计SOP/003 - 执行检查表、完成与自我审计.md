# 执行检查表、完成与自我审计

## 1. B0--B5 的有界流程

| 阶段 | 目的 | 最小产物 | 通过/停止条件 |
|---|---|---|---|
| B0 Evidence Freeze | 固定可复核的文献输入与 authority status | LiteratureEvidenceEnvelope | 未冻结即 BACKFLOW_INPUT_NOT_FROZEN 并停止 |
| B1 Route Inventory | 从来源建立 R/Z/H0 路线库存和最小缺口 | RouteInventory | 每条路线有 R、Z、缺口和 admission/stop |
| B2 Route Cards | 按 RB-D01--D16 写 RouteBackflowCard | 完整路线卡 | 缺关键维度只能 EVIDENCE_INSUFFICIENT |
| B3 Impact Triage | 判定 I0--I4 与受影响 owner | ImpactLedger | 没有 exact old/new delta 不得重开旧审计 |
| B4 Selective Re-audit | 对 I2/I3 写 source-facing addendum | parent/A3 delta | AS_RUN 保持；候选不得改 dev current truth |
| B5 Synthesis and Self-Audit | 写回流综合、自检、下一入口 | synthesis + self-audit | 逐卡 remainder=0；范围、未知、停止条件可见 |

阶段间不能跳过：B2 不能以 B1 名称替代；B3 不能以“文献很多”推定影响；B4 不能以新的说明文字重写历史；B5 不能以总论替代逐路线卡。

## 2. 标准 checklist

### CL-0：角色、原意与范围

- [ ] 当前角色是 GOVERNANCE_ALIGNMENT；当前动作保护的是“锻刀与 Q 发现同一共同收敛过程”。
- [ ] 已回读核心认知中的理论级靶、罗素计算—存在—自指、明显核心承诺、一遍匹配和不遍历全部细节的直接原文。
- [ ] 已区分：用户的发现性假设、来源事实、路线推断、尚未闭合的数学/哲学结论。
- [ ] 已确认本轮不是候选分支集成、worker 调度或数学证明任务。

### CL-1：LiteratureEvidenceEnvelope

- [ ] 当前 dev HEAD、candidate ref、source commit、common base、target HEAD 和 worktree 状态已实际核验。
- [ ] 已列 selected/excluded commits，未把广泛 snapshot 或 dirty 文件自动纳入。
- [ ] 每项采用 source 都有 manifest/hash 和页/行 locator；没读到原件的材料标为未核验。
- [ ] authority_status 已判为 FROZEN_CANDIDATE_ONLY、CURRENT_EVIDENCE 或停止态。
- [ ] candidate/current、archive/current owner、worktree/ref 三种身份没有混用。

### CL-2：路线库存与卡片完整性

- [ ] 每条路线都写出 R_i、候选 Z_i 和其最小差异，而非术语相似。
- [ ] 每张 RouteBackflowCard 覆盖 RB-D01--RB-D16 或给出明确 N/A/不足理由。
- [ ] T/u/F/C/I/O/Done 均有来源支持；没有用“理论很基础”代替 consumer。
- [ ] 所有 P1/P2/P3 的正面和缺失都标出来源层。
- [ ] H0→Z0 如被主张，T0--T5 已逐门审查。

### CL-3：支付、失配与控制

- [ ] 每一 suspected tension 都有 payment/guard 检查。
- [ ] Power Set-subset 与 RepFun、模型与 bare ZFC、proof layer 与实际 consumer 等路线差异未被合并。
- [ ] 已给正控制、负控制、same-task control 和可推翻条件。
- [ ] 一条来源的 payment 只关闭其声明的任务，不外推为 ZFC 全面防御。
- [ ] 任何模型、proof assistant、元语言事实均保留 SOURCE_LAYER_CONTROL 边界。

### CL-4：P/Q 与影响

- [ ] 逐卡分开 Target-Q、Candidate-Q、Control-Q 和 Q 状态前后。
- [ ] I0--I4 有 exact old/new evidence；没有影响则明确 NO_IMPACT_ON_CURRENT_AUDIT。
- [ ] I2/I3 仅在 CURRENT_EVIDENCE 下改 current owner，并且 AS_RUN 与 SOURCE_BACKFLOW_DELTA 分栏。
- [ ] I4 仅产生资格化 ForgeIntent；没有把它写成 Q-4、ZFC_Q_LOCATED 或数学结论。
- [ ] 已检查文献回流是否真正提高 Q 的可检验性；若仅增加工具/文档字段，判 TOOL_ONLY_DRIFT。

### CL-5：写回、验证、结束

- [ ] 每个 durable fact 写到唯一 owner；README 只加入口，MEMORY 只加队列/下一步。
- [ ] 回流卡、影响账本、addendum 和综合之间有双向链接。
- [ ] 已运行适用的分片、来源、链接和 diff 检查，并保留命令/版本/输出范围。
- [ ] 只 stage 当前路径；未把候选 worktree 或主树的并行 dirty 文件混入。
- [ ] 最终写清 execution boundary、未知、停止条件和 reopen_if。

## 3. 完成、暂停与重开

### 完成条件

只有同时满足下列条件，才可写 LITERATURE_BACKFLOW_COMPLETE_WITH_SCOPE：

1. B0 有有效 envelope，所有 B1 路线都处置为一张 RouteBackflowCard 或有明确排除；
2. 卡片数与路线库存数一致，remainder=0；
3. 每张卡有 RB-D01--D16、判词、control、falsifier、action 和 stop/reopen；
4. I2/I3 的每一项都已经选择性回接，或清楚说明为何当前只保留 candidate draft；
5. 所有 current-owner writeback 经结构/来源/diff 验证并精确 commit；
6. 最终综合没有越过“来源/方法结论”边界。

### 合法停止

下列任一情况应停止当前执行而不是以更多解释填洞：

| 状态 | 含义 | 下一步 |
|---|---|---|
| BACKFLOW_INPUT_NOT_FROZEN | ref、commit、target 或 source identity 未冻结 | 仅完成 B0 或等待可复核包 |
| CANDIDATE_INTEGRATION_REQUIRED | 卡需要改变 dev owner，但 evidence 仍是 candidate | 交给 canonical integrator 的单独集成流程 |
| SOURCE_CARD_INSUFFICIENT | 缺关键一手 locator 或 same-task 数据 | 登记最小 source gap |
| ROUTE_FIDELITY_UNRESOLVED | 不能判断 formation/consumer route 是否相同 | 保持 ROUTE_MISMATCH_PENDING |
| Q_QUALIFICATION_REQUIRES_USER_START | I4 已形成但需要新的 ForgeIntent | 等待用户用 P-FORGE-SOP 或另行指令启动 |

### 重开触发

重开只由以下事件触发：候选或 dev HEAD 改变；一手来源/manifest 被修正；新来源改变 RB-D03--RB-D14；已有 payment/control 被反驳；用户改变 P/Q、Power Set 或 H0/Z0 的目标定义；被集成的候选使 authority_status 从 candidate 变为 current。

## 4. 本 SOP 自身的自我审计

每次修订本 SOP，且每次 B5 结束时，按下列问题形成独立 self-audit：

1. 它是否把“锻刀与找 Q 是同一件事”编译为每张路线卡的 Q 状态、影响和下一动作，而非只在序言复述？
2. 它是否将 R_i、Z_i、Q_i 与 H0、Z0、Q0 分层，阻止由动机或技术相似直接得出理论结论？
3. 它是否保留了 AS_RUN 历史事实与后来来源回流之间的时间差？
4. 它是否要求 actual consumer、formation route、T/u/F/C/I/O/Done、payment 和同一任务控制？
5. 它是否允许负校准、route mismatch、支付与反类比成为有价值结果，而不把它们当作“理论安全”的总判词？
6. 它是否包含候选 worktree/current owner 的权限边界，以及候选证据不能自行改 current truth 的规则？
7. 它是否对文献输入、路线卡、影响、写回、验证、停止和重开都给出可执行 checklist？
8. 它是否避免创建第二套研究数据库、全量重跑 130 卡、自动 worker 或自动集成等与当前结果无直接关系的设施？

当前首次自审由 audit/20261003-P-FORGE-LITERATURE-BACKFLOW-SOP-SELF-AUDIT.md 拥有。该报告审计的是本 SOP 的设计和写入，不能冒充 B0--B5 已实际运行。

## 5. 供 /goal 使用的启动词

当研究发起人要实际启动 B0--B5 时，可使用：

~~~
按照SOP=P-FORGE-LITERATURE-BACKFLOW-AUDIT-SOP，继续推进，直至无法推进。
~~~

这句会启动本 SOP 的执行合同，而不是本 SOP 的制定工作。它从 B0 重新冻结候选/当前证据开始；没有 B0 通过，不进入文献结论、集成、P-DAG worker 或新的数学主张。
