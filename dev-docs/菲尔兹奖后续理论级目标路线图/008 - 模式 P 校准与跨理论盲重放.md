# 模式 P 校准与跨理论盲重放

> **身份：** `METHOD_CALIBRATION_DRAFT / PROMPT_BOUNDED_BEHAVIOR_EVALUATION / NOT_A_MATHEMATICAL_RESULT`。
>
> **目的：** 这项工作的交付物首先是能有效引导首轮理论定位的模式 P，不是替 ZFC 或 HoTT 提前宣布一个问题已经成立。HoTT 的无泄漏重放是 P 的基准；ZFC 的 Power Set 或更好位置是 P 通过基准后才有解释力的外推检验。

## 1. 重新确定工作单位

用户要求反复打磨的对象是模式 P 本身。它应当把“罗素的计算—存在—自指张力”变成一个可给 AI 消费的结构，使 AI 不必遍历理论的全部衍生细节，仍能在理论 X 的**明显、中心、对象级**承诺附近提出可审的 `u/F/Q` 线索。

因此，下列三种结论必须分开：

| 层 | 可接受的证据 | 不能声称什么 |
|---|---|---|
| P 的选择能力 | fresh、无答案泄漏的代理选到预先声明的理论位置 | 该理论已有缺陷或 UR。 |
| P 的过程能力 | 代理给出具体 `Q`、依赖形状、消费者与同一任务卡，且可被控制反驳 | P4/P5/P6 已由数学证明。 |
| 候选的数学／现实地位 | 原典、版本固定的消费者、控制、必要时形式证明与现实任务证据 | 单次代理输出足以决定理论真伪。 |

第一次 ZFC 探针落到 `Ord/V`，说明原 P 把对象层与元语言总体混淆。加上 `L0–L2` 后，未给出 Power Set 名称的复测选到幂集公理。这是一条**选择能力的局部证据**，不是 P 的完成证书。

## 2. P 的当前可测试规格

### 2.1 入口门：决定什么有资格进入 P

`L0–L2` 先于 P0–P6：

1. **L0 对象／接口层。** `u` 必须是理论 X 的原生一等对象、域或可用接口；不能把外部模型、真类或课堂说明直接当靶。
2. **L1 核心形成／承诺。** 必须定位一条核心规则、闭包、识别或可用性承诺，由它把 `u` 作为理论能力的可重复中心交出；理论变体和可选扩展须明示。
3. **L2 内部交接。** 同一个 `u` 必须在不换题的情况下进入后续内部规则、判断、消去、传输或真实消费者。

这三门不要求所有理论都模仿 ZFC 的幂集形式。对 HoTT，`u` 可以是原生 universe／identity interface；关键是它确实在该变体的对象语言和规则中起作用，而不是只存在于外部语义。

### 2.2 罗素动态核：决定候选是否可深化

在 `L0–L2` 通过后，固定 `P0–P6`：计算性形成／使用读法，必入对象，不可另账，精确存在性／身份／可用性追问 `Q(u)`，直接或上升式依赖，追问未落定前的实际预支使用，以及保持输入、操作、观察和 Done 的同一任务 UR。

P 的强制反误配规则是：

- 不能由“无穷”“高维”“不可计算”“不完备”或一次 timeout 自动取得 P4；
- 不能由理论的裸 `∃u` 自动取得 P3，也不能把研究者加上的枚举或算法要求归给理论；
- 不能用换成局部版本、外部模型或不同 Done 条件的办法冒充 P2、P5 或 P6；
- 不通过 `L0–L2` 的输出记录为 `META_LAYER_CAPTURE`，作为 P 的负控制，而非新的理论候选。

## 3. HoTT 是 P 的第一基准，不是旧答案复述题

HoTT 重放的目标不是把本仓库已有结论改写一遍。一个合格盲重放必须：

1. 不向代理提供本仓库的已知靶、候选名、证明文件、路线图、历史回答或结果措辞；
2. 只提供版本化的 P 规格和对 HoTT 的中性理论范围；代理可使用一般已学习的数学知识；
3. 要求它固定一个 HoTT 变体，区分核心规则与可选公理／扩展，并选择唯一的 `u/F/Q`；
4. 交付 `L0–L2`、P0–P6、反控制、真实或候选消费者、同一任务卡和明确的未知；
5. 把“选到与既有 HoTT 罗素线有可核重叠的位置”与“重放了既有机器证明”“证明 HoTT 有缺陷”严格分开。

预先声明的失败分类如下：

| 失败码 | 含义 | 应怎样修 P |
|---|---|---|
| `META_LAYER_CAPTURE` | 选中外部模型、元语言或非一等对象。 | 收紧 L0/L2。 |
| `GENERIC_SLOGAN` | 只说高维／无穷／自指，未固定 `u/F/Q`。 | 收紧 L1 与 P3。 |
| `ANSWER_LEAK` | 输入、路径或措辞给出了已知结果。 | 该 run 作废，重建隔离任务包。 |
| `TASK_SWITCH` | 通过改变输入、观察或 Done 制造了困难或消解。 | 收紧 P2/P6。 |
| `OVERASSERTION` | 将线索、超时或标准定理说成 P4–P6。 | 保留反控制并降级结论。 |
| `MISSED_CORE_SITE` | 未选到预先声明的核心位置，却无更强的对象级理由。 | 回查入口门与理论卡，而不是替输出找借口。 |

## 4. 行为试验顺序与隔离

```text
冻结 P 版本和 HoTT 的中性范围
  → 一名 fresh Terra / Max 代理无文件／无网络盲重放 HoTT
  → Master 对照既有 HoTT 位置、检查泄漏与失败码
  → 修订 P，保留旧结果为负控制
  → 另一次 fresh HoTT 重放确认不是偶然措辞
  → 才以同一冻结 P 进行 ZFC 盲匹配
  → 比较 Power Set 与任何更强的对象级竞争位置
```

在其它目录启动 Codex CLI 的 Terra / Max 实例可以成为后续独立运行面，但不能只因目录不同就称为独立或无泄漏。每个实例都必须冻结：准确的模型／effort 请求、P 文本哈希、理论卡、可见路径、禁读路径、网络与写入权限、启动命令、输出、终态和可能的上下文继承。工具未返回独立 runtime model identity receipt 时，只报告请求字段。

## 5. ZFC 是外推，而不是 P 的训练答案

在 HoTT 重放完成前，不用 ZFC 的 Power Set 成功或失败来判定 P 是否写对。HoTT 是内部基准，因为它允许我们检查代理是否在不被告知答案的情况下重新接近既有的理论位置；ZFC 是不同理论结构下的外推。

冻结后的 ZFC 盲匹配应比较而非预设：Power Set 必须作为 `L0–L2` 下的基线位置，但代理若能给出另一个更强的对象级候选，也必须按同一规则和反控制比较。任何“更好”都至少要说明：为何它比 Power Set 更直接地承载理论不能回避的形成承诺；为何它不只是元层／真类／模型叙述；以及它是否能提出更具体、未被已有 guards 化解的 `Q`。

## 6. 当前停止条件

当前只进行 P 的方法校准和候选定位。除非一个后续单元完成精确 `Q`、P4、P5、P6 和同一任务证据，不创建 ZFC 的数学结论、内在矛盾声明、现实相对 UR 或新的证明义务。每次盲重放只能修改 P 的一个明确缺口，并把失败保留为下一版 P 的反控制。

## 7. HoTT 首次无泄漏重放：有效的负控制，不是成功重放

第一名 fresh Terra / Max 请求代理在未阅读项目材料和未得到既有 HoTT 靶名称的条件下，选择了一个由小 universe 索引的 W-type `W_𝒰`，并额外引入向下 smallness／resizing 证书 `s : Σ a:𝒰. Equiv (El a) W_𝒰`。条件于 `s`，它构造一个自子树边 `w ≺ w`。

这个输出有价值，但**不通过 HoTT 重放验收**。它触发三项预先定义的失败码：

| 失败码 | 在本次输出中的表现 | 为什么不能升格 |
|---|---|---|
| `MISSED_CORE_SITE` | 候选落在特设的“内部迭代树”变体，而没有重新定位到 HoTT 基础中已有、不可绕开的身份／universe 位置。 | P 的目标是先捕捉理论自身的明显承诺，不能从一个局部应用域替代整体靶。 |
| `ARTIFICIAL_EXTENSION` | 关键证书 `s` 是标准 predicative HoTT 没有承诺的额外 resizing／smallness 原理。 | 不能先假设理论拥有 `s`，再把 `s` 的后果算作理论对 `u` 的存在性或使用压力。 |
| `TASK_SWITCH / OVERASSERTION` | W-elimination 已使用 `W_𝒰`，而 `Q` 问的是另一个未提供的 `s` 是否存在；报告把这种并列称为 P5／P6。 | 这不是“同一个对象在 Q 未落定前被预支使用”；理论从未承诺 `s`，同一任务卡也变成了检验一个外加扩展。 |

因此，本次只支持一个更精确的 P 修订：除 `L0–L2` 外，候选在 P3 之前还必须通过 **`L3` 原生承诺门**：`Q(u)` 不得以理论 X 未承诺的额外公理、resizing、编码、商或外部语义作为它的唯一启动条件。若候选的环路只在加入 `e` 后形成，`e` 必须被标为竞争扩展／反控制，不能当作 X 的 P4/P5。

这条负控制正是此阶段的价值：P 没有靠“自指”一词自动成功；它暴露了下一次 HoTT 盲重放必须把**原生形成承诺、原生消费者、原生 Q**锁在同一理论变体里。完整可见报告和 Master 判词见 `audit/20261002-模式P-HoTT无泄漏盲重放-Terra-Max.md`。

## 8. 第二次 HoTT 重放：选回 universe identity 区域，仍未重放过程

加入 `L3` 原生承诺门和 `L4` 理论范围中心性后，新的无泄漏代理没有再选择 W-type resizing。它选择了 univalent HoTT 的 universe identity interface：由等价 `e` 形成 universe path `ua(e)`，再由 `J`／transport 消费该路径。这个位置通过 `L0–L4`，并且重新接近本项目既有 HoTT 主线的 **universe—identity—univalence** 区域。

但它仍不是成功重放。其 P4 只是普通的单向数据流

\[
e\to ua(e)\to \operatorname{transport},
\]

没有直接回环或上升式再问；更重要的是，`ua(e)` 立即回答了它自己定义的 Q，所以没有 Q 未落定时的消费者。代理正确把 P5/P6 标为未建立，却错误把普通依赖报告成 P4。由此得到下一版 P 的两条强制门：

1. **D0：Q 不可被同一引入规则即时清偿。** 若定义 Q 后，理论的原生规则正好直接给出它，Q 只是可用性查询，不是罗素式存在性／身份追问。
2. **D1：P4 必须是再入或非下降追问。** 普通 `input → witness → consumer` 链不算 P4；每一步必须把同一类 Q 原生地推到自身或严格更高、无预设终点的层，并固定其 generator、观察与停止条件。

下一次 HoTT 盲重放还须加入 **D2 原生无界生成器门**：若声称上升式 P4，必须指明理论自身已经承诺的构造族或形成规则，令同一 identity/availability 追问在任意有限层后仍产生下一层；不能由人工递归、外加 universe 或工具 timeout 充数。这样，P 才会从“选到正确接口区域”继续逼近“重放已有 HoTT 过程”。

## 9. 第三次 HoTT 重放：universe hierarchy 的规则形状仍不是理论原生 Q

加入 `D0–D2` 后，第三个无泄漏代理转向可数累积 universe hierarchy，提出 `Uᵢ : Uᵢ` 的同层闭合问题，并把 `Uᵢ : Uᵢ₊₁` 的规则 schema 视为无界生成器。它正确避免了 external resizing，并识别出一条严格上升的 universe 规则形状；但这仍**不通过**完整 P 的校准。

理由是：理论原生提供的是上升层级，不以 `Uᵢ : Uᵢ` 为自己正在等待解决的任务。把“同层自分类”指定为 Q，仍是在理论外加一个未被原生消费者要求的闭合目标；其报告也没有给出 P5，只把 universe 作为一般量化域。它还自行替换了 P0–P6 的正式量尺，不能被计为本项目的 P 评分。

这引出下一版的决定性门：

1. **L5 原生需求门：** `Q(u)` 必须由理论 X 已经承诺的形成、判断或真实消费者实际提出；不能仅仅是“如果理论还多给我一个同层／全局／自包含性质会怎样”。
2. **P5 先行检验：** 在投入 P4 的无界结构之前，先定位原生消费者怎样依赖 Q 的落定；没有这种依赖，任何上升链只能是背景结构，不能成为罗素式压力。
3. **量尺不可自换：** 盲重放必须使用冻结的 P0–P6 标签，不允许代理把它们改写成“对象、形成、消费者”的新数字表。

第三次输出因此保存为 `RULE_SHAPE_ONLY / Q_NOT_NATIVE_DEMAND / P5_ABSENT`。它说明 P 已能让代理反复看向 HoTT 的 universe 区域，却还没有稳定地让它构造出“理论自身在使用中不断重新提出的 Q”。这正是后续继续打磨 P 的工作点。

## 10. 脱敏朴素集合论正控制：P 可定位有限规格冲突型位置

在不出现历史名称或著名公式的任务包中，fresh Terra / Max 代理仅由无限制理解规则和成员关系，独立选择“以对象不属于自身为条件形成对象，再将该对象代入成员双条件”的位置，得到 `u∈u ↔ ¬(u∈u)`。有界形成、恒真条件、恒假条件均被用于控制。

这说明 P 脱敏后仍可引导模型定位朴素集合论的正确 formation/use 位置。它同时迫使 P 做一项重要分层：朴素集合论此处的结果是有限成员规格冲突；形成规则已经交付 `u`，因而不能未经分析地把它归类为 HoTT 式的“对象准入未决而被预支使用”或无界追问。完整记录见 `audit/20261002-模式P-朴素集合论脱敏正控制-Terra-Max.md`。

## 11. P1／P2 双轨提案：理论位置定位与计算—逻辑翻译不能互相吞并

用户指出，当前 P 的打磨并非错误，却可能遗漏另一条更接近其原始要求的道路：从计算视角不断形式化、解构朴素集合论的形成—代入—判断结构，再把这一结构翻译成逻辑／语言层的模式，帮助 AI 在理论 X 中寻找同形位置。此处暂称现有路线为 **P1**，新路线为 **P2**；这是待校准的研究设计，不是已经证明两者完备、等价或必然都有效的结论。

| 轨道 | P1：理论位置与使用次序定位 | P2：计算—逻辑翻译与模式匹配 |
|---|---|---|
| 起点 | 理论 X 的原生对象、形成规则、消费者与完成条件 | 一段脱敏的形成／代入／判断计算结构 |
| 首问 | 理论自身在哪个基础接口处形成、交接和使用 `u`？ | 哪些逻辑语言操作能把“形成的对象再进入生成它的判断”编译为同形计算？ |
| 主要产物 | `u/F/Q` 候选卡、controls、同一任务卡 | 一个有类型的逻辑／语言中间表示、翻译规则、可拒绝的匹配条件 |
| 典型误差 | 元语言总体、局部构造、外加公理、换题 | 把任意递归、任意否定、任意固定点误认作同形；漏掉类型／界／极性 guard |
| 验证 | 无泄漏理论定位、真实消费者、同一任务和 UR | 正／负控制的编译：无限制理解应给出有限规格冲突形；有界形成、类型／层级 guard 应阻断相应闭合 |

P2 的初始逻辑中间表示不使用历史名称，至少区分以下操作位置：

```text
Bind(φ)       ：语言允许一个条件／谓词 φ
Form(φ) = u   ：由 φ 形成并交付对象 u
Reenter(u,φ)  ：将 u 代回 φ 或交给同一判断接口
Polarity(φ)   ：φ 对被代入判断是肯定、否定或更一般的极性依赖
Close          ：形成规则与再入判断组合后产生的等式、蕴含、冲突或上升式新问题
Guard          ：已有界、类型、层级、证书、阶段或可用性规则怎样阻断 Close
```

P2 不能只寻找“自指”。它需要显式检查：对象由何种 binder/formation 形成；代入是否在同一语言层被允许；同一判断是否以反向、否定或不下降方式重现；以及 guard 是否将原计算改成另一任务。无限制理解的正控制给出有限规格冲突；有界形成的 guard 阻断无条件闭合。这正是 P2 可被形式化、可被反驳的起点。

双轨的升级纪律是：P1 命中而 P2 未能编译，只能说明一个理论位置值得继续审计；P2 命中而 P1 没有原生对象／消费者，只能说明逻辑形状相似。只有两轨在同一理论变体、同一对象、同一消费者和同一任务上会合，才有资格进入更强的来源、过程或机器验证。

## 12. P3 必要：恢复被 P2 原子化掉的构造时序

用户要求回到当初从计算视角看到的张力。其原文不只是说“代回后得到 `q↔¬q`”，而是：候选对象 `S` 的构造尚未完成、其是否已是论域可讨论元素尚未落定时，形成规则已经要求成员算符把 `S` 当作可用输入；在计算读法里，构造过程不断把自身拿入和拿出，无法完成。

这与 P2/v0 有一处决定性差别。P2 写作

```text
Form(φ)=u → Bridge → Reenter
```

并默认 `Form` 已原子地把 `u` 交付。它因而可以忠实表达有限的逻辑余式 `q↔H(q)`，却**不能直接表达**“`u` 仍是 pending 而 operator 已使用 `u`”这一先后次序。把 `Form` 当作瞬时完成，正是它绕开了原始计算张力的地方。

因此提出第三轨 **P3：Construction-State / Admission-Order Diagnostic**。P3 的最低状态语言是：

```text
Draft(u)             ：构造已命名 u，但尚未完成交付
Admitted(u)          ：u 已获论域资格，允许进入相应算符
NeedBuild(u)         ：完成 u 的形成仍有未满足义务
NeedEval(R(u,u))     ：形成义务要求判断／计算 R(u,u)
OperatorUse(R,u)     ：某算符把 u 作为输入使用
Guard                ：该算符是否要求 Admitted(u)
```

P3 的核心不是把历史集合论改造成标准形式系统的定理，而是明确建模一个**构造语义假设**：若某类 formation contract 的完成需要评估 `R(u,u)`，而评估该判断合法地预设 `Admitted(u)`，但 `Admitted(u)` 又只在 formation 完成后获得，则出现依赖环：

\[
\operatorname{Admitted}(u)
\leftarrow \operatorname{BuildDone}(u)
\leftarrow \operatorname{Eval}(R(u,u))
\leftarrow \operatorname{OperatorUse}(u)
\leftarrow \operatorname{Admitted}(u).
\]

这个环才是“算符先于存在性落定”的直接计算表达。它必须逐理论固定：什么算 `Draft`、何时授予 `Admitted`、哪个 operator 有该前置条件、formation 是否真的依赖该 evaluation、以及标准理论是否把 formation 作为原子存在公理从而拒绝这种构造语义。没有这些，P3 只是启发，不是理论 X 的缺陷结论。

三轨分工由此明确：

| 轨 | 保留什么 | 它不能替代什么 |
|---|---|---|
| P1 | 理论自身最应审视的对象、形成接口与消费者位置 | 逻辑反馈和构造状态的精确翻译。 |
| P2 | 已完成语言规格中的 `Bind/Form/Bridge/Reenter/Polarity/Guard` 反馈形状 | `Form` 进行期间的 pending／admitted 时序。 |
| P3 | 构造过程、资格授予、算符前置条件与未完成义务的依赖图 | 静态逻辑是否真的不相容、或理论对象的基础位置。 |

今后的升级条件不是“三轨都必须给同一种结论”，而是明确它们在同一理论、同一 `u` 和同一 consumer 上分别报告什么：P1 给位置，P2 给已完成规格的逻辑余式或 guard，P3 给构造时序是否存在未支付的准入依赖。P3 若不存在真实构造语义，只能报告 `CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`，不能把静态公理的存在断言伪写成运行中的非法程序。
