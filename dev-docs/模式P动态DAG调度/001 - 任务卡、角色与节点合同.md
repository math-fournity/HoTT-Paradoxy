# 任务卡、角色与节点合同

## 1. Master 的任务卡

每一轮先由 Master 冻结一张 `TaskCard`，而不是先启动若干泛泛的“找问题”代理：

```text
task_id / theory variant T / research target
u, F, C, Q, I/O/Done and layer (known / unknown fields separately marked)
source pack and hashes / theory-version boundary
current evidence level / controls / disallowed task switches
node budget / allowed access profiles / success and stop predicates
```

未知字段不是可由 worker 自行补造的空格。TaskCard 必须说明它们是否应由 P1、来源追踪、P2、P3 或 Battle 解决；未写出的字段保持 `UNKNOWN`。

## 2. 角色分工

| 角色 | 可以做什么 | 不能做什么 |
|---|---|---|
| Master | 冻结 TaskCard、选择 DAG、按证据增加节点、参与质询、复核来源、裁决并写回 current owner | 把自己的候选当作已裁决结果，或让同一提示预先迫使三刀一致 |
| P1 locator | 从 source 找 `u/F/C/Q` 的位置与同一任务，输出 L0–L7 MatchTrace | 把裸关系、外加算法或历史答案伪装成 consumer |
| P2 mapper | 核 Bind/Form/Bridge/Reenter/Polarity/Guard 的语言合同 | 因 P1 选中对象就假定 feedback 存在 |
| P3 mapper | 核 source 是否真有 pending/admission/completion transition | 把静态存在公理或直觉构造时间改写成运行语义 |
| source tracer | 读取版本固定原典、形式化库或实际数学消费者，补 source locator 与 I/O/Done | 替三刀直接宣告理论缺陷 |
| challenger / arbiter | 对一项明确分歧做 source-by-source 质询或裁决 | 以投票、修辞或隐藏思维链取代证据 |

Master 也可形成 `MASTER_CLAIM`。这类 claim 必须进入同一 Battle／来源复核路径；Master 不能独自既提出又以“Master 裁决”将其升级。

## 3. NodeCard

每个实际 worker 只收到自己的 `NodeCard`：

```text
node_id / parent evidence IDs / one objective / explicit non-goals
exact model and effort / runner / sandbox and approval profile
access profile / allowed files, branches, URLs and tools
input hashes / answer-leak exclusions / output schema / prelaunch receipt locator
observation cadence / operator-review rule / cancel rule / partial-output policy / recursion=false / no-write rule
trajectory policy / expected native source views / private audit root / terminal audit predicate
reasoning visibility boundary / L1-L5 claims requested or explicitly out of scope
acceptance predicate / expected failure states / successor trigger
```

本任务的 worker 固定请求 `gpt-5.6-terra` 与 `max`。它们经 App Server 或 fresh CLI 启动；不得因为某一接口只支持其它原生 profile 而静默换成不同模型或 effort。每个 worker 默认只读、不可委派子 worker、不可提交、推送、修改项目或外部系统。

NodeCard 必须在启动前以 audit/session 中可定位的文字或哈希封存，不能等节点结束后凭记忆重建。`operator-review rule` 说明何时必须让 Master 审视 private wire／liveness，例如预算提示、失联迹象或用户取消；它不能把经过的秒数编码为自动终止。若将来使用另行资格化的人工中断控制器而仍无 terminal output，Master 才可记录 `OPERATOR_INTERRUPTED_NO_TERMINAL_OUTPUT`、取消方式和可观察终态；未封存的 prompt/source、网页搜索中间态或 agent plan 不得回填为 source fact。这个边界保留 `P-DAG-SOURCE-003` 的历史收据，但不把其 CLI source-node 做法推广到 App Server 理论 worker。

`source-match` NodeCard 还必须冻结一个**可执行的 prompt-input preflight**。在借用认证或启动 App Server 前，Master 用当前 runner 的 `read_frozen_turn` 读取 prompt，确认它恰有一个标注为 `text` 的 fenced block，且该 payload 内含精确 `You are a P-VALIDATION source mapper.` 与 `BEGIN FROZEN SOURCE CARD`／`END FROZEN SOURCE CARD` 标记；若本卡要求 field relay、Gate Ledger 或 `PowerSetDefenseLedger`，还要在抽取后的 payload 内逐项检查父 TaskCard／Ledger 的精确字段标签。这个预检的成功或失败是 NodeCard 的 prelaunch receipt。缺一项即 `INPUT_CONTRACT_FAILURE / NO_AGENT_OUTPUT`：不进入 auth、prompt-input gate 或模型采样，旧 prompt 保留，新 run ID 只作这一功能性修复。

若节点提出“静态理论形成应与某个 construction process 对照”，NodeCard 还必须携带 P3-C `ConstructionBridgeCard`：TheorySide 的 `T/u/F/I/O/Done`、BridgeSource、ProcessSide 的 representation/input/operation/observation/Done、逐字段 map、有限／类型范围、正控制与 task-switch control。没有可追溯 BridgeSource 时不启动 P3 state mapper；输入、对象或 Done 发生替换时，结论只能是 `INTERPRETATION_BRIDGE_TASK_SWITCH`，不能由 worker 把外部 enumeration 或耗时填入理论状态。

所有 P-FORGE NodeCard还要包含 `QConvergenceLink`：`Target-Q`、`Candidate-Q`、`Control-Q`、activation lane、Q状态前后、预期的`Q_GENERATE`／`Q_NARROW`／`Q_BRIDGE`／`Q_CONVERGE`／`Q_REJECT`、同一任务控制与反证。`C_LANE`必须有来源C/I/O/Done、active demand和正义务；`F_LANE`只允许已声明核心formation的probe，且要列u/F、非存在重述、反控制和将来P2/P3或consumer source。若节点只是修复错误分类，须记录它保护的具体卡和`Q_SAFETY_REPAIR`回归。fixture节点可使用`Q_CAPABILITY_CALIBRATION`，但须额外冻结Target-Q、被校准的P字段、正负fixture、将消费能力的下一真实source card和停止条件；Candidate-Q应明确为`NONE`，它不能被写成理论Q。没有任一联系的工作是`TOOL_ONLY_DRIFT`，不能作为理论节点启动或计入锻造推进。

凡属于 ZFC／Power Set 站位的 NodeCard还要包含：`SourceLayerTarget`、当前/预期 `CAL-*`、Round ledger ingress或重复-guard理由、以及对 `STATION_RETAIN`／`STATION_EXIT_REVIEW_PENDING`／`STATION_SWITCH_CANDIDATE` 的预计影响。它们不由 worker 投票决定；Master 在 worker前冻结，并在自然单元后按 013 复核。Q link、CAL、来源层和station是相互检查的字段，不能以其中任一项替代其它三项。缺这些字段的卡是 `FORGE_INTENT_INSUFFICIENT`，不能以“先跑一次再说”绕过。

对可实时从 App Server wire／liveness 观察的盲态理论节点，默认设置 observation cadence（通常 60 秒）而不自动 interrupt；十分钟或更长的持续 reasoning 本身不是失败。当前 runner 的 CLI 没有 `hard-timeout` 参数，也没有自动 `turn/interrupt` 路径。预算、外部服务成本、失联和用户取消先进入 Master 的明确复核；需要人工中断时，必须先资格化独立控制路径。`P-DAG-SOURCE-003` 的 4 分钟 web-source 观察窗仍是它自身的历史 source-node 规则，不能泛化成 App Server 理论思考的上限。

若 NodeCard 使用 Codex App Server且结果会进入 Master 的材料性判断，`trajectory policy`默认是`REQUIRED_AFTER_TERMINAL`：
它预先指定 private wire/rollout/export 的预期身份、thread/turn、是否需要 L1 context、L2 selected read、L3 recall、
L4 cognition或 L5 behavior，以及 output/summary 的公开边界。真正启动前不要求有 trajectory；终态后才由 Master 按
当前 shared reader 生成 `TrajectoryReceipt`。没有 persisted rollout但有 bidirectional wire时保持来源`PARTIAL`而非
把节点写成无轨迹；Host给出的 reasoning summary只可作为 summary，不能被要求补成或解释成完整推理。

## 4. 共同输出

所有节点均交付：

```text
Claims / Evidence / Conflicts / Unknowns / Mutations / Verification / Recommendation
```

凡涉及 P1/P2/P3 位置、映射、guard 或裁决，另必须交付 [MatchTrace](<../模式P三把刀/010 - 代理匹配自我说明合同.md>) 的 `E0–E7`。公开说明的是 source→字段→选择→最小推演→反事实的可复核理由；不得索取或保存模型隐藏思维。

`Mutations` 对 worker 必须是 `none`。若一个节点没有形成可用结论，它仍要说明是 `NO_POSITION_CARD`、`SOURCE_CONSUMER_GAP`、`GUARD_BLOCKED`、`CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`、`BATTLE_INCONCLUSIVE` 还是其他带范围状态。若 runner 在模型采样前失去连接，则 Master 记录 `RUNNER_CONNECTION_FAILURE / NO_AGENT_OUTPUT`，不能把这项环境失败误写为 agent 的 source verdict。

`TrajectoryReceipt`是 Master 的运行证据附件，不要求 worker输出隐藏思维。它至少列 source view、reader/version、raw
locator范围、thread/turn、tool/approval、terminal、L1–L5状态、private artifact mode和未知。若 reader对已验证的
direct App Server envelope产生`unknown`，状态为`TRAJECTORY_PARSER_COVERAGE_GAP`；不得用 final answer或模型自述填补。
