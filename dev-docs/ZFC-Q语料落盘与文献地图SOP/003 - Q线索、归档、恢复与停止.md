# Q线索、归档、恢复与停止

## 1. Q LeadCard，不是 Q

一个 work family 只有在原件、书目身份和所需阅读范围已核验后，才能形成 Q LeadCard：

| 字段 | 要求 |
|---|---|
| QL ID / Work ID | 精确连接 work family 与原件／MinerU locators。 |
| 理论位置 | ZFC变体、对象、formation或实际consumer。 |
| 线索形状 | P1/P2/P3/P5/P6、H0→Z0、Power Set或其它明确位置。 |
| 来源事实 | 精确引文、页码、版本和原PDF locator。 |
| 竞争读法 | source payment、task switch、model/proof layer与标准回答。 |
| 分流 | HOTT-MOTIVE-ZFC、P-FORGE、专门source run、control或拒绝。 |

Q LeadCard 只说明“值得进入专门资格化”。它不等于 ZFC Q，也不自动授权P-DAG、worker或数学结论。

## 2. Archive layout

每个 corpus batch 使用：

```text
audit/ZFC-Q-CORPUS-MAP/<batch-id>/
  MANIFEST.md
  WORK-FAMILIES.md
  ACQUISITION.md
  PDF-VALIDATION.md
  MINERU-DERIVATIVES.md
  SEARCH-LOG.md
  SCREENING.md
  CITATION-NETWORK.md
  COVERAGE-MAP.md
  Q-LEADS.md
  FINDINGS.md
  originals/
  derived/
```

原件与派生物不得混放。每次下载、版本替换、MinerU parse、引用发现或Q lead分流都在相应owner中记录；项目根 README 只做批次入口和当前范围说明。

## 3. 完成与恢复

一个 batch 达到 `COMPLETE_WITH_SCOPE` 必须满足：

1. manifest中每一个 seed、work family和强引用都有 acquisition／unavailable／exclude disposition；
2. 已接受PDF都通过身份核验，所需MinerU处理有成功或失败记录；
3. search、screening、citation、coverage和Q leads的remainder可重算；
4. findings明确说明已完成范围、未完成范围和下一ingress；
5. 没有把access URL、MinerU文本、题名相似或书目数升级为Q。

恢复时先读取总SOP、项目 archive root、最近batch manifest和coverage map。新DOI、作者原典、citation expansion、可得全文或实际consumer可以建立新batch；同义检索、重复下载和已关闭Q卡不得自动重开。

## 4. 调用和权限

用户可在 `/goal` 使用：

```text
按照SOP=`ZFC-Q-CORPUS-MAP-SOP`,继续推进，直至本轮冻结语料没有可获取、可处理、可映射或可资格化的下一项。
```

这授权公开文献发现、原件落盘、PDF核验、MinerU本地派生、地图和Q lead routing。它不授权绕过数学证明门、P-DAG／worker、修改数学STATE、Power Set station、tag、push、发布或把浏览器下载路线当作学术权威。
