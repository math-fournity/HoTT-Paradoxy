# 终期验证、交付物、恢复与启动词

## 1. Phase 4：确定性随机抽样引文核验

目的：证明内容确实进入过执笔者的持久产出（而非仅凭哈希宣称），并给"读过"一个可反驳的检验。

1. **种子**：冻结于 manifest（002 片 §2.3），任何时点不可更换；
2. **抽样方法**（完全确定性，不依赖随机库）：对文件 f 的每一行 i 计算 `h = sha256(seed + f + ":" + str(i))`；按 h 的十六进制串升序排序，取前 K=20 行（即"哈希最小的 20 行"）；排序键与并列打破规则（行号升序）写入脚本；
3. **引文规则**：行 ≤200 字符 → 逐字引用；>200 字符 → 前 200 字符＋总字符数＋整行 SHA-256；
4. **核验**：验证脚本按同一规则重算抽样与引文，与 D1 中所载逐条比对；任何一条不符 → G4 FAIL；
5. 抽样行可能落在 SHARED 区间——引文仍锚定在该文件自身行号上；
6. 抽样在**全部读完后**才写入 D1（防止预读答案的疑义）；种子虽事先冻结，样本在写作时才知道内容——这正是该检验的证明力所在。

## 2. D1 覆盖证明的格式

`audit/GUI-ASSET-RECOVERY/COVERAGE-PROOF.md` ＋ `coverage.json`：

- 每文件表：总行数 / SHARED 行数（指针数）/ READ 行数 / RELOAD 行数 / 收据数 / 抽样引文 20 条；
- 总账：八文件行数合计 T（以冻结数为准）、义务行 D、covered=D、remainder=0；
- 验证脚本的完整输出原文（不裁剪）；
- 诚实边界声明：本证明的可审计代理性质（哈希＋行号锚定笔记＋抽样引文）；"主观阅读体验"不在可证范围内。

## 4. 停止条件、失效与重开

- **完成**：G1–G8 全过，且 D1–D4 落盘并通过脚本；`认知闭包/GUI-ASSET-RECOVERY-001.md` 状态改 `TOTAL_CLOSED`；
