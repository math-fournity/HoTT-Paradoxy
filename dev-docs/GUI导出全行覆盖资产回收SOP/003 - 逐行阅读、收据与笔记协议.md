# 逐行阅读、收据与笔记协议

## 1. 分块规则

- 块大小 **150–400 行**（执行者上下文 ≥100 万 token 时可放宽至 **≤600 行**，见 005 片 §7）；按内容密度调整：机械块/环境块密集区可取上限，语义密集区取下限；优先在 `## User` / `## Codex` 边界切块；块间不重叠、不留缝；
- 每文件从其第一个义务行（UNIQUE 区间起点）推进到最后一个义务行；SHARED 区间跳过（指针已在 manifest）；
- 块进度按阅读顺序推进；中断点任意，但**每块读完必须先落盘收据与笔记，再读下一块**。

## 2. 亲读动作的定义

1. 用 Read 工具（offset/limit）读当前块的原文——块内每一行进入上下文；
2. 立即写收据（`ledger.jsonl` 追加一条）与笔记（`notes/<tag>.md` 追加一节）；
3. 收据中的块哈希必须由脚本按行区间精确计算（禁止手抄估计）；
4. "亲读"的可审计代理 = 收据（哈希）＋该块笔记中的行号锚定内容。两者缺一不可：只有哈希没有内容笔记＝无效覆盖（G3 拒绝）。

## 3. 收据 schema（`audit/GUI-ASSET-RECOVERY/ledger.jsonl`，append-only）

```json
{"rid": "R0007", "kind": "READ|RELOAD", "file_tag": "dev-03", "start": 9851, "end": 10150,
 "n_lines": 300, "chunk_sha256": "<精确字节切片哈希>", "seq": 7, "ts": "<ISO>",
 "class_counts": {"user_turn": 2, "codex_final": 1, "codex_mid": 6, "mech_env": 1, "mech_goal": 2, "filechange": 3, "other": 0},
 "salient_n": 9, "notes_ref": "notes/dev-03.md#R0007", "reload_reason": null}
```

- `kind=RELOAD` 的收据必须带 `reload_reason`（如"D2 叙事需要 L12043-12105 原文"）；
- 纠错不修改旧收据，追加 `{"kind": "CORRECTION", ...}` 条目指向被纠正的 rid；
- 账本任何时点必须可被验证脚本独立重算（G2）。

## 4. 分层笔记格式（`notes/<tag>.md`，每块一节）

```markdown
### R0007 · dev-03 · L9851-L10150
- 【用户轮·逐字】L9862：「……」（>200 字符：前 200 字＋len＋行 SHA-256 前 16 位）
- 【Codex 终局·逐字】L9940：「……」（同上规则）
- 【Codex 中间·要点】L9870-9935：三段进度叙述——每段一句要点
- 【资产】L9912：`ZFC-H9 规格表`（类别：概念/方法/形式化/来源/开放候选；→A-00xx；**一行一资产、不合并**，与 assets-ledger 条目 1:1，见 §9）
- 【FileChange 线索】L10149：`HoTT/formal/xxx.lean`（新增）
- 【机械块】L9851-9860 environment_context；L9936 codex_internal_context(goal)
- 【已读无资产】（当块无新内容时显式写这一分类）
```

- 分类计数必须与笔记中的条目对得上（G3 抽查）；
- 用户轮的"逐字"以导出原文为准；若轮内含 `<codex_internal_context>` 等注入块，注入部分归机械类，用户手写部分归用户轮；
- FileChange 胶囊每一行都登记（文件名＋操作），终期汇入 D3 的资产线索总索引。

## 5. 机械行与共享指针的处理

- 机械/模板行**同样亲读**（进入块的行区间即被读），笔记中以块级分类标记，不逐行摘录（R-3 裁定）；
- SHARED 区间不重读；若某 SHARED 区间在 D2/D3 写作时需要原文引用，走 RELOAD 协议（对**目标文件自身**的行区间重读并记收据——引用锚定在被引文件上）。

## 6. RELOAD 协议（"过去读的不再上下文中了，要重复加载"）

1. D2/D3/D4 动笔前，列出各文档需要的原文区间清单；
2. 凡该区间内容不在当前上下文（压缩后丢失、或从未以所需粒度过目）→ 对该区间执行 RELOAD：重读＋记收据（kind=RELOAD，带理由）；
3. 最终交付物中的每一处逐字引用，必须能指向一个 READ/RELOAD 收据或其所在块；
4. RELOAD 不改变覆盖归类（该行早已 READ），只补"当下在上下文"的证明。

## 7. 崩溃/压缩/换会话恢复算法

完整协议（常驻工作集、压缩触发判定、重载对照表、CL-A/CL-BR 清单）见 **005 片**；本节为最小摘要：

1. 读 `认知闭包/GUI-ASSET-RECOVERY-001.md` ＋ 本 SOP 全部五片 ＋ `ledger.jsonl` 尾部；
2. 用验证脚本核验最后一条收据的块哈希与文件仍一致（文件被改动则触发 manifest 失效流程）；
3. 计算第一个未覆盖义务行 → 从该处续读；
4. 恢复后第一块读前，快速回读账本中最近 5 条收据的笔记节标题，重建工作记忆的连续性；
5. 任何一步失败 → 停在 `PARTIAL`，如实登记，不得凭记忆续写笔记。

## 8. 执行纪律

- 先写后读下一块（收据落盘优先于一切）；
- 不跳块、不按主题挑读（那是 v1 的做法，本 SOP 禁止）；
- 每完成一份文件的义务区间，在账本追加一条 `{"kind": "FILE_DONE", "file_tag": ...}` 汇总条目；
- 会话结束（预算/人为）时追加 `{"kind": "CHECKPOINT", "next_gap": "<file:line>", ...}`。
