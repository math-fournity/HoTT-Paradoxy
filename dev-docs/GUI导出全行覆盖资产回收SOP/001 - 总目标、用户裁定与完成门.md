# 总目标、用户裁定与完成门

## 1. 任务的性质

这不是一次摘要或抽查，而是一场**阅读战役**：八份 GUI 导出的每一行，要么被执笔者亲自读过并留下收据，要么属于一段与已读内容逐字节相同的区间并有明确指针。它与 GPT 的 `P-FORGE-ATOMIC-AUDIT-SOP` 同构（分母冻结 → 原子执行 → 回接 → 综合），只是原子单位从"锻刀执行单元"换成"GUI 导出的文本行"。目的有二：其一，把 GPT 在 2026-10-02 至 10-05 八条 worktree 线上留下的过程资产**细化地**回收（用户原话：「有些"技术"积累，我不想这些技术积累粗糙的被扔掉」）；其二，让"读过了"本身成为可审计事实，而不是宣称。

## 2. 对象与范围

| 项 | 值 |
|---|---|
| 语料 | `git-worktree对话录/` 下八份 GUI 导出（dev-01/02/03/04/06/07/08/09；无 dev-05） |
| 语料身份 | 以 Phase 0 冻结的 `audit/GUI-ASSET-RECOVERY/manifest.json` 为准（每文件 SHA-256、字节数、行数）；冻结锚为执行开始时的 HEAD |
| 阅读义务 | manifest 去重后的独有行全集（义务分母 D，remainder 语义见 002 片） |
| 工作区 | `audit/GUI-ASSET-RECOVERY/`（manifest、账本、笔记、终期四件套） |
| 明确出界 | 原始 JSONL trajectory（除非 GUI 导出与 `git-worktree对话录/README.md` 出现矛盾需注释，不改读为审）；八份导出的原文一字不改；不产生数学结论；不重开 GPT 的任何判词 |

## 3. 四项核心合同

- **C1 每行亲读**：八份导出的每一行都被归类为 `READ`（执笔者亲自读过，有收据）、`RELOAD`（终期按需重读，有收据）或 `SHARED_POINTER`（与某已读区间逐字节相同，指针指向该收据）。`## User/## Codex` 标记、`<environment_context>`、`<codex_internal_context>`、FileChange 胶囊等机械/模板行**同样亲读**并在笔记中分类标记；FileChange 胶囊单独登记为资产线索。
- **C2 分层登记**：用户每一轮消息逐字摘录；Codex 终局/决定性陈述逐字摘录；中间过程按要点登记；资产逐条带行号锚定；机械块分类。超长行（>200 字符）摘录前 200 字符＋长度＋整行 SHA-256。
- **C3 可审计证明**：逐块收据含该块精确字节切片的 SHA-256；终期按冻结种子做确定性随机抽样引文核验；验证脚本从文件重算一切并与账本比对，输出 `PASS/FAIL`。主观"内容曾经过上下文"无法在压缩后直接证明，本合同给出的是最强可审计代理。
- **C4 跨压缩恢复**：收据与笔记在每块读完后立即落盘（先写后读下一块）；账本 append-only；压缩/换会话后按恢复算法从第一个缺口续读；终期写 D2/D3 前，凡需原文而已不在上下文的区间执行 RELOAD 重读并记收据——最终交付物全部由当下在上下文中的内容写成。

## 4. 三项用户裁定（2026-10-07，研究发起人经确认问答裁定）

| # | 裁定 | 内容 |
|---|---|---|
| R-1 | 抽取密度＝**分层登记** | 用户轮逐字＋Codex 终局逐字＋中间要点＋资产行号；机械块分类 |
| R-2 | 证明强度＝**哈希＋摘录＋抽样引文** | 逐块 SHA-256＋行号锚定摘录＋终期确定性随机抽样逐字引文回验 |
| R-3 | 机械行＝**全部亲读＋分类标记** | 严格满足每一行过目；FileChange 胶囊作为资产线索单独登记 |

## 5. 完成门 G1–G8

| 门 | 条件 |
|---|---|
| G1 | manifest 冻结且脚本重算身份一致；义务分母 D 与去重清单可由脚本从八份文件完整重算 |
| G2 | 账本覆盖 D 的每一行；每条 READ/RELOAD 收据的块哈希经脚本从文件重算一致 |
| G3 | 每块笔记存在：≥1 条行号锚定的要点/资产条目，或显式 `已读无资产` 分类 |
| G4 | 抽样引文核验 PASS（种子冻结于 manifest；每文件 K=20） |
| G5 | D2 八线全程叙事完成（每线从头到尾的发展脉络） |
| G6 | D3 资产登记 v2 与 D4 原索引修订建议交付；v1 两份初步报告被明确标注为 preliminary 并指向 v2 |
| G7 | D1–D4 相互一致（抽查行号锚定互指不矛盾） |
| G8 | 总账：八文件全行（126,503 量级，以冻结数为准）全部归类 `READ/RELOAD/SHARED_POINTER`，remainder=0 |

**停止条件**：只有 G1–G8 全过才准结束。预算耗尽/环境故障时，如实留下覆盖表（remainder≠0）＋下一缺口位置＋恢复入口，**不得宣称完成**。
