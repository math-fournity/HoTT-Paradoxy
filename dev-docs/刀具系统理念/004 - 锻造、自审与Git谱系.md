# 锻造、自审与Git谱系

## 1. 模式 P 刀具锻造与理念自审 SOP

唯一执行 SOP 名称为 **《模式 P 刀具锻造与理念自审 SOP》**，canonical 路径是 `dev-docs/模式P动态DAG调度.md`（文件旧称“模式 P 动态 DAG 调度”，仍是同一 owner）。每次新的或恢复的 `/goal`，在作实质性目标判断前，都按 SOP 完整读取本理念索引及 4 个分片，再读 SOP 索引与全部分片。

可直接在后续 `/goal` 中写：

```text
请执行《模式 P 刀具锻造与理念自审 SOP》：先完整读取
dev-docs/刀具系统理念.md 及其全部分片，再读取
dev-docs/模式P动态DAG调度.md 及其全部分片；按 current Goal 恢复工作，
完成本自然单元的 delta SelfAuditCard，并把有效刀具修订精确提交到 Git。
```

## 2. 每个自然单元必须逐项审的维度

每张 delta `SelfAuditCard` 至少包括：

1. 当前 source unit 的直接用户原文、hash／档案身份、时间段和 `IN_SCOPE`／前驱／排除理由；
2. 该原意在《刀具系统理念》哪一项，原话要求了什么、禁止了什么、开放了什么；
3. 实际 Goal/TaskCard、理论位置、每把刀、NodeCard、prompt、来源、反控制、轨迹、输出和 Git 变化；
4. 每条意图到实现／运行证据的 locator，不以 SOP 自述、AI 总结或分支提交替代；
5. 对齐判词、偏差类型、影响到的刀具字段／访问边界／当前结论、直接修复或停止动作；
6. 最小反事实、source falsifier、新的正负控制或“没有变化”的理由；
7. Power Set／ZFC 单元还须说明本轮如何处理“已加强 Russell 防御”前提、逐项来源核防线、残余问题和同任务 consumer；
8. `Tool-BirthCard` 或 `NOT_REQUIRED(reason)`、`OLD_TOOL_FIELD_GAP`／`DERIVED_TOOL_CANDIDATE`／`UNCONTAINED_PATTERN_CANDIDATE`／`NOT_ENOUGH_EVIDENCE`、下一个触发条件和 exact Git commit。

偏差至少区分 `ALIGNED`、`EXPECTED_CALIBRATION_FAILURE`、`IDEA_SPEC_INCOMPLETE`、`EXECUTION_DEVIATION`、`RUNNER_OR_EVIDENCE_FAILURE`、`ORIGINAL_IDEA_CHALLENGED`。短运行没命中、工具报错、源缺失或 prompt 没采样，不能直接说理念被反证。

## 3. 全历史对照与分母新鲜度

用户明确要求完整回溯、创建／退休刀具、改变成功定义、HoTT→ZFC 升级或 AI／隔离／证据合同改变时，执行 full origin audit：从最初直接用户来源，到 P 出现前讨论、P1/P2/P3 打磨、案例校准、动态 DAG 和 `/goal` 连续运行分界；逐单位记录来源、处置、当前实现、运行证据与 Git 谱系。预 Goal 历史与 Goal 后的 `CONTINUATION_DELTA` 严格分开。

在以下情况，原“full audit aligned/complete”状态立即降为 stale，并从受影响 source units 重审：原文补录、文件 hash／字节／行数变化、收据或提交与报告不符、source denominator verifier 失败、理论／P 定义变化。当前被重新呈交的 `/goal` 驱动原文已作为本轮直接用户要求写入 `rulings.md`；full-origin audit 尚未审计这一来源单元与其 cutoff 归属。完成前，状态保持 `SOURCE_COVERAGE_RECHECK_REQUIRED`，不能把本分支已有审计摘要当成全历史闭合证据。

## 4. 工具迭代和 Git 收据

一项工具迭代只有在有明确差异／source／控制，有可审阅的规格和反事实时才进入 current tool。保存失败和旧版本，不回写历史 NodeCard 来迎合新合同。通过原项目 baseline 检查后，只 stage 本自然单元拥有的精确路径；运行相关分片／JSON／diff／来源检查；回读 current owner；然后精确 commit。Git log 保留演化谱系，但不证明理论数学正确。

worker 不写 current owner。并行 worktree 下，贡献分支只写注册的独占路径；current truth 更新由 canonical integrator 在目标 HEAD 上逐项复核后完成。branch-local PASS、candidate commit 和 relay 都不得称为 canonical current 状态。
