# P-FORGE-LITERATURE-BACKFLOW-AUDIT-SOP：P-FORGE 路线级文献回流审计 SOP

> **身份：** TASK_SCOPED_ROUTE_LEVEL_EVIDENCE_DELTA_AUDIT / P_Q_CO_FORGING / NOT_A_ZFC_Q_OR_MATHEMATICAL_RESULT。
>
> **稳定引用名：** P-FORGE-LITERATURE-BACKFLOW-AUDIT-SOP。
>
> **当前准备状态：** PLAN_READY / EXECUTION_INPUT_NOT_FROZEN / LITERATURE_BACKFLOW_NOT_EXECUTED。

## 1. 要解决的确切问题

已有 P-FORGE 原子审计已经对 130 个实际锻打单位完成 A0--A3，并把其历史范围闭合为：

~~~
ATOMIC_AUDIT_COMPLETE_WITH_SCOPE
ZFC_SITE_SELECTED
Power Set Q-0 UNFORMED
ZFC_Q_NOT_LOCATED
~~~

另一工作树的 HoTT 创建动机反投影 ZFC 文献调查，提供了可能改变这些结论之**来源边界**的新材料：作者动机 R_i、ZFC 对应位置 Z_i、具体 source payment、route mismatch、actual consumer、以及 H0 到 Z0 的反类比控制。本 SOP 的任务是让该材料以可审计方式回流既有 P/Q 共同锻造过程。

回流不是在原子审计之外添加“文献附录”。它检验：一项文献事实是否真正改变某个固定路线卡的 formation、reentry、payment、same-task、Done 或控制，从而要求选择性重审旧父结论，或产生一个受限的下一份 Q-qualification ForgeIntent。

## 2. 三条不可越过的推理边界

~~~
R_i（HoTT/UF 作者动机）
  不蕴含 Z_i（ZFC 的同层、同任务对象）
  不蕴含 Q_i（模式 P 所需的未付张力）。

H0（既有 HoTT 过程位置）
  不蕴含 Z0（ZFC 对应位置）
  不蕴含 Q0（ZFC 的 Q）。

来源中存在“不便、批评、模型、编码或证明助手现象”
  不蕴含 bare ZFC 的理论级问题。
~~~

只有在理论层、对象、形成、操作、观察、完成标准和反控制保持可追溯的情况下，路线卡才可把一个来源事实提升为候选资格；即使如此，它仍只可进入 ForgeIntent 资格化，不能直接成为 ZFC 结论。

## 3. 此 SOP 不做什么

本 SOP 不自动：

1. 集成候选 worktree、改写 dev 的 current owner、创建 clean integration worktree，或 cherry-pick 任何提交；
2. 启动 Terra/Max worker、P-DAG 节点、网络检索、Battle、source download 或 MinerU；
3. 重跑 130 张历史 AtomicAuditCard，或把后来文献倒灌为旧单位的 AS_RUN 事实；
4. 宣称 ZFC 有或没有 Q、Power Set 已被防住、H0 已传输到 Z0，或产出数学结论；
5. 把路线卡、来源数、文献数量或检查表勾选数当成 P 或 Q 已经收敛的证据。
