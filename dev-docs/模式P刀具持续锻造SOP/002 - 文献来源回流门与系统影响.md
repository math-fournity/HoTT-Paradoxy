# 文献来源回流门与系统影响

> **身份：** SOURCE_BACKFLOW_GATE / P_FORGE_INGRESS_CONTRACT / NOT_A_NEW_BLADE_OR_THEORY_RESULT。

## 1. 为什么它是锻刀系统的一部分

原子锻打审计已经把锻刀与发现 Q 绑定为同一可审计过程：每个自然单元必须让固定 Q 卡生成、收紧、桥接、淘汰、会合或免于误报。路线级文献回流审计补上另一个此前没有被主流程显式表达的问题：**外部来源包到底有资格改变哪一张 P/Q 卡？**

如果没有这个门，来源调查会有两种相反漂移：

1. 一篇论文、一个模型或一个候选 worktree 因关键词相似被直接写成 ZFC Q；
2. 多份 payment/guard/control 报告只增加文档，却没有说明它们怎样收紧下一次 ForgeIntent。

`SourceBackflowGate` 将二者统一到 P/Q 共同锻造：来源要先变成可定位的同一任务证据，才可影响锻刀；来源不能改变 Q 状态时，它仍可作为 I0/I1 的有界负校准。

## 2. 入口、分流与退出

~~~mermaid
flowchart LR
  A[外部文献或候选 worktree] --> B[B0 EvidenceEnvelope]
  B --> C[B1 R/Z/Q 或 H0/Z0 路线]
  C --> D[B2 RB-D01..D16 RouteBackflowCard]
  D --> E[B3 I0..I4 impact triage]
  E -->|I0/I1| F[更新来源前沿与重开条件]
  E -->|I2/I3 + CURRENT_EVIDENCE| G[选择性 parent/A3 addendum]
  E -->|I4| H[新的 ForgeIntent 候选]
  H --> I[既有阶段1.5 QConvergenceLink]
  F --> J[不启动理论节点]
  G --> J
~~~

| B3 结果 | 对未来锻刀的实际作用 | 不允许的越级 |
|---|---|---|
| I0 | 保留精确 source gap、seed或fulltext条件。 | 把缺口写成理论缺陷。 |
| I1 | 更新 SourceLayerCoverageMatrix、PowerSetDefenseLedger或下一来源的最小判别条件。 | 因为“有新文献”就创建 ForgeIntent。 |
| I2 | 只有 source 已成为 CURRENT_EVIDENCE，才可为一个原子/parent卡写 source-facing addendum。 | 倒灌改写 AS_RUN。 |
| I3 | 只有 source 已成为 CURRENT_EVIDENCE，才可收紧 A3 的来源范围/财富/重开门。 | 以 candidate worktree 修改 current synthesis。 |
| I4 | 允许提出新的 ForgeIntent；随后仍须经过阶段1、1.5和2的 QConvergenceLink、同一卡与授权门。 | 将 I4 直接称为 ZFC_Q_LOCATED 或启动 worker。 |

## 3. 对三把刀的具体影响

| 刀 | 历史原子审计后的强化 | 文献回流后的强化 |
|---|---|---|
| P1 | 不再把“有定义/存在”当作活跃 Q；同时保留 C_LANE 与 formation-origin F_LANE，防止 consumer-only 门漏掉形成路径。 | actual consumer必须与 formation route、T/u/F/C/I/O/Done同卡；RepFun、模型或概念比较不能替 P1付款。 |
| P2 | 编码、公式、proof search和固定点不自动是同一对象的 reentry。 | 文献里的 formula、truth、realizability、identity语言必须先通过 source-layer与route检查；否则只形成control。 |
| P3 | 静态公理、局部proof witness、递归或外部运行时间不等于 NeedBuild→OperatorUse→BuildDone。 | constructive/realizability来源的显式状态和payment不能被倒灌为ordinary ZFC生命周期；真正P3卡须来自同层consumer。 |

这不是第四把刀。它是一个**来源输入编译器**：决定一份外部材料能否成为 P1/P2/P3 使用的同一卡证据。

## 4. 对校准、站位和新刀的影响

1. CAL-* 只衡量 P 的校准能力；来源回流的 I0/I1 不可被计作 CAL-3/CAL-4，也不能代替 QConvergenceLink。
2. SourceLayerCoverageMatrix 现在要同时记录来源层和来源身份：候选文献能显示 L-C/L-D/L-E 的缺口或控制，但未被接受前不能改变 current coverage。
3. PowerSetDefenseLedger 的 PS4/PS5 现在还要求：若剩余主张来自文献，必须能指出它经过哪个 EvidenceEnvelope、哪条 RouteBackflowCard和哪一个 I-level。
4. 外部来源不能单独证明 P1/P2/P3 的花纹宇宙有新职责；所以 I0--I4 都不自动产生 Tool-BirthCard或新刀。

## 5. 已验证的首个实例

LEB-20261003-002 对两个 candidate commits 的九条路线给出首个完整实例：

~~~
I0=2 / I1=7 / I2=I3=I4=0
Candidate-Q=0 / ForgeIntent=0 / current-owner mutation=0
~~~

它实际改变的不是 `ZFC_SITE_SELECTED / Q-0 UNFORMED`，而是未来来源必须满足的结构：Power Set-subset same-Done consumer、ordinary ZFC P5 consumer、T0--T5 transport、具体 proof-verification consumer或clean canonical integration。该实例的执行记录是 [20261003-P-FORGE-LITERATURE-BACKFLOW](<../../audit/20261003-P-FORGE-LITERATURE-BACKFLOW.md>)。

## 6. 停止与重开

没有外部来源包试图改变 current P-FORGE 判断时，不运行这个门。出现新的候选 source、candidate ref、集成结果或直接反驳既有 payment/route/task判词的材料时，重新建立 B0 delta；不要复用旧 ref 名称、旧 handoff 或worktree实时内容。
