# 续跑与门禁修订（v2）

> **身份**：设计会话（Claude Code，Haiku 5.5，2026-10-07）按研究发起人的委托"完全处理好它"作出的裁定。本片是第二次运行（续跑）的规则。研究发起人若有不同裁定，以其裁定为准。
> **优先级**：与 001 至 005 冲突时，以本片为准。001 至 005 的文字未改动，锚句 B1 至 B8 所在的行未变，协议锚表无需重放。
> **不变的**：完成门 G'1 至 G'11 的判据；R1 至 R5 的交付规格；封印（I0 至 I8）；执行者身份声明（001 §9）。本片只改变达到它们的工作方式。

## 0. 续跑的起点

- 第一次运行的工作区已提交为存档，即 `audit/GUI-ASSET-REAUDIT/`（128 个文件）。它是续跑的起点。
- 其中 40 个已提交块（B-dev-01-0001 至 0040）的收据，经设计会话独立重算全部一致（`认知闭包/GUI-ASSET-REAUDIT-001.md` §6）。这些收据有效。
- 第 41 块（B-dev-01-0041）有一份未提交的草稿，位于 `notes2/dev-01.md` 中该节。处置：在该节末尾追加一行 `[作废·块未提交]`，不删除；然后从拍 1 重做（005 §4 第 9 步）。
- 续跑由 CL-R2 开始，步骤见 §8。

## 1. 方法 B 不运行；义务行即全部行（修订 002 §3.4）

- 目标限定 git 只能用 status、ls-files、rev-parse、hash-object、cat-file。`git diff` 不在其中，因此方法 B 不运行。
- SHARED 恒为空。义务行即语料的全部行（manifest2 的 T = 126503）。
- 方法 A 仍可作信息性统计，但不用于减少义务行。
- 这与研究发起人"以最大的成本"的指令一致，也与第一次运行的实际做法相同。

## 2. 分片（修订 003 §4 与 005 §2(g)）

- notes2、classes2、assets2 按块边界分片。每片不超过约 250 KB，整块不拆。文件名为 `notes2/<tag>.part-NN.md`、`classes2/<tag>.part-NN.tsv`、`assets2.part-NN.md`。
- 切分只移动节，不改节正文的字节。切分前后，每个已提交块的节正文哈希必须相同（口径与 RA 的 notes_sha256 一致）。切分后运行 §5 的核对。
- 分片表写入 `notes2/INDEX.json`，每片列出覆盖的块与行范围。
- 工具（commit_block、reread、check_all 等）须按分片读取；节的解析口径不变。

## 3. 压缩边界：工作集完全重载，其余分片由工具核对（修订 005 §4 第 7 步，M8）

- 工作集每次 CL-BR2 必须整读：本规范全部分片（001 至 006）、认知闭包、SESSION-REAUDIT.md、STATUS.md、seal-log.jsonl 的末尾 50 行、ledger2.jsonl 的末尾 60 行、当前分片的 notes2、classes2、assets2 全文、当前块原文（若未提交）。
- 其余分片不整读进上下文，由 §5 的工具逐分片核对。
- 理由：整读全部笔记的代价随进度线性增长。第一次运行在 40 块时，CL-BR2 已需整读约 756 KB，且每块约增加 14 KB；全部 636 块时无法装进单个上下文。本修订把"完全重载"限定在工作集，其余由工具核对哈希。这是设计会话的裁定；若研究发起人不接受，须明确改裁定，否则续跑无法完成。

## 4. 门禁（新增；005 §4 增补第 10 步）

- **GATE**：每块开始（拍 1）之前，运行 `tools/gate.py <BLOCK>`（执行者自建）。它检查：账本全链、最近一条 RS 收据的存在、§5 的分片核对结果、本块是否已有未作废的草稿节。通过则在账本写入 GATE 记录（含时间与所依 RS 的编号）；未通过则停止，写 PARTIAL。
- 草稿写入前，本块必须已有 GATE 记录，且它早于本块的第一条草稿记录。commit 前同此。
- 审计时以账本顺序为准：每个 RA 之前都有对应的 GATE，且该 GATE 之前有对应的 RS 窗口。第一次运行的 40 块为 v1 收据，不适用本条，已在 §0 说明。
- 注意：工具只能记录执行者声明的结果。门禁的作用是让顺序可审计，不替代纪律。

## 5. 分片核对（新增；工具）

- `tools/verify_shards.py`（执行者自建）对全部已提交块核对：chunk_sha256 与 bytes（按 002 §1）；notes_sha256、classes_sha256、assets_sha256（按 commit_block 的口径，在所在分片中定位）。输出 `shard-verify.json`，每块一行。
- CL-BR2 第 7 步与 CL-E2 必须运行它。全部通过才算过 CL-BR2 第 7 步。

## 6. PASS 的写入（修订 003 拍 4 的记录方式）

- reread.py 写入 PASS 前，本块的第二遍整读必须覆盖块的全部行：second-start 至 second-end 覆盖块区间，且 returned-end 等于块末行。不满足则拒绝写入。
- 提前写入的 PASS 是程序错误：登记为 REREAD_PREMATURE，并在真实整读完成后覆盖（沿用既有规则）。

## 7. ID 缺口与豁免（修订 003 与 004）

- 资产 ID 不得复用，不得跳号。出现缺口，须以 ID_GAP 记录写明原因；CL-E2 对账时逐项说明。A2-0135 的缺口在续跑时补登。
- 类别豁免须写明理由，并登记为 EXEMPTION_ADDED。执行者新增的豁免，待设计会话在审计时复核。已有的豁免 `^/tmp/pattern-p-forge-` 暂时接受。

## 8. 续跑的步骤（CL-R2 起）

1. 读本规范全部分片（001 至 006）与认知闭包，记录每片的 EOF 行号与字节数。
2. 建立工具 `tools/gate.py` 与 `tools/verify_shards.py`（若尚不存在），并对现有的单文件运行 §5 的核对与账本全链核对。全部通过。
3. 按 §2 对 `notes2/dev-01.md`、`classes2/dev-01.tsv`、`assets2.md` 分片；切分后再运行 §5 的核对，全部通过。
4. 在 `audit/GUI-ASSET-REAUDIT/` 下创建 `ACTIVE`（空文件）。它是压缩钩子的开关。
5. 对第 41 块：草稿节末尾追加 `[作废·块未提交]`；classes2、assets2 中的草稿行与 reread-state 的 beat1 记录移入 `drafts-void/`，不删除。
6. 从拍 1 开始：GATE → 拍 1 至拍 5 → commit_block（预检、提交）。每块重复。
