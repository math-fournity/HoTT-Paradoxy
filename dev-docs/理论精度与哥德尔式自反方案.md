# 理论精度、观察边界与哥德尔式自反方案

> **稳定引用名：** T-PRECISION-DIAGONAL-SOP。
>
> **身份：** TASK_SCOPED_RESEARCH_PLAN / THEORY_OF_THEORY_OBSERVATION / PLAN_READY_NOT_EXECUTING。
>
> **当前状态：** PLAN_READY / EXECUTION_NOT_STARTED / DOES_NOT_REOPEN_F050_CLOSED_WITH_SCOPE；它不将想法 T 写成已证明定理，也不将 F-050 的有界收尾重新叙述为开放总证明。

## 目的

本方案把研究发起人提出的想法 T 组织为一个可检验的上位研究程序：

1. T-OBS：定义理论相对于任务域的观察精度，研究低精度接口何时压平会改变完成或存在判词的过程差异；
2. T-DIAG：在理论的实际接受／证明／完成接口能够被有效编码、自指和反射时，研究观察精度边界何时升级为哥德尔式不完备、反射失败或必须拒绝接受；
3. T-ZFC：将前两层的已支付条件实例化到一个版本固定的 bare-ZFC-facing interface，而不把项目自定义模型误写成 ZFC 的对象语言结论。

ZFC 是 T 的重要实例，不是 T 的定义。T 也不预设“所有不完备都是维度缺失”；其可证明形式必须以任务域、观察投影、判词、有效编码和实际接口为条件。

## 与既有哥德尔路线的关系

本方案不是另一套与现有 [GODEL-Q-REFLECTION-SOP](哥德尔式ZFC完成观察反射方案SOP.md) 竞争的路线。

- **T-PRECISION-DIAGONAL-SOP** 是上位程序：先给出任务相对的观察精度语言，随后才问该边界能否通过有效编码和对角化升级；
- **GODEL-Q-REFLECTION-SOP** 保留为其中的 **T-DIAG 执行模块**：它已经拥有 GodelizationCard、G0--G5、实际 completion acceptance interface 的来源门和既有可审计闭包；
- 直接调用 GODEL-Q-REFLECTION-SOP 仍可进行其已定义的 G0；调用本方案时，只有选中 T-DIAG 单元才加载并复用该模块，不能重复发明一份同义的接口卡或把两个模块当成两条独立 Goal。

因此，T 的新增内容是：把哥德尔式模块放入 T-OBS 的相对观察边界和 T-Meta 的同一任务审计之中，并让 ZFC 成为 T-ZFC 的受限实例，而不是把它预设为唯一对象。
