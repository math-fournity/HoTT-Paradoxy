# 执行检查表、停止与自审

## 1. 每次 `/goal` 的执行顺序

| 阶段 | 最小判别行动 | 产物与可继续条件 |
|---|---|---|
| A0 | 重读本 SOP、P-FORGE、Q0/Q1/Q2 owners、候选 ref 与当前 dev target；若使用 candidate worktree，完成 backflow B0 delta。 | Frozen TaskDescriptor、owner/freshness verdict。缺 exact ref、source 或 dirty disposition时停止。 |
| A1 | 冻结原过程卡：`P/State/I/Op/F/O/OriginDone`，并区分用户原文、AI解释与待裁定条件。 | `ActualQCard` 的 origin half；若 `OriginDone` 不可固定，标 `USER_DONE_ADJUDICATION_REQUIRED`。 |
| A2 | 冻结连续统来源卡，逐段提取 ZFC 基础措辞、模型、判词、Done 改写／支付和反控制。 | `SourceCompletionCard`；若只得到 `revisedResolved` 或 no-policy claim，保留为控制而非正证。 |
| A3 | 冻结 exact HoTT Q 及其 Agda theorem、C-357/C-358、现实解释与理论变体限制。 | `HoTTQCard`；不能把相邻模型当同一演算。 |
| A4 | 寻找实际基础验收 policy owner 和对两侧可用的输入／输出／Payment。 | `AcceptancePolicyCard`；无 owner 即 `SOURCE_POLICY_UNDERDETERMINED`，不能直接调用实际异判。 |
| A5 | 尝试构造共同 `ActualQInstance`，每字段用证据状态而非 Bool；先跑所有必要控制。 | `SameActualQ` proof 或 `ACTUAL_Q_UNIFICATION_REJECTED_WITH_SCOPE`。 |
| A6 | 在 Lean/Agda 分别固定命题、源码、依赖、source snapshot、负控制与 run receipt；生成跨系统命题对应表。 | 精确 `CLAIM.md`、kernel run、source manifest、claim matrix 行；跨 kernel 假设显式标记。 |
| A7 | 只有 A1–A6 同时支付时，调用政策 consequence theorem；否则记录实际卡的拒绝或来源不足结论。 | `ACTUAL_Q_POLICY_CONFLICT_WITH_SOURCE_BOUNDARY` 或一个有界负结论。 |
| A8 | 执行 P/Q 自审、来源/证明/解释分层复核、current-owner 写回、验证与精确 Git commit。 | 更新 Feature、MEMORY、rulings、Q0/Q1/Q2 evidence owners；无语义变化则 `NO_CHANGE(reason)`。 |

任何需要 Terra/Max、网络、其他分支或 Battle 的步骤，仍先走现有 P-DAG 的 TaskCard/NodeCard。这个 SOP 不因被 `/goal` 引用而自动启动它们；已授权 worker 仍固定 `gpt-5.6-terra / max`、只读、无递归，并由 Master 唯一写 current owner。

## 2. 交付前检查表

### 实际 Q 身份

- [ ] `T/u/F/C/Q/I/O/Done` 在 Zeno、continuum、HoTT 与 policy 卡中逐项给出。
- [ ] `OriginDone` 没有由 AI 为让定理成立而临时添加。
- [ ] `Done_formal` 与 `OriginDone` 的方向、域、量词、桥支付和相反控制明确。
- [ ] 每个相同／不同字段都有 `SOURCE_ESTABLISHED`、`SOURCE_REFUTED`、`SOURCE_UNOBSERVED`、`SOURCE_INAPPLICABLE` 或 `SOURCE_CONFLICTED` 身份。

### 来源与归因

- [ ] ZFC、ZFC-supported continuum、模型语义、数学实践、物理解释和 proof/runtime 层分开。
- [ ] 每个来源 claim 有版本、locator、上下文和直接支持范围。
- [ ] `originalResolved` 与 `revisedResolved` 没有混同。
- [ ] `bridgeRequired` 来自实际 policy owner，而不是研究者自身的希望。
- [ ] 若声称“数学界公认”，有相称的一手/权威来源分母，不以单一百科或论文代替整个共同体。

### 机器证明

- [ ] 每个数学命题有稳定 claim ID、完整量词、假设、精确理论变体和禁止外推。
- [ ] HoTT 相关命题在原生 Cubical Agda 或已证明保真的翻译中运行；Lean `Eq` 不代替它。
- [ ] Lean 实分析／政策命题的 `#print axioms`、依赖、环境、stdout/stderr、source hash 和负控制都保存。
- [ ] 跨 proof assistant 的连接逐项标明“机器证明”“外部 formal result assumed with receipt”“来源认证”或“AI解释”。
- [ ] 运行通过不被说成 source fact，source fact 不被说成 kernel theorem。

### 反控制与可推翻性

- [ ] 闭连续时间端点正控制仍通过。
- [ ] 显式 `CompletionBridge` 支付时，候选不会继续声称未支付。
- [ ] 支付不同的 profile 可以合法异判的反控制仍通过。
- [ ] exact HoTT theory variant 的模型覆盖不足会阻断外推。
- [ ] 不同实际 Q 的反例会触发 `ACTUAL_Q_UNIFICATION_REJECTED_WITH_SCOPE`，而不是更改 Q 定义躲避反例。

## 3. P/Q 共同锻造自审

每个自然单元附一张 `ActualQSelfAudit`，回答：

```text
Target-Q / Candidate-Q / Control-Q
本单元究竟让 ActualQInstance 的哪一字段生成、收紧、桥接、淘汰或会合？
P1/P2/P3 的哪个字段、哪份来源、哪项 kernel result 导致这个变化？
是否把 source-unobserved 写成 false、把 revisedResolved 写成 originalResolved，
或把同一关键词写成同一 Q？
哪一项结果会推翻当前结论？
这次工作是否只是工具改动；若是，它是否为固定卡的 Q_SAFETY_REPAIR？
```

不能回答前三项时，标 `TOOL_ONLY_DRIFT` 或 `SOURCE_PREPARATION_ONLY`，停止把该单元算作 Actual-Q 发现推进。

## 4. 停止、重开与完成

| 状态 | 停止条件 | 可重开条件 |
|---|---|---|
| `USER_DONE_ADJUDICATION_REQUIRED` | 原圆环／芝诺的 `OriginDone` 无法从现有原案稳定冻结。 | 研究发起人明确裁定过程、完成条件或允许的现实模型。 |
| `ACTUAL_Q_UNIFICATION_REJECTED_WITH_SCOPE` | 同一任务、理论变体、来源判词或 policy owner 有直接控制性差异。 | 新的一手来源或新的保真过程映射消除该差异。 |
| `SOURCE_POLICY_UNDERDETERMINED_WITH_SCOPE` | 有模型/一致性/数学事实，缺实际 acceptance policy。 | 找到版本固定的基础充分性／解决声明，明确消费 fixed Q。 |
| `ACTUAL_Q_POLICY_CONFLICT_WITH_SOURCE_BOUNDARY` | A1–A8 均通过，来源与机器 consequence 边界完整。 | 新来源支付 bridge、改写 policy，或发现同 Q 映射错误。 |
| `FORMALIZATION_BLOCKED_WITH_SCOPE` | 任务和来源已固定，但当前 proof assistant 无法保真表达所需命题。 | 找到原生演算、已证明翻译、或用户批准的理论变体调整。 |

“直至无法推进”指到达上述任一停止状态，或完成实际冲突交付；它不允许因没有新想法而无限搜索、不断新增 `Bool` 字段或把 source gap 解释为 ZFC 已失败。

## 5. `/goal` 启动词

```text
按照SOP=ZFC-Q-ACTUAL-INSTANCE-FORMALIZATION-SOP，继续推进，直至无法推进。
```

此启动词的首项行动是 A0，而不是直接写新 Lean fixture。它会先确认 candidate evidence 是否需要 backflow delta、实际过程 Done 是否可冻结、以及当前 Q0/Q1/Q2 owners 是否已因新证据失效。
