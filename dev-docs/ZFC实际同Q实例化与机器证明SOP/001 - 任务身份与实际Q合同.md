# 任务身份与实际Q合同

## 1. 任务描述与研究型 profile

| 字段 | 固定内容 |
|---|---|
| 父结果 | `F-045` 的圆环—连续统完成桥、`F-046` 的元—子—过程边界、`F-047` 的 HoTT Q 比较性归因，最终要么形成实际 Q 的来源绑定机器证明，要么给出有界的同 Q 不成立／来源政策不足结论。 |
| 当前工程决定 | 是否能把 `ZFC-CIRCLE-Q0/Q1` 与 `ZFC-HOTT-Q2` 由候选、控制和条件 theorem 升格为同一完整实际 Q 的实例化包。 |
| profile | `RESEARCH_PROFILE_GOVERNED / COMPOSE_FROM_OWNERS`：方向、来源、两个 proof assistant、candidate worktree 和当前 dev evidence 都会改变结论；它不是自动创建 Host Goal、worktree、worker 或外部写入的授权。 |
| 当前活跃方向 | 仅三条：原过程—连续统同一任务、固定 HoTT Q—基础验收同一理论变体、来源级政策归属。它们只有在同一 Q 合同中汇合时才算本任务进展。 |
| 非目标 | 不证明 `ZFC ⊢ False`；不把 IEP、数学共同体或用户判断伪装成 Lean 内核事实；不把 source 缺失写成理论失败；不以新 fixture 代替实际实例。 |

本任务的来源选择 verdict 是 `COMPOSE_FROM_OWNERS`：当前 `F-045`–`F-047`、`ZFC-CIRCLE-Q0/Q1`、`ZFC-HOTT-Q2`、C-357/C-358、现有 `MetaObservationConsistency.lean` 和候选 branch 的来源／运行各自拥有一部分必要事实，任何一个单独文档都不足以完成实际实例。

## 2. 实际 Q 不能只是一句相似性

本 SOP 所称的“同一个完整 Q”必须冻结为下面的对象；字段来自项目既有 `T/u/F/C/Q/I/O/Done` 合同，但加入过程层、来源层和政策层的连接。

```text
ActualQInstance =
  TheoryLayer      : bare ZFC / ZFC-supported continuum / source-defined acceptance layer
  Process P        : State, initial input I, allowed operation Op, transition F, observation O
  OriginDone       : P 的原过程完成谓词
  FormalModel M    : representation R(P), mathematical/model completion Done_formal
  Bridge           : Done_formal → OriginDone 或 Done_formal ↔ OriginDone 的精确方向、域和支付
  Consumer C       : 来源实际使用 M 并声称/拒绝完成的输入、输出、Done contract
  HoTTQ H          : exact calculus、source program、input, theorem, completion predicate
  AcceptancePolicy : 一个来源归属的判断者、允许输入、判词空间和支付责任
  Judgment         : originalResolved / revisedResolved / bridgeRequired / no-policy-claim
  Controls         : 连续端点、显式 bridge、不同任务、guard、反向/反例控制
```

`TheoryLayer` 不允许把 bare ZFC、实数模型、物理连续运动解释、IEP 的哲学判断、KLV 相对模型和 proof-assistant runtime 混成一个对象。每一层都必须保留自己的 source、版本和完成谓词。

## 3. 证据状态不是 Bool

实际来源映射不得把“来源没有交付”写成 `false`。每个 O1–O5、`bridgePaid` 与 `originalTaskPreserved` 使用以下证据状态：

```text
SOURCE_ESTABLISHED       版本固定的一手来源或已形式化对象明示支持
SOURCE_REFUTED           版本固定的一手来源或反控制明确否定
SOURCE_UNOBSERVED        已检查范围没有足以判定的来源
SOURCE_INAPPLICABLE      字段不属于该来源声明的任务／层级
SOURCE_CONFLICTED        两份同层权威来源给出不能兼容的内容
```

只有将来源状态冻结为机器可消费的特定 proposition 或有限证书后，才能进入 Lean／Agda 定理。这个转换必须保留原来源 locator、解释增量和 `SOURCE_*` 身份；不允许把 `SOURCE_UNOBSERVED` 降格为 Boolean `false`。

## 4. 两类最终交付与禁止的中间话术

| 终点 | 必须同时满足 | 允许的结论 |
|---|---|---|
| `ACTUAL_Q_POLICY_CONFLICT_WITH_SOURCE_BOUNDARY` | 原圆环／芝诺、连续统解法与 HoTT Q 的同一 `State/I/Op/O/Done` 映射通过；来源实际作出同层原任务／bridge判词；来源归属的政策实际要求同类观察；跨证明器命题与运行收据闭合；相称反控制未推翻。 | “在所固定的 ZFC 支撑基础验收／Standard Solution 范围内，来源证据与机器化 consequence 显示政策冲突。”不能缩写为`ZFC ⊢ False`。 |
| `ACTUAL_Q_UNIFICATION_REJECTED_WITH_SCOPE` | 同一任务映射、来源判词或同层政策有直接反证；控制说明不是任意换题。 | “在所固定的来源与任务范围内，Zeno 与 HoTT 不能被作为同一个完整 Q 使用。” |
| `SOURCE_POLICY_UNDERDETERMINED_WITH_SCOPE` | 所有可用来源仅给模型／相对一致／修订任务声明，未给基础验收 policy 或实际 LiftClaim；搜索分母、同义词和 stopping evidence 固定。 | “当前来源不足以归因于 ZFC 支撑的统一政策。” |

以下都不是完成：新增条件 fixture；更多 `Bool` 字段；只重跑已有 Lean；把用户的研究判断填成 source fact；把 IEP 的 `revisedResolved` 写作 `originalResolved`；把 HoTT 内部 `never` 当作外部 ZFC 来源的 `bridgeRequired`。

## 5. 关键可证伪点

1. 原过程的 `OriginDone` 若不能从用户原案或版本固定的过程规格得到稳定定义，停止在 `USER_DONE_ADJUDICATION_REQUIRED`；不得让程序员临时补一个“最后一步”条件。
2. 连续统来源若明确支付 `Done_formal → OriginDone` 或说明两者本来不是同一任务，Q0 按范围被支付或拒绝。
3. HoTT Q 若无法翻译为和来源层同一理论变体的过程规格，Q2 不能用它作 ZFC 验收反例。
4. 若没有实际来源声明同一 acceptance policy，`QUniform` 只保留为条件性 test，不成为基础框架判词。
5. 任一控制表明 profile 差异是实质字段而非遗漏字段时，停止强行统一，不以“都涉及完成”继续推进。
