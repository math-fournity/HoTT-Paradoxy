# 官方依据与本机基线

## 1. 任务与证据边界

父结果是让本项目的同一套治理方法可以被本机Claude Code发现、完整读取、按角色消费，并通过既有工具保存证据。当前交付是可实施方案；配置安装、模型行为与数学研究是三个尚未执行的阶段。没有额度不妨碍本地文件、链接、JSON和Python的离线核对，但禁止以这些结果代替Claude fresh/压缩恢复实测。

本轮来源选择为`COMPOSE_FROM_OWNERS`：组合现行项目合同、已安装Claude全局适配层，并以必需的官方网络调研补足外部机制证据。研究者当前队列仅用于避让，不继承其执行权限。本轮为独占文档/取证contributor，研究STATE仍由原研究integrator管理。

| O09 | [Goal](https://code.claude.com/docs/en/goal)：每轮另有模型评价完成条件，可能因判断不可能或错误清除goal | 默认不启用Claude `/goal`；项目任务完成以SOP/证据为准，不迁移Codex的状态API和blocked阈值 |
| O10 | [Checkpointing](https://code.claude.com/docs/en/checkpointing)：Bash修改及外部修改不由普通rewind完整跟踪；symlink路径也有恢复限制 | `cognition_runtime checkpoint/recover`和Git仍拥有项目状态恢复；禁止只rewind STATE等受管文件 |
| O11 | [Model configuration](https://code.claude.com/docs/en/model-config)：上下文和压缩阈值依模型、提供方、配置而变 | 未来先核实际model/provider/context；不把Codex的872k/700k配置数字移植为Claude事实 |
| O12 | [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)与[Costs](https://code.claude.com/docs/en/costs)：上下文会自动压缩，已在磁盘与已在当前上下文不同 | 逐段EOF、压缩失效与语义复认照旧；不声称缓存或分块消除了总上下文需求 |
| O13 | [Desktop](https://code.claude.com/docs/en/desktop)：本地Code与CLI有共享配置，云端/桌面其它模式另有边界 | 本方案首先认证本机CLI；Desktop Code另外检查启动根与工作树，不推及Cowork或云端 |
| O14 | [Agent teams](https://code.claude.com/docs/en/agent-teams)：属于多会话协作能力 | 本项目不启用，不把团队功能当消化大上下文的替代方法 |

O01的附加限制：原生AGENTS加载不会触发所有`InstructionsLoaded`观测；项目`@`导入repo外文件涉及另行信任；指令属于模型上下文而非硬执行规则。本方案不导入Codex全局AGENTS、不依赖该hook计数认证读取。官方200行建议不成为本项目删内容的门槛。

检索过程先搜索，再打开英文正文和相关章节。直接批量获取官方`.md`副本返回HTTP403；文档索引请求也失败。已改用可读的内置web页面继续调研，没有把失败下载说成全文离线镜像。本方案只声称上表列明机制的官方调研，不声称读完官方站点所有页面。
