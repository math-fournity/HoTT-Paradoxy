# 分支卡、综合与接手（v3）

## 1. 分支卡（`cards/<分支>.md`）

必需章节，顺序固定：

- `## 终点`：分支最后一轮做了什么、停在何处。
- `## 回溯（终点到分叉）`：从末尾倒着看到的阶段。每条一个阶段，写明轮号范围。
- `## 分叉节点`：分叉发生在父分支的哪一轮（引用父分支轮），分叉前后有什么变化。
- `## 独有阶段`：本分支独有、父分支没有的内容。
- `## 未决与风险`：未解决的问题、可能的误读之处、需要用户裁定的事项。

规则：

- 每条以 "- " 开头；每条至少含一个 `[分支#NNNN]` 引用，引用必须存在（本分支的轮，或分叉节点所在的父分支轮）。某章节无内容时，写一条“（无）”并附一个引用。
- `## 终点` 必须引用本分支的末轮（编号最大的自有轮）。
- `## 分叉节点` 必须引用分叉轮（`_branch.json` 的 `fork.parent_branch` 与 `fork.parent_doc`）。根分支写“根分支，无分叉”并附本分支第一轮的引用。

## 2. 综合（`synthesis/`）

- `THREADS-MATRIX.md`：主题 × 分支矩阵，格子引用轮号。至少含一个引用。
- `CLAIMS.tsv`：论断表，制表符分隔，表头为 claim_id、claim、status、refs、threads。claim_id 唯一，claim 非空；status ∈ SUPPORTED、ASSERTED_ONLY、CONTRADICTED、SUPERSEDED、OPEN；refs 为 `[分支#NNNN]`，至少一个。
- `USER-STATEMENTS.md`：用户原话索引，按主题排列。原话用「」括起，逐字复制，且须在单行内；同一行必须有 `[分支#NNNN]`；每个引文必须是所引某一轮文档中的逐字子串（工具检查）。
- `CONTRADICTIONS.md`：分支之间的矛盾、重复或互相引用。每条以 "- " 开头，并逐条引用轮号。
- `HANDOFF.md`：接手指南（见第 3 节）。

## 3. 接手指南（`HANDOFF.md`）必须包含

以下五节，各用一个二级标题，标题中须含对应的词（工具检查）：

1. `## 1. 先读……`：先读哪些分支、哪些轮（按分叉树的顺序给出）。
2. `## 2. 跳过……`：哪些段落可以跳过（写明理由）。
3. `## 3. 不能相信……`：未经证据支持的论断；已被反驳的论断。
4. `## 4. 待用户裁定……`：逐条，写清需要什么裁定。
5. `## 5. 下一步`：可执行的动作，1 至 5 条，不超过五条。

## 4. 原则

- 线程说了什么，不等于我们判断它对。综合不替线程背书。
- 每条论断必须能回到具体轮（`[分支#NNNN]`）。
- 证据与断言分开：用 status 写明。
- 未解决的写 OPEN，不补成结论。

## 5. 分支卡分组（权威）

分支卡分三组，各组由一个会话完成。开工前提：本组每个分支以及它的分叉父分支，标注校验（`--stage annotations --unit <单元>`，不带 `--docs`）都必须已经 PASS。

| 组 | 分支 | 轮数 |
|---|---|---|
| K1 | `dev-08` | 127 |
| K2 | `archive-01a0fb08`、`archive-01a0fb73`、`dev-01`、`dev-02`、`dev-03` | 3 + 10 + 21 + 13 + 26 = 73 |
| K3 | `dev-04`、`dev-06`、`dev-07`、`dev-09` | 15 + 13 + 8 + 16 = 52 |

不可见尾部单元不写分支卡（见 004 §1 的校验范围）。
