# 审计、停用旧方案与封印（v3）

## 1. 抽样审计

- 抽样清单在标注开始之前固定，且只固定一次：`--stage sample` 对每个单元按哈希排序取前 k 轮，k = max(2, ⌈5% × 轮数⌉)，不超过轮数。种子为 `gui-qa-tree-audit-v1`，结果可复现。清单写入 `audits/<单元>.sample.json`。已有标注的单元拒绝重抽，`--force` 也不能绕过。
- 全部抽样：25 个自有轮（占 252 个自有轮的约 10%，小单元按最少 2 轮计）；9 个不可见尾部轮全部抽取。
- 审计：审计会话（与标注会话不同）先独立阅读抽样轮并写自己的标注，写入 `audits/<单元>.auditor.jsonl`（字段同 003 §2）。在写完之前不得打开标注者的文件。
- 比较：`--stage audit --unit <单元>`。逐轮比较 status；审计者的引文须是该轮文档中的逐字子串。
- 门槛：单元的状态一致率 ≥ 0.9，否则该单元报告为 FAIL，须整体复核。全量 `--stage audit`（不带 `--unit`）另写 `reports/audit.json`，给出总体一致率，须 ≥ 0.9（C7）。
- 裁决：不一致之处由设计会话裁决，写入 `audits/<单元>.decisions.md`。裁决须写明采用哪一方，并附依据的轮号与原文。
