# 机器校验与收据（v3）

## 1. 命令

前缀统一为 `python3 -I -B audit/GUI-SYNTH-REDO/tools/check_annotations.py`，之后接下列参数：

- 抽样（只在标注开始之前运行一次）：`--stage sample`
- 标注（单元；分部标注时加 `--docs`）：`--stage annotations --unit <单元> [--docs 0001-0040]`
- 分支卡：`--stage cards --unit <分支>`
- 综合：`--stage synthesis`
- 审计（该单元须已标注完成）：`--stage audit --unit <单元>`
- 全量：`--stage all`（不带 `--unit`：annotations 与 cards 全部单元，并写汇总报告）

导出（源变化或需要重建时）：`python3 -I -B audit/GUI-SYNTH-REDO/tools/qa_tree_export.py --force`。导出之后须核对 `qa/_manifest.json` 的源哈希，抽样清单不随导出重抽。

## 2. 结果

- 退出码：0 = PASS；1 = FAIL；2 = 用法或单元名错误。
- 报告：每个单元一份 `reports/<阶段>--<单元>.json`，如 `reports/annotations--dev-08.json`。并行会话各写各的单元报告，互不覆盖。
- 汇总：不带 `--unit` 且不带 `--docs` 的运行另写 `reports/<阶段>.json`（`annotations.json`、`cards.json`、`audit.json`、`synthesis.json`）。
- `--docs` 只限定覆盖检查的轮号范围；报告记录 `subset`，且不写汇总。引文与 refs 检查仍对该单元已写入的全部行生效。
- 审计的汇总 `audit.json` 另给总体状态一致率（C7）。
- dev-08 的 a–d 四部分全部写完之后，须运行不带 `--docs` 的单元检查，由它判定覆盖是否完整。

## 3. 失败处理

- 只修改标注文件、分支卡与综合文件，不修改 `qa/`。
- 若 `qa/` 与 `qa/_manifest.json` 的源哈希不一致，停止并报告；不得自行重建 `qa/`。
- 引文不匹配：重新打开该轮文档，逐字复制；不得改动文档。
- 抽样报“拒绝重抽”或“未覆盖”时，不得用 `--force` 绕过：抽样只固定一次（006 §1）。

## 4. 收据

- 每轮的源收据：`qa/<分支>/_index.jsonl`（源行号、字节区间、源 SHA-256）。
- 全局收据：`qa/_manifest.json`。
- 抽样清单：`audits/<单元>.sample.json`（抽样规则、种子、轮数、生成时间与轮号）。
- 校验报告：`reports/`（见 §2）。
