# 阅读与标注规则（v3）

## 1. 读单元与回溯读法

- 单元：一个分支文件夹（如 `qa/dev-08/`）中的自有轮，或一个不可见尾部段（`qa/_unexported/<rollout>/`）。
- 读法：从单元末尾（编号最大）倒着读到第一条自有轮（0001）。读到分叉节点即止：分叉节点属于父分支，由父分支的标注单元负责。若需要理解分叉原因，只额外读分叉节点与其前一轮。
- 每轮必须读完整文档，不得只读标题或首尾。
- 大单元分部分：dev-08（127 轮，约 1.74 MB）分为 `dev-08.a`、`dev-08.b`、`dev-08.c`、`dev-08.d` 四部分，轮号范围见 §6。每部分写入自己的标注文件 `annotations/dev-08.<部分>.jsonl`。

## 2. 标注（每轮一行 JSON，写入 `annotations/<单元>[.<部分>].jsonl`）

| 字段 | 要求 |
|---|---|
| `doc` | 轮号，四位字符串，如 "0007" |
| `intent` | ≤160 字。这一轮用户要什么（释义，可由该轮直接核对） |
| `intent_quote` | ≤200 字。用户原话中最能代表意图的一句；必须是该轮文档中的逐字子串。无用户消息时为 "" |
| `ai_action` | ≤200 字。助手在这一轮做了什么（读了什么、做了什么、提交或运行了什么） |
| `ai_quote` | ≤200 字。助手原话中的关键一句，逐字；可为 "" |
| `outcome` | ≤160 字。结果或状态 |
| `status` | ANSWERED、OPEN、DEFERRED、SUPERSEDED、ERROR、UNCLEAR、NO_CONTENT 之一 |
| `refs` | 字符串列表：路径、提交哈希、运行编号等。每一项必须逐字出现在该轮文档中；可为 [] |
| `reader` | 标注会话名（非空）。同一单元的标注会话与审计会话必须不同 |
| `model` | 模型 ID（非空）。不得为 GLM-5.3 家族 |

格式示意（内容为虚构）：

```
{"doc":"0007","intent":"要求比较两个方案的代价","intent_quote":"…","ai_action":"读取两份记录并列出差异","ai_quote":"…","outcome":"给出三条差异，未定结论","status":"ANSWERED","refs":[],"reader":"…","model":"…"}
```

## 3. 判断口径

- 用户轮：提出目标或问题、纠正助手、作出裁定，才算实质内容。仅确认语（如“好”“继续”）记为 NO_CONTENT，并在 outcome 中写明。
- 助手轮：只标注有结论、有动作、有结果的部分。进度播报（“我先读……”）不单独成条，并入 ai_action。
- 释义必须能由该轮文档直接核对，不得补充文档中没有的信息。不确定时用 status=UNCLEAR，并在 outcome 写明不确定之处。

## 4. 禁止

- 不得跳过任何一轮：每个自有轮恰好一条标注（无内容也要写 NO_CONTENT）。
- 不得改写引文：intent_quote、ai_quote 必须逐字复制。
- 不得引用其他轮或其他分支，除非该内容在本轮文档中逐字出现（refs）。
- 不得修改 `qa/`。文档由导出器生成，手工改动视为违规。
- 不得打开其他组的标注文件，也不得替其他组写标注（§6）。

## 5. 节奏与续做

- 每读完 10 轮，把对应标注追加写入文件（追加，不覆盖已有行）。
- 压缩或中断后不依赖记忆：先运行校验（004），以报告中的缺口为准继续。续做顺序不限，只看 doc 集合是否完整。

## 6. 并行分组（权威）

本次标注分为八组，每组由一个独立会话完成。组与单元、轮号范围以下表为准，`check_annotations.py` 的 `--docs` 与之一致。

| 组 | 单元（轮号范围） | 轮数 | 源字节（约） |
|---|---|---|---|
| G1 | `dev-08.a`（0001–0040） | 40 | 443 KB |
| G2 | `dev-08.b`（0041–0063） | 23 | 434 KB |
| G3 | `dev-08.c`（0064–0092） | 29 | 431 KB |
| G4 | `dev-08.d`（0093–0127） | 35 | 433 KB |
| G5 | `dev-03`（26 轮）、`dev-07`（8 轮）、`archive-01a0fb08`（3 轮） | 37 | 369 KB |
| G6 | `dev-09`（16 轮）、`dev-06`（13 轮） | 29 | 342 KB |
| G7 | `dev-01`（21 轮）、`dev-04`（15 轮） | 36 | 313 KB |
| G8 | `dev-02`（13 轮）、`archive-01a0fb73`（10 轮）、八个不可见尾部单元（共 9 轮：`unexported-01a0fb08`、`01a0fb73`、`01a0fc02`、`01a0fc53`（2 轮）、`01a10097`、`01a10533`、`01a106f7`、`01a107f1`） | 32 | 204 KB |

规则：

- 一个会话只负责一组，不替其他组写标注。
- 组内每个单元按 §1 逐轮读完整文档，按 §2 写标注；每读完 10 轮追加写入（§5）。
- dev-08 的四部分：标注文件分别为 `annotations/dev-08.a.jsonl` 至 `dev-08.d.jsonl`；检查时单元名仍是 `dev-08`，用 `--docs` 限定范围。四部分全部写完之后，再运行不带 `--docs` 的单元检查，由它判定 dev-08 的覆盖是否完整。
- 各组写入的文件互不相同，因此八组可以同时进行。
- 不可见尾部单元（`unexported-*`）的每一轮都要写明“未在任何 GUI 导出中”（SOP 002 §4）。
