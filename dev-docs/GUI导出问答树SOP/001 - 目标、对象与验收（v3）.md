# 目标、对象与验收（v3）

> **身份**：设计会话（Claude Code，Haiku 5.5，2026-10-08）按研究发起人的指示编写。与 002–006 冲突时，以本片的验收判据为准。

## 1. 原问（逐字）

- 2026-10-07，研究发起人：「我的目的是为了让接手这8个git worktree的工作的AI，最后能够以一个综合的角度去继续工作，但是现在这种提取方式，是不是和GUI导出的文件没有区别了？」
- 2026-10-08，研究发起人：「现在的这种方式，太慢了，几百个，这么慢怎么行？要快，你考虑一下如何加速？而且还要做好，做对，做完整，做到可审计。」
- 2026-10-08，研究发起人：「我是觉得可以切分之后形成编号化的文档，每个文档一片文档，然后AI下去通过每个分支文档的末尾，倒着去摸清楚，直至到达分叉节点的位置，AI在那个对话录中到底在干什么？」「每个分支的对话录放到一个单独的子文件夹中就可以了。」

## 2. 对象

- 输入：Codex 原始 rollout（`~/.codex/sessions/` 与 `~/.codex/archived_sessions/`），由导出器按谱系读取。涉及 8 个分支（dev-01、02、03、04、06、07、08、09）及其共享的归档根（R00、R01）。
- 对照：`git-worktree对话录/dev-*-gui.md`（GUI 导出）。只作对照，不作输入，不作判据。
- 不在对象内：dev-05（无导出文件）；其他任何 worktree。

## 3. 产物（全部在 `audit/GUI-SYNTH-REDO/`）

| 产物 | 位置 | 生成者 |
|---|---|---|
| 问答文档（每轮一份） | `qa/<分支>/NNNN.md` | 导出器 |
| 分支索引与收据 | `qa/<分支>/_index.jsonl`、`_branch.json` | 导出器 |
| 不可见尾部（未被任何导出引用的轮） | `qa/_unexported/<rollout>/` | 导出器 |
| 分支树与清单 | `qa/_tree.json`、`qa/_manifest.json` | 导出器 |
| 标注（每个自有轮一条） | `annotations/<单元>[.<部分>].jsonl` | 标注会话 |
| 分支卡 | `cards/<分支>.md` | 分支卡会话 |
| 综合 | `synthesis/` | 综合会话 |
| 校验与审计报告 | `reports/`、`audits/` | 校验工具、审计会话 |

## 4. 验收（判据 C1–C7）

- C1 覆盖：自有轮合计 = 唯一可见轮（当前 252）；不可见尾部逐轮导出（当前 9）。
- C2 标注完整：`check_annotations.py --stage annotations` 对全部单元通过；每个自有轮恰好一条标注。
- C3 引文逐字：全部 `intent_quote`、`ai_quote` 是所在轮文档的逐字子串；全部 `refs` 逐字出现在所在轮文档中。
- C4 分支卡：`--stage cards` 通过（章节齐全，每条有效引用）。
- C5 分叉：每个 `_branch.json` 的 `fork.parent_doc` 在父分支索引中存在。
- C6 综合：`synthesis/` 中的每个引用存在；论断表每条有证据引用。
- C7 审计：按 006 的抽样，独立复核的状态一致率 ≥ 0.9；不一致逐条记录。

## 5. 非目标

- 不做数学结论。若某轮出现数学命题，只能作为该轮的主张标注（status 与 outcome 写明），不得升格为结论；F-011 门禁对任何数学结论仍然适用。
- 不判定 HoTT 是否矛盾，不评价研究路线的对错。
- 不修改 `~/.codex/`（Codex 的工具与状态）、`git-worktree对话录/`（含其 README）、任何 rollout 原件。
- 不 commit，不 push，不调用 Agent 工具（子代理）。
- 不写研究 owner 文件（STATE、MEMORY、方向追踪、全景视野、核心认知）。

## 6. 身份

- 每个标注行记录 `reader`（会话名）与 `model`（模型 ID）。
- 标注会话与审计会话不得为同一会话。
- 模型家族不得为 GLM-5.3（此前的身份规则保留）。
