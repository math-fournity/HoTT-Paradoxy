## 2. 受控阶段

### G0：冻结候选 interface

目标：从一手来源或可执行正式系统固定 T、Accept_T、输入域、输出、Done、适用过程类别与 source owner。

最小判别动作：形成一张完整 GodelizationCard，并逐项标 SOURCE_CERTIFIED、MACHINE_PROVED、PROJECT_DEFINED 或 OPEN。

停止：没有真实 interface，只能登记 ACTUAL_INTERFACE_UNDERDETERMINED_WITH_SCOPE；不得用 C-359 或新 Bool fixture代替。

#### G0 当前执行记录（2026-10-04）

已在 [G0 接口分母](../../audit/20261004-GODEL-Q-REFLECTION-G0-INTERFACE-DENOMINATOR.md) 冻结一个真实、版本固定的 Metamath `set.mm` proof-acceptance interface（`develop@160ebb63…`），并将它与 IEP/Norton 的标准解答 completion contract 及 C-366 的 Zermelo process-representability control 分开。

该结果只表明：实际 `Code / Check / Accept_T` 作为 proof-validation interface 可以冻结；它没有把同一 interface 接到芝诺／圆环／fixed H0 的 `OriginDone`、`ρ` 或 bridge。故本方案的 parent-Q 链仍停在 `PARENT_COMPLETION_ACCEPTANCE_INTERFACE_UNDERDETERMINED_WITH_SCOPE`，G1–G6 不因该 proof interface 自动释放。

本轮还重放了 Foundation 的通用哥德尔第一／第二不完备性 source，因而 G2 的 code/quote/substitution/provability技术骨架已具 exact machine baseline；但它的 `ArithmeticTheory` 假设尚未被映射到 `set.mm`／bare ZFC 或任何 parent completion process。此基线不等于 target-specific G2 payment，详见 `audit/20261004-GODEL-Q-REFLECTION-G2-FOUNDATION-GENERIC-GODEL-BASELINE.md`。

为避免把“同一源树中有 ZFC module 与 generic theorem”误当作映射，本轮增加了一个受控直接实例化检查：`ZermeloFraenkelChoice : SetTheory` 与 `Arithmetic.incomplete` 所需的 `ArithmeticTheory` 不能直接对接，Lean 给出预期类型拒绝。该结果属于 `G2_TARGET_MAPPING_GUARD`，只说明必须实际构造并验证 interpretation／arithmetization；它不释放 G2、G3 或 parent-Q 链，完整收据见 `audit/20261004-GODEL-Q-REFLECTION-G2-FOUNDATION-ZFC-GODEL-MAPPING-GAP.md`。

在三类来源、Foundation/Flypitch mapping control 和最后一轮四查询统一-source screening 后，G0 当前来源分母已作 `COMPLETE_WITH_SCOPE` 收束：没有同一版本固定 source 同时支付 actual ZFC-facing acceptance、特定 `OriginDone` 与 bridge/task switch/rejection。它不宣称不存在这样的来源，只使无新 ingress 时继续制造 G1/G2 fixture 成为不合格推进。详见 `audit/20261004-GODEL-Q-REFLECTION-G0-INTERFACE-DENOMINATOR.md` §7.2。

后续 exact `set.mm@160ebb…` database replay 通过官方 verifier 的 `VERIFY PROOF *`，并直接发现 source 已在 ZF 内定义 Gödel-set formula、satisfaction、generic Metamath formal systems、provable pre-statements和theorem witnesses。官方 Appendix C 还给出 database token/frame 到 abstract formal-system component 的说明性 correspondence，但同时说明有限 database通常只描述 formal system的有限子集，完整 mapping需要另行形式化说明语言；因此 exact source没有支付 actual database→`mFS` mapping、defined adequate `Prv`或target diagonal。2026-10-05 对公开 `develop@584b685…` 的最小增量复核只见 typesetting 修订，没有新的 G2 mapping candidate。这条 G2 source requalification现已作有界收束，详见 `audit/20261004-GODEL-Q-REFLECTION-G2-SETMM-INTERNALIZATION-REQUALIFICATION.md`。

此前 MM0 matching-runner blocker现已被实际消耗。固定 `mm0-hs@0d414c0…` 在 locked GHC 8.6.5／`lts-13.27` lane 完成 build；它对 raw source的`show-bundled`在现代 double-quoted `$j` color metadata处以 exit 1拒绝。只规范化这六条 comment metadata后，fixed Metamath verifier仍重新验证全部 proof，`from-mm`产出20 MiB MM0和41 MiB MMB，reference `mm0-c` exit 0。该结果只增加`M_LEVEL_WHOLESALE_TRANSLATION_CONTROL_VERIFIED_WITH_SCOPE`；不能从派生输入成功推出 raw-byte direct replay、更不能推出`set.mm → mFS`、adequate `Prv`、diag或parent bridge。详见matching-runner audit与run receipt。

### G1：固定原过程与 ρ

目标：对同一候选接口，冻结 State、Input、Operation、Observation、FormalDone、OriginDone 与保真映射 ρ。

最小判别动作：同一任务卡加一个 bridge-paid 正控制和一个 DifferentTask 反控制。

停止：用户原过程或来源过程无法唯一固定时，登记 USER_PROCESS_CONTRACT_REQUIRED 或 ORIGIN_DONE_NONUNIQUE_WITH_SCOPE。

### G2：编码、有限检查与可表示性

目标：证明 Code、Check、Accept_T、substitution 的有效性／终止性／对象层可表示性，并支付 `ObjectCodeBridge`（code 到 T 内可引用 object；算术中的 numeral/term 或集合论中的 set-code）和 `InternalProvabilityAdequacy`（外部 proof relation 到 T 内 `Prov_T` formula）。

最小判别动作：对有限 code 的 checker 给出 totality evidence；对任一 source claim 分开标明是在 T 内、M 内还是只在 host 中执行；再给一个 code/object/substitution 对应的正控制与一个 host-quotation 不足的反控制。对 `set.mm` 首先检查 actual database到`mFS/mPPSt/mThm`的 mapping。

停止：若 checker 只能在 host 中存在，登记 META_ONLY_ENCODING_WITH_SCOPE；不得暗中用 host 计算替代 T 内 representability。

### G3：对角化资格

目标：固定 quote、substitution、diagonal 或 fixed-point construction，并检查它作用于 Accept_T 而非同名外部谓词。

最小判别动作：机器检查 diag 输入输出类型、编码往返和至少一个非自引用正例。

停止：缺 quote、substitution、有效枚举或可表示性时，登记 NO_GODELIZATION_PRECONDITION_WITH_SCOPE。

### G4：反射边界 theorem

目标：构造 d，并证明固定的 Accept_T / Bridge / OriginDone 合同下究竟发生不接受、反射失败、不完备性，还是来源已支付 bridge。

最小判别动作：主 theorem、negative control、BridgePaid control、AcceptanceAbstention control。

停止：只交付其精确条件性 theorem；绝不从失败的一次 proof search 推出不可证明性。

### G5：元元层同一任务审计

目标：审计 ρ 和 source owner，判断 G4 的 d 是否仍属于研究发起人真正关心的过程类别。

最小判别动作：逐字段同一任务表，至少覆盖对象、输入、操作、观察、Done、consumer、bridge 与现实解释。

停止：若 d 是新造句法任务而非原过程，结论降为 GENERIC_GODEL_BOUNDARY_WITHOUT_REALITY_BRIDGE。

### G6：与 F-050 总闭环的接入

只有 G0 至 G5 全部有来源或机器支付，才允许把结果作为 M2、M3、M4 或 M5 的新输入。接入时必须重审 C-359 的 SameFullQ、P、B 前提；不允许以名称相同自动传输。

当前 canonical closure 是 CC-20261004-godel-q-reflection。每次开始、跨 Session、压缩恢复、切换 T、切换 Accept_T、切换 ρ、切换证明器或形成 material conclusion 时，先读：

## 4. 完成、停止与重开

| 状态 | 必要条件 | 允许的结论 |
|---|---|---|
| ACTUAL_GODEL_Q_REFLECTION_BOUNDARY_WITH_SCOPE | actual interface、ρ、encoding、diag、bridge 和 kernel theorem 全部支付 | 该精确 interface 的反射不完备或 completion boundary |
| SOURCE_INTERFACE_DEFENSE_WITH_SCOPE | source 明确拒绝、加 bridge 或改写 Done | 该来源 target 的防御成立 |
| NO_GODELIZATION_PRECONDITION_WITH_SCOPE | T 或 interface 无有效编码、substitution 或 fixed point | 该 target 不满足哥德尔化条件 |
| META_ONLY_GODEL_RESULT_WITH_SCOPE | theorem 只在 M 中构造，未支付 T 内 representability 或现实 ρ | 仅元理论结果 |
| FORMAL_TARGET_UNDERDETERMINED | T、Accept_T 或 OriginDone 无法稳定冻结 | 不开始伪造 diagonal |

总方案完成只在以下两种情形之一发生：

1. 一个来源和机器支付的实际 哥德尔式 reflection boundary 已形成；
2. 所有经 G0 冻结的候选 interface 都以明确 denominator、反控制和 reopen condition 得到有界结论。

一个来源沉默、一个 checker timeout、一个 project-defined fixture、一个未运行 external compiler 或一个 R3/R4 历史文件都不是总完成条件。
