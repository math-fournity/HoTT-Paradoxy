# P校准收敛、来源覆盖与Power Set站位退出合同

> **身份：** `CALIBRATION_AND_STATION_CONTROL / CURRENT_METHOD_CONTRACT / NOT_A_ZFC_THEOREM_OR_NEGATIVE_CONCLUSION`。

## 1. 为什么需要这份合同

P 的目标不是不断增加 prompt 门，也不是把“成功抓到已知罗素正控制”误写成“已在 ZFC 找到未知 Q”。同样，Power Set 是正确的显眼首点，并不授权在同一邻域无限重复 guard。这里给出两个独立的、可审计的状态机：

1. **P 校准收敛：** 当前证据究竟只证明已知 fixture，还是已经证明在独立理论接口上能生成并验证新线索？
2. **Power Set 站位退出：** 当前工作是在处理一个新的 retained-guard ingress，还是只是在重复已关的防线？何时应进入整体换站审查？

这份合同不把“未知”变成可机械打分的属性，也不设任意节点数量阈值。它要求每个状态变化都有冻结 profile、来源、控制和可推翻条件。

## 2. `PCalibrationConvergenceCard`

每次准备声称“P 已写对”“P 已在 ZFC 上开始兑现一遍匹配”，或准备进一步修改 P1/P2/P3 时，先写：

```text
Calibration target: location / language reentry / construction order / same-task bridge
Target-Q / Candidate-Q / Control-Q: research task shape, frozen local card, and calibration/control role
Input identity: blind profile or fixed source card; answer-leak exclusions
Known-control status: which expected positive/negative control is being exercised?
Independent-interface status: is the interface distinct from the fixture family?
Discovery result: no candidate / site candidate / prospective Q?
Validation result: source layer, active-demand/payment, P2/P3, controls
QConvergenceLink: candidate identity, Q state before/after, and generate/narrow/bridge/converge/reject effect
Novelty boundary: not pre-supplied as this profile's expected answer or prior project answer
Falsifier: what output/source would lower this level?
Next state / stop condition
```

### 2.1 校准状态

| 状态 | 允许说什么 | 仍不能说什么 |
|---|---|---|
| `CAL-0 INPUT_INTEGRITY` | 隔离、模型/effort、prompt 和 runner 的输入合同已通过。 | P 对任何数学接口有效。 |
| `CAL-1 KNOWN_CONTROL` | P 能在明确的已知正／负控制上按预期区分，例如 H050 的无限制负自回代与 H051 的 bounded guard。 | P 已发现新理论问题。 |
| `CAL-2 INDEPENDENT_INTERFACE_SELECTION` | 在不泄漏项目答案的 profile 中，P 对一个不同接口给出 concrete site／prospective task，并经来源确认其对象和层级。 | 该 site 已是 Q，或 P 已知如何绕过支付／guard。 |
| `CAL-3 SOURCE_SURVIVING_PROSPECTIVE_Q` | 一个不作为该 profile 的预设答案、也非既有项目答案的线索，在来源包中通过 active-demand、nontriviality、payment 和同一任务的初检。 | 三刀已会合，或已找到 ZFC Q。 |
| `CAL-4 SAME_CARD_Q_CONVERGENCE` | P1/P2/P3 在同一 `T/u/F/C/Q/I/O/Done` 上保留 retained-guard surplus、真实 positive obligation 与相称控制。 | ZFC 不一致、UR 或数学定理，除非另有相称证据。 |

`CAL-1`不是失败；`CAL-2`也不是“P 已写对”的充分证明。当前 Power Set 线的已知正控制主要在 `CAL-1`；不同接口的盲态候选可能达到 `CAL-2`，但只要来源把它直接支付、降为 proof layer，或缺同一任务，就不能升到 `CAL-3`。

### 2.2 修改刀具的收敛纪律

新的 gate、prompt 字段或刀具修订只有在下列任一事实下才可提出：

- 已冻结卡的来源事实无法由现有字段忠实表达；
- 正／负控制显示旧字段把不同结果合并；
- input contract、field relay 或 layer map 的实际失败可由一个最小修订预防，并有回归收据；
- 一个 Tool-BirthCard 显示 P1/P2/P3 都出现不可消除的 distortion witness。

“模型没有命中”“想再精细一点”“又发现一个相似 guard”不构成修刀理由。每次修订须写明它会改变哪一个 `CAL-*` 判词，以及它怎样改变一张固定 Q 卡或保护其不被误判；没有校准影响时，记为 `NO_NEW_CALIBRATION_DELTA`。

### 2.3 `QConvergenceLink`：校准服务于 Q 的共同涌现

`CAL-*`衡量的是 P 在何种输入与来源条件下表现出何种能力；它不是 P-FORGE 的独立终点。P-FORGE 的
研究进程由 [009](<009 - ZFC共同锻造与成功判据.md>) 的 Q 状态管理：`Q-0 UNFORMED`、`Q-1 SEED`、
`Q-2 ACTIVE_CANDIDATE`、`Q-3 BRIDGING`、`Q-4 CONVERGED`或`Q-R REJECTED_WITH_SCOPE`。

每一个校准、来源、guard、Tool-BirthCard 或 Battle 必须说明它对某张 Q 卡的作用：

| verdict | 何时允许 | 对 P-FORGE 的含义 |
|---|---|---|
| `Q_GENERATE` | 在显眼 `u/F` 上出现可来源核验的 prospective Q。 | 新卡从 `Q-0` 进入 `Q-1`。 |
| `Q_NARROW` | 一个来源或控制排除具体 Q 形状，同时留下更窄的同一任务空间。 | 保留可重开条件，不把理论写成安全。 |
| `Q_BRIDGE` | P2 或 P3 为固定卡补上来源支持的片段。 | 允许从 `Q-2` 向 `Q-3` 检查。 |
| `Q_CONVERGE` | 三刀同卡会合。 | 仅此时可登记 `Q-4 / ZFC_Q_LOCATED`。 |
| `Q_REJECT` | 来源支付或 guard 关闭固定候选。 | 登记 `Q-R`，是有界发现而非失败。 |
| `Q_SAFETY_REPAIR` | 修复能防止一张已冻结卡被误报为Q。 | 合法维护，但必须列被保护的卡和回归。 |
| `Q_CAPABILITY_CALIBRATION` | 受控正负fixture验证P能辨认未来 Candidate-Q 的必要结构，并列出 Target-Q、消费它的真实 source card和停止条件。 | 发现能力增长；不改变特定理论卡的Q状态。 |

`Q_CAPABILITY_CALIBRATION`不能取代真实来源：若没有被校准的P字段、成对controls、Target-Q、明确的下一真实source card和停止条件，它不成立。没有上述联系的工具修改是`TOOL_ONLY_DRIFT`。它可作为一般运行维护存在，却不累计为 P-FORGE 的研究进展，
不得以它延后 Q 的重新定位、增加理论节点或宣称“正在逼近”。这条纪律把“锻刀”和“发现 Q”保持为同一个
可审计过程，而不把刀具数量、prompt 数量或 guard 数量当作代理指标。

## 3. `SourceLayerCoverageMatrix`

每个 ZFC／Power Set ForgeIntent 必须声明 `SourceLayerTarget`，并把来源放进下列格之一。一个 formalization source 可以忠实表述规则，却不能自动覆盖数学实践、模型语义或现实 construction：

| 层 | 问题 | 当前 Round 1 状态 | 不能由它代替 |
|---|---|---|---|
| `L-A RULE/AXIOM` | 具体 formation、bound、rank、class/set规则如何说？ | `PARTIAL`: Isabelle/ZF 文档和源码给出若干规则；原生公理陈述与其数学使用仍要分开。 | 实际 consumer/Done。 |
| `L-B PROOF/FORMALIZATION` | proof package 或形式化库怎样使用规则？ | `COVERED_WITH_SCOPE`: Metamath、Isabelle、Mathlib、HF controls，以及 H075 的 Constructible Reflection proof card。 | 裸理论语义或实践。 |
| `L-C MODEL/SEMANTIC` | 某个模型、内模型、satisfaction/reflection怎样解释接口？ | `GAP`: `Mset`／`Reflects` 出现在 Isabelle proof-theory source 中，不因术语含有 model/reflection 就计作独立语义层覆盖。 | 所有模型或现实过程。 |
| `L-D MATHEMATICAL_PRACTICE` | 数学消费者的任务、输入、观察和Done是否依赖该对象？ | `GAP`: 尚无非有限 Power Set consumer满足 retained-guard surplus。 | 仅靠定理名或库存在。 |
| `L-E CONSTRUCTION_BRIDGE` | 理论静态形成与实现／实践／现实过程是否同一任务？ | `PARTIAL_FINITE_CONTROL`: H073仅覆盖 `Finset`。 | 任意／无限 ZF set。 |

`L-A`到`L-E`不是“越外层越真”的等级。它们是不同证据责任。每个 candidate 必须声明它需要哪些层；缺层时保持 gap，不能用已经覆盖的层补写。

## 4. Power Set 站位状态机

### 4.1 Round 停止

`ROUND_STOP_REPEATED_GUARDS`在下列情形成立：已固定账本中同一 guard、同一来源层和同一任务控制已经处理，而新提案不改变 PS4、PS5、来源层或理论接口。此时节点不得启动，判为：

```text
REPEATED_GUARD_NO_NEW_FORGE_INTENT
```

Round 1 已达到这一状态；其具体分母由 `audit/20261003-P-FORGE-POWERSET-DEFENSE-LEDGER-ROUND1.md`拥有。

### 4.2 全局站位退出审查

Power Set 不是因为若干卡被 guard 阻断就自动退役。只有满足下列审查输入，才可讨论整体换站：

```text
S1  当前 ledger 已列每张已消费来源的 PS0–PS6、反证和 reopen trigger。
S2  SourceLayerCoverageMatrix 对 L-A 至 L-E 全部有明确状态；GAP 可以保留，不能隐藏。
S3  至少一个非 Power Set 的显眼基础接口已按同一 P1/P2/P3 标准作竞争检查。
S4  当前没有满足“新 ingress”条件的已授权来源卡：
    retained-guard PS4、非有限同一任务 bridge、新接口竞争位置或账本反证。
S5  `PCalibrationConvergenceCard` 明确当前只能到哪一 CAL 状态，未把 fixture 成功冒充 Q 收敛。
```

站位判词只能是：

| 判词 | 含义 |
|---|---|
| `STATION_RETAIN` | 存在一个新的、已冻结的有效 ingress。 |
| `STATION_EXIT_REVIEW_PENDING` | S1–S5尚未齐备，或有 source/interpretation gap。 |
| `STATION_SWITCH_CANDIDATE` | S1–S5齐备且当前无有效 ingress；形成有界负结论草案，等待研究发起人选择下一明显承诺。 |
| `STATION_REOPENED` | 新来源、控制或 retained-guard surplus推翻了既有 stop。 |

`STATION_SWITCH_CANDIDATE`不等于“ZFC 被防住”，更不自动授权选择 Choice、Replacement、Infinity、truth/satisfaction或其它下一靶。研究发起人选择下一站，Master 冻结新站的理论接口和控制。

reasons                  = L-C/L-D/L-E仍有明确 gap；S3的非Power-Set显眼基础接口

## 5. 重新启动 `/goal` 的最小首动作

恢复 `P-FORGE-SOP` 后，Master 先回读本合同、Round 1 ledger 和最新 terminal-node 收据，再写一张新的 `ForgeIntent`。它必须含：

```text
SourceLayerTarget / Calibration target and current CAL level
QConvergenceLink: fixed candidate/card, Q state before/after and expected delta
Power Set station impact / S1–S5 delta
P1/P2/P3 or P3-C fields to change
same-task controls / stop and reopen condition
why this is not a repeated guard
```

任何缺项让 node 停在 `FORGE_INTENT_INSUFFICIENT`。这不会阻止研究；它防止“继续”被解释为无限添加同义来源。

## 6. 不应外推

本合同只管理研究方法的身份、来源分母和停止条件。它不证明 P 已经写对、ZFC 有或没有问题、HoTT 已被数学推翻、Power Set 已被穷尽，或将未来理论选择交给自动状态机。
