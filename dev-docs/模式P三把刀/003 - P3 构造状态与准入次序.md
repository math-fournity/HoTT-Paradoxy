# P3 构造状态与准入次序

## 它的刀刃

P3 直接保留“算符先于存在性落定”的计算张力。它不从已完成的公式出发，而是问：对象 `u` 处于构造中时，哪个 operator 已把它当作输入；该 operator 是否要求 `u` 已获论域资格；而资格是否又只能等 formation 完成后取得。

## 最小状态语言

```text
Draft(u)             已命名，尚未完成交付
NeedBuild(u)         formation 尚有义务
NeedEval(R(u,u))     义务要求评估某判断
Admitted(u)          可作为论域元素进入 operator
OperatorUse(R,u)     operator 以 u 为输入
Guard                OperatorUse 是否前置 Admitted(u)
BuildDone(u)         formation 完成
```

P3 寻找的不是任意循环，而是有规则依据的依赖环：

\[
Admitted(u)\leftarrow BuildDone(u)\leftarrow Eval(R(u,u))
\leftarrow OperatorUse(R,u)\leftarrow Admitted(u).
\]

## 当前方法与惯性

P3 的自然惯性是“把静态理论重新读成构造过程”。这正是它的力量，也最容易越界：很多形式理论把存在公理、形成规则或证明对象当作原子判断，并没有承诺运行时的 `Draft`、`NeedBuild` 或资格调度。因此 P3 必须显式标注自己的构造语义来源：理论规则、证明器实现、形式化算法、真实数学实践，还是哲学／现实解释假设。

## 进一步迭代的方法

- 先冻结状态机和 transition rules，定义每个状态由什么证据进入／离开；
- 对每条依赖边逐项写出规则或语义依据，不能以“直觉上构造要花时间”代替；
- 将 `formation-as-atomic`、`operator-without-admission-precondition`、`explicit certificate/guard`、`well-founded stage/limit rule` 作为负控制；
- 设计最小正控制：确有 pending 对象、formation 完成依赖 operator evaluation、operator evaluation 明确要求 admission；
- 和 P2 配对：P2 给已完成规格的逻辑余式，P3 给生成该余式前是否已有未支付时序债务。

## 强制 MatchTrace

P3 输出必须把每条 state/edge 写成 `source transition → P3 label → prerequisite/effect → counterfactual`，并说明何种邻近静态读法被排除。例如不能只说“存在 pending”，必须说明它由哪种状态表示引入；不能只说“operator 先用对象”，必须给 guard 与实际 transition。没有逐边 MatchTrace 的 cycle 或 completion 结论为 `UNEXPLAINED_P3_TRACE`，不能提升为 process tension；共用输出格式由 [010](<010 - 代理匹配自我说明合同.md>) 固定。

## 停止条件

如果理论只提供静态存在／形成断言，且没有可审计的构造状态或使用前置条件，P3 输出 `CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`。这不是理论安全证明，也不是 P3 失败；它说明当前材料不能把哲学上的构造读法提升为该理论的运行事实。
