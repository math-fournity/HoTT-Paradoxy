# ZFC共同锻造与成功判据

> **身份：** `CURRENT_FORGING_SUCCESS_OWNER / ZFC_LOCATION_RESEARCH / NOT_A_MATHEMATICAL_INCONSISTENCY_CLAIM`。
>
> **用户裁定：** 锻 P1/P2/P3 与定位 ZFC 问题是同一个过程。刀具只有在共同把一个 ZFC 的 Q 定位出来时才算在本研究意义上锻成；ZFC 对刀具的反馈反过来决定下一轮怎样修刀。

## 1. 共同成功不等于三张独立候选卡

`ZFC_SITE_SELECTED` 与 `ZFC_Q_LOCATED` 分开：

| 状态 | 含义 |
|---|---|
| `ZFC_SITE_SELECTED` | P1 在无泄漏条件下选择了对象级核心位置，例如 Power Set。 |
| `ZFC_Q_LOCATED` | P1/P2/P3 在**同一** ZFC theory variant、同一 `u`、同一 formation、同一 consumer 和同一 Done 上，各自给出互相兼容的定位。 |
| `ZFC_TENSION_EXPLAINED` | 已明确该 Q 为什么在人话上不合理，并有相同任务、标准回答和反控制。 |
| `ZFC_MATHEMATICAL_CLAIM` | 另需精确形式命题、来源、证明或模型证据；前三层都不自动产生它。 |

当前 `P(a)` 只达到 `ZFC_SITE_SELECTED`。它不因为已有 P1 卡或 P2/P3 的“不适用”就被说成已经定位到问题。

## 2. 三刀会合合同

对同一个候选，必须冻结：

```text
T      : ZFC 的精确语言／公理变体
u      : 一等集合对象或形成接口的输出
F      : 形成规则
Q      : 同一对象的、由理论实际提出的追问
C      : 有 source contract 的真实消费者／算符
I/O/Done : 同一任务的输入、操作、观察、完成条件
```

三刀各自的不可替代义务：

| 刀 | 对 ZFC 会合必须贡献什么 |
|---|---|
| P1 | 证明 `u/F/C` 是 ZFC 自身的核心位置，`C` 具有输入／输出／Done 的 source contract，且外置／局部化会改变当前任务。 |
| P2 | 从实际 ZFC language contract 中给出 `Bind/Form/Bridge/Reenter/Polarity/Guard` 的正匹配，或精确指出哪个 guard 使当前 Q 不可能是 P2 形状。 |
| P3 | 从实际 construction/consumer semantics 中给出 pending/admission/completion transition，或精确指出静态公理为何没有该语义以及缺少什么 source。 |

若 P2/P3 合法输出“不适用”，它们提供的是重要防线；此时**共同 Q 尚未定位**，而不是 P1 单独胜利。

所有三刀卡还必须提供 [010 所定义的 `MatchTrace`](<010 - 代理匹配自我说明合同.md>)：每项 source fact 如何填充刀具字段、候选为何从竞争位置中被选出、Q 如何最小归约、哪个邻近 site 被排除、替换何条件即失效。P1 另受 `L6/Q-friction` 和 `L7/obligation mode` 约束：Q 不得只是同一 interface 反身性或定义展开立即回答的判断，也不得只是允许 consumer 合法回答 false 的普通查询。

## 3. 当前 Power Set 差距

当前卡：

```text
u = P(a)
F = power-set existence axiom
P1 = object-level, direct-completion site selected
P2 = no unrestricted formula binder / bridge / reentry on neutral ZFC card
P3 = no pending/admission lifecycle in static existence axiom
```

所以最初的自然语言问题仍是候选而非已定位的 Q：

> 什么使 `P(a)` 有资格作为“所有 a 的子集已经完成、可被后续算符使用”的对象？

要把它变成 `ZFC_Q_LOCATED`，下一轮必须找到真实 ZFC consumer 的**source contract**（输入、输出、Done），确定该 consumer 是否对这个“已完成”状态提出了未被公理原子化掉、且不能以 false 分支正常完成的**正义务**，并让 P2/P3 对同一义务给出实际 language/process 映射。不能以不可枚举、元语言全体、外加算法要求、裸关系符号，或一个可普通判假的 membership 查询代替这一步。

## 4. 联合盲测合同

`ZFC-COFORGE-001` 证明“三刀同一 prompt 各自填卡”会污染 P1：P2/P3 的易填性会改变 P1 的 site selection。因此共同锻造不是同时让三把刀抢同一个提示，而是按下列**冻结接力**进行：

1. **P1 blind selection：** 不提供既有 Power Set 结论、路线图、审计答案或历史名称；只给冻结 ZFC source card，P1 独立选择 `u/F/C` 并冻结卡；
2. **P2 blind mapping：** 只给同一 source card 与已冻结 P1 卡；不得重选 `u`，只判断 language contract 是否可在该 `u/F/C` 上形成 Q；
3. **P3 blind mapping：** 只给同一 source card 与已冻结 P1 卡；不得重选 `u`，只判断 construction/consumer semantics 是否形成 Q；
4. **Master convergence：** 比较 `u/F/Q/C/I/O/Done` 是否同一；`NOT_APPLICABLE`、`GUARD_BLOCKED`、`CONSTRUCTION_SEMANTICS_NOT_SUPPLIED` 都是有效结果；
5. 只有明确会合才可写 `ZFC_Q_LOCATED`；未会合时，输出哪把刀的何项 gap 驱动下一轮修订。

每一棒均须要求外部代理交付结构化自我说明。它报告的是可观察、可核对的来源—规则—选择理由，不能被误称为模型隐藏思维的完整转录；其质量将用 source 对照、相邻候选淘汰和反事实重跑检验。

P1 的独立性不是把工具又拆成两条线，而是保护三把刀各自的惯性，确保它们真正会合而非被同一提示预先强制成一致答案。

多 worker 的实际组织、各节点能否读取项目分支／网络、何时派 Battle 与 Master 如何裁决，现由 [模式 P 动态 DAG 调度](<../../模式P动态DAG调度.md>) 拥有。该编排不降低本片的同卡会合标准。

### 4.1 COFORGE-001 结果

在同时提示 P1/P2/P3 的首次联合外部测试中，代理选取 bounded separation，P2/P3 均 fail closed，输出 `ZFC_SITE_SELECTED_ONLY`。这不是对 Power Set 的反证；它是 `JOINT_PROMPT_P1_DRIFT` 证据，迫使协议采用上述冻结接力。完整收据：`audit/20261002-ZFC-COFORGE-001-外部CLI-Terra-Max.md`。

### 4.2 COFORGE-002-P1 结果

冻结接力的 P1 独立 session重新选回 Power Set witness `u=P(a)`，并给出完整 availability→membership consumer 的说明；但其候选 Q 是 `a∈P(a)`，最小归约为 `a⊆a`。这满足 site selection，却被同一 interface 平凡清偿，故记为：

```text
ZFC_SITE_SELECTED / SITE_SELECTED_Q_TRIVIAL / NOT_ZFC_Q_LOCATED
```

这次 MatchTrace 精确暴露 P1 需新增 L6：共同锻造必须寻找由实际 consumer 提出的、未被 formation rule立即消掉的 Q。P2/P3 不应消费这张平凡 Q 卡；下一轮先以 L6 修订后的 P1 重选。

### 4.3 COFORGE-003-P1：非平凡 membership 条件仍未通过 obligation mode

L6 修订后的独立 P1 选择 `a∈P(P(a))`，并将它最小归约为 `∀x∈a, x⊆a`；它还以 `a∈P(a) ↔ a⊆a` 作为被排除的反身性邻近项。这份报告首次把“为什么选它”完整写出来，见 `audit/20261002-ZFC-COFORGE-003-P1-外部CLI-Terra-Max.md`。

但这只是一个非平凡的 affirmative membership 条件：若它不成立，membership consumer 可以正常给出 false。冻结卡没有给出一个必须令此条件为真的 consumer Done，也没有让 formation 等待该条件。因此主研究者新增 L7/obligation mode，并将该卡降为：

```text
ZFC_SITE_SELECTED / ANSWERABLE_FALSE_BRANCH / NOT_ZFC_Q_LOCATED
```

### 4.4 COFORGE-004：独立 L7 审查

独立 Terra / Max reviewer 在最有利于候选的“membership 是 consumer”读法下，仍给出 `ANSWERABLE_FALSE_BRANCH`：true 是 affirmative answer，false 是完成的 negative answer；静态 card 未给出“false 即未完成”的 consumer contract。它也明确列出了令这一卡通过 L7 所缺的 source fact，完整可复核说明见 `audit/20261002-ZFC-COFORGE-004-L7复核-外部CLI-Terra-Max.md`。

这只复核 L7 在本张中性卡上的作用，不能证明任何 ZFC 命题或排除未来由真实 consumer source 支持的 Power Set 候选。

### 4.5 COFORGE-005-P1：L0–L7 重跑暴露 consumer contract 缺口

在不提供既有候选的更新盲测中，独立代理比较了 `b∈P(a)` 与 `P(a)∈P(a)`。它把前者选为最接近的 route，但严格检查后拒绝把“membership 是 relation”当作 source-defined consumer task：source card 没有给出输入—输出—Done contract。最终是：

```text
SOURCE_CONSUMER_GAP / NO_ZFC_Q_ON_NEUTRAL_CARD
```

这次结果把 L2 精化为 L2b：裸 relation/predicate 不能自动占据 `C`。完整 E0–E7 报告见 `audit/20261002-ZFC-COFORGE-005-P1-L0-L7重跑-外部CLI-Terra-Max.md`。下一张 ZFC source card 必须是版本固定的、拥有实际 consumer contract 的材料；在此之前，Power Set 仍只是显眼 site，而没有共同 Q。

### 4.6 P-DAG-BATTLE-001：L2b 的首次有界动态裁决

用户要求把三把刀的使用改为由 Master 动态 DAG 调度后，第一张 Battle 用现有的 `C` 字段分歧作 smoke：一名 Terra/Max advocate 尽力让 relation-level membership 充当最小 consumer；一名 challenger 审核 C 的 input/output/Done contract；独立 arbiter 只消费同一 source card、L2b 和两份 sealed claims。arbiter 输出：

```text
RESOLVED_BY_SOURCE / SOURCE_CONSUMER_GAP
```

结果不是由多数票得到：advocate 自己承认其 `RELATION_AS_MINIMAL_CONSUMER` 依赖“atomic assertion 自动算 consumer”的额外 convention；source card 没有该约定，故 Master 保留 L2b 的缺口判词。完整 DAG receipt：`audit/20261002-P-DAG-BATTLE-001-Terra-Max.md`。这一运行验证 Battle 机制的来源裁决链，仍不构成 ZFC Q。

### 4.7 P-DAG-SOURCE-001：真实 consumer 有了，P2/P3 仍未会合

动态 DAG 的下一节点允许只读公开来源。它在 Mathlib4 `v4.16.0` 的 `ZFSet` ZFC-model 中冻结了 `u=powerset(prod x y)`、`F=powerset`、`C=funs x y`、`funs x y=sep(IsFunc x y) u`、`mem_funs` contract。这是正式库里的实际 power-set consumer，因而在该**模型／库变体**上通过 L2b；它不能被写成标准 ZFC 的同一来源事实。

对同卡独立运行的 P2 得到 `NOT_APPLICABLE`（没有 formula representation／Bind／Reenter），P3 得到 `CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`（没有 lifecycle transition）。所以新的 MasterVerdict 仍是：

```text
QUALIFYING_FORMAL_CONSUMER_WITH_SCOPE
P2_NOT_APPLICABLE
P3_CONSTRUCTION_SEMANTICS_NOT_SUPPLIED
NO_COMMON_Q / NOT_ZFC_Q_LOCATED
```

完整 receipt：`audit/20261002-P-DAG-SOURCE-001-Terra-Max.md`。它是第一张“真实 C 而没有虚构 P2/P3”的正控制；下一张 source card必须明确标准 ZFC、模型、库或数学用法的理论层级，并在需要时提供真实操作语义。

### 4.8 P-DAG-SOURCE-002 与 BATTLE-002：先固定 C/I/O/Done 所在层，P2 的 source match 仍不是共同 Q

`metamath/set.mm` 的 `ax-pow → axpow2 → vpwex → pwexg → pwex` 提供了 `A∈V ⟹ 𝒫A∈V` 的版本固定 proof-system source card。`pwex` 的 Done 是证明接受，故它可严格称为 `QUALIFYING_PROOF_SYSTEM_CARD`。但它没有在冻结 source 中提供一个对象层、语义实际使用层或 runtime 层的下游 C/I/O/Done。Battle-002 的裁决是：

```text
RESOLVED_BY_SOURCE
proof-system C supplied
ZFC object-level / semantic / actual-use / runtime C not supplied
```

因此 P1 新增 `L2c / layer integrity`：TaskCard 必须先标明 C/I/O/Done 的层；proof-level contract 不得跨层填入其它 consumer。该门防的是一种新的伪会合，不是贬低 `pwex` 的证明系统作用。

同一轮的 Isabelle2020 `ZF/Constructible/Formula.thy` 给出一张不同的 ZF source card：`formula`、`sats(A,p,env)`、`Forall` 的 `Cons(x,env)`、`incr_bv` 以及 arity/environment 守卫的 `DPow`。在这一张卡上，P2 的范围严格正匹配为：

```text
represented formula → satisfaction bridge → environment/de Bruijn re-entry
→ arity/environment guard
```

这不是 quotation、provability、fixed point 或 ZFC 悖论。P1 对同卡的 verdict 是 `QUALIFYING_SOURCE_CARD_NO_Q`：source 没有给出由一个 native consumer 的 Done 正向要求、且不能走 false branch 结束的 Q。P3 对同卡是 `CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`：公式递归、`sats` 与环境扩展是静态 syntax/semantics interface，而不是同一对象的 Draft/Admitted/OperatorUse/BuildDone transition。

所以本轮共同状态是：

```text
P2_MATCHED_WITH_SCOPE
P1_SOURCE_CARD_NO_Q
P3_CONSTRUCTION_SEMANTICS_NOT_SUPPLIED
PROOF_LAYER_ONLY
NO_COMMON_Q / NOT_ZFC_Q_LOCATED
```

下一张 TaskCard 必须先冻结目标层。只有 source 在那一层给出 native nontrivial positive Q 与 Done，且 P2/P3 能对同一对象、formation 和 consumer 画出语言／状态映射，才进入共同 Q 审查。完整收据：`audit/20261002-P-DAG-SOURCE-002-与-BATTLE-002-Terra-Max.md`。

### 4.9 P-DAG-SOURCE-003：未产出的网络节点不进入会合证据

三张企图寻找 Cantor 型 consumer 或 P3 lifecycle 的 `PRIMARY_WEB_SOURCE` NodeCard 在 4 分钟观察窗没有 final output。它们被取消后没有形成 source card、P1/P2/P3 MatchTrace 或 Battle 条件，故没有更新 `u/F/C/Q/I/O/Done` 的任何字段。唯一的流程结论是：以后先以具体 URL／version／layer／deadline 封存 NodeCard；没有 terminal output 时返回 `TIMEOUT_NO_TERMINAL_OUTPUT`，不得从 partial search 或“没找到”推断没有相关 consumer。完整收据：`audit/20261002-P-DAG-SOURCE-003-TIMEOUT-Terra-Max.md`。

### 4.10 P-DAG-SOURCE-005：Cantor theorem 不替代 same-`u` consumer

Master 对固定 Isabelle/ZF `ZF_Base.thy` source 直接审读了 `PowI`／`PowD` 与 `cantor`。`cantor` 是一个正式证明任务，陈述存在 `S∈Pow(A)` 使任意 `b` 不覆盖幂集；但在此来源范围内，`Pow(A)` 没有作为既有同一对象输入交给一个 source-defined semantic consumer，`S∈Pow(A)` 也没有被给成 formation 未支付的 Q。故该卡是：

```text
SOURCE_INSUFFICIENT_FOR_SEMANTIC_CONSUMER_CARD
NO_NATIVE_Q / NO_P2_OR_P3_MAPPING
```

它确认当前 L2/L2b/L2c 不会把一个定理 statement 错提升为共同 Q；不产生新 P 层或新刀。完整范围：`audit/20261002-P-DAG-SOURCE-005-Isabelle-ZF-Cantor-Master.md`。

## 5. 反向驱动规则

从此之后，任何刀具迭代都必须以一个 ZFC 共同锻造 gap 为触发：

```text
ZFC gap → 指定 P1/P2/P3 字段缺口 → 修订一把刀
→ 同一冻结 ZFC card 复测 → 记录会合增减
```

这使“刀具变锋利”和“ZFC 问题越来越可定位”成为同一条可审计链，而不再是两条平行工作线。

## 6. HoTT 无泄漏重放释放门

研究发起人在三把刀形成前已经规定：先用 P 与 Terra/Max 在不作弊条件下重新定位 HoTT 的问题；只有重放成功，才将冻结 P 用于 ZFC，检验它是否定位到 Power Set 或更好的位置。HOTT-DISCOVERY-007 后，先前 fresh CLI HoTT controls 的 blind context 均降为 `CONTEXT_ISOLATION_NOT_QUALIFIED`。`governance-v3.26.0` App Server lane随后通过 zero-material health和HOTT-DISCOVERY-008：它在冻结 D-L6b Prompt上得到一个无工具的 P1 discovery candidate，但 Book source的 `thm:hlevel-prod` 直接支付该候选，故仍没有同一 `u/F/C/Q/I/O/Done` 会合／重定位既有实际 Q 的 `HOTT_REPLAY_PASS`。可复用的 runner lane已经存在，但每个节点仍要重新证明输入与权限边界。

H015–H017 现在提供了这个 release condition 的有界满足：受控 App Server lane 中的 blind P1 在不见命名 source／答案时，以 D-L5 至 D-L9 选回 concrete `U`、同一 staged process 和 process-wide completion Q；source tracer 对应到 `judgeU`／`question`／`Halts`／`never`；同一具体 source card上的 P2/P3分别输出`P2_NOT_APPLICABLE`与`COMPLETION_PROCESS_NOT_ADMISSION_CYCLE`。H018又把“任务忠实性”准确标作`USER_JUDGED_A_DIRECTION_WITH_SCOPE`，而不是 kernel 所证的现实对应。完整收据见`audit/20261002-P-DAG-HOTT-REPLAY-015-017-Terra-Max.md`与`audit/20261002-P-DAG-HOTT-TASK-FIDELITY-018-Master.md`。

因此即时规则是：

```text
ZFC P-DISCOVERY / source / fixture / negative-control work: permitted under the renewed HoTT calibration
ZFC_Q_LOCATED / ZFC UR / “P 在 ZFC 成功”: blocked
next ZFC discovery requirement: freeze a D-L5--D-L9 blind P1 NodeCard and validate it against one source card;
                                do not reuse pre-release ZFC site selection as its result
ZFC upgrade condition: P1/P2/P3 still must meet on one ZFC theory variant, one u/F/C/Q/I/O/Done,
                       with a real consumer's positive obligation and task/UR controls
```

这不是把 ZFC 方向关闭，也不把 P1 source-process replay说成 ZFC 结论。它只纠正了执行顺序：此后的ZFC盲态选择必须消费已经由HoTT回测过的D-L5至D-L9，而ZFC共同 Q仍要经过本文件的严格会合标准。完整谱系见`audit/20261002-P-DAG-刀具系统全历史逐段对照审计.md`与H015–H018收据。

### 6.1 HOTT-DISCOVERY-005：native task 仍可能是已支付的任务

H-005 在 D-L5 下首次选出原生 HoTT 等价使用任务，但固定 Book source 随即给出 `ua : (A ≃ B) → (A = B)`；因此它是 `D_L5_DISCOVERY_PASS / P1_L6_TRIVIAL_CONTROL`，不是 release condition 的一部分。这个控制现已编译为 discovery-stage `D-L6/direct-payment screen`：对 packet-visible direct answer，节点须登记 `DISCOVERY_DIRECT_RULE_ANSWER`。H-006 进一步显示该 screen 不能让发现停在第一个被筛掉的 site，故 D-L6b 要求最多两个额外显眼基础接口。release predicate 因而要求 HoTT replay 不只避免 meta-layer candidate，还要越过 D-L6/D-L6b 并给出一个不被同一 formation/interface 直接偿付的、source-grounded P1 Q，随后才能要求 P2/P3 同卡会合。

同一薄 source packet 到此停止重复使用。后继 HoTT node 必须另行冻结 source packet 的选择理由、可见范围、禁止项目答案、所需 prospective native consumer 类、deadline 与终态政策；它不能通过不断改写提示把已有 `ua` 任务重新包装为张力。
