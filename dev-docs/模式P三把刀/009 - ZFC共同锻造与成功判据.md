# ZFC共同锻造与成功判据

> **身份：** `CURRENT_FORGING_SUCCESS_OWNER / ZFC_LOCATION_RESEARCH / NOT_A_MATHEMATICAL_INCONSISTENCY_CLAIM`。
>
> **用户裁定：** 锻 P1/P2/P3 与定位 ZFC 问题是同一个过程。刀具只有在共同把一个 ZFC 的 Q 定位出来时才算在本研究意义上锻成；ZFC 对刀具的反馈反过来决定下一轮怎样修刀。

## 1. 共同成功不等于三张独立候选卡

`ZFC_SITE_SELECTED` 与 `ZFC_Q_LOCATED` 分开：

| 状态 | 含义 |
|---|---|
| `ZFC_SITE_SELECTED` | P1 在无泄漏条件下选择了对象级核心位置，例如 Power Set。 |
| `ZFC_Q_LOCATED` | P1/P2/P3 在**同一** ZFC theory variant、同一 `u`、同一 formation、同一 consumer 和同一 Done 上，各自给出互相兼容的定位。 |
| `ZFC_TENSION_EXPLAINED` | 已明确该 Q 为什么在人话上不合理，并有相同任务、标准回答和反控制。 |
| `ZFC_MATHEMATICAL_CLAIM` | 另需精确形式命题、来源、证明或模型证据；前三层都不自动产生它。 |

当前 `P(a)` 只达到 `ZFC_SITE_SELECTED`。它不因为已有 P1 卡或 P2/P3 的“不适用”就被说成已经定位到问题。

### 1.1 P/Q 共同涌现不变量：锻刀不是与定位 Q 并列的工作

本研究里的“锻刀”和“发现 ZFC 的 Q”只有一个共同过程。P1/P2/P3 并不是先被做成一组独立、
可宣布完成的元工具，再拿去寻找 Q；它们在具体卡的失败、guard、来源支付、字段缺口和局部会合中
不断被修订，而这些修订的唯一研究性价值，是让一个可反驳的 Q 更容易**生成、收紧、桥接、淘汰或会合**。

这里的“涌现”是受来源约束的工作流概念，不是自动发现定理的承诺：一把刀可以先给出一个
`Q` 片段，另一把刀可以证明该片段被 guard 阻断，第三把刀可以给出或拒绝构造次序。只有这些片段
仍指向同一冻结 `T/u/F/C/Q/I/O/Done` 时，Master 才能把它们合成为同一候选的状态更新。

| Q 状态 | 含义 | 合法来源 | 不是 |
|---|---|---|---|
| `Q-0 UNFORMED` | 只有明显基础位置；没有可交给三刀的同一任务追问。 | `ZFC_SITE_SELECTED`、来源缺口。 | “已经有问题”。 |
| `Q-1 SEED` | P1 在固定 `u/F` 上提出一个 prospective Q，但消费者／Done 或支付尚未完整。 | blind discovery 或 formation-origin probe。 | 已验证候选。 |
| `Q-2 ACTIVE_CANDIDATE` | 固定来源给出 `C/I/O/Done`，Q 经 active-demand／payment 初检仍未被直接清偿。 | source validation 与同一任务 controls。 | P2/P3 已会合。 |
| `Q-3 BRIDGING` | P2 或 P3 在同一候选上给出来源支持的 bridge、reentry 或 state/admission 片段。 | 同卡 MatchTrace。 | 全部三刀已支持。 |
| `Q-4 CONVERGED` | P1/P2/P3 在同一冻结卡上共同保留正义务、未支付剩余与相称控制。 | 三刀会合合同。 | ZFC 不一致、UR 或数学定理。 |
| `Q-R REJECTED_WITH_SCOPE` | 来源支付、guard 或同一任务 control 关闭了这个候选或候选族。 | 固定来源与反控制。 | ZFC 已被全面防住。 |

这些是证据成熟度状态，不是强制的线性流水线：一个足够完整的来源卡可以直接形成 `Q-2`，而一个 guard
可以从任一尚未会合的状态进入 `Q-R`。唯一不可跳过的强门是 `Q-4`：它仍要求三把刀在同一冻结卡上会合。

`Q_CAPABILITY_CALIBRATION`不是第七种 theory-Q 状态。它记录的是：受控正负 fixture 已证明 P 能辨认
未来 Candidate-Q 所必需的一个结构，例如同域 negative reentry、payment、admission edge 或 Done 忠实性。
它必须列出 `Target-Q`、被校准的 P 字段、正控制、负控制、将消费这项能力的下一真实 source card，以及停止条件。
它不使任何理论卡前进到 `Q-1`，也不能成为无限追加夹具的理由；缺任一字段即是 `TOOL_ONLY_DRIFT`。

`QConvergenceLink`固定区分三层，防止真实来源控制被误写成理论Q：

| 字段 | 必须回答 | 边界 |
|---|---|---|
| `Target-Q` | 理论 X 中要寻找的未付资格／完成追问的任务形状。 | 不是一张已有Candidate-Q，也不是泛泛的“理论有问题”。 |
| `Candidate-Q` | 某张冻结 `T/u/F/C/Q/I/O/Done` 卡上的具体追问；没有时明写 `NONE`。 | 只有它进入 `Q-0`至`Q-4`／`Q-R`。 |
| `Control-Q` | 用来验证P能识别或排除某种Candidate-Q形状的fixture、source或反事实。 | 不能冒充Candidate-Q或代替实际消费者。 |

`Candidate-Q`有两条激活路线：`C_LANE`由来源明示的consumer进入，必须满足同层 C/I/O/Done、active demand、
positive obligation和无直接支付，才可到`Q-2`；`F_LANE`由 profile/source 明示的核心 formation进入，只可到
`Q-1 / FORMATION_ORIGIN_PROBE`，必须有具体`u/F`、非存在重述的完成／资格／self-ascent追问、反控制和将来
P2/P3或consumer来源。F-lane 的C/I/O/Done可保持`UNKNOWN`，不得被误写成共同Q；未声明的`∃r`或`∃f`不能
借F-lane发明 checker。

每个 `ForgeIntent`、工具修订和自然单元必须给出一个 `QConvergenceLink`：

```text
Target-Q / Candidate-Q / Control-Q identity and Q state before
expected delta: Q_GENERATE / Q_NARROW / Q_BRIDGE / Q_CONVERGE / Q_REJECT / Q_CAPABILITY_CALIBRATION
the P1/P2/P3 field or control that supplies this delta
same-task evidence and falsifier
Q state after, or why the node must stop
```

`Q_SAFETY_REPAIR` 是唯一不直接改变 Q 状态的例外：它必须指出正在防止哪一张已冻结卡被误报为
Q，并提供回归。若一个所谓修刀既不改变 Q 状态、候选空间、同卡桥接资格，也不保护某张卡免于
误判，也不满足 `Q_CAPABILITY_CALIBRATION` 的全部字段，它是 `TOOL_ONLY_DRIFT`：可以作为一般维护另行处理，却不能记作 P-FORGE 的研究推进或触发
新的理论节点。

当前 Power Set 的状态仍是 `Q-0 UNFORMED`：`P(a)` 是显眼位置，尚未得到有来源的 active-demand
候选。RK-0、rank、bounded formation、H073 bridge 与 H074/H075 的直接支付控制都在收紧可接受
Q 的形状；它们没有把当前卡推进为 `Q-1`、`Q-2` 或 `Q-4`。

## 2. 三刀会合合同

对同一个候选，必须冻结：

```text
T      : ZFC 的精确语言／公理变体
u      : 一等集合对象或形成接口的输出
F      : 形成规则
Q      : 同一对象的、由理论实际提出的追问
C      : 有 source contract 的真实消费者／算符
I/O/Done : 同一任务的输入、操作、观察、完成条件
```

三刀各自的不可替代义务：

| 刀 | 对 ZFC 会合必须贡献什么 |
|---|---|
| P1 | 证明 `u/F/C` 是 ZFC 自身的核心位置，`C` 具有输入／输出／Done 的 source contract，`Q` 是当前活跃 demand 而非公式名，且它既未被 F 立即清偿、也未被同一 source packet 的公理／已给条件／witness直接支付。 |
| P2 | 从实际 ZFC language contract 中给出 `Bind/Form/Bridge/Reenter/Polarity/Guard` 的正匹配，或精确指出哪个 guard 使当前 Q 不可能是 P2 形状。 |
| P3 | 从实际 construction/consumer semantics 中给出 pending/admission/completion transition，或精确指出静态公理为何没有该语义以及缺少什么 source。 |

若 P2/P3 合法输出“不适用”，它们提供的是重要防线；此时**共同 Q 尚未定位**，而不是 P1 单独胜利。

所有三刀卡还必须提供 [010 所定义的 `MatchTrace`](<010 - 代理匹配自我说明合同.md>)：每项 source fact 如何填充刀具字段、候选为何从竞争位置中被选出、Q 如何最小归约、哪个邻近 site 被排除、替换何条件即失效。P1 另受 `L5b/active-demand status`、`L6/Q-friction`、`L7/obligation mode` 与 `L7b/packet-payment screen` 约束：定义名不自动成为 Q；Q 不得只是同一 interface 反身性或定义展开立即回答的判断，也不得只是允许 consumer 合法回答 false 的普通查询，更不得是同一来源包中已由当前公理、已给定理前提或 supplied witness直接支付的义务。

## 3. 当前 Power Set 差距

当前卡：

```text
u = P(a)
F = power-set existence axiom
P1 = object-level, direct-completion site selected
P2 = no unrestricted formula binder / bridge / reentry on neutral ZFC card
P3 = no pending/admission lifecycle in static existence axiom
```

所以最初的自然语言问题仍是候选而非已定位的 Q：

> 什么使 `P(a)` 有资格作为“所有 a 的子集已经完成、可被后续算符使用”的对象？

要把它变成 `ZFC_Q_LOCATED`，下一轮必须找到真实 ZFC consumer 的**source contract**（输入、输出、Done），确定该 consumer 是否对这个“已完成”状态提出了当前活跃、不是定义名、未被 formation 或同一 packet 的现成公理／已给条件直接支付、且不能以 false 分支正常完成的**正义务**，并让 P2/P3 对同一义务给出实际 language/process 映射。不能以不可枚举、元语言全体、外加算法要求、裸关系符号，或一个可普通判假的 membership 查询代替这一步。

H023/H024读取Isabelle `Relative.thy`的`M_trivial` powerset材料：它明确说powerset不是absolute，并只证明internal `y`到external `Pow(x)`的一向包含。H023在模型采样前因marker失败，H024唯一修marker后完整运行并给出`NO_CONSUMER_DONE_Q_MATCH`。这里的external `Pow(x)`是relative-model comparison，不是M内部consumer；没有I/O/Done或positive Q。

该控制防止将“模型没有外部所有子集”误报为“ZFC承诺了外部所有子集却做不到”。它不减弱Power Set作为显眼site，也不提供共同Q。完整收据：`audit/20261002-P-DAG-ZFC-SOURCE-023-024-RELATIVE-POW-Terra-Max.md`。

### 3.4 H028：choice-function 公式把“出现 Q”与“当前未支付 Q”分开

H028冻结 Isabelle `AC_Equiv.thy` 中的 `Pow(A)-{0}`、dependent product 和 `AC0` 文字。它的直接来源事实有两层：文件在 Isabelle/ZF 层定义 `AC0 ≡ ∀A. ∃f. f∈Π X∈Pow(A)-{0}.X`，并另有带 `well_ord(A,R)` 前提的 `ex_choice_fun_Pow`；文件还明确标为“obviously not ZFC”。因此实际 source card 只**命名** `Q(A)=∃f. f∈C`，没有在 bare ZF 中断言它，也没有提供 `R` 与 well-order proof。

这张控制卡显示两种相反但同样不能升级的读法：

```text
actual Isabelle/ZF definition card: FORMULA_ONLY_NOT_ACTIVE_DEMAND
counterfactual T = ZF + asserted AC0: positive Q, but SOURCE_PACKET_DIRECT_PAYMENT
conditional ex_choice_fun_Pow without R/well_ord proof: CONDITIONAL_PAYMENT_NOT_ACTIVE
```

这张片段也没有 L2b 所要求的同层 actual consumer contract：`Π X∈u.X`在此只是定义／定理式中的集合表达式。因此它是`SOURCE_CONSUMER_GAP`加支付分类控制。Power Set formation本身不支付 Q；但这并不留下可交给 P2/P3 的共同义务。H028 因而新增 P1 的 L5b 与 L7b，而不是把 AC0 写作 ZFC 的矛盾、runtime construction 或 ZFC Q。完整 NodeCard、prompt、source/trajectory 审计与 Master verdict见`audit/20261002-P-DAG-ZFC-SOURCE-028-AC0-POW-Terra-Max.md`。

### 3.5 H029/H030：已被显式 AC 支付的 proof-system 对照

Isabelle/ZF `AC.thy` 是紧邻 H028 的精确对照：它显式 `axiomatization AC`，并证明 `AC_func_Pow`。若TaskCard严格声明 proof-system layer，则 formal derivation可填该层的C/I/O/Done；它不能跨层填成ZFC对象或数学实际使用consumer。

H029先显示 source payment chain，却暴露公开 MatchTrace 标签漂移；H030在新增`T4d`五行 Gate Ledger 后给出可复核分层：Q是 completed theorem，不是未支付的当前Q；F只形成 `Pow(C)-{0}`；`AC → AC_Pi → AC_func → AC_func0 → AC_func_Pow` 直接支付 Q。因此：

```text
QUALIFYING_PROOF_SYSTEM_CARD
SOURCE_PACKET_DIRECT_PAYMENT
NOT_ZFC_Q_LOCATED
```

这个控制阻止两种错误相反的读法：不能把“有 AC 公理”说成没有支付，也不能把 proof acceptance说成现实或对象层交付。它只关闭P1的未支付Q路径，不能凭此关闭B向；B向仍要P3给出对象尚未完成就被算符使用的来源transition和同一任务对照。H029/H030没有这些字段，故P2/P3不启动。完整范围见`audit/20261002-P-DAG-ZFC-SOURCE-029-030-AC-POW-PROOF-GATELEDGER-Terra-Max.md`。

## 4. 联合盲测合同

## 4. 联合盲测合同

`ZFC-COFORGE-001` 证明“三刀同一 prompt 各自填卡”会污染 P1：P2/P3 的易填性会改变 P1 的 site selection。因此共同锻造不是同时让三把刀抢同一个提示，而是按下列**冻结接力**进行：

1. **P1 blind selection：** 不提供既有 Power Set 结论、路线图、审计答案或历史名称；只给冻结 ZFC source card，P1 独立选择 `u/F/C` 并冻结卡；
2. **P2 blind mapping：** 只给同一 source card 与已冻结 P1 卡；不得重选 `u`，只判断 language contract 是否可在该 `u/F/C` 上形成 Q；
3. **P3 blind mapping：** 只给同一 source card 与已冻结 P1 卡；不得重选 `u`，只判断 construction/consumer semantics 是否形成 Q；
4. **Master convergence：** 比较 `u/F/Q/C/I/O/Done` 是否同一；`NOT_APPLICABLE`、`GUARD_BLOCKED`、`CONSTRUCTION_SEMANTICS_NOT_SUPPLIED` 都是有效结果；
5. 只有明确会合才可写 `ZFC_Q_LOCATED`；未会合时，输出哪把刀的何项 gap 驱动下一轮修订。

每一棒均须要求外部代理交付结构化自我说明。它报告的是可观察、可核对的来源—规则—选择理由，不能被误称为模型隐藏思维的完整转录；其质量将用 source 对照、相邻候选淘汰和反事实重跑检验。

P1 的独立性不是把工具又拆成两条线，而是保护三把刀各自的惯性，确保它们真正会合而非被同一提示预先强制成一致答案。

多 worker 的实际组织、各节点能否读取项目分支／网络、何时派 Battle 与 Master 如何裁决，现由 [模式 P 动态 DAG 调度](<../../模式P动态DAG调度.md>) 拥有。该编排不降低本片的同卡会合标准。
