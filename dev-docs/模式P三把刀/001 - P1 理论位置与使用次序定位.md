# P1 理论位置与使用次序定位

## 它的刀刃

P1 从理论 X 的内部开始，而不是从某个历史悖论的名字开始。它的任务是找出：理论为了获得基础性、普适性或经济性能力，原生交付了什么一等对象／接口 `u`；这个对象如何形成、如何被同一理论的后续规则实际消费；围绕它有什么不应被外置或局部化的 `Q`。

P1 不是自动判错器。它交付的是一个可反驳的 **位置卡**，至少含理论变体、`u`、formation、consumer、`Q`、同一任务卡和 controls。

## 当前方法与惯性

P1 的自然惯性是“从理论骨架向外看”。这使它擅长定位 ZFC 的 Power Set、HoTT 的 universe／identity interface 等明显位置，也使它容易被 `Ord/V` 这类宏大但元语言的说明诱惑。故 P1 永久保留下列入口门：

1. `L0`：`u` 是对象语言的一等对象／原生接口；
2. `L1`：核心规则直接形成、识别、闭包或可用化 `u`；
3. `L2`：同一 `u` 被后续内部规则或真实消费者交接；
4. `L2b`（consumer contract）：关系符号、谓词或可写的表达式本身不自动构成 consumer。source 必须给出一个消费 `u` 的 judgment rule、operation 或任务，并说明至少其输入、成功输出／Done 或下一步交接；否则为 `SOURCE_CONSUMER_GAP`。
5. `L2c`（layer integrity）：`C/I/O/Done` 必须属于 TaskCard 已声明的同一层：proof system、理论对象、语义实际使用或 runtime。proof-level theorem 只能填 proof-system card；它不能因结论提到 `u` 自动成为对象层、实际使用层或 runtime consumer。跨层提升必须有目标层自己的命名 `C/I/O/Done`，否则为 `PROOF_LAYER_ONLY` 或相应 layer gap。
6. `L3`：`Q` 只能从理论已经承诺的规则启动，不加 resizing、编码、商、模型或新公理；
7. `L4`：候选是理论范围的基础接口，不是研究者挑出的局部应用；
8. `L5`：`Q` 必须是原生 formation／judgment／consumer 实际提出的需要，不能只是研究者希望理论额外满足的性质。
9. `L5b`（active-demand status）：source 中出现一个 `Q` 的公式、定义名或缩写，不等于理论或 consumer 已经在当前卡中提出 `Q`。TaskCard 必须逐项标明：`Q` 是定义、被断言／假定的公理、当前证明目标、带前提的定理结论，还是已给 witness 的使用条件；只有当前理论变体或当前 consumer 真正要求它，才可进入 L6/L7。单有定义时状态为 `FORMULA_ONLY_NOT_ACTIVE_DEMAND`。
10. `L6`（Q-friction）：`Q` 不能被同一 formation/interface 立即以反身性、定义展开或已给 witness 平凡清偿。若 `Q` 立刻归约为已知 yes/no，而没有下一项真实 obligation、guard、payment 或未落定的 completion demand，则它只能说明 site，不是张力 Q。
11. `L7`（obligation mode）：`Q` 必须是 consumer 要成功完成当前任务所需的正前提，或 formation 尚未支付的形成义务；它不能只是一个允许回答“假”的普通 membership／equality／predicate 查询。若 consumer 可以合法地返回 false、拒绝该输入或走另一分支，而没有未支付的 formation／admission／completion 债务，则状态为 `ANSWERABLE_FALSE_BRANCH`，不是张力 Q。
12. `L7b`（packet-payment screen）：在 L7 之后，逐项扫描**冻结 source packet 中当前理论层可用**的 formation、定义、公理／假定、定理及其已给前提、和 supplied witness。定义只命名命题，不支付它；带未给前提的定理只记 `CONDITIONAL_PAYMENT_NOT_ACTIVE`；若同一 TaskCard 的公理、已成立定理或已给 witness 以最短路线直接推出 `Q`，状态为 `SOURCE_PACKET_DIRECT_PAYMENT`，不是未支付的张力 Q。只有没有这类当前支付路线的正义务，才可交给 P2/P3。**范围限制：** L7b 只关闭 P1 的“当前来源包尚未支付 Q”路径；它不证明实际／计算层已经完成，也不关闭 B 向。若要把 formal payment 读成“理论把尚未构造者当作已交付”，仍须由 P3 给出 `Draft/NeedBuild/OperatorUse/Admitted/BuildDone` 的来源 transition，并以同一任务的 I/O/Done 对照核验。

## 强制 MatchTrace

每份 P1 位置卡必须交付公开的、可逐项核对的 `MatchTrace`，不是隐藏思维链：

| 步 | 必填内容 |
|---|---|
| T1 | 哪一条 source rule 支持 L0/L1？ |
| T2 | 为什么该 rule 的输出可作为同一 consumer 的输入（L2）；source 在哪里规定此 consumer 的输入、结果与 Done（L2b）；该 contract 属于哪一层，是否跨层偷换（L2c）？ |
| T3 | Q 从哪个实际 formation/judgment/consumer demand 导出？它在本卡是定义、断言／假定、证明目标、带前提定理结论，还是已给 witness 的条件（L5b）？ |
| T4 | Q 经最小定义展开后是什么；是否被立即清偿（L6）？ |
| T4b | Q 是当前任务必须满足的正前提，还是可合法回答 false 的普通查询（L7）？ |
| T4c | 列出 packet-visible formation、definition、公理／假定、定理和 supplied witness 对 Q 的最短路线；逐条标 `NOT_PAYMENT`、`CONDITIONAL_PAYMENT_NOT_ACTIVE` 或 `SOURCE_PACKET_DIRECT_PAYMENT`（L7b）。 |
| T4d | 交付**固定顺序的 Gate Ledger**：`L2c layer`、`L5b active-demand status`、`L6 F-only payment`、`L7 positive-obligation mode`、`L7b packet payment`。每行只回答该门的问题，列 source fact、pass/fail/unknown 和理由；不得把一门的结论贴到另一门标签下。 |
| T5 | 至少一个邻近对象为何被排除，或为什么当前候选优于它？ |
| T6 | 去掉或替换哪一条 source fact，选点会失效？ |

没有 T1–T6/T4b/T4c/T4d 的候选为 `UNEXPLAINED_SITE_SELECTION`，不能进入 P2/P3 映射。T2 缺 source-defined consumer contract 时，状态为 `SOURCE_CONSUMER_GAP`；T2 的 proof-system card 被升格为对象／语义／runtime card 时，状态为 `PROOF_LAYER_ONLY`；T3 只给公式名／定义而未给活跃 demand 时，状态为 `FORMULA_ONLY_NOT_ACTIVE_DEMAND`；T4 显示 Q 平凡时，状态为 `SITE_SELECTED_Q_TRIVIAL`；T4b 显示 Q 只是允许 false 的查询时，状态为 `ANSWERABLE_FALSE_BRANCH`；T4c 显示 packet 已支付时，状态为 `SOURCE_PACKET_DIRECT_PAYMENT`；T4d 的字段互换为 `MATCHTRACE_GATE_LABEL_DRIFT`，该输出只能作为prompt/contract修订证据；这些状态均不得称 `ZFC_Q_LOCATED`。每一个 T1–T6 条目还必须遵守 [代理匹配自我说明合同](<010 - 代理匹配自我说明合同.md>) 的“选中—淘汰—反事实”格式；仅说“这很基础”或“它看起来最像 P”不构成理由。

## 发现与验证不能互相吞掉

P1 有两个连续但不同的阶段。用户关于“一遍匹配”的原意属于**发现**：在不泄漏项目答案、也不遍历理论细节的条件下，AI 可以用已学习的理论知识提出一张可证伪的位置线索。L0–L7b 属于**验证**：来源、consumer、Done、层级、活跃义务与来源包支付状态已经可核时，才判断这张线索是否能成为共同 Q。

| 阶段 | 可以输出 | 必须明确缺少什么 | 禁止升级为 |
|---|---|---|---|
| `P-DISCOVERY` | `MODEL_RECALL_SITE_CANDIDATE`：候选 concrete subject/`u`、process／formation `F`、process-wide completion `Q?`、一个邻近竞争位置、预期需要哪一种 C/I/O/Done source；仅在 D-L5 至 D-L10 都通过时可用 | C/I/O/Done、source locator、P2/P3 mapping 可为 `UNKNOWN`；`Q?` 仍须预指向一个 prospective native task，且不能是 F 已直接交付的答案，也不能凭一个存在断言自行发明未声明的检查器 | `SITE_SELECTED`、`ZFC_Q_LOCATED`、数学或 UR 结论。 |
| `P-VALIDATION` | 当前 T1–T6/T4b/T4c/T4d MatchTrace、L0–L7b verdict | 无法从固定 source 补齐的字段继续保持缺口 | 以模型回忆或 theorem name 填 C/Done；把定义名当作已断言义务；把未给前提的定理当作当前支付；将一个gate的判词贴到另一个gate标签。 |

发现阶段不是逃避来源，而是防止把用户要求的“先一遍发现线索”错误地塞进 source-validation gate。发现输出一旦产生，Master 必须派 source tracer 或 source card 复核；只有验证阶段通过相应门，才可交给 P2/P3、Battle 或共同 Q 审查。HOTT-REPLAY-002 的 `SOURCE_INSUFFICIENT` 正是这一区分的修订依据：它正确拒绝虚构 consumer，却没有测试 P 的盲态发现能力。

发现态在此分为两条不互相冒充的输入路径。`C-lane`从 prospective native consumer／judgment 出发，后继必须补齐其 C/I/O/Done。`F-lane`从 profile 中已经显式声明的核心 formation `F` 出发，后继首先核 F 的完成性追问是否真的含有 P2/P3 形状；它不得把缺 consumer 当作已经通过 L2b，也不得以“F已经交出u”宣布 Q。两条路径都只产生可证伪线索；完整 `ZFC_Q_LOCATED`仍须在同一版本、同一`u/F/C/Q/I/O/Done`上会合。

`D-L5 / native-task anchor` 是 discovery 阶段的最小 Q 纪律：`Q?` 必须能说成理论自己的形成、判断、消去、transport、等价使用或其它 prospective task，而不是只问编码、universe annotation、元语言良构性、实现选择或记录历史是否一致。发现者可以不知道 C/I/O/Done 的精确 source，但要指明哪一类 native source consumer 将来可能把这项任务验证为真问题。否则 verdict 为 `DISCOVERY_META_LAYER_CAPTURE`，只作负控制。HOTT-DISCOVERY-004 以 universe-index preservation 为例，驱动此修订。

`D-L6 / direct-payment screen` 是紧接 D-L5 的发现态预筛：如果同一张冻结卡已经把 `F` 写成一个直接回答 `Q?` 的 constructor、eliminator、equivalence/inverse、computation rule 或给定 witness，则发现者必须给出最短 `F → answer(Q?)` 路线并把该 site 记为 `DISCOVERY_DIRECT_RULE_ANSWER`，而不是把它当作最终 `MODEL_RECALL_SITE_CANDIDATE`。它只依据 packet-visible `F` 的直接形状，不能替代验证态 L5b/L6/L7/L7b：定义是否只是命名、额外公理是否真的被断言、定理前提是否已给、真实 consumer 和 Done 仍须由独立 source card 核对。HOTT-DISCOVERY-005 的 `isEquiv(idtoeqv)`／`e:A≃B ⟼ p:A=B` 是此门的回归控制。

`D-L6b / bounded alternate-site continuation` 防止发现门变成过早停机：一个被 D-L5 至 D-L10 任一门拒绝的显眼 site 只退出候选集，不能自动结束一遍发现。发现者在同一响应中至多检查两个额外的显眼基础接口；若其中有一个越过 D-L5 至 D-L10，交付它作为唯一 candidate；若三个总 site 都被筛掉，交付 `NO_MODEL_RECALL_CANDIDATE / DIRECT_PAYMENT_ONLY`。这不是理论遍历，也不允许为凑满次数硬造局部候选。HOTT-DISCOVERY-006 是 D-L6b 的回归控制；HOTT-DISCOVERY-010 是 D-L7 的第一回归控制。

`D-L7 / subject-and-task anchor` 防止 discovery 把实现过程的容器误当成被审视的基础对象。最终 candidate 必须分别写出：**subject**（理论内何一显眼对象／接口被询问）、**process**（对它执行什么 formation、judgment、elimination、搜索或 consumer task）以及对象、输入、观察和 provisional Done。`Delay`、fuel、scheduler、evaluator、编码器等过程骨架可以作为 F 或观察工具，但除非理论本身的显眼基础承诺正是该骨架，它们不能单独占据 P1 的 `u`。只命名“这个延迟搜索会不会返回”而没有 subject 的 candidate 为 `DISCOVERY_PROCESS_SKELETON_ONLY`；它可保留为过程线索，却不能进入 source tracer、P2/P3 或共同 Q。D-L7 不要求 discovery 已有 source-defined C/I/O/Done，也不把它改成现实／UR verdict；它要求 AI 至少没有把“问的机器”误写成“被理论交付、值得问的东西”。HOTT-DISCOVERY-010 是这一 guard 的回归控制。

`D-L8 / concrete-core-instantiation anchor` 防止 D-L7 把一个任意变量、属性名或 schema slot误写成最终靶点。若冻结理论画像已经列出有限个显眼的原生核心对象／接口，final candidate 必须从中选出一个**具体实例**，并说明为何它比“任意 C”“某性质本身”更像理论自己的基础承诺。`C` 这类尚未实例化的 catalogue 可以是 task input，不能单独占据 final `u`；“C 的某个性质”也不等于 C 已被定位。若输入没有足够的 concrete core menu，discovery 可以停在 `NO_MODEL_RECALL_CANDIDATE`，不能编造实例。只交出 schematic `C`／property 的状态为 `DISCOVERY_SCHEMATIC_SUBJECT_ONLY`，保留为精确反控制。D-L8 不预定这个具体实例的 source result，更不把它写成现实判词；它只检查 P 是否真正把一遍匹配压到了可审的理论位置。HOTT-DISCOVERY-013 是此 guard 的回归控制。

`D-L9 / completion-fidelity anchor` 防止已经找到 concrete subject 的 discovery 又把 `Q?` 缩成一轮局部判断。若 process 按阶段反复调用某个本地可判定 interface `J(k)`，`Q?` 必须问这个**同一 process 的完成**：它是否／何时交出所声明的 Done，或什么形成／判断义务会令它无法完成；不能只问某个固定 `J(k)` 是 yes 还是 no。局部 branch 的确可以由 interface 正常回答，它只说明一步，不是 UR 或罗素式 completion pressure。只交出单层 `J(k)`／固定 witness 查询者为 `DISCOVERY_LOCAL_BRANCH_ONLY`，不进入 source tracer、P2/P3 或共同 Q。D-L9 不预设 process 会停或不停，也不把 process-wide question本身认定为现实任务；它只保持“理论 X 回答起来不合理的问题 Q”中的完整完成标准。HOTT-DISCOVERY-014 是此 guard 的回归控制。

`D-L10 / declared-operation anchor` 防止 discovery 把“理论断言存在某物”自行改造成“验证任意已给对象是否满足某关系”的新任务。候选的 process／judgment／consumer必须在冻结 profile 里由规则、接口或操作名称显式给出，或明确预指向某一类已声明原生 operation；仅有 `∃r`、`∃f` 或一个形成结果时，不能凭数学上可表达性发明 `judge(r)`、记录系统或检查器。只给未声明检查任务的状态为 `DISCOVERY_UNDECLARED_OPERATION`，可保留为对 source tracer 的反控制，但不作为 `MODEL_RECALL_SITE_CANDIDATE`。D-L10 不要求 discovery 已具 source contract；它要求 discovery 没有把理论的存在承诺悄悄换成一个画像从未承诺的消费者任务。H035/H036 的封闭菜单选择与 H037 parent-source mismatch 是这一 guard 的回归来源。

`D-L10F / formation-origin anchor` 细化 D-L10，而不削弱它：冻结 profile 已**明确声明**的核心 formation rule／axiom／interface 本身是一条原生 operation 路径，不能被“尚未命名 consumer”自动排除。它允许 AI 从同一 `F` 的完成、可用资格、直接或上升式自指依赖提出 `FORMATION_ORIGIN_PROBE`；但仍禁止把“F断言`u`存在”重述为 Q，或凭 `F` 发明 `judge(r)`、checker、记录服务或外部任务。F-lane 的 Q? 必须同时写出具体`u/F`、不同于`u`存在的未直接支付追问、最小 completion/self-ascent trace、一个邻近反控制、以及将来需要的 P2/P3 或同层 consumer source。C/I/O/Done 可以保持 `UNKNOWN`，故 F-lane 只交付 discovery probe，不能写为已验证位置卡、共同 Q、UR 或数学结论。H040–H042 的 consumer-only profile遗漏此路径；其 no-candidate 只保留该较窄范围。

## 进一步迭代的方法

- 用无泄漏盲重放检查 P1 是否选到理论自身的明显位置；
- 用 `META_LAYER_CAPTURE`、`DISCOVERY_DIRECT_RULE_ANSWER`、`DISCOVERY_PROCESS_SKELETON_ONLY`、`DISCOVERY_SCHEMATIC_SUBJECT_ONLY`、`DISCOVERY_LOCAL_BRANCH_ONLY`、`DISCOVERY_UNDECLARED_OPERATION`、`FORMULA_ONLY_NOT_ACTIVE_DEMAND`、`CONDITIONAL_PAYMENT_NOT_ACTIVE`、`SOURCE_PACKET_DIRECT_PAYMENT`、`ARTIFICIAL_EXTENSION`、`MISSED_CORE_SITE`、`Q_NOT_NATIVE_DEMAND` 等失败码修订门，而不事后为输出找理由；
- 固定真实 consumer，核输入、操作、观察和 Done，防止将局部化后的不同任务冒充原任务；
- 若 P1 产生了上升／时间张力，交给 P3 核是否真的有 pending 与资格前置条件；若产生语言反馈，交给 P2 核是否真能编译。

## 正负控制与停止

正控制是：代理在不知项目答案时，从理论的原生对象和规则独立定位到预先声明的中心接口。负控制包括 proper class、外部语义模型、特设 extension、局部 W-type 或只靠术语相似的候选。

在 `P-VALIDATION` 阶段，若没有明确对象、formation、consumer 和同一任务，P1 返回 `NO_POSITION_CARD`；它不能以“理论有无穷对象”代替工作。`P-DISCOVERY` 阶段可以保留一个明确标注 `MODEL_RECALL_SITE_CANDIDATE` 的对象／formation 线索，但不得把它误写成验证通过的位置卡。
