# P1 理论位置与使用次序定位

## 它的刀刃

P1 从理论 X 的内部开始，而不是从某个历史悖论的名字开始。它的任务是找出：理论为了获得基础性、普适性或经济性能力，原生交付了什么一等对象／接口 `u`；这个对象如何形成、如何被同一理论的后续规则实际消费；围绕它有什么不应被外置或局部化的 `Q`。

P1 不是自动判错器。它交付的是一个可反驳的 **位置卡**，至少含理论变体、`u`、formation、consumer、`Q`、同一任务卡和 controls。

## 当前方法与惯性

P1 的自然惯性是“从理论骨架向外看”。这使它擅长定位 ZFC 的 Power Set、HoTT 的 universe／identity interface 等明显位置，也使它容易被 `Ord/V` 这类宏大但元语言的说明诱惑。故 P1 永久保留下列入口门：

1. `L0`：`u` 是对象语言的一等对象／原生接口；
2. `L1`：核心规则直接形成、识别、闭包或可用化 `u`；
3. `L2`：同一 `u` 被后续内部规则或真实消费者交接；
4. `L2b`（consumer contract）：关系符号、谓词或可写的表达式本身不自动构成 consumer。source 必须给出一个消费 `u` 的 judgment rule、operation 或任务，并说明至少其输入、成功输出／Done 或下一步交接；否则为 `SOURCE_CONSUMER_GAP`。
5. `L2c`（layer integrity）：`C/I/O/Done` 必须属于 TaskCard 已声明的同一层：proof system、理论对象、语义实际使用或 runtime。proof-level theorem 只能填 proof-system card；它不能因结论提到 `u` 自动成为对象层、实际使用层或 runtime consumer。跨层提升必须有目标层自己的命名 `C/I/O/Done`，否则为 `PROOF_LAYER_ONLY` 或相应 layer gap。
6. `L3`：`Q` 只能从理论已经承诺的规则启动，不加 resizing、编码、商、模型或新公理；
7. `L4`：候选是理论范围的基础接口，不是研究者挑出的局部应用；
8. `L5`：`Q` 必须是原生 formation／judgment／consumer 实际提出的需要，不能只是研究者希望理论额外满足的性质。
9. `L6`（Q-friction）：`Q` 不能被同一 formation/interface 立即以反身性、定义展开或已给 witness 平凡清偿。若 `Q` 立刻归约为已知 yes/no，而没有下一项真实 obligation、guard、payment 或未落定的 completion demand，则它只能说明 site，不是张力 Q。
10. `L7`（obligation mode）：`Q` 必须是 consumer 要成功完成当前任务所需的正前提，或 formation 尚未支付的形成义务；它不能只是一个允许回答“假”的普通 membership／equality／predicate 查询。若 consumer 可以合法地返回 false、拒绝该输入或走另一分支，而没有未支付的 formation／admission／completion 债务，则状态为 `ANSWERABLE_FALSE_BRANCH`，不是张力 Q。

## 强制 MatchTrace

每份 P1 位置卡必须交付公开的、可逐项核对的 `MatchTrace`，不是隐藏思维链：

| 步 | 必填内容 |
|---|---|
| T1 | 哪一条 source rule 支持 L0/L1？ |
| T2 | 为什么该 rule 的输出可作为同一 consumer 的输入（L2）；source 在哪里规定此 consumer 的输入、结果与 Done（L2b）；该 contract 属于哪一层，是否跨层偷换（L2c）？ |
| T3 | Q 从哪个实际 formation/judgment/consumer demand 导出？ |
| T4 | Q 经最小定义展开后是什么；是否被立即清偿（L6）？ |
| T4b | Q 是当前任务必须满足的正前提，还是可合法回答 false 的普通查询（L7）？ |
| T5 | 至少一个邻近对象为何被排除，或为什么当前候选优于它？ |
| T6 | 去掉或替换哪一条 source fact，选点会失效？ |

没有 T1–T6/T4b 的候选为 `UNEXPLAINED_SITE_SELECTION`，不能进入 P2/P3 映射。T2 缺 source-defined consumer contract 时，状态为 `SOURCE_CONSUMER_GAP`；T2 的 proof-system card 被升格为对象／语义／runtime card 时，状态为 `PROOF_LAYER_ONLY`；T4 显示 Q 平凡时，状态为 `SITE_SELECTED_Q_TRIVIAL`；T4b 显示 Q 只是允许 false 的查询时，状态为 `ANSWERABLE_FALSE_BRANCH`；四者均不得称 `ZFC_Q_LOCATED`。每一个 T1–T6 条目还必须遵守 [代理匹配自我说明合同](<010 - 代理匹配自我说明合同.md>) 的“选中—淘汰—反事实”格式；仅说“这很基础”或“它看起来最像 P”不构成理由。

## 发现与验证不能互相吞掉

P1 有两个连续但不同的阶段。用户关于“一遍匹配”的原意属于**发现**：在不泄漏项目答案、也不遍历理论细节的条件下，AI 可以用已学习的理论知识提出一张可证伪的位置线索。L0–L7 属于**验证**：来源、consumer、Done、层级和正义务已经可核时，才判断这张线索是否能成为共同 Q。

| 阶段 | 可以输出 | 必须明确缺少什么 | 禁止升级为 |
|---|---|---|---|
| `P-DISCOVERY` | `MODEL_RECALL_SITE_CANDIDATE`：候选 `u/F/Q?`、一个邻近竞争位置、预期需要哪一种 C/I/O/Done source | C/I/O/Done、source locator、P2/P3 mapping 可为 `UNKNOWN` | `SITE_SELECTED`、`ZFC_Q_LOCATED`、数学或 UR 结论。 |
| `P-VALIDATION` | 当前 T1–T6/T4b MatchTrace、L0–L7 verdict | 无法从固定 source 补齐的字段继续保持缺口 | 以模型回忆或 theorem name 填 C/Done。 |

发现阶段不是逃避来源，而是防止把用户要求的“先一遍发现线索”错误地塞进 source-validation gate。发现输出一旦产生，Master 必须派 source tracer 或 source card 复核；只有验证阶段通过相应门，才可交给 P2/P3、Battle 或共同 Q 审查。HOTT-REPLAY-002 的 `SOURCE_INSUFFICIENT` 正是这一区分的修订依据：它正确拒绝虚构 consumer，却没有测试 P 的盲态发现能力。

## 进一步迭代的方法

- 用无泄漏盲重放检查 P1 是否选到理论自身的明显位置；
- 用 `META_LAYER_CAPTURE`、`ARTIFICIAL_EXTENSION`、`MISSED_CORE_SITE`、`Q_NOT_NATIVE_DEMAND` 等失败码修订门，而不事后为输出找理由；
- 固定真实 consumer，核输入、操作、观察和 Done，防止将局部化后的不同任务冒充原任务；
- 若 P1 产生了上升／时间张力，交给 P3 核是否真的有 pending 与资格前置条件；若产生语言反馈，交给 P2 核是否真能编译。

## 正负控制与停止

正控制是：代理在不知项目答案时，从理论的原生对象和规则独立定位到预先声明的中心接口。负控制包括 proper class、外部语义模型、特设 extension、局部 W-type 或只靠术语相似的候选。

在 `P-VALIDATION` 阶段，若没有明确对象、formation、consumer 和同一任务，P1 返回 `NO_POSITION_CARD`；它不能以“理论有无穷对象”代替工作。`P-DISCOVERY` 阶段可以保留一个明确标注 `MODEL_RECALL_SITE_CANDIDATE` 的对象／formation 线索，但不得把它误写成验证通过的位置卡。
