# 案例校准矩阵

> **用途：** 案例不是用来给三把刀盖章的装饰品。每个案例都用来检验某把刀的特定能力，并允许另两把刀输出 `NOT_APPLICABLE`、`GUARD_BLOCKED` 或 `CONSTRUCTION_SEMANTICS_NOT_SUPPLIED`。把所有案例硬压成同一种结构，会毁掉工具的辨别力。

## 1. 总矩阵

| 案例 | P1：理论位置 | P2：逻辑语言形状 | P3：构造／完成过程 | 本案例在工具箱中的作用 |
|---|---|---|---|---|
| 朴素集合论的无限制理解 | 强正控制：无界按条件形成是理论骨架位置。 | 强正控制：`Bind→Form→Bridge→Reenter→negative feedback` 可归约为有限局部规格冲突。 | 原始构造读法的候选：检验是否真有 pending／admission 语义，不能由静态公理自动假定。 | P2 的主要正控制；P3 的“必须提供构造语义”边界案例。 |
| 有界集合形成／分层规则 | guard/control：已有集合界、类型或层级切断无界 formation。 | 强负控制：bridge 域或 reentry 被 guard 阻断。 | 可能有明确完成／证书规则；不能从 blocked reentry 推断过程失败。 | P2 防伪阳性、P1 防“任何集合论都同形”。 |
| 芝诺过程 | 位置候选是连续／稠密数轴、极限和“到达”的理论处理，不是某个集合对象。 | 当前 P2/v0 应主要输出 `NOT_APPLICABLE`：这里没有 formation–reentry–polarity 的 language contract。 | 强过程校准：`Remaining(r)→Step→Remaining(r/2)` 与 Done 的关系，检验无限细分怎样影响完成。 | P3 的完成过程／无界下降正控制；P2 的不强行匹配控制。 |
| 圆环悖论 | 位置候选是连续点、去点／展开、端点逼近与复原完成条件的理论处理。 | 当前 P2/v0 默认不强配；若要建立极限／闭包型 P2 语法，必须另起 family，不能挪用 reentry 语法。 | 强过程校准：`Cut→Unroll→Approach→Reconnect?→Done`；检查“无限逼近”是否被当成已复原。 | P3 的边界复原／完成条件校准；与芝诺共同检验连续完成。 |
| HoTT | P1 应先无泄漏定位原生 universe／identity／consumer 区域。 | P2 检验该区域是否真的有 language-level formation/reentry/guard，而非把高维或固定点当反馈。 | P3 检验是否存在实际 pending→operator→admission 依赖，而非把静态类型规则伪读为运行。 | 三刀的主要 holdout 基准：不能倒灌已有答案。 |
| ZFC | P1 的首个对象级基线为 Power Set，也允许更强竞争位置经同规则比较。 | P2 检查形成总体是否真的有合法 reentry／polarity 结构，不能把“所有子集很多”当逻辑反馈。 | P3 检查有无可审计的构造语义和资格前置条件，不能把存在公理默认翻译成程序。 | 跨理论 holdout：只在 HoTT 校准稳定后承担外推评价。 |

## 2. 芝诺是不是三把刀？

芝诺是三把刀都应该**看一眼**的案例，但不是三把刀都应给出同一种正匹配的案例。

- **P1：是。** 它帮助 P1 学会从“理论怎样规定连续位置、无限可分和到达”找基础前提，而不去寻找某个偶然对象。
- **P2：目前不是。** P2/v0 的刀刃是 formation—reentry—polarity；芝诺的核心是递减剩余距离和完成条件，没有条件形成对象后再自代的 bridge。强行给芝诺找 `q↔H(q)` 会把 P2 训练坏。未来可以单独建立 P2 的“递推／极限／闭包”子 family，但不能将它冒充为当前 P2/v0 已命中。
- **P3：是强正控制。** P3 需要把运动过程写成状态：当前位置、剩余距离、允许的步、下一状态和 Done。连续减半产生每个有限步骤之后仍有剩余的过程；离散最小步长／有限格点是反控制。这里的 P3 不是 admission cycle，而是 **completion-process module**。

因此芝诺教三把刀的不是“都要自指”，而是：P1 要找到前提，P2 要诚实说不适用，P3 要把完成过程真正写出来。

## 3. 圆环是不是三把刀？

圆环同样是全工具箱案例，却不是 P2/v0 的正控制。

- **P1：是。** 它考察连续点、去点后的展开、端点与复原的理论化位置；关键不是普通拓扑定理，而是理论对“已经接回”的完成条件怎样处理。
- **P2：当前默认不适用。** 若未来 P2 新增“边界／极限／闭包”语言 family，必须用独立 IR 明确 `Cut/Boundary/Approximate/Closure/Done`，不能把端点逼近偷偷翻译成 predicate reentry。
- **P3：是强正控制。** 它可冻结状态机：`Cut → Unroll → Approach → Reconnect? → Done`，问删除的点、端点状态和复原操作各自需要什么。用户所说“圆环复活芝诺幽灵”的正是这里：如果理论以极限或闭包宣布 Done，P3 必须分开记录“逼近发生了”和“同一复原操作完成了”。

圆环的具体现实归因、原对象、操作和 Done 仍须回到项目已有的原始圆环材料；本矩阵只规定它怎样校准三把工具，不能替代原案。

## 4. 最小案例路线

1. **先磨 P2：** 无限制理解／有界形成／正极性 sanity control；它们给桥、回代、极性与 guard 的清晰 oracle。
2. **先磨 P3 的两种 module：** admission-order（朴素集合论的构造读法）与 completion-process（芝诺、圆环）。两种 module 不得混写；前者追资格环，后者追完成状态。
3. **用芝诺／圆环测 P1：** 看 P1 能否落在连续／完成前提，而不是把历史名称当候选。
4. **再用 HoTT 作无泄漏 holdout：** 检验三把刀是否各自报告其真实适用域与会合处。
5. **最后用 ZFC 作外推 holdout：** 比较 Power Set 和任何更强对象级竞争位置；不允许从朴素集合论正控制直接跳成 ZFC 结论。
