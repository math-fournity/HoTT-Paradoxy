# 文献地图与学术检索质量

## 1. 为什么需要这一阶段

HOTT-MOTIVE-ZFC 的既有 run 强在来源忠实性：原件、哈希、页码、R/Z/Q/E 卡、消费者、标准回答和重开条件均可复核。它们却不是领域地图。一个冻结分母的 included = n/n，只说明这个小分母的每一项已处置，不能说明作者动机、集合论基础、逻辑史、构造主义、证明助手和数学实践的整个相关文献已被系统搜索。

本阶段借用 PRISMA-S 的透明检索原则和系统综述的信息检索纪律，但不把数学哲学／逻辑史研究伪装成医疗干预的 PRISMA review。需要继承的是：可重算的来源范围、数据库与检索式、时间、命中、筛选、去重、引文追踪、覆盖与局限；不需要把临床研究的 PICO、试验注册或效应汇总套入本项目。

本项目只能在满足本片的条件后使用“领域文献地图完成于所声明范围”之类措辞。没有满足时，正确身份是 `SOURCE_RUN_ONLY` 或 `LITERATURE_MAP_REQUIRED`。

## 2. LITERATURE-MAP-001 的研究问题与地图轴

地图不是泛搜“ZFC paradox”。它必须围绕可证伪的问题族建立 corpus：

| 地图轴 | 必须回答的问题 | 最低来源族 |
|---|---|---|
| M-A HoTT／UF 动机 | 作者或早期权威文本如何说明为何需要 HoTT／UF，且他们实际对比的基础是什么？ | 作者论文、讲演、书、项目文档、早期同行说明。 |
| M-B 集合论基础与形成 | 哪些 ZF/ZFC／NBG／ETCS／类理论文献讨论 formation、Power Set、Separation、Replacement、完成总体、predicativity 或其限制？ | 基础文献、逻辑史、教材／综述、正式定义和批评。 |
| M-C 计算与交付 | 哪些文献把 set existence、证明、程序、realizer、proof assistant 或有效交付相连或区分？ | 构造主义、realizability、类型论、证明论、形式化项目。 |
| M-D 实际消费者 | 哪些数学／形式化实践真正把相关对象交给指定任务，并公开支付或省略 choice、label、map、formation、computation 或 Done？ | 数学论文、库源码、证明助手文档、案例研究。 |
| M-E 反驳与替代 | 哪些来源直接支持标准防线、理论层区分、模型解释、经典完成总体立场或对本项目类比的反例？ | 批评文献、模型理论、哲学／历史综述、控制来源。 |

每个 M-Record 至少标：地图轴、理论变体、历史时期、语言、作者／机构、发表类型、原件可得性和与 R/Z/Q/E 的关系。不要因为题名含有 Russell、ZFC、type theory、infinity 或 computation 就把它纳入。

## 3. M0：冻结协议与检索来源宇宙

第一次执行地图前建立 `audit/HOTT-MOTIVE-ZFC/LITERATURE-MAP-001/PROTOCOL.md`，固定：

1. 本轮的问题、地图轴、理论变体、时期、语言和发表类型边界；
2. 计划检索的书目来源及其可访问性，例如 zbMATH Open、MathSciNet（若获访问）、arXiv、Crossref、OpenAlex、PhilPapers、作者／机构主页、出版社／会议卷和正式 proof-assistant archives；
3. 哪些来源只作补充，例如普通网页搜索或 Google Scholar；它们不能作为唯一可重复的数据库分母；
4. 纳入、排除和暂缓标准；每项必须说明排除的原因而不是只保留“有用”材料；
5. 引文追踪计划：从哪些种子做 backward reference chasing、哪些平台／索引做 forward citation chasing、截止日期与最大迭代；
6. 人工／独立检索审阅资源是否存在。若没有独立审阅者，必须保留 `SEARCH_PEER_REVIEW_NOT_AVAILABLE`，不能把同一 AI 的复查写成独立同行评审。

协议可修订，但每次修订必须说明它影响哪个地图轴、旧 query 的可比性和已筛选记录是否需要重审。

## 4. M1：可重算检索与书目记录

每次数据库、目录、作者站点或引文索引的检索都在 `SEARCH-LOG.md` 记录一行，至少含：

| 字段 | 要求 |
|---|---|
| M-Search ID | 稳定编号。 |
| 日期、平台与接口 | 包含数据库／网站、入口 URL 或 API、可见版本和访问限制。 |
| 完整检索式 | 原样保存 Boolean、字段、过滤器、语言／时期限制和排序；网页检索保存完整 query。 |
| 命中数与导出范围 | 记录计数、分页／截断、导出格式和是否能获取全部记录。 |
| 地图轴和预期作用 | 说明它服务 M-A 至 M-E 哪一轴，不用结果反推问题。 |
| 后续处置 | 待去重、待筛选、无命中、不可得、纳入或排除。 |

书目记录以 `M-###` 编号保存到 `CANDIDATE-RECORDS.md`。原件、DOI、arXiv、ISBN、URL、版本、哈希与 locator 分栏保存。相同作品的预印本、正式版、译本、讲演和二次报道必须合并为同一 work family，同时保留多个 report identity。

## 5. M2：筛选、去重与引文网络

`SCREENING.md` 对每一条 M-Record 给出下列可审计 disposition：

```text
INCLUDED_FOR_FULL_READING
EXCLUDED_OUT_OF_SCOPE
EXCLUDED_DUPLICATE_WORK_FAMILY
EXCLUDED_NO_RELEVANT_THEORY_OR_TASK
EXCLUDED_SECONDARY_WHEN_PRIMARY_AVAILABLE
UNAVAILABLE_WITH_REASON
DEFERRED_WITH_REASON
```

排除并不意味着文献错误；它只说明不回答本轮地图问题。对每一条 included source 运行：

1. backward tracking：阅读其参考文献中与地图轴直接相连的工作；
2. forward tracking：在已声明的引文索引中查被引作品；
3. author／institution tracking：检查关键作者、项目和正式 archive 的相邻原典；
4. bridge tracking：将 HoTT motive、ZFC rule、actual consumer 和 P history 的缺边单独列入下一 query family。

每一轮追踪都必须记录扩张产生的候选数、去重数、纳入数和停止理由。引用次数或搜索排序不等于相关性；AI 的语义判断也不等于来源内容。

## 6. M3：覆盖地图、饱和与论文级表述

`COVERAGE-MAP.md` 是领域地图的核心，不是来源清单。它应以 M-A 至 M-E 为行、理论变体／时期／发表类型／语言／来源平台为列，记录：

- 已检索且有完整 search log 的单元；
- 已发现但未读的强引用；
- 已纳入全文阅读的 work family；
- 已排除／不可得／语言能力不足的余项；
- 哪些反控制已经有来源，哪些只是当前项目的推断；
- 每个地图空白的下一检索动作和可推翻条件。

“饱和”只能意为：对预先声明的 query family、数据库、作者群和引文迭代，新增一轮没有产生满足纳入标准的新 work family；它不是“相关文献绝对不存在”。如果只有偶然网页结果、只读少量种子或没有完整 query log，就必须标 `SATURATION_NOT_ASSESSED`。

可使用下列身份：

| 身份 | 最低条件 |
|---|---|
| `MAP_PROTOCOL_DEFINED` | M0 protocol 已冻结，尚未执行检索。 |
| `MAP_EXECUTION_ACTIVE` | 至少一个数据库／作者／引文通道已经按完整日志运行。 |
| `MAP_COMPLETE_WITH_SCOPE` | M0–M3 对冻结的轴、数据库、时期、语言和追踪范围完成；余项可重算。 |
| `MAP_LIMITED_BY_ACCESS_OR_LANGUAGE` | 已写明付费、接口、语言、全文或审阅能力的限制。 |
| `SEARCH_PEER_REVIEW_NOT_AVAILABLE` | 没有独立检索策略审阅，不得暗示已有同行检索复核。 |

“博士论文级”在本项目中指上述过程可以由不持有本次对话记忆的研究者复跑、质疑和扩展，并能看见何处尚有盲区；它不是以论文数量、PDF 数量或 AI 自信衡量。

## 7. M4：与 R/Z/Q/E 及模式 P 的关系

地图阶段的工作与候选资格化必须分开：

```text
M-Record：文献为什么被发现、属于地图哪个轴、是否需要阅读
R/Z/E Card：来源在具体理论／任务中说了什么
Q Card：同一对象、formation、consumer、P、控制和 Done 是否会合
```

地图新发现的来源可以反驳既有 P 历史叙述、扩展原典 corpus 或引入真实消费者；它不能仅凭关键词创建 Q。反过来，任何现有 Q-R、SOURCE_PAYMENT 或 ANTI_ANALOGY_CONTROL 都应进入 coverage map，防止新检索用相同花纹重复打开已支付的任务。

## 8. 启动、停止与恢复

当 `LITERATURE-MAPPING-AUDIT.md` 仍标 `LITERATURE_MAP_REQUIRED` 时，后续对 HOTT-MOTIVE-ZFC-SOP 的推进优先从 M0/M1 开始。M 阶段不启动 P-DAG、worker、数学 STATE、Power Set station 切换或数学证明。

一次 `LITERATURE-MAP-001` run 的最小交付是 protocol、search log、candidate records、screening、citation network、coverage map 和 findings。只有这些都存在并可复算，才能报告本地图范围的完成；随后再回到 002 片的 candidate-admission 前沿，选择真正改变 P1/P2/P5/P6、同一任务或 H0→Z0 的来源开展 successor run。
