# 档案、完成、恢复与停止

## 1. 每次调查 run 的档案结构

实际 `/goal` run 在 `audit/HOTT-MOTIVE-ZFC/<run-id>/` 建立下列实物；仅创建本轮实际需要的文件：

```text
MANIFEST.md              source denominator, scope, version, include/exclude, hashes
SOURCE-CATALOG.md        source identity, URL/path, access date, hash, locator, archive status
R-CARDS.md               source-reported HoTT motives
Z-CARDS.md               ZFC-side reconstructions and source layers
Q-CARDS.md               P / same-task / control / state dispositions
CONSUMER-CONTROLS.md     actual consumers, C+, C−, standard answers
COVERAGE.md              denominator counts, remainder, unavailable/deferred reasons
FINDINGS.md              bounded synthesis, claims/evidence/conflicts/unknowns, next trigger
```

原件归档规则：

1. 已有本地 PDF／源码先记录绝对路径、原始文件哈希和许可／访问事实；不重写来源。
2. 新的公开原件按用户当次授权与现有论文获取流程保存；记录 URL、获取时间、版本、哈希、文件名和失败原因。
3. MinerU/OCR、摘录、索引和笔记是派生阅读材料，必须指回原件；不得替代原文。
4. 历史 AI 文本只以 `HISTORICAL_AI_DRAFT` 身份归档，不能填 R/Z/Q 的一手来源字段。

## 2. 标准调查记录格式

每项来源、卡片和结论都使用可追溯 IDs：

```text
HMZ-S-###   source item
HMZ-R-###   motivation card
HMZ-Z-###   ZFC-side card
HMZ-Q-###   candidate / control card
HMZ-C-###   consumer or standard-control card
```

`FINDINGS.md` 中每条公开判断至少含：身份与范围、支持 source locator、AI 增加的解释、竞争读法、当前处置、反证／重开条件。`SOURCE_REPORTED`、`AI_INTERPRETATION`、`QUESTION`、`CANDIDATE_SEED`、`SOURCE_PAYMENT` 与 `MACHINE_PROVED` 必须分开；后者仍受项目数学证明门禁。

## 3. 覆盖、彻底性与停止

“彻底调查”只对冻结分母成立。一个 run 可以写 `DENOMINATOR_COMPLETE_WITH_SCOPE`，当且仅当：

1. `MANIFEST` 中每个 A–E 来源项都有终态；
2. 每张 R-Card 都有 Z disposition，不能只摘动机；
3. 每张进入 Q 的卡都有同一任务、标准防线和控制处置；
4. 引用追踪中所有被标为 `MUST_FOLLOW` 的来源都已读、不可得或明确排除；
5. `COVERAGE.md` 的 included/deferred/unavailable/out-of-scope remainder 可重算；
6. 当前 `FINDINGS.md` 列出未解决问题、下一入口及其触发条件。

它不允许写“所有 HoTT 文献已读”“所有 ZFC 问题已查完”或“未命中证明 ZFC 无问题”。新原典版本、未处理的强引用、用户扩大范围、真实消费者反例或控制失效可重新开启一个 successor run。

## 4. `/goal` 启动、恢复与阶段切换

用户可使用：

```text
按照SOP=`HOTT-MOTIVE-ZFC-SOP`,继续推进，直至无法推进。
```

启动时，执行者必须：

1. 读取本 SOP 全文、路线009、当前 rulings/Feature/MEMORY和项目规定的完整认知；
2. 找到最近 `audit/HOTT-MOTIVE-ZFC/*/MANIFEST.md`，判断是继续同一分母、开始 successor，还是先修复旧档案；
3. 在不启动 worker 的前提下，从未处理的分母项开始；只有一个来源充分的 Q-Card 满足当前独立授权时，才路由 P-DAG；
4. 每个自然单元更新 archive、coverage和当前恢复信息，并精确 Git commit 本 SOP 范围内的实物；
5. 到达本轮停止条件后保存 findings，而不是用“继续搜”绕过未支付的标准防线。

恢复不等于自动重开已关闭卡。`Q-R REJECTED_WITH_SCOPE`、`ANTI_ANALOGY_CONTROL`和`SOURCE_PAYMENT` 只有在新一手来源、同一任务消费者、理论版本变化或用户明确要求下才能重审。

## 5. 本 SOP 的完成边界

SOP 创建完成只表示未来可被正确调用；一次调查 run 完成只表示其冻结分母与档案闭合；项目完成须由研究发起人基于全部 archived runs 决定。三者都不等于 ZFC 候选已成立或 HoTT／ZFC 的数学关系已经被证明。
