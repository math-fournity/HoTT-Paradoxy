# 项目身份、来源分母与卡片

## 1. 项目身份与不变量

```text
Project ID: HOTT-MOTIVE-ZFC-INVESTIGATION
Scope: HoTT/Univalent Foundations creation motives → source-grounded ZFC candidate seeds
Primary outcome: reproducible source archive plus R/Z/Q/E dispositions
Not an outcome: ZFC inconsistency, universal critique of ZFC, automatic Q discovery
```

每项材料有且只有一种当前身份：`SOURCE_DENOMINATOR_ITEM`、`R_SOURCE_REPORTED`、`E_SOURCE_REPORTED`、
`MOTIVATION_ONLY`、`Z_SIDE_UNDER_SPECIFIED`、`ANTI_ANALOGY_CONTROL`、
`P_REQUALIFICATION_REQUIRED`、`CANDIDATE_SEED`、`Q-R REJECTED_WITH_SCOPE`，或在完整卡片支持时的
`Q-1/Q-2/Q-3/Q-4`。来源修辞、AI 的历史解释、机器证明、实际消费者和用户 UR 判定不可混为一栏。

## 2. 来源分母的五类

每次 run 先在 `audit/HOTT-MOTIVE-ZFC/<run-id>/MANIFEST.md` 冻结本轮分母。分母不以“搜到多少论文”计数，而以
已列来源是否有版本、身份、处理和剩余引用为准。

| 类 | 必须调查的问题 | 最低档案字段 |
|---|---|---|
| A. HoTT／UF primary motives | 作者到底说了什么动机、限制、对比或能力目标？ | 作者、版本、年份、原件路径/URL、哈希、页/行 locator、短引文、R-ID。 |
| B. HoTT technical realization | 单价性、HIT、宇宙、结构同一性、机器实现怎样具体兑现该动机？ | 精确理论变体、规则／公理、适用范围、依赖。 |
| C. ZFC／集合论 source | `Z_i` 是 ZFC、ZF、NBG、ETCS、具体模型、proof formalization还是数学实践？ | 理论变体、source layer、对象/formation/consumer、守卫。 |
| D. 实际消费者与标准回答 | 哪个使用者把动机所关心的对象交给任务？理论是否已经显式支付成本？ | 输入、operation、observation、Done、正反控制、支付/未支付。 |
| E. 批评、比较与反例 | 是否已有工作直接讨论该动机或反投影？ | claim identity、支持/反驳范围、不可外推项。 |

来源优先级：作者原文／正式版本 > 权威教材或正式项目文档 > 可复核的形式化源码与运行 > 同行综述 > 访谈／讲演 > AI 历史材料。派生 OCR/MinerU 文本只作 locator；关键语句回原件。

## 3. 三张必需卡与一张条件式现实任务桥卡

### 3.1 `R-Card`：动机卡

```text
R-ID / source identity / exact locator / source hash:
literal motivation or contrast:
claim class: CONTRASTIVE_CRITIQUE | REPRESENTATION_COST |
             CAPABILITY_GOAL | NOVEL_OBJECT_LANGUAGE | HISTORICAL_CONTEXT
what the source explicitly does not claim:
linked Z-ID(s) / unresolved references:
```

`R-Card` 只报告来源，不能写“故 ZFC 有问题”。例如“directly impossible to capture”必须保留 `directly`，不得改成
“impossible to encode”。

### 3.2 `Z-Card`：ZFC侧还原卡

```text
Z-ID / exact theory variant / source layer:
u / formation F / consumer C / I/O/Done:
what the HoTT motive maps to here:
layer: RULE_AXIOM | PROOF_FORMALIZATION | MODEL_SEMANTIC |
       MATHEMATICAL_PRACTICE | CONSTRUCTION_BRIDGE
standard defense / payment / guard:
nearest control and task-switch risk:
```

`Z-Card` 必须先通过 P1 的 `L0–L2`。`V`、外部模型、泛称“集合论”、一条 theorem name、或软件运行时的
现象都不能代替理论内对象和同一层 consumer。

### 3.3 `Q-Card`：候选卡

```text
Target-Q / Candidate-Q / Control-Q:
same T/u/F/C/Q/I/O/Done:
P1 position and active-demand/payment ledger:
P2 Bind/Form/Bridge/Reenter/Polarity/Guard:
P3 construction/admission/Done or ConstructionBridgeCard:
X_i / Op / O / Done same-task comparison:
C+ / C− / standard answer:
Q state before/after / falsifier / stop or reopen:
```

没有 active positive obligation、formation-origin 的未付追问或固定卡防护时，不得创建 Q-Card；最多保留为
`MOTIVATION_ONLY` 或 `Z_SIDE_UNDER_SPECIFIED`。

### 3.4 `RealityTaskBridgeCard`：只在 E-source 明确连起有限／现实过程与形式 totality 时创建

```text
E-ID / source identity / exact locator / source hash:
real or cognitive task X_h / input / operation / observation / Done_h:
formal construction X_Z / u / formation F / consumer C / observation / Done_Z:
literal bridge type: IDENTITY_CLAIM | ANALOGY | METAPHOR | CRITIQUE | UNKNOWN
source qualifiers and what it does not claim:
exact theory-side pairing source(s):
same-subject / same-operation / same-observation / same-Done verdicts:
P1/P2/P3 status and source-layer boundary:
C+ finite/process control / C− formal payment or task-switch control:
falsifier / reopen condition:
```

这张卡解决一个易混淆点：一份文献可以真实描述“有限任务何时完成”与“无限对象如何被当作完成总性”，但它若只说
`metaphor`、`analogy` 或一般认知图景，就**不**自动证明 `Done_h = Done_Z`。它不是 HoTT 动机卡，不是 ZFC 公理卡，也不是 Q 卡；
它只是把需要被理论侧来源检验的同一任务义务固定下来。

要以 `RealityTaskBridgeCard` 进入 Q，必须另有版本固定的理论侧 source 将 \(u/F/C/I/O/Done\) 固定在同一层，并逐项保留
subject、operation、observation 和 Done。只把“对每个元素”改写成“全部元素已完成”、只把 sethood 改写成实际运行结束，或
只因 Power Set/totality 一词共现，均判为 `SAME_TASK_NOT_ESTABLISHED`。

## 4. `H0→Z0→Q0` 专用传输卡

`H0` 不是可直接翻译的数学项。传输卡必须逐项填写：

| 门 | 必须回答 |
|---|---|
| T0 | ZFC侧的对象语言一等对象 `u_Z` 是什么？ |
| T1 | 何条 formation / interface 将它交给同一理论的后续使用？ |
| T2 | HoTT的 subject、process、observation、Done怎样不换题地映射？ |
| T3 | ZFC规则／证书／guard是否已经直接支付被问的完成性？ |
| T4 | P2/P3的再入、上升、准入或完成结构在哪个来源层真实出现？ |
| T5 | 有何有限／截断／标签／来源支付对照，能区分真对应和词面相似？ |

任一门失败，结果是 `ANTI_ANALOGY_CONTROL` 或 `TRANSPORT_UNDER_SPECIFIED`。这是一项项目产出，不能被改写成
“Q0 不存在”或“ZFC 通过了 H0”。
