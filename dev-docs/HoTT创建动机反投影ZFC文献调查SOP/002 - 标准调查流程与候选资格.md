# 标准调查流程与候选资格

## 阶段 0：冻结本轮问题与文献分母

1. 写 `run-id`、用户指定范围、当前分支/commit、SOP版本和停止条件。
2. 冻结 A–E 五类来源的本轮 include/exclude 清单；每项标 `UNREAD`、`READ`、`DEFERRED_WITH_REASON`、`UNAVAILABLE` 或 `OUT_OF_SCOPE_WITH_REASON`。
3. 定义本轮最多调查的 `R-ID` 集合及其引用追踪规则；没有分母不得使用“彻底”“全部”或“文献证明”。
4. 检查是否已有本地 PDF、来源快照、审计或历史草稿；复用仅限相同版本、范围与来源身份。

## 阶段 1：从 HoTT 原典提取 `R_i`

每项 R 先以原文最小可支持范围存档，再写一段独立的解释。按以下问题逐项回答：

1. 作者是在批评 conventional/set-theoretic foundations，描述表达代价，追求能力，还是报告历史背景？
2. 对比对象是 ZFC、一般 classical set theory、某种 set-theoretic presentation、proof assistant实践，还是其他理论？
3. 原文的量词和限定是什么：`directly`、`in practice`、`without choice`、某个 universe、某类结构？
4. 有无作者自己的反向限定或互操作说明？它们必须成为控制，不得只摘取有利句。

阶段结束条件：每个选定 R 都有 `R-Card`，但没有任何 ZFC 结论。

### 原件获取与派生阅读纪律

1. 先检查本地 `HoTT/theory-schema/`、`sources/`、已有论文库和项目 archive；已有原件须保留路径、版本和哈希，不重新命名或覆盖。
2. 缺少公开原件时，优先使用权威作者／会议／期刊页面；需要定位或取得数学论文全文时，按 `math-paper-harvest` 的原件优先流程进行，记录 URL、访问日期、版本、许可／访问边界和失败。
3. MinerU/OCR 仅在原件存在后生成或消费，作为 locator 和阅读辅助；动机的关键措辞、限定词和否定句必须回到原始 PDF／源码／网页核对。
4. 付费墙、登录态、未许可的下载、历史 AI 转述或无法验证版本的镜像都不得填入 primary R source；分别标为 `UNAVAILABLE`、`HISTORICAL_AI_DRAFT` 或 `SECONDARY_ONLY`。

## 阶段 2：从 `R_i` 重建 `Z_i`

对每张 R-Card，至少构造两种竞争的 Z 读法：

```text
Z-A: 作者所指的ZFC/集合论限制、表示成本或实践困难
Z-B: 理论明确保住差异、提供选择/层级/证书，或动机只是能力偏好
```

再回 ZFC／集合论原典或真实使用者，固定理论变体。必须拆开：

- ZFC object language、ZF/NBG/ETCS 等变体；
- proof formalization、模型／语义、数学实践和软件实现；
- set equality、isomorphism、equivalence、choice、natural transformation、transport；
- set existence、proof witness、可执行过程和实际交付。

阶段结束条件：每张 Z-Card 都有 source layer、guard、payment和至少一个竞争读法。缺 consumer 或精确理论变体时停为 `Z_SIDE_UNDER_SPECIFIED`。

## 阶段 3：模式 P 与同一任务资格

只对来源充分的 Z-Card 使用 P1/P2/P3：

1. **P1：** `u/F/C/I/O/Done` 是否是理论内的真实对象、形成和使用？active demand 是什么？
2. **P2：** 是否有 source-supported Bind/Form/Bridge/Reenter，且不是一般编码、引用、层级或换代表？
3. **P3：** 是否有理论内 pending/admission/operator/Done，或来源充分的同一任务 ConstructionBridge？
4. **同一任务：** `X_i / Op / O / Done` 是否保留；不能把“有一个选择”加强为“自然选择”，不能把“存在 set”加强为“行动者已获得可执行结果”。

`H0→Z0→Q0` 同时执行 001 的 T0–T5。任一 source payment、guard、task switch或层级错配都必须写入卡片，不作为失败删去。

## 阶段 4：消费者、标准防线与反解释

每个可能 Q 至少需要：

| 内容 | 要求 |
|---|---|
| 正控制 C+ | 一个来源明确保留／支付被讨论条件的近邻任务。 |
| 标准回答 C− | 理论如何区分层级、支付选择、限制域、保留标签、或改变 Done。 |
| 真实消费者 | 输入、操作、观察和 Done 可定位；定理名或抽象定义不够。 |
| 反事实 | 改变哪项来源事实会使 Q 失效或重开。 |

若标准防线保住同一任务，判 `Q-R REJECTED_WITH_SCOPE`、`SOURCE_PAYMENT` 或 `ANTI_ANALOGY_CONTROL`；不能因为原动机强烈而保留候选。

## 阶段 5：候选归档与升级

只有在一张冻结 Q-Card 有同一对象、来源、任务、正反控制和未支付义务时，才可升级为 `CANDIDATE_SEED` 或按 P/Q 共同锻造合同进入 `Q-1/Q-2`。这一步仍不等于 ZFC 矛盾、UR 或数学定理。

若要启动 P-DAG、network source node、worker、机器证明或 Power Set station change，必须另满足各自授权和当前合同；本 SOP 不以“调查项目”名义扩大这些权限。
