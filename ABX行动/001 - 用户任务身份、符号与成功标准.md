# 用户任务身份、符号与成功标准

## 1. 用户已决定的范围

用户明确否认“旧算术第三弹失败”可以否定原圆环第三弹：原 A、B、X 与 `Spec_A`／`Spec_B` 并不是同一任务。ABX 因而重新从原圆环过程出发，同时要求吸收和审计 GLM 在 ZCode 会话 `sess_7cb03240-9567-4a2e-9061-b6f0273cd09b` 中完成的 Flash/G4 工作。完整用户背景在[sources/prompts/Codex-ABX行动-用户指令与GLM背景-20260921.md](../sources/prompts/Codex-ABX行动-用户指令与GLM背景-20260921.md)，不是本片的摘要替代。

ABX 允许并要求完成三件事：

1. 忠实固定原 A、B、X 的对象、允许操作、观察和完成标准；
2. 审计既有 Flash/G4 形式资产能证明什么、不能证明什么，并复用其真实控制；
3. 重新寻找某个真实 HoTT 规则、定理、库接口或消费者是否在原任务中把静态 A 当作过程性 B 的完成。

它不授权把“未找到消费者”写成 HoTT 全局无问题，也不授权把任意来源记录的缺失写成 HoTT 内部矛盾。

## 2. 符号消歧

旧文本中 `H` 有两个不同含义，必须拆开：

| 记号 | ABX 中的含义 | 不等于 |
|---|---|---|
| `H_top(M,N)` | 通常点集拓扑／结构拓扑下的同胚或等价关系 | 后文的真实理论使用事实 |
| `R_origin(P,Q)` | 来源、指定缺口、复原目标和允许过程均被保持的富化表示关系 | “普通同胚的反面”或裸类型不等价 |
| `X` | 指定圆 `C`、指定点 `p`、去点呈现、端点闭合／复原这一被考察过程 | 任意开区间或 `√2` 对象 |
| `A` | 理论的静态／声明性处理：例如同胚、紧化、理想点、已给闭合对象或等价运输 | 自动完成过程 B 的证明 |
| `B` | 在同一 X、输入、允许操作、观察和 Done 下，端点是否实际合并、原闭合/来源是否复原的过程性任务 | 一个不带过程合同的静态对象 |
| `K` | 一个真实 HoTT 规则、定理、库接口或消费者，把 A 用作 B 的可替换处理的可定位事实 | `H_top` 本身 |
| `U` | 从来源丰富表示到裸表示的明确 forgetful map/投影 | univalence 自动删除信息 |

此前四弹策略中为“理论侧实际承诺”使用的 `H`，在 ABX 统一改称 `K`；`H_top` 只指用户原文的传统同胚判据。

## 3. ABX 的成功链

ABX 只有在下列链条被同一实例连接时，才可能产出一个现实相对失配候选：

```text
X 固定
  → H_top(M,N) 的精确范围
  → R_origin 所需的来源/复原/过程合同
  → U 明确丢弃什么，或明确没有丢弃什么
  → K：真实 HoTT 使用位置采用静态 A
  → 同一输入、允许操作、Observation、Done 下的保留或失配
  → 最强正控制、反解释和相称机器证明
```

其中 `R_origin` 可以是富化对象范畴中的等价、指定原对象的恢复关系，或一个预注册过程性 Done；它不能仅由“给类型多加一个 Σ 字段”命名后自动成立。若 ABX 只能证明“富化记录比裸记录多数据”，结果是 `REPRESENTATION_BOUNDARY_ONLY`。

## 4. 成功、反证与停止

| 结果 | ABX 的处理 |
|---|---|
| 富化数据在 HoTT 的等价/运输下被完整保留 | 记录为 `DEFENSE_PRESERVES_TASK`；反驳“univalence 自动丢 R”的强说法 |
| 裸 `N` 可构造某种闭合/紧化 | 记录该较弱 Done 的正控制；不能据此声称已复原指定原 `C,p` 或完成过程 B |
| 对明确定义的 `U`，不存在满足自然性/来源保持的恢复 | 记录为精确的 `NO_NATURAL_SOURCE_RECOVERY` 候选；不外推为所有实现不可恢复 |
| 发现真实 `K` 且它使 B 的 Observation/Done 不保持 | 进入 ABX 的形式化失配阶段 |
| 固定分母没有 `K` | 只作 `NO_K_WITHIN_DECLARED_DENOMINATOR`；扩大检索必须另有依据 |

阶段完成不要求预设哪一种结果。数学结论只有在精确命题、源码、原生 kernel run 和 claim/run 索引全部闭合后才可交付。
