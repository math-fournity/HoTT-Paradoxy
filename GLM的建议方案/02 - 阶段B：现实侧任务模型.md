# 02 - 阶段 B：现实侧任务模型（核心方法论升级，2–6 周）

## 0. 这个阶段解决什么

审计 B2/B5 的根因：现有程序在**数学库**里找"现实侧消费者"（E6），而方向 A/B 的失配
发生在现实世界。本阶段把"现实侧"本身形式化为一个可机器检查的对象，使失配主张在
**理论 × 现实联合模型**内成为定理——消费者由构造给出，E6 检索被替代而非延后。

这是整个方案里唯一的大型新建工程，也是你"机器统观"的正确形态：统观的对象不再是
自己产出的工件（CE-MAP 的自指问题），而是**HoTT 构造 × 现实任务**的真实乘积空间。

## 1. 模型总设计：现实演算 RL（Reality Layer）

一个小型、可嵌入 Agda（`--safe`，不依赖 cubical 特性即可起步）的带资源操作语义：

```text
RL 进程 P ::= 步进机器，每步携带 (时钟 t, 能耗 e, 观察标签 o)
状态转移   : P --τ--> P'（内部步，t+1，e+c）
            P --?a--> P'（输入步：只在 a 于当前因果可用时允许）
            P --!v--> P'（输出/交付步）
观察函数   : obs : Run(P) → Trace（时间戳-事件序列）
完成标准   : Complete(P, spec) := 存在有界 n，Run_n(P) 满足 spec 的验收谓词
```

三个设计约束：

1. **可判定/可枚举的有限前缀语义**：观察与完成标准都在有限运行前缀上定义，使
   "现实侧可完成"是 Π₂⁺ 但可逼近的谓词（复用 R2 的公平枚举/半判定资产 C-199–C-207
   作为机器底座）；
2. **资源维度一等公民**：t/e/因果可用性/精度模数是状态的一部分，不允许事后补——
   这是与 HoTT 抽象的对照点所在；
3. **不声称物理完备**：RL 是"现实任务的可执行规格"，不是物理定律；其合法性来自
   任务族规格的显然性（限时任务真的有期限），不来自物理学。

**术语对齐（自审计 G2）**：`Complete(P, spec)` 的合取式完成标准就是用户"合取命题
前提"（KC-000003/000019）的形式化——现实完成是多条件合取，理论化替换掉其中若干条；
对它的检查即用户命名的 **ASK**（KC-000012/000013：可计算性/计算合法性预分析）。
方向 B 失配 = 绕过 ASK 把理论对象当已交付；方向 A 失配 = 合取前提被替换后现实可完成
任务理论侧不可完成。另按 2026-09-13 用户澄清：T2（在线）承担**时序**面（先后/可用/
落定），T5/T6 承担**时间结构**面（连续/稠密/可分/运动），两面对照不可互吞。

## 2. 五个任务族（T1–T5）：规格草案与已有种子

| 族 | 微语法核心 | 完成标准 | 现实锚 | 已有种子（直接改写为 RL 规格） |
|---|---|---|---|---|

| T2 在线/流式 | 输入按因果序到达；完成 = 每个前缀在下一输入前给出可接受答案 | `∀n, answer_n 依赖仅 ≤n 输入` | 流处理、交互协议 | C-106–C-109（在线资格）、C-92–C-95（阶段擦除） |

预算：每族 2–3 个 bounded unit；**先做 T2（在线）**——种子最全（C-106–C-109 +

但对象是 HoTT 的几何构造本身，优先级排序见 04 号矩阵。

## 3. 桥层：解释、交付、失配的形式定义

这是把方向 A/B 从口号变成谓词的部分：

```text
解释  I : TaskSpec(RL) → HoTT类型        -- "理论声称能解此任务" = Sol_T(t) 非空/可栖居
      实例：T1 任务 → Σ (f : A → B)（值正确）         —— 注意：期限 d 在 I 下消失
            T2 任务 → Σ f（图像正确）                  —— 因果序在 I 下消失
            T5 任务 → Σ x, isCauchyLimit(x)            —— 模数在 I 下消失
交付  d : HoTT对象 → RL过程               -- "把理论解当现实交付使用"
失配  Mismatch(t, I, d) := 现实任务 t 满足 Complete_RL，
      但经 I-d 管道的任何交付都不能 Complete_RL（或丢失被 t 本质依赖的观察 J）
```

关键定义（对齐 Z 技术核，直接复用阶段 A 的 PromotionSemantics 签名）：

```text
D-essential(J, α)  := ∃ w₀ w₁ ∈ RL, α(w₀) ≡ α(w₁)（理论侧不可分） ∧ J(w₀) ≠ J(w₁)
```

其中 α 是 I 的"抹除效应"：I(t) 只保留了理论可见的维度（值、图像、极限），α 即
"现实过程 → 理论可见投影"。RL 完成标准即 ASK 侧检查（§1 术语对齐）。

## 4. 三条目标定理（模板与预期证明路径）

**Th-1（非因子化定理，每族一条）**
`D-essential(J_T, α_T) → ¬∃ f, J_T = f ∘ α_T`
证明路径：直接构造 w₀/w₁ 对（种子 claim 已提供大多数构造），矛盾即得。
难度：低（多数是 C-claim 的重述）。意义：把"理论看不见维度 D"从直觉变成该任务族的
定理。

**Th-2（无典范交付定理）**
`¬∃ canonical d, ∀ t, d(I(t) 的栖居元) 完成 t`
其中 canonical 按等变性/一致性定义（沿用 C-142–C-148 的 swap 等变口径）。
证明路径：T5 族已有最接近的种子（统一恢复不存在）；T1/T2 需要新构造，预期模式与
"无典范选点"同型：任何 d 必须在某些 w 上做出无理论依据的选择。
难度：中。意义：这是"提升为完成对象必然非法"的机器版本。

**Th-3（支付下界定理，尽力）**
`任何使 J 可恢复的扩张 d⁺ 必须携带 π，π 不在 α 的像中`
证明路径：把"支付"参数化（crisp 假设、transport、标签、模数——来自支付目录），
证明携带 π 的扩张存在（正向，容易）且 π 的必要性（用 Th-2：无 π 即无典范 d）。
难度：中高；允许首轮只对 T5（模数）和 T1（标签化选择）闭合。
意义：把 `DEFENSE_WORKS_WITH_EXPLICIT_PAYMENT` 从判词升为定理——"支付不是可选优化，
是恢复被删维度的唯一通道"。

**定理线自动升级条款**：若在某族中得到比 Th-1/2/3 更强的失配——即"任务 t 现实可完成、
理论侧 `Sol_T(t)` 也可栖居，但**任何**支付都无法补救交付"——这就是原始意义的
`NATURAL_USAGE_MISMATCH` witness，按原 goal.md §11 强门走定理线（该门对这类对象是
正确的门）。

**ERCF-3 门 B 解锁（自审计 G3/G8）**：`OUT-TOP-ERCF3-T3-REPAIRED-SYNTAX` 之后遗留的
义务（对象层可表示性、证明谓词 `P` 的表示性、反射与对角不动点）以"仍需门 B 消费者"
为门。RL 任务族按构造供给该消费者：当某个 T 族任务的 HoTT 侧求解需要把证明谓词/
替换/编码函数在对象理论中表示时（例如 T2 在线任务的"已验证交付"语义），该任务就是
门 B 意义上的自然消费者，ERCF-3 线即可在不变更其自身 Gate 的前提下重启。这同时服务
当前用户主方向（`方向追踪/005` §6.1 的理论经济 × 自反）。

## 8. 本阶段的诚实边界

1. RL 是任务规格模型，不是物理理论；"现实可完成"在 RL 内的定理不能自动升格为
   物理必然性——报告措辞保持"在任务规格语义下"；
2. Th-1/2/3 是关于**联合模型**的定理，不是关于 HoTT 内部的定理；这正是它们能被
   机器证明的原因，也是它们不冒充 HoTT ⊢ ⊥ 的原因；
3. 若某族的 Th-2 失败（存在典范交付），要如实登记为该族的防御成功——它进入
   支付目录而非被遗忘；
4. **A-方向公平性纪律**（对齐阐释层 003 的警告）：理论侧任务必须是现实侧任务的
   忠实翻译，不得偷换成强得多的任务、也不得先行剥除必要信息再把缺口归咎 HoTT——
   每个族的规格必须附"任务同源声明"（两侧输入/观察/完成标准逐项对照）；
5. **ASK 不是万能拒绝**（对齐阐释层 003）：未找到证明 ≠ 不可完成、未知 ≠ 非法；
   RL 不得把开放状态登记为非法输入。
