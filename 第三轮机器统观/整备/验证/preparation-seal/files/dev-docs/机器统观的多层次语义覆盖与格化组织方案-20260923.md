# 机器统观的多层次语义覆盖与格化组织方案

> 身份：HUMAN_EDITED／2026-09-23形成的AI设计候选；正文保留形成时的设计论证与未执行状态。用户随后要求整备第三轮，选定做法已编入[goal-5](../goal-5.md)及[A/B交接](../第三轮机器统观/README.md)，尚未启动新研究。所属F-016/F-024；当前执行与历史判词仍由STATE及各原owner拥有，本文件不与新SOP竞争当前执行权。

本方案研究HoTT现实相对悖论探索中的覆盖单位：怎样同时看见单条规则、局部家族、跨构造组合、共同抽象取舍与所选理论整体。方法为用户原意回核、当前规划与P47范围审阅，以及FCA一手文献核对。得到的是改进设计和有限范围的方法风险判断，不是已经发现了一个HoTT非现实性见证，也不是过去全历史工作审计。

## 1. 用户新问题与本轮忠实理解

用户指出：机器统观应当层次化覆盖，类似形式概念分析的格化；某些非现实问题可能不在孤立细节处显现，而在不同层次的局部或整体中显现；文本组织与既有遍历方式可能使其一直不可见。用户在提出风险及询问改进，并未据此宣布已有数学缺陷。

这不能只解释成“再增加几组两两组合”。至少要同时容纳三类研究对象：多项规则的相互作用；一群规则共同采用的背景抽象；理论某个整体安排相对现实任务的取舍。前两类也可能在不同粒度反复出现。

这还要求反观研究方法自身的抽象：为了方便遍历，我们把理论切成条目；这种切分保留了什么，又把关系、共同背景或整体取舍放到了哪里？这是待检查的方法风险，不是已经证明任意切分都会失真。机器统观的分解方式本身，也应成为可被修正的研究对象。

与既有原意的连接：KC-000002要求完整Theory Schema；KC-000010/011保留现实相对任务和理论自身的时间／时序处理；KC-000029/030将经济收益作为观察位置；KC-000040要求把知识谱作为被考察对象；KC-000044–000048要求现实诠释、对齐与有靶过程。本轮新增的是覆盖组织方式，不擅自改写这些原话的数学地位。

## 3. 五种观察尺度，而非五层文件目录

这五项是本方案的任务组织建议，不是FCA文献规定的五层，也不等同于HoTT的universe或h-level。

|观察尺度|要共同看什么|独立于下层的提问|
|---|---|---|
|规则／使用实例|具体形成、引入、消去、计算及其上下文|该处真正允许什么、要求什么；它怎样服务一个现实／假想现实任务？|
|局部机制家族|若干共同承担一种功能的规则|这个家族作为一个思维工具，为何好用，整体省去了什么？|
|跨构造组合|连续调用、相互依赖、共同侧条件、反馈或三项以上协同|资格怎样沿实际路径传递；各处局部成立是否支持这次整体使用？|
|共同抽象取舍|散布在不同章节的一组表示／推理选择|这些选择共同使什么因素不再参与判断；哪种任务会重新需要它？|
|所选理论整体|固定演算、显式公理、元理论与现实解释的整体安排|这套框架怎样界定对象、同一、取得与完成；它将哪些责任放在理论外或另一层？|

高层审查要产生高层的新问题，而不只是把低层报告压成摘要。低层读完也不自动完成高层；高层形成一个漂亮解释，也不证明细节规则已经支持它。

两个方向需要反复往返：从具体规则向上寻找共同取舍；从共同取舍及原现实任务向下寻找敏感过程和决定性规则。跨构造还要横向查看依赖、组合和反馈。一个规则可以同时出现在多个家族或任务链中，不强制唯一父目录。

## 4. FCA能提供什么，还需补什么

按Ganter、Rudolph、Stumme的教材性文献，FCA从对象集、属性集与关联关系构成的formal context出发，用extent／intent描述形式概念，再组织其上下位关系。这里作为**来源报告与方法借鉴**使用，不声称本轮机器重证其数学结果。[Explaining Data with Formal Concept Analysis，§2–3](https://iccl.inf.tu-dresden.de/w/images/4/49/IntroFCA-RW2019.pdf)

它给本项目的具体启发是：按共同语义属性形成有重叠的观察单元，而不是完全继承书本目录。例如，“涉及对象取得”的单元和“涉及跨阶段使用”的单元可以共享若干规则，却各自提出不同问题。

拟议输入可从既有材料小规模建立：

- 对象：带固定演算、版本、上下文的规则使用实例，以及已明确构造并资格化的组合单元；不能只用一个不带上下文的名词代表所有用法。
- 属性：携带／截断见证、需要统一选择、按呈现不变、需要相干条件、指定阶段可用、涉及完成判据等来源支持的特征；不要先把“有问题／没问题”作为循环定义的分类属性。
- 关联：每个判断有具体来源、适用条件和证据状态。未知、确实不具有、未适用分开；不能把没读到的属性当成已证不存在。

严格的概念格应绑定一个明确的formal context和闭合关系。当前设计图若尚未完成这一步，就叫“多层次语义网络”，不冒称已经计算出的FCA格。概念计算即使完整，也只相对于输入context；没有进入对象／属性选择的机制不会因此获得覆盖。可以计算“已确认属性”的视图，但必须明确它是当前证据组织，不是理论全部语义的认证。

还要区分三种关系：

1. **概念上下位／范围包含**：用于变换观察粒度；
2. **理论依赖／资格前提**：哪项使用需要哪些已取得条件；
3. **操作组合／信息与责任传递**：先后、并行、反馈、多个输入共同支持一个输出。

概念上的共同属性不等于操作的相互作用。互补规则可能没有很多共同属性，却在组合中共同决定结果；因此FCA组织之外，还需要有类型的依赖、过程路径及多输入组合记录。可以在同一份Markdown中描述这些关系，不需要三套数据库。尤其不能把FCA的分类闭合直接解释成理论操作闭合或现实任务完成。

## 5. 将覆盖对象从条目提升为语义单元与关系

每个入选单元复用现有C/D/S/E、TC/OP与TaskSpec身份，只补本任务需要的内容：

|信息|用途|
|---|---|
|尺度、成员及source locator|说明现在把哪些内容作为一个整体考察，范围是否跨章。|
|共同功能／抽象取舍|为什么这些内容值得放在一起，而不只是名称相近。|
|关系及资格条件|明确包含、依赖、组合、翻译、反馈各自含义。|
|本层独立问题与敏感过程|本层究竟新问了什么，什么过程可能使其条件关键。|
|已回答／未覆盖、证据及后继|局部结论约束哪里，还有什么不能继承。|

原八轴张量继续使用，TheoryConstruct可以指向一个有成员与关系的语义单元；观察尺度另在任务范围中显式填写。它与原ObservationLayer不同：后者关注值、trace、Path、资源等观察量，前者关注研究者把多大、多种内容放在一起考察。不盲目再做一个巨大笛卡尔积。

覆盖需要分开报告：点、家族／单元、关键关系、组合路径／反馈／多输入交互、共同取舍／整体问题。各自还有“来源定位、语义审查、候选构造、机器核验、现实对应”的证据阶段。不能把节点数、阅读数或一个总百分比当成全部完成。

结论跨尺度默认不自动继承。例如单条规则的合法性、一个家族的某性质、一个组合过程的可行性，分别需要相应范围的论证；要迁移结论就给明确的保持性／组合性依据。高层有怀疑也不能让所有成员自动变成缺陷。

## 6. 调度：没有单点信号时，也有高层提问通道

现有“看到信号再深化”用于分配深入成本有价值；候选设计建议把它改为两条互补路径：

- **信号驱动**：沿局部异常、来源提示或具体任务深入；
- **结构驱动**：在当前有界pass中，选择有来源理由的共同取舍、重要接口或整体任务，即便其成员未报异常也单独提出并检查问题。

两条路径并行于方法上，不需要并行Agent。结构驱动应有具体入选理由，如跨章共享的抽象、多个条件共同支撑的结论、反复延期的形成／使用责任、对象与元层交接，而非任意抓取一批规则拼在一起。

每个有界统观pass应说明有哪些自上而下的单元，以及未选的高层问题为何暂缓；不得把“成员均无异常”作为唯一排除理由。两两、三项和更高项交互按真实关系选取，不宣称固定二元／三元强度足够。软件组合测试中的高阶与有序交互资料只能作方法参照，不能将其经验分布搬成HoTT的错误分布。[NIST组合测试方法说明](https://csrc.nist.gov/projects/automated-combinatorial-testing-for-software/software-testing-methodology/dos-and-don-ts-of-testing)、[Ordered t-way Combinations](https://csrc.nist.gov/pubs/cswp/26/ordered-t-way-combinations-for-testing-state-based/final)

要控制规模，可以按当前任务选邻域、语义相关组合与有限深度，保存未触达项和重开条件；高层概念只按需展开。没有义务先算出一个覆盖整部理论的巨大格才允许发现。理论合法性、现实任务与完成语义仍负责筛选组合，不能把各扩展能力不加条件地合并。

## 7. 一个HoTT试点应该怎样长出来

建议先用既有“对象取得—存在证据—消去—唯一刻画—统一使用／交付”主题作一个小范围试点。这是示范选题建议，不自动把它升为当前队列第一项，也不排除别的理论主题。

在规则层分别核合法条件；在机制层问“何种证据足以取得对象”；在组合层追踪一次完整任务中证据与资格如何传递；在共同取舍层问“何时可以只看结果／性质而不再携带取得过程”；在整体层问“所选理论与现实解释怎样划分定义、存在、持有和完成”。每一层都要有自己的待答问题。

这些都是候选问题，尚未断言HoTT在任一处错误。先形成一个同任务过程，再回到原生规则与证据。不能因为某个消去器正确拒绝一个越界请求，就将高层的整个取得／完成问题关闭；也不能因为高层描述令人不安，就编造源规则允许的能力。

最小验收建议：

1. 一个跨章主题形成可回源的成员、属性、关系和未覆盖范围；
2. 五种观察尺度各有当前问题与状态，不能只把同一句话换五个标题；
3. 至少有一项结构驱动的高层检查，入选不依赖先发现单点异常；
4. 同一source集合改变文档切分／阅读顺序后，能重建关键语义单元，不被排版替代语义；
5. 预置一个合法的多项／有序交互控制样例，及一个组合后仍正常的对照，检查遍历器会去看哪些关系；控制只验证方法，不冒充HoTT悖论；
6. 原问题与各精化模型的关系明确，局部判词不越级；
7. 交出新的可讨论过程，或具体指出哪个高层连接仍缺依据，而不是只新增一张图。

若试点只提高了分类美观度，没有产生新问题或减少实质遗漏，先修属性与单元定义，不扩数据库／工具平台。若出现信号，按原方法作原生证明、反解释和现实对应；本方案不降低那些证据要求。

方法初步跑通后，还要用一个不以存在／交付为中心的主题作留出检查，例如时间／运动结构与变形／复原任务。该主题保留原始问题，不预置唯一模型；目的在于检查新组织是否仍把一切问题压回熟悉的机制。两种主题不是全理论代表，不能因留出通过就宣称覆盖完备。
