# R05：完成结果触发扩图时的证书作用域

问题为W1已经登记的反馈关系：后继策略读取先前完成结果，再扩展依赖图；谁可改图、哪个阶段被冻结。方法是明确外部controller，用StageColimit源码的有限自然数投影观察过程，配冻结及非终点对照。证据仅是有限软件运行，不是原生SeqColim执行、全称不终止定理或自然HoTT使用者的行为。

输入为阶段n的节点0…n及边x→x−1；fsuc投影把旧节点映到x+1。证书同时保存图标识、节点和是否有后继。controller只有读到当前终点结果后才按策略扩图；扩图是本实验显式授权给controller的动作，不是HoTT内部一条偷偷修改证明的规则。目标在扩图前后逐次记录，没有隐含deadline。

实际运行`feedback-run-002`：growth和frozen各观察6轮；另给阶段2/节点1的非终点输入，条件分支没有获得扩图许可。growth每次读到终点后产生下一图、把旧节点映为1；旧无作用域的布尔true仍可被错误包装器接受，但图/节点绑定证书拒绝为新规格背书。随后实际走1→0，在新图取得新的完成结果。frozen保持同一图/节点，证书与当前观察持续对应。逐个观察的旧边保持检查也符合预期。各项结果来自源码/原始stdout/result，不从运行次数推无界性质。（MO3-J-MS05-R05-RUN）

这个过程确实实施了“读取完成→扩图”，补上静态C01没有执行的部分；它也明确了失配发生在controller改变规格后仍消费旧布尔标记。保作用域的对照没有完成无限扩图任务，只阻止这次越范围使用，所以不偷换Done说已修复全部过程。（MO3-J-MS05-R05-SCOPE）

运行演化：001的非终点对照只计算分支谓词，没有送进同一个controller流程。自审后将该输入也走完整observe路径，002实际记录不扩图再走1→0；两条六轮主过程预期不变。001原收据和对应source.py逐字保存，002是当前交付依据。这是既定对照的执行补强，没有降低或更改验收。

与C01的关系：相同有限算术形状为参照，但本controller没有原生HIT/路径解释，也没有已证明的无限轨迹→C329翻译。C327–330仍只按原命题成立。R05当前可交付“有限反馈原型已实际运行，旧证书与新输入须分开；未找到原理论承诺无条件移植这份完成值的证据”。不能交付“HoTT证明自己永不完成”或“所有反馈安全”。

余项：自然HoTT消费者若真的把这种无作用域完成值升级成新图证明，须另有具体来源和原生接口；本轮未定位到。它属于来源资格未建立的更强候选，不把八域/非叶/偏差回归的已接受义务从本轮移走。R05的本层回答与边界进入覆盖005及最终反遗漏；不要求为这一个诊断原型另建通用动态证明平台。
