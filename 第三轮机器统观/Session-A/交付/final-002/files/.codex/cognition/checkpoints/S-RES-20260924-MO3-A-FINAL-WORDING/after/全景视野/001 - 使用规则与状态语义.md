# 使用规则与状态语义

## 1. 结果状态语义

| 状态 | 只允许支持的含义 |
|---|---|
| `DOCUMENTED` | 有正文/记录，尚未证明实现或运行 |
| `PAPER_ONLY` | 有纸笔推导或说明，未有相称机器证明；按 F-011 不得由当前 AI 重新交付为已成立数学结论 |
| `FINITE_CHECKED` | 有明确有限模型/有限测试，不能外推无限命题 |
| `FORMAL_CHECKED_WITH_SCOPE` | 指定 proof assistant、版本、源码和命题通过，不能外推未覆盖规则 |
| `MACHINE_PROVED_LOCAL_UNCOMMITTED` | 精确 claim/source/kernel run/index 链已在当前工作树闭合，但尚未进入获准 Git commit，不能声称 version-closed |
| `MACHINE_PROVED_VERSION_CLOSED` | 精确 proof/source/run/index 已进入 registry 指定的可恢复 Git commit；不扩大命题或替代 kernel proof |
| `RUNTIME_OBSERVED_WITH_SCOPE` | 某次运行按记录的环境/输入/版本完成，不能外推全部环境 |
| `VERIFIED_WITH_SCOPE` | 证据包、实现/来源和相称验证在明确范围内闭合 |
| `SOURCE_INSPECTED_WITH_SCOPE` | 固定源码和 lexical/结构锚点已核；没有进入保存 kernel run 的模块不得称为机器重放 |
| `REVIEW_REQUIRED` | 历史结果存在，但依赖/版本/适用域/来源仍需复核 |
| `NOT_RUN` | 设计或输入已存在，但实际动作未运行 |
| `UNKNOWN` | 证据不足以作更强判断 |
| `NEGATIVE_WITH_SCOPE` | 在明确范围内的反例/失败/缺件，不能外推为全局不存在 |

下列词不被本文件当作证据等级：`AI 说已经完成`、`文件很多`、`hash 相同`、`Git committed`、`PASS`（未读判据时）、`paper-like`、`同行同意`。

## 4. 全景与方向的交叉审视

每次工作结束至少回答：

| 问题 | 本次要看什么 | 若不满足 |
|---|---|---|
| 方向是否仍服务核心认知 | 当前方向的 user/core 关联、目标范围和排除条件 | 标 `MISALIGNED`/`REVIEW_REQUIRED`；不能修改 core 求一致 |
| 方向是否产生新结果 | 新 paper/code/run/failure/unknown 是否有结果 ID | 没有就 `NO_RESULT_YET`，不能填“已完成” |
| 结果是否有方向归属 | result 的 direction ID 和 unmapped reason | 孤儿结果 fail closed |
| 状态是否有直接证据 | 文件、代码、测试、运行、Git、source hash 和适用范围；数学结论另查 formal source/kernel run/claim index | 降级 `REVIEW_REQUIRED`/`UNKNOWN`；数学命题降格为非结论状态 |
| 是否需要更新 core | 只有用户新原文/明确工作意识变更才是“是” | AI 结果不得反向改 core |
| 是否需要更新方向 | 候选、优先级、下一动作、依赖或状态改变 | 原位更新本文件和 STATE 对应 owner |
| 是否需要更新全景 | 新结果、正反例、失败、未知、验证范围改变 | 原位更新本文件和 result owner |

## 5. 版本和证据冲突

- WebGPT `README` 的 revision40 与 `STATE/MEMORY` revision41 并存；本投影使用 `STATE revision41` 作为 WebGPT 记录分母，同时把 README revision40 作为历史漂移证据，不覆盖它；
- WebGPT `FRAMEWORK_MANIFEST` 的业务 Skill 版本为 1.3.3，而实际 Skill frontmatter/内容为 1.3.4；本投影不刷新旧 manifest 求一致；
- LocalGPT live 工作树 dirty，而顶层 source snapshot 有自己的 tree SHA；live dirty 只说明已检查的现场，不等于 source snapshot 已包含 dirty 内容；
- WebGPT R039 测试 `31/31` 只覆盖其测试断言；`native_kernel=NOT_RUN`、`general_proofs=PAPER_ONLY` 必须继续显示；
- 顶层三件套已接入 generation-4、STATE/load v3、逐文件 merge receipt 和全量历史 source register；fresh Python 输入保真与负向行为可核验，fresh 模型/压缩后实际使用和 2,396 条 claim 的句级语义仍未认证。

## 6. 更新规则

- 新用户悖论/元数学原文：先存 primary input、人工更新 curation，再由 manager 生成新 core generation/transition，并同步 `rulings`；一般治理要求只进 ruling/Feature；
- 新候选/优先级/状态/下一动作：更新 `方向追踪.md` 与 STATE；
- 新结果/失败/未知/运行收据：更新 `全景视野.md`、原 result owner、artifact/ledger/Git；
- 新的数学结论：先通过 `MATH_PROOF_BEFORE_DELIVERY_V1`，把源码/run/index 留在 repo，再回到 `HoTT/` 当前 owner；未通过只能记录为候选/问题，不能只写在本文件；
- 结果与方向冲突：保留冲突，降级状态，回到直接证据；
- projection source revision/hash 改变：标 stale，重新生成或原位修订，并在 Git 保存前版本；
- 不在本文件追加一个覆盖旧结论的“最新版”段落作为双真值；当前结果 owner 必须原位收敛，历史由 Git/审计保留。
