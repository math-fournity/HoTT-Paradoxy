## 1. 已接上的完整链

```text
全局AGENTS
 → repo-cognitive-closure：适用性判断 + 发现项目入口
 → 项目root AGENTS + common治理 + TASK_ROUTING
 → 完整最高指示，确认研究/审计/来源解释/治理/机械上下文角色
 → 匹配的A执行或B审计Skill
 → Goal6单体开工闭包
 → Goal5必读领域细则 + 原始认知与当前证据
 → 实際工作 / 结论审计 / 当前owner写回
 → 跨Session、压缩、角色或版本变化：先恢复，再继续
```

新全局方法由既有repo-cognition-governance组织整备，不增加第三核心调度器。Global两核心的`.codex/skills`与实际可发现的`.agents/skills`副本保持同字节，避免同名不同规则。共享方法在独占工作树，dirty主库main未改；OpenCode/portable Web/config/Hook/模型实验未动。

## 3. 当前主Agent的治理角色理解复核

本轮完整读取最高指示后，使用`GOVERNANCE_ALIGNMENT`：

1. 保护的发现动作是“理论收益→被改条件→针对过程”，连同跨尺度主动提问；规则加载最终应帮助选题与构造，不能只提高打勾数量。
2. 最危险的偏差是把已读当已用、把精化模型当原问、把局部覆盖当整体完成，以及审计者继承执行权限。本轮靠角色合同、恢复入口和证据分级约束这些可见行为。
3. 新route让任何Session在开始/恢复时找到共同认知，再根据实际任务进入A或B；普通机械/治理工作仍有最高指示背景，却不被迫制造数学候选。
4. 已写文件由diff支持；加载计划由真实loader支持；本次全文读与复述只是一例消费；7项机械检查不证明新Session/真实compaction行为；第三轮研究与最终数学成果仍未产生。

这是公开的决策理由与产物，不是模型隐藏思维记录，也不是自颁理解合格证。

一次实质自审发现：最初角色表把“原意讨论”也放进研究生成，可能让普通答疑被强制变成新研究。因此补入SOURCE_EXPLANATION并同步root/common/PROTOCOL/路由；原文仍全文读、实际语义判断仍source-first，但不强迫与问题无关的候选和14题。这个修正来自静态情境审阅，不冒称fresh模型已表现正确。
