## 4. 自主调度研究前沿

维护小型前沿，不建数据库或多 AI 平台。采用三个逻辑位置：**收敛、探索、深层**；它们是注意力槽，不是三个 Worker/Job，也不要求同时填满。

优先：接近用户核心问题、HoTT 规则真实参与、见证可构造、下一检查有判别力、机制不重复。不要按冲击力、迎合预期、公式量或文档数量排序。

每轮选一个最值得推进的候选和一个关键未知，解释本轮选择；记录九方向最近实际触达和暂缓原因，定期将被忽视方向放入探索。不要机械让成本问题永久占据所有位置。新的线索来自八种构造操作，不依赖用户追加故事。

相同失败重复出现时换构造/证明方向/子问题，不靠改名维持活跃。开放深层问题不因长期未解而被永久关闭；暂挂说明具体依赖与重开证据。

## 5. 实际研究循环

对本轮选中对象执行：

1. 写最小但不失真的对象、函数、关系、状态与假设；固定 task_version。
2. 沿 Schema 回查原始规则，做正向推演；从不相容目标反推缺失引理。
3. 固定比较任务与观察量，分别标明核心承诺、表示承诺、解释承诺。
4. 同时尝试证明冲突与构造满足全部原要求的反模型/正实例。
5. 审查类型、宇宙、消去限制、等号、因果/总性、侧条件、量词与现实桥梁。
6. 提取范围准确的结论，更新各证据轴；原因与修复可保持开放。
7. 由关键未知决定下一动作，在本轮授权和可执行资源内继续；必要时转另一分支。

当反模型保留了原任务，必须改变候选判断；当所谓修复换了任务或新增数据，标明差别。富化可反驳绝对不可表达性，但不抹去原表示的损失。删除假设后没找到矛盾，不证明它必要或唯一；需要满足实例或进一步证明。

完整卡点决策表、种子和跨系统比较见 [execution-playbook.md](references/execution-playbook.md)。

[acceptance-cases.md](checks/acceptance-cases.md) 是行为场景，不是已经执行的 Fresh Session 测试。`checks/test_full_closure_loading.py` 只检验全文读取辅助工具与入口约束，不证明模型确实接收了每一段正文。安装通过不证明数学、研究有效性、宿主自动加载、持续后台运行或独立专家认可。
