# 03 - 方法论与数学评估

> 本报告是审计的核心分析层：评估 WAI 的方法论能否在原则上送达目标，其对"不可计算性/
> 计算合法性"路线的使用在数学上处于什么位置，以及最强在手结果为何被闲置。
> 本报告的判断由审计人独立作出，附推理与可反驳点；与 WAI 自评不一致处均已标明。

## 1. 核心发现：Goal 完成门在结构上不可达

goal.md §11 的完成门要求**同时**满足五条件。把它们按"是否存在能签发证书的裁判"分类：

| 条件 | 内容 | 可签发证书的裁判 | 可达性 |
|---|---|---|---|
| 1a | exact HoTT 规则/表示、抽象/资格变化、机器证明的不完成/不相容 | proof assistant kernel | **可达**（R4 线正在做） |
| 1b | HoTT 必要性（消融） | kernel + 消融对照 | **可达**，但可预测结果见 §3 |
| 1c | natural consumer | 无机械裁判（"自然性"是社会/经验判断） | **半可达**（只能被论证，不能被证明） |
| 1d | 现实同任务对应（同一任务、输入、观察、完成标准） | **不存在**：'现实'不是任何 kernel 可判定的谓词 | **不可达**（机器无法证明理论↔现实对应；只能证明理论内命题，然后由人接受类比） |
| 2 | 最强反解释 + 独立/跨框架复核 | 部分可达 | 开放世界义务，永可再加一条 |
| 3 | 学术覆盖达到具名截止日与渠道分母 | 文献审计 | **已经失守**（2026-09-14 已过，判词 `COMPREHENSIVE_COVERAGE_NOT_ACHIEVED`） |
| 4 | 统观覆盖证书（有界覆盖/公平/归约） | 覆盖管理器 | 只能对**自设分母**签发（见 §5） |
| 5 | 最终报告可重建 | 写作义务 | 可达 |

结论：**条件 1d 与 3 使完成门成为混合体——形式部分可由机器闭合，哲学部分（现实对应）与
已失守的截止日部分不能。** WAI 的 R5 规则（"只有 trusted HoTT rules 推出 ⊥ 才能使用"）
又关掉了另一条形式出口，而这有充分理由：HoTT+univalence 相对 ZFC+不可达基数有模型
（Kapulkin–Lumsdaine–Voevodsky 单纯集模型；cubical set 模型给出构造性解释），寻找内部矛盾
的先验成功率与在 ZFC 中找矛盾同级。WAI 的规划把语义模型登记为搜索轴 TC-14（
`HOTT-PARADOX-PROGRAMMATIC-EXPLORATION-COMPLETENESS/002`：cubical sets/assemblies、
simplicial/realizability models），**但从未把"存在模型 ⟹ 内部矛盾线必然落空"吸收为
安排工作量的先验**——否则 R3/R4 线的优先级不会高于现实侧桥梁线。

于是目标系统呈现如下动力学：任何实际发现都会被 WAI 自己的正确纪律分解为
"generic 部分（机器可证但 §1 明令禁止计为完成）+ 哲学部分（不可机器证）"，
见证因此永远不出现，而 goal.md 末行规定"保留未知并继续……除非用户明确修改目标"。
**这是一个设计上不自终止的自主循环。** 这不是执行力问题，是目标契约问题。

## 2. 范畴错配：哲学命题被塞进数学定理验收门

用户目标的本体（`HoTT/Z_LAW_REALITY_RELATIVE_PARADOXES.md` §0）：

- Z 强律是哲学普遍命题，其文档自己写明"若要向项目外发表不依赖项目定义的普遍定理，
  仍须量化 theory/reality/abstraction"——即**承认不可在当前框架内形式化为定理**；
- 用户验收语言："找到一个合法的理论推演……当提升发生时产生**可证明的**非法构造或非现实性"——
  注意被证明的是**提升后的形式后果**，而不是"现实中有人这样用"。

WAI 的验收实践却引入了数学共同体式的定理标准：E6 natural consumer（要有人在自然使用中
真的需要越级资格）、最强竞争解释、正控制。这套标准对**定理**是对的（防止把已知边界冒充
新发现），对**哲学论证的实例**是过度的：Z 铁律要的是"存在对被否定维度 T 本质敏感的效应
分岔"（存在量词），机器证明一个分岔实例 + 提升语义桥即满足；不需要世界上存在一个
恰好踩中该分岔的 HoTT 用户。

**WAI 在过去五天里已经机器证明了分岔实例族**（01 号报告 §4 的表）。它们被封存的唯一
原因是 E6。本审计判断：E6 门槛对用户目标是不必要条件，且极可能不可满足——因为 WAI
在**代码库**（Cubical lib、agda-unimath、论文实现）里找消费者，而方向 B 说的"现实侧交付"
发生在**世界**里（编译器、运行时、物理时间、能耗、工程合同），代码库里本来就不会有。
在错误的空间里做穷举，产出必然是一连串 `BOUNDED_NEGATIVE`——这正是 N1/N2/N5/N10、
E6 定向扫描、12 批抽样实际得到的东西。

## 3. 不可计算性/不完备性路线的数学定位与可预测结局

用户指定的路线（不可计算性、计算合法性）在 WAI 体系中是 R0–R4 阶梯。逐级评估：

- **R0–R2（已完成）**：停机校准、ProgramCode、公平枚举、半可判定、双 kernel 归约
  （Coq MM2 ⪯ PC_HALTING + Cubical 模型对应）。数学上干净，强度标注（synthetic
  implication）无懈可击。但这些都是**一般计算理论**：对任何图灵完备系统成立，
  goal.md §1 明令禁止计为完成。WAI 知道并遵守。
- **R3（已完成）**：重放 `uds-psl/coq-synthetic-incompleteness`，条件性本质不完备 +
  Robinson Q 独立句。同上：generic。
- **R4（进行中）**：把 R3 的十二项义务保真接到一个具名 HoTT calculus。**本审计预测其
  终局判词**：`GENERIC_GODEL_BOUNDARY_WITH_HOTT_INSTANCE`。理由：(a) HoTT 的规则集
  是有效可公理化的，univalence/HIT 作为公理模式不破坏证明谓词的可枚举性（H-EFFECTIVITY
  将机械通过）；(b) HoTT 解释 MLTT+Nat，故解释 Q，不完备性经由解释转移，机制不依赖任何
  同伦结构；(c) WAI 自己在 `R3-R4-GODEL-RETURN-001.md` §6 设计的 ARITHMETIC-ONLY 消融
  将正确地显示删掉 Path/univalence/HIT 后结果不变——即 HoTT 必要性不成立。而
  `GENERIC_...` 恰是 goal.md §1 禁止当作 Goal 完成的类别。**因此即使 R4 全部做成功，
  也不构成完成；这条线在设计内就不可能送达 Goal。**
- R4 的一个真实残余价值：HoTT 特有的计算合法性事实不在不完备性，而在**典范性/求值**侧：
  Book HoTT（公理式 univalence）中 transport 沿 ua 不计算（canonicity 失败），cubical
  以区间/cofibration 复杂度为代价恢复计算；Cubical Agda 的 cubical 内容无可执行交付路径
  （N10/S052 实测：后端拒绝 `--cubical`，`--erased-cubical` 仅擦除）。这是"理论对象被
  当作已获得能力"（方向 B）的实锤级现象，且 HoTT 特有。WAI 已测到全部零件（C-100–C-105
  ua 计算、S052 工具链交付审计），但同样因 E6/DEFENSE_WORKS_SCOPED 判为"不够"。

**可反驳点**：若有人证明 univalence/HIT 以某种方式改变对象理论自身的证明谓词或有效公理化
（例如通过非有效的规则模式），R4 可能升级为 HoTT-essential。现有文献没有这种迹象；
WAI 的资格化门（Q-EFFECTIVITY）恰好会正确地检测并拒绝这种情况。因此本预测稳健。

## 4. 最强在手结果的重组价值（本审计的正面主张）

把已验证的零件组装起来，用户目标的"最强可交付版本"其实已经存在：

1. **抽象层**：HoTT 的恒等（funext/ua 之后）是同伦不变的，看不见时间、代价、轨迹、
   阶段落定（C-96–C-99、C-71–C-76、C-92–C-95、C-106–C-109 机器证明：任何通过裸
   恒等因子化的观察量都不能区分它们——非因子化核心的直接实例）；
2. **提升层**：若把"行为相等的函数"提升为"现实计算过程的完整身份"（这是理论允许、
   现实错误的提升），则可证明地丢失运行时间/能耗/在线资格/固定点轨道信息
   （正控制显示：必须改变表示、增加结构才能恢复——理论不提供典范恢复方式，
   C-134–C-141 不可恢复族 + C-142–C-148 无典范选点）；
3. **现实层**：现实侧任务（限时交付、流式处理、竞态裁决）对这些维度本质敏感——
   这不是数学定理，是任务语义，由用户哲学框架接受（Z 文档 §0 的存在量词读法）。

这三层合起来就是 Z 文档所描述的"效应谱 Y≠X"的严格化实例。WAI 缺的从来不是证据，
是**一次面向用户的组装交付**。它不做组装的原因是其定理门要求 E6；而组装不需要 E6。
（注意：这不妨碍 WAI 继续把"是否存在更强 witness"作为开放问题保留——两者不冲突，
冲突的只是优先级。）

## 5. 统观覆盖的自指问题

CE-MAP v1 的 478 项分母中，约 430 项是 WAI 自产工件（41 自建 proof package、186 自评
claim、143 自写 STATE record、108 自派 machine-overview 实物）。覆盖证书因此度量的是
"自产工件在自设八轴分类法中的登记完备性"。这在工程上有用（防重复、防遗漏登记），
但把它称为"机器统观完备性"会产生名实差：**对真实候选空间（HoTT 的全部抽象变换 ×
现实任务空间）它没有约束力**，69 个 UNKNOWN 只是承认这一点。WAI 的措辞纪律
（`OPEN_WORLD_COMPLETENESS_NOT_CLAIMED`）是好的，但一个更诚实的命名是
"自产工件登记完备证书"。同理，"每个 bounded unit 结束执行遗漏审计"的义务，其检索空间
仍是同一自设分类法的同义词扩展。

## 6. R4 目标选择的错位：原型实现 ≠ 理论

`R4-HOTT-NAT-EFFECTIVITY-001` 把 cubicaltt/redtt/cooltt/cctt 四个**社区研究原型**作为
"exact HoTT calculus"候选，然后必须自建 certified-input profile 排除 holes/undefined/
无终止递归（四者的风险列 WAI 自己都写明了）。问题：被 certified scanner 划出的受限方言
是 **WAI 自己的构造物**；对它证明的任何性质，其对象是一个既非 HoTT 理论、也非上游实现
的第三者。WAI 在 TaskSpec 中诚实承认（"只能定义一个受限输入语言，不得声称修复或证明
完整上游 calculus sound"），但没有承认推论：**这条路线的保真赤字是结构性的，不是工程
细节**。更直接的替代路径存在：对已发表的形式演算（如文献中已形式化的 QIIT 语法、
ABCFHL/CCHM 演算的形式化）做保真对接，而不是对原型实现做扫描。WAI 并非不知道
（C-223–C-226 用了 akaposi/cohtt 的形式语法切片），但当前 successor 又回到了实现路线。

## 7. 文献/先验覆盖的缺口（针对所有者的预设"HoTT 必然考虑了已知悖论")

已覆盖（核过，质量好）：Gödel/Turing/Church/Rosser/Kleene/Post/Rice–Shapiro/Tarski/
Hilbert–Bernays/Löb/Lawvere/Chaitin（FND 族，primary 实读进行中）；2LTT、LOPS、
Boulier–Tabareau、Oracle Modalities、Parametric CT、groupoid syntax（HCT/MET 族，
已到机器重放级）。**这条防线验证线正是对"HoTT 考虑过已知悖论"的正确执行**——WAI 实际
在逐个证明：已知攻击在 HoTT 中要么被类型分层挡住、要么有显式支付装置。

缺口（按影响排序）：

1. **现实侧计算理论缺席**：LIT 分母七族（FND/MOC/TRM/PAR/HCT/MET/MFM）全部是数学/
   类型论/证明工具族；计算分析（computable analysis）、物理 Church–Turing 论题、
   Pour-El–Richards 型"数学对象不可物理实现"结果、超计算辩论**零命中**（本审计 grep
   确认）。而"现实同任务对应"恰恰需要一侧的"物理上什么可计算/可完成"的理论。这是
   文献分母与目标之间的结构性缺口。
2. **一致性/典范性正结果未被用作先验**（见 §1）：它们在 TC-14 轴里，但从不影响
   排程决策。
3. SET/经济学侧（理论工具性的收益-代价谱）以 C11 账本形式存在，但其"经济性"文献
   （例如关于 cubical 转换检查复杂度、proof assistant 工程代价的实证文献）未见登记。

## 8. 方法论做对了什么（公平清单）

为防止本报告被读成单向否定，列出 WAI 方法论中本审计认为**应当保留**的资产：

1. 防误报黑名单（goal.md §1）+ 四级判词阶梯 + R0–R5 强度分层：直接消灭了历史上最常见的
   失败模式（把一般不完备性说成 HoTT 悖论）；
2. synthetic implication 的显式前提保留（C-208/C-219–C-222/C-244–C-249）；
3. 有界负结论 + 复活条件登记（不把"没找到"写成"不存在"）；
4. 消融设计先于结论（ARITHMETIC-ONLY 等）；
5. 外部批评吸收模式（F1–F7：接受、机器反证、登记不抹除）；
6. run 收据体系（F-011）与 fail-closed 校验器。

问题不在这些纪律本身，而在它们被套在了一个它们无法裁决的目标上，并且挤占了
组装交付与现实侧建模的优先级。
