## 2. 对未来锻刀的四个实质改变

### A. 锻刀的计量单位已改变

未来有效锻打不再按 prompt 数、worker 数、报告数、guard 数或 Git 提交数计量。它必须对一张固定 Q 卡产生：

~~~text
Q_GENERATE / Q_NARROW / Q_BRIDGE / Q_CONVERGE / Q_REJECT
或指向该卡的 Q_SAFETY_REPAIR
~~~

不能指向固定 Q 的字段、runner、prompt 或文档工作是 TOOL_ONLY_DRIFT，不再计为 P-FORGE 的发现进展。

### B. 外部来源不再直接进入 ForgeIntent

文献、候选 worktree、来源综合或 PDF 筛读若企图改变 P-FORGE 判断，必须先走：

~~~text
LiteratureEvidenceEnvelope
→ R_i/Z_i/Q_i 或 H0/Z0/Q0 route
→ RB-D01--RB-D16 RouteBackflowCard
→ I0--I4 impact triage
→ only I4 may propose a ForgeIntent
~~~

这把“读到新文献”与“有资格启动一轮新锻打”分开。

### C. 三把刀的来源输入被收紧

P1 需要同 route 的 actual consumer 与同一 T/u/F/C/I/O/Done；P2 不能把编码、公式、proof search 或模型词汇当作 reentry；P3 不能把静态公理、proof witness、递归或外部耗时当作 lifecycle。外部来源若只给 model/payment、概念比较、历史判断或 metadata seed，只能成为控制、缺口或 I0/I1。

### D. 校准与站位不再被来源数量推动

CAL-* 衡量的是 P 的校准能力，I0/I1 衡量的是来源前沿；二者不互相代替。Power Set station 也不能因来源积累自动切换：文献剩余主张必须能落到 EvidenceEnvelope、RouteBackflowCard、I-level，以及 PowerSetDefenseLedger 的 PS4/PS5。

## 4. 仍然没有发生的改变

~~~text
new blade                       = no
~~~

这部分同样是系统影响：未来 AI 不能再把“文献工作做得很多”用作绕过上述门的理由。

## 5. 下一次 P-FORGE 的真正起点

下一次锻刀不应从“再找些文献”开始，而应从一个可填写的新 ForgeIntent 开始。若它依赖外部来源，先满足 SourceBackflowGate；然后必须能回答：

1. 哪张固定 Q 卡受到改变？
2. 来源为何保留同一 formation route、T/u/F/C/I/O/Done？
3. payment、guard、route mismatch、task switch 和 source layer 已怎样被排除？
4. 该来源得到 I4 的理由是什么？
5. P1/P2/P3 在同一卡各自要检查什么，何种结果会停止？

没有这些答案，未来系统应当停在来源前沿，而不是启动新的理论节点。
