1. P1（“同阶段不可用”）的候选可以被精确定义（§1），但它的**支付装置在每一步都可用**（§2：D1–D6），且其中 D6 把“从粗类型取回被悬置因子”变成**类型检查义务**。

## 1. P1 候选的固定定义（同一任务 + 完成判据）

| 项 | 内容 |
|---|---|
| 任务 `T_P1(k)` | 给定过程 `p` 与阶段 `k`：在阶段 `k` **交付**该过程那时已经落定的结果（不是“最终存在某个结果”） |
| 现实侧 | 执行 `p`；若在 `k` 个回合内落定，交付该值；判据是“在 `k` 内交付” |
| 理论侧抽象 | 把 `p` 记为其**结果类** `[p]`（例如 delay 商 `Delay A / ≈`、Cauchy 商、阶段擦除后的类），任务写成“从 `[p]` 与 `k` 交付” |
| 反差候选 | 存在 `p ≈ p'`，使 `p` 在 `k` 内交付 `v` 而 `p'` 不在 `k` 内交付；于是任何只依赖 `[p]` 的交付函数不可能同时正确 |
| 相关核心主题 | 时间/时序、过程与可用性、ASK 的“此刻是否有资格交付” |

**已有机器对应**：`MP-RACE-TIMEOUT-001` 的 C-73–C-76 正是这个反差的固定片段——`p0 ≈ p2` 而 `race p0 q1`/`race p2 q1` 不等价（C-73）、业务 continuation 在 `p0` 上返回而在 `p2` 上发散（C-74）、`deadline 1 p0 = some true` 而 `deadline 1 p2 = none`（C-75）、商上不存在 race 选择子（C-76）。也就是说 **E2/E3/E4/E5 已经机器闭合**，只剩 E1（真实任务）与 E6（真实接口）。

## 2. 支付装置审计（每一步都可用）

| # | 支付装置 | 形式 | 现有机器证据 | 状态 |
|---|---|---|---|---|
| D1 | 阶段索引 / 前缀模型 | 把策略建模为“当前可用前缀”的函数，而不是完整流 | C-106–C-109（时刻 0 无前视；分时刻正例；完整知识 ≠ 在线资格） | 可用 |
| D2 | 阶段擦除⇔不动点判据 | 显式阶段流 + 忘却翻译；擦除可行 ⇔ 律有不动点 | C-92–C-95 | 可用 |
| D3 | partial / strict 分类器并存 | 用部分值替代总值，把“尚未落定”变成类型内的位置 | C-118–C-123 | 可用 |

| D5 | 上下文族保留时序 | 不把时序能力放进结果商，而放进上下文等价 | C-71–C-76、C-77–C-91 | 可用 |

D6 是本次审计的关键：**在商与截断上，“从粗类型取回被悬置因子”在类型层就已经不可能**，除非该因子对关系不变——而那正好意味着它没有被悬置。因此 P1 的失配不可能来自“理论忘了阶段”，只能来自“某个接口**先承诺**了阶段能力，却把域声明成粗类型”。

## 3. 判词与理由

> **判词：`P1_BOUNDED_NEGATIVE_PAYMENT_DEVICE_AVAILABLE`。**

理由分三层：

1. **模型层**：C-73–C-76 已给出同一任务下的完成性反差（E5），而 HoTT 的处置是**正确拒绝**把 race/deadline 放进结果商——这是 `DEFENSE_WORKS`/`REPRESENTATION_BOUNDARY`，不是理论失误。
2. **装置层**：D1–D5 表明，只要任务允许细化表示，阶段可用性总能被带回来；D6 表明，只要域是粗类型，任何取回动作都要过类型检查。
3. **方法层**：C11 的证伪条件明确规定——若被悬置因子能在同阶段同层被带回来，判词必须停在表示边界。P1 正落在此格。

## 4. 用 checklist 重读既有审计集合

checklist（C11 §2.3 的两问 + E6 的三项）：

1. 接口是否**钉死在粗抽象**（公开类型以商/截断/等价存在为域）？
2. 调用链是否**必须取回**被悬置因子（时序/见证/成本/来源/阶段）？
3. 该要求是否发生在任务规定的**同一阶段或同一层**？

**结论**：在已审计集合内没有任何候选同时满足 ①②③；唯一“①成立”的候选（delay 商）在②上被接口自身承诺的边界挡住。这给出一个更强的负结论：

> 在“**类型层**”寻找 E6 是徒劳的——商/截断的消去规则已经把能力边界写进类型。E6 若要存在，只能出现在“**接口文档承诺超出接口类型能力**”的地方。

## 5. 锐化后的 E6 判据（可操作版）

一个候选升级为 `NATURAL_USAGE_MISMATCH` 的必要条件（五项全需，逐项给出证据类型）：

1. **粗域接口**：接口的公开类型以粗抽象为域（商 / 截断 / “等价存在” / 阶段擦除后的类）。证据：源码签名或 API 文档。
2. **同一任务**：调用链的输入、输出规格与完成判据与“现实侧完成的任务”一致。证据：调用点 + 任务说明。
3. **必须取回**：接口的**文档/契约**要求它交付被悬置因子（时序、见证、成本、来源、阶段）。证据：接口文档/论文承诺原文。
4. **同阶段或同层**：该要求发生在任务规定的阶段或层级，且细化表示在该处不可用（例如 API 固定版本、任务禁止携带额外数据、或要求在理论内部完成担保）。证据：阶段/层级约束的来源与版本。
5. **无外部豁免**：不需要神谕、全知未来、额外输出或改变任务。证据：调用链与输入集合。

第 1、3 项是**接口事实**（源码/文档），不是定理——这就是为什么 E6 不能被更多数学证明替代。第 4 项是 C11 判别格的落点。

## 8. 重开条件与停止条件

**重开条件（任一成立即重开 P1）**：

1. 出现一个真实、固定版本、可回查的接口，其**文档承诺**要求在同一阶段交付被商/截断/外延化悬置的因子，而它的公开类型以粗抽象为域；
2. 或出现一个任务，其成功判据本身**禁止**携带额外表示（例：接口不可扩展、数据必须在阶段 k 前定稿）；
3. 或外部工具链/库改变消去规则（例如出现允许从粗类型取回数据的原语），使 D6 不再成立。

**停止条件**：候选只在“同阶段同层可用”的格子里出现；或反差需要神谕、全知未来、额外输出；或结论完全由一般停机/一般商/一般复杂度给出而 HoTT 规则未进入关键步骤。
