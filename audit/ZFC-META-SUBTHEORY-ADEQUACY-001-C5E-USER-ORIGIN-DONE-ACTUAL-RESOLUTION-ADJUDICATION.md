## 2. 项目合同的裁定

用户已经把本项目要审的命题固定为：“明明芝诺／圆环没有在 finite-stage process意义上解决，为什么极限理论可以声称已经在ZFC中解决？”并在 C2C 把该 `OriginDone` 写为 `∃ n : Nat, remaining n = 0`。

在这个**用户定义的原任务**下，IEP仍使用“Standard Solution / resolution”来谈同一Zeno/Achilles/Dichotomy discourse。故本项目可以、且必须将该 application language映入：

```text
applicationClaim           = true
claimsOriginalResolution   = true
requiresBridge             = true
bridgePaid                 = false  -- current source-to-spec denominator
explicitTaskSwitch         = false  -- in this user-Q contract
```

最后一项不否认IEP说“final step is mistaken”。它的精确意思是：若一个来源一边继续称其为对**用户固定原任务**的resolution，一边拒绝该任务的`OriginDone`，该拒绝不能同时充当 C5A 意义上“明确改题且不声称原题已经解决”的 payment。它是本项目的任务保真裁定，不是关于学术共同体唯一正确解释的历史断言。

## 3. 反控制仍保留

若研究发起人后来把IEP的revised continuous completion接受为自己 `OriginDone`，或一手来源明确说其只解决不同任务、并不解决 finite-stage Q，那么 `taskSwitchControl` 会取代本卡的failure branch。这正是 C5D 所保留的可反驳读法。

因此本卡交付的是：

```text
under USER_ORIGIN_DONE_POLICY:
  the source-certified ApplicationCase is applicationUnpaid.
```

它不交付：bare ZFC的对象语言矛盾、物理离散性定理、或“数学共同体已经承认错误”。
