# 数学结论机器证明与证据留存规范

> 状态：`CURRENT_PROJECT_CONTRACT`
> 版本：`math-proof-delivery/v1.1`
> 用户裁定：`rulings.md` §15
> 宪法入口：根 `AGENTS.md` 的 `MATH_PROOF_BEFORE_DELIVERY_V1`

## 1. 目的

本规范保证当前 AI 不再把纸笔推导、语言论证、有限测试、外部论文转述或历史 AI 自述直接包装成已经成立的项目数学结论。每个由当前 AI 交付为“已证明”的数学命题，都必须同时拥有：

```text
精确命题
  → repo 内证明源码
  → 匹配语义的 proof assistant/kernel 实际运行
  → repo 内不可覆盖运行收据和原始输出
  → 当前 claim—proof—run 索引
  → 交付前一致性检查
```

它不要求在形成猜想之前先证明，也不阻止报告开放问题、失败或外部来源；它只禁止证据状态越级。

## 2. 什么属于“数学结论”

当前 AI 把下列内容作为成立事实陈述时，均命中门禁：

- 定理、引理、推论、恒等式、等价、蕴含和不变量；
- 存在性、不存在性、不可能性、唯一性、可判定性、终止性和复杂度命题；
- 一个反例已经否定某个一般命题；
- 一个模型、商、路径、截断、程序或变换具有某个全称性质；
- HoTT、某个 HoTT 变体或其它理论必然/不可能做某事；
- 由当前 AI 对历史材料、外部来源或实验作出的新数学综合结论。

以下内容可以不先形成机器证明，但必须保持非结论身份：

- 用户原文和用户研究立场；
- `QUESTION`、`CONJECTURE`、`HEURISTIC`、`COUNTEREXAMPLE_CANDIDATE`；
- `PAPER_ONLY` 的纸笔候选；
- `SOURCE_REPORTED_NOT_REPLAYED` 的外部/历史定理转述；
- 研究计划、定义草案、证明义务清单和失败报告；
- 纯治理、来源、文件、Git 或软件测试事实。

一段文字同时包含来源转述和当前推论时，只有来源部分可以保持转述身份；当前推论仍须过门禁。使用“显然、标准、众所周知”不能豁免。

## 3. 机器证明的资格

### 3.1 合格证据

合格机器证明必须由实际 proof assistant/kernel 对**本次精确源码**成功检查，并记录：

- proof assistant、kernel、标准库和关键依赖的精确版本/commit；
- 命令、工作目录、环境变量中非敏感的必要部分和退出状态；
- 形式命题、假设、公理、导入、宇宙和理论变体；
- 源码及锁定依赖的 SHA-256；
- 原始 stdout/stderr；
- 运行时间和 host/架构的非敏感身份；
- 证明支持什么、明确不支持什么。

若使用模型检查或穷举作为证明，只能把它提升为机器证明，当且仅当：

1. 命题本身是明确有限域命题；
2. 域的完整枚举和边界有机器证据；
3. 程序断言与数学命题之间的对应已明确；
4. 运行覆盖全部域，而非抽样；
5. 结论不外推到无限域、未枚举变体或现实世界。

### 3.2 不合格替代品

下列证据不能单独满足门禁：

- AI 自述、纸笔证明或 Markdown 中的公式；
- 代码存在但没有实际运行；
- Python/Node/Lean/Agda 文件名看起来像证明；
- 单元测试、随机测试或有限样本被外推为全称定理；
- 普通 Lean `Eq` 被用来替代 cubical Path、univalence、HIT 或截断的原生语义；
- 外部论文、网页或历史 proof receipt 未在当前项目精确环境重放；
- `exit 0` 但命令、版本、输入、源码哈希或原始输出缺失；
- 只存在于 `/tmp`、聊天附件、内存变量、工具 stdout 或未保存沙箱中的结果。

### 3.3 外部库重放与源码审计必须分层

外部库场景至少区分三层，措辞不得混用：

1. `SOURCE_INSPECTED_NOT_REPLAYED`：固定版本源码中确实出现某个定义、定理或证明项；当前 run 没有检查它。
2. `MACHINE_REPLAYED_EXTERNAL_LIBRARY_WITH_SCOPE`：保存的命令实际检查了目标模块及其导入闭包，且 source/run/index 与外部版本身份闭合。
3. `MACHINE_PROVED_CURRENT_PROJECT`：当前项目自己固定了形式命题和证明源码，并由匹配 kernel 检查；不能因与外部定理相似就自动取得这一身份。

保存的 stdout/trace 必须列出实际检查闭包；源码树中的另一个模块不因共享依赖或同一仓库而成为该 run 的已重放目标。若要把“源码存在”提升为“本轮机器反证”，必须直接检查该模块或建立已机器证明的保真连接。

对外部库 proof replay，`source-manifest` 或同级机器证据还必须列出实际导入闭包中出现的显式 `postulate`/`primitive` 声明及扫描规则。对于 literate Agda，只计算 Agda code fence 内的声明；Markdown prose 中的同名词不能算公设。树级哈希只能固定语料身份，不能代替闭包、公设和命题范围。

## 4. HoTT 特定忠实性

凡结论依赖 HoTT 特有规则，proof package 必须固定所用系统，例如 bare/axiomatic HoTT、Cubical Agda、cubical type theory、agda-unimath、guarded/clocked/directed 扩展或其它明确变体。

- 若结论依赖 univalence、Path、transport、HIT、truncation、higher coherence 或具体 judgmental computation，必须在原生支持这些语义的系统中证明；
- 若使用普通 Lean/Coq/Agda 编码替代，必须另有机器证明的语法/语义翻译和保真定理，并把保真范围纳入同一索引；
- 一个有限 Bool 模型可以证明其自身命题，不能自动证明标准 HoTT 强制同一行为；
- proof assistant 正确拒绝非法 formation、非正性、宇宙循环或不可接受消去，是 `DEFENSE_WORKS` 证据，不能改写成理论悖论。

## 5. 持久资产职责

### 5.1 证明源码

权威根：`HoTT/formal/`。

新工作优先使用：

```text
HoTT/formal/<topic-or-claim-id>/
```

目录内保存形式化源码、项目/构建文件、必要说明和非可再现依赖的锁定身份。可再生 build cache 不进入证据源。

### 5.2 运行证据

权威根：`HoTT/verification/runs/<run-id>/`。run ID 发布后不复用、不覆盖；修订后的证明产生新 run。

每个作为交付依据的 run 至少包含：

| 文件 | 责任 |
|---|---|
| `RUN.json` | run ID、proof/claim IDs、工具/版本、命令、cwd、时间、退出状态、结论范围、证据状态 |
| `stdout.txt` | 原始标准输出；空输出也保留空文件并在 RUN 中说明 |
| `stderr.txt` | 原始标准错误；失败和 warning 不删除 |
| `environment.txt` | 可公开的 OS/arch/tool/dependency 信息；不保存 secret |
| `source-manifest.json` | 证明源码、配置和关键依赖的 path/bytes/SHA-256 |

可附加 `README.md`、kernel certificate、编译日志或容器收据。失败 run 若改变结论、揭示边界或是最终 Gate 的前置，必须保留；不重要的本地语法试错不强制永久保存。

### 5.3 当前索引

唯一快速索引：`HoTT/CLAIM_EVIDENCE_MATRIX.md`。每个交付结论必须可从一个 claim ID 到达：

```text
claim ID → 形式命题/自然语言对应 → proof ID → source path
         → run ID/path → tool+version → status → scope/non-goals
```

运行目录和索引都不替代源码；源码和 `exit 0` 也不替代索引中的精确命题/外推边界。

### 5.4 证明证据关系与重放登记

`HoTT/verification/PROOF_VERSION_CLOSURE.json` 使用 `hott-proof-version-closure/v2`。它不重新证明数学，负责验证
claim、proof、run、source 与 index 的关系没有被元数据改写或错接。每个登记包必须同时满足：

1. registry、`RUN.json`、`source-manifest.json`、`index-row-manifest.json` 的 proof ID 与 run ID 一致；
2. registry 的 claim 范围展开后，必须与 RUN、row manifest 的 claim 列表完全相同，不能少冻一行或多挂一条；
3. proof ID 与各 claim ID 在当前矩阵中各有且仅有一行，行哈希与 row manifest 一致；
4. registry 主源码必须出现在 source manifest 中，实际命令必须以登记工具链执行该源码；
5. 历史依赖缺口例外必须绑定**精确 proof ID + run ID + source-manifest/stdout 哈希 + 缺失源码哈希**；同一 proof 的新 run
   不继承旧例外；
6. 一个已存在 proof/claim 的新重放不改写主矩阵行。它先在 registry 的 `replay_runs` 建立
   `REPLAY_OF_EXISTING_CLAIMS` 关系，再由 `mark_proof_run_indexed.py` 标记 RUN，最后由
   `freeze_proof_index_rows.py` 冻结该重放看到的唯一 proof/claim 行。

因此，矩阵是 claim/proof 的当前快速索引，registry 负责主 run 与后续 replay 的多对一关系。单纯发现相同 proof/claim ID 行，
不足以把一个新 run 标成“已索引”。

## 6. 交付状态机

```text
DRAFT
  → QUESTION | CONJECTURE | HEURISTIC | PAPER_ONLY | SOURCE_REPORTED_NOT_REPLAYED
  → FORMAL_STATEMENT_FROZEN
  → PROOF_SOURCE_PERSISTED
  → KERNEL_RUN_PERSISTED
  → PACKAGE_OR_REPLAY_RELATION_REGISTERED
  → INDEXED
  → MACHINE_PROVED_LOCAL_UNCOMMITTED
  → MACHINE_PROVED_VERSION_CLOSED   (仅在获准 Git commit/tag 后)
```

失败或缺件时不能跳到后续状态：

| 缺件/失败 | 允许交付状态 |
|---|---|
| 尚无精确形式命题 | `QUESTION/HEURISTIC` |
| 有纸笔证明，无 kernel run | `PAPER_ONLY` |
| 只有外部/历史证明 | `SOURCE_REPORTED_NOT_REPLAYED` |
| 源码存在，工具不可用或运行失败 | `FORMAL_SOURCE_NOT_VERIFIED` 或 `PROOF_ATTEMPT_FAILED` |
| kernel exit 0，但 run 未保存/未索引 | `RUN_OBSERVED_NOT_DELIVERABLE_AS_CONCLUSION` |
| 全部本地 Gate 通过但未 Git 提交 | `MACHINE_PROVED_LOCAL_UNCOMMITTED` |
| 证明资产和索引进入可恢复 commit，并记录 exact commit/tag 与当前树核验 | `MACHINE_PROVED_VERSION_CLOSED` |

## 7. 交付前检查

每次准备交付数学结论前：

1. 列出最终答复和稳定研究文档中的全部数学结论；
2. 为每项查 `HoTT/CLAIM_EVIDENCE_MATRIX.md`；
3. 回读形式命题和 proof source；
4. 重放或核验本轮对应 run，而不是只信旧 PASS；
5. 核对 `RUN.json`、stdout/stderr、environment、source manifest 和哈希；
6. 运行 `verify_proof_version_closure.py`，核对 registry/RUN/manifests/matrix 的身份、唯一性、claim 集合和历史例外范围；
7. 若这是已有 claim 的新重放，确认 `replay_runs` 有该精确 run，主矩阵行仍指向原 primary run；
8. 核对 proof assistant 是否匹配命题语义；
9. 核对自然语言没有扩大形式命题的量词、理论变体或现实解释；
10. 确认失败/警告没有被删去；
11. 确认 authoritative 证据不依赖 `/tmp` 或其它 repo 外唯一副本；
12. 根据 Git 状态选择 local-uncommitted 或 version-closed 措辞。

任一项失败，删除“已证明/数学结论”等成立性措辞，降格并列出下一证明义务；不能通过减少假设说明或扩大 proof 的解释来求通过。

## 8. `/tmp` 与可恢复性边界

`/tmp` 可以用于：编译缓存、解压依赖、一次性中间文件和可从 repo 内源码重建的 scratch。它不得成为：

- 证明源码的唯一副本；
- 最终 stdout/stderr 或 kernel certificate 的唯一副本；
- 依赖身份、命令、版本、哈希或结论映射的唯一记录；
- 最终答复引用的权威证据路径。

在用户未授权 Git commit 时，资产仍须写入 repo 并标 `LOCAL_UNCOMMITTED_NOT_VERSION_CLOSED`。这满足本地留存，不等于跨机器持久化；未来获授权后应精确提交，不自动 push。

## 9. 历史兼容

本规则从当前用户裁定起约束未来交付，不批量改写历史对话或伪造过去不存在的 run package。已有 `PAPER_ONLY`、`FINITE_CHECKED`、`REVIEW_REQUIRED` 和 aggregate receipt 继续保留其历史证据等级。

未来若要把旧主张重新作为当前数学结论交付，必须按本规范创建新的 proof/run/index 链；旧报告中的 `exit 0` 可以作为定位线索，不能自动豁免当前门禁。

## 10. 验收

本治理能力的本轮验收仅包括：

- 根/`.codex` AGENTS、本地治理 Skill、业务 Skill 和 PROTOCOL 均含门禁；
- `HoTT/formal/`、`HoTT/verification/runs/` 和 `HoTT/CLAIM_EVIDENCE_MATRIX.md` 职责可达且一致；
- 静态 verifier 正向通过，并能拒绝缺 marker、`/tmp` 权威根和缺 run 必需文件合同；
- proof closure 回归能拒绝错接 run、缺失 claim 冻结行、重复 claim ID、RUN 身份/命令错配、旧依赖例外外溢，
  并验证新 replay 先登记关系再 mark/freeze；
- Feature/ruling/README/MEMORY/STATE 与本地 checkpoint 对齐。

这些检查证明规则和路由已实现，不证明每个未来 AI 都会遵守。fresh model behavior 仍需单独验收；任何未来数学结论本身仍需自己的机器证明包。
