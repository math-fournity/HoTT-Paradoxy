## 一、为什么这不是又一次“加强开局加载”

用户对认知闭包的原始要求是：闭包是与当前任务对应的活动认知工作集。决定当前判断的内容应直接进入上下文；
其余内容可以保存为带 owner、版本、定位和失效条件的索引，并在将要支撑材料判断时回源。任务持续多轮、跨压缩或
跨 Session 时，AI 要继续消费该工作集；用户修正、新证据、阶段变化和 owner 变化发生时，还要对闭包执行增、删、
改、查，并让更新后的认知立即支配当前后续工作和未来恢复。

本项目已经证明，旧框架没有充分达到这一目标。四件套的全文、hash、加载顺序、checkpoint 和大量结构测试都可以
通过，但 AI 仍在后续 turn 将用户的“构造过程”错误收窄成“构造耗时”。canonical trajectory 审计显示，出错 turn
没有重新读取决定性 core/essay 正文；结果是 L2 当前读取 FAIL、L4 认知执行 FAIL、L5 输出语义 FAIL。直接证据见：

- `audit/构造过程误读与认知消费审计-20260923.md`；
- `audit/四件套逐轮语义对齐治理修复-20260923.md`；
- `audit/governance-v4.0.0-four-set-evidence-20260913.md`。

旧全局框架确实具备开局 closure、最终 governance write-back、失效提示和 closed incident 防复活；缺失的是一个
显式、持续的 active/deferred 工作集、材料决策点复核、affected-slice 失效传播、工作中 CRUD，以及写回后重新
激活新 owner 的循环。因此本次升级修复的是全局生命周期，不是继续增加四件套默认体量。

## 二、3.24.0 的新合同

新标识为 `COGNITIVE_CLOSURE_CONTINUITY_V1`。逻辑闭包含五个部分：

1. **直接激活集**：即将支配判断的用户原意、current requirement、不变量、关键证据、冲突和未知；
2. **索引延迟集**：当前不必全文驻留，但拥有 owner、version、locator、freshness 和触发条件的认知；
3. **持久权威集**：Feature、rulings、current design、MEMORY、代码、测试、运行证据和 Git 等唯一 owner；
4. **非活动历史集**：closed、superseded、historical、draft 内容，默认不能仅因显眼或近期而取得任务资格；
5. **依赖与失效条件**：哪些用户修正、阶段、owner、版本、证据或运行现场变化会使计划和结论 stale。

执行循环是：

```text
建立/恢复
  -> 激活直接集并登记延迟索引
  -> 在材料决策点消费
  -> 修正/证据/阶段变化使 affected slice stale
  -> 增量回源并执行增删改查
  -> 持久变化写回唯一 owner
  -> 重新激活新 owner
  -> 继续、完成或形成跨 Session 恢复点
```

“材料决策点”包括选择任务或方案、定义规格、选择工具和证据、形成强结论、分析转实现、实现转验证、停止、完成和
final；它不要求每次机械读文件都重读全仓。这里的“删”首先是从 active set 退休，历史通常仍由 closed/
superseded/replacement/Git 保存；它不扩大物理删除授权。

两个原有核心 Skill 保留：`repo-cognitive-closure` 负责全过程建立、激活、消费、失效和重建；
`repo-cognition-governance` 负责持久认知的新增、修正、退休、索引和写回。没有新增第三 Skill、语义 Hook、
数据库、常驻 Agent 或每 Session 强制闭包文件。

## 五、对本 HoTT 项目未来 Session 的约束

项目级 `CORE_SEMANTIC_REALIGNMENT_V1` 和四件套全文要求继续有效，它们比全局默认更强；3.24.0 不削弱或替代它们。
未来 AI 在本项目中不能把“启动时读过四件套”当作本轮所有后续判断的永久通行证。至少在下列节点必须重新核对
相关 core/essay 原文或 current owner，并让依赖旧解释的计划、结论和 successor stale：

- 用户纠正核心概念或指出此前理解错误；
- 从审计转方案、方案转实现、实现转验证；
- 选择下一 wave、宣告停止、完成或失败；
- 数学对象、现实任务、观察量、允许操作或完成标准发生变化；
- 四件套、STATE、stable record、证明源码、run receipt、外部版本或 Git owner 变化；
- 压缩恢复或跨 Session 接手。

索引可以降低上下文体量，但一旦索引所指内容将支撑材料主张，就必须回读 current owner。写回治理文件后，当前 AI
还必须重新激活新 owner，不能继续沿写回前的旧复述工作。本项目当前数学 STATE、研究队列和证明结论没有因本次
全局治理升级而改变；本文件只提供持久审计入口。
