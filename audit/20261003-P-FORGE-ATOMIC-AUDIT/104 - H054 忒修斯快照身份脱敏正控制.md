## 2. `AS_RUN`：从快照塌缩到身份任务的合成线索

运行输入固定两个完成的trace：一条从初始工件逐件替换，另一条用已移除的原件重组；它们可以在端点有同一当前部件子集。公开输出将模式线索准确限为：若一个身份／连续性判断只接收当前subset、却被要求回答历史敏感问题，`subset equality`会抹掉lineage而不是回答该身份问题。

```text
Target-Q (overall theory target) = ZFC/Power Set仍为Q-0；本节点不提供实际理论任务
Candidate-Q (as run)             = NONE
Control-Q (as run)               = 合成 Trace → Snapshot → identity/continuity-observer 线索
Q state before/after             = Q-0 UNFORMED / Q-0 UNFORMED
as-run Q delta                   = Q_STATUS_UNINFERABLE_FROM_EVIDENCE for theory-Q
```

它的 `MODEL_RECALL_SITE_CANDIDATE` 只意味着模型在脱敏题面中提出了一个**待来源验证的 synthetic site**。输出同时列出三刀的暂定容纳：P1保住工件和替换任务却丢掉“连续还是重组”的区分；P2保住当前成员与端点可比性却丢掉provenance、顺序和trace；P3保住阶段却没有把continuous lineage列为完成条件。它自己在D4把来源、实际理论、定理、新刀、UR和现实状态都标为`UNKNOWN`。

该卡的同一任务反控制与 falsifier 已在公开输出中给出：若有来源或控制显示下游身份任务被定义为只依赖当前部件成员、从不依赖替换或重组历史，则这个terminal line应被推翻。H054当时尚未执行这个反控制，因此不能把单独一次正输出写成完整的P校准。

## 3. 当前 P-FORGE 合同下的反事实

按当前三刀和Tool-Birth合同，H054是`Control-Q`，不是理论`Candidate-Q`。它若要成为合格的`Q_CAPABILITY_CALIBRATION`的一半，至少还需要：

```text
positive control  = H054 snapshot-only输出
negative control  = H055：状态携带immutable ordered lineage后，身份consumer可区分
same-task source  = H056或更强的一手来源，实际定义u/F/C/I/O/Done
arbiter           = H057，对旧刀是否无扭曲容纳作sealed-pack裁决
```

在这张卡单独重放时，当前合同会给出：

```text
P1 = 无实际理论的u/F/C；不得把snapshot equality冒充identity consumer
P2 = 有合成的many-to-one representation clue；无source-required same-object reentry
P3 = 有两个完成trace；无source-defined admission/identity Done
Candidate-Q = NONE
Tool-Birth verdict = NOT_ENOUGH_EVIDENCE
```

因此它不会把ZFC从`Q-0 UNFORMED`推进到`Q-1`，也不授权把“历史信息丢失”泛化成集合论表达能力或圆环路线。它的当前作用是把以后来源卡应回答的接口写清楚：`(currentSnapshot, immutableOrderedLineage) → identityConsumer`；该接口本身仍是条件性草图。
