# H018 HoTT任务忠实性边界

> **AtomicAuditCard：** `H018 / H_NUMBERED_NODE / R03_MASTER_TASK_FIDELITY / ATOMIC_AUDIT_COMPLETE_WITH_SCOPE`。

H018不是新的模型运行，而是Master对三层身份的分离：形式过程`U/judgeU/Q/Halts/never`；source明示的“目录C的相同到第k+1层是否落定”及first `now k` Done；以及用户对“确认两个东西是不是同一个、相同到哪层才了结”作为UR A向任务的研究判断。

结论是 `USER_JUDGED_A_DIRECTION_WITH_SCOPE`：用户认定的A向任务与形式h-level询问过程有可逐项检查对应，但这不是对所有现实任务的数学定理，也不是kernel证明。H017已说明B向admission/operator cycle未建立。

```text
Target-Q = HoTT A向过程与用户任务的任务忠实性
Candidate-Q = H015 U-process completion question
Control-Q = source task/Done、用户UR判断、H016/H017 negative controls
delta = Q_NARROW_WITH_SCOPE
```

**当前合同：** `P1 source/process/completion PASS_WITH_SCOPE + P2/P3 negative differential + USER_JUDGED_A_DIRECTION_WITH_SCOPE`。这完成旧HoTT calibration lock的限定目的，允许后续ZFC discovery/calibration，却不允许`ZFC_Q_LOCATED`、ZFC UR、HoTT不一致或B向结论。

**falsifier/财富：** source task若与H015对象/Done不相合，或用户撤回/修正UR任务判断，重开H018；真实现实对应仍需要独立证据。H018仅保存任务身份边界。

**本卡最终判词：** `ALIGNED_WITH_SCOPE / Q_NARROW_WITH_SCOPE / USER_JUDGED_A_DIRECTION_WITH_SCOPE / B_DIRECTION_NOT_ESTABLISHED`。
