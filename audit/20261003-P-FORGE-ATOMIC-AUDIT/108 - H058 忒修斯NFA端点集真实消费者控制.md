## 2. `AS_RUN`：实际C/I/O/Done显示端点抽象对该任务足够

H058可以填入完整的source-local任务卡：

```text
I       = initial state set S 与 input word x
operation = stepSet的fold，即 evalFrom S x
representation = Set σ of possible ending states
C       = acceptsFrom S 的语言membership consumer
Done    = 存在 s ∈ accept 且 s ∈ evalFrom S x
```

`Path`并没有消失：source单独定义它，并证明endpoint membership等价于存在某条path。可是`C`不问“两条path是否同一持续对象”，只问至少一个接受端点是否存在。因此由不同路径到同一端点所造成的provenance不区分，并未改变同一任务的Done。

```text
Target-Q (overall theory target) = ZFC/Power Set仍为Q-0
Candidate-Q (as run)             = NONE
Control-Q (as run)               = 真实path→endpoint-set压缩是否已违反consumer的完成条件
Q state before/after             = Q-0 UNFORMED / Q-0 UNFORMED
as-run Q delta                   = Q_NARROW_WITHOUT_CANDIDATE_Q
```

这一`Q_NARROW`有界排除了一个过宽候选族：“只要具体过程被集合端点表示压缩，就必有历史身份张力”。它不声称所有集合表示或所有自动机相关任务都不涉及history。

## 3. 当前 P-FORGE 合同下的反事实

现行合同将H058保留为罕见的完整source-local control：P1有真实consumer和Done；P2有`Path → endpoint membership`存在性bridge；P3有逐输入符号的state transition与接受完成条件。三者没有会合为theory-Q，因为它们在同一任务中都被直接支付。

```text
P1 = actual C/I/O/Done present; obligation is existential acceptance
P2 = source-backed witness/existence bridge; not a diachronic identity reentry
P3 = transition + Done present; no pending identity admission
identity-Q = absent from the source task
Candidate-Q = NONE
```

这张卡因此防止把“存在Path”误写成“consumer必须保留每条Path的身份”。若要在同样明确的source层重新提出Trace–Snapshot–Identity候选，必须额外有一个consumer把continuation/reconstruction的差异纳入它自己的acceptance／Done，且它只可见snapshot或被禁止使用lineage。
