## 2. `AS_RUN`：公式、当前义务与支付路线分别固定

H028的公开结果首先确认：Power Set formation本身不交付 choice function；但这一点不足以说明 `Q(A)` 是当前未支付需求。回到 source 后，Master 固定如下三分：

| 读法 | `L5b` 当前活跃性 | `L7` 正义务 | `L7b` 可见支付 | 有效处置 |
|---|---|---|---|---|
| 实际 Isabelle/ZF source | `AC0`只是定义 | 不适用，因为没有当前任务要求 `Q(A)` | conditional theorem 还缺 `R`与well-order证明 | `FORMULA_ONLY_NOT_ACTIVE_DEMAND` / `CONDITIONAL_PAYMENT_NOT_ACTIVE` |
| 反事实 `ZF + asserted AC0` | 活跃 | `∀A.Q(A)`有正存在式形状 | asserted AC0直接给出`Q(A)` | `SOURCE_PACKET_DIRECT_PAYMENT` |
| 反事实给定`R, well_ord(A,R)` | theorem route活跃 | theorem conclusion是正存在式 | 已给前提使`ex_choice_fun_Pow`直接给出`Q(A)` | `SOURCE_PACKET_DIRECT_PAYMENT` |

同时，实际片段的 `ΠX∈u.X` 只是定义／定理式中的集合表达式，并不提供 object-level、semantic actual-use或runtime 的 `C/I/O/Done`。因此：

```text
Target-Q (as run)    = Power Set参与choice-function存在式时，是否有当前同层、未支付的正义务
Candidate-Q (as run) = NONE; actual source is formula-only and lacks L2b consumer contract
Control-Q (as run)   = asserted-AC0 and supplied-well-order counterfactual direct-payment routes
Q-state delta        = Q_SAFETY_REPAIR; actual ZFC status remains Q-0 UNFORMED
```

## 3. 当前 P-FORGE 合同下的反事实

H028发现旧 P1 没有把“公式出现”“当前 active demand”和“冻结 source packet已经支付”拆成独立门。它因此新增／明确了：

1. `L5b`：定义名不自动成为当前 Q；
2. `L7b`：在 L7 之后扫描 formation、定义、公理／假定、已给定理前提和 supplied witness 的最短支付路线。

这不是第四把刀，也没有将 `AC0`写为构造过程。当前合同会把 H028严格分类为：

```text
actual card      = SOURCE_CONSUMER_GAP + FORMULA_ONLY_NOT_ACTIVE_DEMAND
asserted AC0 CF  = SOURCE_PACKET_DIRECT_PAYMENT
given well-order = SOURCE_PACKET_DIRECT_PAYMENT
P2/P3            = NOT_ADMISSIBLE_ON_NO_SURVIVING_Q
```

worker公开 MatchTrace把正义务和支付的 gate 标签对调，故其未校正标签本身只能是 `MATCHTRACE_GATE_LABEL_DRIFT`；本卡只采用 Master 回到冻结 source 后作出的五门规范化判词。
