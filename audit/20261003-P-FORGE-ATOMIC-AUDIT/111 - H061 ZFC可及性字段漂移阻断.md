## 2. `AS_RUN`：来源读法有用，TaskCard映射不可接受

公开输出给出的来源读法是有限且合理的：

```text
r⁻¹[{a}] ∈ Pow(R)  ↔  r⁻¹[{a}] ⊆ R
                  ↔  a 的每个前驱在 R
```

它还把该条件读为正向、受单调性guard约束的归纳前提，并正确说没有source-defined `Draft/Admitted/OperatorUse` lifecycle。问题发生在E3：它把`T`改写为premise metavariable `t`、把`C`改写为approximation `R`、把`I/O`重新分配。于是它不再是NodeCard冻结的同一`T/u/F/C/I/O/Done`，不能作为H060正向家族的可接受P2/P3 MatchTrace。

```text
Target-Q (overall theory target) = ZFC/Power Set仍为Q-0
Candidate-Q (as run)             = NONE
Control-Q (as run)               = guard-satisfying `Pow(R)` reentry是否产生同卡剩余义务
Q state before/after             = Q-0 UNFORMED / Q-0 UNFORMED
as-run Q verdict                 = Q_STATUS_UNINFERABLE_FROM_EVIDENCE
```

这里的`UNINFERABLE`不等于来源无信息；它只说这个输出因字段身份漂移不能承担关于冻结卡的Q判词。

## 3. 当前 P-FORGE 合同下的反事实

按当前合同，H061应当先被冻结字段，再填P2/P3：

```text
T/u/F/C/I/O/Done = NodeCard的既定值，不能由mapper重新选择
P2               = 只能判定 `t∈Pow(R)` 是正向subset bridge，若同卡字段完整
P3               = source未给lifecycle，不能从induction hypothesis改写为运行状态
Candidate-Q      = NONE until a field-faithful source map exists
```

因此当前反事实判词为`Q_SAFETY_REPAIR`：修复的是H060／H061之间的同卡继承，不是再造一个新门或以错误字段得出“no defect”。H062的历史回归会在下一原子卡独立审计；本卡不得用H062后来结果反写H061当时已经正确。
