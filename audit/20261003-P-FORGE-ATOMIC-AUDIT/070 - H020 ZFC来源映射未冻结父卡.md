# H020 ZFC来源映射未冻结父卡

> **AtomicAuditCard：** `H020 / H_NUMBERED_NODE / R04_P1_SOURCE_VALIDATION_DEVIATION / ATOMIC_AUDIT_COMPLETE_WITH_SCOPE`。

H020的意图是让一个版本固定的 Mathlib `ZFSet` source card 接住 H019 的 all-subobjects 站位，检查 `powerset → funs` 是否出现非平凡、同层的正义务。它实际暴露的首先不是 ZFC 的性质，而是一次接力协议的缺口：NodeCard文字提到 H019，冻结 prompt 却没有把父卡的 `T/u/F/Q?` 逐字段带入，因而 worker 可以合法地换成泛化的 `f`。这使本次运行不能验证 H019，也不能构成对旧 `powerset → funs` 读法的反证。

## 2. `AS_RUN`：一次不能回接 H019 的来源映射

当时的 prompt 允许 mapper 仅以四行 Mathlib 摘录重新挑选 P1 subject。公开报告记录它选择了泛化 `f`，而不是把 H019 的 all-subobjects formation 作为不可变父字段。因此运行虽完整终态，却没有回答它被赋予的父问题。

```text
Target-Q (as run)    = H019 all-subobjects formation site 是否在 Mathlib model card 中获得同层 consumer 的非直接正义务
Candidate-Q (as run) = UNFROZEN / worker reselected generic f
Control-Q (as run)   = NodeCard parent label 与 prompt 内缺失的 T/u/F/Q? relay
Q-state delta        = Q_STATUS_UNINFERABLE_FROM_EVIDENCE for H019; no ZFC Q status may change
```

报告保留的有限负信息是：这四行 bare excerpt 没有自明的正义务。但它不能被夸大为“幂集不产生 Q”，因为它没有保住同一对象、同一 formation、同一候选任务。其实际 P/Q 增量是发现了 `EXECUTION_SPEC_INCOMPLETE`：来源 P1 validation 不得重选父字段。

## 3. 当前 P-FORGE 合同下的反事实

今天的 P-DAG 合同要求 source validation 在启动前冻结 `T/u/F/C/Q/I/O/Done`，validator 只能补充、收窄或拒绝，而不能重选。H020若按现行合同提交，将在采样前以：

```text
INPUT_CONTRACT_FAILURE / NO_AGENT_OUTPUT
reason = parent T/u/F/Q? missing from frozen packet
```

结束。这不是把后来 H022的正确判词倒灌给 H020；恰恰相反，H020的运行事实解释了为什么 H021要先形成独立 source card，H022才可以验证一个固定 parent。当前的 QConvergenceLink 是 `Q_SAFETY_REPAIR`：它防止一个不保持同一任务的模型输出被误记为 Q 的发现、收窄或拒绝。
