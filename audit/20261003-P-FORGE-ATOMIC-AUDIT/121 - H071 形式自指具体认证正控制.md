> **AtomicAuditCard：** `H071 / H_NUMBERED_NODE / R10_DIAGONAL_INTERNAL_CERTIFICATION_POSITIVE_CONTROL / ATOMIC_AUDIT_COMPLETE_WITH_SCOPE`。

## 2. `AS_RUN`：发现线索，而不是已存在的理论Q

H071输出固定：

```text
u       = g
process = 内部contradiction-certification task，使用Proof/quotation/substitution/diagonalization
S1      = g、其code(g)/Proof引用、认证任务的native junction
Q?      = UNKNOWN
```

它还保留关键对照：不能在无来源支持时把fixed contradiction code `c⊥`等同于`code(g)`，也不能把内部认证变成external proof-search runtime。这个约束确保“具体自指”没有被偷换成已发生的矛盾或无限运行。

```text
Target-Q (overall theory target) = ZFC/Power Set仍为Q-0
Candidate-Q (theory)             = NONE
Control-Q                         = concrete g + native internal certification task能否产生discovery seed
Q state before/after             = Q-0 UNFORMED / Q-0 UNFORMED
as-run Q delta                   = Q_CAPABILITY_CALIBRATION_WITH_SCOPE
```

`S1`是 deidentified profile内的模型识别线索，不能通过名称相似性当作某个现实formal system中的真实consumer或Q-1。

## 3. 当前 P-FORGE 合同下的反事实

当前合同会把H071视为合格的正控制：它验证P1可要求具体subject和native task，且不会把它们的存在冒充完成。要升级为理论card，仍需固定source的calculus、实际`g`或对应对象、task wording、C/I/O/Done，并分别检查：

```text
P2 = source-backed code/formula/quotation bridge and same-object reentry, if any
P3 = source-backed construction/admission semantics, if any
Q  = active and not directly paid in that same source task
```

H072被设为source-layer控制；它不能反向使H071的synthetic certification task成为source fact。
