# H041 ZFC平衡画像终端语义假阴性

> **AtomicAuditCard：** `H041 / H_NUMBERED_NODE / R05_BALANCED_D_L10_TERMINAL_TOKEN_FALSE_NEGATIVE / ATOMIC_AUDIT_COMPLETE_WITH_SCOPE`。

H041以 H040 同一平衡 D‑L10画像重试，唯一意图是让模型写出精确无候选终端行。模型确实输出 `NO_MODEL_RECALL_CANDIDATE / DIRECT_PAYMENT_ONLY`，却没有另写标签 `D2`；旧 runner将其判为“D2 缺失”。这是一种输出 schema 假阴性：精确 terminal verdict本身已经承担 D2语义，但当时的机械检查还不能识别它。它不是理论、模型或 P1筛选失败。

## 2. `AS_RUN`：终端语义存在，旧 schema 没有接住它

H041和 H040一样只覆盖该平衡 profile、最多三个筛选站位和 D-L10。其公开终端说明没有 candidate 幸存，但旧runner的段落匹配协议要求额外的字符串标记。

```text
Target-Q (as run)    = 平衡画像内是否有通过 D-L5--D-L10 的 candidate
Candidate-Q (as run) = NONE within the stated profile/screening bound
Control-Q (as run)   = exact terminal verdict versus old explicit-D2 output schema
Q-state delta        = Q_SAFETY_REPAIR; acceptance remains old-oracle failed
```

这不支持“整个 ZFC 无候选”，只支持一件操作性事实：当时 oracle 对同一终端语义产生了假阴性。

## 3. 当前 P-FORGE 合同下的反事实

H041触发 runner修订：独立、精确的 terminal verdict可以承担 D2 的语义，但仍要求 D0/D1/D3--D5、唯一终态、字数与零工具。这一修订不会倒灌成 H041当时的 PASS；它给 H042一个固定的 fresh rerun 合同。

```text
CURRENT_CONTRACT = TERMINAL_EQUIVALENT_D2_ELIGIBLE
historical status = OLD_OUTPUT_ORACLE_FALSE_NEGATIVE
Candidate-Q       = NONE
```

若H041终端实际上缺少精确无候选文字，或D0/D1/D3--D5不完整，重开其终端语义判断。若修订后的 runner改变了其它输入／分析语义，H042不能作为纯oracle回归。
