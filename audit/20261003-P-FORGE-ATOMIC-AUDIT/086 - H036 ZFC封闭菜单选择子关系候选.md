## 2. `AS_RUN`：条件性菜单候选，但父 Q 不是 profile-native task

H036的正确范围是“在这四项冻结菜单中，模型倾向于 selector relation”。它当时尚无 D-L10，故可输出一个 prospective judgement。其可见输入只说该理论对一个 set-indexed nonempty family **asserts one joint selector relation**，没有声明接收任意 supplied `r`、计算其逐项选择性质、返回判断或记录 Done 的 operation。

```text
Target-Q (as run)    = closed-menu中除已暂扣全子对象路线外的条件性第二显眼承诺
Candidate-Q (as run) = supplied-r selector judgment, conditional on the menu
Control-Q (as run)   = H037 frozen source validation of the same parent question
Q-state delta        = Q_GENERATE_WITH_SOURCE_GAP; not a theory-Q finding
```

这不是“Choice 有问题”的结论。它是 `CONDITIONAL_MENU_MODEL_RECALL_CANDIDATE`：在规定菜单中出现的模型候选，须由同一 parent source验证，且不能重选为“某个 f 存在”。

## 3. 当前 P-FORGE 合同下的反事实

H036促成 `D-L10 / declared-operation anchor`：候选 Q 所用的 judgment、operation或consumer必须由 profile明确声明；仅有 `∃r`／`∃f` 或 formation output 时，模型不得发明 `judge(r)`、validator或recording service。按当前合同，H036原始 parent会在 discovery层被拒绝：

```text
CURRENT_CONTRACT = DISCOVERY_UNDECLARED_OPERATION
Candidate-Q       = NONE
QConvergenceLink = Q_SAFETY_REPAIR
```

这不是把 H037后来得到的 source consumer gap倒灌到 H036；它说明为何当时的 discovery候选不满足更精确的“理论自己的任务”要求。
