## 1. 为什么这条证明属于 Q2

Q2的目标是检验一个真实ZFC／模型验收是否遗漏HoTT Q的过程完成观察。仅凭`QuestioningDelay`的`never`还不足以描述“遗漏”具体意味着什么。本包提供一个严格、最小的形式控制：同一个固定Q在原universe与集合截断上的完成结果不同，而将截断对象统一恢复回原universe的section不存在。

它由此证明：**若某个未来验收器的观察与这一类粗化相同，‘它让Q停止’不能单独被读为‘它已保留原Q的对象与完成任务’。**

这条蕴含是条件性的模板。它没有声明任何实际ZFC模型或论文验收器确实使用该粗化；那仍是`SOURCE_ACCEPTANCE_CONTRACT_SEARCH`的任务。

## 2. 机器命题与范围

`ObservationCompletionBridge.agda`在原生Cubical Agda中证明：

```agda
coarseCompletionCreatesNoRestoration :
  (question (Type ℓ-zero) judgeU ≡ never)
  × (runFor 0 (question TU judgeTU) ≡ just 1)
  × (¬ (Σ[ g ∈ (TU → Type ℓ-zero) ]
          ((A : Type ℓ-zero) → g ∣ A ∣₂ ≡ A)))
```

其中：

- 第一项来自固定universe的逐层h-level Q；
- 第二项来自该universe集合截断`TU`上的相同询问；
- 第三项是不存在统一section的no-recovery条件。

主run使用macOS Agda 2.8.0 + cubical 0.9、`--safe --cubical --guardedness`，退出码0、stderr为空。运行收据、source manifest、全局proof行和claim行已被冻结；`verify_formal_proof_run.py`对源码、依赖、外部工具链、索引和行哈希返回`PASS_WITH_SCOPE`，以同一精确命令重跑则返回`EXACT_EXIT_STDOUT_STDERR_MATCH`。捕获时的`RUN.json`正确记录其尚未进入提交；在本报告与资产进入提交`b0b1926f`后，`verify_proof_version_closure.py --proof-id MP-ZFC-HOTT-OBSERVATION-BRIDGE-001`返回`SELECTED_PACKAGES_VERSION_CLOSED / HEAD_BYTES_CHECKED`。

## 4. Q2 的证据边界

`C-357`支持下列形式事实：

```text
original Q completion      = never
coarsened Q completion     = stage-one success
uniform recovery of source = unavailable
```

它不支持下列外推：

- 集合截断错误；
- 对截断提问与对原universe提问必定是同一现实任务；
- ZFC、Kapulkin–Lumsdaine模型或任何模型验收器使用了集合截断作为其观察；
- ZFC的时间观察力已被证明不完备；
- HoTT不一致、UR现实判断已经被内核认证。

所以C-357是Q2的**形式桥控制**，不是Q2的最终证据。实际`AcceptanceContract`仍需来源定义`C_meta/I/O/Done_meta/AdequacyLift/ObservationFamily/Payment`。
