## 1. 要回答的不是一个问题，而是三个问题

用户所说的圆环挑战可分为三层，不能由“社区知道／不知道”一句话合并：

| 问题 | 本次判词 | 含义 |
|---|---|---|
| 社区是否知道去点、端点固定、闭合与补空间会改变所能做的事？ | `SOURCE_SUPPORTED_YES` | Book 与公开讨论有直接材料。 |
| 社区是否知道普通 HoTT 的同伦型语言不能自动承担点集拓扑、补空间、环境同痕或连续复原任务？ | `SOURCE_SUPPORTED_YES` | Book、2018 HoTT mailing-list 讨论与 cohesive HoTT 文献均明确区分。 |
| 社区是否已经提出并解决用户的精确命题：`H_top/U` 被当作同一 `X` 的来源—过程强完成 `Done_strong`，从而构成“圆环悖论”？ | `NOT_ESTABLISHED` | 本次固定来源没有这个完整合同、也没有这一名称或这一结论。未命中不能外推为全网或全体社区没有讨论。 |

这里的第三层才对应 ABX 的真正目标。前两层的“知道”本身不产生一个实际消费者 `K`。

## 2. HoTT Book：它明确划出的边界

本地固定的 Book 源码为 `sources/webgpt/workspace-snapshot/HoTT/theory-schema/upstream/book-578b85cc/`；官方入口为 [The HoTT Book](https://homotopytypetheory.org/book/)。该书页面说明这是第一版的持续小修订本，故本报告不把网页上的任意后续 PDF 版本混同为本项目已经审计的 `578b85cc` 快照。

### 2.1 普通 HoTT 的“空间”不是点集拓扑空间

Book 引言在固定快照 `introduction.tex:69–91` 说明，类型被当作同伦意义的空间／高阶群胚，并明确说这些空间是“purely homotopically, not topologically”。紧接着它列举：类型内部没有“open subset”或序列“convergence”的概念。

这不是对圆环挑战的回避性回答，而是理论范围的正面声明：

1. 点集开子集、去点补空间、端点极限、度量连续性和由平面实现的闭合过程，不会仅因一个普通 HoTT 类型被称作“space”而自动存在；
2. 因此，不能从 Book 的 `S¹`、类型等价或 univalence 直接读出“现实中的圆去点再复原已完成”；
3. 如果 ABX 要谈这些条件，就必须如当前方案那样把它们写进额外的 `OriginPresentation`、`R_origin`、`Observation` 和 `Done_strong`，或改到具有相应结构的理论扩张中。

### 2.2 Book 知道端点和允许操作会改变结论

Book §1.12 的固定文本（`preliminaries.tex:1721–1728`）使用一个**去点圆盘**中的环路作拓扑直觉：在两个端点都固定时，环不能在去点圆盘内缩成常值；允许一个端点变化时，环可以缩回。

这与用户的“去点圆再复原”不是同一命题：对象是去点圆盘中的环路，讨论的是路径同伦，既没有 `S¹\setminus\{p\}` 到开区间的同胚，也没有来源历史、两端闭合或 `Done_strong`。但它是强的相邻证据：Book 作者清楚区分**固定的边界条件／允许操作**与较弱的变形结论。它不能被读成“同伦变形总是任何意义的复原”。

### 2.3 Book 的 `S¹` 是 HIT，而非已经带点集复原结构的物理圆

Book 第 6 章把 `S¹` 给成一个高阶归纳类型，生成元是 `base : S¹` 与 `loop : base = base`；其消去原则从“目标类型中的一点和闭路”得到函数。官方 PDF 的 Chapter 6 同样可核对这一构造。[官方 Book PDF 的圈构造段](https://hott.github.io/book/hott-online.pdf.html)

因此，Book 中的 `S¹` 有一个指定点和一个路径生成元，却不等于 ABX 的 `RealCircle/east/StrongPuncture/OpenRealInterval` 点集模型。把两者直接等同，恰恰会越过 Book 已经划出的理论层级。

## 3. 公开 HoTT 讨论：补空间和环境同痕问题被明确提出过

2018 年 HoTT Google Group 的讨论 [“What is knot in HOTT?”](https://groups.google.com/g/HomotopyTypeTheory/c/OxOXaZ46aPg/m/sno0YO-9BAAJ) 很接近本次问题的结构。提问者把普通 HoTT 的同伦论层面，与定义 ambient isotopy 所需的实数和区间对象区分开，并追问“如何取得一个空间的 complement”。Michael Shulman 的回复不是否认问题，而是把它路由到 cohesive HoTT：先在拓扑层定义结与管状邻域／补空间，再用 shape functor 取得同伦数据。

这支持三个有限结论：

1. 至少该公开讨论中的参与者清楚知道“同伦”与“拓扑补空间／环境同痕”不是同一个层次；
2. 他们没有把普通 HoTT 的 circle 或 path 自动当作满足点集拓扑任务；
3. 他们把需要保留的几何信息放到 cohesive/topological 层，再通过显式 shape 过程连接到同伦层。

这段讨论不是全体社区投票，也没有讨论用户提出的“圆去一点—开区间—端点闭合复原”故事。因此它不能支持“所有 HoTT 使用者都知道圆环悖论”的社会学断言；它能否定的是“该类边界从未被社区意识到”的强说法。

作为解释性旁证，Mike Shulman 在 [MathOverflow 的 circle 问答](https://mathoverflow.net/questions/169097/a-pointless-circle-in-hott) 中再次区分 HoTT 的同伦型 circle 与点集闭曲线，并解释普通 HoTT 的 type 不应直接按“某个平面中的闭曲线”理解。该问答不代替 Book 或正式文献，但说明这一解释框架已经进入公开教学讨论。

## 4. Cohesive HoTT：这不是未被看到的意外，而是专门分层的研究主题

相关文献的重点尤其重要。

- Michael Shulman 的 [*Brouwer's fixed-point theorem in real-cohesive homotopy type theory*](https://arxiv.org/abs/1509.07584) 明确说 cohesive 类型可以具有独立的拓扑与同伦结构，并把从拓扑到同伦的过程称为 shape／fundamental `∞`-groupoid。
- Urs Schreiber 与 Michael Shulman 的 [*Quantum Gauge Field Theory in Cohesive Homotopy Type Theory*](https://arxiv.org/abs/1408.0054) 给出一个与本题非常接近的对照：几何圆具有点集及拓扑／光滑结构，而它呈现的同伦型 `Π(S¹)` 或 `Bℤ` 在同伦意义上可只有一个点和非平凡自同构。文中强调两种结构是独立的。

这并不等于“他们已经解决了你的圆环判词”。但它意味着：把一个带几何／连续／补空间信息的对象映到其同伦型时，可能遗忘什么，正是 cohesive HoTT 公开建模的主题。该文献不是把信息差当作普通 HoTT 的内部矛盾；它把差异写成有名称、有额外规则、有明确方向的层间结构。

从 ABX 的语言说，cohesive 文献提供的是 `U` 需要被**显式命名和限定**的强正面先例；它没有提供“某个 `K` 已经把 `U(P)` 错当成 `Done_strong(P)`”的证据。

## 5. 对“社区是否知道圆环悖论”的精确回答

可以给出如下分层回答：

1. **知道相邻数学与理论边界：是。** 去点空间、固定端点、可否改变端点、补空间、ambient isotopy，以及普通 HoTT 与拓扑／cohesive HoTT 的分界，都有 Book、公开讨论和文献锚点。
2. **知道“抽象会失去来源／过程语义”：在结构意义上，是。** Cohesive HoTT 的 shape 与几何对象的分层正是对此类区别的明示处理。
3. **知道并承认用户定义的圆环悖论已击中 HoTT：没有证据。** 本次没有发现他们把 `M`、`N` 的通常同胚或类型等价当作指定来源、端点闭合和过程复原的完整完成；更没有发现他们把这种做法称作自相矛盾或“HoTT 已被击落”。
4. **能否以“社区没意识到”作为第三弹的支点：不能。** 在已审来源中，这一方向被反例化为至少部分错误。第三弹若要继续，必须转为寻找一个具体外部 `K`：某个库、论文实现或应用真正做出了从弱同伦／拓扑信息到强过程完成的未经授权提升。

因此，本次调查改变的是 ABX 的**解释性定位**，不改变它的核心 Gate：`H_top → R_origin → U → K → Observation/Done` 仍须由同一实际调用链闭合。Book 或 cohesive 理论知道有层间差异，既不构成 K，也不自动让 ABX 失败。

## 6. 检索边界、负结果与后续

本次公开检索使用了以下有判别力的检索轴：`punctured circle + HoTT`、`circle minus a point + HoTT`、`S¹ + complement + HoTT`、`one-point compactification + HoTT`、`stereographic projection + HoTT`、以及 HoTT Google Group 的 `circle`／`complement`／`cohesive` 相关可发现页面。它找到的是上述 Book、Google Group、MathOverflow 和 cohesive HoTT 文献。

在这组来源和检索词内，没有命中“`R_origin`／provenance／`Done_strong`／圆去点后端点闭合复原”作为已命名 HoTT 悖论。该结果只能写作：`NO_EXACT_ABX_FORMULATION_FOUND_WITHIN_DECLARED_SOURCES_AND_QUERIES`。它不是全网、全论文、全代码库或整个社区的负结论。

下一项有价值的工作不是重复这次书目检索，也不是把“社区知道边界”改写成“社区已解决所有现实对应问题”。若 ABX 继续，应选择一个版本冻结的 cohesive HoTT 实现、拓扑化 HoTT 库或明确声称几何复原的下游应用，检查它是否实际构成 `K`。若找不到这样的候选输入，当前 ABX 停止条件继续有效。
