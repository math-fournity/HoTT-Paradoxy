## 一、工作单元

本工作单元实现 `R2-SEMIHALT-001`。此前 R2 已具备有限程序自然数码、`ProgramCode × Config × fuel` 的公平有限调度，以及保持原 `haltsWithin` 的 scheduled observation。本轮把这些基础连接成两种可执行对象：

1. 面向固定 program/input 的 stage-indexed partial answer `semiHaltAt`；
2. 面向全部 program/input/fuel case 的公平正见证流 `enumerateHalting`。

两者都只在有限计算已经提供正见证时输出 `just`。某个有限 stage 的 `nothing` 只是一项有界观察结果，不承担无界否定语义。

## 二、构造与证明义务

源码：`HoTT/formal/cubical-machine-halting/SemiHalting.agda`。

### 固定查询的分阶段过程

`semiHaltAt stage p c` 直接执行 `haltsWithin stage p c`。前者的 `isSome` 与后者 judgmentally 分支一致，并由 `isSome-semiHaltAt` 给出显式 path。`haltsWithin-next-stage` 证明 bounded positive observation 随 stage 保持，继而得到 `semiHaltAt-persistent`。

这使 approximants 构成一致的逐步信息：有限阶段都可计算；正答案不会撤回；没有正答案的有限前缀不被提升为对所有未来阶段的结论。

### 与 `CodeHalts` 的闭合对应

`finalAt-implies-haltsWithin` 把精确第 `n` 步终止转换为不晚于 `n` 的 bounded positive。反向 `haltsWithin-implies-CodeHalts` 对 stage 归纳，并用 `or-true-split` 区分当前终止与后继计算中终止。它产生某个精确有限步 witness，再进入 propositional truncation。

由此构造：

```text
CodeHalts p c  ->  SemiReturns p c
SemiReturns p c ->  CodeHalts p c
```

这里没有从 truncation 中选取最小停机时刻，也没有制造负答案。

### 公平全域枚举

`enumerateHalting n` 读取 `FairEnumeration.caseAt n` 并计算 `observeAt n`；观察为真时输出该 case。`bounded-case-eventually-emitted` 使用规范 `caseIndex` 证明所有 bounded positive case 在有限位置被发射；`canonical-emission-sound` 证明规范位置的每次正发射都还原为同一个 program/input/fuel 的 `haltsWithin=true`。

## 三、开发期反例与修正

第一次原生 type-check 在 `haltsWithin-implies-CodeHalts` 的当前终止分支失败：单纯 `with isFinal ...` 没有给 `finalAt zero` 保留所需的路径证据。修正没有增加公理，而是定义布尔引理 `or-true-split`，显式返回“当前观察为真”或“剩余 bounded observation 为真”的证据。修正后原生 Cubical Agda type-check exit 0。

## 五、精确解释

本包实现了一个半判定器的可执行表示：调用者可以依次提高 stage；若目标程序有有限停机 witness，机器证明保证某个 stage 返回正答案；若某 stage 尚未返回，过程没有给出“永远不停机”的结论。`loopCode` 的全阶段负控制来自该具体循环程序的归纳证明，不是半判定接口对任意输入生成的总负答案。

因此，用户提出的“在 HoTT 代码框架下构造不能停机的代码”在一个受限意义上已经做到：R2 的 `loopCode` 有机器证明的全有限阶段非终止轨迹，而本轮证明 partial search 对它永不返回正见证。但这类单个显式循环非常容易识别，本身不构成 HoTT 非现实性悖论，也不证明停机问题对任意程序不可判定。
