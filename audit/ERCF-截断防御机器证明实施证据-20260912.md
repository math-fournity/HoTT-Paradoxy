## 1. 判别目标与结果

上一研究增量已经用普通 Lean 闭合通用 factorization，但尚未让 HoTT 特有规则参与。本轮选择 propositional truncation 作为第一个原生“信息经济”接口，因为它明确：

- 用 point constructor 把 `A` 的 witness 放入 `∥A∥₁`；
- 用 squash path 把截断内任意两点同一化；
- 只在目标具有相应低同伦层级时允许安全消去。

机器结果不是悖论，而是防御：mere existence 可用于 proposition-valued consumer；若要求从 `∥Bool∥₁` 逐点恢复原 Bool witness，squash path 会迫使两个输出相等，与 `false≢true` 冲突。理论没有把未知 witness 假装成已取得 witness，而是用 HIT/消去边界阻止该资格提升。

## 4. 预检失败谱系

失败没有被删除或改写为数学拒绝：

1. `SOURCE_PATH_INVOCATION_ERROR`：首次命令只传 `TruncationDefense.agda`，但 cwd 是 repo 根，Agda 报目标文件不存在。修复为 repo-relative path；没有进入类型检查。
2. `LIBRARY_FLAGS_NOT_APPLIED`：只用 `-i` 而未用 cubical library registry，import 报 `InfectiveImport`，说明依赖模块没有取得 `--cubical/--two-level` 配置。
3. `MIXED_GLOBAL_OPTIONS_CACHE`：尝试把 library flags 全局传给 Agda，primitive interface 生成于不一致 option 组合，后续报 `CubicalNotErasure`。该 XDG cache 被移动到 D 盘 `xdg-data-preflight-mixed-options/` 保留，不复用。
4. `SOURCE_GUARDEDNESS_MISMATCH`：fresh XDG + 正确 library registry 后，主 source 缺 library 的 infective `--guardedness`，Agda 明确拒绝。源码补入该真实 option。
5. `KERNEL_PREFLIGHT_ACCEPTED`：在 fresh D XDG、`--library-file`、`-l cubical-0.9`、`--ignore-interfaces` 下完整重检成功。

这些失败分别属于路径、配置、cache identity 和 infective option；没有一个证明或反驳 C-67–C-70。最终命题没有为了求绿而削弱。

## 7. 研究判词

### 已闭合

- Cubical propositional truncation 是一个实际、原生的信息遗忘构造，而不是任意投影模型；
- 在选定的 Agda/Cubical 版本中，向 proposition 的受保护 consumer 可机器构造；
- 对 Bool 逐点恢复原 witness 的合同与 squash path 不相容；
- 该接口没有绕过 ASK，它把“不允许从 mere existence 无条件取得 witness”写进可检查规则。

### 没有闭合

- 没有现实/操作任务证明 HoTT 自己承诺了被拒绝的 extraction；
- 没有 HoTT 内部矛盾、非停机轨迹或 coverage no-go；
- 没有否定所有 choice、所有 `∥A∥→A` 或所有非-proposition consumer；
- 没有进入 syntax/quote/eval/validator 的 ERCF-3；
- 没有新颖性或外部专家认证。

当前正确分类是 `DEFENSE_WORKS_MACHINE_PROVED_LOCAL_UNCOMMITTED`，不是 `NATURAL_USAGE_MISMATCH`。
