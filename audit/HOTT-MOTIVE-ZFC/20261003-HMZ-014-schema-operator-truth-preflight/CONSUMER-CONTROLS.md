# HMZ-014：统一 Build 探针的消费者控制

## Candidate contract versus source contracts

| Field | H9 proposed contract | Sources actually inspected | Consequence |
|---|---|---|---|
| input | arbitrary code \(p\), arbitrary set \(a\) | fixed schema formula; or coded formula in a specified ordinal structure | no common input contract |
| formation | an internal `Build(p,a)` | schema instance / class-formation under stronger resources / recursively defined T | formation is scoped and paid |
| consumer | whole-V truth/membership use | SO model, ordinal computations, fixed derivation-system model | consumer is not bare ZFC whole-V |
| observation | `0∈Build(⌜σ⌝,{0})` yields truth of arbitrary \(σ\) | satisfaction only for a stated LT structure, with explicit assignment/parameters | observation is restricted |
| Done | uniform correctness for all codes | rule/schema or recursion/reflection under explicit conditions | Done differs |

## P gates

```text
P1: the proposed whole-V Build is not supplied by the ZFC schema sources.
P2: moving formula coding/satisfaction to a metatheory or specified structure is
    an explicit layer switch, not evidence that it cannot be externalized.
P3: T uses a declared recursive construction and reflection; no pending object
    is accepted before its own truth/formation is settled.
P4: no same-object reentry; transfinite recursion is controlled by initial
    segments and structure parameters.
P5: no actual consumer pre-spends a whole-V Build.
P6: no same task/UR comparison is source-supported.
```

## Reopen condition

An admitted successor must show a version-fixed source whose consumer actually treats an arbitrary formula code as a ZFC-internal Build input, claims whole-V correctness or an equivalent same-Done contract, and lacks an explicit code/structure/reflection/payment boundary. A source that restricts its language, model, ordinal stage or recursion does not reopen this card.
