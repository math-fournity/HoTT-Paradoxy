# HMZ-020：有界发现

Classical realizability supplies the strongest source control so far for P5. It demonstrates that a program-oriented semantics can be associated with ZF-related proofs even in a classical setting. The project therefore cannot characterize ZF/ZFC as simply outside proof-program correspondence.

The correspondence is not free: Krivine explicitly supplies a realizability algebra, continuations, `ZFε`, a ground model, a nonstandard model with stack-valued truth, and proof-like terms. Those are part of the source’s formation and consumer contract. Neither this source nor the ordinary ZF formalization source identifies the user-P event of a consumer using \(u\) before its own required constructive-like delivery is paid.

```text
ZF-RELATED PROGRAM SEMANTICS: SOURCE-SUPPORTED
BARE ZFC PROGRAM-LIKE DELIVERY PROMISE: NOT FOUND
P5 PREEMPTIVE-USE SURPLUS: NOT FOUND
P-QUALIFIED ZFC Q: NO
RUN DISPOSITION: P_REQUALIFICATION_REQUIRED
```

This leaves a very narrow, falsifiable frontier: find a same-layer ordinary ZFC consumer with a program-like Done and an unpaid formation/preemptive-use transition, or record a source that shows why such a consumer contract cannot be demanded without changing the task.
