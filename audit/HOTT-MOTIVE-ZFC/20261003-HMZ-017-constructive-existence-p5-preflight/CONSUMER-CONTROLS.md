# HMZ-017：constructive delivery 与 ZFC 的控制

## Source contract

```text
Constructive source input: an existence proof in constructive logic/type theory.
Operation: extract a program constructing the object.
Observation: program terminates and is correct.
Done: a verified construction is delivered.
```

This is a strong, explicit consumer/Done model. It shows that mathematics already has a vocabulary and formal practice for separating existence from usable construction.

## What is still missing for a ZFC P card

1. A ZFC object \(u\) whose same theory’s consumer requires constructive delivery;
2. source evidence that ZFC supplies only existence while that consumer treats it as delivered;
3. a pending formation/admission condition and a P2/P3 process;
4. same subject, operation, observation and Done across the constructive and ZFC sides.

Without those fields, treating Palmgren’s requirement as a test that ZFC “fails” would change the foundational contract rather than expose a ZFC internal inconsistency or P-qualified Q.
