## 二、发现（Findings）

**F1［中］FileChange 线索的"逐条"承诺未全额兑现**：R-3 与 003 片 §4 要求胶囊逐条登记；高容量块（如 R0010，单块 197 个胶囊）以分组压缩登记（"①SOURCE-023/024 全套＋收据"），通用收据文件（RUN.json 等）与部分具名文件不可从交付物逐条检索。D3 的"FileChange 胶囊资产线索总索引"实为 8 行指针（"见笔记各批次节"）＋106 处计数，**不是 004 片 §3 承诺的"八线全部文件操作的时间线视图"**。缓解：语料有哈希保全，无永久丢失；影响：按文件名检索资产线索需回语料。处置建议：或补建真索引（从语料机械重扫即可，胶囊行格式固定），或在 D3 如实降格该节声明。

**F2［中］D4-R2 事实错误**：声称"现 README 覆盖 dev-01/02/03/04/06/07/08（无 dev-05）"并建议"补入 dev-09"——实际 README 五处结构（handoff 表 L28、阅读入口 L34、分叉图 L106、cutoff 表 L130、文件表 L149）**均完整覆盖 dev-09**；"无 dev-05"也已在 L15 说明。照此修订会错误改动完好的 README。处置：**使用 D4 前剔除 R2**；其余五条（R1 轮次告警/R3 一句话定位/R4 资产指针/R5 终态补齐/R6 provenance）抽查合理。

**F3［低］§9.8 轮次归属的边界约定差**：子线 READ 自报 user_turn 合计 50 vs UNIQUE 区标记数 30——跨 SHARED/UNIQUE 缝的轮次归属口径差（执行者按"本块笔记转写的轮"计，合同按"标记行在块内"计）；dev-08（无缝）精确一致佐证非系统性失计。内容级无损失（第 12 项已证）。

**F4［低］约 5 轮用户原话未严格逐字**：均为粘贴框引型长轮（如 L6491 goal 粘贴、L9709 嵌入块轮），笔记以"首句＋…＋尾句"压缩或仅录嵌入块。条目均在（class_counts 齐），形式偏离 R-1 字面（>200 应取前 200）。

**F5［低］token-log 的累计语义**：log 含中途未修复态的 missing 计数（如 dev-02 累计 91），与 G4B 终态（义务残留 0）口径不同；审计者读 log 需知其为流水而非终态。

**F6［备注］互锁退出码未直接捕获**（管道掩蔽），REFUSE 消息＋零污染已证；退出码 3 的声明未复核。
