## 2. 按严重程度排列的发现

### F1 — P1：C-168 把 double 的性质误交付成 codeAtom 的性质

定位：报告 §8.3(d)；`HoTT/CLAIM_EVIDENCE_MATRIX.md:319`；`HoTT/formal/ercf3-t3/ArithmeticTags.agda:68–83`；同目录 README §4。

报告先介绍 `codeAtom (avar n)=2n`、`codeAtom (anum n)=2n+1`，随后称“编码非满射，1 无原像，因此任何全解码器必须有缺省分支”。源码 `one-has-no-preimage` 的真实类型却是：

```agda
Not (Σ' Nat (λ m → double m ≡ suc zero))
```

它只谈 `double`，没有谈 `codeAtom`。本审计直接导入原 `ArithmeticTags.codeAtom`，机器证明：

```agda
codeAtom (anum zero) ≡ suc zero
(n : Nat) → Σ' Atom (λ a → codeAtom a ≡ n)
```

两条分别由 `Countercheck.one-has-codeAtom-preimage` 和 `Countercheck.codeAtom-surjective` 给出。源码在 `HoTT/formal/audit-c168-20260913/Countercheck.agda`；proof ID `MP-AUD-C168-20260913`；run `HoTT/verification/runs/20260913-AUD-C168-01A09B1E-01/`；`--safe --without-K --no-libraries --ignore-interfaces`，exit 0、stderr 空。两条已进入矩阵独立审计索引。

影响：C-168 的形式引理本身可以通过，中文包结论却把函数换掉了。C-176 等条目的“符合 C-168／由 C-168 要求缺省分支”说明也需复核。这不推翻后续 `codeT'`/`codeF'` 的往返证明；它推翻的是从该引理得出的编码非满射说明和所声称的必然设计要求。

建议：保留旧行作为历史证据，用正式修订把 C-168 精确限定为 double；撤回 codeAtom 非满射和由此强制解码器形态的叙述。不能只重跑 Agda 后继续沿用原中文。

### F3 — P1：S108 的关键推理缺少必要对象，却被用于关闭整个候选形状
