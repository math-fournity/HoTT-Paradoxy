# 实施路线、资源与验收

实施按完整链路逐步扩大，不先把每个组件做到极深，也不把一个永久示例当作全系统。每个阶段结束都要保留可以运行的上一阶段，并报告新增能力、减少的关键未知和仍未贯通的研究线。

| 阶段 | 需要交付的真实能力 | 退出判据 | 暂不做 |
|---|---|---|---|
| M0 规则与任务资格化 | 固定 profile；导出一个片段；锁定 Task 与正反控制 | 原文、声明、精确目标和原生检查对应；缺口可查询 | 全库自动形式化、模型训练 |
| M1 最小完整搜索链 | 自动生成、求解、缩减、原生核验、解释、保存和恢复 | 自动复现校准现象；成功与失败均可重放；生成器无答案硬编码 | 大型知识图谱 UI、并发 AI |
| M2 符号与高阶路径 | 原生项搜索、辅助引理发现、路径与宇宙条件处理 | 至少一项不能由纯有限枚举替代的任务完整通过，并保留反控制 | 把全部 HoTT 降成一个有限模型 |
| M3 六线覆盖 | 每条线有真实可执行入口和完整案例链 | L1–L6 各有实际运行案例；未解决性质诚实输出，不支持的线保持未完成 | 以文档化替代未实现后端 |
| M4 搜索有效性评测 | 控制预算的基线、留出任务、消融和误判分析 | 证明系统能增加有效探索，而非只加候选数量 | 宣称新颖性已经全球认证 |
| M5 项目集成与维护 | 接现有唯一 owner、版本与证据合同 | 集成、查询、重放、取消、恢复和回滚均通过 | 未授权 push、发布或后台运行 |

M0 的首个片段推荐从 L1 的现有 delay／商／观察模型开始，原因是输入、操作、既有正反控制和原生工具链已经有可发现资产。它只服务于验证搜索链。M1 完成后必须进入 M2 或另一未覆盖线；继续调同一模型的数字需要有新的研究理由。

**原型参数是可调整的工程起点。** 建议初始使用 1 个原生证明进程、至多 2 个轻量模型求解进程；这不是调用多个 AI。模型、内核和 LLM 分别计量时间与成本，受总预算约束，避免相互等待使一轮无法结束。

可用的首轮配置示例是：项大小从 1 到 4、操作深度从 1 到 3、有限过程长度从 1 到 6；轻量求解单次 30 秒，原生检查单次 120 秒，一轮总时长上限 30 分钟。它们用于测量可运行性，不是数学边界；首次校准后根据实际分布调整。无限或高阶任务以证明搜索预算记录，不能假装这些有限范围覆盖它们。

内存上限应依据实际主机剩余容量设置，并给正在工作的其它 AI 留出余量；本方案不假定某个硬件规格。开始实现时记录 CPU、RAM、磁盘与工具版本。模型 API 费用按实际调用量统计，不预报未经核查的价格，也不自动启用更贵模型或远端 embedding。

如果 30 分钟内只完成少量候选，先区分声明提取、类型检查、模型求解和原生证明的耗时，不立即增加并发。重复输入可缓存，成批导入可复用已锁定模块；目标改变、假设改变或工具变化必须使相关缓存失效。

**评测包含三个层次。**

- 校准集：旧包的精确正例与反例，用于验证工具链和命题对应。已被 LLM 上下文看见的结果不得称为盲测。
- 留出集：在冻结搜索器与评价规则后确定的任务变体或独立任务；保存生成来源与答案可见性。若训练数据污染无法排除，注明限制。
- 开放研究集：允许搜索器提出新的关系，但“新”须经过机制比较和文献审查。没有找到新关系是可以报告的研究结果，不能回头修改 gold 标准制造成功。

比较至少包括同预算的“仅有类型枚举”“LLM 提案＋核验”“混合搜索＋反例反馈”。比较时固定任务、允许规则、工具与总预算；模型换代应另列实验，不能混入同一曲线。关闭反例反馈、关闭符号探索或关闭覆盖调度可用于消融，但不降低合法性及证据要求。

| 指标 | 要回答的问题 | 防止误读 |
|---|---|---|
| 有效候选比例 | 生成内容有多少真正满足类型与规格输入 | 高比例可能来自过窄语法 |
| 每预算获得的已核新关系 | 是否增加可用研究认识 | 先去除旧机制换名与同义引理 |
| 首个有判别力结果的耗时 | 是否更快消除关键未知 | 正、负结果分别列出 |
| 未覆盖规则与任务面 | 系统遗漏什么 | 不能只显示已支持部分的百分比 |
| 错误升级率 | 是否把超时、有限测试、换题当成功 | 对应有确切负控制的分母 |
| 现实对应未决比例 | 哪一层仍依赖未完成解释 | 不为了降比例强行作判断 |
| 复跑与恢复成功率 | 结果是否能回到输入和证据 | 只统计实际执行的恢复场景 |

统计比较报告任务数、运行次数、成本和波动；样本不足时保留描述性结果，不宣称普遍性能优势。无需为了这些指标先建评分平台，首版可由 run 原件生成表格。

**必须执行的验收场景。**

| 场景 | 预期行为 |
|---|---|
| 证明源码不引用目标，仅空模块通过 | 不产生目标证明结果 |
| 候选重定义 False、替换目标或增加公理 | 按配置拒绝并记录 exact reason |
| 两个不同 universe／profile 的规则混用 | 阻断错误推演，保留待适配项 |
| 某个 SMT 编码截掉高阶数据 | 不升级为原生 HoTT 结论 |
| 燃料耗尽、网络失败或内核崩溃 | 输出不同执行原因，不写成非停机定理 |
| 修复新增标签、成本或输入 | 标明新增／预先保留，不冒称从原输入恢复 |
| 现实侧一次选择与理论侧全称相容选择混用 | 任务对应保持未决或标为改变 |
| 已知无统一选点上加一个无作用的时间参数 | 报告旧机制承担障碍，不计新机制 |
| 输入声明、Task 或工具哈希改变 | 旧结果 stale，需重新核验 |
| 运行中断后恢复 | 不丢失败原件、不重复发布终态、不抢占其它写者 |
| 一条难线连续无证明成功 | 保留其搜索机会与未知，不能自动从地图消失 |
| 所有样例均通过但有未支持语法 | 不宣称整个 profile 已覆盖 |

**研究判断也要有明确输出。** 对最有价值的每个候选，报告一段完整故事：原来做什么、理论怎样描述它、变化在哪一步、合法过程得到什么、现实对应为何值得比较、最强正面解释是什么。只有公式或日志的报告不满足目标；只有故事、没有对应证明的报告也不满足数学交付要求。

**主要风险与处置。**

| 风险 | 可观察信号 | 处置及返回主链条件 |
|---|---|---|
| 形式化换题 | Task hash 不变却额外输入或完成标准改变 | 拆分版本，恢复原规格后继续 |
| 搜索空间爆炸 | 候选增长而有效结果停滞 | 用已证相容的去重、符号值、分线预算；不删除未覆盖家族 |
| 评价器偏差 | 某类候选总因描述标签被排除 | 回查原意与形式条件，评估规则与候选分开修订 |
| 全部困难归入旧信息丢失 | 消融总回到同一个定理 | 扩展任务／规则组合，保留已知基线但减少重复 |
| 物理前提未核 | 模型假设被写成现实事实 | 降为模型相对，独立寻找物理依据 |
| 证明助手与执行混淆 | 类型检查 PASS 被当作实时交付 | 分开 proof run 与程序运行，按实际任务补证据 |
| 活跃 repo 并行变化 | 源码、索引和记录混代 | 使用锁定快照、独立输出、明确集成所有权 |
| 新工具引入成本过高 | 花大量工作在基础设施且没有新实验 | 回到最小适配器；只有实际瓶颈才引入组件 |

阶段工期不预设为发现期限。可以在实现开始后以 M0/M1 的实际速度估算后续工程量；时间结构保真、广域自指及现实对应属于研究风险，不能用固定天数保证解决。

交付完成分三次判断：本方案是否完整、搜索系统是否按声明范围有效、是否找到目标现象。前两者可以作为工程验收对象；最后一项必须由具体构造、原生证明与现实关系共同决定。没有目标发现时，系统仍必须交出准确的搜索边界、失败与下一项可判别未知。
