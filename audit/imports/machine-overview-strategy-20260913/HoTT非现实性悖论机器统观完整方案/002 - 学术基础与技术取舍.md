# 学术基础与技术取舍

机器统观可以借鉴已经成立的研究路线，但不能把若干工具名称拼起来就宣称具有 HoTT 悖论发现能力。本方案区分三种借用：直接使用可核验的工具接口；在 HoTT 中重新实现或验证一种算法思想；仅作为长期研究方向参考。

2026 年的 Theory-Level Autoformalization 立场论文，明确把关注点从孤立命题转向包含定义、引理与相互依赖的整套形式知识。它支持建立理论层结构这一方向，但作为立场论文，它没有交付自动覆盖全部 HoTT 的系统。[18 · 理论层自动形式化](https://arxiv.org/abs/2607.13292)

| 学术路线 | 已有工作支持的能力 | 本方案采用方式 | 必须补上的适配 |
|---|---|---|---|
| QuickSpec | 测试函数并生成候选规律，包括条件等式 | 快速产生代数候选的参照 | 测试不是证明；普通函数测试不能覆盖任意依赖类型与高阶路径 |
| Hipster | 在 Isabelle/HOL 中探索引理，并为当前目标寻找缺失引理 | 借用“主动发现＋目标驱动”双模式 | 不直接把 HOL 结论当原生 HoTT 结论 |
| TheSy | 基于归纳数据类型、递归定义和符号值的理论探索 | 借用逐步加深、符号比较、证明后回馈 | 其猜想推断阶段不等同于有效证明；HoTT 依赖与相干性需另处理 |
| SyGuS／CEGIS | 用语法约束候选，用语义规格与反例引导合成 | 用于有限片段的操作、模型和观察函数合成 | 规格由独立任务输入决定；求解失败不得写成全理论无解 |
| CEGAR | 检查抽象轨迹能否对应具体轨迹，并精化抽象 | 保存对应失败点，探索其理论意义 | 普通 spurious trace 不自动成为 HoTT 现实相对悖论 |
| egg／等式饱和 | 紧凑表示大量等价表达式，减少改写顺序敏感性 | 仅对已确认的、任务相容的改写做候选去重 | 不合并需要区分的成本、来源、路径见证和高阶相干数据 |
| Alloy／有限模型求解 | 在声明的模型范围内找满足实例或反例 | 作为有界结构搜索后端或独立对照 | “无实例”严格绑定范围；LTS 不是完整 HoTT 语义 |
| FunSearch | LLM 生成程序，与固定评价程序形成演化反馈 | 借用程序级候选与多样性保留 | 本项目没有现成的“非现实性分数”；哲学对应不能用单一分数冒充 |
| LeanDojo | 程序化证明环境、前提提取与检索增强证明 | 借用来源定位、可用前提检索及评测分离 | Lean 的工具和训练数据不能直接移作 Cubical 证明能力 |
| Cubical Agda | 原生单价性、高阶构造与计算性路径操作 | 第一原生核验后端 | 固定编译器、库、选项及完整导入闭包；不外推至全部 HoTT 变体 |

上述能力分别由原论文或官方资料支持。[4 · QuickSpec](https://github.com/nick8325/quickspec)、[5 · Hipster](https://arxiv.org/abs/1405.3426)、[6 · TheSy](https://arxiv.org/abs/2009.04826v2)、[7 · SyGuS](https://www-cad.eecs.berkeley.edu/~sseshia/pubs/b2hd-alur-fmcad13.html)、[8 · CEGIS](https://people.csail.mit.edu/asolar/SynthesisCourse2020/Lecture10.htm)、[9 · CEGAR](https://www.cs.cmu.edu/~emc/papers/Papers%20In%20Refereed%20Journals/Counterexample-guided%20abstraction%20refinement.pdf)、[10 · egg](https://arxiv.org/abs/2004.03082)、[11 · Alloy](https://alloytools.org/spec.html)、[12 · FunSearch](https://www.nature.com/articles/s41586-023-06924-6)、[13 · LeanDojo](https://arxiv.org/abs/2306.15626)、[3 · Cubical Agda](https://staff.math.su.se/anders.mortberg/papers/cubicalagda.pdf)

TheSy 的一个关键启发是用符号值减少具体测试值的组合爆炸；另一个关键边界是它把猜想推断与归纳证明分开。对本项目而言，应同时借用这种探索效率与证据分离，而不能把符号比较得到的候选等式直接写入可信引理库。[6 · 算法概览，论文 §2](https://arxiv.org/pdf/2009.04826v2)

等式饱和需要特别谨慎。它的通常目标是把相等表达式合并以节省搜索；本项目恰恰可能需要研究哪些信息在识别后不再可见。因此保留两种身份：程序和证明的原始语法身份，以及已证明相等的数学身份。只有对于本任务所需观察也已证明相容的改写，才能用于语义去重。高阶路径之间不能只因端点相同便被合并。

**HoTT 相关领域不是全部现成后端。**

| 领域 | 来源提供的启发 | 系统中的位置 |
|---|---|---|
| 部分性 | Partiality, Revisited 以 QIIT 构造部分性单子，并精确讨论选择假设 | 比較不同部分计算表示的条件；不把最小 delay 模型冒充完整构造 |
| Guarded／clocked | Guarded Cubical Type Theory 提供处理递归、路径与生产性的特定规则 | 独立 profile，用于阶段、反馈和时序保持研究 |
| 成本类型论 | CATT 把求值成本纳入理论，并讨论成本敏感的函数类型 | 比较成本所需结构与外延表达的关系，不当作普通 HoTT 的默认规则 |
| 双层类型论 | 2LTT 区分内外理论及其判断 | 自描述、内部模型与相干问题的对照系统；不是一句“升宇宙”可以代替 |
| 分析与运动结构 | HoTT Book 的实数与相关构造 | 时间结构研究的规则来源；稠密性与物理运动之间的对应独立论证 |

这些资料为研究提供模型与对照，并未证明本项目的目标悖论已经存在。[14 · Partiality](https://arxiv.org/abs/1610.09254)、[15 · Guarded Cubical](https://arxiv.org/abs/1611.09263)、[16 · CATT](https://arxiv.org/abs/2011.03660v2)、[17 · 2LTT](https://arxiv.org/abs/1705.03307)

**推荐技术路线。** 第一版使用 Python 协调与文件化案例、原生 Cubical Agda 核验、一个小型有类型枚举器；需要约束合成时接 cvc5。官方 cvc5 示例已提供由语法、待合成函数及约束组成的 SyGuS 接口；这说明接口可借用，不说明 HoTT 语义已自动获得。[19 · cvc5 SyGuS](https://cvc5.github.io/docs/latest/examples/sygus-fun.html)

Agda 的反射接口可以访问类型和定义、构建或检查项，因此可作为声明提取与候选核查适配器的起点。第一版不依赖对所有 Agda 内部结构的完整反射：明确支持的构造精确导出，未支持的构造标记并回到原文，不用缺省值补成伪规则。[20 · Agda 2.8.0 Reflection](https://agda.readthedocs.io/en/v2.8.0/language/reflection.html)

不建议第一阶段同时集成 QuickSpec、Hipster、TheSy、Alloy、egg 和多个证明助手。先借用方法，接通最少真实组件；只有候选规模或验证任务表明当前方案不足时，再引入对应工具。Rust／egg 是候选去重瓶颈出现后的扩展，Isabelle/HOL 是独立比较后端，二者都不是启动前置。

以下替代方案暂不采用：只用 LLM 读论文后自评；把全部 HoTT 翻译成普通集合逻辑再搜索；只扫库中函数名寻找消费者；给每个 KC 创建一个常驻 Agent；训练一个新大模型后再开始研究。它们分别会放大主观评价、语义丢失、命名偏差、协调负担或准备成本。

学术界的贡献在于可复用的搜索与验证技术；本项目需要新增的是任务相对语义、HoTT 保真适配、覆盖驱动调度和现实对应审查。后者应当被作为系统自身的研究与工程责任，而不是被藏在“采用先进方法”的描述中。
