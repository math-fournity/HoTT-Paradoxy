# 理论表示、任务描述与系统架构

系统采用“来源保持的理论表示＋独立任务描述＋可核验候选”的结构。图谱负责指出连接和缺口，原始声明与证明仍是权威；任务描述负责规定要比较什么，不能由候选结果反向改写。

**理论配置先于规则混用。** 每个运行固定一个 profile，包括演算身份、编译器与库版本、公理、宇宙约定、支持的类型构造、计算规则和允许的元层工具。

| profile 类别 | 首版处理 | 不能混用的事实 |
|---|---|---|
| 书式 HoTT | 以锁定的 HoTT Book 原文为规则基线；公理化部分单列 | 不能自动享有某个 Cubical 实现的判断性计算规则 |
| 原生 Cubical | 复用项目已登记的 Agda／Cubical 配置，先重验局部闭包 | 不能代表所有 Cubical 变体，更不能直接代表全部物理模型 |
| Guarded／clocked | 首版登记接口和未支持项，后续以论文及实现锁定 | Agda 的 guardedness 检查选项不自动等于某篇 guarded 类型论 |
| 2LTT | 独立内外层规则；按任务加载 | 外层严格相等不能搬成内层 Path 的性质 |
| 成本或效应扩展 | 显式增加成本、资源或效应语义 | 扩展中成立不说明原配置免费提供这些能力 |

依赖核查必须包含隐式参数和公理的传递闭包；禁止仅搜索源文件中的 postulate 字样便宣布无公理。书、库、工具三者给出的“相等”也分别记录。[1 · HoTT Book](https://homotopytypetheory.org/book/)、[3 · Cubical Agda](https://staff.math.su.se/anders.mortberg/papers/cubicalagda.pdf)

**规则表示采用带类型的声明及有来源的超图。** 一个推理步骤可能同时需要多个前提，因此普通“词语 A 与词语 B 相关”的图不足以承担推演。图的边至少区分 defines、imports、uses-in-proof、requires-premise、computes-by、interprets-as 与 heuristic-related；最后一类只作导航，不能参加逻辑推导。

每个 RuleRecord 的必需内容是：

| 字段 | 含义与校验 |
|---|---|
| id／revision／source | 稳定身份，原文 locator、精确字节哈希与所属版本 |
| kind | 原始规则、定义、派生定理、表示选择、扩展或实现事实 |
| profile／context | 所属理论，变量绑定、隐式参数、宇宙与约束 |
| premises／conclusion | 结构化语法与原始文本并存，不能只有 LLM 摘要 |
| equality_kind | 判断相等、Path、等价、关系或操作语义；允许不适用 |
| eliminator／computation | 对具体构造逐项登记，禁止套用通用 HIT 消去句式 |
| evidence | 未核、来源审读、源码检查、原生核验；各自关联证据 |
| effects_on_task | 信息、观察、完成义务的变化假说及其任务范围 |

effects_on_task 是研究注释，不是内核事实。“截断忘掉时间”不能作为无条件规则；需要具体输入中哪些时间数据被哪项截断影响。原声明导出失败时产生 UNSUPPORTED_DECLARATION，不生成空定义。

**任务描述与候选生成分离。** TaskSpec 既支持可执行的有限程序任务，也支持明确给定的数学模型及物理解释任务。后两者不能因为采用相同字段而被视为同一种现实证据。

~~~yaml
task_id: MS-TASK-...
revision: 1
purpose: 独立说明原活动与要达到的结果
source_basis: 原始问题、正式规格、公开应用或明确的模型假设
input:
  type_ref: ...
  available_information: ...
environment:
  arrival_policy: ...
  nondeterminism: ...
  fairness: ...
observation:
  value: ...
  trace: ...
  time_structure: ...
completion:
  kind: exact | approximate | eventually_stable | productive | bounded
  criterion_ref: ...
quantifiers:
  instances: single | finite_family | all_in_declared_domain
  realization: one_run | strategy | uniform_algorithm
allowed_resources: ...
prohibited_extra_information: ...
known_positive_controls: ...
~~~

省略字段必须写“未知”或“不适用”并附理由，不能让缺省值悄悄变成全知、无限资源、默认公平或精确完成。productive 表示持续服务的完成方式，不等于必须停止；approximate 必须带误差要求，不能用近似输出冒充精确值。

**现实对应使用关系，不强制使用单个遗忘函数。** 对确定性表示，可以使用编码函数；对非确定性选择、不同呈现或过程模拟，使用带条件的关系。一次选择、对所有输入的统一函数、与全部自同构相容的选择是不同规格，系统不可自动互换。

候选 Case 的逻辑内容为：

~~~text
理论配置 T
原任务 Q 与现实侧模型 R
表示／解释关系 E
理论化操作链 τ
观察与完成要求 O、F
操作链引入或取消的义务 Δ
待证明性质 P
现实对应证据 B
~~~

这是一组设计字段，不是已经证明的通用数学定义。Case 的匹配性由逐项义务说明：两侧有哪些对应输入、哪些观察必须保持、完成标准如何关联、哪个新增条件来自理论操作。若其中某项未知，案例可以继续搜索，但不得交付为现实相对目标已经成立。

**A 方向的典型证明义务**是：给出原任务完成见证；明确理论化后所研究的过程或实现类；证明对应的额外困难；定位引入该困难的条件。只排除一个程序，只能交付该程序的失败；排除整个实现类，需要该类的全称证明。

**B 方向的典型证明义务**是：证明理论所得对象的精确资格；固定被解释为更强能力的转换；证明该转换没有履行所要求的实现／完成义务。若主张不存在任何有效算法，必须固定有效性模型和量词，不能以一次执行失败替代。

**组件按职责而非服务数量拆分。**

~~~mermaid
flowchart TD
    S["锁定来源与核心认知"] --> X["声明提取与理论地图"]
    S --> Q["任务描述与对应关系"]
    X --> G["候选生成与搜索"]
    Q --> G
    G --> M["模型检查与反例缩减"]
    G --> K["原生 HoTT 核验"]
    M --> G
    K --> G
    M --> B["任务与现实对应审查"]
    K --> B
    B --> R["案例报告与经证明的知识"]
    R --> G
~~~

| 组件 | 主要责任 | 输出 | 禁止越权 |
|---|---|---|---|
| 来源适配器 | 从固定文件与声明取得可追溯材料 | RuleRecord、覆盖缺口 | 不把自然语言相似度当逻辑依赖 |
| 任务编辑器 | 保存任务及每次修订依据 | TaskSpec、对应义务 | 不随候选失败静默降低完成标准 |
| 搜索器 | 按 grammar 和预算生成有类型构造 | Case、候选证明 | 不修改可信规则和判定程序 |
| 有界求解器适配器 | 编码有限模型、返回实例或范围结果 | solver 输入、结果、见证 | 不认证未经翻译证明的高阶结论 |
| 原生证明适配器 | 检查源码及精确命题 | proof/run/index 证据 | 不解释物理现实或认领原创性 |
| 案例评估与报告器 | 汇总性质、任务关系、局限和新颖性 | 可读报告、多轴状态 | 不把 LLM 意见升级为数学证明 |

第一版由一个协调进程调用以上逻辑模块。LLM 是搜索和任务提出的可选调用，不构成第二个状态 owner。多 AI 委派不是架构必要条件；如未来使用，仍须遵守具体授权、隔离与验收范围。

对理论地图的首版建设采用“核心规则全家族登记＋按研究线深化”。Π、Σ、Id／Path、等价、宇宙、自然数与归纳、具体 HIT、截断、商及派生结构均要有条目；未自动支持的家族明确可见。没有进入搜索语法的条目仍在地图上，不能因适配器尚未实现而从统观中消失。
