# 证明证据与运行合同

本章规定拟实现系统的工程合同。接口名称和数据字段是设计，不是当前 repo 已存在的命令。第一版使用文件化案例与单写者协调，不要求数据库或分布式任务平台。

**每个结果同时保留六条状态轴。**

| 轴 | 典型状态 |
|---|---|
| 形式合法性 | unchecked、well_typed、rejected、unsupported |
| 数学证据 | conjecture、tested、bounded_result、native_checked、source_reported |
| 任务保持 | unresolved、preserved、changed_input、changed_completion、changed_rules |
| 现实对应 | model_only、operationally_specified、empirically_supported、unresolved |
| 研究关系 | calibration、known_mechanism、new_to_project、literature_review_pending |
| 执行 | queued、running、finished、timeout、cancelled、infrastructure_error |

这些字段分别拥有证据定位。不存在“编译通过，所以现实相对悖论成立”的状态跳转。未读过或未重放的论文结果保持来源身份；候选的正反证据均保留。

**原生证明链必须精确绑定命题。** 协调器先生成不可由候选进程修改的 Target 模块，固定目标类型与假设；候选进程只提供允许的证明源码。核验入口引用精确目标与证明符号，拒绝重定义目标、修改证明选项、额外公理或替换导入。

对 Cubical 结果检查完整依赖、公理允许清单、宇宙与选项；不接受未解 meta、未经许可的终止规避或仅声明类型未给证明。一个空模块成功、仅导入成功、名称相同但目标变弱、源码未被入口实际依赖，都不得生成 native_checked 结果。

一份普通逻辑／SMT 结果有两种提升方式：在原生系统重新构造该精确性质；或者使用已机器证明、适用于该命题的翻译。仅证明语法能够往返，不等于命题与证明语义保真。没有这两种证据时，求解器结果只属于前端模型。

证明收据包括 claim/proof identity、完整命题、源码与依赖 manifest、工具二进制身份、命令参数、cwd、选项、开始结束时间、退出状态、原始 stdout/stderr、被检查目标以及禁止外推。缓存命中必须绑定全部相关输入；最终交付需要一次可审计的真实检查，不能仅凭旧接口缓存自述。

**拟议的文件布局如下。**

~~~text
machine-overview/
  profiles/          已人工确认的理论配置
  tasks/             TaskSpec 与修订依据
  grammars/          搜索语法及其来源
  cases/<case-id>/   不可覆盖的案例版本
  runs/<run-id>/     原始执行输入、输出、环境与收据
  generated-index/   可以重建的查询投影
  reports/          指向 case/run 的可读报告
~~~

这是一份未来目录建议，不在本轮创建。正式数学成果进入现有 HoTT/formal、HoTT/verification/runs 与 CLAIM_EVIDENCE_MATRIX；探索器目录保存生成与搜索过程，不另建竞争性的数学主张矩阵。

CaseRevision 至少包含 schema_version、case_id、parent_revision、profile_hash、task_hash、grammar_hash、source_pins、candidate_ast、target_text_hash、assumptions、obligations 和状态轴。未确定的字段用显式 unknown，不能空值默认成成功。Case 身份稳定，内容变更产生新 revision，原件不覆盖。

Run 至少包含 run_id、case_revision、attempt、runner_version、tool_identity、input_hashes、resource_limits、random_seed、model_prompt_refs、events、outputs、exit_reason 和 evidence_refs。敏感模型访问凭据不进入 Run；公开可见的提示、响应、工具调用与返回可保存，隐藏推理不作为必需证据。

**拟议 CLI 的责任边界。**

| 命令 | 输入与作用 | 输出及失败行为 |
|---|---|---|
| inspect-profile | 固定来源与配置，核支持域 | 规则覆盖和不支持项；不运行数学搜索 |
| create-case | Task、grammar 与候选结构 | 新案例版本；重复幂等返回同一身份 |
| search | 案例／研究线、范围及预算 | 候选与原始运行；不会改原任务 |
| verify | 精确 case revision 和目标 | 内核收据；基础设施失败单独返回 |
| review-correspondence | 两侧模型、轨迹与条件 | 对应判断与证据；LLM 意见保持建议身份 |
| explain | 指定 case/run | 从原始证据生成报告，不修改证据 |
| query／list／get | 稳定 ID 与过滤条件 | 当前投影与原件 locator |
| retire／validate／export／migrate | 精确资产及版本 | 受控生命周期操作、校验或迁移收据 |

写操作默认支持 dry-run；正式应用使用 expected revision/hash，拒绝 stale base。未来 manager 是这些结构化记录的唯一写入者：实现时同时提供 schema 检查、引用完整性、确定性序列化、round-trip、差异预览、备份和恢复。未交付这些能力前，不将随手生成的 JSON 目录宣布为正式机器治理数据库。

**原子性与并发。** 第一版同一案例只有一个协调写者；求解器进程只写各自 run 的临时目录。运行结束后校验产物，写完 manifest，再原子发布终态收据；索引从终态收据生成。并行求解器不能共同覆盖同一源码、缓存或结果路径。

幂等键由 profile、Task revision、grammar revision、候选 AST、目标、求解器和参数规范化后生成；原始源字节单独 hash，不用规范化文本替代。相同键的重复执行可以复用已验证结果，也可显式创建 replay attempt；不能覆盖失败。生成随机候选的种子与模型返回属于输入的一部分。

取消先请求求解器结束，超时后终止其进程组，保存 partial 输出和 cancelled/timeout 状态。崩溃恢复检查输入完整性和原子收据：已有最终收据只读恢复；临时目录标 interrupted，再开新 attempt。不能把发现旧输出文件当作上次成功。

**错误必须准确归类。**

| 错误 | 处置 |
|---|---|
| TYPE_REJECTED／UNIVERSE_MISMATCH | 保存具体诊断；只说明该表达式或配置失败 |
| UNSUPPORTED_CONSTRUCT／BACKEND_SCOPE_MISMATCH | 转支持该语义的后端或记录研究缺口 |
| TASK_REVISION_CHANGED／SOURCE_HASH_CHANGED | 原结果 stale；不得沿用旧 PASS |
| SOLVER_NO_MODEL_WITHIN_SCOPE | 记录范围；不外推无界不存在 |
| SOLVER_UNKNOWN／TIMEOUT／OOM | 保留未知；不计作候选被反驳 |
| MISSING_PROOF／TARGET_CHANGED | 拒绝 proof receipt，保留候选 |
| KERNEL_ERROR／DEPENDENCY_ERROR | 先使用已知最小正例检查环境，再决定是否重跑 |
| CORRESPONDENCE_UNRESOLVED | 数学结果保留，现实相对主张不升级 |
| REPLAY_MISMATCH | 比较源码、工具和输出；无法解释时降级 |

**运行隔离保护数学输入与评价器。** 候选执行环境只读访问锁定来源、Task 与判定程序，写入独占 run 目录；默认无网络、无宿主凭据、无共享 repo 写权限，并有时间、内存和进程数限制。LLM 不能通过候选程序修改 gold 标准、目标模块或评分函数。隔离必须由操作系统或进程执行机制实现，不能只写进 Prompt。

首版不要求在主机重装整套容器平台：可以采用已有可用的受限执行环境；若尚未建立可靠执行隔离，先限制候选为声明式 AST，由可信解释器执行。任意 LLM 生成脚本不得在主工作树直接运行。

**集成复用。** 当前项目已有 capture_agda_proof_run.py、capture_lean_proof_run.py、verify_formal_proof_run.py、verify_proof_version_closure.py 等资产。实现阶段先核其当前接口与隔离假设，再编写最小适配；不复制一份捕获器形成双真值。保留旧收据原字节，新版本索引变化依项目合同处理。

正式接入共享 repo 之前，在独立路径完成原型及可读 diff；集成需要明确路径所有权，状态更新走当前 checkpoint manager。当前另一 AI 的活跃研究不被探索器自动重新调度；计划、启动搜索、后台运行和 Git 发布是分别授权的动作。
