## 5. 接手建议

当前不宜直接进入 M5，也不宜继续用同一 L1 模型增加数字或逐个核验 50 个 witness。下一自然工作单元应在现有分支完成一次有界修复：

1. 先关闭 P1-1 至 P1-5：固定完整执行/runner 身份，定义 validator 的强 schema 与重算 oracle，修正 correspondence/report join，并统一路径作用域；
2. 把本复审的邻近反例转成回归：缺 target/import/proof、env hash、exit/status、伪造 complete、任意 legacy marker、profile-failed review、伪造 separation、跨 search report、path escape；
3. 再核 P2：RUN↔ATTEMPT、sparse control 和 handoff 双身份；
4. 重新跑 29 项旧测试、上述新反例、三族保存证据校验和至少一项 fresh native run；最终 run 应绑定 clean commit 或完整 runner manifest；
5. 这些通过后回到父目标，优先为真正未覆盖的 L3 时间／运动结构或 B/L5 方向建立新 TaskSpec。L3 必须写运动模型、连续／非连续结构与完成标准，不能把 L1 delay 改名复用；若新任务需要非平凡 Path/HIT，再以它驱动 M2 的最小高阶能力。

这条路径既保留另一 AI 已取得的实质进步，也使自动化系统在扩大搜索之前先能可靠回答：“我究竟用了什么输入、运行了什么、证明属于哪个任务、报告为什么可信。”
