## 1. Chain-A 现在能被命名到什么程度

MPIM 讲座页没有给出其“Cubical Agda proofs can be converted to proofs in set theory”的第一条模型的论文名。随后的一手来源将其模型**家族**收紧为：

```text

  -> Cubical Agda is based on that family
  -> semantic-consistency route for the source-stated CCHM theory
```

支持它的最小来源链是：

| 来源 | 支持的事实 | 不支持的事实 |
|---|---|---|
| Mörtberg, *Computational Proofs in Cubical Type Theories* (2023), p. 41 | “standard model of CCHM cubical type theory”是 Cubical Agda 所基于的模型；它与 equivariant cartesian model 分开。 | 没有给 fixed cubical v0.9 的逐项 library translation。 |
| CCHM 2018 | 在 cubical-set model 上给 cubical type theory、univalence、部分 HIT extension 和 constructive metatheory 的语义。 | 没有声称 fixed `QuestioningDelay` package 完整等同于其 calculus。 |
| Orton–Pitts 2018 | 说明 CCHM 的 particular presheaf model：De Morgan algebra 的 Lawvere theory 上的 presheaves。 | 没有为 H0 提供 translation 或 process observation theorem。 |

因此，H098-A 的正确处置是：

EXACT_MPIM_FIRST_TRANSLATION_PAPER_NOT_DIRECTLY_CITED

它比“MPIM 第一条模型仍完全不明”更强，但仍不足以把模型家族直接叫作 H0 的 set-theoretic translation theorem。

## 2. fixed H0 的实际依赖闭包

H0 的 `QuestioningDelay` 由本项目的程序和 `UniverseHasNoLevel` 证明构成。后者在 fixed library tag `b150186d2544e7efeddd31e5d14a8b9ecbb100f7` 中调用 `Cubical.Homotopy.EilenbergMacLane.Base`。

该 tag 的源码将 Eilenberg–MacLane 类型展开为：

| 固定组件 | v0.9 source 中的具体形状 | 已有模型来源的状态 |
|---|---|---|
| `EM₁` | 一个 HIT：`embase`、群参数化 `emloop`、二维 `emcomp`、`emsquash`。 | CCHM/CHM 没有在本次固定来源中给出该 exact declaration 的 semantic theorem。 |
| higher `EM` | `EM-raw` 递归使用 `EM₁` 与 `Susp`；`EM` 再用 h-level truncation。 | CHM 给 suspension/truncation 等重要 HIT 的语义；这不能单独支付 `EM₁` 与整个 v0.9 closure。 |
| univalence / universe / h-level | H0 的 universe non-level proof需要这些结构。 | CCHM source 中有 univalence/universes的来源级支撑；尚无 H0 exact map。 |
| `Delay` + `QuestioningDelay` | 本项目局部定义的 computation / finite-fuel observation。 | 没有 source-defined semantic image、`never` preservation/reflection 或 finite halt witness theorem。 |

CHM 2018 的贡献足够精确地防止两种相反错误：它确实为 spheres、torus、suspensions、truncations、pushouts 等某些 HIT 给出 constructive semantics；同时它把 general HIT schema 的详细 formulation/semantics留作未来工作。因此，不能用“CCHM 有 HIT”既宣称 exact `EM₁` 已支付，也不能反过来宣称它绝不可能被支付。
