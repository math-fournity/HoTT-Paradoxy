# 四件套逐轮语义对齐治理修复

## 1. 事故与根因

2026-09-23，当前AI在解释用户“忽略构造过程”时，没有在该turn回核核心认知／扩展认知，而先读近期
审计报告与外部通常解释，将“对象构成、依赖落定、ASK与使用资格”收窄为“构造耗时”。直接证据见
[构造过程误读与认知消费审计](构造过程误读与认知消费审计-20260923.md)。

现有四件套治理对新Session、压缩、研究档和wave有强加载要求，但没有把“普通后续问答中解释／评价
用户核心概念”列为独立turn触发。F-014的历史证据已经明确`fresh model behavior NOT_RUN`；结构PASS只证明
文件身份、顺序和可用性。这次事故把该未知变成了行为失败证据。

根因不是文档缺失或用户没有说明，而是认知消费缺口：Session级“曾加载”被当作当前turn“已经使用”；
近期AI报告替代了用户原文；外部标准解释先于忠实复述取得判断权。

## 2. 最小修复

新增`CORE_SEMANTIC_REALIGNMENT_V1`，由根AGENTS持有always-on触发，PROTOCOL v3.1拥有完整执行合同，
项目治理Skill 4.1提供差异层提示，详细水合合同v1.1区分Session与turn证据。F-023拥有当前需求和交付状态，
rulings保存用户原意。

触发后：先读相关完整KC与扩展认知owner；跨主题、用户纠错／偏航或KC不确定时完整重读核心与扩展；
先固定`user_claim / forbidden_reduction / task_consequence / open_proof_obligations`，再允许外部评价；final
使用原文locator。纯机械turn不触发，但不得附带core语义判断。

没有新增摘要卡、语义数据库、Hook、常驻审计AI或自动意义判定。原因是这次首先是已有原文没有被消费，
多一份派生摘要会扩大漂移面；模型理解不能由脚本机械认证。
