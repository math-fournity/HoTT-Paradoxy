## 一、问题与判别目标

本工作单元检验一个容易混淆、但对“由代码视角寻找 HoTT 非现实性悖论”至关重要的问题：在 Cubical Agda 中证明某个对象程序永不停止，是否已经等于发现了 HoTT 自身的不可停机问题或非现实性推演？

判别必须分开三个事件：

1. 被建模程序是否在任意有限步内到达终止指令；
2. 对该性质的证明项是否由 Cubical Agda kernel 接受；
3. 对所有程序统一判定停机的算法是否存在。

R1 只处理第 1、2 项。第 3 项属于 R2，需要程序的有限代码、通用有界解释器、自应用或标准归约，不能从一个显然循环的例子推出。

## 三、机器证明的精确内容

### C-188：停机正控制

`haltProgram` 在初始状态的步数 `zero` 已位于 `halt` 指令；`halt-now` 构造命题截断中的有限见证：

```agda
halt-now : Halts haltProgram initial
```

### C-189：固定循环的逐有限步不变量

`loopProgram` 在所有标签上执行 `inc0 zero`。因此每次都把程序计数器送回 `zero`，终止测试在任意有限观察下标上都化简为 `false`：

```agda
loop-diverges : Diverges loopProgram initial
```

这里 `Diverges` 的定义是全称量词 `(n : ℕ) → DoesNotHaltWithin n ...`，不是某一次运行在有限观察窗内没有返回。

### C-190：没有截断的有限停机见证

`loop-not-halts` 把任何假想的截断停机见证消去到空类型：该见证要求终止测试为 `true`，C-189 对同一步数给出 `false`。

```agda
loop-not-halts : ¬ Halts loopProgram initial
```

命题截断在这里把“存在某个有限停机步数”处理成 mere proposition；证明只需否定这种存在，不选择或恢复具体见证。

## 四、边界裁决

本次结果完成 `R1-FIXEDMACHINE-001`，但没有完成长期目标。理由不是例子“不够复杂”，而是量词与机制尚未跨过以下边界：

- `loopProgram` 的循环由定义直接给出；尚未证明不存在覆盖全部程序和输入的总停机判定器；
- 本次 kernel 检查约 19 秒后正常结束。对象程序发散与证明检查器发散是不同命题；
- 命题截断参与 `Halts` 的接口，但同一固定程序结论可在更弱的依赖类型论中重现，尚无 HoTT 必要性；
- 没有真实下游 consumer 把较弱资格当作较强资格使用；
- 没有冻结现实任务、输入、观察与完成谓词，因而没有方向 A/B 的同任务现实对应；
- 没有 Gödel 编码、可证性谓词、反射、对角句或不完备性结论。

所以该包是计算语义的正负校准。它阻止机器统观把“一个固定循环”和“观察窗内未完成”误晋升为目标悖论，也为下一阶段提供了可复用的对象机定义。
