不把它表述为 source error。

## 2. 来源实际说了什么

IEP 的 Standard Solution 把 runner 的 path 表成以正、有限速度完成的 physical continuum；它把
速度、微积分、经典力学、实数时间的位置函数和 point-events 作为模型资源。它还将有选择公理的
Zermelo–Fraenkel set theory 称为多数观点中的实分析基础，并说它间接解决 Zeno。这些是一个真实的
**ZFC-supported standard-solution application** 的来源事实，而不是 bare ZFC 对物理运动的对象语言定理。

Norton 则把此次 source denominator 中的完成合同说得更精确：有限 action sequence 的严格读法是
“做完全部 action，包括最后一个”；对于没有最后 action 的无限 action sequence，他把 completion
缩减成“做完全部 action”，并说明删去 first/last-action 条件后，原来推出“跑者不能完成”的结论不再
成立。网页随后给每个编号 action 配一个时间。这是 completion 条件的明确改写；它没有给出从严格
first/last-action completion 到修订 completion 的等价定理。

## 4. 与现有机器核的关系

`HoTT/formal/zfc-actual-q-policy/ZenoSourceCompletionContract.lean` 中的 `C-362` 不声称证明网页或
bare ZFC。它在上述 source classification 已固定之后，证明一个严格的逻辑 control：

```text
RevisedAllActionsCompletion
∧ ¬ StrictLastActionCompletion
∧ ¬ OriginalBridge
```

此核与来源卡一致地说明：若 source 只认证 reduced contract，就不能从该来源语义**自动**导出 strict
original completion。它也有重要的反向含义：增补一个 rich completion-contract tag 或明确的 process code
可以区分这两类世界；所以本卡不支持“ZFC 无法表示时间、步骤、数列或过程”的说法。

## 6. 正反控制、自审与后继

**正控制。** IEP 确实给出连续模型、到达判词及其 ZF-with-Choice/real-analysis foundation framing；
这不是凭“ZFC 不含 time primitive”杜撰出来的 consumer。现有 rich-contract/process-code controls 也说明
更强观察接口在形式上可以保留 `OriginDone`。

**DifferentTask control。** Foundation 的 `Provable` task、Norton/IEP 的 motion-completion task、圆环的
reconstruction task 与 H0 的 finite-halt task 具有不同 input/operation/observation/Done。相同的自然语言
“完成”不能付出 `SameFullQ`。

**SOP §003 自审。** A-001 改变了 D-001 的判别面：从 proof acceptance 改为实际 motion-completion
consumer；固定了 source、版本读取日期、completion fields、反证条件和正反控制。它只关闭该来源分母，
不产生 bare-ZFC 结论。

**required successor：** `H-001 / M1-H0Map-candidate-reconciliation`。下一单位须只读核对另一 worktree
中 fixed H0 的最新候选及其 exact commit／dirty ownership，判断是否已存在可安全接入的 H0 semantic target；
若该候选仍未版本闭合或由他人占用，登记 `EXTERNAL_BLOCKED_WITH_SCOPE` 并转到不同 READY route
`GZ-012 / R4 representability boundary`。这个 successor 改变的判别面是 fixed H0 的 exact transport，
不是继续添加同类 Zeno 文献。

**reopen if：** 新的、版本固定的 source owner 明确把 bare ZFC 的 formal acceptance 本身提升为该 strict
过程／物理 completion 的充分条件，或提供同一任务的 bridge equivalence；或者研究发起人固定一个不同的
`OriginDone` 合同。
