# R03 HoTT重放与刀具角色向量

> **ParentReconciliationCard：** `R03 / A2 / PARTIALLY_SUPERSEDED_WITH_SCOPE / NOT_A_MATHEMATICAL_RESULT`。

R03原本把一条 HoTT 定向的盲态发现、固定来源对应和 P2/P3 排除控制概括为“从具体累积宇宙 `U` 的分阶段询问中生成
Candidate-Q”，并提出三把刀的角色向量。八张已完成原子卡支持这条链的实际结构：P1定位一个来源对应的完成询问，P2与
P3各自排除两种错误读法，最后由 Master 保留用户判断的 A 向任务范围。原子证据同时收紧了父级的强表述：这不是 HoTT
内部规则的矛盾、也不是独立现实消费者已经提出的理论级 Q；它是一个**来源对应且由用户判断任务忠实性的候选形状**。

## 3. P/Q影响、角色向量与被替换的表述

在固定来源卡的范围内，R03的可复算结构是：

```text
T/u/F/C/Q/I/O/Done
  = frozen HoTT-oriented source profile / U / askFrom→answer / source catalogue task /
    first now k / staged yes-or-no observation / first source-defined now k or finite runFor witness

P1 = POSITIVE_POSITION_AND_SOURCE_PROCESS_CORRESPONDENCE
P2 = EXCLUSION_CONTROL (no formula-level same-query reentry)
P3 = EXCLUSION_CONTROL (completion process is not admission lifecycle)
```

这里的 `C` 是来源中明示的目录／询问消费者，尚不是独立证实的现实消费者；因此这张结构表只给出来源和任务解释的范围。
它不能升级为“HoTT 自身要求无限计算”或“任何确认相同性的现实任务都无法完成”。

原 R03 使用的 `Q-2 ACTIVE_CANDIDATE` 语言在原子回放后应替换为：

```text
SOURCE_MATCHED_DEIDENTIFIED_CANDIDATE
  + USER_JUDGED_A_DIRECTION_WITH_SCOPE
  + P2/P3 EXCLUSION_CONTROLS
```

这不是撤回 H015 的发现作用，而是防止“来源对应的过程候选”被越级说成已由理论或现实消费者付款的 Candidate-Q。
因此原父级的整体结论属于 `PARTIALLY_SUPERSEDED_WITH_SCOPE`：完整发现→来源→控制链成立；其理论级 Candidate-Q
命名须降至上述范围。

`WQ-0003 / CONVERGENCE_SIGNATURE`仍保留为`HYPOTHESIS_RESTRICTED`：R03说明一把刀可以正向定位而另外两把刀作为
来源排除控制共同确定范围。它尚未证明其它理论，特别是 ZFC 的罗素式 B 向候选，可以降低 P2/P3 的正向要求。

```text
Target-Q               = HoTT定向来源卡中“相同／h-level询问何时完成”的任务形状
R03 Candidate-Q        = U 的过程是否交出 first now k（source-matched, user-scoped）
R03 Control-Q          = H011/H012及H016/H017的P2/P3排除控制；H018的任务分层
theory-Q delta         = NONE
ZFC_Q_LOCATED          = NO
```
