## 二、形式结构

### 1. 有限程序语法与总 decoder

```agda
data ProgramCode : Type where
  pcNil  : ProgramCode
  pcCons : Instr → ProgramCode → ProgramCode

decode : ProgramCode → Program
```

每个 `ProgramCode` 都是有限构造的指令表。表内按自然数标签查找，表外标签解释为 `halt`，所以 decoder 对所有标签都有结果。C-191 固定表头、表尾和空表外标签的三条计算方程。

### 2. 对全部有限表统一的有界解释器

```agda
runFor : ℕ → ProgramCode → Config → Config
```

`runFor` 对 fuel 做结构递归。这里的总性是严格的程序性质：无论输入程序表和状态是什么，只要 fuel 是一个自然数，解释器都会结束并返回一个配置。C-192 进一步证明它与 R1 的迭代语义一致：

```agda
runFor fuel code state ≡
iterate fuel (step (decode code)) state
```

对应的 `finalAt` 观察也与 R1 的 `isFinal` 一致。

### 3. 正负控制

C-193 证明单指令 `haltCode` 在任意 bounded observation 中均被识别为已经停机。

C-194 证明单指令 `loopCode`：

- 在任意精确有限步都没有到达 `halt`；
- 对任意有限界，`haltsWithin` 都返回 `false`；
- 不存在命题截断的有限停机见证。

这两组控制说明解释器没有把“fuel 用完”与“已经停机”混为一谈，也把 R1 的固定例子迁入了有限程序语法。

## 四、为何仍不能称为 R2 不可判定性

bounded evaluator 与 halting decider 的量词不同：

```text
bounded evaluator:
  ∀ fuel code input, 在有限时间内返回 fuel 步观察

halting decider:
  ∀ code input, 在有限时间内正确回答是否存在某个停机步数
```

前者已经构造；后者没有。枚举所有 fuel 可以在程序确实停机时最终找到见证，但对发散程序不会给出否定答案。C-194 的否定来自这个特定循环的归纳不变量，不是一个覆盖全部程序的算法。

因此以下义务仍然开放：

1. `ProgramCode` 的自然数编码／解码与往返或至少满射枚举；
2. 对 `(code,input,fuel)` 的公平 dovetailing 与 starvation 定理；
3. 当前语言的通用计算能力，或从已知不可判定模型到它的机器证明保真归约；
4. s-m-n／自应用／递归定理路线所需的代码变换；
5. 不存在总停机判定器的 certified theorem；
6. 第二内核的同题校准。
