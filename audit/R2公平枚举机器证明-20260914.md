## 一、工作单元

本工作单元关闭 `R2-FAIR-001`。R2 NATCODE 已使每个有限程序有自然数码；本轮再编码 `Config=(pc,r0,r1)` 与 `(programCode,inputCode,fuel)`，定义 `caseAt : ℕ → SearchCase`，并为任意有限 case 构造一个明确的 `caseIndex` 与不晚于该 index 的到达证明。

这里的公平性是全域有限阶段覆盖：没有某个有限 program/input/fuel case 永远被其它 case 挤掉。它没有声称编码索引很小、每个 case 只出现一次，或搜索已返回第一个停机 witness。

## 二、构造

源码：`HoTT/formal/cubical-machine-halting/FairEnumeration.agda`。

### 固定三元组与配置

三个自然数依次写成自定界一元位串，复用 `NatProgramCode.codeBits/unbits`。`readUnary` 在空输入上返回 0，所以 decoder 对所有自然数总定义。`decodeTriple-encodeTriple` 给像上往返；Config 把三个字段逐项映射到该 triple。

### 公平 schedule

```text
caseIndex p c f
  = encodeTriple (encodeNat p) (encodeConfig c) f

caseAt n
  = numbersToCase (decodeTriple n)
```

`caseAt-caseIndex` 组合 triple、program 与 config 三层往返。`AppearsBy stage target` 包含一个 `index ≤ stage` 与 `caseAt index = target`；`eventuallyVisited` 选择 `stage=index=caseIndex`，`noStarvation` 再封装存在有限 stage。

这不是把 surjectivity 换个名字：结果中保存了具体索引、有限阶段上界以及对应 case 的等式，可直接被下一轮搜索正确性证明消费。

### 观察连接

`observeAt n = haltsWithin (caseFuel (caseAt n)) ...`。`observeAt-caseIndex` 证明规范位置执行原 program/input/fuel 的同一 `haltsWithin`；halt 与 loop 控制确认编码／调度没有交换结果。

## 五、不能推出

本包没有构造一个不断推进 stage、遇到 `true` 才返回的 partial function；也没有证明 `CodeHalts` 与该过程返回之间的双向关系。因此它不等于 `R2-SEMIHALT-001`。

它同样不证明：

- 当前双计数器语言通用；
- 通用停机不可判定；
- s-m-n、自应用或 recursion theorem；
- Gödel/Rosser/Löb 或 exact HoTT 不完备性；
- 公平性依赖 HoTT 特有结构；
- natural consumer、现实 A/B 失配或内部矛盾。

下一项必须复用 `caseAt/noStarvation/observeAt-caseIndex`，构造停机的正半判定过程；在没有 finite witness 的分支保持 partial，而不是补一个默认 `false` 冒充总判定。
