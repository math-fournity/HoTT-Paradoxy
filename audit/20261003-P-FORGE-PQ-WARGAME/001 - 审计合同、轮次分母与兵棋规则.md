# 审计合同、轮次分母与兵棋规则

## 1. 目的与边界

本审计复查的是模式 P 的方法演化和来源受控的候选生成过程，不审判 ZFC 的数学一致性，也不把历史
worker 输出重写为新的理论证据。它问的是：**每一轮在当时真的改变了什么关于 Q 的可审计状态？**

“兵棋”在这里指反事实的研究流程推演：在不改变当时来源、模型运行或用户授权的前提下，分别比较实际选择
与“如果当时已要求 `QConvergenceLink`，哪一个节点应启动、停止或分叉”的选择。它不模拟未发生的数学结果，
不从隐藏推理推断动机，也不把替代路径当成已经验证的发现。

本审计覆盖：

```text
PRE_GOAL_HISTORICAL_CORPUS
  → 第一轮 P1/P2/P3 夹具和外部控制
  → HoTT replay / ZFC calibration / source / Battle / Tool-Birth / P3-C节点
  → H074/H075、CAL/station修订
  → 2026-10-03 P/Q共同锻造修订
```

它不覆盖一般 HoTT 机器统观、圆环主研究、未进入模式 P 工具系统的历史材料，或不构成自然锻造单元的
纯发布／翻译／归档提交。

## 3. 共同逐轮卡

每一轮只在上一轮卡已经封存后开始。它必须分别填写：

```text
Round identity / date window / exact evidence universe
Starting P state / starting candidate-Q state / known guards and unknowns
Actual move: source, fixture, prompt, tool revision, control or Battle
Actual Q delta: Q_GENERATE / Q_NARROW / Q_BRIDGE / Q_CONVERGE / Q_REJECT /
                 Q_SAFETY_REPAIR / NONE
Counterfactual: with today's QConvergenceLink, what would be launched,
                stopped, or classified differently?
Verdict: ALIGNED / IDEA_SPEC_INCOMPLETE / EXECUTION_DEVIATION /
         EXPECTED_CALIBRATION_FAILURE / RUNNER_OR_EVIDENCE_FAILURE /
         ORIGINAL_IDEA_CHALLENGED
Wealth: bounded future source, candidate, control, tool or audit question;
        status must be HYPOTHESIS / READY_FOR_FORGE_INTENT / REJECTED, never fact
Falsifier / next-round dependency
```

`Q_SAFETY_REPAIR`必须指向固定卡及回归；`NONE`不自动是失败，但若该轮被计作 P-FORGE 推进则构成
`TOOL_ONLY_DRIFT`。每张卡还需写清它是在审理论 Q、候选空间，还是 P 的发现能力；三者不能混成
一个“进展”标签。

## 5. 停止与写回纪律

1. 不因本表已列出所有轮次而声称完成；每一行都须有独立 round card、来源和反事实。
2. 一个 round card 可以提出多个 `Wealth` 项，但它们全部先是 `HYPOTHESIS`；只有有固定
   `T/u/F/C/Q/I/O/Done`、来源目标和反证条件者才可升级为 `READY_FOR_FORGE_INTENT`。
3. 单轮发现规格缺口时，可精确修订 SOP 并提交；后续轮次必须消费新版本，前序事实仍按当时合同审计。
4. 每完成一轮，更新索引状态、`MEMORY/001` 的下一轮和 Git 谱系；不将整份总结提前写成最终结论。
5. 现有 `/goal` 仍为 paused。本审计不运行新的理论节点、网络检索或外部 worker；未来财富只有在用户恢复
   P-FORGE 后才可进入 ForgeIntent。
