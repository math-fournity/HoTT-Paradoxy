# R15 原子锻打分母冻结与范围纠正

> **状态：** `COARSE_SCOPE_CORRECTION / ATOMIC_DENOMINATOR_PARTIAL / ATOMIC_AUDIT_REQUIRED / NOT_A_THEORY_RESULT`。

## 1. 触发：15、13 与实际锻打不是同一个数

研究发起人追问“审计了多少轮、实际锻刀过程是多少轮”。这暴露出 R14 的范围表达错误：

```text
15 = R00--R14 的审计卡数量
13 = R01--R13 的粗粒度自然单元数量
≠  实际 P-DAG 原子锻打／运行单元数量
```

R00是原初目标／分母基线，R14是粗粒度综合，二者都不是实际锻打。R01--R13各自又压缩了多个相互独立的
NodeCard、source-match、blind discovery、preflight failure、Battle、source control、方法修订与运行收据。
因此把13写成“实际锻打轮次”属于 `AUDIT_SCOPE_INCOMPLETE`：R00--R14仍是有用的宏观审计，不能被删去；
但它不满足“把之前每次实际锻打逐次审一遍”的原要求。

## 3. 后续细粒度审计合同

下一阶段不应再创建一个新的理论问题。它先建立一个按时间／依赖排序的原子 ledger，并对每个实际单元逐次写
`AtomicAuditCard`。每张卡至少包含：

```text
atomic id / parent coarse unit / exact NodeCard or report / terminal identity
actual action / source-visible inputs / prompt or runner result
QConvergenceLink effect or explicit Q_SAFETY_REPAIR target
counterfactual under current P/Q contract
classification / falsifier / downstream dependency
```

规则是：

1. 输入合同失败、隔离失败、Battle和修订不能因“没有数学输出”而跳过；它们要么保护固定Q卡，要么被标为
   `TOOL_ONLY_DRIFT`／运行证据故障。
2. 一个汇总报告含多个terminal node时，必须拆出每个node；一个node重复提及于多个报告时，只记一次并以
   exact run identity去重。
3. 保留 R01--R13 作为原子卡的父级因果图，不将它们删除或重新命名为原子事实。
4. 只有 exact ledger 的 `remainder=0`，才可重新把R14提升为“全过程完成”；此前只能称作粗粒度综合。
