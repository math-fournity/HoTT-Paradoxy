# R03 HoTT重放与刀具角色向量

> **状态：** `COMPLETE / TARGET_CANDIDATE_CONTROL_FIELDS_VALIDATED / CONVERGENCE_SIGNATURE_HYPOTHESIS`。

## 1. 链条与三层 Q 字段

H013、H014先把盲态输出从 Delay wrapper 与 schematic `C` 收紧到具体累积宇宙 `U`；H015再把局部
`judgeU k`问法收紧为整个 staged process 是否交出 first `now k`。H016/H017在同一固定 source card 上分别
给出 P2 不适用和 P3 completion-not-admission 的来源判词；H018把 formal process、source task 与用户的
A-direction判断分开。

用R02修复后的字段重放：

```text
Target-Q     = HoTT 中“相同／h-level 询问何时真正了结”的完成任务形状
Candidate-Q  = U 的 staged question 是否交出 first now k
Control-Q    = H016 P2 无 Bind/Form/Bridge/Reenter；H017 无 admission/operator edge；
               H018 的 task-fidelity分层
```

三层没有混淆：Target-Q没有被写成 source 事实，Candidate-Q没有被夸成现实任务定理，Control-Q也没有
被误写成 HoTT Candidate-Q。

## 3. 兵棋推演：会合不必等于三把刀都正向命中

R03 暴露当前 `Q-4 CONVERGED` 的一个待审假设。若它被理解成 P1、P2、P3 都必须给出同向的正义务，
那么 H015–H018 永远不能“收敛”：P1正向定位完成任务，P2/P3却以来源支持的负判词防止它被错误解释。
但这三份输出共同确定了这个 A-direction Candidate-Q 的正确身份和范围。

因此提出：

```text
WQ-0003 = CONVERGENCE_SIGNATURE
```

它不是“放宽三刀会合”。它要求每个 Target-Q 预先声明三把刀的预期角色向量，例如：

```text
P1 = POSITIVE_POSITION_AND_TASK
P2 = EXCLUSION_CONTROL
P3 = EXCLUSION_CONTROL
```

只有三个角色都在同一 `T/u/F/C/Q/I/O/Done` 上得到来源支持，才可说该 Target-Q 的**范围判词**收敛。
对于罗素式 ZFC B-direction，预期签名可能仍要求 P2/P3提供正向 reentry/admission 边；它不能借 HoTT A-direction
的控制签名降低门槛。
