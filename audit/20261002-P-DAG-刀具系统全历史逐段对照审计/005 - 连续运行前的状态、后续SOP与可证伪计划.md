# 连续运行前的状态、后续SOP与可证伪计划

## 1. 历史分界时的 honest state

```text
P1 blind process-shape replay: PARTIAL_PASS
source correspondence for Delay/Judge/now-later: MATCHED
P2 on the H010 source card: NOT_YET_REPLAYED_IN_THIS_CHAIN
P3 on the H010 source card: NOT_YET_REPLAYED_IN_THIS_CHAIN
same-real-task / UR mapping: NOT_YET_MAPPED

```

这是连续运行**前**唯一可由已有证据支持的状态。它不抹去早期 `P1/P2/P3-DELAY-001` 的 source-aware控制，却不允许拿旧 CLI control 代替这次 H010 的新 source card 接力。

## 2. 当前最小可验后继

下一条 DAG 不应再重跑同一盲 discovery prompt。它应固定 H010 source identity，分别启动两个 `PINNED_LOCAL_SOURCE`、`P-VALIDATION` 节点：

| Node | 允许可见材料 | 要回答的窄问题 | 预注册可接受状态 |
|---|---|---|---|
| H011-P2 | `QuestioningDelay.agda` 的 Judge、askFrom、answer、Halts 片段与 P2 卡；不含旧 P2 report。 | 是否存在 Bind/Form/Bridge/Reenter/normalization feedback？ | `NOT_APPLICABLE` 或有 source-backed chain；不能由普通递归硬造 feedback。 |

两个节点的公共输出必须是 E0–E7 MatchTrace，不请求隐藏 chain-of-thought。只有它们各自自然终态、通过 trajectory receipt，才由 Master 把结果与 H010 的 P1 card 放在同一 `T/u/F/C/Q/I/O/Done` 表中。

它们已在运行前冻结为：[H011 P2 NodeCard](../20261002-P-DAG-HOTT-VALIDATION-011-P2-NODECARD.md)／[prompt](../20261002-P-DAG-HOTT-VALIDATION-011-P2-PROMPT.md) 与 [H012 P3 NodeCard](../20261002-P-DAG-HOTT-VALIDATION-012-P3-NODECARD.md)／[prompt](../20261002-P-DAG-HOTT-VALIDATION-012-P3-PROMPT.md)。二者固定 `source-match` profile、同一 `QuestioningDelay.agda` hash、Terra/Max、zero tools、60 秒观察和无默认 hard timeout；冻结后的 bytes 不能为追逐预期 verdict 而改写。

即便 H011/H012 皆为 negative/not-applicable controls，也是一项正确的锻造结果：它能检验三刀不会在同一个“不断问”的表面形状上相互补字段。它不会释放 HoTT replay 或 ZFC gate。

## 3. `/goal` 连续运行的自审动作

每一个自然工作单元完成后，Master 在 `模式P动态DAG调度/005` 所要求的 SelfAuditCard 外，再更新本包的 delta 表：

```text
historical source unit(s) touched
actual NodeCard / prompt / source / wire / terminal evidence
alignment class and changed reason
what this run does not establish
whether it changes a tool, a runner, a source card, or only an audit statement
exact Git commit or NO_CHANGE reason
```

这不是新数据库，也不要求为没有变化的每一轮伪造 commit。它使将来能区分“理念最初就有问题”与“我们当时没有按理念运行”。

## 4. 观察优先的运行契约

对耗时较长的理论节点，以下是当前可审计的默认行为：

```text
0 < observation_interval_seconds      required
every unclosed observation window     private STILL_RUNNING receipt
automatic wall-clock interrupt        unavailable in the current runner
budget / loss / cancellation           Master review input, never a seconds-triggered interrupt
manual interrupt                       separate capability; not yet qualified by this runner
```

“超过 60 秒”不是失败，“思考十分钟”也不是异常。当前 runner 不把任何经过时间作为停止条件；预算、worker 失联和用户取消只能触发 Master 的实时复核，不能自动中断。H010 的历史 180 秒不得被回写；后续超过一个观察窗的真实 node 需要检查 liveness 轨迹是否足以区分仍在运行、已失联和已终态。此次收紧属于`IDEA_SPEC_INCOMPLETE → REPAIRED`：原有“无默认短上限”仍不足以排除将来以可配置参数重新引入秒表中断，修订后该路径从当前 runner 删除。

## 5. 完成与重新开启条件

这项**历史审计**在下列条件满足后可以被认为完整：来源分母、每个 source unit 的 in/out 处置、每项实作映射、偏差分类、反事实与分界时状态均已写清，且结构／链接／Git diff 通过。它不等于 P-DAG 数学研究完成。

P 工具链只能在以下任一事实发生时重新开启完整审计，而非仅追加一段总结：

- 用户修改 P 的原初含义、三刀数目、成功定义或 actor 授权；
- 新 worker、source card、trajectory shape 或 isolation boundary 改变；
- H011/H012及H013–H022的后继发现某一刀职责变化、同卡字段泄漏或冻结relay失效；
- HoTT replay release、ZFC upgrade 或 P4 proposal 被提出；
- 有直接正／负控制挑战本包 004 §4 的任一判词。

在上述条件前，下一步是补上同一现实任务／UR 映射，或冻结另一个不泄漏的 HoTT P1 source profile，而不是用更多无关 ZFC 搜索替代 HoTT holdout。
