## 3. 新花纹与新刀具的出生审计

用户已明确：老刀的“惯性系”可能限制它能表达的花纹宇宙。新刀具可以由一把或多把老刀派生，也可以是无法被旧刀字段、反控制和验收语义容纳的全新花纹。以下合同替代“永远不创建 P4”的静态假设。

### 3.1 先做容纳判定，不能凭新奇命名

对每一个 `NEW_PATTERN`，Master 必须写一张 `Tool-BirthCard`，逐项回答：

| 审计问题 | 必须给出的证据 |
|---|---|
| 花纹是什么？ | 一个固定理论卡／过程／来源中的最小可复现结构，含输入、观察、完成条件和反控制。 |
| P1 能否忠实表达？ | 尝试映射到对象、formation、consumer、Q、same task；若失败，指出哪个必要字段不存在或被扭曲。 |
| P2 能否忠实表达？ | 尝试 Bind/Form/Bridge/Reenter/Polarity/Guard；不能只说“不是逻辑”。 |
| P3 能否忠实表达？ | 尝试 Draft/NeedBuild/NeedEval/Admitted/OperatorUse/BuildDone；不能只说“不是时间”。 |
| 是遗漏、冲突还是外部噪声？ | 以既有 source、正负控制和当前 card 判定 `OLD_TOOL_FIELD_GAP`、`CROSS_TOOL_CONFLICT`、`RUNNER_EVIDENCE_FAILURE` 或 `UNCONTAINED_PATTERN_CANDIDATE`。 |
| 新刀为何必要？ | 证明至少一个理论判断职责、最小正控制、最小负控制和对同一 ZFC/HoTT card 的增量，均不能由修 P1/P2/P3 达到。 |

### 3.2 三种出生结果

| verdict | 含义 | 允许动作 |
|---|---|---|
| `OLD_TOOL_FIELD_GAP` | 花纹可由旧刀表达，只是字段、guard、prompt、source card或验收遗漏。 | 修旧刀，保留旧失败，做同卡回归；例如 D-L10F。 |
| `DERIVED_TOOL_CANDIDATE` | 新责任只在已有两把或三把刀交界出现，可定义为显式组合 operator，但其基本判断仍可还原。 | 先写派生 contract、正负控制和与原刀的非重复证明；未验前不编号新刀。 |
| `UNCONTAINED_PATTERN_CANDIDATE` | 花纹的最小判断职责无法忠实映射到 P1/P2/P3；强行映射会改变对象、过程、观察或 Done。 | 建立新刀提案，冻结独立命名、输入、判词、正负控制、source/worker plan、Git lineage；只在至少一次正反控制后升级为新刀。 |

`P4` 不是保留名或自动下一个编号。当前 `RK-0` 明确是 `DERIVED_SHARED_ANVIL_NOT_P4`：它只让 P1/P2/P3共同消费同一 formation-promotion pattern，没有新增独立理论判断职责。

### 3.3 连续 SOP 的强制自审增量

每个自然锻造单元的 SelfAuditCard 除既有“原初理念／规格／执行／证据”判断外，必须增加：

```text
pattern-universe claim:
  Which P1/P2/P3 inertia was applied?
  What pattern features fit / did not fit?
  Was the failure caused by source absence, prompt compilation, an old-tool field gap,
  a derived-tool boundary, or a genuinely uncontained candidate?
  Tool-BirthCard required? yes/no, with reason.
```

这一步不是自动创建刀具，也不是为每个困难另建流程。它确保未来不会把“老刀的花纹宇宙容不下”误报为理论失败、模型幻觉或用户理念被反证。
