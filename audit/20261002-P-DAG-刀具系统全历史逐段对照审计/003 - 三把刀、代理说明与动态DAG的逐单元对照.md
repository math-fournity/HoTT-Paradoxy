## 5. U18：动态 DAG 是调度职责，不是多数投票机器

U18 明定 P1/P2/P3 可以由不同 external worker 使用；节点可按目的选择盲态、项目分支、来源或网络；冲突才有 Battle；Master 也要可被质询；这个调度能力要成为项目 SOP。

| 要求 | 现有实现 | 保留边界 |
|---|---|---|
| 各刀独立 worker | NodeCard、access profile、fresh-per-node、P1/P2/P3 可分开启动。 | 不用 native subagent；不把相同 agent 的重复输出算独立证据。 |
| 访问按节点开关 | `BLIND_CARD`、`PINNED_LOCAL_SOURCE`、`PRIMARY_WEB_SOURCE`、`PROJECT_EVIDENCE_REVIEW`、`BATTLE_PACK`。 | 允许 source 并不允许答案泄漏；网络和 dev/main 不是全局开关。 |
| 有分歧才 Battle | challenge → reply → independent arbiter → Master verdict。 | Battle 不投票，不读取隐藏 CoT；无新增证据停 `BATTLE_INCONCLUSIVE`。 |
| Master 有判断也可被挑战 | source／运行／控制优先于 Master 文字；旧 Battle-001/002。 | Master 不能用自己的总结填 source 缺口。 |
| SOP 可发现 | 项目 Skill、TASK_ROUTING、DAG index 和 README 路由。 | 文档没有授权自动启动 node 或修改数学 STATE。 |

判词为 `ALIGNED_WITH_REPAIR_HISTORY`：早期 source nodes 的预封存、URL 和终态策略不完整，后来通过 NodeCard／failure taxonomy 补全；这属于 `RUNNER_OR_EVIDENCE_FAILURE`，不制造新刀。

## 6. U19：观察优先替代统一短墙钟

U19 指出 180 秒对于 Terra/Max 理论推理可能不够，且 App Server 已提供 thread/turn/wire 的实时观测，所以没有理由把短墙钟当作默认失败。当前实现将 NodeCard 改为：

```text
observation cadence = 60 seconds by default
hard timeout = absent by default
terminal interrupt = only after a pre-frozen positive hard-stop predicate
```

旧 H010 NodeCard 仍如实记录当时的 180 秒和 20 秒 grace；不能用新政策篡改历史。H010 在 91.081 秒自然终态，因而它并未实际受该上限截断。当前唯一验证是 runner 的 CLI／参数拒绝与自然终态；尚未有超过一个观察窗的真实理论节点验证 `STILL_RUNNING` 连续收据。这个剩余缺口写入 005 的后继条件。
