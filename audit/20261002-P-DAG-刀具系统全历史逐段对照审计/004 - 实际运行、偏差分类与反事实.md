## 3. H010 的五层事实

| 层 | 当前收据支持 | 状态 |
|---|---|---|

| 工具行为 | direct wire 审计为 0 command、0 file change、0 approval。 | `SUPPORTED_FOR_H010_SCOPE` |
| P1 发现 | `Delay(ℕ)`／`now/later`／“是否会出现 now k”与 source process shape 对应。 | `P1_PROCESS_SHAPE_PARTIAL_PASS` |
| 理论／现实结论 | P2、P3、real task／UR、universe specialisation 都未由 blind output 完成。 | `NOT_PASSED` |

H010 不应用以下错误读法：

- 它不是“HoTT 不一致”的证据；
- 它不是“原来的 HoTT 问题已经重新定位”的充分证据；
- 它不是 P3 的正命中，因为 source 没有显示 Draft/Admitted/OperatorUse 的资格循环；
- 它也不是 P2 命中，因为 source card 没有 formula binder、bridge、合法 reentry 和 feedback；
- 它仍是有价值的 P1 calibration：在不见项目答案的条件下，模型重抓到了原来过程的对象／完成形状。

## 4. 三个可证伪的总体判词

1. **P3 是否直接保存张力。**当前回答 `YES_AS_A_TOOL_SPEC`：P3 的状态语言直接问“未获准的 `u` 是否已被 operator 使用”。若未来 P3 只剩 “later/never” 或泛化循环而不再要求 operator、admission、same-object edge，则这份判词立即失效。
2. **P1/P2/P3 是否不同。**当前回答 `YES_WITH_CONTROLS`：Delay card 已出现 P1 process、P2 not-applicable、P3 completion-process/non-admission 的不同状态。若一个新收据为让三刀“会合”而用 P1 的 source contract 填 P2 bridge 或 P3 transition，则应判 `CROSS_TOOL_FIELD_LEAK`。
3. **动态 DAG 是否实现用户要求的控制。**当前回答 `YES_FOR_THE_SAVED_NODE_TYPES`：NodeCard、access profile、source/Battle、Master verdict、trajectory receipt 都存在。若发现节点可在没有冻结 source／prompt／model echo 或无 terminal evidence 时仍改变 current verdict，则应撤回此判词。

## 5. 对“新的刀具”的裁定

`NO_P4_JUSTIFIED_YET`。新刀具至少需要同时满足：

1. 它问的是不同于 P1 的位置／consumer、P2 的语言反馈、P3 的构造资格次序的理论问题；
2. 它有自身的最小正控制与负控制；
3. 它能在同一冻结 ZFC 或 HoTT card 上贡献一个不能由三刀现有字段表达的判断；
4. 它不是 timeout、prompt 包装、trajectory parser、权限或 source 缺失的工程缺口；
5. 它通过 source-aware `MatchTrace` 被说明，且与用户原初张力的关系明确。

当前尚未达到这些条件。拒绝仓促建立 P4 是对 U11 的尊重：三把刀的不同惯性应先真正被打磨，而不是每次发现运行缺陷就改变理论工具的数目。
