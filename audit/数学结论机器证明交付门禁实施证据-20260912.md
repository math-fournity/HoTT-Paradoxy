## 1. 验收主张

本轮只实施治理规则，不提出新的数学命题。因此本轮不需要、也不应伪造一个数学 proof package。验收对象是：未来当前 AI 能否在交付数学结论前找到并执行明确门禁，以及证明源码、运行原件和索引是否有唯一项目内归属。

| 主张 | 实现 | 验证 | 边界 |
|---|---|---|---|
| 数学结论交付前必须机器证明 | 根/`.codex` AGENTS、PROTOCOL、双 Skills | static verifier marker/term check | 不证明未来模型一定遵循 |
| 证明源码不放在 `/tmp` 唯一副本 | `HoTT/formal/` contract | exact authoritative root check；`/tmp` 负向 | `/tmp` 仍可作可删缓存 |
| 实际结果必须持久化 | `HoTT/verification/runs/<run-id>/` | required five-file contract | 本轮无数学 run，不制造空假收据 |
| 每项结论可由索引定位 | `HoTT/CLAIM_EVIDENCE_MATRIX.md` | marker/root/link check | 旧 aggregate proofs 标历史、需重放 |
| 无证明时不交付为结论 | AGENTS/稳定规范/Skills | 要求存在降格状态词 | static text 不等于行为验收 |
| HoTT 特定语义不被普通测试替代 | AGENTS/稳定规范/formal README | contract inspection | 每个未来 proof 仍需逐命题验证 |

## 2. 权威路径

