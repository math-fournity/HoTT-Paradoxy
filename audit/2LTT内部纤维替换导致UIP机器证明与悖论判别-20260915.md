## 1. 本轮回答的精确问题

2LTT 一手论文 §2.7 报道：同伦模型通常能在外部逐对象取得 fibrant replacement，但这种构造一般不在 base change 下稳定；如果把它提升为在任意上下文中可形成、引入、消去和计算的内部 type former `R`，内层理论会满足 UIP。本轮不重复转述，而是检查三个可分离问题：

1. 论文式 (2.13)/(2.14) 到 inner UIP 的推演能否在项目固定 proof assistant 中由内核接受；
2. 哪些规则真正被证明使用，特别是 COMP-R 是否必要；
3. 结果究竟支持“HoTT 自身矛盾”、一个已知扩展边界，还是用户方向 A/B 的待桥接候选。

## 2. 为什么不能直接用单层 Cubical `Type` 浅嵌入

若把外层类型和内层类型都解释成宿主 Cubical Agda 的普通 `Type`，宿主的路径消去器可以直接把一个内层路径消去到任意所谓“外层”命题。这会绕开论文中最关键的步骤：外层命题必须先由 `R` 变成内层类型，才能成为内层路径归纳的 motive。这样的证明即使通过，也不能说明 `R` 做了什么。

本包因此采用边界保持的代数接口：

- 外层类型是普通 Agda `Type`；外层等式是归纳等式 `E._≡_`；J 来自该等式，UIP 是显式字段 `strictUIP`；
- 内层类型由 `Inner : Type₁` 的 code 与 `El : Inner → Type` 解释；
- `Idᵢ/reflᵢ/Jᵢ` 是内层恒等结构，且 `Jᵢ` 的 motive 必须返回 `Inner` code；
- `Πᵢ/lamᵢ/appᵢ` 提供从 based UIP 到一般 UIP 所需的内层函数类型；
- `R : Type → Inner`、`r`、`elimR` 对应 FORM-R、INTRO-R、ELIM-R。

代码没有 `postulate`、未解洞、终止/正性/宇宙检查绕过。record 字段明确列出条件；它们不是被伪装成无条件定理的宿主公理。

## 3. 机器证明路径

### 3.1 严格环路的 canonicalisation（C-227）

`encode` 用外层 J 把严格等式 `u E.≡ v` 送到内层 `Idᵢ A u v`，并在严格反身时定义性化为 `reflᵢ`。对严格环路 `h : u E.≡ u`，`strictUIP h E.refl` 给出外层等式；`strictCong encode` 把它送到两个内层路径项之间的外层等式；再次 `encode` 得到内层二阶路径：

```text
encode h =ᶦ reflᵢ
```

这对应论文式 (2.14)。

### 3.2 路径依赖外层见证的统一内化（C-228）

源码固定：

```text
StrictWitness A u v p
  = (h : u E.≡ v) → encode h =ᶦ p
```

它是外层类型，并依赖内层路径 `p`。`lifted-witness` 对 `p` 做受限内层 J；motive 不是 `StrictWitness ... p` 本身，而是 `R (StrictWitness ... p)`。只有 context-uniform `R` 能让这个 motive 成为内层 code。反身分支由 `r strict-loop-canonical` 给出。这是论文式 (2.13) 的机器对应，也是本现象中“理论经济提升”的精确位置。

### 3.3 从 R 见证到 UIP（C-229/C-230）

`recR` 是 `elimR` 在常值内层 family 上的派生特例。它把 `lifted-witness p` 映射到 `p =ᶦ reflᵢ`：给定一个 `StrictWitness`，在 `h = E.refl` 处求值并对路径取内层对称即可。`based-uip` 因而收缩任意内层环路。内层 Π 与一次 `Jᵢ` 再给出：

```text
inner-uip : (p q : Idᵢ A x y) → Idᵢ (Idᵢ A x y) p q
```

`NontrivialInnerLoop` 把一个环路和“它不等于反身”的反证器打包；`replacement-excludes-nontrivial-loop` 直接把 `based-uip` 送入反证器，得到 `⊥`。

## 4. 控制与消融

### 4.1 原生 HoTT 高阶控制（C-231）

同一 Agda 文件在抽象模块外使用原生 Cubical `S¹`。Möbius family 在 `base` 上取 `Bool`，沿 `loop` 取 `notEq`；若 `refl ≡ loop`，对 `false` 的 dependent transport 会推出 `false ≡ true`。因此内核接受 `refl≢loop` 和对称的 `loop≢refl`。

这个控制证明通常 Cubical HoTT 确实具有 UIP 会删除的高阶结构。它没有把原生 Cubical `Type` 冒充为上述 abstract record 的完整模型；两者的模型对应仍由 2LTT 语义承担。

### 4.2 删除 strict 两层桥的正控制（C-232）

在单一 Cubical universe 中定义：

```text
NativeR X = X
native-r x = x
native-elimR P d z = d z
```

这同时具有 FORM、INTRO 和 dependent ELIM 形状，并与原生 `S¹.loop ≠ refl` 共存。故“存在一个叫 R 的形成/消去接口”本身不是失败原因。决定性组合是：

```text
outer UIP
  + strict equality → inner equality
  + R 对依赖内层路径 p 的外层 StrictWitness p 统一可用
  ⇒ inner UIP
```

### 4.3 COMP-R 消融

`TwoLevelReplacement` 没有 COMP-R 字段，证明体也没有对应计算律。C-227–C-230 因而证明：FORM-R、INTRO-R 和 ELIM-R 的常值 family 特例已经足以产生 UIP。这个结论比“form-R 到 comp-R 全部假设后推出 UIP”更精确；它没有宣称 ELIM-R 可进一步删去。
