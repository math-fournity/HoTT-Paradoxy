# P-DAG P1 形成起源路径：H040–H042 的原初理念对照与规格修复

> **身份：** `DELTA_SELFAUDIT / P1_FORMATION_ORIGIN_REPAIR / H040_H042_SCOPE_CORRECTION / NOT_A_ZFC_Q_OR_MATHEMATICAL_CLAIM`。

## 1. 触发事实

H040–H042 的盲态“平衡基础承诺画像”以六项明显承诺测试 P1，并最终取得 runner-valid 的：

```text
NO_MODEL_RECALL_CANDIDATE / DIRECT_PAYMENT_ONLY
```

该输出当时被记录为“平衡画像无候选”。H040/H041 的冻结 prompt 却同时写了两条决定性的编译约束：

```text
Q? must be a prospective native declared operation/judgment/consumer task.
If the visible formation itself directly supplies Q?, mark DISCOVERY_DIRECT_RULE_ANSWER.
```

它还把 D-L10 实施为“不得从 bare existence/forming statement 变出 checker/service/consumer”。这个防止 `∃r` 被偷换成 `judge(r)` 的控制本身是正确的；但该 prompt 没有给“核心 formation 自己尚未支付的完成性追问”留下输出通道。

## 2. 与原初用户理念和 P1 当前规格的逐项对照

| 权威材料 | 它要求什么 | H040 编译后的行为 | 判定 |
|---|---|---|---|
| 用户原文／`rulings.md` §“P 是放大镜” | ZFC 首点固定为 Power Set；第一义务是从 **Power Set 自身的形成承诺** 导出存在性追问 Q。 | profile 提供“形成一个正好包含所有子集合的集合”，却要求 Q? 必须是 consumer/judgment/service。 | 形成起源路径被遗漏。 |
| 用户原文／`rulings.md` §“一遍匹配” | 先从明显承诺生成线索，之后再核证。 | `NO_MODEL_RECALL_CANDIDATE` 被 consumer-only screen 触发。 | 不能作为完整 P1 一遍匹配的反例。 |
| P1 `L7` | Q 可以是 consumer 的正完成前提，**或 formation 尚未支付的形成义务**。 | H040 将 formation 一律按 direct answer 处理。 | P1 抽象规格与 prompt compiler 不一致。 |
| P1 `D-L10` | 禁止从存在断言偷换出未声明 `judge(r)`／checker。 | 正确拒绝了未声明 checker，但没有区分“形成 F 自己已被 profile 声明”为原生 operation。 | D-L10 需要路径分支的明文化。 |

## 3. 自审结论

```text
original user idea: NOT_CHALLENGED
P1 abstract method: IDEA_SPEC_INCOMPLETE at the formation/consumer boundary
H040–H042 prompt compilation: EXECUTION_DEVIATION / FORMATION_LANE_OMITTED
H042 strongest valid scope: CONSUMER_ONLY_PROFILE_NO_CANDIDATE_WITH_SCOPE
invalid inference: H042 => all P1 formation-origin routes have no candidate
```

这不是把“存在公理”重新包装成 Q。formation-origin lane 仍需使 Q 不是“`u` 是否存在”的重述，也不是可普通返回 false 的 membership query，更不是研究者发明的 checker。它要求从同一核心 formation `F` 的完成／可用资格／自指或上升式探针中给出一个可由 P2/P3 后续拆解的 **未直接支付追问**。

## 4. 修复：P1 的两条发现路径

| 路径 | 可以作为过程起点 | 禁止偷换 | 验证后的上限 |
|---|---|---|---|
| `C-lane`（consumer-origin） | 来源明示的 judgment/consumer/task，有或预指向 C/I/O/Done。 | 从 `∃r` 发明任意 `judge(r)`。 | 可走完整 consumer TaskCard。 |
| `F-lane`（formation-origin） | profile 明示的核心 formation rule/axiom/interface 自己。 | 把“F 已断言 u 存在”重复为 Q；从 F 发明外部 checker。 | 可交给 P2/P3 作 formation-origin probe；C/I/O/Done 继续 `UNKNOWN`，不可称 `ZFC_Q_LOCATED`。 |

F-lane 的最低条件为：

1. 精确的理论内 `u` 和已声明的核心 `F`；
2. Q? 直接问 F 所承诺的**完成／资格／同一对象自指或上升依赖**，不是外加的属性测试；
3. Q? 不由 F 的 witness/definition/axiom立即清偿；
4. 明示哪一类 P2 re-entry、P3 admission 或同一任务 consumer source 将来能够使它被证实或击落；
5. 保持 `MODEL_RECALL_SITE_CANDIDATE / FORMATION_ORIGIN_PROBE`，直到同一 source task card 补齐或反驳。

## 5. 后续可证伪重放

下一节点应当只给脱敏的“所有子集合形成”核心承诺及 F-lane 规则，不出现 `Power Set`、`ZFC_Q_LOCATED`、旧答案或来源文本。它必须：

- 先比较 F-lane 与一个邻近核心承诺；
- 若选 formation-origin candidate，公开给 `u/F/Q?`、为什么 Q? 不等于“u 存在”、最小 self/ascent/completion trace、以及需要何种 P2/P3/consumer source 才能验证；
- 若无候选，返回严格的 formation-lane no-candidate，而不是 consumer-only no-candidate；
- 不产生数学结论、UR 或 ZFC Q。

这次修复不创建 P4：它只恢复 P1 自身早已承认、却未被 H040 prompt 编译出来的 formation-origin 责任。
