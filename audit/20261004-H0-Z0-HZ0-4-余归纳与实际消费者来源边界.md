## 1. H0 的余归纳时间结构是独立依赖

此前 H098 已把 universe proof 的高阶侧展开为 `EM₁ + Susp + truncation + univalence + universe`。H100-A 发现，H0 还有一个不能省略的过程侧依赖：

```text
data Delay' A = now A | later (Delay A)
record Delay A where coinductive; field force : Delay' A
never.force = later never
runFor n = finite unfolding observation
```

`question = never` 的机器结论因此不是仅关于一个抽象命题的无限性；它依赖该余归纳对象、`force`、`later` 与所有有限 fuel observation 的关系。

Cubical Agda 论文支持“copatterns 使 bisimilarity 与 path equality 对齐”的语言能力。它没有在本次来源范围内给出 exact `Delay/force/later/never/runFor` 的 denotational set-theoretic model。

Guarded Cubical Type Theory 和 Clocked Cubical Type Theory 是重要的正向邻居：它们将“later”写入 calculus，并在 presheaf 中给 guarded recursive types 语义。可是它们把 delayed availability 置于 guarded modality／clock discipline 中；一手来源还把 first-class coinduction 的某些能力列为后续扩展。它们没有定义 fixed Cubical Agda H0 的 unguarded coinductive record map。

H100-A 的来源裁决：

```text
COINDUCTIVE_DELAY_GUARDED_VARIANT_GAP_WITH_SCOPE
```

## 2. 已经找到了真实的 Cubical Agda 数学消费者，但它不是 H0 消费者

Ljungström–Mörtberg 2023 是一条真实而重要的 `C_accept` 正控制：论文把 `π₄(S³) ≅ ℤ/2ℤ` 描述为 complete Cubical Agda formalisation、fully formalised computer-assisted proof，并报告 `--safe`、无 admitted goals/postulates 和一个规范化到 `-2` 的 Brunerie number。

这足以说明“同行评议数学论文把固定 Cubical Agda formalisation 的 typechecking/normalisation 当成一个数学结果”是可定位的实际来源行为。

但是它的字段是：

| 字段 | π₄ paper 的实际值 | H0 所需值 |
|---|---|---|
| 输入 | π₄(S³) formalisation 与 Brunerie-number computation | fixed `QuestioningDelay` package |
| Done | formalisation/typechecking + specified normalisation | finite `now k` / halt witness |
| 输出 | `π₄(S³) ≅ ℤ/2ℤ` | H0 的 process completion observation |
| H0Map | 无 | exact translation required |
| foundation/ZFC adequacy | 无 | explicit `C_accept` + `AdequacyLift` required |


## 5. H0→Z0 现在收束到的两项义务

H0-Z0 的来源阶段不再继续用主题相似性扩张。以后只有以下两种新证据会改变当前判词：

1. **Exact semantic transport**：版本固定地解释 Cubical Agda 2.8.0 + cubical 0.9 中的 `EM₁`、HIT、universe、un-guarded coinductive Delay、QuestioningDelay；并证明／反证 finite `runFor`、`now`、halt witness 与 `never` observation 的保持或反射。
2. **Actual H0 consumer**：一份真实来源以 fixed H0 或上述精确 translation 为输入，声明具体 I/O/Done，并把 model／proof result 提升为 foundation/process adequacy，或明确拒绝这一步。

这两项之前，HZ0-3/HZ0-4 不能进入机器化为“ZFC 有 Q”的证明。可形式化的只是条件命题或局部 Delay control，不能替代整个 H0Map。
