## 一、工作单元与父任务

本工作单元关闭 active goal 中的 `R2-NATCODE-001`。父模块 `ProgramCode.agda` 已有有限指令表、总 decoder 与以外部 fuel 递减的通用有界解释器；本轮给 `Instr` 和 `ProgramCode` 增加自然数代码、全域 decoder、合法像往返及数值解释器语义保持。

完成该单元并不等于 R2 完成。下一依赖是 `R2-FAIR-001`：为 program code、input/config code 与 fuel 构造公平、无饥饿的联合枚举；之后才是停机正半判定、语言通用性和 certified undecidability。

## 二、编码与 decoder

源码：`HoTT/formal/cubical-machine-halting/NatProgramCode.agda`。

1. 自然数参数使用 `trueⁿ false` 自定界一元码。
2. 五个指令构造子使用固定三位标签：`000/001/010/011/100`。
3. 有限程序表以 `true` 引入一条指令，以 `false` 终止。
4. bit list 由 `codeBits` 按最低位优先、带 sentinel 的方式编码为 `ℕ`；`unbits` 以代码本身为 fuel。
5. streaming decoder 对 fuel 和 bit list 同时有默认分支；显式 stack 在读完后部程序时恢复前部 `pcCons` 顺序。

非法输入策略不是隐藏的 partiality：

- fuel 为零或输入提前结束返回 `pcNil`；
- 三个未分配标签 `101/110/111` 都解释成 `halt`；
- `decodeNat-zero` 与 `decodeNat-invalid101` 分别给空码和一个实际自然数非法标签码的机器控制。

`Instr` 的自然数编码使用单指令程序嵌入；`decodeInstrNat` 对空／异常程序码返回 `halt`，合法像满足往返。

## 三、证明结构

### C-195：总编码／解码与非法码语义

`run` 在 fuel 上结构递归，所以 `decodeNat : ℕ → ProgramCode` 对全部自然数有定义。三个 parser-state 非法标签等式与一个具体自然数码控制由定义性归约闭合。

### C-196：像上往返、单射和覆盖

证明链是：

```text
bit packing 两侧方程
→ 已知长度的 unbits/codeBits 往返
→ codeBits 支配位串长度
→ unary 参数 parser
→ Instr parser
→ ProgramCode parser
→ decodeNat (encodeNat p) = p
→ encodeNat 单射 + decodeNat 对全部有限程序覆盖
```

长度界使用 `Cubical.Data.Nat.Order` 的差值见证次序。最终证明不依赖自定义 indexed-order transport 行为，final run 无 warning。

### C-197：数值解释器语义保持

`runNat/finalNat/haltsWithinNat` 先调用 `decodeNat`，再调用 R2 原有解释器。把 `decodeNat-encodeNat` 通过 `cong` 运输，得到三个对所有程序、状态、fuel 成立的像上等式。

### C-198：正负控制

编码后的 `haltCode` 保持任意界内 `true`；编码后的 `loopCode` 保持任意精确有限步和任意有限界内 `false`。这里没有新增无界循环定理；它复用 R2 的已证控制来验证数值层没有改变任务。

## 五、开发中发现并修复的三个问题

1. 初版 stack constructor `_▷_` 与 Cubical Prelude 的 path whiskering 运算符重名，Agda 以 `ClashingDefinition` 拒绝；改成具名构造子 `push`。
2. 初版沿用普通 Agda `rewrite`，Cubical Path 并不是内建 equality rewrite 的绑定，Agda 以 `NoBindingForBuiltin EQUALITY` 拒绝；所有相关证明改为 `cong`、`subst` 与 path composition。
3. 第二版自定义归纳次序的传递性虽 exit 0，却产生 `UnsupportedIndexedMatch` warning；它被 Cubical 库以差值 `Σ` 见证定义的 `Nat.Order` 取代，最终 full recheck 零 warning。

这些失败没有被包装成研究突破；它们说明为什么 final source 采用当前路径。

## 六、不能推出

本包没有证明：

- 公平枚举 program/input/fuel；
- 当前指令语言 universal；
- 通用停机不可判定；
- s-m-n、程序自应用或 Kleene fixed point；
- Gödel、Rosser、Löb 或 exact HoTT 不完备性；
- 任何编码困难是 HoTT 特有；
- natural consumer、现实同任务 A/B 失配；
- HoTT 或 Cubical Agda 内部矛盾。

`decodeNat` 对程序表的覆盖只说明每个有限程序在自然数枚举中有位置。只有为所有相关维度给出公平 pairing／dovetailing 并证明每个有限见证最终被访问，才可进入 `R2-SEMIHALT-001`。
