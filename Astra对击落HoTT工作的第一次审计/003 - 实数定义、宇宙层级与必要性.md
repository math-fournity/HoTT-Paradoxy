# 实数定义、宇宙层级与必要性

## 1. A02：`dcut` 并未忠实照录 Book 的 locatedness
<!-- audit-cites: C003-01 C003-02 C003-03 -->

原典 §11.2 明确引用 §3.7 的逻辑记号。后者规定析取是命题截断的和：`P ∨ Q := ∥ P + Q ∥`。证据是本地 [logic.tex:647](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/theory-schema/upstream/book-578b85cc/logic.tex:647) 与 [reals.tex:191](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/theory-schema/upstream/book-578b85cc/reals.tex:191)。公开来源：[Book logic.tex](https://github.com/HoTT/book/blob/578b85cc8d586b1677ec4335148adeb443057d24/logic.tex)。

实际 [CutRealLayer.agda:110](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/CutRealLayer.agda:110) 却是：

```agda
((q r : ℚ) → (q < r) → fst (L q) ⊎ fst (U r))
```

应逐项对照的原典形状是：

```text
(q r : ℚ) → q < r → ∥ fst (L q) ⊎ fst (U r) ∥₁
```

这是**规格忠实性缺陷**，不是代码排版差异。当前定义要求每个输入区间返回一个被标记的分支；原典只要求命题意义的析取。`q < r` 也不是 `L q` 与 `U r` 互斥的依据。当前源码 §7.1 自己说明两边可以同时成立，继而使用 `isSet⊎`，最终只证明了 `isSetDCut`。原典则把整个 `dcut(L,U)` 称为 mere proposition。

不能以“总空间仍然是 set”消除问题：**set 与 mere proposition 不同**；两个不同定义都构成 set，并不证明它们表示同一个实数对象。要把这个变体用于批评原典，必须给出保真连接，当前没有这样的证明。

影响传播：`DedekindReals`、`ℝLayerAt`、`Sufficiency`、`Necessity` 及相关自然语言解释都依赖该定义。现有充分性证明可以继续作为此变体的形式证明记录，但不应原样称为“Book §11.2 的精确收费命题”。

修订方式有两种，不能混写：按原典修正 `dcut` 并产生新 run；或保留当前代码并准确命名为携带 locatedness 选择数据的变体，再独立证明所需的忘却/恢复性质。本轮没有修改这些 owner，也没有伪造新证明。

## 2. GOLD 的强见证与通用实数规格要分开
<!-- audit-cites: C003-04 C003-05 -->

[CutGoldForm.agda](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/CutGoldForm.agda:115) 为固定平方根切割给出具体 `L/U`、命题性、上下界、不交、双向 rounded 和 located 的构造。对一个具体切割提供额外的可计算见证，本身可以是有用的加强。

问题出现在把具体实例中的强见证，直接选成**所有实数的定义条件**。当前 GOLD 也没有一个最终导出的项，把这些组件装配到独立的、忠实于 Book 的标准 `DedekindReals` 记录；`CutRealLayer` 没有导入 GOLD。函数签名逐个接受与集成到统一规格，必须分别验收。

还应避免要求无关的“δ 路线完备性”：一个存在性构造成功后，不需要枚举所有可能见证方法才算证明完整。只有声称所有方法失败、某路线必需或搜索穷尽时，才需要相应完备性证据。最小必要补强是标准规格装配及语义验证。

## 3. A03：当前充分性并不承担必要性
<!-- audit-cites: C003-06 C003-07 -->

[CutRealLayer.agda:139](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/CutRealLayer.agda:139) 分别声明：

```text
Sufficiency ℓ = SingleOmega ℓ → ℝLayerAt ℓ
Necessity ℓ   = ℝLayerAt ℓ → SingleOmega ℓ
```

实际有证明体的是 `sufficiency`。因此“给这种 Ω 数据就能构造所需的小型表示”有对应代码；“没有这种 Ω 就不能构造实数”在现有代码中仍没有相应证明。

[NecessityLEM:123](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileFourNecessityLEM.agda:123) 明写：

```agda
LEM→Necessity lem _ = SingleOmega-from-LEM lem
```

下划线参数说明实数小型化前提完全未被使用。这个条件命题有价值，但不能把它描述为从实数结构中识别出必需的 Ω 假设，更不能据此关闭无条件必要性。

当前源码注释、CLAIM-PACKAGE 和 ZCode 回答中，同时出现“必要性 CONJECTURE”与“免费假装被机器证死”“收费点已经钉死”。后者仍超出前者的证据。局部标签保守不使周围较强叙述自动成立。

## 4. 宇宙的小型化不是“实数尚未存在”的同义词
<!-- audit-cites: C003-08 -->

`ℝLayerAt ℓ` 额外要求一个 `Type ℓ` 中的 set，与 `Type (ℓ-suc ℓ)` 中的 `DedekindReals ℓ` 等价。它是在研究指定宇宙中的大小，不是定义“存在一个实数”或“某个实数构造已完成”。

Book 给出的第一种做法就是追踪宇宙层级，其余做法包含 resizing、命题 LEM 和 σ-frame 路线。不能把“为了简化层级记号采用某种原则”改写成“没有该原则就没有实数”。原典的这些分支属于必须处理的正向对照，不是通过把所有构造成本都称为“收费”便可统一排除的异议。

## 5. `SingleOmega` 与 resizing 的关系尚未被本包确立
<!-- audit-cites: C003-09 C003-10 -->

当前 `PropResizing ℓ` 搬运 `Type (ℓ-suc ℓ)` 中的单个命题；`SingleOmega ℓ` 要求整个 `hProp ℓ` 在 `Type ℓ` 中有小型表示。源码第 81 行写“等价于 propositional resizing”，第 132 行写“不蕴含”，第 137 行又承认关系未论证。三种口径不能共同构成已闭合结论。

学界已有精细区分，不能靠类型名推断关系。例如 Escardó 的 [Agda 讲义](https://www.cs.bham.ac.uk/~mhe/HoTT-UF-in-Agda-Lecture-Notes/HoTT-UF-Agda.pdf) 专门区分 pointwise resizing 与 Ω 的小型性，并区分最底层和后继宇宙。这里仅将其作为必须对照的一手文献入口，未重放其定理。

另外，CLAIM-PACKAGE-REAL-LAYER §3 从书中列出 σ-frame 路线，直接宣称某个精确反向蕴含已被“证伪”。**替代构造路线的文字提示不是一个满足该形式前提而违反该形式后件的模型。** σ-frame 是否表示所有 `hProp ℓ`、是否得到当前 `ℝLayerAt`，仍需要精确桥梁。这一正反两边的越级都应撤回。

## 6. 本片建议验收
<!-- audit-cites: C003-11 -->

1. 先固定真正要研究的标准切割与 universe 参数，解决 A02。
2. 把 GOLD 装配到该规格，明确它提供的额外计算数据。
3. 重证充分性，保留其实际方向。
4. 必要性单列：给直接证明、给精确模型反例，或保持开放；三者都允许结束一个有界研究单元。
5. “同一现实任务为什么必须使用这个小宇宙对象”另立论证，不能藏在 `ℝLayerAt` 的中文别名中。

完成这些工作，可以形成可认真讨论的基础研究问题；当前并没有证据允许省掉它们并宣称已经得到理论失败结论。
