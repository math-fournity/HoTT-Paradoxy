# 公理注入、规范性与元理论

## 1. A04：演示中的 LEM 不是 HoTT Book 的 LEM
<!-- audit-cites: C004-01 C004-02 -->

[MissileFourChargeDemo.agda:26](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileFourChargeDemo.agda:26) 声明：

```agda
postulate
  LEM : (A : Set) → A ⊎ (A → ⊥)
```

后面的 `n-lem` 将它应用于 `ℕ`，并把左分支中的自然数直接取出。标准命题 LEM 应包含 `isProp A` 前提。本项目另一个模块 `MissileFourNecessityLEM` 所消费的 `LEMProp` 恰恰有这个前提；两个模块不能因为都叫 LEM 就当作同一原则。

Book §3.4 将不受限制的版本另称 `LEM∞`，并说明它与 univalence 不相容；标准 `LEM₋₁` 被刻意限制到 mere propositions。定位：[logic.tex:358](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/theory-schema/upstream/book-578b85cc/logic.tex:358)，相关原典反证位置 `thm:not-lem`。**该不相容性在本报告中是原典转述，未冒充本轮新机器证明。** 本轮已经直接核实的事实是：被测源码确实省略了 `isProp`，且测试了 `LEM ℕ`。

因此，“标准 HoTT 加入其可选 LEM 后发生了这种行为”的归因没有通过前提忠实性审计。应将旧材料改称“不受限制的和式选择公设演示”，并重新设计标准命题 LEM 的样例。当前 `n-lem` 的任意自然数提取方式尤其不能直接保留为标准 LEM 的消费者。

## 2. AC 与 UA 的名字也不能代替精确前提
<!-- audit-cites: C004-03 C004-04 -->

同一模块的 AC 部分只 postulate 了某个关系 `P` 和一个已经选好的函数：

```text
P  : ℕ → ℕ → Set
ch : (n : ℕ) → Σ[ k ∈ ℕ ] P n k
n-ac = ch 0 .fst
```

这里没有形式化“从逐点截断存在出发，利用某个选择公理获得整体选择”的过程。实际观察的是不透明 `ch` 的投影。要成为一个关于特定 AC 原则的结论，必须先写出该原则的类型、适用对象、截断位置及消费者，而不能把已经给定的选择函数称为 AC 公理本身。

[UA 演示](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileFourTargetA-UACounterexample.agda:18) postulate 了一个把同构数据送到类型路径的函数，名字叫 `ua`，没有提供与标准 `idtoequiv` 的逆性质或计算关系。它是在已经启用 cubical 的系统里增加一个不透明常量；不能将其同本库具有计算行为的标准 `ua` 无条件混同。

最小必要对照应包括：标准 cubical `ua notEquiv` 的同一消费者、普通不透明常量的同类消费者、当前公设消费者。现有 `ProbeControl` 只有 `zero ≡ zero` 的 `refl`，它核查了最简单的正例，但不足以区分“HoTT 特有机制”与“任何不透明输入都可能留下未化简表达式”。

## 3. A06：六次 `refl` 失败具体说明什么
<!-- audit-cites: C004-05 C004-06 -->

本轮重放六个负向探针，均 exit 42；它们尝试以 `refl` 证明指定项等于 `zero` 或 `suc zero`。保存的诊断说明这些目标不能以该反身证明项通过当次转换检查。

不得越级为以下结论：

- 已获得该等式的对象层否定证明；
- 不存在其他命题相等证明；
- 该项不会归约到任何自然数；
- 该项归约永不终止；
- 任意实现都无法处理该理论；
- 已证明某个 HoTT 命题独立或不可证。

六个探针是固定实例的计算行为材料。若要证明更一般的规范性失败，需要确定对象演算、扩展签名、归约关系和“典范形”的定义，并覆盖相应量词。不透明项停在中性形式，与无限执行是不同现象。

官方 [Agda 2.8.0 postulate 文档](https://agda.readthedocs.io/en/v2.8.0/language/postulates.html) 说明公设属于无定义常量，safe 模式禁止普通公设；[cubical 文档](https://agda.readthedocs.io/en/v2.8.0/language/cubical.html) 给出其原生计算机制。它们支持区分“扩展了签名”与“基础系统自身失败”。

## 4. A07：ReboundDisarm 没有完成紧化理论的形式化
<!-- audit-cites: C004-07 -->

该文件实际只给出：

```agda
ideal-point-is-explicit = base
endpoint-identification-is-a-path = loop
hit-computation-witness : intLoop (pos 0) ≡ refl
hit-computation-witness = refl
```

三项都可被独立检查。但文件没有：拓扑空间与开集、删点嵌入、紧性、紧化的泛性质、两端逼近序列、极限、原 M/N 对应或可逆操作模型。因此它不能承载“紧化反弹已经处理完毕”“收费只能转移到 Ω”的结论。

`base` 是库的构造子，不会由于本地别名叫“理想点”就自动成为原始拓扑构造中新增的点。`intLoop 0` 的计算特例也不量化所有闭项，不能替代全理论 canonicity 定理。它适合保留为 HIT 的基本计算正控制。

## 5. Gödel、否定证明与第四项元理论
<!-- audit-cites: C004-08 C004-09 -->

第 027 片把“拒绝在引擎内发生，意义由元理论颁发”同 Gödel 第二定理相联系。它也承认主定理模式仍是草案。但是同时出现“任何诚实引擎”“每个经典理想元素”“必然三选一”等全称表达。

现有材料没有为这些量词固定：

1. 可有效公理化的精确对象理论及其算术表达能力；
2. 对象语法、证明编码、证明谓词和所需可导出性条件；
3. 对应的一致性语句与元理论假设；
4. “承载”“完成义务”“表达力塌缩”的正式关系；
5. 从这些前提到所说三分结论的证明。

因此它不能被交付为已完成的 Gödel 实例或普遍不可能性定理。一个否定命题在 Agda 中得到证明，是对象层的正面证明结果；这和编译器拒绝某段代码又是两件事。

[Huber 2017 版论文](https://arxiv.org/abs/1607.04156v2) 的 canonicity 结论针对论文所定义的 cubical 演算及受限上下文。这不能自动认证带 `--two-level`、普通公设和全部实现特性的 Agda 安装，也不能证明“HoTT 未来不可能被反驳”。本轮仅核查来源身份与摘要范围，未重放该论文证明。

## 6. 成功判据必须允许失败
<!-- audit-cites: C004-10 -->

若一个候选构造被理论接受算成功，被理论拒绝也算成功，加入结构恢复同一任务仍算成功，那么“成功”已不能区分候选成立与否。应在研究前允许至少以下否定判词：

- 比较了不同任务，候选失效；
- 原理论并未承诺该能力，当前归因失效；
- 一个满足相同输入与完成要求的正构造出现，候选需修订；
- 结果是额外公设或人为错误规格的后果，不能归因给原理论。

这不封闭用户的研究方向。相反，它使“发现非现实性”的成功判断具有可复核的内容。

## 7. “最后一米永远不可形式化”也没有被第四项证明
<!-- audit-cites: C004-11 -->

原始回答 `68#/response/text` 把“非现实性判词机器不可完成”称为第四项的定理级产出；`74#/response/text` 又说跨理论的同一物不能成为理论内的类型，只能交给用户判词。现有代码没有一个量化全部形式化、全部现实对应或全部观察语义的不可表达定理。

因此应区分：“这份工作尚未形式化现实对应”“作者选择把价值判断留在哲学论证层”“任何形式系统都不可能形式化该对应”。前两项可以是诚实状态或方法选择；第三项需要独立的不可能性证明，不能从当前缺件推得。把对应关系放到判词层，也不会免除论证者解释为何它保持同一任务的责任。

同一回答序列里的“univalence 承认的唯一相等”也应改写为具体规格：判断相等、宇宙中的类型路径、给定结构上的身份与所选等价关系须分别固定。原 M/N 若为带拓扑或来源结构的对象，不能仅凭“同胚等价类型化”几个字就省掉编码及结构保持义务。本报告不把这些未展开的桥梁认证为“已核实”。

## 8. 检查一份证明完成，不等于执行其所描述的过程完成
<!-- audit-cites: C004-12 -->

第 027 片的“引擎必须真的算完才能盖章”，若指给定源码的类型/证明检查，是本轮有实际运行支持的描述；若据此指所定义的每个数学对象已经穷尽生成、每个程序已经执行终止，则扩大了操作对象。本轮 Agda 接受的是有限证明文本与定义，对无限定义域的量化不会因此变成逐个执行完所有实例的记录。

故“真实运行的 Agda 比理论更现实”本身不是保真证明。应分别给出 proof checking、对象归约、被模拟程序执行与现实完成的判据。这一层区分仍缺失时，第四项不能把前三项的解释缺口转化为一个已经完成的元定理。
