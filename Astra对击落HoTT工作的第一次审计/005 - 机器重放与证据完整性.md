## 2. A08：两个本地导入漏项
<!-- audit-cites: C005-14 C005-15 C005-16 -->

[SOURCE-AUDIT.json](../audit/astra-hott-first-20260919/SOURCE-AUDIT.json) 以显式 import 递归核对 10 个入口的项目内依赖，并对照原 manifest 与原 checker 输出：

| run | manifest 漏列的实际导入 | 直接连接 |
|---|---|---|
| GOLD-02 | `MissileTwoUniversalIrrationality.agda` | GOLD 导入并在 locatedness 分支调用 `√2-irrational` |
| NECESSITY-LEM-01 | `CutRealLayer.agda` | 直接导入 `LEMProp`、`SingleOmega`、`Necessity` |

两模块都出现在保存的 checker 输出里，故这不是仅凭目录猜测的依赖。尤其第二项漏掉的是**被证明命题的定义 owner**：如果它改变，主文件自己的 hash 不足以固定命题身份。

GOLD-02 的 manifest 还没有 `external_dependencies` 列表，现有 verifier 因默认空列表而跳过该 run 的外部工具链哈希校验。其他九个 run 都记录了 Agda 归档/二进制、cubical 归档/库文件/树身份。本轮其余 run 的核验固定了实际使用的相同工具链，因而不影响本轮“实际重新运行”的观察；但不能倒推 GOLD 历史收据自身已经独立封装完整。

**修复不是改写旧 hash。** 应生成一个新证据单位，冻结当前实际传递闭包、依赖和命题版本，登记新旧关系，并保留历史缺口。

## 3. A09：`--safe` 的注释命中被误当成选项资格
<!-- audit-cites: C005-17 -->

[verify_formal_proof_run.py:239](/Volumes/D/HoTT_AI_HANDOFF_20260911/scripts/audit/verify_formal_proof_run.py:239) 的 cubical 检查在整个源码字符串中搜索 `--safe` 和 `--cubical`，没有解析 `OPTIONS` pragma。

TA 文件第一行实际只有：

```text
{-# OPTIONS --cubical --guardedness #-}
```

第二行注释却含“刻意不带 --safe”。所以其全文含有 `--safe` 字符串，canonical verifier 给出 PASS。本轮实测再现了这个 PASS；`source_audit.py` 分离 pragma 与全文后，TA 的 `pragma_safe=false`、`whole_text_contains_safe=true`。

这不表示作者暗藏公理：文件头已经明确披露公理演示意图。问题在于**校验器没有执行它看起来在执行的语义检查**，使公设型演示和 safe 证明包通过同一路资格判断。公开包必须把两类分开，并检查实际选项、允许公设和导入闭包。不得从这个缺陷进一步声称 Agda 内核不可靠；它是项目证据校验脚本的实现问题。

## 4. 独立性、信任基础与剩余运行限制
<!-- audit-cites: C005-18 -->

本轮是另一个审计 Session 的重新运行，不是另一个 proof kernel 对同一形式化的交叉认证。仍信任固定 Agda 实现、它的 cubical primitives、锁定库与硬件。无需因此默认另建第二套完整证明，但报告不能把“一次独立重放”称为“消除了全部实现风险”。

语义审查是另一条证据线：本轮所有核心 run 通过的同时，A01–A04 仍成立为规格/推理缺口。修复后若目标类型变化，旧 run 不能认证新目标。

## 5. 可移植公开仍有实际工作
<!-- audit-cites: C005-19 C005-20 -->

`compile.sh`、`AGDA_LIBRARIES` 和历史 argv 使用 `/Volumes/D/...` 的本机路径。当前成功重放验证的是本机安装，尚未验证陌生读者的干净环境。根据 Terra 的定位，本轮额外复制字节相同的 M1 入口到不同 cwd，原样执行历史 argv，实际得到 exit 42 与 `ModuleDefinedInOtherFile`：相对目标在新目录，绝对 include root 仍指原目录。新证据见 [relocated-m1-stdout.txt](../audit/astra-hott-first-20260919/terra-comparison-20260919/relocated-m1-stdout.txt) 和 [VERIFICATION.json](../audit/astra-hott-first-20260919/terra-comparison-20260919/VERIFICATION.json)。这是路径耦合的实测失败；不是完整公开包跨平台验收，也不是数学反例。

公开证据单位至少应提供：精确 source/依赖 allowlist、模块类型与假设表、相对路径命令或可复现容器、必要正负控制、可读结果与一键核验。公共稿可以省去对话、失败迭代史和治理细节，但不能省去理解最终结果所需的前提、控制和已知缺口。

本项目已有公开包规划，当前明确为尚未实施；因此不需要再创建另一套发布平台。本轮也未获用户要求去导出、push 或发表任何内容。
