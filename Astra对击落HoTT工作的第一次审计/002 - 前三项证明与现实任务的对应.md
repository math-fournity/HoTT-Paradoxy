# 前三项证明与现实任务的对应

## 1. A01：M2 与 M3 目前回答的不是同一个实数任务
<!-- audit-cites: C002-01 C002-02 C002-03 -->

[M3 源码](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileThreeVerdictCollision.agda:61) 的两个规格为：

```text
Spec_B = Σ[ q ∈ ℚ ] q ·ℚ q ≡ 2r
Spec_A = Σ[ f ∈ (ℚ → Bool) ]
         ∀ q → (f q ≡ true → q·q < 2r) × (q·q < 2r → f q ≡ true)
```

前者要求交付一个有理数精确根；后者要求一个有理数平方比较的布尔判定函数。二者的输入、输出及完成标准没有在代码中统一。M3-UNC 的关键证明体只是：

```agda
M3-L1-unc eqv = spec-B-empty (equivFun eqv specA-inhabited-unc)
```

这清楚展示了已有证明的依赖：调用 M2 的空性结论，将一个已有的 A 元素沿假设的等价送到 B，再产生反证。代码没有引用“HoTT Book 断言 A 与 B 等价”的定理，也没有实现一个真实使用者把 A 当成 B 的操作。

**审计结论**：M3 是这两个自定义规格之间的分离结果。它还不是“HoTT 理论声称二者相同，而 Agda 否定了该声称”的证据。两种规格都能用 HoTT 表达，不能代替“HoTT 承诺它们是同一任务”的来源。

Book §11.2 在定义切割后给出的是有理数嵌入实数和实数上的运算。所读原文没有把构造实数定义为必须返回一个满足平方等式的有理数。原始源码见 [reals.tex](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/theory-schema/upstream/book-578b85cc/reals.tex:172)；公开原典见 [HoTT Book 的固定版本源码](https://github.com/HoTT/book/blob/578b85cc8d586b1677ec4335148adeb443057d24/reals.tex)。

### 1.1 现实同一性固定共同对象，形式化须保留该对象的任务
<!-- audit-cites: C002-04 C002-05 -->

用户在原始 `72#/request/messages/62` 明确说：不同理论视角下 M/N 的数学身份可能改变，但它们仍指向数学现实中的 X 及其变化过程。来源身份见 [REALITY-IDENTITY-CONTEXT.json](../audit/astra-hott-first-20260919/REALITY-IDENTITY-CONTEXT.json)。本审计将其理解为**跨理论保持共同指称、对象来源与变换过程的要求**，不是让某个理论的相等定义反过来决定原问题换成了什么，也不把数学现实收窄为必须直接测量的物理物体。

这一研究出发点可以直接用于比较；不需要先让 HoTT 许可研究者把 X 当作共同对象。需要检验的是：两份形式化是否忠实地描述了所说的 X、允许操作、观察与完成条件。对象在过程中的延续也不自动表示变换前后所有状态和性质相同。

对本审计此前表述作一项限定：**仅指出两个形式规格不同，不能单独判定用户的研究策略失败。** 还要检查这种差异是否恰是被研究的理论化造成的。不能一看到形式身份不同，就把本应审查的抽象差异全部归为用户换题。与此同时，共同指称也不会自动证明任意两个交付规格等价。M3 当前缺的正是这项对应，而非研究者采用共同对象的资格。

用户要观察的是：理论是否在抽象共同对象时丢掉了完成任务所需的条件。为检验它，至少需要明确：

| 比较面 | 目前缺少的共同约束 |
|---|---|
| 输入 | 共同的 X、初态与允许的变换历史，怎样分别送入两种表示；不把同一对象误作所有时刻状态相同 |
| 输出 | 返回判定函数、精确有理数、实数表示、有限精度结果，哪一个才是任务要求 |
| 允许操作 | 允许增加点、变换表示、保留来源标签或在更大宇宙中构造吗 |
| 完成 | 有限项描述、给任意精度的算法、过程终止、物理操作成功，怎样区分 |
| 保真 | 翻译是否保留输入、观察与完成，不只是把两件事命名为同一个 X |
| 归因 | 额外要求来自 HoTT 的规则/实际用法，还是来自审计者新增的规格 |

这些约束既适用于内部矛盾目标，也适用于现实相对非现实性目标。它们不要求先接受传统解释为最终答案；它们要求比较对象在论证中保持稳定。

自主构造一个有明确目的、规则和对应的理论实例同样可以研究；不要求先找到某个现实软件已经发生误用。本片对“实践层天天使用”的来源要求，针对的是 ZCode 已经作出的那项具体归因，不是给所有未来探索增加自然软件消费者前置。

### 1.2 `Spec_A` 还不是 GOLD 中的下切割
<!-- audit-cites: C002-06 C002-07 -->

`Spec_A` 的谓词只检查 `q² < 2`。GOLD 的下谓词则显式包含负数分支：

```text
L q = (q < 0r) ⊎ ((0r ≤ q) × (q·q < 2r))
```

这个源码差异已经足以阻止把 M3 的布尔表直接称为 GOLD 的 Dedekind 下切割。若要用具体负有理数检验两者，应另做对应的 kernel 控制。本轮不把尚未单独形式化的数值例子包装成新机器反例。

更重要的是 `specA-inhabited-unc` 实际构造了判定函数，而非 postulate 一张无限表。因此其自身已经削弱“此表只能被理论假装预先交付”的解释。一个函数有无限定义域，并不意味着源码在构造时逐个填满该定义域；当前有限源码正是必须被认真解释的正向证据。

## 2. A05：M1 的实际命题比“逼近过程不收敛”窄
<!-- audit-cites: C002-08 -->

[M1 模块](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileOneProcessLayer.agda:46) 定义整数递推 `pellP/pellQ`、整数判别式 `D`、符号函数，随后给出 `D-invariant`、`pell-gap-never-closes` 和 `gap-never-zero`。

源码没有定义：有理夹钳端点对、与 GOLD 切割的夹逼关系、误差界、收敛谓词、完成过程的操作语义、全体算法的编码或“最优”的比较规格。因此模块头的“最优夹钳”“核验其不收敛”不能按原样继承 kernel 状态。

应保留的范围是：**给定递推的判别式在每个自然数指标上不为零**。它可以作为另一个过程模型的引理；若要论证“永不精确相遇”，还需把该模型与判别式的关系接上；若要论证“不收敛”，更必须先固定收敛的含义。非零残差、没有有限精确根与不能达到任意精度不是同一性质。

这里的“每个自然数指标”是 `∀ n : ℕ` 的全称证明，**不是只运行到有限步数的观察**。Terra 对这个量词的强调是正确的。本报告限制的是该定理所对应的过程与解释范围，不降低其对固定递推的全称证明强度。

这不是要求把所有初等数学都重做一遍，而是要求被用来诊断理论的观察量确实出现在形式规格里。

## 3. M2 与 BP 可以保留的贡献
<!-- audit-cites: C002-09 -->

[M2](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileTwoUniversalIrrationality.agda:312) 的精确目标是全称有理无根性及其 Σ 形式；下降、奇偶、整数与商表示的证明体实存，且有真实重放。它是有效的形式化资产。

[BP](/Volumes/D/HoTT_AI_HANDOFF_20260911/HoTT/formal/dedekind-omega-missile/MissileByproductGapDecidable.agda:33) 的 `decGapAt` 直接返回否定分支，`noGapWitness` 消费 M1。它提醒研究者“获得否定结论”与“搜索一个不存在的见证”是不同任务。但该模块未定义一个无界搜索器及其运行语义，不能把注释中的搜索不终止视为另一个已形式化定理。

## 4. 圆环问题到算术例子的连接仍需独立说明
<!-- audit-cites: C002-10 -->

本轮 20 个模块中没有原始 M/N 线段的拓扑、带来源结构的对象、删除一点及复原过程、操作许可、现实完成判据，也没有把它们保真翻译到 Pell/有理根规格的定义。

这不证明原始圆环问题没有价值，也不证明它不能形式化。它说明：当前算术证明尚不能作为原始圆环论证的完整机器替身。若保留原始研究目的，需要给出这条翻译；若论文只研究算术与实数表示，则必须把范围改写为该精确主题。

**本片停止条件**：拿到一个可审查的同任务映射和真实理论承诺之前，不把 M1–M3 的检查通过升级为 HoTT 已有现实相对失配。重开条件是新增这样的映射、自然使用证据或独立形式化的完成规格。
