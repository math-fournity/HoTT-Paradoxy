# 校验器修复的残留缺陷与受控反例

## 1. 实际修复了什么

`verify_formal_proof_run.py:223–232` 将全文查找 `--safe` 改为提取看似 OPTIONS pragma 的文本，再检查 token：

```python
re.findall(r"\{-#\s*OPTIONS([^#]*?)#-\}", text_data)
```

对原来只有普通注释写“刻意不带 --safe”的 TA-01，这个改动有效；本次验证器确实拒绝该控制模块。GLM 的这项局部修复有证据。

但这个正则没有区分有效 pragma 与注释中的相同字面文本。因此“OPTIONS pragma 实际解析”“校验器已彻底修好”的强表述不成立。

## 2. 最小可复现输入

本次只在审计独占目录生成合成 Agda 文件和透明标注的合成收据，不修改真实证明、主张矩阵或历史收据。关键文件是：

[CommentPragma.agda](../audit/astra-hott-second-20260919/synthetic-verifier-controls-v2/CommentPragma/CommentPragma.agda)

```agda
{-# OPTIONS --cubical #-}
{-
{-# OPTIONS --safe --cubical #-}
-}
module CommentPragma where
postulate witness : Set
```

第二个 OPTIONS 在块注释内。Agda 实际执行没有启用 safe；外层 Python 正则却同时取到两个 pragma 的文本。

## 3. 正控制、负控制与误接受结果

运行脚本：[check_pragma_controls.py](../audit/astra-hott-second-20260919/check_pragma_controls.py)。脚本调用**当前原始验证器的 `validate(..., rerun=True)`**，不是另写一个模仿验证器，然后宣称原验证器失败。

| 合成控制 | Agda 实际 exit | 当前验证器结果 | 判断 |
|---|---:|---|---|
| SafePositive：真实 safe pragma、普通数据声明 | 0 | PASS + 精确重放一致 | 正控制通过 |
| UnsafeNegative：没有 safe pragma、含 `postulate witness` | 0 | `AGDA_SAFE_CUBICAL_PRAGMA_REQUIRED` | 负控制正确拒绝 |
| CommentPragma：同样含公设，注释内补假 safe pragma | 0 | **PASS + EXACT_EXIT_STDOUT_STDERR_MATCH** | 验证器误接受 safe 资格 |
| 对同一 CommentPragma 命令真正增加 `--safe` | 42 | Agda 报 `[SafeFlagPostulate]` | 证明是选项识别错误；Agda 的 safe 检查工作正常 |

完整结果：[PRAGMA-CONTROLS-v2.json](../audit/astra-hott-second-20260919/PRAGMA-CONTROLS-v2.json)；原输出：[forced-safe stdout](../audit/astra-hott-second-20260919/checks/control-v2-CommentPragma-forced-safe/stdout.txt)。合成包的 index 与 run 都显式标注测试身份，不进入 `HoTT/CLAIM_EVIDENCE_MATRIX.md`，不是一份新的数学成果。

首次控制脚本使用了 Agda 保留字 `opaque` 作为标识符，导致两个样例解析失败，无法检验所问问题。失败文件与 `PRAGMA-CONTROLS.json` 原样保留；v2 仅换为合法标识符 `witness` 后完成上述控制。不能将首次 setup 失败计为所审计校验器的证据。

## 4. 影响边界

这一结果是**校验器正确性缺陷**：校验器可能将实际非 safe 的合成程序归为 safe 证明证据。它没有让 Agda 接受一个在真实 safe 配置下被禁止的公设，也没有构造任何 HoTT 矛盾。

当前三份新主证明的有效第一行确实含 `--safe`，本次源码审读、工具链 pins 与精确重放支持它们各自范围的检查结果。本控制不撤销这些证明；它撤销的是“此验证器已经足以可靠认证所有输入 safe 资格”的一般承诺。

同时，验证器默认缺省允许空 `external_dependencies`，也不自动检查传递导入闭包。本次合成包利用的是公开的测试接口与最小所需字段；这不表示新三份真实 manifest 缺外部依赖。它提醒公开验收须把“源码真实资格”“执行配置”“依赖闭包”分别核对。

## 5. 后续修复应满足的最小合同

1. 注释中的 pragma 不参与有效选项集合；需处理行注释、嵌套块注释及真正的 pragma。不能继续在全文上加一个更长的正则就声称完成语言解析。
2. 正式 safe 证明运行应让 Agda 实际在规定选项下检查；新增显式参数会改变运行合同，须产生新收据而非改历史 argv。
3. 公设控制另有明确分类与预期诊断，不能因它故意非 safe 就丢弃其工具行为价值，也不能让它使用 safe 定理的标签。
4. 保留本组三控制，以及执行配置/依赖的实际检查。回归 PASS 只关闭其覆盖范围，不证明任意 Agda 文本都正确处理。

本轮用户授权是审计修复；这里交付缺陷和可复查控制，未修改 canonical verifier。
