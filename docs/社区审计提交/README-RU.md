## Общие границы трёх документов

- Ни в одном из них **не** утверждается, что HoTT противоречива. «Проблема» здесь означает нереальность теории по отношению к реальности, а не внутреннее противоречие.
- У каждого вывода указан его статус: подлинные слова инициатора проекта, математический факт (с протоколами запусков), вывод метауровня, пересказ источника, суждение.
- Для всех цитируемых документов и кода указаны пути в репозитории.
- Атрибуция (какая посылка виновата) — главная тема каждого документа: в каждом изложены посылки-кандидаты, конкурирующие атрибуции, данные, которые позволяют их различить, а также суждение и его статус (поправка инициатора проекта от 2026-09-24).

## Как начать аудит

1. Сначала прочтите 03 (самый короткий), затем §0 документов 01 и 02 («Сначала выводы») и их раздел «Вопросы для аудита сообществом»;
2. Воспроизведите машинные доказательства по разделу «Как воспроизвести»;
3. Пошаговый контрольный список для независимых рецензентов, не связанных с историей проекта: `../../Cloud-Opus审计并补完GLM/13-外部复核请求.md`.
