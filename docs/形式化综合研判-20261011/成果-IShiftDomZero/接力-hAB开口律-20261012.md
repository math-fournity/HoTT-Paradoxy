## 0. 目标（一句话）

`hAll` 的唯一剩余前提 `hAB` 归结为码恒等式

```
iT 0 (free ℒₒᵣ p) = subst ℒₛₑₜ ?[^&0] (iT 1 (shift ℒₒᵣ p))          (p : IsSemiformula ℒₒᵣ 1 p)
```

它是下面**开口律**的 `m = 0` 特例：

```
iT m (subst ℒₒᵣ (QvecVOr m) q) = subst ℒₛₑₜ (QvecV m) (iT (m+1) q)     (q : IsSemiformula ℒₒᵣ (m+1) q)
```

其中 `QvecV m = QvecVOr m = [#0, #1, …, #(m-1), &0]`（长度 `m+1`），
即 `qVec` 对 `?[^&0]` 迭代 `m` 次。

## 1. 机制（为什么为真）

`subst` 下降一层绑定子时把代入向量 `W` 换成 `qVec W = ^#0 ∷ termBShiftVec W`
——**前置一个新的 `^#0` 并把所有索引 +1**。
`iTR` 内部有 `qqAlls … 2` 两层绑定，所以开口向量在那里已长到长度 `m+3`：

* 索引 `i < m+1` 处是 `^#i`（恒等）；
* 索引 `m+1` 处是 `^&0`。

而 `iVE (m+1) ^#z = eqAtom ^#(z+1)` 把源变量 `z` 放在索引 `z+1`——
于是**代入恰好落在变量槽上，不碰 `eqAtom` 自己的值槽（索引 0）**。
裸公式的"同索引交换"是**假**的（机器化反例：`ITSubstCounter.naive_law_is_false_shape`）；
这里的正确形式是"**在正确的槽上**交换"。

## 5. ⚠️ func 支的层次疑点（2026-10-12 15:40，待核验）

写 `subst_QvecV_conjunct` 时逐索引核算，发现 **`conjunct` 零件所需的向量层数
可能比"两层 qVec"高一层**。推理如下（**尚未机器验证，勿直接当作结论**）：

* `ve2 n k f w` 的体是 `imp (conjunct 3 n 0 w.[0] ⋏ (conjunct 3 n 1 w.[1] ⋏ ⊤)) …`
  且整体包在 `qqAlls … 2` 里。
* `conjunct b n i y = (subst ?[^#i] cDomN) ⋏ (subst (^#i ∷ shiftVec b n) y)`，
  其中 `^#i ∷ shiftVec 3 n` 的长度是 `n+1`，第 `j+1` 项是 `^#(3+j)`（`j ∈ 0..n-1`）。
* 对 `ve2 (mm+1) …`：`n = mm+1`，故该向量用到索引 `0..mm+1`，**最大索引的项是
  `^#(3+mm) = ^#(mm+3)`**。
* RHS 是把 `subst (QvecV (mm+1))` 施于整个 `ve2`，下降两个绑定子 ⇒ 体内向量是
  `qVec²(QvecV (mm+1)) = QvecV (mm+3)`，**长度 `mm+4`，索引 `mm+3` 处是 `^&0`**。
* 于是 `QvecV (mm+3)` 在索引 `mm+3` 处把 `^#(mm+3)` 映成 `^&0`，
  **不能**固定 `conjunct` 的向量。`QvecV (mm+4)`（长度 `mm+5`，索引 `0..mm+3`
  都是 `^#j`）才够。

**若此推理成立**，则 `iVE_open` 的 func 支不能只在 `ve2` 体内用
`subst_QvecV_*` 一次性消掉，而需要：要么把 `subst` 的下降层数重新对齐
（检查 `ve2` 的 `n` 究竟是 `mm+1` 还是 `mm+2`——取决于 `iVE_func` 的调用形式），
要么让主律在 `iT` 层而不是 `iVE` 层处理 `ve2`。

**结论（2026-10-12 17:30，已机器验证）**：小实例核验做完了，
**`QvecV (mm+4)` 的推断是错的，正确的是 `QvecV (mm+3)`**。理由分两层：

1. `subst_QvecV_conjunct`（`IVEOpenFunc12.lean`，**已证、无 sorry**）对
   `conjunct 3 n i y` 用的外向量就是 **`QvecV (n+3)`**，且它确实固定整个合取项。
   `conjunct` 的两条代入向量分别是 `?[^#i]`（索引 `i`）与
   `^#i ∷ shiftVec 3 n`（索引 `{i} ∪ {3,…,n+2}`），最大索引 `n+2`。
   `QvecV (n+3)` 的长度是 `n+4`，在索引 `0..n+2` 上全是恒等 `^#j`，
   所以两项都被固定。这就是上面机器证明的内容。

2. `iVE_open` 的 func 支缺口已**精确定位**（`Ve2BinderProbe.lean` + `LayerCountProbe.lean`，无 sorry）：

   * `ve2 n k f w = qqAlls <body> 2` —— **恰好两个绑定子**（`rw [ve2]`）。
   * func 支里 `iVE` 的层是 `mm+1`，故体是 `conjunct 3 (mm+1) i _`。
   * `termSubstVec k w v` 取 `w` 的下标是「`v.[i]` 里烤进的 bvar 下标」而非 `i`
     （`nth_termSubstVec hv hi` + `termSubst_bvar` 一行证）。
   * **决定性事实**：`conjunct 3 (mm+1) i _` 的向量 `^#i ∷ shiftVec 3 (mm+1)`
     最大 bvar 下标 = `3 + mm = mm+3`；而 `qVec² (QvecV (mm+1)) = QvecV (mm+3)`
     在索引 `mm+3` 处是 `^&0`（`nth_QvecV_last`），**不是恒等**。
     所以外层取 `QvecV (mm+1)` 时，两次下降确实**差一层**。
   * **修法（已机器锁定）**：外层向量改成 `QvecV (mm+2)`，两次下降落在
     `qVec^2 (QvecV (mm+2)) = QvecV (mm+4)`，正好是 `subst_QvecV_conjunct`
     `(n := mm+1)` 所需的层。关键等式 `(mm+1)+3 = mm+4` 已由
     `LayerCountProbe.lean` 的两个 example 机器验证（`ring` 即得）。

   **缺口已从模糊变精确，且零件全部齐备**：`subst_qqAlls_two`（下降律）、
   `qVec2_QvecV`（下降向量）、`subst_QvecV_conjunct`（合取开口律）都已机器验证。
   剩余只是把 `shift_ve2` 的证法照搬到 `subst` 版本—— Lean 端摆列，无需新数学。
