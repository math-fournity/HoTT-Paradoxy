## 0. 目标（一句话）

`hAll` 的唯一剩余前提 `hAB` 归结为码恒等式

```
iT 0 (free ℒₒᵣ p) = subst ℒₛₑₜ ?[^&0] (iT 1 (shift ℒₒᵣ p))          (p : IsSemiformula ℒₒᵣ 1 p)
```

它是下面**开口律**的 `m = 0` 特例：

```
iT m (subst ℒₒᵣ (QvecVOr m) q) = subst ℒₛₑₜ (QvecV m) (iT (m+1) q)     (q : IsSemiformula ℒₒᵣ (m+1) q)
```

其中 `QvecV m = QvecVOr m = [#0, #1, …, #(m-1), &0]`（长度 `m+1`），
即 `qVec` 对 `?[^&0]` 迭代 `m` 次。

## 1. 机制（为什么为真）

`subst` 下降一层绑定子时把代入向量 `W` 换成 `qVec W = ^#0 ∷ termBShiftVec W`
——**前置一个新的 `^#0` 并把所有索引 +1**。
`iTR` 内部有 `qqAlls … 2` 两层绑定，所以开口向量在那里已长到长度 `m+3`：

* 索引 `i < m+1` 处是 `^#i`（恒等）；
* 索引 `m+1` 处是 `^&0`。

而 `iVE (m+1) ^#z = eqAtom ^#(z+1)` 把源变量 `z` 放在索引 `z+1`——
于是**代入恰好落在变量槽上，不碰 `eqAtom` 自己的值槽（索引 0）**。
裸公式的"同索引交换"是**假**的（机器化反例：`ITSubstCounter.naive_law_is_false_shape`）；
这里的正确形式是"**在正确的槽上**交换"。

## 5. ⚠️ func 支的层次更正（2026-10-12 15:40，**已用 Lean 核验**）

> **核验方式**：`IVEOpenFunc13.lean` 里四条 `example` 全部 type-check
> （`QvecV 3` 的索引 1 是 `^#1`、索引 3 是 `^&0`；`QvecV 4` 的索引 3 是 `^#3`）。
> 结论：**`conjunct` 零件需要 `QvecV (m+4)`，不是 `(m+3)`**。

### 原推理（现已证实）

写 `subst_QvecV_conjunct` 时逐索引核算，发现 **`conjunct` 零件所需的向量层数
可能比"两层 qVec"高一层**。推理如下（**尚未机器验证，勿直接当作结论**）：

* `ve2 n k f w` 的体是 `imp (conjunct 3 n 0 w.[0] ⋏ (conjunct 3 n 1 w.[1] ⋏ ⊤)) …`
  且整体包在 `qqAlls … 2` 里。
* `conjunct b n i y = (subst ?[^#i] cDomN) ⋏ (subst (^#i ∷ shiftVec b n) y)`，
  其中 `^#i ∷ shiftVec 3 n` 的长度是 `n+1`，第 `j+1` 项是 `^#(3+j)`（`j ∈ 0..n-1`）。
* 对 `ve2 (mm+1) …`：`n = mm+1`，故该向量用到索引 `0..mm+1`，**最大索引的项是
  `^#(3+mm) = ^#(mm+3)`**。
* RHS 是把 `subst (QvecV (mm+1))` 施于整个 `ve2`，下降两个绑定子 ⇒ 体内向量是
  `qVec²(QvecV (mm+1)) = QvecV (mm+3)`，**长度 `mm+4`，索引 `mm+3` 处是 `^&0`**。
* 于是 `QvecV (mm+3)` 在索引 `mm+3` 处把 `^#(mm+3)` 映成 `^&0`，
  **不能**固定 `conjunct` 的向量。`QvecV (mm+4)`（长度 `mm+5`，索引 `0..mm+3`
  都是 `^#j`）才够。

### 已证实的后果

**`QvecV (mm+3)` 不足以处理 `conjunct`**：`conjunct 3 (mm+1) i y` 的第二半是
`subst (^#i ∷ shiftVec 3 (mm+1)) y`，该向量用到索引 `mm+1`，其项是
`^#(3+mm) = ^#(mm+3)`；而 `QvecV (mm+3)` 在索引 `mm+3` 处是 `^&0`。

**这解释了为什么 `subst_QvecV_subst_cFunc` 能证成而 `conjunct` 不能**：
`cFunc` 的代入向量 `[^#2,^#0,^#1]` 只用索引 `0,1,2`，`QvecV (mm+3)` 在其上是
恒等（因为 `2 < mm+3`）；而 `conjunct` 的向量伸到索引 `mm+1`，正好撞上
`QvecV (mm+3)` 的末槽。

### 关键区分：`iTR` 用 `b = 2`，`ve2` 用 `b = 3`

**这是决定性的**（`IVEOpenFunc13.lean` 两条 `example` 已 type-check）：

|---|---|---|
| `iTR n 2 R v` | `^#i ∷ shiftVec 2 n` | 索引 `n`，项 `^#(n+1)` |
| `ve2 n k f w` | `^#i ∷ shiftVec 3 n` | 索引 `n`，项 `^#(n+2)` |

代入 `n = m+1`：

* **`iTR` 侧**顶项是 `^#(m+2)`，落在索引 `m+1`；`QvecV (m+3)` 在索引 `≤ m+2`
  上全是 `^#j`（**已证：`(QvecV (m+3)).[m+2] = ^#(m+2)`**）⇒ **`iTR` 的 conjunct 被固定**。
* **`ve2` 侧**顶项是 `^#(m+3)`，需要索引 `m+3`；而 `QvecV (m+3)` 在那里是 `^&0`
  （**已证**）⇒ `ve2` 需要 `QvecV (m+4)`。

### 修正后的路线（已调整）

`iT` 的 `rel`/`nrel` 支直接落到 `iTR`，而 `iTR` 只用 `conjunct 2 n j`（`b = 2`），

**`iT_subst_open` 不需要 `iVE_open` 的 func 支**，只需要：

* `conjunct 2 n j` 的代入律（`b = 2` 版，比 `b = 3` 版容易，因为 `QvecV (m+3)` 够用）。

## 6. ⚠️⚠️ 重要更正：开口律的**层数差一层**（2026-10-12 17:00，机器核验）

`OpenLawCheck.lean` 的三条 `example` 全部 type-check，得出：

```
qVec (qVec (QvecV m)) = QvecV (m + 2)          -- 下降两层绑定子
iTR 的 conjunct (b=2, n=m+1) 最大读索引 = m+2
QvecV (m+2) 在索引 m+2 处 = ^&0                -- 差一层！
QvecV (m+3) 在索引 m+2 处 = ^#(m+2)            -- 这才够
```

**核算细节**：
* `subst (^#j ∷ shiftVec b n) y` 把 bvar `z` 换成向量第 `z` 项：
  索引 0 → `^#j`，索引 `k (1≤k≤n)` → `^#(b+k-1)`；
* `termSubst w` 再读 `w.[z]`，故需 `w.[i] = ^#i` 对 `i ≤ b+n-1` 成立；
* `iTR`：`b=2`、`n=m+1` ⟹ 最大索引 `m+2`；
* 下降两层得 `QvecV (m+2)`，其索引 `m+2` 是 `^&0` ⟹ **不成立**。

**这推翻了我 15:00 前后"等式为真、只需正确槽位"的判断**——当时的核算
漏掉了 `termSubst w` 会把索引**再读一次** `w.[z]`（我只算到
"`^&0` 落在索引 `m+1`"，没算 `subst` 那一层对 `w` 的索引）。

### 影响

* **`hAB` 的等式形式（`iT 0 (free p) = subst ?[^&0] (iT 1 (shift p))`）
  在"下降两层"的读法下不成立**——除非 `iT` 的 `rel` 支实际下降的层数与
  `QvecV` 的构造差一层。
* **可能的出路**（按优先级）：
  1. **核对 `iT` 的 `rel` 支的真实层数**：`iT n (^rel k R v) = iTR n k R v`
     是**不下降**的（`iTR` 直接以 `n` 为参数），而 `subst` 是作用在
     **已经算好的 `iT` 结果**上。所以真正要算的是
     "`subst (QvecV m) (iTR (m+1) …)`"，其中 `iTR` 内部已有 `qqAlls 2`
     ——**这正是下降两层的来源**，与上面的核算一致。
  2. **改用 `QvecV (m+1)` 作为外层向量**（即 `free` 用 `qVec ?[^&0]` 而非
     `?[^&0]`），则下降两层得 `QvecV (m+3)`，够用。需要核对
     `free` 的定义是否允许这种改述。
  3. **主律改在 `iT` 层陈述**，把 `conjunct` 的 `b=2` 部分与
     `QvecV` 的层数一起重新对齐。
* **`m = 0` 实例已核验**（`OpenLawCheck2.lean`，全部 type-check）：
  * `qVec²(QvecV 0) = QvecV 2`，条目 `[^#0, ^#1, ^&0]`；
  * `conjunct 2 1 0` 的第二半向量是 `^#0 ∷ ^#2 ∷ 0`（长度 2），
    需读索引 0、1 —— 但 `QvecV 2` 在那里是 `^#0`、`^#1`，**第二项对不上**；
  * `QvecV 3` 的索引 2 是 `^#2` ⟹ 需要 `QvecV 3`。
  **结论：差一层是确定的，不是核算错误。**

### 出路的具体化（更新）

**出路 2 最有希望**：若外层向量用 `QvecV (m+1)` 而非 `QvecV m`，
下降两层得 `QvecV (m+3)` —— 对 `iTR`（`b=2`，最大索引 `m+2`）正好够。
`free L x = subst L ?[^&0] (shift L x)` 里的 `?[^&0]` 换成
`qVec L ?[^&0] = ^#0 ∷ ?[^&0]`（即 `QvecV 1`）即可。**但这会改变
`hAB` 的陈述**，需要回到 `HABKey.iT_free_eq` 重新对齐
（`free` 的向量选择与 `iT` 的层数必须同时调整）。

**出路 1 的核对点**：`iT n (^rel k R v) = iTR n k R v` 不下降；
下降只发生在 `subst` 施于 `iT` 结果时。所以关键量是
"`subst (W) (iTR (m+1) …)` 里 `W` 取什么"，即 `hAB` 里 `subst ?[^&0]` 的
`?[^&0]` 应换成多长的向量。**这正是出路 2 要回答的问题。**

## 7. ⚠️⚠️⚠️ 更根本的问题：向量**长度**也不匹配（2026-10-12 17:40）

§6 的"差一层"只是症状；逐项展开后暴露出**长度**问题。

### 核算（原子 `rel` 支，m = 0）

| | 向量 | 长度 |
|---|---|---|
| `free` 的代入向量 `?[^&0]` = `QvecV 0` | `[^&0]` | **1** |
| `iTR n 2 R v` 的 conjunct 向量 `^#j ∷ shiftVec 2 n`（n=1） | `[^#j, ^#2]` | **2** |
| `subst` 下降两层后 `qVec²(QvecV 0)` = `QvecV 2` | `[^#0, ^#1, ^&0]` | **3** |

三个长度 `1 / 2 / 3` **互不相同**，而：
* `termSubstVec L 2 (QvecV 0) v` 需要代入向量长度为 **2**（`v` 是 2-元向量），
  但 `QvecV 0` 长度是 **1** —— **类型上就接不上**；
* `substs_substs` 要求内外向量**长度相同**（`IsUTermVec` 的 `n` 是精确长度，
  不是上界——见 `IsUTermVec` 的定义 `n = len w ∧ …`）。

### 结论

**`hAB` 目前的陈述（用 `?[^&0]` 作代入向量）在类型层面就走不通**，
不只是"差一层"。

### 需要的修正（待用户/下一会话裁定）

`free L x = subst L ?[^&0] (shift L x)` 用的 `?[^&0]` 只把 bvar 0 换成 fvar 0。
但 `iTR` 的 conjunct 需要的是**长度 `n+1`** 的向量（`n` = 层数）。
两边的"打开绑定子"操作在**元层**是同一件事，在**编码层**却用了不同长度的向量。

可能的修法：
1. **改 `hAB`/`free` 的向量**：让 `free` 用 `qVec ?[^&0] = [^#0, ^&0]`（长度 2），
   则下降两层得 `QvecV 3`（长度 4），对 conjunct（长度 2）够了。但要核对
   `free` 的定义在别处（`hAll`、`Derivable.all_m`）是否可改。
2. **改 `iTR` 的 conjunct 向量**：把 `^#j ∷ shiftVec 2 n` 换成与 `free` 相容的
   形状。但 `iTR` 的语义要与 `arithTrln.translate` 的引号保持一致
   （`iT_quote` 已证），改动风险高。
3. **在元层重新推导**：直接用 `iT_quote` 处理**引号化**的公式
   （`p = ⌜φ⌝`），绕开"任意码"的困难——但 `hAll` 的 `p` 是 V 内任意码，
   §1 已记录此路不通。

**建议**：这是**研究缺口**，不是工程长尾。需要先确认
`iT_quote`（引号层）与 `iTR` 的向量约定，再决定改哪一侧。
