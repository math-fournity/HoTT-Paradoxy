## 0. 目标（一句话）

`hAll` 的唯一剩余前提 `hAB` 归结为码恒等式

```
iT 0 (free ℒₒᵣ p) = subst ℒₛₑₜ ?[^&0] (iT 1 (shift ℒₒᵣ p))          (p : IsSemiformula ℒₒᵣ 1 p)
```

它是下面**开口律**的 `m = 0` 特例：

```
iT m (subst ℒₒᵣ (QvecVOr m) q) = subst ℒₛₑₜ (QvecV m) (iT (m+1) q)     (q : IsSemiformula ℒₒᵣ (m+1) q)
```

其中 `QvecV m = QvecVOr m = [#0, #1, …, #(m-1), &0]`（长度 `m+1`），
即 `qVec` 对 `?[^&0]` 迭代 `m` 次。

## 1. 机制（为什么为真）

`subst` 下降一层绑定子时把代入向量 `W` 换成 `qVec W = ^#0 ∷ termBShiftVec W`
——**前置一个新的 `^#0` 并把所有索引 +1**。
`iTR` 内部有 `qqAlls … 2` 两层绑定，所以开口向量在那里已长到长度 `m+3`：

* 索引 `i < m+1` 处是 `^#i`（恒等）；
* 索引 `m+1` 处是 `^&0`。

而 `iVE (m+1) ^#z = eqAtom ^#(z+1)` 把源变量 `z` 放在索引 `z+1`——
于是**代入恰好落在变量槽上，不碰 `eqAtom` 自己的值槽（索引 0）**。
裸公式的"同索引交换"是**假**的（机器化反例：`ITSubstCounter.naive_law_is_false_shape`）；
这里的正确形式是"**在正确的槽上**交换"。

## 5. ⚠️ func 支的层次更正（2026-10-12 15:40，**已用 Lean 核验**）

> **核验方式**：`IVEOpenFunc13.lean` 里四条 `example` 全部 type-check
> （`QvecV 3` 的索引 1 是 `^#1`、索引 3 是 `^&0`；`QvecV 4` 的索引 3 是 `^#3`）。
> 结论：**`conjunct` 零件需要 `QvecV (m+4)`，不是 `(m+3)`**。

### 原推理（现已证实）

写 `subst_QvecV_conjunct` 时逐索引核算，发现 **`conjunct` 零件所需的向量层数
可能比"两层 qVec"高一层**。推理如下（**尚未机器验证，勿直接当作结论**）：

* `ve2 n k f w` 的体是 `imp (conjunct 3 n 0 w.[0] ⋏ (conjunct 3 n 1 w.[1] ⋏ ⊤)) …`
  且整体包在 `qqAlls … 2` 里。
* `conjunct b n i y = (subst ?[^#i] cDomN) ⋏ (subst (^#i ∷ shiftVec b n) y)`，
  其中 `^#i ∷ shiftVec 3 n` 的长度是 `n+1`，第 `j+1` 项是 `^#(3+j)`（`j ∈ 0..n-1`）。
* 对 `ve2 (mm+1) …`：`n = mm+1`，故该向量用到索引 `0..mm+1`，**最大索引的项是
  `^#(3+mm) = ^#(mm+3)`**。
* RHS 是把 `subst (QvecV (mm+1))` 施于整个 `ve2`，下降两个绑定子 ⇒ 体内向量是
  `qVec²(QvecV (mm+1)) = QvecV (mm+3)`，**长度 `mm+4`，索引 `mm+3` 处是 `^&0`**。
* 于是 `QvecV (mm+3)` 在索引 `mm+3` 处把 `^#(mm+3)` 映成 `^&0`，
  **不能**固定 `conjunct` 的向量。`QvecV (mm+4)`（长度 `mm+5`，索引 `0..mm+3`
  都是 `^#j`）才够。

### 已证实的后果

**`QvecV (mm+3)` 不足以处理 `conjunct`**：`conjunct 3 (mm+1) i y` 的第二半是
`subst (^#i ∷ shiftVec 3 (mm+1)) y`，该向量用到索引 `mm+1`，其项是
`^#(3+mm) = ^#(mm+3)`；而 `QvecV (mm+3)` 在索引 `mm+3` 处是 `^&0`。

**这解释了为什么 `subst_QvecV_subst_cFunc` 能证成而 `conjunct` 不能**：
`cFunc` 的代入向量 `[^#2,^#0,^#1]` 只用索引 `0,1,2`，`QvecV (mm+3)` 在其上是
恒等（因为 `2 < mm+3`）；而 `conjunct` 的向量伸到索引 `mm+1`，正好撞上
`QvecV (mm+3)` 的末槽。

### 关键区分：`iTR` 用 `b = 2`，`ve2` 用 `b = 3`

**这是决定性的**（`IVEOpenFunc13.lean` 两条 `example` 已 type-check）：

## 8. 新识别的一个缺口（2026-10-12 20:00）

`all`/`exs` 支需要 `subst (QvecV m) domZero = domZero`。

### 为什么 `subst_eq_self` 不够

Foundation 的 `subst_eq_self`（`Formula/Functions.lean:747`）签名是：

```
subst_eq_self (hp : IsSemiformula L n p) (hw : IsSemitermVec L n n w)
  (H : ∀ i < n, w.[i] = ^#i) : subst L w p = p
```

**`hw` 要求向量的长度 = `n` = 公式的层数**。但 `subst` 实际只读 `w.[i]`
（`i < n`），**长度无关**。`QvecV m` 的长度是 `m+1`；对 `domZero`（层数 1）
需要长度 1，而 `m ≥ 1` 时 `m+1 ≥ 2`。**接不上。**

### 需要的引理（长度自由版）

```
subst_eq_self_of_forall :
  IsSemiformula L n p → IsUTermVec L (len w) w →
    (∀ i < n, w.[i] = ^#i) → subst L w p = p
```

**证明路线**：对 `p` 结构归纳（`pi1_structural_induction`），
`rel`/`nrel` 支逐项用 `Bootstrapping.termSubst_eq_self`——
**它只要 `H : ∀ i < n, w.[i] = ^#i`，不含长度约束**（这正是关键）；
`and`/`or` 支直接归纳；`all`/`exs` 支用 `qVec`（长度 +1，`H'` 由 `H` 逐项给，
新项 `^#0` 自动满足）。

**本会话未完成**。**具体的卡点**：`pi1_structural_induction` 的
`definability` 义务要求 `P` 是 Σ₁ 或 Π₁ 关系，而
`P := fun n p ↦ ∀ w, IsUTermVec L k w → (∀ i < n, w.[i] = ^#i) → subst L w p = p`
里的 `∀ i < n, w.[i] = ^#i`（`w.[i]` 是**函数应用**）不是 Σ₁/Π₁ 可定义的，
`aesop` 因此失败。试过把 `k` 提到外层、去掉 `k = len w` 前提，都不解决。

**已排除的路线**：把 `QvecV m` 当作长度 1 的向量（`IsUTermVec ℒₛₑₜ 1`）
**不可能**——`QvecV m` 的长度是 `m+1`，而 `IsUTermVec` 的 `n` 是精确长度，
`1 ≠ m+1`（当 m ≥ 1）。所以 `subst_eq_self` 那条路根本走不通。

**已排除的第二条路线**：Foundation 的 `IsSemiformula.induction`（不带 definability 的
版本）在 `Formula/Basic.lean` 里是**被注释掉的**（`/-` 开始），只有
`pi1_structural_induction` 可用，而它要求 `𝚷ᴬ₁-Relation P`——`definability`
义务绕不过去。

### ★ 第三条路线（推荐，与 `shift_domZero` 同构）

`domZero` 是**引号化的元层公式**：`domZero = ⌜arithTrln.domain/[#0]⌝`
（`quote_domain_zero` + `emb_app_self`，正是 `ShiftDomZeroProbe.shift_domZero`
用的那一招）。所以应当**在元层**处理，而不是在 V 层做归纳：

```
subst (QvecV m) domZero
  = subst (QvecV m) ⌜domain/[#0]⌝                      （quote_domain_zero）
  = ⌜(domain/[#0]) ⇜ W⌝  其中 W 是 QvecV m 对应的元层项向量   （quote_substs'）
```

`quote_substs'`（`InternalTranslate.lean:318`）给出
`(⌜σ ⇜ w⌝ : V) = subst L (SemitermVec.val fun i ↦ ⌜w i⌝) ⌜σ⌝`。
只要能把 `QvecV m` 识别成某个元层向量 `fun i ↦ ⌜w i⌝` 的编码，
就归结为**元层命题**：`domain/[#0] ⇜ w = domain/[#0]`，
即 `w 0 = #0`（元层 `Semiterm.bvar 0`）——这由 `QvecV m` 的第 0 项是 `^#0` 直接给。

**注意**：`shift_domZero` 走的是 `quote_shift`（`Semiformula.quote_shift`），
`subst` 的对应物是 `Semiformula.typed_quote_substs`
（`Formula/Coding.lean:109`，`@[simp]`）——**用它可以避免直接构造 `QvecV` 的元层对应**。

### 已排除的两条路线（供参考，别重走）

* ~~`subst_eq_self`~~：要求向量长度 = 公式层数，`QvecV m` 长度 `m+1 ≠ 1`。
* ~~`IsSemiformula.induction`（无 definability）~~：在 Foundation 里**被注释掉了**；
  只有 `pi1_structural_induction` 可用，它要求 `Πᴬ₁-Relation`，
  而 `∀ i < n, w.[i] = ^#i`（函数应用）不可定义。
