## 速查表：每条死路的**杀伤范围**（ Master 指令加的列）

> 「一条路死了」不等于「所有同类都死了」。引用任何一条前先看它杀的是什么。

| # | 死路 | 杀伤范围（只杀这些变体） | **不杀**什么 |
|---|---|---|---|
| 1 | 等式形状 `subst (iVE …)` | 任何含 `subst ℒₛₑᵧ W (iVE n t)` 且把 `iVE` 输出当项向量的**等式** | 蕴含形状；不含 `subst (iVE …)` 的新桥 |
| 2 | `iT_substs1_term` 类型错 | 「用 `iVE` 输出当 `subst` 向量位」的所有变体（不论等式/蕴含） | 向量用 `?[^#0]` / `?[^&0]` 的新桥 |
| 3 | 语义路线 | 任何**经过 `SetTheory.complete`**、需要把 V 层码变 `SetTheorySentence` 的变体 | 纯语法/推导层的证明 |
| 4 | 收窄 t | 任何**改 `ExsBridge2` statement** 加 `IsTermFVFree` 的方案（会让归约在 fvar 上失效） | 不依赖收窄 t 的证明 |

**最常被误引的是第 1 条**：`ITSubstCounter.lean:43` 那条例证常被当成「iVE 相关的都不行」。
**它只杀等式、只杀 `subst (iVE …)` 这个构形。** 任何不含该构形的新桥不受它影响。

## 死路 1：等式形状 `iT 0 (substs1 t p) = subst (某物) (iT 1 p)`

**为什么死**：`ITSubstCounter`（本树 `ZFC/ITSubstCounter.lean`，公理干净）机器证伪了同族命题：

```lean
-- ITSubstCounter.lean:43  naive_law_is_false_shape
theorem naive_law_is_false_shape (x : V) :
    subst ℒₛₑᵧ ?[^&0] (iVE (1 : V) (^&x : V)) = ^rel 2 ↑cEqN [^&0, ^&x]   -- 不是 eqAtom ^&x
```
真因：`eqAtom t = ^rel 2 cEqN [#0, t]` **自带 bvar 0**，`subst` 撞的是它自己的绑定变量。

**⚠️ 但注意杀伤范围**：这只杀**等式**形状。`ExsBridge2` 是**蕴含**，
`imp (iT 0 (p[t])) (^∃ …)` 里**根本没有 `subst (iVE …)` 这一项**，
所以这条证伪**不直接适用于 `ExsBridge2`**。
把它当成「等路线已死、只剩蕴含」的标记，别当成「蕴含也死」的证明。

## 死路 2：`iT_substs1_term`（中间引理版等式）

**为什么死**：**类型层错**。`subst L w p` 的 `w` 语义是**项向量**，
而 `iVE n t` 的输出永远是**公式**（`eqAtom` / `ve0` / `ve2`）。
把公式码塞进项向量位 = 两个无意义的东西「相等」。

**危险之处**：Lean **会接受这个 statement 的类型检查**（那里写的是 `V`，不是类型化的
`IsUTermVec`），所以看起来像个正常目标。001-Flash 写完 statement 才发现是假的，
001-Step 独立发现同一点并撤回。
记录见 `ZFC/ExsBridge3.lean`（提交 `9f6e38b5`，文件头有撤回段）。

**教训（通用）**：**statement 能类型检查 ≠ statement 有意义。**
本 codebase 里几乎所有东西都是 V 里编码的，类型错误会退化成「两个乱码相等」。

## 死路 3：语义路线（`SetTheory.complete` + 模型事实）

**为什么死**：`SetTheory.complete` 的签名要
```
complete : ∀ (T : SetTheory) [𝗘𝗤 ℒₛₑᵧ ⪯ T] (φ : SetTheorySentence), (∀ M …, M ⊧ φ) → T ⊢ φ
```
**`φ : SetTheorySentence` 是 Lean 的类型化句法对象，不是 V 层的码。**
`ExsBridge2` 要证的是 V 层码命题 ⟹ 卡在「把码变成引号」那一步，
而**反向引理（码 → 引号）已被机器核验为假**（非标准码）。

**关键细节**：这不是「t 的问题」，是 **`p` 的问题**。
004-Step 曾猜「闭项 t 可能救语义路线」，`W8-semantic-closed-t-20261014.lean`
已核验**否**：`substs1 t p` 只影响子项 `t`，**不改变 `p` 本身**；
而要把含 `p` 的 V 层码变成 `SetTheorySentence`，仍要反向引理。

**附带的前提不匹配（会挡掉很多看似可用的 Foundation 工具）**：
`ExsBridge2` 在 `[ORingStructure V] [V↓[ℒₒᵣ] ⊧* 𝗜𝚺₁]`，而
* `NumeralSemantics.eval_numeralF_iff`（本树 `ZFC/NumeralSemantics.lean`（顶层 `variable` 段））要
  `[SetStructure V] [V↓[ℒₛₑᵧ] ⊧* 𝗭]`
* `ArithInterp.lean:73` 的 `SetTheory.complete` 范式同理
⟹ **hExs 的证明必须全程留在算术侧**，任何依赖 `SetStructure` 的引理都不能直接引。

## 死路 4：收窄 `t`（改 statement 加 `IsTermFVFree`）

**为什么不行**：`IsTermFVFree` **存在且好用**
（`foundation-src/Term/Functions.lean:696`：`IsTermFVFree L n t := IsSemiterm L n t ∧ termShift L t = t`；
`Functions.lean:703` 有 `@[simp] ¬ IsTermFVFree L n ^&x`；001-Flash 本树核验 5 条探针全 clean，提交 `2a23452b`）。

**但 Foundation 的 `exsIntro` 只要求 `IsTerm`**：
```lean
-- foundation-src/.../Proof/Basic.lean:808
lemma ex_m {s p t : V} (h : ^∃ p ∈ s) (ht : IsTerm L t) (hp : …) : Derivable T s
```
所以 Craig 推导的 `exsIntro` **给不出比 `IsTerm` 更强的保证**。
把 `ExsBridge2` 收窄成「t 无自由变量」会让 `exsBlockerQ_of_bridge2`（004-Step 证的归约）
**在含 fvar 的 t 上失效** ⟹ **不能改 statement**。

**结构事实（001-Flash 机器证，`ProbeExsRetype.lean`）**：层 0 的项
* **不含绑定变量**（`example (z : V) : ¬ IsSemiterm ℒₒᵣ 0 ^#z := by simp`）
* = 「函数符号作用于层 0 项向量」，叶子只有**自由变量**或 **0 元函数符号**（zero/one 是闭的）
⟹ 这是唯一可能被利用的结构约束，但它不能用来改 statement。

## 非反例：`t = ^&0`、`p = ^rel 2 ↑cEqN [#0, #0]`（即 `#0 = #0`）

**为什么不是反例**：004-Step 核验——LHS 与 RHS **两边都真**
（LHS 是 `a = a` 型，RHS 是 `∃x∈ω, x = x`）。所以
「两边自由变量集不同 ⟹ 桥为假」这个论证**还没找到具体反例**。

# 活路线（Master + 001-Step 定出的桥候选形状，2026-10-14）

## exs 桥的候选形状

```
iT 0 (substs1 t p) = subst ℒₛₑᵧ ?[^#0] (domZero ^⋏ iT 1 p)
```

**它可能活着的三条理由**（对照上面六条死路逐条检查过）：

1. **向量是 `?[^#0]`（绑定变量）**——不是 `?[t]`、不是 `subst (iVE 0 t)`。
   **类型上就对了**（`^#0` 是项，不是公式码），直接躲开死路 1 和 2。
2. **`domZero` 在等式里** ⟹ **witness 引理整条义务消失**（「t 的值在 ω」不再需要证）
   ⟹ 躲开死路 4 与 `IsTerm` 前提不足的整个问题。
3. **不依赖 t 含不含 fvar**（t 只在 LHS 现身）⟹ 非标准元问题不影响。

**模仿对象**：all 支的 `bridgeB`（也是等式、也是单变量向量）——exs 支把 `?[^&0]` 换成 `?[^#0]`。
`bridgeB` 原文（Master 树 `MasterAssemblyProbe.lean`）：
```lean
theorem bridgeB (q : V) (hq : IsSemiformula ℒₒᵣ (1:V) q) :
    subst ℒₛₑᵧ (?[^&0] : V) (iT (1 : V) q) = iT (0 : V) (subst ℒₒᵣ (?[^&0] : V) q)
```

**归约侧已就绪**（我核过，见上一节）：`exsBlockerQ_of_bridge2` 只吃一个前提、无隐含丢失。
所以**只要这条等式证出，`ExsBlockerQ` 立刻到手**。

## 结构性禁区（与上表第 6 条同源，值得单独记）

**任何用 `?[^&0]`（自由变量）做 exs 桥 witness 的方案都危险。**
理由（001-Step 的结构性结论）：那等于要求「对所有 x（含 x ∉ ω）都满足」
⟹ 即 ω 的初等封闭 ⟹ **在非标准模型里为假**。
⟹ exs 桥的 witness 侧**必须用绑定变量 `^#0`**，不能用自由变量。
