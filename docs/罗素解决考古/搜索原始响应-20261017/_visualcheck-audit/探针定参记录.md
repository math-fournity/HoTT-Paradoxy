**关键发现 1（存储格式）**：`-mono` 直出的 PNG 内容上是二值（2 色），但**存储深度是 8-bit**（每像素 1 字节），这是直出文件大（1.5–6.7 MB）超出方案预期（100–300 KB）一个数量级的主因。

**关键发现 2（清晰度逐档，analyzeImage 视觉审计）**：

- **200 dpi**：页眉可读（"E. ZERMELO. Grundlagen der Mengenlehre. I."）；正文可读但边缘粗糙（中等锯齿）；**脚注已接近可读极限**——锯齿严重、笔画宽度接近单像素、细笔画有断裂风险（如 "t" 横竖连接处、"vol." 的 l）。
- **300 dpi**：正文完整可读（轻度锯齿，descender/衬线完整，"fi" 连字未粘连）；**脚注完整可读，页码 "366—368, 46, 481" 可精确抄录、三位数字无一位缺损**；星号脚注标记清晰。
- **400 dpi**：完全清晰、页码可精确抄录，但相对 300 dpi **已接近收益平台（diminishing returns）**——不解锁新的可读性层级，文件反而大 (400/300)² ≈ 1.78 倍。

| 版本 | 文件 | SHA-256（前 16 位） | 大小 | 墨水覆盖率 | 视觉结论（analyzeImage） |

| threshold 50% | `probe-r300-th50.png` | `10bb2d0f0ba2eda5` | 751 KB | 9.46% | **笔画饱满、边缘锐利、字腔适中、分隔线连续、无丢失无膨胀——最佳平衡点** |
| threshold 60% | `probe-r300-th60.png` | `faa37c6daeb3c766` | 753 KB | 10.16% | 笔画膨胀、字腔缩小、间距压缩、有粘连倾向与糊化前兆 |

压缩参数附加测试（以 th50 751 KB 为基准）：`-define png:compression-strategy=2`（filtered）反而 2.19 MB、`strategy=3`（Huffman）1.06 MB、`compression-filter=0` 750 KB（与默认持平）——**默认 filter + `-compress zip` 即最优**。

## 4. 内容一致性/差异量化

- mono 直出经 `-threshold 50%` 重处理：与直出**逐像素 0 差异**（已二值图像不受影响）。
- mono 直出 vs 各阈值版（灰度管线）差异均为 ~3.4% 像素（3.56M–3.63M / 总 105,358,428）——差异量级相同，说明两条管线（渲染时硬二值化 vs 抗锯齿渲染后阈值化）的差别主要在**边缘像素分布**（抗锯齿处理方式），而非阈值选择本身。
- mono 直出的额外像素是边缘"黑化"噪点：对逐页文字审计是噪声不是内容，且导致 PNG 压缩率低（1-bit 重编码后仍 2.1 MB/页）。
- 三档 dpi 的 mono 直出墨水覆盖率几乎一致（10.18–10.38%）——`-mono` 阈值行为稳定，但其边缘质量劣于灰度+threshold 管线。

## 5. 最终定参（全项目 692 页统一）

| 项 | 定参值 |
|---|---|
| 渲染分辨率 | **`-r 300`** |
| 管线 | **两步：`pdftoppm -png -gray -r 300`（抗锯齿灰度渲染）→ `magick -threshold 50% -strip -define png:bit-depth=1 -compress zip`（二值化 + 真 1-bit 压缩）** |
| threshold | **50%**（需校准；40% 丢浅印、60% 有粘连，50% 是唯一验证过的平衡点） |
| 输出格式 | PNG，1-bit 深度，grayscale，默认 filter + zip 压缩，`-strip` 去元数据 |
| 单页产物大小 | **约 750 KB**（探针实测 751 KB） |

**不用 `-mono` 直出**的理由：(1) 内容上与 th50 无丢失差异，但边缘噪点（"发虚"）对逐页比对不利；(2) 1-bit 重编码后仍 2.1 MB/页，692 页 ≈ 1.45 GB，不可行；(3) 灰度+th50 管线 750 KB/页、692 页 ≈ 519 MB。

**跳过与否的判定**：本探针**选择做**阈值校准（而非跳过），因为实测发现 `-mono` 直出除清晰度外还有**文件大小不达标**的独立问题，而 threshold 校准同时解决两者（750 KB 达标 + 视觉更干净）。

## 6. 文件大小权衡（如实说明与方案预期的差异）

- 方案预期 100–300 KB/页；探针实测 **751 KB/页**（300 dpi 1-bit PNG）。
- 差异原因：方案预期可能按 200 dpi 或有损压缩估计；300 dpi 下 105M 像素 2 色 PNG 的无损压缩天际线约 750 KB（已测默认/Huffman/filtered 等压缩组合，最优即 750 KB）。
- 总量影响：692 页 × 751 KB ≈ **519 MB**（git 入库量）；相对彩色页图（4–6 MB/页 × 692 ≈ 2.8–4.2 GB）小 **5.5–8 倍**——接近但严格说不足"一个数量级"。
- 取舍：**审计质量优先**。降 dpi 到 200 可接近方案预期大小但脚注质量不达标（接近可读极限，引用页码无法保证逐位核对）；有损压缩不适合逐行文字比对。维持 751 KB/页。
- 预计批量耗时：692 页 ×（pdftoppm 渲染 + magick 读写 ~15 MB 中间文件）≈ 每页 3–5 秒，全量约 40–60 分钟。

## 7. 批量转换标准命令行（供后续转换代理直接使用）

```bash
# 前置变量（逐份 PDF 执行一批）
PDF="<pdf绝对路径>"          # 如 /Volumes/D/HoTT_AI_HANDOFF_20260911/docs/罗素解决考古/搜索原始响应-20261017/zermelo1908-pp261-281.pdf
OUT="<审计二值图输出目录>"    # 如 <响应目录>/_audit-binary/zermelo1908-pp261-281
TMP="<临时目录>"             # 建议 <响应目录>/_audit-binary/_probe 或 /tmp 专用子目录（可重算中间文件）
PAGES=$(pdfinfo "$PDF" | awk '/^Pages:/{print $2}')

mkdir -p "$OUT"
# 逐页处理（磁盘峰值 ≈15 MB，安全；输出页码统一 3 位）
for i in $(seq 1 "$PAGES"); do
  pdftoppm -png -gray -r 300 -f "$i" -l "$i" "$PDF" "$TMP/gray"
  f=$(ls "$TMP"/gray-*.png)
  magick "$f" -threshold 50% -strip -define png:bit-depth=1 -compress zip \
    "$OUT/$(printf 'page-%03d.png' "$i")"
  trash "$f"   # 临时灰度图；脚本环境无 trash 时用 rm
done
```

注意事项：
- **路径含中文，所有变量必须双引号包裹**。
- pdftoppm 单页输出的文件名页号位数随 PDF 总页数变化（21 页 → `gray-01.png`，325 页 → `gray-001.png`），故用 `ls "$TMP"/gray-*.png` 取实际产物名。
- 临时灰度图是**可重算的中间产物**，不留档；最终 1-bit PNG 是交付物，逐页登记 SHA-256。
- 不要用 `-mono` 直出（见 §5）；不要加 `compression-strategy`（见 §3，反而变大）。
- 探针样张（最终管线的产物即 `probe-r300-th50.png`，751 KB）可作后续各批转换后的抽查基准。
