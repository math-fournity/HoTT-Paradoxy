## 2. 本会话实测校正的实物事实（接手者免重趟，比 01 §7 更细）

这些是本会话真实踩过并修掉的点，01 文档写作时未知：

1. **`import Lean` 可用**：`Qualification.lean` 需要它跑 `run_cmd` 公理审计。担心过
   `MATHLIB_CLOSURE.json` 闭包（1,893 模块）不含 `Lean` 模块会失败——实测通过：闭包校验
   只查 JSON 内列出的模块 digest，`import Lean` 由 `lean_path`（工具链 prefix 的
   `lib/lean`）解析，`Lean.olean` 是工具链自带、不需入闭包。先例：`termination-gate`
   的 `QualificationGate.lean` 同样 `import Lean` 且有正式收据。
2. **Foundation 接口三修**（编译必错点，已修在源里，但改包时要记得）：
   - `foundation`（`Z/Z.lean:496`）的 `IsNonempty` 是 **instance 隐式**参数——不能
     `foundation s (isNonempty_def.mpr …)` 位置传参，要 `haveI : IsNonempty s := ⟨w, hw⟩`
     后 `foundation s`（`haveI` 会触发 style linter 警告，无害，可 `have` 替代）。
   - 包内 `autoImplicit=false` 且裸文件没有 `Type*` notation 与 `SetStructure`——必须
     `import Foundation.FirstOrder.SetTheory.Basic.Misc`（或 `Z.Z`）+ `open FFL`（用到
     `𝗭`/`⊧*` 时加 `open FFL.FirstOrder FFL.FirstOrder.SetTheory`，照抄
     `zfc-con-pa-boundary` 文件头）。
   - `mem_sep_iff` 全隐式参数：实例化传 `fun _ => mem_sep_iff` 即可（实测通过）。
3. **合取组装用 `@`**：`qual_russell_arch` 的证明字段用 `⟨@noRussellSet, @sep_russell_not_mem, …⟩`
   全显式形式——写 `fun _ _ => noRussellSet` 会触发 implicit lambda 特性导致类型错位
   （`V✝` 被当作第一个显式参数吃掉），这是本会话唯一一次非平凡的编译失败。
4. **负控制收据的 sources 是完整 build order + 负控文件在最后**（照
   `ZFC-CON-PA-BOUNDARY-NEG-01` 先例）：正控五文件 + `GodelQ/Negative/WrongSepContradiction.lean`，
   一次调用出 REJECT 收据。
5. **`devbuild_ns.py` 用法**：`python3 …/devbuild_ns.py HoTT/formal/claude-cg001/russell-archaeology <源文件…>`——
   源路径**相对包目录**；缓存落 `tools/devbuild_ns/russell-archaeology/`（未跟踪产物，
   不进收据）。它快（单文件秒级），适合迭代；正式收据才用 `capture_run.py`（每次全量
   重验工具链与 1,893 模块哈希，约几十秒）。
