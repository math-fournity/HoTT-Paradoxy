## 4. 本审计提出、但尚未写入规划的补强项

以下是 audit recommendation，不是已经完成或擅自采纳的新需求；在修改规划前应由当前 maintainer 原位审阅：

1. **source-closure preflight**：P1 前要求 source `proof-version closure` 和数学治理 contract 已有可解释 PASS，或明确把旧 verifier 的失败列为 release-specific closure 重建前置。
2. **typed negative-control schema**：为 R07 列 `expected exit`、诊断 class、normalized hashes、正对照与非对象层断言；不再让 generic positive theorem verifier 假装覆盖它。
3. **GOLD bridge decision**：强制选择“只公开组件化 cut 条件”或“先补 `Lₚ/Uₚ → dcut` packing proof”；两种文字不能混用。
4. **manifest dependency repair**：GOLD 与所有 release unit 的新 manifest 必须固定 Agda binary、Cubical archive/tree、library file、依赖 closure 和许可证来源。
5. **CI least privilege + recovery**：CI 必须以 read-only contents / 无 secrets / pinned actions 为最低边界；P4 增加公开后错误发现时的 revert/correction/retained-evidence 路线，而不是把 `POST_PUBLISH_VALIDATION_FAILED` 当作终点。
6. **M3 status selection**：确定 M3 是首页的历史条件对照、manifest 的 `SUPERSEDED` 证据，还是与 M3-UNC 并列的读者可见结果；不能以两个“最终结论”造成重复负担。
