## 2. R07 的历史 receipt 不能直接成为 release receipt

R07 当前有八个最终相关运行：

| 运行 | 旧 status / 记录 exit | 本审计观察 | 发布阻塞 |
|---|---|---|---|
| TA-01 | `KERNEL_ACCEPTED_WITH_SCOPE`, 0 | UA 公理化模块可编译 | 不是 safe theorem；必须标为控制条件。 |
| TA-02 | `META_CONTROL_PASSED_AS_EXPECTED`, 0 | 正常 `zero ≡ zero` 通过 | `command_argv` 含人类说明性 cwd/env 文本。 |
| TA-03/04 | `META_NEGATIVE_CHECK_AS_EXPECTED`, 1 | 当前 Agda 实际返回 `42`，分别拒绝零/一 refl | 旧 exit 字段不再可作为 exact replay oracle。 |
| TA-AC-01/02 | `META_NEGATIVE_CHECK_AS_EXPECTED`, 1 | 当前 Agda 实际返回 `42` | 同样的 argv / exit drift。 |
| TA-LEM-01/02 | `META_NEGATIVE_CHECK_AS_EXPECTED`, 42 | 当前 expected `UnequalTerms` 仍可复现 | argv 结构较完整，但 generic positive-run verifier 不消费 negative status。 |

未来 release manifest 必须建立单独的 `EXPECTED_NEGATIVE_CONTROL` 合同，至少有：

```text
control_id, source_paths, exact argv, expected_exit, expected diagnostic class,
normalization policy, stdout/stderr hashes, positive-control dependency,
why this is a meta-level control, and object-level nonclaims
```

历史 `RUN.json` 不应重写，因为它们是历史证据；应由新的 portable replay receipt 记录新命令和新观察。

## 3. source-manifest 与依赖闭包

M1、M2、M3、M3-UNC、BP、TA、REAL-LAYER、Rebound 与 Necessity 的 source manifests 包含 `TOOLCHAIN.json`、`AGDA_LIBRARIES` 和 Agda/Cubical 外部依赖身份。GOLD-02 的 source manifest 却只列出 `CutGoldForm.agda`、`CutInfra.agda`、`compile.sh`、`AGDA_LIBRARIES` 与设计文档，未列 `TOOLCHAIN.json` 或 Cubical release/tree identity；而其 argv 实际依赖它们。

这不否定 GOLD-02 已保存的本机 kernel run，却意味着其 historical manifest 不是未来 portable dependency closure。P1 必须新建 release-local toolchain descriptor 与 dependency closure，不应偷偷回填旧 manifest 来伪造历史完整性。

## 4. 全局 proof closure 当前失败

[`PROOF_VERSION_CLOSURE.json`](../HoTT/verification/PROOF_VERSION_CLOSURE.json) 的 frozen baseline 是 `d3dfb0e…`，而 [`verify_proof_version_closure.py`](../scripts/audit/verify_proof_version_closure.py) 第 406–413 行要求当前 matrix 逐字以该 frozen matrix 为前缀。当前实际运行结果：

```json
{"status":"BLOCKED","error":"CURRENT_MATRIX_NOT_APPEND_ONLY_SUCCESSOR"}
```

直接 Git diff 显示 M1 被插入到 frozen top-level proof summary 表，而不是仅追加在 frozen 文末；因此错误是 evidence-index 演化与 verifier 的 append-only 前提不一致。该失败并不反证已重放的单个 Agda theorem，但它禁止说“所有候选包的 source/run/index/Git 关系已由该全局 closure verifier 验证”。

此外，当前 `later_packages` registry 中只列出 `MP-DEDEKIND-OMEGA-REAL-LAYER`；M1、M2、M3、M3-UNC、BP、GOLD、TA、Rebound 和 Necessity 还没有被该 registry 作为后续 package 完整纳入。未来修复应创建新的、不变的 release-specific closure snapshot，而不是让已有 v2 registry 承担它从未登记的单位。

## 5. 数学交付治理 checker 当前失败

[`verify_math_proof_delivery_governance.py`](../scripts/audit/verify_math_proof_delivery_governance.py) 当前输出：

```text
MARKER_MISSING:.codex/AGENTS.md:math-proof-delivery-gate:v1
```

根 `AGENTS.md`、PROTOCOL 和业务 Skill 中仍有数学交付门禁；失败原因是 `.codex/AGENTS.md` 已变为导航页，而旧 checker 仍要求它复制 marker。故这是 validator 与导航重构的 contract drift，不能被解释为数学 gate 消失，也不能被忽略为绿色通过。修复时应选择：让 validator 接受导航指针，或加入不会制造第二份规则正文的 machine-readable pointer marker，并为这个行为增加正/负测试。

## 6. portability 的直接反例

在 detached audit worktree 以 historical argv 重放 M1，会因为 source 相对路径与 argv 中绝对 include root 指向不同 worktree 而报 `ModuleDefinedInOtherFile`；在主工作树同一 argv 才能 byte-exact 成功。这是已观察到的事实，直接证明历史本机 replay 与未来 independent portable replay 是不同的验收对象。公开包不能将旧 `/Volumes/D/...` argv 原样写入 CI 承诺。
