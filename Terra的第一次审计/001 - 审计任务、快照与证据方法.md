## 3. 证据等级与用语

| 标记 | 含义 | 本报告中能支持什么 | 不能支持什么 |
|---|---|---|---|
| `PERSISTED_KERNEL_RUN` | repo 内保存的 `RUN.json`、stdout、stderr、environment、source-manifest 和索引行 | 给定工具链、源 hash 与命令下的已保存 kernel 结果 | 现实解释、外部认可或不同工具链泛化 |
| `SESSION_RERUN_OBSERVED` | 本审计期间以保存 argv 对当前 source 执行的 replay | 当时 exit/stdout/stderr 与保存收据一致的现场观察 | 独立新 run receipt；未来机器仍应重跑 |
| `STATIC_CONTRACT_CHECK` | validator 对文件结构、哈希或关系的检查 | 所检查结构的通过/失败原因 | 数学重证或模型理解 |
| `SOURCE_INSPECTION` | 对精确源文件、类型和直接 `postulate`/option 的阅读 | 源码中实际声明、可见依赖和缺失连接 | 未读取理论/库/现实模型的全局否定结论 |
| `INTERPRETIVE_INFERENCE` | 从形式命题到“任务”“完成”“现实”的解释 | 有标明前提的研究讨论 | 已形式推出的数学结论 |
| `OPEN` / `CONJECTURE` | 未闭合的证明、模型或桥梁义务 | 未来需解决的精确问题 | 已完成结论 |

因此，“数学真理性”在本报告中分三层：

1. **形式层**：固定 Cubical Agda 系统中，给定类型的 inhabitation/非 inhabitation/等式是否被 kernel 接受；
2. **规格忠实层**：自然语言陈述是否没有扩大类型中的量词、假设、理论变体或依赖；
3. **研究目的层**：该规格是否真的连接同一现实任务、理论化步骤与不可兑现的完成条件。

只有第一层的大部分局部命题已获得强证据；第二层有若干明确缺口；第三层仍未闭合。

## 4. 本审计实际调用的可复核入口

下列命令和 owner 是报告中的主要可复核入口；命令输出不在此处伪装成新的 primary receipt，原 run 目录仍是数学证据 owner：

```text
python3 -B scripts/audit/verify_formal_proof_run.py \
  --project-root . --run-dir HoTT/verification/runs/<RUN-ID> --rerun

python3 -B scripts/audit/verify_proof_version_closure.py --project-root .
python3 -B scripts/audit/verify_math_proof_delivery_governance.py --project-root .
python3 -B scripts/audit/verify_governance_shards.py
```

理论变体和二进制/库身份由 [`TOOLCHAIN.json`](../HoTT/formal/dedekind-omega-missile/TOOLCHAIN.json) 固定：Agda `2.8.0-3d04bac` / release v2.8.0、Cubical v0.9、release asset hash、二进制 hash、库 tree hash 与 `AGDA_LIBRARIES` 路径。该文件本身含开发机绝对缓存路径，所以它是 source 项目的历史可重放证据，而不是未来公开 CI 的相对路径合同。

## 5. 四件套与研究航向的受限作用

四件套和 [`HoTT研究三问`](../HoTT/HoTT研究三问-找什么-怎么找-凭什么-20260909.md) 用于限制解释：当前研究目标是考察指定 HoTT 表示/解释与现实完成任务的关系，不是预设 `HoTT ⊢ ⊥`。它们不能代替本报告的 proof source/run/index，也不进入未来公开结果包。与此一致，本报告把“现实桥梁未闭合”写成开放义务，而不把哲学动机改写成已有定理。
