research hydration 对两个 active record 均返回 `review_required`。这只证明 source identity 不一致，不证明哪一版正确或谁修改。

## 2. FR-001 目标

确定 active Goal 与 R4 TaskSpec 的 intended current content、来源、适用状态和 pin，消除“actual 文件与 STATE record 各自自称 current”的冲突。

FR 不以“把 pin 改成 actual hash”为完成。完成要求是内容身份被证据裁决，source hash、revalidation、相关投影和 checkpoint 同步。

## 3. 共同前置

1. 冻结 actual goal/R4、STATE record、S151 checkpoint、R3→R4 obligations、相关生成脚本和用户来源的 path/hash/time/status；
2. 查 Git、checkpoint、Session、dev-notes、允许读取的 Host trajectory/备份 locator；
3. 区分 byte snapshot、片段、语义摘要、record pin 与作者自述；
4. 保存搜索范围与未检查位置，不把未命中写成全局不存在；
5. 保留现有文件不覆盖，直到 intended content 判定完成。

## 4. 路径 A：旧 bytes 可恢复

1. 核旧文件 SHA 与来源时点；
2. 对 actual/pinned 做全文 diff；
3. 逐节分类：用户目标变化、证据更新、方案扩写、措辞变化、未登记漂移；
4. 回到用户指令、rulings、Feature 和底层证据裁决；
5. 写 FR report，列 accepted/rejected/unknown；
6. 通过 canonical checkpoint 原位重钉。

## 5. 路径 B：旧 bytes 未恢复

1. 登记 `HISTORICAL_PIN_SOURCE_NOT_RECOVERED`；
2. **禁止**声称完成 actual-vs-pinned 文本 diff；
3. 从 STATE、S151 Session/RUNS、obligation JSON、用户原文、rulings、生成脚本和 actual 文件建立 `SEMANTIC_RECONSTRUCTION_WITH_MISSING_BYTE_BASELINE`；
4. 每项只允许：

```text
SUPPORTED_CURRENT_CONTENT
SUPPORTED_HISTORICAL_INTENT
NEW_UNPINNED_CONTENT
CONFLICT
UNKNOWN_DUE_TO_MISSING_SOURCE
```

5. 只有 `SUPPORTED_*` 且无冲突的内容进入 intended version；
6. `NEW_UNPINNED_CONTENT` 必须找到用户/Feature/证据来源，否则保持 proposal；
7. `UNKNOWN` 不由当前文件存在填补；
8. checkpoint 记录缺失基线，不伪造 before copy。

### 5.1 审计引用锚点子步骤

旧 bytes 缺失时，还要为所有依赖 affected source 的审计结论建立引用分母，不由审计者只挑几段“关键引文”。每条至少记录：

```text
anchor_id
audit claim/report locator
claimed source path/section
quoted literal or semantic proposition
materiality
current locator/hash
current status
evidence level
effect on dependent conclusion
```

允许状态：

```text
PRESENT_EXACT
PRESENT_WITH_SEMANTIC_CHANGE
ABSENT_IN_CURRENT
AMBIGUOUS
UNVERIFIABLE_WITHOUT_OLD_BYTES
```

exact quote 用 literal search；概念主张做 section/semantic review。旧 bytes 不存在时，历史审计文本最多证明 `SOURCE_REPORTED_OLD_ANCHOR`。changed/absent/ambiguous 必须传播到依赖判词；只有提取分母和处置 `remainder=0` 时，才能声称受影响审计引用已全量检查。

第九轮演示的 4 个 current exact anchors 均存在，但初始 GLM 审计有 29 行直接引用 goal/R4；4/4 是 seed，不是完整 denominator。

## 6. 用户裁定与 canonical integrator

- 既有用户指令、rulings 与 Feature 足以唯一裁决时，由 canonical integrator 执行并引用旧来源；不重复询问；
- 只有两个版本表达互斥目标、既有权威无法消解时，才请求新的用户选择；
- 新决定进入 `rulings.md`；执行旧决定只在 FR report/checkpoint 引用既有 ruling；
- read-only recovery、hash、inventory 和 semantic reconstruction 在用户要求执行本方案后即可开始；owner mutation/checkpoint/commit 各按已有授权执行。

## 9. VC-001：版本闭合

在相称 Git 授权下：

1. `git status --porcelain=v1 -uall` 冻结完整路径与两列状态；
2. 每个 proof package 枚举 source/run/index/dependency/source identity；
3. 审计往返、baseline/meta、S-AUD 作为独立审计批次，不与数学包混交；
4. 每批跑 closure verifier、link/hash、`git diff --check`；
5. 精确 stage/commit，回读 tree 与路径；
6. 只对实际进入 commit 的资产翻转 version status。

commit 只使“source-reported 记录”可恢复；它不把原事件升级成已独立验证，也不补造缺失 double-pass receipt。

## 10. owner baseline v2 的角色

44 路径 baseline 是 2026-09-15 的 selected-path 历史附件。它不是全 owner universe、非原子、不归因，且未安装为治理工具。除非以后出现两次同型归因失败并证明现有 Git/checkpoint 不足，不建设第二套 manager。

## 11. VC 验收与返回研究

- 接受批次有 exact manifest/commit；
- 未提交残余按 owner/source/status 保留；
- proof closure 对提交快照通过；
- 无混入其它作者或未验收路径；
- 历史无 receipt 项证据等级不变；
- 高价值证据可恢复后停止整理，返回 PSJ/TGSQ。
