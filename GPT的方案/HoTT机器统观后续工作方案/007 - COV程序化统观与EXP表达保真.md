# COV程序化统观与EXP表达保真

## 1. CE-MAP 的正确身份

CE-MAP v1 对 revision-149 的 478 个具名输入完成 478/478 登记，保留 69 explicit unknown。它证明 named-artifact registration coverage，不证明真实候选空间或开放学术世界穷尽。

COV 不废弃 CE-MAP，而是让 external task、source-grounded consumer、formal calculus、跨框架结果、negative holdout 和新论文进入其输入。

## 2. 八轴搜索张量

```text
TheoryConstruct
× AbstractionChange
× RealityOrTask
× ConsumerOrContext
× ObservationLayer
× CompletionProperty
× Oracle
× FrameworkOrModel
```

每个 TaskSpec 固定：calculus、CandidateClass、generator、reducer、consumer、observation、completion、oracle、denominator、controls、coverage claim、unknown ingress、invalidation、stop/reopen。

不能定位的现象先登记 provisional 新类别，不为保护 taxonomy 将其排除。

## 3. 六类生成器的真实薄切片

| 生成器 | 首个真实链 |
|---|---|
| typed term/proof synthesis | exact R4 target 的 Nat＋Path 小 grammar，列 unsupported constructs |
| rule mutation/ablation | PSJ construct 与 comparison calculus 的单因素消融 |
| consumer/context synthesis | 从来源化 signature 生成 well-typed context，保留 synthetic 标签 |
| self-reference/universal computation | 复用 ProgramCode/T3，接 exact proof relation |
| metamorphic/differential/property | CAN 五对照与第二 kernel/version transfer |
| source/AI-guided proposal | source/spec 冻结；AI 提 typed candidate；holdout verdict 不可见 |

六个空目录、六份计划或六个候选名字不算 P2 横向骨架。每类至少一条：

```text
input → candidate → oracle → receipt
```

## 4. 相对完备性

- finite grammar：成员分母、coverage proof／独立重算、remainder=0；
- infinite codes：dovetailing/iterative deepening、no-starvation receipt；
- class reduction：total、typed、termination、task/consumer/observation/completion preservation；
- open world：source/version/consumer ingress、out-of-envelope holdout、unexpected-result stale propagation。

timeout、目录数、关键词数、LLM 一致和 `NO_HIT_WITHIN_SCOPE` 不构成全局无候选证明。

## 5. reducer 保真

每次缩减检查：

1. calculus/axioms；
2. direction 与 construct；
3. input/consumer/observation/completion；
4. witness/oracle verdict；
5. reality map preserved/changed fields；
6. HoTT essential construct。

无法保持时保留原 witness，缩减项另立 family。不能为了最小化把任务缩没。

## 6. unknown ingress

```text
new paper/theorem/formalization
new framework version/issue/consumer
new application contract
phenomenon outside current TC/OP/oracle
cross-kernel/model difference
new counterexample/defense
new user correction
```

意外结果先保全 raw evidence，再分类、加 controls、定位旧 envelope 缺口、传播 stale、建立下一 bounded successor。

## 7. 每轮遗漏审计

记录 cells、未触达轴、generator blind spot、fairness、reducer 换题、oracle 假阳/假阴、source/consumer denominator、HoTT essentiality、现实桥梁、holdout、taxonomy 修订和下一 successor。

这些进入现有 TaskSpec/Session/report，不新建每轮第二矩阵。

## 8. EXP-001 的用户来源

用户 core 还要求：

1. 构造一个极简、理应被基础理论覆盖的目标理论，检查严格范型是否阻止保真表达；
2. 检查 HoTT 能否表达用户的悖论研究理论，包括 abstraction、reality premise、construction、completion、ASK、存在／不存在、时间／时序。

这两项不能被 PSJ、TGSQ 或 R4 自动替代。

## 9. 最小表达保真任务

```text
source theory objects/operations
formation and construction history
observation/completion relation
abstraction map
ASK qualification relation
required preservation
```

在 R4X 选定 exact target 后构造 interpretation，并分别判断：

```text
SYNTAX_ENCODABLE
DERIVATION_PRESERVED
OBSERVATION_COMPLETION_PRESERVED
ONLY_EXTERNAL_PARAMETER_PRESERVES_TASK
NO_FAITHFUL_INTERPRETATION_CANDIDATE_WITH_SCOPE
INCONCLUSIVE
```

单个编码失败不证明无法表达；能写一个类型也不证明保留任务。

## 10. COV/EXP 停止条件

COV 每个 declared pass 在分母、coverage/fairness、controls、omission audit 和 receipt 闭合后停止。开放 ingress 留给后继，不让当前 pass 永远运行。

EXP 首轮在一个最小 source theory 的 interpretation 与 preservation 判词完成后停止，再决定是否扩到完整用户悖论理论。
