# 共同任务、术语与优先级原则

## 共同目标

第二阶段要寻找的不是任意奇异证明、一次 proof assistant 拒绝或单独更丰富的表示。合格的结果必须能明确说明：一个指定 HoTT 构造、规则、定理或实际使用，怎样改变了同一任务的输入、允许操作、观察或完成条件，并在相称范围内给出正控制、反控制和机器证据。

共同的最小对象语言是：

```text
X       = 被研究的对象或过程
R_min   = 对 X 的最小来源—操作—复原敏感规格
U       = 从 R_min 忘却到较弱表示的显式映射
H       = 弱表示之间实际允许的关系，例如同胚、等价、Path 或 transport
Done_w  = 弱表示可交付的完成
Done_s  = R_min 所要求的强完成
```

`R_min` 不是现实的全部历史。它只允许纳入有独立任务理由、能够指定观察、且会影响 Done 的字段。现有 `RichCurve`、`Denotes`、闭图和 `CurveRun/Success` 是起点；新规格不得为了制造否定结论临时加入字段。

## 四个分支

| 分支 | 问题 | 合格命中 | 当前角色 |
|---|---|---|---|
| P1：结构规格 | 能否得到独立、最小、可形式化的 `R_min`，并精确说明 H/U 不保留何物 | 一个受控的 `H` 成立而 `R_min` 不自动成立的命题，连同最强正恢复 | 所有后续比较的共同规格；先做 |
| P2：规则级桥 | HoTT 的核心规则、必要扩张或某个明确理论定理是否真的把 H/U 提升为 `Done_s` | 可定位的 `K_theory`，即理论规则或定理本身的强任务桥 | 最直接检验理论自身；P1 后做 |
| P3：实际消费者 | 某个版本固定的库、论文实现或应用是否把 H/U 当作同一现实任务的 `Done_s` | 可定位调用链 `K_app`，连同同一 Input/Operation/Observation/Done 的失配或防线 | ABX 所在分支；P2 后做 |
| P4：实现忠实性 | 证明助手实现是否与声明的演算或规则不一致 | 可复现接受错误项、拒绝正确项或语义差异 | 独立软件正确性支；只由触发证据启动 |

`K` 是总称。P2 的 `K_theory` 是规则或定理，P3 的 `K_app` 是实际消费者，P4 的 `K_engine` 是实现层现象。三者不能互相替代。

## 排序原则

优先级不由视觉冲击、旧投入、文件数量或某支已有大量代码决定，而由以下顺序决定：

1. **共同依赖优先**：P1 固定 P2/P3 的任务，不先固定 `R_min` 就搜索桥会让目标任意化。
2. **理论直接性优先**：P2 直接检验 HoTT 规则级承诺；若命中，它比应用层扫描更能回答理论自身的问题。
3. **消费者成本后置**：P3 的外部版本、接口和调用链审计昂贵，只有在强 Done 已固定后才有清晰 oracle。
4. **实现审计按触发进行**：P4 只有在规则语义与特定实现结果发生实质差异时才有判别力；不能把一般类型拒绝重名为引擎问题。

历史机器统观、Gödel、Markov、B1a、GOLD、Flash 和已完成 C-250–C-324 控制只在它们改变一个分支的精确命题时进入；它们不是第五条自动执行线。
