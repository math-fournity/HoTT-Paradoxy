# 已知陷阱与速查

## 1. 已知陷阱

每条写：发生过什么，下次怎么做，出处。

1. **开工前没看默认分支**：README 重写推送之后才发现，PR #2 早已合并，main 上还有研究发起人一侧 09-27 至 09-29 的存档，只好普通合并补救。
   - 做法：开工前和推送前各 `git fetch origin main` 一次，确认 main 是否前进。
   - 出处：`.claude/explore/20260930-README重写-工作台.md` 第 6 节第 8 条。
2. **按字数估体量**：README 设计时估约 42 KB，重写后实际约 79 KB（2026-09-30 再次更新后约 84 KB），因为 UTF-8 的中文一字 3 字节。
   - 做法：按字节估。
   - 出处：`.claude/总索引/005 - 工作日志.md` 的 README 重写条。
3. **核心认知校验的默认参数**：`verify_core_cognition.py` 不带参数时指向旧的一代，会报错。
   - 做法：带第 9 代的 curation 与 transition 参数（005 第 4 节）。
   - 出处：同上。
4. **Lean 的 `simp` 会引入公理**：用 `simp only` 证燃料方程，`#print axioms` 显示依赖 `propext`。
   - 做法：改用 `rw`、`cases` 或项证明，就可以零公理。
   - 出处：`.claude/explore/20260930-追问Delay程序-工作台.md` 第 4 节第 4 条。
5. **`postulate` 子串命中注释**：目标内校验器按子串查 `postulate`，连注释也算，运行 `20260924-CG001-MEASUREMENT-LOG-01` 因此作废。
   - 做法：注释里不写这个词。
   - 出处：CG-001 证据索引 §4；relay R3 第 3 条。
6. **负控制“死在对的文件里”不等于“因对的理由被拒”**：Opus 的一个 Lean 负控制注释说由内核拒绝，实际是细化器拒绝。
   - 做法：核对报错的原文与阶段，Lean 另记 `rejection_stage`。
   - 出处：CN-040、CN-043。
7. **`CLAIM.md` 在收据哈希里**：捕获之后再改，校验会报 `SOURCE_HASH_OR_SIZE_MISMATCH`。
   - 做法：定稿之后再捕获；之后的修订写 `REVISIONS.md`。
   - 出处：`HoTT/formal/claude-cg001/universe-questioning/REVISIONS.md` 文首。
8. **Agda 热身**：新环境第一次运行，stdout 会多出一批 `Agda.Builtin.*` 的检查行，与收据不一致。
   - 做法：先热身一次。
   - 出处：`Cloud-Opus审计并补完GLM/01-工具链与复现.md` 4.2 节。
9. **云端推标签与强推**：推标签被 HTTP 403 拒绝，改基所需的强推也被拒绝。
   - 做法：标签用本机脚本；分支不改基，直接合并。
   - 出处：`Cloud-Opus审计并补完GLM/15-入核与登记记录.md` §5、§8.2。
10. **浅克隆**：第 8 代核心认知的校验在云端跑不了。
    - 做法：在本机跑。
    - 出处：同上 §5。
11. **写入授权**：共享 owner、共享矩阵、README、社区稿都要授权，而且授权不外推。
    - 做法：先写 relay 草稿，列出要改的句子，请研究发起人决定。
    - 出处：005 第 2 节；`rulings.md` 第 33 条。
12. **解释加码**：两次被两项自检抓到。
    - 把 Lean 那一级写成“去掉单价性”（实为同时压平所有高阶结构的粗粒度对照）；
    - 把宇宙写成一族目录的“极限”（没有任何形式极限被证明）。
    - 做法：每次交付前按《最高指示-Claude版》§7 做两项自检：精化有没有冒充原问，解释有没有加码。
    - 出处：CN-046 第 2、3 节；`HoTT/formal/claude-cg001/questioning-delay/REVISIONS.md`。
13. **先写后证**：登记里写“七个运行都已精确重放”，必须等七个校验都跑完再提交。
    - 做法：提交前逐个看校验输出。
    - 出处：本会话 2026-09-30 的做法，记在 `.claude/总索引/005 - 工作日志.md`。
14. **Claude Code 云端的宿主规则**：
    - 前台不能 `sleep`：长任务放后台，等完成通知，或等待进程结束；
    - 结束一轮之前，停机钩子要求改动已提交并推送；
    - 文件与提交正文里不写模型标识（宿主要求的提交尾注除外）；
    - 删除命令的目标不要用 shell 变量，安全检查会拦下。
15. **总索引的维护规则**：002 原位更新；003、004 只追加行，状态变化改“状态”列；005 只追加（`.claude/总索引/001 - 使用与维护规则.md` 第 3 节）。
