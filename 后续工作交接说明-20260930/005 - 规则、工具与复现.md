## 1. 开工闭包与角色

- **先定目标与角色**：研究生成、独立审计、来源解释、治理对齐、机械维护。文件存在或旧 goal 存在，都不自动启动研究。
- **档位**：T0 只读，T1 写代码或文档，T2 数学研究，T3 checkpoint、数学结论、core 更新、投影写回。会话首条声明档位；任务中途越档，要先升档再过门（根 `AGENTS.md`“任务路由（v5 分档）”）。
- **四件套**：`核心认知.md` → `方向追踪.md` → `全景视野.md` → `扩展认知.md`，按固定顺序全文读，后三件都是索引加全部分片。T2 及以上必读。
- **《最高指示》**：Codex 会话读单体 `最高指示.md`；Claude 会话读 `最高指示-Claude版.md`，经 `.claude/rules/` 常驻上下文，在新理论单元、压缩恢复之后等时刻重读。
- **逐轮再对齐**：要解释、评价或据以选择研究发起人的悖论观、原意、研究方向时，先回读相关 KC 原文与扩展认知分片，再下判断；把忠实复述与评价分开写（根 `AGENTS.md` 的 `CORE_SEMANTIC_REALIGNMENT_V1`）。

## 3. 证据门禁（F-011）

一个数学命题要作为结论交付，须依次做到（根 `AGENTS.md` 的 `MATH_PROOF_BEFORE_DELIVERY_V1`）：

1. 固定 claim、proof ID、命题全文、量词、假设与禁止外推；
2. 源码进 `HoTT/formal/`；
3. 在语义匹配的内核上实际运行：HoTT 的结论用 Cubical Agda，Lean 的相等满足 UIP，不能冒充 HoTT；
4. 运行进 `HoTT/verification/runs/<run-id>/`，必需文件是 `RUN.json`、`stdout.txt`、`stderr.txt`、`environment.txt`、`source-manifest.json`；
5. 在 `HoTT/CLAIM_EVIDENCE_MATRIX.md` 建唯一索引行。Claude 线在获授权之前，先登记目标本地索引，并把给共享矩阵的行写成 relay 草稿。

不能冒充证明的：Python 枚举、有限测试、超时、文件存在、Git 提交、另一个 AI 的赞同。完整规范在 `docs/quality/数学结论机器证明与证据留存规范.md`。

## 6. 新建一个证明包（以 CG001 线为例）

- **命名**：
  - 包目录 `HoTT/formal/claude-cg001/<包名>/`；
  - proof id `MP-CG001-<名称>-001`，负控制 `MP-CG001-<名称>-NEG-001`；
  - 运行 `<YYYYMMDD>-CG001-<名称>-01`，负控制 `…-NEG-01`；
  - 下一个命题编号 `CG001-C-81`（006 第 2 节）。
- **源码**：Agda 首行 `{-# OPTIONS --safe --cubical --guardedness #-}`，不用公设。注释里也不要写 `postulate` 这个词：目标内校验器按子串查找，会命中注释（006 第 1 节第 5 条）。依赖用导入，不要复制别的包的源码。
- **`CLAIM.md`**：命题全文、名字到命题的对照、负控制、解释（带身份标注）、禁止外推。它的哈希会进入运行收据，**捕获之后不再改**；范围与措辞的修订写同包的 `REVISIONS.md`。
- **捕获**（Linux 云端；工具在 `.claude/goals/CG-001-targeted-overview/tools/`）：

```sh
python3 -B .claude/goals/CG-001-targeted-overview/tools/capture_cg001_agda_linux_run.py \
  --run-id 20260930-CG001-<名称>-01 --proof-id MP-CG001-<名称>-001 --claim-id CG001-C-NN \
  --source HoTT/formal/claude-cg001/<包>/<文件>.agda --include HoTT/formal/claude-cg001/<依赖包> \
  --manifest-file HoTT/formal/claude-cg001/<包>/CLAIM.md --expect ACCEPT --scope "..." --non-goal "..."
python3 -B .claude/goals/CG-001-targeted-overview/tools/capture_cg001_lean_linux_run.py \
  --run-id … --proof-id … --claim-id … --source <A.lean> [--source <B.lean>] [--leanchecker] --expect ACCEPT|REJECT --scope "..."
```

- **核对**：先在 CG-001 证据索引加一节，给每个 proof id、run id、claim id 各写一行，行首是这个编号；然后对每个运行执行：

```sh
python3 -B .claude/goals/CG-001-targeted-overview/tools/verify_cg001_run.py --run-dir HoTT/verification/runs/<run-id> --rerun [--expect-rejected]
```

  输出存 `.claude/goals/CG-001-targeted-overview/verification/<run-id>.json`。
- **登记**：
  - 总索引 003 追加证明包行与命题行，更新下一个编号；
  - 004 登记 CN；
  - 005 记工作日志；
  - 002 原位更新；
  - relay R1 追加给共享矩阵的行草稿。
