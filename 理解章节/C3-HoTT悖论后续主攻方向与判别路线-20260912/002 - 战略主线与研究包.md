# 战略主线与研究包

## 4. 战略主线与战术先手

### 4.1 战略主线：数学分类—有效交付—有效自反的三级断裂

战略主线选择 `DIR-W-RP-B01 × DIR-L-SELF-REFLECTION`，原因是：

1. 它直接回应 KC-000025—KC-000027：HoTT 对齐程序后不会神奇地越过程序的自反和计算界限。
2. 它把用户的“逻辑 + 几何 + 程序”认识转化为可检验命题，而不是继续把 HoTT 当成纯静态空间语言。
3. RP-B01 已经给出一个清楚骨架：命题 LEM 可给数学停机分类 `χ`，但没有同规格的无神谕统一有效总实现。
4. 现有材料最关键的开放项 `B01-TARGET` 恰好不是再证明经典对角论证，而是找到“自然 Think in HoTT 使用方式究竟在哪里把数学函数资格提升成有效交付资格”。
5. 自指线可以把一般停机分离推进到理论自身的 syntax、substitution、evaluation、provability 和 reflection，而不是停留在外部程序例子。

但它现在还不能直接称为 HoTT 特定悖论，因为 RP-B01 的对角核心使用的是命题 LEM 和通用有效程序模型，尚未用到单价性、HIT 或 HoTT 特有的 identity 结构。下一步必须补的是 HoTT 特定的自然接口，不是更多有限样本。

### 4.2 战术先手：部分计算抽象对后续操作是否封闭

第一个实际研究包选择 `DIR-W-RACE-TIMEOUT`，原因是：

1. R041 已经提供最小反例：`p0 ≈ p2`，但与 `q1` 竞争后返回不同值。
2. 它同时提供正向控制：顺序 `bind` 尊重结果等价。这能排除“所有组合都失败”的粗糙叙述。
3. 它提供整项完成性差异：相同 continuation 下，`C(p0)` 返回 7，而 `C(p2)` 发散。
4. 它提供不依赖“必须选择最快者”的黑箱不可能三角：值可靠性、只要一方返回就响应、独立结果外延性不能同时满足。
5. 它天然连接 HoTT 的商／HIT/QIIT 消去与同余责任，也天然连接现实中的 race、timeout、调度和在线可用性。
6. 它有明确停止条件：若真实 HoTT 接口从未承诺 race，或准确要求携带时钟／trace，那么结论就是边界或防御，不继续换延迟数字制造“新例子”。

所以，A 线是我们建立完整研究方法的最佳试验场；B 线是最终要攻克的更深理论主线。

## 5. 第一研究包：`Partiality–Contextual Adequacy`

建议给第一个实际研究包使用工作名：

> **部分性抽象的上下文充分性：结果等价何时足以支持组合，何时必须保留完成时序？**

### 5.1 必须固定的理论对象

至少同时固定三层，不能只在纸上使用同一个 `Q` 字母：

1. 具体对象 `Delay(A)`：包含 `now(a)`、`later(p)` 和明确的无限等待对象／余递归语义；
2. 结果等价 `≈result`：只保留“是否有限返回、返回什么”，忽略有限停顿次数；
3. 一个真实 HoTT 部分性对象 `P(A)`：从下列候选中只选一个并固定版本、构造子、等式和消去原则：
   - 集合商 `Delay(A)/≈result`；
   - 文献中的 partiality QIIT；
   - 明确的 guarded/clocked partiality 后再取某种商。

在没有核对真实签名以前，不得把 setoid 层 `bind` 自动升级成

```text
P(A) × (A → P(B)) → P(B)
```

因为 continuation 只给商上的值时，可能没有统一代表提升；选择原则、setoid 构造和 QIIT 构造必须分开。

### 5.2 固定操作语言和观察协议

操作集至少分为两组：

- 正向控制：`return`、顺序 `bind`；
- 时序探针：公平 `race`、有限 `timeout`。

观察协议也必须显式分层：

| 观察 | 问题 |
|---|---|
| 返回值 | 最终返回什么？ |
| may-complete | 是否存在有限返回证据？ |
| must/respond | 在声明的调度下，只要条件满足是否保证响应？ |
| completion round | 第几个逻辑回合可用？ |
| contextual termination | 放入允许的程序上下文后，整项是否完成？ |

不能把物理秒偷偷代入逻辑回合，也不能把 timeout 的替代值写成“证明原过程发散”。

### 5.3 要形成的定理阶梯

本研究包不是再跑一组示例，而应按下列阶梯逐级闭合：

1. **关系层**：证明 `≈result` 的精确定义和等价关系性质。
2. **顺序正例**：证明 `bind` 对输入和 continuation 的点态 `≈result` 相容。
3. **竞争反例**：用 `p0=now(0)`、`p2=later²(now(0))`、`q1=later(now(1))` 证明 `race` 不相容。
4. **商下降不可能**：若 `race_P` 对所有代表忠实，则由 `[p0]=[p2]` 推出不同返回值商类相等，形成指定模型中的矛盾。
5. **整项完成性反差**：固定 `k(0)=now(7)`、`k(1)=ω`，证明替换单个“结果等价”组件可令整个组合从完成变为不完成。
6. **黑箱不可能三角**：在明示查询接口下，证明值可靠性、响应性和独立结果外延性不可兼得。
7. **最小富化**：分别检验保留完整 Delay、完成轮数、因果 trace、clock/grade 或改成集合值非确定结果，哪一种最小改变能恢复目标操作。
8. **上下文等价**：对包含 `bind + race/timeout` 的小语言定义观察上下文，证明结果等价严格粗于该语言的上下文等价；再问商掉哪一种关系才真正对全部操作封闭。

前五项已有 R041 纸笔骨架；第六项已有条件论证；真正的新工作集中在第七、八项和真实 HoTT 构造。

### 5.4 这条线怎样从“边界”升级为“现实相对悖论”

仅证明 `race` 不下降还不够。必须补一条自然使用桥梁：

```text
现实任务：运行两个实际部分程序并在一个可用结果出现时继续
        ↓
HoTT 表示：把部分程序只按最终结果取商／同一化
        ↓
自然承诺：商类是“该部分计算”的完整身份，因此可在程序语言中替换
        ↓
后续上下文：race 或 timeout 需要被删掉的完成先后
        ↓
反差：两个被称为相同的组件使整项分别完成和不完成
```

要核查的关键不是“HoTT 能否写 race”，而是：

- 该 partiality 构造的论文、库或语义实际承诺哪些操作？
- “部分计算的自由 ω-cpo／monad”之类身份是否只服务顺序组合？
- 并发或 timeout 的 consumer 是否另行要求更强等价？
- 使用者是否在没有证明同余时，把 quotient path 当作全语言 substitutivity？

若真实接口明确不承诺竞争操作，结论是 `DEFENSE_WORKS` 或 `REPRESENTATION_BOUNDARY`。若一个自然的 HoTT 程序语义把该 quotient 当成含竞争语言的完整程序身份，才可能达到 `NATURAL_USAGE_MISMATCH`。

### 5.5 这一研究包的正反分支

| 结果 | 应如何解释 | 下一步 |
|---|---|---|
| `bind` 和真实 QIIT monad 都成立，race 被形成规则拒绝 | HoTT 正确区分了顺序计算与竞争上下文 | 保存防御；转向最小富化或 B 线 |
| race 只能在保留 clock/trace 后定义 | 证明时序是该操作的必要结构，不是从结果身份免费恢复的数据 | 比较富化前后是否仍是同一现实任务 |
| 某自然 consumer 无证明地把商路径用于 race | 找到现实相对使用失配的候选 | 固定版本、接口、调用链和整项反差，进入形式化 |
| 所有自然接口都明确区分两种等价 | 没有悖论，只有已被理论正确治理的边界 | 停止该族，不再增加 delay 枚举 |
| 反例依赖人为平局政策或人为预知未来 | 候选不自然 | 修正合同；仍不自然则淘汰 |

## 6. 战略研究包：`Classification–Delivery–Reflection`

建议把战略包命名为：

> **从数学分类到有效交付，再到有效自我 ASK：HoTT 的程序性资格边界**

### 6.1 RP-B01 已经真正得到什么

在固定通用有效程序模型并加入命题 LEM 后，可定义：

```text
Halt(p,x) := ‖Σ n v. T(p,x,n,v)‖
χ(p,x) : Bool
```

其中 `χ=1 ↔ Halt`、`χ=0 ↔ ¬Halt`。这给出一个合法的数学分类函数资格 `Q3`。

RP-B01 的对角论证说明：不存在一个同输入、同输出、无神谕、对所有输入有限完成的统一程序 `h` 来实现 `χ`。也就是 `Q3` 不自动给出 `Q4`。

必须保留三层区分：

1. 每个固定 `(p,x)` 有一个正确常量程序；
2. 数学上有统一分配函数 `χ`；
3. 有一个从任意 `(p,x)` 有效取得正确结果的统一程序。

前两项都不能冒充第三项。`noncomputable` 标记也不能代替对角证明。

### 6.2 下一步不是重证停机定理，而是寻找自然升级点

真正未完成的是 `B01-TARGET`。需要固定一个可回查的 HoTT 使用接口，逐项问：

- 它是否声称每个 `ℕ→Bool` 的内部数学函数都能提取为同规格程序？
- 它怎样处理命题 LEM、选择、公理化 univalence 或 opaque constant？
- 它区分证明层命题、数据层和运行层吗？
- 用户提供实现、外部 oracle、unsafe 映射或 `implemented_by` 一类机制是否改变了原合同？
- 它是否把“理论中可定义”叙述成“现实中可求值”，还是明确拒绝？

这里可以得到两种同样有价值的结果：

- 接口明确拒绝或要求额外实现：`DEFENSE_WORKS`；
- 接口或其自然哲学解释确实作出统一有效交付承诺：用 `χ` 给出反例，形成 `NATURAL_USAGE_MISMATCH`。

不得因为普通 Lean/Rocq 中存在类似机制，就直接称为 HoTT 结果。要固定 exact theory、library、axioms、extraction/backend 和输出规格。

### 6.3 与自指／反射线合流

当普通分类—交付断层固定后，再进入“有效自我 ASK”：

1. 固定一个 HoTT 对象演算 `T` 的有限语法编码 `Code_T`；
2. 固定 substitution、有限步 evaluation、typing/provability judgment；
3. 区分外部元理论定义的 checker 与 `T` 内部可调用的 checker；
4. 明确 checker 是证明产生器、Bool 分类器、部分求值器，还是 soundness/consistency 断言；
5. 只有具备 quote／self-application／evaluation 的真实闭合接口后，才应用 Gödel、Tarski、Lawvere 或停机式对角方法；
6. 检验 universe hierarchy、strict outer layer 或 two-level type theory 是防御、富化还是任务改变。

这条线最有希望把“HoTT 继承程序的界限”变成 HoTT 特定研究，因为困难不再只是外部机器停机，而是：

> 单层 univalent/homotopical equality、对象内语法商、严格 substitution/evaluation、可判定 type checking、总反射和自包含 universe 能否同时承担所需资格？

但在 exact calculus 和接口固定以前，这仍是研究问题，不是已证不可能定理。

### 6.4 战略线的 HoTT 特异性 Gate

每个结论必须回答：

| 检查 | 若答案为否 |
|---|---|
| 单价性、identity/path、HIT/QIIT、universe 或 HoTT 元理论结构是否进入关键推导？ | 只能称一般计算／逻辑界限的 HoTT 实例 |
| 是否固定了 HoTT 变体和额外公理？ | 不能泛称 HoTT |
| 是否有自然的对象层→执行层或对象层→元层接口？ | 只能称条件模型 |
| HoTT 自己是否承诺了被反驳的强资格？ | 若没有，只能称外部误读或防御成功 |
| 同一现实任务是否保持，而不是中途加入 oracle、deadline 或全域 checker？ | 若改变任务，不构成用户要求的反差 |
