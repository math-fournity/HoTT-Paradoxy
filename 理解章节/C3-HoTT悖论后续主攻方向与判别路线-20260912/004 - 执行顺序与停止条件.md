# 执行顺序与停止条件

## 10. 推荐的实际执行顺序

### Gate 0：证据身份

1. 尝试取得数学 R041 所称源码、25 项测试原始输出、`cf58f27` 和增量容器 manifest。
2. 若仍不可得，允许根据已固定 SHA 的正文重新实现一个**新 provenance** 的最小模型；必须写明“按正文重建”，不得冒充原源码。
3. 证据恢复不能无限阻塞数学研究，因为纸笔定义和反例已经足够固定下一理论问题。

### Work Unit 1：真实 partiality 构造

1. 只选一个 quotient/QIIT/guarded partiality 定义；
2. 固定 Theory Schema、等价、消去原则和现有 operation contract；
3. 重建 `bind` 正例与 `race` 反例；
4. 判定 `race` 是非法形成、不可下降，还是需要富化。

完成判据：得到一个 exact theorem statement、一个正向控制、一个负向结果和一个 HoTT 规则级解释。

### Work Unit 2：上下文充分性与最小富化

1. 定义含 `bind + race/timeout` 的小语言；
2. 定义观察与 contextual equivalence；
3. 证明 `≈result` 是否严格过粗；
4. 给出最小富化候选并验证恢复了哪些操作、牺牲了哪些等式。

完成判据：明确“应该用哪一种 identity 才能支撑哪一种程序语言”。

### Work Unit 3：自然现实桥梁

1. 选择一个真实论文／库／语义 consumer；
2. 固定其实际承诺和非承诺；
3. 将现实 race/timeout 任务与抽象操作逐项对齐；
4. 只在自然 consumer 真正越级时提出现实相对悖论。

完成判据：进入 `DEFENSE_WORKS`、`REPRESENTATION_BOUNDARY` 或 `NATURAL_USAGE_MISMATCH` 之一；不能停在“看起来可疑”。

### Work Unit 4：RP-B01 自然接口

1. 完成通用 Code 模型和 `Rep(χ)` 的 exact 形式规格；
2. 选择一个真实 HoTT 计算／提取接口；
3. 用四组控制：有限步停机、同常量经典分支、真正停机分类、显式 oracle／替代实现；
4. 判断接口是防御还是越级。

### Work Unit 5：有效自我 ASK

只在 Work Unit 4 已固定对象层—执行层责任后，加入 quote/eval/provability 和 self-application，研究单层 HoTT 自我建模与反射的资格边界。

## 11. 决策树与停止条件

```text
候选是否固定了现实任务、HoTT 配置、抽象和后续操作？
├─ 否：不进入研究；先补合同
└─ 是
   ├─ 操作尊重抽象等价吗？
   │  ├─ 是：保留为正向控制，寻找真正丢失的资格
   │  └─ 否
   │     ├─ HoTT 规则拒绝形成/下降吗？
   │     │  ├─ 是：DEFENSE_WORKS
   │     │  └─ 否：检查是否有真实不健全性
   │     └─ 富化表示能恢复吗？
   │        ├─ 是：REPRESENTATION_BOUNDARY
   │        └─ 否：形成更强 no-go 候选
   └─ 是否存在自然 consumer 把较弱资格当成较强资格？
      ├─ 否：停止，不靠换例子维持活跃
      └─ 是：构造同任务现实/理论成对证据
         ├─ 反差只来自任务被改写：淘汰
         └─ 反差来自自然资格越级：NATURAL_USAGE_MISMATCH
```

全局停止条件：

- 三个连续变体只改变数字、命名或调度细节而没有新操作／新接口；
- HoTT 形成或消去规则已经清楚拒绝可疑步骤；
- 找不到自然 consumer，只有研究者人为强加的错误承诺；
- 结论完全由一般停机、一般商或一般复杂度事实给出，且 HoTT 没有进入桥梁；
- 无法保持“同一现实任务”，必须靠增加 oracle、全知未来、全域 checker 或额外输出才制造冲突。
