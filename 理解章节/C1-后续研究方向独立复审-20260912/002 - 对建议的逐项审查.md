# 对建议的逐项审查

## 2. 对建议总方向的审查

### 2.1 从“抽象丢了什么”推进到“哪些后续操作还能做”——正确

这一转向同时符合：

- KC-000010：目标是 Think in HoTT 后出现现实中本无的完成困难；
- KC-000012/KC-000013：ASK 不只是入口检查，还要追踪资格在转换和使用中是否被略过；
- KC-000014/KC-000022/KC-000024：A/B 两类现实相对目标；
- `HoTT研究三问`：必须定位“理论结果→现实承诺”的提升步骤；
- `hott-paradox-research` 的 OP03/OP06/OP07：组合合法操作、忘去后恢复、改变观察尺度。

过去的许多工作只证明：

~~~
抽象把两个具体过程认成同一个对象
~~~

但用户要的具体悖论还需要：

~~~
有人随后用这个对象承担了一个确实需要被删信息的任务
~~~

附件把注意力放到“后续操作”上，正是在补这座桥。

### 2.2 “不应继续堆同类反例”——基本正确

R039 已经明确给出停止条件：不再更换自环名称、不再放大有限图数量。`全景视野.md` 也把 R036/R038/R039 定位为有限模型与条件边界，而不是 HoTT 特定悖论。

因此，继续增加：

- 更多有限等待长度；
- 更多全零流或自环；
- 更多同类不透明运输；
- 更多只改变故事、不改变机制的例子；

不会自动提升证据强度。

但“停止同类枚举”不等于“冻结整个 RP-B01 或自指方向”。附件在这里收束得过头：它正确冻结了重复模型，却没有保留用户最新认知前沿要求推进的 B 方向。

## 3. 对四条具体建议逐项审查

## 3.1 第一主线：部分计算的商与 `bind`

### 已被新 R041 支持的部分

R041 给出明确 Delay 配置和结果等价：

~~~
p ≈ q  :=  Πa. (Conv(p,a) ↔ Conv(q,a))
~~~

并分别得到：

1. 对实际给出的 `f,g : A→Delay(B)`，若 `p≈p'` 且逐点 `f(a)≈g(a)`，则 `bind(p,f)≈bind(p',g)`；
2. `p0=now(0)`、`p2=δδ now(0)` 虽然 `p0≈p2`，但与 `q1=δ now(1)` 竞争时返回不同值；
3. 取 `k(0)=now(7)`、`k(1)=ω` 后，`C(p0)` 返回而 `C(p2)` 不返回；
4. 黑箱选择器不能同时满足值可靠、至少一方返回时响应、以及对每个输入独立结果外延；
5. 标准商递归正确拒绝一个不尊重等价的 `race`，没有产生 HoTT 内部矛盾。

这使附件的中心经验——“单独结果等价不能自动成为扩展了 race 的语言中的上下文等价”——有了直接正文依据。

### `D` 层 `bind` 与 `Q` 层 `bind` 的差别

附件区分：

~~~
D(A) × (A → D(B)) → D(B)
Q(A) × (A → Q(B)) → Q(B)
~~~

这一区分是实质性的。R041 自己也在 `2.1` 明确承认：代表层相容只支持 setoid 级组合与固定代表 continuation，不能自动构造只在商上取值的 continuation。后者可能需要相容代表族、商消去、选择或另一种递归原理。

一手资料支持这一历史分歧：

- Chapman、Uustalu、Veltri 对 quotient-type 路线指出 monad multiplication 的构造困难，并在其方案中使用命题外延性和可数选择；setoid 路线则能保留 monad。见 [论文页面](https://www.cambridge.org/core/journals/mathematical-structures-in-computer-science/article/quotienting-the-delay-monad-by-weak-bisimilarity/EC1E1F7E7692C991FCDE85C61673C799)。
- Altenkirch、Danielsson、Kraus 使用 HoTT 启发的 quotient inductive-inductive type 构造不依赖可数选择的 partiality monad；与 weak-bisimilarity delay quotient 的等价在可数选择下给出。见 [Partiality, Revisited](https://arxiv.org/abs/1610.09254)。
- Møgelberg、Zwart 系统研究 delay monad 与其他效应的组合，给出哪些分配律存在、哪些不存在，以及弱互模拟下可挽救的范围。见 [What Monads Can and Cannot Do with a Few Extra Pages](https://arxiv.org/abs/2311.15919)。

所以，“不要从某一种商表示的构造困难外推为部分计算根本不能组合”是正确的反向校准。

### 排序上的问题

R041 已经把真正有判别力的一对操作做出来：

~~~
bind          = 尊重结果等价的正向控制
race/timeout  = 依赖相对完成回合的负向探针
~~~

继续研究一般 `bind_Q` 可以回答“某个商/生成式 partiality 构造是否形成 monad”，但它很可能首先得到一个已知构造边界，而不是用户要的第三层自然使用实例。若把它列第一主线，必须明确它服务的是：

1. 查明表示选择如何改变组合能力；
2. 为后续真实操作建立精确接口；
3. 不是把“选择困难”直接包装成现实悖论。

### 裁决

`RETAIN_WITH_REFRAMING`：

把“部分计算商上的 `bind`”纳入“**部分计算抽象的操作闭包边界**”。R041 已完成一个代表层 `bind/race` 分离；下一步若继续，应核一个真实 quotient/QIIT 接口及其承诺，而不是再做同类延迟枚举。

## 3.2 第二主线：完整输入函数与在线因果策略

### 正确的部分

附件的三层区分是清楚而重要的：

~~~
逐输入存在输出
  → 有一个统一数学函数
  → 有一个遵守信息到达顺序的在线策略
~~~

即使有 `F : Stream → Stream`，也不自动有：

~~~
输入前缀相同
  ⇒ 当前必须交付的输出前缀相同
~~~

这比“存在不等于选择”多出一个因果/前缀条件，直接命中：

- KC-000011：程序的顺序、分支、循环让时序参与工作；
- KC-000012/KC-000013：问题的合法性包括输入是否已经可用；
- KC-000014/KC-000022：现实交付与数学完成的双向差异；
- `hott-paradox-research` 的 OP02：移动信息可用时刻。

Guarded 研究也支持“有时间结构”仍需区分具体能力：

- gDTT 以 `later`、clock quantification 和 delayed substitutions 管理 guarded recursion 与 coinduction，见 [Guarded Dependent Type Theory](https://arxiv.org/abs/1601.01586)；
- guarded lambda-calculus 的 clock-quantifier-inspired 构造可以允许 acausal functions，说明“可定义完整流函数”与“满足在线因果协议”确实不是同一件事，见 [The Guarded Lambda-Calculus](https://arxiv.org/abs/1606.09455)。

### 风险

`F(α)(n)=α(n+1)` 在“时刻 n 只能看见到 n、却必须输出 n+1”合同下显然不可实现。这个例子只校准因果定义；它本身不是 HoTT 悖论，因为协议已经明说不允许读取未来。

要升级为项目候选，必须找到真实接口：

1. 哪个 HoTT/guarded/clocked 构造产生普通完整流函数；
2. 哪个实际使用步骤把它解释成在线策略；
3. 该步骤是否保留 causality proof、clock 或 delay；
4. 若没有保留，为什么使用者仍有理论依据期待同一个交付能力；
5. 若类型规则已经拒绝这种提升，这应登记为 HoTT 的防御面。

### 裁决

`STRONG_EXPLORATION_CANDIDATE`。

它比继续做同类 silent-step 图更可能产生新机制，也更接近用户 A 方向；但在固定真实接口之前只能是探索位，不能用“猜下一位不可能”冒充发现。

## 3.3 备选：当前状态与证据适用范围

“旧证明仍在文件中”与“它仍授权当前动作”不是一回事。令：

~~~
v0 : Valid(token, s0)
~~~

状态更新到 `s1` 后，`v0` 不自动成为 `Valid(token,s1)`。这一点与 ASK 的“依据被扩大/被替换”以及路径证书迁移工作相合。

但它很容易退化为普通规格工程错误：

- 漏写 state 参数；
- 没有版本化环境；
- 把旧授权缓存当当前授权。

只有当某种自然的 HoTT 等价、transport、截断或结构同一性把状态依赖系统性地隐藏，而使用者仍被允许执行同一动作时，才有研究升级价值。

### 裁决

`PARKED_WITH_REOPEN_CONDITION`：

保留为规约/状态支线；出现真实 HoTT 转换、非平凡状态依赖或与 race/cancel 的自然组合时重开。

## 3.4 验证线：R034 原生证明

这项建议是正确而且必要的。

R034 的纸笔命题是：

~~~
¬ Π(X,Y:U). ||X=Y|| → X → Y
~~~

其关键不是一般停机，而是：

- 命题截断；
- 单价性给出的 Bool 取反宇宙回路；
- Σ 类型中的回路；
- 依赖函数的自然性/`apd`；
- Bool 没有取反固定点。

用户新提供的 R034 文件与 workspace 正文逐字相同，消除了“网页展示版和交接版是否同一正文”的疑问；它没有改变 `NATIVE_NOT_RUN`。

现有 `workspace/scripts/research/r034_formal/MereMigration.agda` 只是参数化草稿。它把 `Tr`、`flipPath` 和 `flipβ` 作为模块参数；自定义的普通 Agda identity 并没有真实构造单价路径。即使这份草稿语法通过，也只证明“这些参数推出结论”，不等于在一个实际 Cubical/HoTT 库中实例化了参数。

本轮当前环境：

~~~
agda = NOT_FOUND
Lean 4.33.1 = FOUND
~~~

普通 Lean 4 的 `Eq` 不是本项目需要的高阶单价 identity 环境，不能为了“有 Lean”而换题。真正原生验证至少要：

1. 固定 Agda 与 cubical library commit；
2. 用真实 Path/Univalence/PropositionalTruncation 改写草稿；
3. 不留 postulate、unsolved metas 或未声明不安全选项；
4. 运行并保存命令、版本、源码 hash、退出码；
5. 同时保留固定 Bool 对上恒等迁移可构造的正向控制。

Cubical Agda 官方文档确认其提供计算性单价性和 HIT；集合商库也确实以 HIT 定义 set quotient。见 [Agda Cubical 文档](https://agda.readthedocs.io/en/stable/language/cubical.html) 与 [Cubical set quotients](https://agda.github.io/cubical/Cubical.HITs.SetQuotients.Base.html)。

### 裁决

`HIGH_VALUE_VERIFICATION_LANE`。

它应与探索主线并行存在，但不应被说成“验证全部历史候选”。它只提高一个判别力很强的小命题的证据强度。
