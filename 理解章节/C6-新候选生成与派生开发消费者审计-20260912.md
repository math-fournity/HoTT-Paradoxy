## 0. 结论

1. N4 按八种构造操作（OP01–OP08）与九个方向（DIR01–DIR09）生成候选，并显式排除已关闭反例的改名（R036/R038、R034、race/timeout、truncation witness、online lookahead、cost recovery）。
2. 一个高价值候选被本轮**实测排除**：`ua` 的 definitional regularity（`transport (ua idEquiv) x` 是否定义性归约到 `x`）。探针在 Cubical Agda 2.8.0/Cubical v0.9 中显示 `refl` 可直接通过，且 `transport (ua notEquiv) true` 也定义性归约为 `false`；该工具链的 `ua` 计算规则足以消除这一候选。重开条件：book HoTT 的纯公理化 `ua`、或其它没有计算规则的模型/工具链。
3. 候选池收敛到五个短名单：type-quotient 代表选择、Cauchy/quotient 实数的 modulus 提取、SIP 在表示可观察消费者中的替换、有限/无限选择原则的静默泛化、以及“派生开发自述”审计。
4. 最关键的新认识：N1/N2/N3 已经表明**核心库接口系统性防御**；E6 若存在，更可能在**派生开发（论文/库/工具链）对自身构造的承诺**里，而不是在 Cubical 核心库里。N5 因此固定为 **派生开发消费者审计**：对固定版本的 HoTT 派生工作，逐条核对它们的“可计算/可提取/可序列化/可交付”自述是否超出了其接口实际提供的资格。
5. `核心认知.md` 不变；本轮没有新的用户原文。

## 3. 本轮探针：`ua` regularity 实测排除

探针源：`S-RES-20260912-046-NEW-CANDIDATES/evidence/agda/UAProbe.agda`（Cubical Agda 2.8.0 / Cubical v0.9，`--safe --cubical --guardedness`）。

```agda
probe-regular : transport (ua (idEquiv Bool)) true ≡ true
probe-regular = refl

probe-beta : transport (ua (idEquiv Bool)) true ≡ true
probe-beta = uaβ (idEquiv Bool) true

probe-not : transport (ua notEquiv) true ≡ false
probe-not = refl
```

结果：整个模块 type-check 通过（exit 0）。也就是说，在这个工具链里：

- `transport (ua idEquiv)` 定义性归约到恒等（regularity 在该实例成立）；
- `transport (ua notEquiv) true` 定义性归约为 `false`（`ua` 计算规则强）。

因此 `CAND-REGULARITY` 在 Cubical 2.8.0/Cubical v0.9 上被实测排除：

```text
failed_at = cubical-2.8.0/ua-regularity-probe
reopen_if = 纯公理化 ua（无计算规则的 book HoTT 呈现）、其它 cubical 模型或工具链版本
```

这不是“HoTT 解决了问题”的证明；它只说明该候选所依赖的定义性缺口在这个具体工具链不存在。

## 4. 短名单与 N5 选择

### 4.1 选定：派生开发消费者审计（`CAND-DERIVED-DEVELOPMENT`）

理由：N1（核心库截断/商/成本/传输审计）与 N2（提取接口审计）都在固定接口上得到 defense/bounded negative；N3 关闭了过渡抽象边界。若 E6 存在，最可能出现在**派生开发对自身构造的承诺**中：论文或库把“我们有 `∥Σ…∥` / 一个商类 / 一个 `ua` 路径”写成“我们可以计算/提取/序列化/交付某物”。这类承诺会比接口本身多走一步。

N5 的固定审计集合（版本/URL/hash 逐条记录）：

1. `Partiality, Revisited`（arXiv:1610.09254）与 `Quotienting the delay monad by weak bisimilarity`（MSCS 29(1)）；
2. `What Monads Can and Cannot Do with a Few Extra Pages`（arXiv:2311.15919）；
3. `Cost-Aware Type Theory`（arXiv:2011.03660）；
4. 本地/可获取的 HoTT 派生开发：Cubical v0.9 中引用 quotient/truncation/UA 的论文级模块与 `HoTT/formal/` 当前包；
5. 如可得：agda-unimath / UniMath / HoTT-book 形式化的真实入口（逐文件 hash）。

审计问题（每条必须给出原文 locator 与接口签名）：

- 它是否有“extract / compute / decide / serialize / normalize / run”一类承诺？
- 该承诺依赖的是定理级资格（path/truncation/quotient）还是执行级资格（可归约、可编译、可提取）？
- 接口是否显式携带所需假设（choice、modulus、section、coherence）？
- 有没有真实调用链在同一任务下把较弱资格当较强资格使用？

输出三值：`FOUND_CANDIDATE` / `BOUNDED_DEFENSE` / `INCONCLUSIVE_SOURCE_UNAVAILABLE`。只有 `FOUND_CANDIDATE` 才进入 F-011 机器化。
