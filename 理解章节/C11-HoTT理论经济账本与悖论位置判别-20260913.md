## 0. 结论（v2）

1. 起点保持：先列**理论经济**（收入 / 被悬置或被加入的现实因子 / **补偿操作** / 复活条件），再由账本生成任务形状。
2. 诊断精确化：不是“以前从未有过理论地图”——`HoTT/THEORY_SCHEMA.md` 已有核心规则、派生结构、语义、扩展与审查地图，C6 也已做过方向 × 操作的候选矩阵。真正的问题是**已有地图没有持续驱动选题**，而 C11 提供的新轴是“经济性与补偿操作”，必须与 Theory Schema 拼装使用，而不是另起一套总框架。
3. 总账不变量仍是**待检验猜想**，并且明确**不是准入判据**：任何候选都不得因为落在“同阶段 / 同层可用”而被拒绝进入机器化；对候选只要求说明“补偿操作保留了什么、改变了什么”。
4. “同阶段 / 同层”是**检查坐标之一**，不是悖论位置的完整分类。完整检查还需：时间与运动结构（连续/稠密/可分/完成过程）、量词与完成顺序、输入/表示/规则的改动类别，以及 B 方向（把尚未完成当作已经取得）。
5. 回溯检验目前只完成“**旧证据是否被准确归类**”的一致性检查；它**没有**验证账本的解释力与预测力。把全部旧结果找到一行，不等于方法已被验证。
6. 补偿操作必须逐例论证，不能预填“任务不变、只是表示更细”。三类动作必须分开：**从原输入恢复** / **从一开始预先保留** / **新增输入、假设或规则**。
7. 下一步不是“按两问选候选”，而是**用一个实际候选检验账本能否产生新认识**；同时保留自主构造路线：由我们提出独立、合理的任务，展示具体 HoTT 理论化怎样改变其前提。

## 2. 账本结构

### 2.1 六个字段

| 字段 | 含义 | 质量要求 |
|---|---|---|
| **行类型** | 该行属于：原始规则 / 派生定理 / 表示选择 / 可选扩展 / 实现事实 | 必须如实标注；派生结果不得写成规则 |
| 经济决策 | 这条设计让理论使用者**不再需要做的现实记账** | 锚在具体规则或具体设计选择 |
| 被悬置或被加入的因子 | 因该决策而不再起作用的现实要素，**或**被主动加入的理想结构 | 用用户词汇：时序、过程、代表元、成本、来源、观察者、准入、稠密性/连续性 |
| **补偿操作（可检查）** | 需要该因子时理论采取的**具体操作**：输入是什么、输出是什么、所需证据从哪里来 | 逐例写清；必须归类为恢复 / 预先保留 / 新增（见 §2.3） |
| 复活条件 | 哪类任务让该因子重新承重 | 必须是任务形状；v2 尚未逐行完成（见 §3.2） |
| 现有判词 | 本 repo 已证明的结论落在本行哪一类 | 给出 claim/run 索引；无证据写 `UNTESTED` |

### 2.2 四个必须分开的坐标

评审指出的层次混用（D1）必须显式拆开，禁止用一句“升层”概括：

1. **宇宙大小**（universe level）——同一理论内部的层级；
2. **对象理论 / 元理论**——是否仍在被担保的理论内部；
3. **理论扩展**（guarded/clocked/partiality/cost-aware…）——是否换了理论或加了规则；
4. **执行阶段**（何时可用、何时落定）——运行/使用侧的时间条件。

“支付装置”必须按这四个坐标分别记账：在 1 内升层 ≠ 在 2 内自我担保 ≠ 在 3 内换理论 ≠ 在 4 内等待。

### 2.3 补偿动作的三分（评审 D-3／V3）

| 动作 | 含义 | 判据 |
|---|---|---|
| **恢复** | 从**原有输入**中取出所需信息 | 必须给出恢复函数与它读取的原始数据 |
| **预先保留** | 从一开始就把该信息保留在输入/表示里 | 正例的输入类型比原任务更丰富；必须说明原任务是否允许 |
| **新增** | 增加新输入、假设、规则或外部证据 | 必须说明新任务与原任务的关系，不得默认“任务不变” |

**例（本 repo 源码级）**：`NoCanonicalPoint.agda:108-114` 的 `labeledChoice X = invEq (snd X) true` 属于**预先保留**（输入里已带 `A ≃ Bool`），不是“从无标签输入中恢复”；`QuotientMonad.agda:57-61` 的 `canon (ret n a) = ret zero a` 属于**预先保留的规范代表**，它**没有**恢复等待时间 `n`。

### 2.4 总账不变量（待检验猜想，不是判据）

> **猜想**：当理论为了经济性悬置（或加入）某个现实因子 F 时，必须在某处给出补偿操作 P；若某个任务要求 F 在“同一阶段”或“同一层”可用，而 P 只能在更晚阶段、更高层或新理论中提供 F，则该任务在该理论内不可完成，而现实侧可能仍可完成。
>
> **本文明确不把这条猜想当准入门槛**。任何候选只要能把“补偿操作保留/改变了什么”写清楚，就可以进入机器化讨论；不满足这条猜想的格子只说明该方向更难，而不是“没有资格出现”。

### 3.1 逐例要求（代替 v1 的“任务不变”预填）

v1 的 §3.1 把“换成带见证的类型 / 加成本结构 / 改用阶段表示”普遍判为“任务不变，只是表示更细”。**v2 取消这个预填**。每一行必须逐例回答三问：

1. 补偿操作读取的输入与原任务的输入**相同**吗（恢复 / 预先保留 / 新增）？
2. 补偿后的输出与完成标准是否与原任务一致？
3. 若不一致，改变的是表示、输入，还是规则？

`audit/p1-时序线候选与支付装置审计-20260913.md` 的 D1–D6 已按此要求重写过支付装置口径，可作为范例。

### 3.2 尚未完成的部分（诚实登记）

## 4. 检查坐标（不是分类，也不是 Gate）

### 4.1 两个坐标（降级使用）

| | 同一层可用 | 同一层不可用 |
|---|---|---|
| **同阶段可用** | 补偿操作存在：通常停在 `REPRESENTATION_BOUNDARY` | 需要在新层/新理论中补偿 |
| **同阶段不可用** | 需要更晚阶段才能补偿 | 两者皆不可用：构造上最困难 |

**使用规则（v2 明确）**：这四格只用于**描述**一个候选的补偿处境，不用于决定候选是否有资格被研究。落在任何一格都可以进入机器化讨论；区别只在于需要写清什么样的补偿操作。

### 4.2 三个补充坐标（v2 新增）

1. **时间与运动结构**：理论把连续/稠密/可分/运动设定成什么？（芝诺线的结构前提；不能用“同阶段”替代）
2. **量词与完成顺序**：存在 vs 指定构造、有限 vs 无限、统一 vs 逐例（C5 的 E1–E5 与 C-118–C-123 已在此轴上）。
3. **改动类别**：恢复 / 预先保留 / 新增（§2.3）；以及“理论主动加入理想结构”的方向——理论可能**不是忘记**了现实，而是**加入**了现实中不存在的统一性或相干性要求。

### 4.3 B 方向

“数学上取得分类/存在，随后被当作已经取得的有效交付”是独立方向（KC-000014/000022）。它不由“同阶段/同层”覆盖，必须单独检查：**把尚未完成当作已经取得**发生在哪一步、由哪条规则或哪个接口支持。

## 6. 执行流程（v2：不设门槛）

1. **收账**：只从规则/设计写行，标注行类型；新行必须给出“收入”对应的具体规则或设计；
2. **补偿**：每行写出补偿操作，并归类为恢复 / 预先保留 / 新增；逐例回答 §3.1 三问；
3. **坐标检查**：用 §4 的 1 + 3 个坐标描述候选（不是筛除）；
4. **构造或退化测试**：
   - 自主构造路线：由我们提出独立任务，展示“理论怎样表示它 → 哪条规则或规则组合改变了什么 → 合法推演产生什么现象 → 怎样对应回原活动”；
   - 组合候选**必过退化测试**：删去新增的时间/自证等要求后，如果候选退化成已知问题，则说明该组合没有增加新机制；
5. **只有跨过第 4 步的候选**才进入 F-011 机器化；未跨过的候选记录 `failed_at` 与 `reopen_if`。
