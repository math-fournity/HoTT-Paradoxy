# A10 怎么找：方法论综合（用户的方法指令全集）

> 本章处理轮次：W8、W17、W23、G4、G5、G10、G11、G12 §六§九。

### 【W8 / W17 / G4】先验模式匹配（用户两次明确要求 + 一次对外部 AI 要求）

**用户说**（W8）：「你应该自主运行，寻找 HoTT 的悖论……你打算如何系统化地去找？」（W17）：「凭借你内在的对 HoTT 的知识，我认为你可以首先在"先验"的情况下完成一波关于 hott-paradox-research 要找到的 HoTT 的悖论……以你的知识量和智能性，在完全理解了我们要在 HoTT 中找什么？如何找？凭什么能找到？这三问之后，你作为大语言模型，可以把这个 hott-paradox-research 要求的内容，作为一个复杂问题的求解，甚至是通过大语言模型的"模式匹配"能力，把 HoTT 中的悖论求解出来、模式匹配出来。」（G4）：「请你审视你内在的神经网络，直接找到你训练语料能够直接让你找到的，HoTT 的中存在的悖论。」

**我的理解**：用户对 LLM 的用法主张：**内在知识是一等搜索工具**——不是检索代理，是把训练语料当语料库做模式匹配的求解器。三次指令（两次内部一次外部）说明这不是随口一说而是方法论立场。配合 A7 的辩证：训练共识不能当裁判，但训练知识可以当**候选发生器**——先验生成，再用铁律/ASK/成对证据过滤。这与 G12 的"先生成，再局部反向检查"完全一致。

### 【G5 / G10 / G11】机器证明的真运行要求

**用户说**（G5）：「你是否可以使用机器证明，比如 Lean 来证明你的这两个悖论在 HoTT 中是存在的，我已经打开了你的代码运行权限。」（G10）：「你现在开始找吧，不仅仅要语言和公式论述，也要有 Lean 或者其他可能的机器证明方式的代码实际证明，**要真的在你的沙盒中运行过**。」（G11）：「这两种你都能在 HoTT 中找到，**并机器证明**吗？」

**我的理解**：证明标准的三级：语言论述不够→要有机器证明代码→代码要真运行过。"真运行"三个字防的是"提交了代码"冒充"验证了定理"——Gemini 论辩中"纸笔草图≠编译通过"的纪律即源于此。

### 【W23】行动方案的内在知识来源

**用户说**：「你根据你的内在的对 HoTT 的知识库，以及我们已经做过的那些探索，能不能对这件事该如何继续完成，提出后续的行动方案？换句话说，我希望你凭借你的智慧，**不是靠外部的搜索，而是依靠你作为 LLM 被训练的时候的内在知识和我们之前的探索**，来对我们想找的这种不可停机/计算非法的 HoTT 悖论，提出后续的探索寻找线索。」

**我的理解**：与 W17 同向但更精确：**排除外部搜索**——找线索的阶段要的是内化知识的重组，不是文献搬运。理由（我的推断）：悖论候选需要的是规则组合的直觉联想，内在知识+已析探索才是正确的搜索空间；外部搜索反而会把工作拖回"世界怎么看"（A7 之禁）。

### 【G12 §六 / §九】方向选择与交付要求

**用户说**（§六，要点）：优先方向 RP-B01（数学分类如何被解释为有效交付）；支持方向 RP-B02（存在证据从哪里来、转换后还允许什么）；开放方向 RP-OPEN（局部/统一可完成、逐步/整体、逐例见证/一致选择、理论内部表达自身、"我们一直围绕有限流、Done 和布尔运输工作，是否已经陷入了某种局部模式？"）；条件重开 RP-A01 与 RP-HIT（"不要因为这些概念听起来最像'把过程静态化'，就再次从名称直接推断它们会造成无限搜索"）。（§九，要点）：直接交付研究思路不要先问选哪个；第二部分提出 6–10 个机制不同的候选，每个说清普通人能懂的过程 Q、A/B 方向归属、对应 HoTT 规则、可疑理论化步骤、被略过/替换/扩大/加强的 ASK 责任、预计困难、与旧候选的差量、最可能失败的反向解释、下一最小判别动作；第三部分挑 2–3 个深入构造草图；第四部分**指出我们研究路线的盲点**（"我们是否过分依赖信息遗忘？是否把完成证书当成了唯一的时间问题？是否只挑容易做有限测试的例子？"）；第五部分给首选动作+两种结果下的分支。

**我的理解**：这是用户方法论的**最完整成文**。四个结构特点：(1) 候选的九字段规格（把 A0/A1/A3 全部参数化）；(2) **自我盲点审查入交付**（第四部分——研究路线本身成为研究对象，与 A7"质疑自己的研究方法"呼应）；(3) 判别性行动（每候选带"最可能使它失败的反例"——生成与证伪一体）；(4) 双分支预案（"出现什么证据应该继续；出现什么反例应该收窄转向或放弃"）。

## 本章整合：找悖论的标准作业流（SOP）

综合所有方法指令，用户方法的完整流程：**步骤 0**（前置加载）：全文加载闭包/三问/动态状态（A9.4）。**步骤 1**（先验生成）：内在知识模式匹配，产 6–10 个机制不同的候选（W17/G4/G12§九）。**步骤 2**（九字段规格化）：普通人能懂的过程 Q、方向归属、规则组合、可疑步骤、ASK 变体、预计困难、差量、反例、最小判别动作（G12§九）。**步骤 3**（反向检查）：对每候选找最强反模型/正向构造——"反模型不是不配合"（G12§八）。**步骤 4**（对证）：成对证据 α(w₀)=α(w₁)∧J(w₀)≠J(w₁)、承诺归属审问、恢复条件对照（三问固化；源头 A1.3）。**步骤 5**（机器验证）：Lean/Agda 真运行（G5/G10）。**步骤 6**（自我盲点审查）：是否陷入局部模式、是否只挑好测的（G12§九第四部分）。**步骤 7**（诚实交付）：允许无突破但要有真实尝试与失败位置；"诚实暴露一个关键缺口，比用含有结论的公理把它填平更有价值"。
