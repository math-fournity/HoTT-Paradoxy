> 文档身份：`CURRENT DOMAIN SYNTHESIS WITH DUAL PERSPECTIVE`  
> 日期：2026-09-12  
> 回答的问题：我们研究过哪些悖论；用户如何理解它们的本质；HoTT 对它们分别怎样处理  
> 写作原则：先在用户数学哲学内部重建，再给标准 HoTT/数学比较；两者并列，不让后一列静默覆盖前一列  
> 证据边界：本文是逐项解释与当前裁决，不是新 HoTT 定理、物理实验、原生证明助手收据或“HoTT 已解决一切”的证书

## 0. 先给一句总答案

HoTT 并不是用一个万能机制“解决所有悖论”。它面对不同问题时做了四种不同的事：

1. **拒绝形成**：不让无限制自指对象、同层所有类型之类型、错误 identity 或不合规归纳定义进入理论；
2. **区分资格**：把“有一个”“有具体见证”“可以统一选择”“可以有效运行”分成不同类型和不同规则；
3. **要求结构**：要谈路径、方向、来源、成本、阶段或状态，就必须把相应数据放进对象；忘掉以后不能免费取回；
4. **承认边界**：Gödel、Tarski、停机与全域自反射一类限制不会因换成 HoTT 消失；HoTT 通过宇宙层级、对象/元理论分离和受限反射管理它们，而不是越过它们。

因此，问“HoTT 如何解决我们研究过的悖论”时，必须先问“解决”是哪一种：

| 处理类型 | 人话 |
|---|---|
| `BLOCKED_AT_FORMATION` | 这东西根本没有合法地写成理论对象 |
| `DISSOLVED_BY_DISTINCTION` | 两个被混成一件事的问题被拆开后，矛盾消失 |
| `MODELED_WITH_EXPLICIT_STRUCTURE` | 问题可以研究，但时间、状态、方向等必须明确编码 |
| `INHERITED_LIMIT` | 理论自身也受这个一般极限约束，不能宣称解决 |
| `INTERPRETATION_OPEN` | 数学内部已清楚，现实/物理解释仍没有证据闭合 |

本项目最重要的发现不是“HoTT 已经无敌”，而是：

> **HoTT 对许多经典悖论确实有比朴素静态逻辑更强的准入、构造和信息使用纪律；正因为旧攻击常被这些纪律挡住，后续研究才必须去找“规则合法、使用自然、却在现实完成资格上仍发生提升”的更精确接口。**

## 2. 用户对悖论本质的看法

先不替用户改写成世界通行解释。按 `核心认知.md` 和用户原文，用户的体系有六个核心环节。

### 2.1 悖论是反证法的信号

用户把悖论看成反证法最终要看见的矛盾：

~~~
理论设定一组合取前提
  → 构造过程
  → 过程/结论/现象与现实冲突
  → 回查哪个前提被错误替换或否定
~~~

悖论不是供人观赏的怪题，而是告诉我们“前提账本里有问题”的信号。

### 2.2 现实事件由合取条件共同成立

用户强调“全真才真，一假即假”。现实中一件事能完成，依赖空间、时间、顺序、输入可用性、资源、构造过程等许多条件。理论为了好用，常把某一项理想化、删除或反转。

用户的 Z 铁律由此说：

> 理论抽象为了工具性必然否定现实的某些条件；完整过程—结论—现象谱中，至少有一个依赖该条件的效应会分岔。

本项目技术上把它校准为：必须证明被改条件确实是有效前提，目标效应确实依赖它；不能拿无关结论作无条件取反。

### 2.3 时间不是只有变量 `t`

用户关注的是工作维度：什么先发生、什么尚未落定、什么现在可用、什么构造已经完成、哪个结果过了截止时间就失去用途、哪项历史不能被当前快照替代。

一个理论能定义 `Time`，不等于这些条件自动进入每条形成、相等和使用规则。

### 2.4 ASK 先于真假

用户的 ASK 不是万能停机判定器，而是资格审查：

1. 对象能否合法形成；
2. 输入/证据此刻是否可用；
3. 依赖是否允许；
4. 任务要求持续输出、稳定、有限终止还是 deadline；
5. 证据是否允许提取所需结果；
6. 保证覆盖当前实例、某个像，还是全域。

ASK 还追踪资格在转换中怎样变化：被略过、被替换、被扩大、被不必要加强。

### 2.5 两类现实相对目标

用户把目标分成：

~~~
A：现实中能完成，理论化以后出现额外完成困难；
B：现实中不能完成，理论却绕过 ASK，假装已经完成。
~~~

这比“找 HoTT 内部矛盾”更宽，也更困难，因为它需要一座从数学结果到现实使用的桥。

### 2.6 训练知识是比较材料，不是裁判

用户要求未来 AI 先在其数学哲学内部理解问题，再使用既有数学作反例、规则核验和证据比较。这不等于用户主张免证；它要求：

~~~
问题所有权属于用户哲学；
数学真值仍属于证据。
~~~

## 3. HoTT 用来处理悖论的七件工具

### 3.1 类型形成：写得出来不等于有资格

HoTT/依赖类型论区分：

~~~
Γ ctx
Γ ⊢ A : U
Γ ⊢ a : A
~~~

一段自然语言描述不是自动合法的类型；一个合法类型也不自动有元素。空类型 `0` 是合法类型，但没有闭项。这直接区分描述、类型形成、对象存在/类型有元素。

它与用户“真假前先问是否合法”很接近，但不把“无元素的类型”叫非法。

### 3.2 宇宙层级：不允许同层“所有类型之类型”

HoTT Book 使用：

~~~
U0 : U1 : U2 : ...
~~~

而不是 `U:U`。官方 HoTT Book 明确说明，同层自包含宇宙会重现 Russell 类悖论，宇宙层级正是避免它的基本机制。见 [HoTT Book](https://homotopytypetheory.org/book/)。

### 3.3 构造与递归纪律：不是任何自调用都能成为函数

自然数递归、W 类型和归纳定义有结构递减/严格正性条件。一般的负向自依赖方程不能仅凭命名获得构造器和消去器。

这是一种 ASK：不是等它无限跑以后才说失败，而是在形成/递归规则处拒绝不合规程序。

### 3.4 命题截断：允许忘记，但限制拿回来

`||A||` 表示“仅知道 A 有元素”，不保留可以任意使用的具体见证。要从 `||A||` 消去到目标 `P`，通常要求 `P` 是命题。

因此：

- `||Σx.R(x)||` 不等于拿到某个 `x`；
- 若目标只是另一个命题，可以传播存在性；
- 若见证唯一或有额外选择原则，某些提取又可能合法。

它既是信息遗忘机制，也是防止“空头支票式提取”的保护机制。

### 3.5 Identity、等价和单价性：只保留声明过的结构

单价性说宇宙中的类型等价对应一种类型 identity。它不说等价程序代码具有同一运行时间、同构物品有同一来源、path 是物理运动，或任意社会角色与历史自动相同。

若来源、成本、方向或状态属于任务，必须把它放进结构签名，再研究保结构等价。

### 3.6 商/HIT 消去：只有尊重关系的操作才能下降

集合商可以把相关对象识别，但从商定义函数时必须证明函数尊重被识别关系。

人话是：

> 你先说“两种输入在这个问题上算同一个”，以后就不能再定义一个偷偷区分它们的输出函数。

如果 `race` 依赖完成先后，而商关系故意忘掉先后，HoTT 不会自动发放商上的 `race`。拒绝下降是正确防线。

### 3.7 对象理论与元理论：不能自己担保一切

HoTT 可以编码很多语法和数学，但完整的自身语法、语义、soundness、consistency、truth 和全域 reflection 往往需要更高 universe、外部元理论或 two-level type theory 的 strict outer layer。

这不是 HoTT 独有的耻辱，而是强形式系统的一般边界。

## 4. 六个用户参照悖论：逐一讲清

## 4.1 芝诺悖论

### 悖论内容

每次走剩余路程的一半：

~~~
x_n = 1 - 2^(-n)
~~~

每个有限 `n` 都有 `x_n<1`，却有极限 `lim x_n=1`。

### 用户的本质判断

用户认为，理论把实际运动的逐步完成换成一个已经给定的无限序列整体，再用极限的静态性质说“到达 1”。这可能隐藏必须按次序完成每一步、无限可分/稠密空间的前提，以及现实运动可能离散或量子化。

所以在用户视角下，芝诺属于 A 类：现实运动能完成，稠密理论过程却制造“永远还有一半”的无法完成。

### HoTT/标准数学怎样处理

HoTT 可以构造实数、Cauchy/Dedekind 完备性、序列和极限。它会严格区分：

~~~
lim x_n = 1
与
∃n, x_n = 1
~~~

前者不推出后者。数学极限也不是“执行了最后一次无限步骤”的程序记录。

### 到底解决了什么

- `DISSOLVED_BY_DISTINCTION`：极限对象与有限索引命中被区分；
- `MODELED_WITH_EXPLICIT_STRUCTURE`：若任务是实际逐步执行，必须另给时间/过程语义；
- `INTERPRETATION_OPEN`：HoTT 不证明物理时空连续或离散，也不证明普朗克尺度是最小像素。

人话结论：

> HoTT 能让“极限等于 1”和“某一步已经走到 1”不再混淆；它不能只靠这一区分替物理世界回答运动究竟连续还是离散。

## 4.2 罗素悖论

### 悖论内容

令 `S` 为所有“不包含自身的集合”的集合。问 `S∈S`：若包含，按定义不该包含；若不包含，按定义又该包含。

### 用户的本质判断

用户提出“假集合”：描述一个集合的样子，不等于它能被构造。又把构造写成阶段：

~~~
r_(n+1) = not r_n
~~~

即不断把 `S` 拿入/拿出，永不落定。用户认为朴素集合论的问题是把尚未形成的 specification 先提升成已经存在的集合，绕过 ASK。

### HoTT 怎样处理

HoTT 没有无限制 comprehension，也没有同层“所有类型的类型”。要写对象，必须通过类型形成规则；宇宙分层为 `Ui:U(i+1)`，不允许 `U:U`。

此外，HoTT 区分一个类型合法形成与该类型是否有元素。一个自相冲突的性质可以对应空类型；理论不因空类型存在就矛盾，只有从空类型造出闭项才出问题。

### 到底解决了什么

- `BLOCKED_AT_FORMATION`：朴素的全域自成员构造没有对应的合法同层形成规则；
- `DISSOLVED_BY_DISTINCTION`：描述/形成/有元素被拆开；
- 用户的“formation gate”直觉与 HoTT 很接近；
- 但用户的 `r_(n+1)=not r_n` 是一种动态解释，不是 HoTT 处理 Russell 的唯一标准证明。

人话结论：

> HoTT 不先把那个危险的 S 当作现成对象再问它属于不属于自己。它先问：你凭哪条规则造出了 S？造不出来，就到此为止；造出一个空类型，也不等于造出了其中的东西。

## 4.3 说谎者悖论

### 悖论内容与用户判断

“这句话是假的。”用户把稳定真值计算写成 `p=not p`；若按时间修订，则成为：

~~~
p_(t+1) = not p_t
~~~

后者可以一直交替，但没有稳定完成值。问题在于句子要求在自己的真值落定前读取该真值。

### HoTT 怎样处理

HoTT 没有一个自动适用于所有内部句子的全域真理谓词，也没有无条件同层 quote/eval。普通递归与归纳构造受类型、宇宙和严格正性约束。

如果要表示交替流，可以显式定义状态序列，或在 guarded/clocked theory 中用 `later` 表示下一阶段；这时得到的是合法动态对象，不是稳定 Bool。

### 到底解决了什么

- `BLOCKED_AT_FORMATION`：没有合法全域自真理接口时，经典自指句不能直接进入；
- `MODELED_WITH_EXPLICIT_STRUCTURE`：修订序列可以表示，但任务从“稳定真值”变成“持续过程”；
- `INHERITED_LIMIT`：Tarski/Gödel 型全域 truth/reflection 界限没有消失。

人话结论：

> HoTT 不必强迫这句话在 true/false 里选一个。它可以拒绝那个自读取真值的接口，也可以把“不断反转”当成一个过程；但过程存在不等于稳定答案存在。

## 4.4 Better Best 悖论

### 悖论内容与用户判断

甲选择“成为最好的”，乙选择“成为比甲更好的”。用户强调先接受甲的选择，使甲的“最好”成为已提交不变量，再审查乙的新要求是否合法。乙的要求与现有承诺冲突，应有限拒绝。

这不是一定要无限循环的程序；错误在于把不相容的后续请求也准入。

### HoTT 怎样处理

可以把状态和不变量编码在依赖类型中：

~~~
State
ValidRequest : State → Request → Type
apply : (s:State) → (r:Request) → ValidRequest s r → State
~~~

没有 `ValidRequest` 的证明，就不能调用 `apply`。也可以把“甲最好且乙比甲更好”表达成空类型/不可满足结构。

### 到底解决了什么

- `DISSOLVED_BY_DISTINCTION`：承诺状态、候选请求和合法更新分开；
- `BLOCKED_AT_FORMATION`：没有合法性见证就不能应用更新；
- bare HoTT 不会自动知道现实中的先后；状态和协议必须建模。

人话结论：

> HoTT 可以让“你已经答应了什么”进入下一步函数的输入类型。乙没有通行证，程序就拒绝。它不需要一直尝试同时满足两个要求。

## 4.5 圆环悖论

### 悖论内容与用户判断

从圆上拿掉一点得 `M`，展开为两端分开的线 `N`。为什么 `M→N` 容易，而 `N→M` 似乎无法让两端只差一个无大小的点？

用户抓住的是：当初确实从 `M` 得到 `N`；为什么反向恢复失去资格；点无大小、连续统稠密性和过程不可逆可能是被抽象前提；“曾经有共同来源”不该被当前裸形态抹掉。

### HoTT/拓扑怎样处理

纯拓扑上，穿孔圆 `S1\{p}` 与开区间/实线同胚；若保留具体同胚，当然可以反向映射。HoTT 的圆是一个 HIT：

~~~
base : S1
loop : base = base
~~~

圆的闭合不是从裸区间自动猜出的，而是由 `loop`/端点识别等结构给出。

若把“带缺失点、共同端点来源、展开历史”的丰富对象忘成裸区间，裸区间确实不能决定两端是两个不同边界，还是应被识别成同一个缺口。

### 到底解决了什么

- `DISSOLVED_BY_DISTINCTION`：拓扑同胚与物理复原过程不是一回事；
- `MODELED_WITH_EXPLICIT_STRUCTURE`：闭合、端点识别、同胚和 provenance 必须显式保留；
- 用户最有价值的残余是“来源历史忘掉后不能免费恢复”，不是“开区间拓扑上无法回到穿孔圆”。

人话结论：

> 如果你把“这两个端原来来自同一个缺口”的纸条一起带着，HoTT 能按这张纸条重新粘合；如果只剩一条裸线，理论不会假装知道该怎么粘。

## 4.6 shenchensh 平行线转动悖论

### 悖论内容与用户判断

一条相交直线绕定点转到平行。仿射交点沿另一条直线越来越远；到了平行时，交点怎样从一侧“跳”到另一侧？若转角连续稠密，最后时刻怎样完成？

用户把它与芝诺归为同病：数学要求交点无间隙移动；平直、无限、稠密空间是隐藏前提；可以通过圆型闭合空间或离散转角否定其中某项前提；用户倾向把时空稠密性视为病根。

### HoTT/标准几何怎样处理

先分模型：

1. **仿射几何**：平行配置没有有限交点；“交点位置”是部分函数，在平行参数处未定义；
2. **射影几何**：加入无穷远点/方向，平行线在射影完备化中相交；
3. **旋转参数**：直线角度可以在有限参数时刻到达平行角；交点坐标趋于无穷不等于某个物体跑完无限距离；
4. **离散转角模型**：是另一套物理/计算模型，需要给出步长和可观测预测。

HoTT 可以形式化这些空间、路径和完备化，但不会把三个模型自动认成同一物理宇宙。

### 到底解决了什么

- `DISSOLVED_BY_DISTINCTION`：配置路径、交点部分函数和物质运动分开；
- `MODELED_WITH_EXPLICIT_STRUCTURE`：仿射/射影/离散模型各自明确；
- `INTERPRETATION_OPEN`：不能从该悖论单独推出物理时空离散、宇宙闭合或普朗克长度为最小单位。

人话结论：

> 直线可以在有限时间转到平行；只是“有限交点在哪里”这个问题在那一刻没有答案。没有答案的是交点函数，不是转动本身卡在无穷远。

## 5. 自指、Gödel 与“无限之镜”

这条线不是六律之一，却是用户对 HoTT 的原始押注。

用户追问 HoTT 能否把自己整个宇宙当对象、能否在同一层证明自己的完备可靠和一致，以及“最终观察者”是否总在体系外。历史 AI 曾把 `Map(1,G)` 错当 loop space，又从宇宙角色相似直接推出宇宙等价；这些公式已经被撤销。

HoTT 的真实处理是：

1. universe hierarchy 防止无条件同层自包含；
2. 对象理论可以编码自身的某些片段，但 raw syntax、substitution、judgmental equality、semantics 和 soundness 需要精确构造；
3. two-level type theory 用 strict outer layer 内部化 inner HoTT 的部分元理论；
4. 对足够强、有效且一致的固定系统，Gödel/Tarski/Lawvere 型限制继续约束全局 truth、consistency 和 reflection。

裁决：`INHERITED_LIMIT / REAL_SELF_METATHEORY_GAP`。

HoTT 没有“解决”自指到可以完全自证。它做的是分层、限定接口、把所需元理论放到更高层或更强系统。用户的直觉——理论不能无代价同时做对象、观察者和最终担保者——有真实技术对应；但“HoTT 完全不能谈自己”仍然过强。

## 6. 项目 HoTT 候选族：HoTT 分别怎样回应

### 6.1 同函数异时

两个程序 `fast`、`slow` 对每个输入返回同一值；函数外延性可给出函数 identity，但固定求值语义下成本不同。

HoTT 的回应是：函数 identity 只拥有输入—输出行为，不拥有代码、轨迹、墙钟和能耗。若要这些观察量，应使用 `Program`、`Sem`、`Cost/Trace` 或 cost-aware/quantitative/effectful type theory。

裁决：`REPRESENTATION_LIMIT / OPEN_REALITY_PROMOTION`。错误只发生在把裸函数 equality 提升为完整执行过程 identity 时；项目尚未给出自然应用中这项提升的最终实例。

### 6.2 Guard-Erasure

阶段过程 `x_(n+1)=F(x_n)` 若忘掉所有阶段，又要求单值 `x` 继续满足更新律，就得到 `x=F(x)`；对 Bool 取反没有固定点。

bare HoTT 可以把整个序列作为对象，并不强迫压成单值。Guarded/clocked theory 用 `later` 与 clock 保留“稍后可用”。只有一个真实 forgetful translation 同时擦掉 stage、又要求更新律下降时，才出现条件障碍。

裁决：`GENERAL_LEMMA_VERIFIED / HOTT_TRANSLATION_OPEN`。

### 6.3 原作—复制品与 provenance

当前快照相同，原作身份不同。单价性只识别声明在结构里的内容。若 `IsOriginal` 依赖历史，就把 provenance 放进 Σ-结构或记录类型。忘掉它以后不能从裸快照恢复。

裁决：`VERIFIED_INFORMATION_LOSS / NOT_HOTT_FAILURE`。

### 6.4 identity path 可逆与现实不可逆

每个 `p:x=y` 有逆 `p^-1:y=x`；现实中的破碎、死亡、资源消费不可逆。HoTT 的回应是：identity path 表达同一性，不是一般状态转移。现实过程应使用普通函数、`Step x y` 关系、范畴态射、directed type theory 或带资源/效应结构。

裁决：`INTERPRETATION_CONFLICT_IF_IDENTITY_AS_PROCESS`。

### 6.5 无规范“较早事件”

一个完全无标签的二元素类型有两个对称点，不能自然选出“较早的一个”；自同构会交换两点。加入顺序、标签或选定点后可以选择。

裁决：`CORRECT_REFUSAL / NO_CANONICAL_POINT`。这是 HoTT 防止凭空生成时间方向的正面结果。

### 6.6 截断存在、见证与交付

从“存在某个值”不能一般地直接取出该值并运行。命题截断限制消去；但可以得到命题目标，或在唯一性/额外选择原则下取得更多。

裁决：`QUALIFICATION_PRESERVED_BY_ELIMINATION_RULE`。历史“截断凭空造见证”的 AI 攻击是错的。

### 6.7 RP-B01：数学分类与有效实现

借助排中律可以在数学上定义停止分类 `χ(p,x):Bool`；这不自动给出可以执行的全域停止算法。

必须分三层：

1. 对固定实例，有有限证书时可以运行；
2. 在加入经典公理的数学理论里，可以证明一个总分类函数存在；
3. 不存在无神谕的统一有效算法实现一般停机分类。

公理常量有类型，不等于有计算规则。一个 proof assistant 接受定义，也不等于 `#eval` 能给所有输入结果。

裁决：`PAPER_AND_FINITE_MODEL_BOUNDARY / NATURAL_HOTT_USE_BRIDGE_OPEN`。这正是用户 B 方向与 W51“逻辑+几何+程序”认知的主交点。

### 6.8 R034：路径证书与 `MereMove`

问题是：已知 `||X=Y||` 且有 `x:X`，能否对所有 `X,Y` 自然地产出 `Y` 元素：

~~~
Π(X,Y:U). ||X=Y|| → X → Y
~~~

R034 纸笔论证用 Bool 取反自同构、Σ 回路与依赖自然性证明这个统一接口不可居留。固定 `Bool/Bool` 对上的恒等函数仍可构造；给实际路径时 transport 也可构造。

裁决：`PAPER_PROVED_WITH_FINITE_CONTROLS / NATIVE_NOT_RUN`。这不是 HoTT 失败，而是 HoTT 的相干性阻止“只知道有路径”被提升为任意统一搬运器。用户提供的 Web 展示文件与 workspace R034 正文 SHA 完全一致；原生 Cubical Agda 仍未运行。

### 6.9 R036/R038：抽象路径与当前态提升

逐边存在具体代表，不等于当前选定代表能沿整个无限路径相容地前进。有限终止链的状态商可能出现抽象无限路径。

HoTT 要求当前态 lift、ranking/Acc 或相容代表。命题截断可向命题性的 Acc 消去，说明截断并非一律毁掉终止证据；无限多个有限前缀又不自动拼成单一无限执行。

裁决：`FINITE_CHECKED_CONDITIONAL_BOUNDARY`。

### 6.10 R039/R041：silent steps、`bind` 与 `race`

R039 证明：发散不敏感弱互模拟可以保 may、不保 must；错误的无限单边余归纳关系甚至不传递；正确结果等价保留是否返回和返回值。

用户新提供的数学 R041 在结果等价 `≈` 下进一步给出：

- 实际 continuation 的顺序 `bind` 尊重 `≈`；
- `race` 不尊重 `≈`；
- `p0≈p2`，但 `C(p0)` 返回 7，`C(p2)` 进入 `ω`；
- 黑箱选择器不能同时满足值可靠、响应性和结果外延性；
- 支持 race 的相容关系必须保留更多完成时刻信息。

集合商的递归原则只允许尊重关系的函数下降。因此 `bind` 可在已证相容范围内下降；`race` 依赖被商掉的完成先后，不能自动下降。拒绝 `race` 是理论准确报告“你的抽象不够支持这个操作”。

裁决：`R041_PAPER_SOURCE_ACQUIRED / CODE_RUN_GIT_LINEAGE_OPEN`。文件名为 R401，但正文记录号是 R041。当前只有 150 行证明笔记；其声称的 25 测试、源码、`cf58f27` 和增量容器未在当前 repo 取得。

### 6.11 自指/反射/Löb 族

历史 R029–R032 得到的正确边界是：

- 固定有限片段、受限反射、proof-producing reflection 可以工作；
- 全域同域解释、无条件 `Prov(A)→A`、完整自身 soundness 会触发对角/Löb/Gödel 条件；
- 必须固定语法、编码、替换、评价和总性；
- 更高 universe 或 two-level outer theory 是显式富化。

裁决：`REAL_GENERAL_LIMIT / HOTT_SPECIFIC_CONSTRUCTION_OPEN`。用户押注有方向价值，但历史工作尚未给出新的 HoTT 特定构造定理。

## 7. 被淘汰攻击：HoTT 为什么没有被它们击中

| 旧攻击 | 为什么失败 | HoTT 的真实规则 |
|---|---|---|
| `Map(1,G)` 是 loop space | `Map(1,G)≈G`；loop space 是 `g=_G g` | 类型必须先正确 |
| 相邻 universe 角色相似故等价 | 角色相似不是 equivalence 数据 | 单价性只把真实等价变成路径 |
| `Id_A(a,b)` 可跨 `a:A,b:B` | 端点必须在同一类型，或先 transport | identity formation 有明确侧条件 |
| 所有 transport 只能发生一次 | 误读线性资源；不同资源可各用一次 | bare HoTT 还是 Cartesian，可复制变量 |
| type checking 慢/搜索难说明本体失败 | 检查给定项与无界搜索不是同一任务 | checking、search、execution 分层 |
| 未定义 `Translate` 可直接接停机归约 | 输入语言、正确性和编码都没给 | 归约必须有完整函数与保持证明 |
| axiomatic `transport(ua(e),x)` 不归约就是永远卡死 | 书式呈现缺计算规则不等于所有 cubical 呈现都不计算 | Cubical TT 给 univalence 计算解释 |
| `||A||` 可提取任意 `A` | 违反截断消去限制 | 目标为命题或有额外条件时才可消去 |
| 有限 fuel 用尽证明程序发散 | 预算耗尽只证明这次未完成 | 发散需循环证书、归纳反证或一般定理 |
| 文件/测试很多证明 HoTT 被推翻 | 工程存在与数学结论不同 | 主张、形式证明、运行、现实桥梁分层 |

这些负结果告诉我们 HoTT 已有的防线在哪里，也防止未来 AI 为迎合目标复活已知错误。

## 8. 用户哲学与 HoTT：哪里相合，哪里有张力

### 8.1 高度相合

| 用户洞见 | HoTT 对应 |
|---|---|
| 真值之前先问计算/形成是否合法 | typing/formation/strict positivity/structural recursion |
| “存在”不等于“已经拿到结果” | Σ 见证与 propositional truncation 分离 |
| 未落定值不能提前使用 | dependent context；guarded/clocked 的 `later` |
| 抽象后不能免费恢复被删差异 | quotient eliminator、naturality、no-section |
| 相等不应吞掉任务所需结构 | structure identity principle；把字段加入签名 |
| 理论不能无代价完全自证 | universe hierarchy、metatheory、2LTT、Gödel/Tarski 边界 |

所以说 HoTT “已经考虑过很多旧悖论”并非空话：它确实把不少 ASK 责任做进了形成与消去规则。

### 8.2 HoTT 的反向校准

1. **合法空类型不是非法命题。**类型形成和有元素不同；
2. **静态数学可以完整描述动态过程。**关键不是纸面静态，而是 stage 是否保留；
3. **极限不是执行无限循环。**极限性质和有限步骤完成要分开；
4. **identity path 不是物理过程。**可逆 identity 不代表现实可逆；
5. **可表达 Time 不等于内生 clock。**但有 reduction 也说明 HoTT 不是绝对静态；
6. **程序视角不能消灭不可判定性。**程序本身继承停机和自反射极限；
7. **物理离散性尚未证明。**Planck 尺度、圆型宇宙和离散转角仍是用户物理假说。

这些校准不是让训练数据推翻用户问题，而是让问题获得不会被简单反例击穿的数学形态。

| 对象 | 直接答案 | 处理类型 |

## 10. 对未来研究的直接含义

历史悖论不应再被机械平移成“HoTT 版”：

- 再写一个 Russell 名字的自环，不会绕过 universe/formation 防线；
- 再写一个说谎者固定点，不会自动得到 HoTT 的合法自引用；
- 再说路径可逆，不会自动把 path 变成物理过程；
- 再说截断丢见证，不会绕过它明确的消去限制。

真正有价值的下一问题是：

1. HoTT 已经合法构造了什么资格？
2. 这个资格经过哪个真实操作后被当成了更强资格？
3. 原任务需要的 stage、cause、cost、witness 或 effective implementation 是否仍在？
4. 如果规则正确拒绝，记录为防线；
5. 如果自然使用仍发生越界，才形成用户要的现实相对悖论。

R041 有价值，因为它不是再证明“等待时间不同”，而是展示**一个等价对顺序组合足够、对竞争上下文不足**。W51×RP-B01 有价值，因为它要求展示**数学分类资格怎样被提升为有效程序资格**。

## 13. 最后的“人话”

用户看悖论时总在追问：

> 你凭什么说这个东西已经存在、已经稳定、已经可用、已经完成？

HoTT 最强的地方，恰恰是它经常回答：

> 先把类型、见证、路径、消去规则和宇宙层级给我；没有这些，我不让你往下走。

这就是它为什么能挡住 Russell、截断空头支票和许多坏自指。

但 HoTT 也会说：

> 我只承诺了结构上的相等、存在或商类；运行时间、来源、因果、在线可用性和物理交付，如果没写进结构，就不是我已经给你的东西。

这就是本项目仍要追问的地方。真正的 HoTT 现实相对悖论，不应来自无视这些边界，而应来自一个**确实合法、确实自然、确实容易被当作更强现实资格的接口**。找到那一步，才是对用户问题最有力的回答。
