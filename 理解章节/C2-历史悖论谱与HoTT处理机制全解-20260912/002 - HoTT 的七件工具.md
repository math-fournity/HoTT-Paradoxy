# HoTT 的七件工具

## 3. HoTT 用来处理悖论的七件工具

### 3.1 类型形成：写得出来不等于有资格

HoTT/依赖类型论区分：

~~~
Γ ctx
Γ ⊢ A : U
Γ ⊢ a : A
~~~

一段自然语言描述不是自动合法的类型；一个合法类型也不自动有元素。空类型 `0` 是合法类型，但没有闭项。这直接区分描述、类型形成、对象存在/类型有元素。

它与用户“真假前先问是否合法”很接近，但不把“无元素的类型”叫非法。

### 3.2 宇宙层级：不允许同层“所有类型之类型”

HoTT Book 使用：

~~~
U0 : U1 : U2 : ...
~~~

而不是 `U:U`。官方 HoTT Book 明确说明，同层自包含宇宙会重现 Russell 类悖论，宇宙层级正是避免它的基本机制。见 [HoTT Book](https://homotopytypetheory.org/book/)。

### 3.3 构造与递归纪律：不是任何自调用都能成为函数

自然数递归、W 类型和归纳定义有结构递减/严格正性条件。一般的负向自依赖方程不能仅凭命名获得构造器和消去器。

这是一种 ASK：不是等它无限跑以后才说失败，而是在形成/递归规则处拒绝不合规程序。

### 3.4 命题截断：允许忘记，但限制拿回来

`||A||` 表示“仅知道 A 有元素”，不保留可以任意使用的具体见证。要从 `||A||` 消去到目标 `P`，通常要求 `P` 是命题。

因此：

- `||Σx.R(x)||` 不等于拿到某个 `x`；
- 若目标只是另一个命题，可以传播存在性；
- 若见证唯一或有额外选择原则，某些提取又可能合法。

它既是信息遗忘机制，也是防止“空头支票式提取”的保护机制。

### 3.5 Identity、等价和单价性：只保留声明过的结构

单价性说宇宙中的类型等价对应一种类型 identity。它不说等价程序代码具有同一运行时间、同构物品有同一来源、path 是物理运动，或任意社会角色与历史自动相同。

若来源、成本、方向或状态属于任务，必须把它放进结构签名，再研究保结构等价。

### 3.6 商/HIT 消去：只有尊重关系的操作才能下降

集合商可以把相关对象识别，但从商定义函数时必须证明函数尊重被识别关系。

人话是：

> 你先说“两种输入在这个问题上算同一个”，以后就不能再定义一个偷偷区分它们的输出函数。

如果 `race` 依赖完成先后，而商关系故意忘掉先后，HoTT 不会自动发放商上的 `race`。拒绝下降是正确防线。

### 3.7 对象理论与元理论：不能自己担保一切

HoTT 可以编码很多语法和数学，但完整的自身语法、语义、soundness、consistency、truth 和全域 reflection 往往需要更高 universe、外部元理论或 two-level type theory 的 strict outer layer。

这不是 HoTT 独有的耻辱，而是强形式系统的一般边界。
