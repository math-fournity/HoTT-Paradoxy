### AI 最终回复

已完成：从现在起，`dev-notes/` 对话归档不再只停留在工作区；每一轮成功归档都必须以**只包含该 note 的本地 Git 提交**完成版本闭合。

新的完整链路是：先记录 `dev-notes/` 的 Git 状态基线，再由归档 Skill 写入当前用户消息和 final draft；只有 helper receipt 返回的 note 不在既有 delta 中、也未被 `.gitignore` 忽略时，才执行：

```bash
git add -- '<receipt-note>'
git commit --only -m 'archive: record dev notes' -- '<receipt-note>'
```

随后会核对新 `HEAD` 的文件清单只能有这一个 note，并确认该 note 已被跟踪且相对 `HEAD` 无差异。这样即使仓库已有其它 staged 或 unstaged 工作，也不会被归档提交夹带进去。`git add -A`、无路径 `git commit`、tag、push、发布和分享都被明确禁止。

为避免把“文件写出来”误称为“进入 Git”，状态现在严格区分：

- `ARCHIVED`：helper 已写入并核验 note；
- `ARCHIVED_AND_VERSION_CLOSED`：该 note 已通过上述单文件 Git commit；
- `ARCHIVED_NOT_VERSION_CLOSED`：存在预先的其它会话 delta、ignore 规则、Git 身份/分支保护失败，或不应写入 Git 的敏感正文。此时会保留归档和诊断，但绝不借 broad commit 把别人的内容提交进去。
