# 框架消融观察与分级治理优化方案（2026-09-18）

## 用户提问（逐字）

> 我最主要的发现，是我发现其他平台的AI，在某些任务上，即便不走这套框架，也是可以工作的。所以引起了我的警觉，这套框架如何优化呢？

## AI 最终回复（逐字，与对外回复一致）

**你的警觉是对的，但它证明的东西比"框架没用"更精确：它证明这套框架的强度只有一档，而它防御的五种失败在任务间分布并不均匀。优化方向不是删掉框架，而是把"一档强度"改成"按风险分级"——并且你的 repo 里已经有一份现成的消融实验数据（S170–S176 七轮绕过），它精确地告诉了我们哪些部件是承重墙、哪些是仪式。**

一、你的观察证明什么、不证明什么。要区分四个不同的标准："能工作"、"能被信任"、"能被恢复"、"能被审计"。其他平台的 AI 在某些任务上过了第一关——但那些任务通常是自包含、短视界、无数学主张、错了可重来的；而且它们大多踩在框架产出的地基上（dev-notes、MEMORY、交接文档、核心认知七代账本都是框架会话写的——"不走框架的 AI"在免费搭乘"走了框架的 AI"积累的状态）。更关键的是幸存者偏差：你看见的是没翻车的那几次，框架防的漂移、结论膨胀、恢复失败恰恰是低频高损事件——保险的价值在没着火时不可见。

二、S170–S176 消融实验的判决书（这是你观察的实验室版本）。这七轮绕过了 checkpoint 事务，结果分两半：**活下来的**——数学执行（金形态四条件过核）、执行纪律（逐段编译、plan-revise）、审计写作（S174/S175 照写分片审计集）、dev-notes 常设规范；**退化了的**——STATE.revision 停在 169、HEAD 漂移导致 canonical plan 被 fail-closed 锁死、全景/方向投影写回挂起、出现一处索引与事实不符、收据缺口永久登记。结论：**执行纪律层可以低成本替代（git commit + dev-notes 就够），状态机层不能**（一旦绕过就静默积累漂移）。还有一个反直觉细节：被绕过的是重的"事务包装"，而更贵的"审计内容"反而被自愿保留了——说明 020 合同把审计瘦到可承受后，AI 自己愿意写；事务没人愿意走是因为它保护的状态太大、复制太重。优化应该顺着这个实证：把事务层降到审计层已经达到的可承受度，而不是强迫任何人走重事务。

三、优化方案：分级治理（Tiered Governance）。治理强度应该正比于四个变量：**主张风险 × 自治程度 × 视界长度 × 状态改写**，而不是 uniformly 全量。你观察到的"其他 AI 不走框架也能干"，本质是那些任务属于低档位——框架应该正式承认低档位的存在，而不是假装一切任务都是研究级：

| 档 | 任务类型 | 启动加载 | 结束义务 | 不变门禁 |
|---|---|---|---|---|
| T0 轻任务 | 只读/单会话/无主张 | 根 AGENTS + MEMORY 队列片 + 任务文件（≈1.5 万） | 无（chat 摘要即可） | 来源边界、禁 Sub Agent、不 push |
| T1 常规工程 | 写代码/文档、无数学主张 | 启动核瘦身后（G2 后 ≈4 万）+ latest/active | 轻量 SESSION.md + 触及集 KC 复认 | 同上 + 写回归属表 |
| T2 研究任务 | 数学研究/系统化探索 | research profile（G2-G4 后 ≈12 万） | 分片审计集（触及集计量） | + 四件套全文、完备性回评 |
| T3 状态改写/结论交付 | checkpoint、数学结论、core 更新 | 全量 | 全量 KC 审计 + 原子事务收据 | + F-011 机器证明门禁、result.json 唯一收据 |

四、行动优先级（合并两份报告的 G1–G7 与本判断）：
1. **G1 修复漂移**（HEAD/RESUME/根 AGENTS 代数）——先把锁死的 canonical 出口修开，一切测量的前提；
2. **G2 STATE 热/冷拆分**（22.4 万 → 1–2 万）——最大单杠杆，且给 T0/T1 提供存在空间（没有瘦身后的 STATE，分级加载无物可载）；
3. **新增：LOAD_SET v5 引入 T0/T1 档**（governance-lite profile + AGENTS 路由表按任务类型分档）——这是对你观察的直接回应；全局 AGENTS 里本来就有"微小任务即时闭包"条款，项目框架缺的正是这一档；
4. **G3 压缩重付改收据制**（hash 锚定 + 逐 KC 复认替代全文重付）；
5. **G4 研究层三文档切档 + G5 审计触及集计量 + G6 checkpoint 保留策略**；
6. **新增：治理 ROI 遥测**——每轮 session 记录"框架各元件实际使用/未使用/若使用会拦住什么"，让下一轮优化有数据而不是有感觉；并把 S170–176 消融审计做成正式证据产品（它已经是免费的实验数据）。

五、永不裁剪清单（有实证支撑的承重墙）：核心认知全文常驻（你的上下文工程，12K、七代零失控，单位价值最高）；F-011 数学证明门禁（42 个 proof package 零冒充记录，执行率最高的机制）；状态写入的 fail-closed（两次真实拦截漂移）；hash 锚定（代际机制是全框架运行最平稳的变更通道）。

六、需要你裁定的点：(1) 是否接受分级治理原则并授权 LOAD_SET v5 设计；(2) 是否授权 G1 修复会话；(3) 是否授权 G2 STATE v3 迁移；(4) 两份报告 + 本轮 dev-notes 是否提交入库。以上任何一项落地前，我不会动任何治理真值源。
