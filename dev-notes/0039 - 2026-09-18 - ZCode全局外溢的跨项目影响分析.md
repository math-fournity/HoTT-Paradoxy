# ZCode 全局外溢的跨项目影响分析（2026-09-18）

## 用户提问（逐字）

> 所以，ZCode在这方面的缺失，导致repo内的治理框架要外溢到全局，而这种外溢性，我觉得最大的问题在于，其他的项目，ZCode中的AI会不会被意外地影响到呢？

## AI 最终回复（逐字，与对外回复一致）

**直接回答：按 v5 默认方案（不装 symlink），其他项目的 ZCode 会话**不会**被本 repo 的治理影响——外溢足迹为零；唯一能造成跨项目影响的通道是可选的 Skill symlink 导入，它的影响有两类（恒定的元数据税 + 低概率的语义误触发），这正是 v5 把它设为默认不装的原因。**

逐通道盘点。第一，根 AGENTS.md：它是 **workspace 级**注入，不是全局注入——ZCode 只在"当前工作区是本 repo"时才组合这份文件，其他项目的会话根本看不见它。所以 repo 宪法本身不外溢，这条最重要的通道天然是 scope 正确的。第二，repo 真值树（.codex/ 内一切）：其他项目的会话不读它，零影响。第三，本项目的 project memory：按项目哈希隔离在 ~/.zcode/cli/memories/projects/<本项目>/，docs 明言"不会带到另一个工作区"，零影响。第四，可选 symlink（~/.zcode/skills/<name> → repo 内 SOP）：这是唯一真实的外溢通道——ZCode 每轮对话向**所有项目**注入已启用 Skill 的 name+description 元数据。影响有二：(a) **元数据税**：三枚 SOP 的名字+描述（描述注入上限约 250 字符/枚）每个对话都在场，约几百 tokens，小而恒定，且挤占共享元数据预算（超预算会退化为只注入名字，伤害所有 Skill 的自动触发）；(b) **语义误触发**：若另一个项目的任务描述恰好命中 SOP 的 description（比如又是一个"审计/治理"类任务），模型可能在无关项目里展开 HoTT 研究 SOP——概率低（描述写得足够领域特异）但非零。第五，全局 AGENTS（~/.zcode/AGENTS.md）与四个 repo-* 全局 Skill：它们确实影响所有项目，但那是你自己早已存在的跨项目治理层，不是本 repo 的外溢——而且这条边界应该立成明规则：**全局层只准放跨项目通用的纪律（闭包/证据/基线类），项目专属内容（HoTT SOP、STATE、任何 repo 事实）永不进全局 AGENTS 或全局 Skills**。本次全部讨论中我从未向 ~/.zcode 全局层写过任何本 repo 内容，就是这个原则的执行。

推论与固化建议：(1) v5 的"宿主最小合同"（只依赖根 AGENTS 注入+文件读+shell）本身就是外溢最小化设计——需要的东西越少，能漏出去的越少；(2) 如果将来某天你确实要硬强制（Hook 级），安全模式是"全局 Hook + repo 路径守卫"：Hook 检测当前 cwd/repo 是否为本 repo，出界立即 no-op——跨项目影响收敛为微不足道的调用延迟；(3) 建议把"全局层准入规则"写进 v5 分片 003 或你的全局宪法（一行即可：项目专属内容禁入全局层），等你授权时一并落地。
