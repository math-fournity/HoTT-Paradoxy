## 这个 SOP 调查什么

它把你的路线固定为一条可追溯的链：

```text
R_i：HoTT 作者或权威文献明确陈述的创建动机
  → Z_i：该动机在 ZFC／集合论侧真正指向的规则、代价、使用方式或消费者
  → Q_i：经模式 P、同一任务与反控制资格化后的 ZFC 候选问题
```

其中还单列了你提出的更强路线：

```text
H0（已知 HoTT 现象） → Z0（ZFC 中的对应结构） → Q0（ZFC 候选问题）
```

这不是把 HoTT 的问题类比到 ZFC。它要求逐项证明：ZFC 中有原生对象和原生形成／使用位置，保持同一个主体、过程、观察量与完成标准，并真正出现尚未支付的完成义务。若这些条件不成立，档案会将其登记为 `ANTI_ANALOGY_CONTROL`，而不会借类比把它写成 ZFC 的缺陷。

## 标准化作业流程

| 阶段 | 必须完成的调查 | 留存物 |
|---|---|---|
| 0. 冻结分母 | 固定本轮 HoTT 原典、技术材料、ZFC/集合论材料、真实消费者与批评／比较文献的 A–E 来源分母。 | `MANIFEST.md`、`SOURCE-CATALOG.md` |
| 1. 原典取证 | 先保存版本、作者、出版身份、页码／节号、原始文件与哈希；MinerU 等文本只作为派生阅读材料。 | 原件身份记录、可定位摘录 |
| 2. R-card | 逐条提取作者实际说出的动机，保留上下文，避免把“宣传语”误读成基础理论批评。 | `R-CARDS.md` |
| 3. Z-card | 对每项动机同时构造竞争性 ZFC 读法：它究竟是 ZFC 公理、集合论实践、实现习惯、表示困难，还是 HoTT 独有的设计目标？ | `Z-CARDS.md` |
| 4. Q-card | 以 P1／P2／P3、同一任务、真实消费者、完成条件和反事实控制筛选，区分候选、被防线化解、来源不足与反类比。 | `Q-CARDS.md` |
| 5. 标准防线 | 调查数学界已有的模型、分层、选择、公理化、证明助手实现与实际使用者，防止把已有防御、表示问题或局部工程困难误报为理论问题。 | `CONSUMER-CONTROLS.md` |
| 6. 覆盖与结束 | 对冻结分母逐项报告已处理项、余项、冲突、未知、下一来源和停止理由。 | `COVERAGE.md`、`FINDINGS.md` |

这里的“彻底”被定义为：**对一份冻结、版本化、可复算的来源分母完成覆盖**，并清楚记录分母之外的开放文献；不以论文数量、关键词数量、AI 一致意见或几句创立动机的修辞冒充完成度。

每次 run 都会在 `audit/HOTT-MOTIVE-ZFC/YYYYMMDD-HMZ-###-scope/` 下独立保存八类材料：`MANIFEST`、`SOURCE-CATALOG`、`R/Z/Q-CARDS`、`CONSUMER-CONTROLS`、`COVERAGE` 与 `FINDINGS`。因此以后可以回看某个候选究竟来自哪篇 HoTT 文献、它被如何映射到 ZFC、哪些标准回答被实际检查过，以及为什么没有或没有升级为 Q。
