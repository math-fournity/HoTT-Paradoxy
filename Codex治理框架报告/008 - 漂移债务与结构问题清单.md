# 漂移债务与结构问题清单（全部经直接核验，注明证据方式）

## P1（高危：中央读路径已失效）

**canonical `plan` 读路径 fail-closed。**
实测：`python3 -B .codex/tools/cognition_runtime.py plan --profile governance` →
`{"status":"BLOCKED","error":"UNCOMMITTED_STATE: .codex/research/hott/RESUME.md"}`。
原因链：`HEAD.json` 停在 revision 169（S-RES-20260917-169）；`RESUME.md` 于 2026-09-18 04:33
被 commit `4065616`（"治理同步 S-RES-20260918-176"）直接改写，未走 checkpoint 事务；
工作区 RESUME sha256 `8db22ba3…` ≠ tracked `27224595…`。Git 视角文件是干净的——
漂移在 HEAD 跟踪层，不在 Git 层。**后果：任何遵守框架的会话现在无法通过 canonical
出口获得加载计划，只能像本报告一样手工重建，或继续绕过。**

## P2（高危：合同被系统性绕过已成惯例）

"STATE checkpoint 机械层**未触碰**（STATE.revision 仍 169，收据缺口如实登记；沿 170–172 模式）"；
"全景视野/方向追踪为 checkpoint 管理文档，写回随 STATE 事务挂起（S-174 索引 panorama_change=YES

2 FAIL = checkpoint `after/` 快照既有已知项"。
即：重事务（全量 KC 审计+原子复制+收据链）在实践中已被连续放弃，代之以直接 git commit；
框架的"唯一收据 = result.json CHECKPOINT_COMMITTED"纪律对这些轮次整体悬空。
这不是某个会话的失误，是**成本超过承受阈值的系统性信号**。

## P6（结构性：分片与加载义务的错配）

v2 分片合同解决导航/编辑，但"全文 = 索引+全部分片"的加载定义让分片文档的
上下文成本不降反升；`soft_line_target=300` 只约束编辑体验，不约束总量。
框架缺一个对应物：**逻辑文档的"预算线"**（如"always_full 层逻辑文档 ≤ X tokens，
超出必须降层或拆 hot/cold"）。

## P7（观察：重复内容的制度性冗余）

- 行分片表头两行/片（合同唯一允许的重复）——量小，非问题；
- 同一判词/收据叙述在 STATE 记录、SESSION.md、MEMORY/003、投影行、审计集内
  五处各写一遍（措辞不同、信息重叠度高）——这是**叙述性重复**，占写义务的大头，
  且五处需人工保持一致（P5.1 的索引不符即其症状）。
