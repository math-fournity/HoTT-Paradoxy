# 会话级义务与 checkpoint 成本

## 一、每个实质工作单元的写作义务（合同来源：PROTOCOL §4/§6、LOAD_SET `checkpoint_required_session_files`）

| 必写件 | 当前体量（实测样本） | 说明 |
|---|---|---|
| `SESSION.md` | ≈1.2K–2.4K tokens（S-175/S-169） | 会话身份、产出、边界、判词 |
| `RUNS.json` | ≈0.3K–1.3K tokens | 运行收据索引 |
| `CORE_COGNITION_AUDIT.md`（索引+分片） | **S-169 = 31,685；S-175 = 12,643** | 全部 46 KC 逐条五元组 + 扩展认知 8 片逐段 + 航向复盘 + 偏航裁决 |
| **单会话写作合计** | **≈13,850 – 34,120 tokens** | S-169 目录全量 / S-175 目录全量 |

历史形态更重：2026-09-12 时代的单文件审计（S-GOV-20260912-005..012 等）
**每份 ≈129,000–131,000 tokens（≈433KB）**，且多份仅差几百字节——同代内容逐会话
复制后小改。020 合同改为分片审计集后降到 1.4–3.4 万，是框架内部已经发生的一次
自我减重（证明"义务本身可以瘦身而不失证据性"有先例）。

## 二、审计义务的结构性放大因子

1. **分母 = 全部 KC（46）而非触及集**：PROTOCOL §4 明确"覆盖 manifest 中全部 KC，
   不能只覆盖本轮使用过的几个"。哪怕本轮只碰 2 条 KC，也要为另外 44 条写
   `NOT_TOUCHED` + 事实依据。S-175 的减重技巧（"重写 11 条，余沿用 S-174 + 指针"）
   是会话层的自发缓解，尚未成合同。
2. **扩展认知 8 片逐段落论证**：AI 阐释层每轮也要逐片回评。
3. **每轮两份大反思**：航向复盘 + 偏航分析（020 合同），叠加在 KC 表之上。

## 三、checkpoint 原子事务的磁盘乘法

实测 S-169 checkpoint（`.codex/cognition/checkpoints/S-RES-20260917-169-.../`）：

```
before/   800K   MEMORY/ 全景视野/ 扩展认知/ 方向追踪/ + MEMORY.md 全景视野.md 扩展认知.md 方向追踪.md + STATE.json
after/    824K   同上（事务后版本）
transaction.json 18.2K
result.json      2.3K（CHECKPOINT_COMMITTED 唯一收据）
合计 2.9M
```

- 139 个 checkpoint 全量照此复制 → **187M、6,068 个文件**。
- 均值 ≈1.35M/checkpoint；早中期 STATE 较小时亦复制当时全部投影分片。
- 这是**正确性机制**（原子回滚）带来的**体积代价**，无保留上限、无轮换策略。

## 四、读/写义务的合成视角（单个研究工作单元）

| 方向 | est tokens |
|---|---:|
| 读：冷启动（research，含全局常驻与典型 Skill） | ≈528K–538K |
| 读：任务水合（理解章节子集等） | +1 万–17 万 |
| 写：SESSION+RUNS+审计集 | 1.4 万–3.4 万 |
| 压缩重付（如发生 1 次） | 再 +49.7 万 |

即框架对"做一步可检查的研究"索取的文本流量在 **55 万–120 万 tokens** 量级，
其中与该步研究本身直接相关的（水合证据+写作）通常不足 1/5。

## 五、sessions 档案累积（写义务的历史存量）

- `.codex/research/hott/sessions/`：188 个会话目录；md+json 共 773 个文件、
  ≈705 万 est tokens / 24.8MB。
- 存量主要来自旧式单文件审计（每份 ≈13 万 tokens）+ 每会话 checkpoint-payload
  副本（S-GOV-20260913-094..100 各 ≈19 万–22.9 万 tokens 的 evidence 拷贝）。
- `historical_session_auto_load=false` 保证这些不进新会话上下文——但它们与
  STATE 内嵌 session 记录不同层，说明框架**有**"档案不常驻"的正确直觉，
  只是 STATE 没有跟上自己的这个设计。
