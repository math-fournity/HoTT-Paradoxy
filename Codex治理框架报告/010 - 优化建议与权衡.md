# 优化建议与权衡

## 总原则（先于一切杠杆）

1. **不删除任何证据**：全部建议是"改层归属/改重付频率/改保留策略"，归档永远可查。
2. **不动用户原文权威**：核心认知.md 的 curation/manifest/hash 纪律原样保留。
3. **每项都需用户裁定 + runtime/validator 版本化落地**：本报告只测量与提议，
   不实施；落地顺序建议 G1→G2→G3（先解锁，再瘦身，后策略）。
4. 数字为 est tokens/会话的静态节省（不含压缩重付的乘数效应；含之则翻倍以上）。

## G1（前置）：修复 P1/P3，恢复 canonical 路径与入口一致

- 做法：一轮专门的治理修复会话——把 S170–176 的直接提交补登为显式 transition
  （或按合同登记为永久 CHECKPOINT_RECEIPT_MISSING），刷新 HEAD.json 至当前实况；
  同步根 AGENTS.md 的 core generation 事实。
- 成本：一次性 ≈1–2 万 tokens 写作；**收益**：plan 出口可用，此后所有测量与
  加载都有 canonical 凭据。
- 风险：补登不得伪造收据（合同已有禁令，走"登记缺口"路径即可）。

## G2：STATE 瘦身（最大杠杆）

| 措施 | 前 | 后（估） |
|---|---:|---:|
| 174 条 session 记录 → 归档文件（query_first） | 223,524 | ≈152,000 |
| 再将 CLOSED/HISTORICAL/SUPERSEDED 的非 session 记录 → 归档 | ≈152,000 | ≈40,000–60,000 |
| 记录体瘦身：STATE 只留指针+身份+hash，判词/收据叙述移回 SESSION.md/runs（引用式） | ≈40,000–60,000 | **≈10,000–20,000** |

- 机制：runtime 已具备 query_first 与 lifecycle 闸门，只需迁移数据 + STATE schema
  升版（v3）+ 迁移脚本 + one-off 校验（分母：322 条记录全部可定位，remainder=0）。
- 每会话节省 **≈20 万 est tokens（governance 降 ≈48%）**。
- 治理性质：保住"所有记录可发现、可显式水合"；放弃"全部记录在必读全文里可见"。
  后者本来就没有买到任务资格（闸门已挡），买到的只是字节过境。

## G3：压缩/会话重付策略改版

- 现状：`FULL_SET_EVERY_SESSION_AND_COMPACTION` → 每次压缩全额重付 49.7 万。
- 建议：压缩后重付 = 启动核（G2 后 ≈4 万）+ 四件套 **hash 收据 + 逐 KC 一行复认
  （46 行 ≈2–3K）+ 抽查 N 段原文**；全文重付仅在新会话首启或 hash 变化时触发。
- 长会话第二次支付从 49.7 万 → ≈6–7 万；同时保留"摘要不得冒充闭包"的红线
  （复认记录本身落 SESSION.md，可审计）。
- 需要用户裁定：这是对 LOAD_SET policy 字段的合同级修改（schema v5）。

## G4：MEMORY/003 与 research 附加文档切档

- MEMORY：`当前验证状态` 改为快照片（每轮覆写，≈3–5K）+ `顺序日志` 转归档
  （query_first，保留全部历史）。节省 ≈2.4 万/会话。
- RESUME/LESSONS/FRONTIER（合计 ≈6.6 万）：各自改为"索引 + 最新 N 节 + 按主题
  水合"；research 冷启动附加从 8.4 万 → ≈2 万。
- 治理性质：不丢任何教训，只是不再每轮全文重读全部历史教训。

## G5：审计与写作义务按触及集计量

- KC 回评分母改为"本轮触及 + 张力/裁决延续条 + **整块 NOT_TOUCHED 清单**（一行
  一条 ID，免五元组）"；S-175 的"重写 11 条+指针沿用"实践合同化。
- 审计集目标 ≤8K/轮（现 1.4–3.4 万）；历史 13 万式永不回退（已由 020 合同保证）。
- 治理性质：保留"每条 KC 每轮都有一个可审计的立场"，改变的是 NOT_TOUCHED 的
  表达密度——这正是 PROTOCOL 自己说的"大量 NOT_TOUCHED 是诚实结果"的应有成本。

## G6：checkpoint 保留与复制策略

- 近 5 期保留全量 before/after；更早的转为 delta（或移入 cold 目录并从
  `HEAD.json.tracked` 解除）。187M → ≈15M。
- `after/` 对分片审计集的覆盖缺口（P5.2）在改版时一并补全或显式声明为 git-side。
- 治理性质：原子性与回滚能力保留在活跃窗口内。

## G7：全局 `~/.codex/AGENTS.md` 分层

- 精简常驻核心（宪法+路由 ≈1.5 万以内），29 节中的 SOP/产品事实/专项路由移到
  按需文件，常驻层只留一行指针。节省 ≈1–1.5 万/每会话（所有 repo 受益）。
- 这是用户全局治理主库的决策（`~/codex` 工作流），非本 repo 可单方面改动；
  本报告仅登记为建议。

## 组合效果（静态口径，est tokens/会话）

| 场景 | 现状 | G2+G4 后 | G2+G3+G4+G5 后 |
|---|---:|---:|---:|
| governance 冷启动 | 413K | ≈195K | ≈195K |
| research 冷启动（含全局常驻/Skill） | ≈530K | ≈310K | ≈310K |
| research 压缩后重付 | 497K | 497K | **≈65K** |
| 每轮写作义务 | 14–34K | 14–34K | **≤10K** |

G2+G3+G4+G5 全落后，研究会话的总文本流量从 55 万–120 万降到 **≈35 万–45 万**，
其中与任务直接相关的比例从 <20% 提升到 >50%。若进一步落 G7 与投影行分片的
hot/cold 拆分（未单列），还可再降数万。

## 反向风险登记（为什么这些改变要慎重、要用户裁定）

1. 全文重读是现行的防幻觉实证手段；收据+复认方案是**制度替代**，需在 1–2 个
   真实会话上对照验证后才能全面切换（建议先在 governance profile 试点）。
2. STATE 迁移是一次 schema 大改，必须走 generator/manager（禁手改生成物），
   且要保留旧版全量迁移收据（项目已有 generation transition 的成熟先例）。
3. 所有"降层"都可能被未来的自己误读为"降级"——每层应保留升回的显式路径
   （query → hydrate → full-load）。
