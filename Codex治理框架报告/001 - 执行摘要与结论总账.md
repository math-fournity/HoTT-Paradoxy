# 执行摘要与结论总账

## 一、总体判断

用户的直觉被测量证实，且比直觉更严重：**治理框架的"遵循成本"已经不是背景噪音，而是会话的主导成本**。

1. 按框架自己的加载合同（`LOAD_SET.json` v4 + `cognition_runtime.py` graph()），一个 Codex 会话在做任何实际工作前，被要求全文过境的文本为：
   - governance profile：**≈ 413,113 est tokens**
   - research profile：**≈ 497,240 est tokens**
   - 系统化/机器统观研究（再加载程序化完备性规划）：**≈ 513,469 est tokens**
2. 这还没算：全局 `~/.codex/AGENTS.md` **≈ 20,474 tokens**（Codex 宿主每会话自动注入，29 个章节），
   以及按需加载的全局 repo-* Skill 家族（16 个，共 ≈44,780；典型治理任务再进 1–3 个，≈8–19K）。
3. 研究类会话的**现实冷启动**因此落在 ≈52–56 万 est tokens——已超过多数现行模型上下文窗口的全部容量，
   即使在百万级窗口下也占去一半以上，留给实际研究、代码与推理的空间所剩无几。
4. 策略是 `FULL_SET_EVERY_SESSION_AND_COMPACTION`：**每次上下文压缩后必须全额重付**。长会话压缩两次，
   仅启动闭包就支付三遍（research 口径 ≈149 万 tokens 的纯过境成本）。
5. 框架的**写作义务**同样沉重：每个实质工作单元必须新写 SESSION.md + RUNS.json + 全量 KC 逐条
   审计集（现行分片格式 ≈1.4–3.4 万 tokens/次；历史单文件格式曾达 ≈13 万 tokens/次），
   并在 checkpoint 事务中复制全部可变文档的 before/after（单次 ≈2.9MB，累计 139 个 checkpoint
   = 187MB 磁盘）。
6. **框架已经开始被自己的重量压弯**（详见 008）：S170–S176 各轮在 MEMORY/003 里自记
   "STATE checkpoint 机械层未触碰（revision 仍 169，收据缺口如实登记）"；canonical
   `plan` 读路径当前因 `UNCOMMITTED_STATE` fail-closed——即框架的中央读入口已经打不开。

## 三、单项最大杠杆（详见 010）

1. **STATE 账本瘦身**：records 占 STATE 字符量 97.5%，其中 174 条 `session` 历史记录占 33.8%
   （261,200 字符）。全部移出后 STATE 仍剩 ≈152K tokens——非 session 记录的冗长同样要治；
   目标形态是"热状态 ≤3 万 + 冷档案 query-first"。
2. **压缩重付策略**：改为"压缩后重付启动核+增量，四件套以 hash 收据+抽查替代全文重付"，
   可把第二次以后的支付从 ≈50 万降到 ≈5 万量级（需用户裁定放宽 `FULL_SET_..._COMPACTION` 合同）。
3. **MEMORY/003 顺序日志切档**：27,551 tokens 的会话流水改为"当前状态快照（≈5K）+ 归档日志"。
4. **research 附加三文档（RESUME/LESSONS/FRONTIER）索引化**：84,127 → 目标 ≈2 万。
5. **checkpoint 保留策略**：近 N 期全量、更早转归档，187MB → ≈15MB。
6. **全局 AGENTS.md 分节路由**：66KB/29 节常驻 → 精简核心+按需路由（属用户全局治理决策）。

## 四、必须保留的治理性质（建议的边界）

以上杠杆全部不触碰：证据永久性（归档不删除）、用户原文权威（核心认知）、hash 校验、
fail-closed、逐 KC 审计的存在性、checkpoint 原子性。改变的是**常驻量与重付频率**，
不是证据纪律本身。所有建议均需用户裁定 + runtime/validator 版本化落地，本报告仅测量与提议。
