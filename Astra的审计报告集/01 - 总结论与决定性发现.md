# HoTT 机器统观：总结论与决定性发现

日期：2026-09-15。身份：`INDEPENDENT_SINGLE_AGENT_AUDIT / CORRECTIONS_REQUIRED_BEFORE_FULL_EXECUTION`。

本报告审查 HoTT 机器统观能否把用户的问题意识转成新的、可核验的候选，并最终得到有现实同任务依据的结果。结论基于用户原文、全部指定 GPT/GLM 方案与往返、跨工作树源码和本轮实际检查。它不是新的 HoTT 数学定理，也不是对未来必然发现悖论的保证。

## 1. 最终判断

**GPT v2.1 值得作为保留大量正确约束的基础，但不宜原样作为下一轮的完整执行合同。需要同时修正证据检查链与发现方法。**

十轮互审确实排除了多种错误：把合成消费者自授为自然消费者、把裸函数相等当完整过程身份、把所有限制统称抽象债务、用一次归约现象代替元定理、用目录数和哈希端点推断历史行为。相关纠正应保留。

但是，双方达成一致的检查分母主要是各轮提出过的条款。它不能证明下一轮研究机制充分，也不能证明当前实现与校验入口已经可用。本轮实际运行发现了这种区别：**文件结构、CE-MAP、协调器旧测试能够通过，同时主项目的证明版本闭合和部分证据校验仍不能通过。**

## 2. 三项执行前必须处理的事实

### 2.1 active Goal/R4 来源身份冲突仍存在

`goal.md` 和 R4 TaskSpec 的实际哈希与 STATE pin 不同；本轮显式 Goal research plan 仍报告 `review_required`。普通 governance plan 的 `review_required=[]` 不能替代该检查。FR-001 是实质前置，但修复应限制到受影响任务，不能让不依赖这些字节的审计、原文恢复和校准停摆。

证据：[Goal query](evidence/commands/goal-query/stdout.txt)、[Goal hydration](evidence/commands/goal-hydration/stdout.txt)、[初始输入快照](evidence/snapshots/initial/files.json)。

### 2.2 “提交后就能通过证据闭合”没有成立

本轮先运行原版本校验器，得到未跟踪 C-188 源文件的阻塞。随后直接调用其逐包检查函数，检查全部 25 个 later packages，发现 **14 包还有独立于 Git 未提交的检查失败**：

- 7 包的包装脚本调用不满足校验器“源码路径必须直接出现在 argv 一次”的假设；
- 6 包已用外部 Cubical 源树固定依赖，却被只查看本地 `files` 的模块检查当作未登记依赖；
- 1 包把后来更新的 LIT 说明列入 source manifest，出现来源哈希漂移。

通用 run verifier 检查 42 个注册包，29 通过、13 拒绝；其中 10 个 T3 基础 Agda 包被按 Cubical pragma 检查、2 个 Coq 包遇到源码树排序算法不一致、1 个为上述 LIT 漂移。拒绝不是 13 份数学证明为假的证据；它说明工具路由、契约兼容与来源分类需要修复。

证据：[逐包结果](evidence/commands/registered-proof-inventory-02/stdout.txt)、[树哈希根因](evidence/commands/verifier-tree-order/stdout.txt)、[专项分析](04%20-%20证明语义、校验契约与运行复核.md)。

### 2.3 main 的研究连续性尚未包含可直接运行的机器统观协调器

机器协调器位于 `/Volumes/D/HoTT-machine-overview/machine-overview/`，本轮 `validate=VALID`，94 项 selftest 通过。main 的 CE 导入保存的是 169 份选定实物，不能因此推断协调器、语法、目标渲染器、全部运行闭包已经集成到 main。main 当前没有 `machine-overview/mo.py`。

最新方案要求 main 单工作面，却没有把这条实际执行连接的集成作为早期验收单元。下一轮若从 main 开始，很容易再次转为手工证明、文献与登记工作，机器发现引擎继续留在外部。

## 3. 最重要的方法修订

### 3.1 将“HoTT 因果作用”与“HoTT 独有”拆开

在另一演算中能保真表达同一机制，首先说明可迁移性或共同机制；它不单独回答原 HoTT 配置中的哪条规则造成了该现象。反过来，仅在 HoTT 代码中写出它，也不能证明 HoTT 规则发挥了必要作用。

下一轮必须分别判断：精确 HoTT 实例、候选内消融因果、跨框架共同机制、限定比较集内的专属性。现有“comparison 同型重现→停止特有性路线”只足以限制排他性主张，不能未经进一步判断消灭一条忠实的 HoTT 实例研究线。用户 KC-000027 对“程序界限被 HoTT 继承”的关注仍有独立研究价值；它也不因此自动完成根 Goal。

### 3.2 把发现准入与最终见证准入分开

严格来源与同任务要求适用于最终现实相对见证。数学探索可以先构造候选、证明局部性质、发现缺失接口，再寻求独立任务证据。当前方案第 008 片把 source-grounded task 写成进入 proof 的一般条件，第 007 片又要求真实生成器切片，二者需要明确区分适用阶段。

既不允许“因为我构造了任务，所以它天然现实”，也不能规定“没有既有自然消费者就不许证明任何新候选”。前者制造结论，后者容易阻止原创发现。

### 3.3 把新候选生成提前到第一轮实际验收

协调器现在主要搜索显式给定的有限 Delay 文法与 Horn 规则树，并使用具名任务渲染器。其校准与证据链有真实价值；广泛 dependent/higher-term synthesis 尚未建立。

下一轮应尽早让一个冻结后的新任务通过现有引擎，清楚标出哪些内容由人预置、哪些由程序搜索、哪些由原生核检查。仅重复旧候选的来源审计不能证明生成器获得了新能力。

### 3.4 把任务公平性扩展为完整任务合同

同 input/observation/completion 是必要起点；还要固定可用信息、允许操作、接口、资源、环境、公平性、量词和交付阶段。富表示正控制只有在这些条件内合法可得，才能排除原候选。偷偷补上原接口没有的数据，不能被称为同任务恢复。

### 3.5 保留时间、自反、表达三条独立入口

TGSQ 不应只寻找“有人把同伦 Path 当作物理运动”的文字。时间结构还包括逼近、极限、表示、运动操作和任务解释；时序包括因果、当前可用、稳定和持续生产。研究输入可以是用户明确的理论问题或有来源的应用，不要求先证明物理时空离散。

EXP 的最小表达保真任务没有普遍理由等待完整 R4 对象语法。R4 是自反/Gödel 路线的专门依赖，应避免让它成为所有候选的共同前置。

## 5. 推荐下一步

采用 `Astra的方案/` 中的修订候选方案，执行顺序为：

1. FR 与证据契约修复到足以支撑第一批工作；
2. 把机器协调器的最小可用闭包正式接入 main；
3. 一次短的旧候选判决，同时冻结时间/应用来源与新候选任务；
4. 尽早完成新 TaskSpec→候选→原生核验→对应审查→失败/结果收据；
5. 按证据让高价值候选得到深化，同时给时间、自反与表达线保留有界机会。

这次审计改变的是未来工作的执行条件与判断方法。当前合格 HoTT 现实相对见证仍为 0；既有正确证明与防线结果继续保留，不能用本报告的批评把它们抹去。
