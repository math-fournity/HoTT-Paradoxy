# 03 - GPT 方案 v2.1 逐片审计与修订需求

> 逐片判词：`正确` / `正确但有缺口` / `有内部矛盾` / `需修订`。DeepSeek 已做同结构审计；
> 本片只在**本审计独有发现**处展开，相同结论标注"同 DeepSeek"以示不重复。

## 索引片 — 正确

身份声明（`NOT_PROJECT_CURRENT_QUEUE_UNTIL_CANONICAL_WRITEBACK`、`NO_NEW_MATH_CLAIM`、
`LOCAL_UNCOMMITTED`）正确；第一执行链 `FR-001 → PSJ-001A → TGSQ-001A → PSJ-001B` 排序正确
（FR 先行经本审计 A1 独立确认其必要性升级）。

**本审计追加**：索引片未说明 FR-001 对 goal.md 的"路径 A"不可用（A1）。修订需求见 `Atria的方案/修订片/001`。

## 001 片（共识基线）— 正确

权威顺序、谱系表（16 节点，含自身两处撤回）、十二点稳定共识均正确且与记录相符（同 DeepSeek）。

## 002 片（总体执行架构）— 正确但有缺口（A3 级）

三发现线 + 两支撑线、P0/P1/A1、八种失败判词、方向 A/B、时间/时序二分均正确。

**缺口（本审计 P0 级，DeepSeek 未定此级）**：工作包表把六类生成器的真实链要求放在 `COV-001`
（007 片），但里程碑 M0–M6 没有任何单元验收"引擎获得生成新候选的能力"。按 A3，这是"确保成功"
的最大能力缺口。修订：新增 `GEN-001` 为 M1 并行单元（`Atria的方案/修订片/003`）。
（DeepSeek 指出的 EXP 排序矛盾同时成立，见 007/009 片。）

## 003 片（FR + VC）— 需修订（A1 + A2）

FR 双路径与五态语义、锚点清单八字段、owner-baseline v2 定位均正确（同 DeepSeek）。

**修订需求 1（A1）**：§1 只登记"7,484 文件未恢复旧 bytes"，未查 Git 历史。事实是 goal.md
**从未被任何 commit 跟踪**、无工作树副本、pinned 哈希非 Git 对象、checkpoint 未快照该文件。
因此对 goal.md 应直接写明"路径 A 在可及范围内不可用"，并把 §6 的"由 canonical integrator
按既有权威裁决"加强为"以 actual 为 intended 候选 + rulings/Feature 语义佐证 + 登记根因 +
目标契约纳入版本控制"。

**修订需求 2（A2）**：§9 VC-001 的六步流程不含"修复 14 项非 Git 类失配"。应新增前置工作包
`EC-001`：枚举失配分类 → 逐项裁决（修包契约 or 修校验器假设 or 登记外部依赖 allowlist 或同步
LIT manifest）→ 重跑直到 25/25 → 再进入 VC-001 的 commit 步骤。

**修订需求 3（A4）**：§9 应把"目标契约与审计文档纳入版本控制"列为 VC-001 的**第一批**内容
（而非仅 proof package）。

## 004 片（PSJ）— 正确但有缺口

九字段、消融合同、comparison pool 前置、PromotionSource 七层分母均正确。

**缺口（同 DeepSeek）**：source-grounded 阈值未钉死。**本审计补充**：A6 表明这个阈值不只是
"审查者口味"问题，而是 KC 构造语气与 §23 贯通要求之间的张力在阈值上的投影；阈值钉死应与
A6 裁定联动，或至少在 PSJ 第一批的 TaskSpec 中显式预注册阈值并声明其为待裁定。

## 005 片（TGSQ/ATD）— 正确但有缺口（同 DeepSeek）

时间/时序二分、八冻结、六维 holdout、三终局、OTM 九要素均正确。

**缺口**：Q2 无命中降级路线缺失（DeepSeek 缺口 5 成立）。**本审计补充 KC 锚点**：KC-000003
（稠密性 vs 量子化）、KC-000004（悖论作为反证、普朗克尺度）、KC-000024（两类时序悖论）是
用户点名主线；TGSQ 第二终局不应关闭 Q2，应降级为"用户哲学框架内的论证交付"（与 A6 的 L2 态
同构）。

## 006 片（R4X/CAN）— 正确

R4 十门、目标选择顺序、arithmetic-only 先行、义务十级、ERCF 四条件、三终局、CAN 五对照与
六观察层全部正确。本审计无新增缺口。

## 007 片（COV/EXP）— 有内部矛盾 + 需修订（A3）

八轴、六生成器、相对完备性、reducer 保真、unknown ingress 均正确。

**矛盾 1（同 DeepSeek）**：§8 自认 EXP 不可替代，却无早于 R4X 的执行位置；KC-000031/000035
是用户显式要求。

**矛盾 2（本审计新增）**：§3 要求六类生成器"每类至少一条 input→candidate→oracle→receipt 真实
链"，但据 A3（registry：M2 "no general dependent/higher-path search"；完备性规划 005：P2=PARTIAL），
当前只有声明文法枚举与三个研究扩展。**要求存在、实现不存在、且无早期验收单元**——这是本审计
对"确保成功"的最重一笔。修订见 `Atria的方案/修订片/003`。

## 008 片（机器证明/反解释/文献）— 正确但有缺口（A7）

F-011 链、九级证据、反解释八项、中性义务五条件、六类 holdout、九项指标、五条来源线均正确。

**缺口（A7，本审计提级）**：§10 "as-of 是纳入边界不是交付期限"软化的是 `rulings §23` 的**明文
用户裁定**，不是方案内部约定。必须三选一登记（顺延具名日 / 撤销并登记理由 / 改 as-of 并经
用户确认）。

**缺口**：§1 把 source-grounded task 写成进入 proof 的一般条件，与 007 要求真实生成器链存在
阶段适用性混淆（Astra 3.2 亦指出）。应区分"探索期可先构造后求来源"与"交付期必须来源化"。

## 009 片（里程碑/首三单元）— 正确但有缺口

M0–M6、首三单元 input/action/deliverable、十项单元结构、反停滞（含"不改名维持活跃"）均正确
且是九轮收敛的结晶。

**缺口**：无 GEN-001 位置（A3）；无 EC-001 位置（A2）；EXP 无位置（DeepSeek）；VC 无紧急里程碑
（DeepSeek）。修订后的里程碑见 `Atria的方案/修订片/005`。

## 010 片（治理写回/自证伪/验收）— 正确但有缺口（A6）

单工作面、owner 写回、动态测量五要素、E3 三层纪律、E4 锚点清单、TR-G1~G5、自证伪八条+回滚
记录、文本终止五条件、正向十门、负向停止、七项用户专属——全部正确，是九轮纪律的集大成。

**缺口（A6）**：§9 把"自然 consumer + 现实同任务"作为唯一正向完成态，未把 L2（组装交付）
设为**并行可达的独立完成态**，只给了 008 §11 的"中间报告"（中间报告不是完成态）。这不是
方案错误（§23 支持该门），而是**未把一个用户原文（KC-000005/010 的构造语气）支持的并行出口
显式化**，导致 DeepSeek 的 R1 风险无法在方案内消解。修订见 `Atria的方案/修订片/004`。
