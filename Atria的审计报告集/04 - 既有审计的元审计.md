# 04 - 既有审计的元审计：覆盖、缺口与未闭合残余

> 问题：GLM、GPT（九轮）、Astra、DeepSeek 四份审计各自覆盖了什么、留了什么？它们的结论能否
> 被假定为完整？本审计是唯一一份对审计生态本身做覆盖对账的。

## 1. 四份审计的能力分工（事实）

| 审计 | 跑了校验器/引擎 | 读了四件套原文 | 做了 Git 考古 | 产出完整性 |
|---|---|---|---|---|
| GLM 独立审计 | 否（明文声明未重放 proof） | **否**（明文声明未走治理加载，仅间接对齐） | 部分（status 计数、commit 抽样） | 完整（7/7 报告 + 索引） |
| GPT 九轮 | 部分（计数/hash/grep 复核） | 部分（通过引用） | 是（含 `git cat-file` 类检查） | 完整（9 轮往返 + v2.1 方案 10 片） |
| Astra | **是**（校验器逐包、selftest、Agda 隔离运行、R3 fresh replay） | 是（36 KC + 四件套分片） | 是（worktree 身份、HEAD） | **不完整（3/≈9）** |
| DeepSeek | 否（明文声明未重放） | 部分（KC ID 级引用） | 是（status、哈希、log） | 完整（7/7 报告 + 7 片增补） |

**关键结构事实**：唯一实际运行了证据契约校验器的 Astra 恰恰是交付不完整的那一份；两份完整度
最高的方案层审计（DeepSeek、GPT v2.1）都没有跑校验器。因此**"14 项证据契约失配"这个 P0 事实
在四份审计中只有一次半落地**（Astra 的总结论 + 本审计的独立复算），从未进入任何一份完整报告。

## 3. 九轮互审的收敛可信度（复核结论）

本审计抽查 GPT v2.1 是否真实吸收让步（同 DeepSeek 02 §6）：P0/P1/A1 三层、source-first 七层
分母、`λ X → X` 五对照、FR 双路径、R4 十门——**全部在声明位置落位**。判词：
`NINE_ROUND_CONVERGENCE_CREDIBLE_ON_MATH_AND_EVIDENCE_DISCIPLINE`。

但**未闭合残余四项**（本审计综合）：

1. **L1/L2 验收关系**（DeepSeek 3.1 已识别）：GPT 把 A1 设为唯一可交付成功，GLM 的
   `DELIVERED_ASSEMBLED` 被收进 008 §11 的"中间报告"——中间报告不是完成态。A6 表明这需要
   用户裁定，不能靠双方让步消解。
2. **PromotionSource 阈值**（DeepSeek 3.2）：九轮自己三次重演"审查者口味分派"，阈值仍未钉死。
3. **审计链与目标契约未版本化**（本审计 A4，DeepSeek 只覆盖九轮文档、未覆盖 goal.md）。
4. **证据契约失配**（本审计 A2）：九轮全程在文本层讨论"版本闭合需 Git 授权"，但从未运行
   `verify_proof_version_closure.py` 的逐包检查，因此 14 项非 Git 失配在九轮中**完全不可见**。

## 5. 元审计的治理含义

1. **"审计完成"必须按 promised 清单做覆盖对账**，不能按自述结论假定完整（A5 是活例）。本审计
   自己也受此约束：本报告集的 00 方案列了 Q1–Q8 与九类报告，下节给出实际覆盖对账。
2. **运行层审计与方案层审计不可互相替代**：Astra 发现的 A2 是任何方案层审计都不可能看见的；
   DeepSeek 发现的 A6/A7/A8 是任何纯运行审计都不会提出的。下一轮若再引入审计，应明确要求
   "跑校验器 + 读用户原文"两者兼备。
3. **本审计的覆盖对账**：Q1（01 §1/02 §1）✓、Q2（01 §2/02 §2）✓、Q3（01 §4/02 §1）✓、
   Q4（01 §3/02 §4/05）✓、Q5（01 §6/02 §7/06）✓、Q6（03）✓、Q7（本文件）✓、Q8（02 §4）✓。
   未覆盖：九轮逐轮文本的完整对账（GPT 001 片已有谱系表，本审计仅抽查，标 PARTIAL）。
