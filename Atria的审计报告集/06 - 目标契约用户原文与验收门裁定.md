# 06 - 目标契约、用户原文与验收门裁定

> 问题：goal.md §11 的"natural consumer + 现实同任务"是用户要求还是 AI 自设门槛？
> 这是 GLM/GPT/DeepSeek 三方争论的焦点，也是 DeepSeek 认为的"成败分水岭"。本审计给出
> 判别性原文证据，并把它重新定性。

## 1. 三方契约一致性（复核，confirmed）

| 层 | 表述 | 一致性 |
|---|---|---|
| KC-000010 | "不是要找 HoTT 内部矛盾，而是…在时间作为理论要素的把握上，存在非现实性的假设…构造一个过程…得到非现实性结果…以不可计算性/不可停机性为特征" | 与 Z_LAW §0 一致 |
| KC-000005 | "找到悖论才是关键，至于悖论作为矛盾，它到底是否定了哪个前提，那是未来的下一个故事" | 构造/发现导向 |
| Z_LAW §0 | 目标=现实相对非现实性（非 `HoTT ⊢ ⊥`）；提升未落定 spec 为完成对象时产生可证明的非法构造 | 与 goal.md §1/§9 一致 |
| rulings §23 | Goal 链含"自然 consumer、现实同任务对应和方向 A/B" + "具名截止日学术覆盖" | 与 goal.md §11 逐项一致（本审计核对，confirmed） |

三方在"目标是什么"上一致。分歧只在"如何验收完成"。

## 2. 本审计的新证据：验收语言是构造导向的（observed，用户原文）

**KC-000010（2026-09-10，WebGPT 线）**：

> "最优雅的结果，是我们用 Think in HoTT 的方式，**构造**出来了一个悖论，这个悖论让人们觉得
> 现实当中根本不存在这种理论推演出的'困难'，但是如果人们 Think in HoTT 的话，那么就一出现
> 无法完成的困难"

**KC-000005（2026-09-09，LocalGPT 线）**：

> "我们真正的目的是：找到它其中存在的悖论…但是我们找到悖论才是关键，至于悖论作为矛盾，
> 它到底是否定了哪个前提，那是未来的下一个故事。"

**KC-000011**：

> "要在 HoTT 中发现关于时间、时序的问题，其实就是看它什么时候，不想让时间、时序参与到
> Think in HoTT 这件事中。"

这三处的验收语言是：**构造一个悖论 → 它在 Think in HoTT 下产生不可完成的困难 → 归因是下一个
故事**。它没有要求"存在一个先在的、库内的、自然使用越级资格的 consumer"。

## 3. 重新定性：这是"两处用户原文之间的张力"，不是"AI 门设错了"

- GLM 的 B1：验收门把哲学命题塞进数学定理门（范畴错配）；
- GPT 的反驳：正向门可达，缺的是负向终止门（GLM 让步）；
- DeepSeek：L1 定理见证 / L2 哲学交付需用户裁定（推荐裁定丙）。

**本审计的定性（精确化）**：争论的双方都有用户原文支撑——

- **支持严格门**：rulings §23（2026-09-14，时序最晚、针对新 Goal 的显式裁定）+ Z_LAW §0
  （"提升为已完成对象时产生可证明的非法构造"）；
- **支持组装交付**：KC-000005/010/011（构造导向、归因延后）。

因此这**不是** AI 自设门槛的错误，而是**用户两处原文的真实张力**，只有用户能裁决。GPT 方案
维持 §23 门是**正确的默认**（时序更晚、更具体、针对当前 Goal），但它把 A1 设为**唯一**可交付
成功，使 KC 的构造语气在方案内**没有任何完成出口**（008 §11 的"中间报告"不是完成态）。

## 4. 建议的裁定形式（不替用户决定）

本审计建议的裁定是**"并行交付态"**，而非 DeepSeek 的"裁定丙"的变体：

```text
裁定甲（维持现状）：A1 为唯一完成态；L2 组装只作中间报告。
  代价：DeepSeek R1 风险（高质量有界负结论无限累积）无法在方案内消解。
裁定乙（并行交付态，本审计建议）：
  - 定理线 A1 保持 §23 完整十门，继续搜索，不降标准；
  - 新增 L2 独立完成态：DELIVERED_ASSEMBLED_WITH_SCOPE
      = 已机器证明的非因子化族（C-71–C-76 / C-96–C-99 / C-92–C-95 / C-106–C-109）
      + 明确写下的"提升为完成对象"语义桥（显式标 SYNTHETIC/解释桥，不冒充自然 consumer）
      + 反解释清单与正控制（已有）
      + 所有者评审通过（唯一裁判是用户，不是 kernel）
  - 两条线互不阻塞：L2 完成不等于 Goal complete，Goal complete 仍需 A1；
  - L2 不豁免 F-011（其数学部分已经机器证明，只是身份是"已证边界 + 解释桥"，不是新定理）。
裁定丙（DeepSeek 推荐）：先跑 PSJ 第一批，以实际命中再定门。
```

**本审计对裁定丙的修正意见**：裁定丙仍是稳健的（不预判结果），但**应先做 EC-001/A2 与 GEN-001/A3**
——因为若目标契约版本不可固定（A1）且证据契约 14 项失配（A2），PSJ 第一批的判词将写在不可恢复
的基座上。因此执行顺序应为：`EC-001 → (GEN-001 ∥ PSJ-001A 只读部分) → 裁定输入齐备 → 用户裁定`。

## 5. 组装交付的现有零件清单（事实，非评估）

若用户采纳裁定乙，可立即进入 L2 组装的已机器证明零件（证据等级
`MACHINE_PROVED_LOCAL_UNCOMMITTED`，非新数学）：

| Z 铁律要素 | 已有机器结果 | 判词 |
|---|---|---|
| 同一抽象等价、现实效应不同 | C-96–C-99（funext 使行为等价函数相等；细化表示可恢复，正控制） | `REPRESENTATION_BOUNDARY` |
| 无时间完成态的压缩伤痕 | C-71–C-76（race/deadline 非同余、商上无选择子） | `REPRESENTATION_BOUNDARY` |
| 阶段/时序擦除 | C-92–C-95（保律擦除 ⇔ 不动点）、C-106–C-109（在线资格边界） | 边界族 |
| 提升未落定 spec 为完成对象 | C-134–C-141、C-142–C-148（不可恢复族、无统一选点） | 边界族 |

**注意**：这些零件目前**全部**被 A1 门判为"不够"。裁定乙不改变它们的数学身份，只改变它们的
**交付身份**。本审计不主张它们已经构成 Goal 完成。

## 6. 对"确保成功"的含义

- 无论裁定甲/乙/丙，**A1（契约身份）、A2（证据契约）、A3（生成器）三项基础设施都必须先做**——
  它们与裁定无关，是任何裁定的执行前提；
- 裁定乙的独特价值：它把"已经机器钉死的最强论证"从"被封存"变成"可交付"，从而**消除
  DeepSeek R1 风险**，同时**不降低定理线标准**；
- 若用户选裁定甲，本审计尊重，但要求方案显式登记"接受 R1 风险"而不是留空。
